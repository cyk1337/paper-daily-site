18:T519,For each intended theorem T, the authors construct a complete shadow set 𝒮={S1,...,Sn}. Each shadow theorem Si is chosen so that T implies Si, giving a forward checker. The set is complete only if the conjunction S1∧...∧Sn implies T, giving a backward checker. Both directions are encoded and mechanically verified in Lean, so completeness is not an informal annotation claim but a machine-checked property. During evaluation, the generated candidate theorem \hat{T} is appended with these checkers. It receives credit only if it type-checks and passes the implication tests induced by the shadow set. A notable design choice is the annotation workflow: experts do not write everything from scratch. LLMs first draft candidate shadows, experts revise them, and Lean verifies completeness. This keeps expert labor focused on correction and validation rather than blank-page authoring. The method is especially well suited to multi-conclusion theorems, bundled conditions, existence/uniqueness statements, and other structures where partial formalization can still compile. Compared with BEq+-style reference-based equivalence checks, SA-Pass is less tied to one canonical expression. Compared with compile rate, it explicitly tests whether the generated statement is neither too weak nor too strong.19:T51b,Three results matter most. The reference formalizations are on average about 1.6× longer than those in earlier short-form benchmarks, reflecting a stronger emphasis on multi-conclusion and structurally richer theorems. Second, metric validity: across outputs from six agentic configurations, SA-Pass achieves 98.8% binary agreement with expert judgments, versus 17.8% for compile rate and 80.6% for BEq+. The low agreement of compile rate is the key point: it cannot separate semantically wrong but compilable statements from genuinely correct ones. An earlier 126-problem version was already used in the ICML 2026 AI4Math Challenge Track 4, which gives the benchmark some external validation beyond an internal case study.1a:T812,DreamProver is built around an iterative wake-sleep cycle.

In the wake stage, the system attempts to prove training theorems using the current lemma library. Two mechanisms are central. The first is learnable theorem identification. Under a fixed budget of proof attempts and error-correction attempts, the LLM is prompted to prove a target theorem using the current library. If it succeeds within budget, the theorem is treated as learnable at the current knowledge level and may imply a more advanced reusable lemma built on top of existing ones. The second is intermediate theorem discovery. When a theorem is too hard to prove directly, the system recursively decomposes it into more tractable intermediate theorems. These intermediate theorems become the raw material for later lemma induction.

In the sleep stage, the system does not simply append all discovered lemmas to the library. Instead, it performs structured lemma evolution. Based on the method description, this includes clustering, pruning, abstraction, and validation: semantically similar candidate lemmas are grouped and deduplicated; each cluster is abstracted into a more general and reusable lemma; the resulting abstractions are formally validated; and the library is updated with a compact set of accepted lemmas. The design trade-off is important. If the system optimizes only for coverage, the library becomes a bag of local tricks. If it optimizes only for abstraction, it risks producing overly general or unverifiable lemmas. DreamProver tries to balance provability, compactness, and transferability.

At test time, the learned lemma library is used explicitly to prove unseen theorems. So the learned artifact is not just an updated model state, but an externalized, compressed set of formal skills. This distinguishes it from methods that repeatedly synthesize fresh intermediate lemmas online.

Relative to prior work, DreamProver is neither fixed-library retrieval nor per-problem lemma synthesis. Its novelty is the closed loop of discovery, abstraction, validation, and reuse.1b:T6ee,The experiments span multiple formal math domains, including inequality, number theory, combinatorics, plane geometry, and machine learning theory. The headline result reported by the authors is a 61% improvement in proving success rate when using the learned lemma library, along with a 50% reduction in proof length and a 48% reduction in token usage. This suggests the gains are not only about solving more problems, but also about finding shorter and cheaper proof trajectories.

From the available full-text content, the most informative experimental dimensions appear to be the following. Third, compute efficiency: the reductions in proof length and token usage indicate that the learned lemmas improve search structure rather than merely benefiting from larger sampling budgets.
