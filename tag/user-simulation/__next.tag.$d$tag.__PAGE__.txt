9:T42e,CRAB-Bench combines three design choices.
1) Constraint-graph task generation: represent a task as a graph of entities/subtasks with discrete attributes and constraints. Use a CSP solver to guarantee at least one valid seed solution, then populate the database with structured distractors that satisfy many local constraints but violate global dependency constraints, forcing agents to do dependency propagation and combinatorial search.
2) RUSE user simulation: replace cooperative template users with personas grounded in behavioral studies, parameterized along four behavior dimensions (including information disclosure and impatience/emotional response), producing more realistic multi-turn interactions.
3) State-based evaluation with rule-based verifiers: concrete-state verifiers check whether the final database satisfies all constraints (solution correctness), while abstract-state verifiers check communication factuality and proper termination. Rule-based checking is chosen to support multiple valid solutions and reduce judge noise compared to LLM-as-judge.a:T477,RealUserSim has two main components:
1) Behavioral profile construction from real conversations. Starting from WildChat-4.8M, the authors filter down to 21,637 English multi-turn (≥3 turns) GPT-4o trajectories from 7,311 users. For each user, GPT-4o produces an “Executable Persona Manual” with up to 15 Command+Example pairs. Commands are actionable instructions for a simulator; examples are verbatim quotes from the user’s messages to calibrate intensity and avoid free-form interpretation.
2) Grounded simulation and fidelity evaluation via PT3 (Paired Trajectory Turing Test). Simulators are conditioned on these profiles, and fidelity is measured across multiple behavioral dimensions with anti-leakage controls. The grounded simulator is also used as a stress test for agent evaluation, revealing failure modes hidden by overly cooperative simulated users.
Design choice: instead of training a dedicated user model, constrain a general LLM with evidence-backed, executable behavioral rules. This is cheap and model-agnostic, but depends on the upstream LLM used for profile extraction and on how much history each user provides.b:T444,The interaction is formalized as a discrete-time stochastic process. The desired simulator should generate from the real user distribution conditioned on a control variable and should remain valid when interacting with a target policy different from the logging policy. The key technical point is that post-hoc trajectory labels are not ordinary controls: they are functions of the full trajectory and are entangled with future actions of the behavior policy. This creates look-ahead bias. Using ideas from off-policy evaluation, the paper further shows that when the evaluation policy diverges from the behavior policy, counterfactual metric variance can grow geometrically, a failure mode named controllability collapse.
