18:T515,A three-stage simulation pipeline:
1) Data-driven persona building: start from anonymized, aggregated behavioral signals (activity patterns, engagement, inferred demographics) and use an LLM to synthesize a structured persona profile (summaries, patterns, narrative descriptors) used as conditioning context.
2) Structured elicitation: present control/treatment variants (visual stimuli) plus a target metric (CTR/subscription) via carefully designed structured questions; each persona-conditioned agent outputs numeric scores per variant and persona-grounded rationales. Prompt format is treated as a key hyperparameter.
3) Statistical aggregation: aggregate per-persona score differences into a simulated treatment-effect distribution \(\mathcal{N}(\hat{\delta}_s, \hat{\sigma}_s)\), analogous to the normal approximation of the real experiment’s relative effect \(\mathcal{N}(\hat{\delta}_{rel}, \hat{\sigma}^2_{rel})\). Quality is mainly measured by sign agreement (improve/harm/no effect). The paper further studies persona-pool subsampling to reduce inference cost.

1) Constraint-graph task generation: represent a task as a graph of entities/subtasks with discrete attributes and constraints. Use a CSP solver to guarantee at least one valid seed solution, then populate the database with structured distractors that satisfy many local constraints but violate global dependency constraints, forcing agents to do dependency propagation and combinatorial search.
2) RUSE user simulation: replace cooperative template users with personas grounded in behavioral studies, parameterized along four behavior dimensions (including information disclosure and impatience/emotional response), producing more realistic multi-turn interactions.
3) State-based evaluation with rule-based verifiers: concrete-state verifiers check whether the final database satisfies all constraints (solution correctness), while abstract-state verifiers check communication factuality and proper termination. Rule-based checking is chosen to support multiple valid solutions and reduce judge noise compared to LLM-as-judge.1a:T477,RealUserSim has two main components:
1) Behavioral profile construction from real conversations. Starting from WildChat-4.8M, the authors filter down to 21,637 English multi-turn (≥3 turns) GPT-4o trajectories from 7,311 users. For each user, GPT-4o produces an “Executable Persona Manual” with up to 15 Command+Example pairs. Commands are actionable instructions for a simulator; examples are verbatim quotes from the user’s messages to calibrate intensity and avoid free-form interpretation.
