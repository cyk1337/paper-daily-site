18:T460,The paper defines an N-unsolvable problem as one with pass@N=0 under the initial policy. In the experiments, GRPO uses n=8 rollouts per prompt, while filtering uses N=64. If a problem has no success in 64 attempts, it will almost always produce an all-failure group during training. With binary rewards, the group-relative advantage in GRPO vanishes when all rewards are identical. The proposed fix is to use a stronger teacher to provide partial reasoning traces. A guidance level ρ controls how much of the teacher trace is revealed. At high ρ, the student solves an easier continuation problem; as ρ decreases, the student must perform more of the reasoning itself. Backward chaining then withdraws guidance until the model attempts the original unguided problem. The paper further argues that generic backward-chaining curricula are suboptimal here because training at ρ>0 is off-distribution relative to test-time ρ=0. The main contribution is not a new RL algorithm. It is specification-driven task construction.

In the enterprise setting, the workflow is authored in Agent Script, which defines routers, subagents, typed actions, tool scopes, and natural-language instructions. A static extraction pass compiles this declarative specification into a typed workflow graph. The graph encodes tool argument schemas, state effects, routing conditions, and loop or termination logic. In other words, the training environment is generated from the agent program itself, not reverse-engineered from logs.

A simulation pipeline then expands each specification into scenario-conditioned and persona-conditioned multi-turn sessions. The scenario determines the user need and which workflows are exercised. The persona controls the simulated customer behavior. Training examples can start from the initial user request or from an intermediate dialogue prefix, so the policy learns decisions at different depths of the interaction rather than only the first move.

Execution is handled by NeMo Gym. In environments without production backends, a frozen helper model plays three roles during rollout: customer simulator, tool or function emulator, and coverage judge. The policy model only acts in the environment. The reward is a grounded task-resolution reward, centered on whether the task is actually solved through successful tool use, not whether the response merely looks plausible. That makes the signal much closer to the real agent objective than token-level imitation.

Optimization uses GRPO. The paper also notes practical details for joint training across multiple environments: agent_ref dispatch selects the environment per example, and exposure is controlled by repeating examples before shuffling. Another important experimental fact is that training uses only public and synthetic data, with no customer data. Second, it introduces two recompute-free schedules. LeanGRPO-Retain simply enables gradient tracking during rollout and keeps the selected-timestep graphs alive until terminal rewards and group advantages are available, then reuses those graphs for backpropagation. It is simple but activation memory grows with the number of selected timesteps.

LeanGRPO-Reweight is more subtle. During rollout, each selected-timestep graph is immediately consumed through a provisional backward pass, producing a provisional gradient and allowing saved activations to be released right away. This shifts the memory burden from retained activations to stored provisional gradients.
