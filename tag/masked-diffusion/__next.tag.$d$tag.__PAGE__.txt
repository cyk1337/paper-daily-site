第一部分是对 MDM 与 UDM 的优化差异做 ELBO 分解。沿用 path-space ELBO 的写法，目标可拆成 transition prediction loss 和 schedule matching loss。标准 MDM 的 forward transition 是朝 mask token 的吸收过程，schedule 与 denoiser 无关，因此 schedule matching 项为零；模型只需学好反向预测。UDM 的 forward/reverse 过程则涉及全词表上的替换，等价地会引入一个依赖 denoiser 的 schedule matching 项。这个项不是常数，而是模型相关的额外误差源，所以 UDM 的 excess loss 更大，也更难优化。这个分析给出了“为什么 MDM 往往更稳”的明确理由，而不是经验判断。

第二部分是表达能力分析。作者用 circuit complexity 来刻画并行模型的计算深度。结论是：即便允许 arbitrary-order prediction 和双向注意力，标准 MDM 仍停留在 TC0 这一常数深度并行计算类里，和 AR 模型在复杂度层级上相近；UDM 因为允许 rewritable state，可以通过多轮重写实现更深的层级计算，达到 TC0 并支持 NC1 级别的层次化计算，例如求值嵌套布尔表达式。这里的重点不是复杂度标签本身，而是“可重写中间状态”带来了真正不同的计算机制。

LED 的设计正是围绕这个结论展开。它不改 MDM 的 commit 机制，而是额外引入一个 proposal branch。训练时，先用一个预训练 MDM 生成 proposal sequence，再把 proposal 作为条件输入，训练 LED 模型用标准交叉熵去预测目标 token。由于 proposal 里既有对的 token，也有错的 token，模型被迫学会两件事：什么时候保留 proposal，什么时候编辑 proposal。这里没有引入 UDM 那种模型依赖的 diffusion schedule，仍然保持 MDM 风格的简单监督。

推理时，LED 在每个 commit stage 内部交替执行 proposal stage 和 commit stage。proposal stage 维护一个可重写的中间状态，允许 token 在多个 lookahead steps 中被反复生成和修正；commit stage 则遵循标准 masked diffusion，一旦某个 token 被提交，就在后续 stage 中固定不再改写。这样，rewritability 被限制在 proposal 分支内部，而最终输出路径仍然是 MDM 式的逐步提交。跨 stage 时，已经验证较可靠的 proposal token 会被保留，错误 token 则在后续 proposal 中继续修正。

这个结构的关键取舍很清楚。为什么不直接训练 UDM？因为那会把 rewritability 放进主生成过程，训练目标更难。为什么不只做普通 MDM？因为 commit-once 机制限制了迭代修正。LED 选择把“可改写”放在辅助分支，把“可训练”留在主分支。它更像是在 MDM 外面包了一层 lookahead editor，而不是把整个模型改成 uniform diffusion。

从实现角度看，LED 也不是简单 reranking。proposal branch 不是只给一个草稿，而是在每个 commit stage 内部多步迭代，形成真正的中间可编辑状态；commit branch 则利用这个 refined proposal 作为额外条件，决定哪些 token 现在值得锁定。这个 proposal/commit 解耦，是全文最值得反复琢磨的设计点。a:Tcee,The paper first develops the theory, then introduces LED.

The optimization analysis starts from the path-space ELBO for discrete diffusion. The objective can be decomposed into a transition-prediction term and a schedule-matching term. In standard MDMs, the forward process is an absorbing transition toward a mask token, and the schedule is independent of the denoiser, so the schedule-matching term vanishes. The model only needs to learn reverse prediction. In UDMs, transitions operate over the full vocabulary, and the schedule effectively depends on the denoiser, introducing an extra model-dependent schedule-matching loss. This creates additional excess loss and makes optimization harder. The paper therefore gives a principled reason, not just an empirical one, for why MDMs tend to train more easily.

The expressivity analysis uses circuit complexity. The key result is that standard MDMs remain in TC0, even with arbitrary-order prediction and bidirectional attention. In other words, their parallel computational depth stays constant because committed tokens cannot be rewritten. UDMs, by contrast, maintain a rewritable state and can repeatedly revise tokens, which enables richer hierarchical computation and supports NC1-style behavior. The exact complexity labels matter less than the underlying mechanism: rewritable intermediate states fundamentally change what the model can compute in parallel.

LED is built around this observation. It keeps the MDM-style commit process intact, but adds a proposal branch that is allowed to rewrite tokens. During training, a pretrained MDM first generates a proposal sequence. LED is then trained, with standard cross-entropy, to predict the target sequence conditioned on that proposal. Because the proposal contains both correct and incorrect tokens, the model must learn when to preserve a proposal token and when to edit it. This preserves the simple supervision of MDMs and avoids introducing a UDM-style model-dependent diffusion schedule.

At inference time, LED alternates between a proposal stage and a commit stage within each commit block. The proposal stage maintains a rewritable intermediate state, allowing tokens to be generated and revised over multiple lookahead steps. The commit stage then follows the standard masked-diffusion process: once a token is committed, it is fixed and cannot be changed later. Across stages, reliable proposal tokens are preserved, while erroneous ones are revised in future proposal iterations.

This is the central design trade-off. Why not train a UDM directly? Because rewritability inside the main generative process makes optimization harder. Why not stay with a plain MDM? Because commit-once decoding limits iterative correction. LED places rewritability in an auxiliary branch and keeps trainability in the main branch. It is better understood as a lookahead editor wrapped around an MDM than as a uniform diffusion model.

Implementation-wise, LED is also more than draft-and-revise reranking. The proposal branch is iterated inside each commit stage, creating a genuine editable latent text state. The commit branch uses the refined proposal as additional conditioning to decide which tokens are safe to lock in. (2026). Let the proposal be the product of token-wise conditional marginals used by parallel sampling, and let the target be the true joint conditional distribution over the block. The log likelihood ratio between target and proposal can be decomposed into a sum of token-level increments along an ordering of the block, and each increment can be obtained from the score function. The problem is that evaluating the full sum requires one score query per token.

SIRS replaces the full evaluation with a single randomly sampled increment, yielding an unbiased estimator of the log acceptance ratio at the cost of one query. The main obstacle is that rejection sampling needs the acceptance probability, namely the exponential of that log ratio, and exponentiating an unbiased estimator does not preserve unbiasedness. To handle this, the paper uses a Poissonized Bernoulli factory following Chen et al. (2026): it samples a Poisson number of clipped increments and combines them into a random acceptance probability in [0,1] whose expectation matches the desired acceptance rate. Since rejection sampling only depends on the expected acceptance probability, the marginal output distribution remains correct under the construction.

To make the Bernoulli factory valid and stable, increments are clipped to [-B, B]. With an exact score model, clipping is the only source of approximation. Larger B reduces approximation error but increases query cost; the paper gives an expected per-step query bound of (1+2B)e^{2B}, independent of block size. A practically important refinement is Rao-Blackwellization. One score query returns conditionals for all remaining masked positions, so the sampled increment can be averaged over all eligible token choices at no extra query cost, reducing variance. The theory also shows a tighter clipping-error bound for the Rao-Blackwellized version.

The analysis decomposes the KL divergence between the sampler output and the data distribution into proposal error, acceptance-probability error, and clipping error. When the score function is exact, the first two vanish. Standard parallel sampling is recovered at B=0, where the method keeps the full correlation error between the block joint and the product of marginals. DLLM-JEPA constructs two views from the same input by sampling two noise levels tL < tH:
- a context view x_{tL}, lightly masked and information-rich;
- a target view x_{tH}, heavily masked and more abstract.

A gradient-carrying forward pass is run on the context view. From that pass, the model produces:
1. diffusion logits for the standard denoising loss;
2. a pooled embedding z_{tL}, used as the JEPA prediction-side representation.

The target view is processed in a second forward pass without gradient, producing z_{tH}. A JEPA loss then trains the context-side representation to predict the target-side representation. Because the target branch is stop-gradient, only one branch backpropagates each step. That is the source of the reported 33% FLOP reduction relative to LLM-JEPA.
