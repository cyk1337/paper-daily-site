a:T8d7,方法建立在 AttnRes 框架上。标准 decoder-only Transformer 有 2L 个 residual-writing sublayers，每个 attention 子层和 FFN 子层都会写一次输出 o_i。普通 PreNorm Transformer 在每个 residual read site 只是把历史写入固定相加；AttnRes 则在 read site t 用一个学习到的 pseudo-query q_t，对历史 source set S_t 做 attention，得到当前 hidden state。原始 AttnRes 直接把归一化后的 o_i 当 key，把 o_i 本身当 value。

论文提出 LR-AttnRes，保留 full-dimensional value path，只把 key 压到 r 维。具体有两个变体。

1. P-LR-AttnRes：Projected Low-Rank Attention Residuals。做法是把原本输出投影从 d 扩成 d+r，一次线性投影同时产出 full residual value 和一个 learned low-rank routing key。这样路由表示由单独参数学习，不再强迫 residual content 自己兼任 key。这个版本的优点是解耦最彻底，表达能力也最强；代价是仍然引入额外投影参数和一部分 FLOPs。

2. S-LR-AttnRes：Sliced Low-Rank Attention Residuals。它不额外学 key projection，而是直接取 full value 的最后 r 个维度作为 routing key。这样做牺牲了一部分解耦程度，因为 key 仍然嵌在 value 里，但省掉了额外参数路径，低秩 routing 带来的 kernel 降本会转化成真实总 FLOPs 降低。这个设计很朴素，但论文结果显示它几乎不损失效果。

论文同时沿用了 Full AttnRes 和 Block AttnRes 两种 source 管理方式。Full 版本对所有历史子层输出做 depth attention，灵活但存储和通信重。Block 版本把连续子层输出按块求和形成 block summary，只保留 embedding、已完成 block 的 summary，以及当前 unfinished partial block。低秩 key 机制可以直接套在这两种版本上。作者的主要结果集中在 Block 版本，因为它更接近可实现的折中点。

从机制上看，这篇工作的关键不是简单“降维”，而是明确区分：residual value 需要高容量，routing key 只需要足够区分深度来源。这个假设如果成立，就意味着 depth routing 的最优表示维度应显著小于 hidden size。论文的实验基本支持这一点，尤其是 r=32 或 64 已经足够。b:T7c0,The method starts from AttnRes in a decoder-only Transformer. Instead of forming the hidden state at each residual read site by summing all previous writes, AttnRes uses a learned pseudo-query q_t to attend over a source set of earlier sublayer outputs. In the original formulation, each output o_i serves as both the value mixed into the residual stream and, after normalization, the key used for depth routing.

LR-AttnRes keeps the value path unchanged but compresses the key path to rank r, with r much smaller than d.

The paper introduces two variants.

1. P-LR-AttnRes. The output projection is expanded from d to d+r, producing both a full residual value and a learned low-rank routing key. This explicitly decouples routing from residual content. It is the more expressive design, since the model can learn a dedicated routing representation.

2. S-LR-AttnRes. Instead of adding a separate key projection, it simply uses the last r dimensions of the full residual value as the routing key. This is less expressive because routing still reuses part of the value representation, but it removes the auxiliary projection path entirely. As a result, the low-rank routing reduction translates into a real reduction in total added FLOPs, not just a cheaper attention kernel.

The paper evaluates these ideas under both Full AttnRes and Block AttnRes. Full AttnRes attends to all previous residual-writing sources. Block AttnRes reduces storage and communication by grouping contiguous sublayer outputs into block summaries, attending only to the embedding, completed block summaries, and the current partial block. The main results focus on the block setting, which is the more practical tradeoff.

The key idea is not just dimensionality reduction. It is the claim that residual values need full capacity, while routing keys only need enough information to distinguish among depth sources. The experiments support that claim: small routing ranks such as 32 or 64 already work well.c:T593,The headline result is that low-rank routing improves both loss and efficiency. The best validation loss reported is 2.9477 from Block P-LR-AttnRes with 8 blocks and r=32. A nearly identical result comes from Block S-LR-AttnRes with 8 blocks and r=64, reaching 2.9480.

The relative comparisons are more informative than the absolute numbers. The sliced variant improves validation loss by 0.0193 over the strongest standard AttnRes baseline in the same setting, while using 3.25x less added compute. Compared with the best projected model, it is only 0.0003 worse in validation loss but uses 11.3x less added compute. That is the central empirical message: most of the gain comes from low-rank routing itself, while the extra flexibility of a learned key projection adds only a very small margin in this setup.

The paper also reports that the best sliced configuration adds only 0.093% FLOPs relative to the non-embedding Transformer core. That number matters because it shows the method is not just better in principle but close to negligible in overhead.

The experimental scope is still limited. The evidence is centered on validation loss and compute overhead, not large-scale pretraining, downstream transfer, or long-run optimization stability. So the paper supports the claim that low-rank depth routing is a better AttnRes design, but not yet that it should replace standard residual streams in production-scale LLMs.d:T425,For a quick read, focus on three parts.
