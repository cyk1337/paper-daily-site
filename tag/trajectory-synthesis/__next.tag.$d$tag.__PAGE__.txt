a:T479,OpenVisTool defines an “instructive” trajectory as satisfying two constraints jointly:
- Outcome validity: the final answer passes the task evaluator.
- Causal utility: holding (image I, query q) fixed, compare a probe/base model’s success rate with the recorded tool calls+observations versus a no-tool baseline. Keep the trajectory only if tool conditioning improves reliability.
The pipeline operationalizes this via three stages:
1) Difficulty screening: remove items that a strong model can solve reliably without tools, reducing prompt-induced but unnecessary tool calls.
2) Domain-specific trajectory synthesis: use structured invocation strategies per domain (charts, tables, GUI grounding, visual search, web-to-HTML) to avoid arbitrary traces.
3) Supervision verification: enforce both validity and utility; the latter is implemented as an explicit counterfactual performance delta rather than a subjective “reasoning-consistency” judge.
Key design choice: use a reproducible, model-based counterfactual test instead of relying on human/judge plausibility, aligning filtering with whether tool evidence changes answerability.b:T45b,A two-stage training paradigm is adopted: The first stage is a scalable interleaved GUI-tool data construction pipeline. Pure GUI data is converted to interleaved GUI-tool trajectories through tool step generation and next-state grounding, eliminating the need to collect high-cost real tool trajectories.
