18:T9a8,论文先做了一个很关键的诊断实验：控制 drafter 可见的视觉预算，从无视觉、低预算到全视觉，观察 accept length 的变化。结论不是简单的“视觉越多越好”，而是最优预算随状态变化且明显非单调。作者把 preferred budget 定义为“达到最大 accept length 的最小预算”，而不是最高 token 概率或最低单步延迟。这个定义很合理，因为 speculative decoding 的核心目标是提高端到端吞吐，而 accept length 比局部概率更直接对应系统收益。实验里 25% 视觉预算在 56.0% 的状态上最优，而 full access 只在 2.9% 的状态上最优，说明固定全量视觉输入既浪费算力，也可能干扰草稿质量。

基于这个观察，作者提出 FOVEA。整体结构分三步。第一，先用 target model 的视觉编码器和 projector 对图像编码一次，得到 projected visual tokens，并构建每张图像的外部 visual memory。这样后续 draft 过程不需要反复处理整张图。第二，在 draft-tree 解码时，每个节点的 hidden state 作为 query 去检索这块 memory，选出与当前状态最相关的视觉证据，而且检索数量是动态的，不是固定 top-k。作者强调 dynamic cardinality，因为不同状态需要的证据量不同。第三，检索到的视觉证据不插入自回归 token 序列，而是通过一个 lightweight gated residual module 融合到当前节点的表示里，只影响当前 token scoring。这样做的关键好处是不会改变历史上下文，因此不会破坏已有 KV cache。

这里的方法取舍很清楚。若把检索到的视觉 token 真正拼回上下文，理论上表达能力更强，但历史 cache 会失效，推理加速收益会被重算吞掉。FOVEA 选择“外部记忆 + 当前状态修正”这条路，牺牲一部分深层交互，换取 cache reuse 和系统可实现性。对 speculative decoding 来说，这是合理的工程-算法折中。

从文中描述看，visual memory 至少包含用于检索的 key 表示和用于融合的 value/update 表示，先经 layer norm 和线性投影构建。每个 draft hidden state 对 memory 做相关性检索，得到 state-conditioned visual readout，再经门控残差注入当前表示。门控设计的意义在于：当当前 token 几乎不依赖视觉时，模型可以接近退化为纯文本 drafter；当需要视觉证据时，再有选择地放大视觉修正。19:Ta86,The paper starts with a strong diagnostic. It varies the visual budget available to the drafter, from no visual input to full visual access, and measures accept length. The result is not monotonic: the preferred budget changes by state, and larger visual access is often suboptimal. The authors define preferred budget as the smallest tested budget that achieves the maximum accept length, rather than the budget with the highest token probability or lowest isolated latency. That choice is sensible because speculative decoding is ultimately about end-to-end throughput, and accept length is more directly tied to system gain. In their analysis, a 25% visual budget is optimal for 56.0% of evaluated states, while full access is optimal for only 2.9%, which already undermines the fixed-interface assumption.

Based on this observation, they propose FOVEA. The method has three main steps. First, the image is encoded once by the target-side visual encoder and multimodal projector, producing projected visual tokens that are stored in a reusable per-image visual memory. This avoids repeated full-image processing during drafting. Second, during draft-tree decoding, each draft hidden state acts as a query into that memory and retrieves the visual evidence most relevant to the current state. Importantly, retrieval cardinality is dynamic rather than fixed, because different states need different amounts of evidence. Third, the retrieved evidence is not inserted into the autoregressive token context. Instead, it is fused into the current node representation through a lightweight gated residual module, affecting only current-token scoring.

That design choice is the core systems insight. If the retrieved visual tokens were appended to the context, the historical KV cache would become inconsistent and would need recomputation, erasing much of the speculative speedup. FOVEA instead uses an external memory plus hidden-state correction, preserving cache reuse while still allowing state-conditioned visual adaptation. It is a deliberate trade-off: somewhat less expressive than rewriting the full context, but much more compatible with practical decoding.

From the method description, the visual memory contains at least retrieval-oriented key representations and fusion-oriented value/update representations, built from normalized projected visual tokens through learned projections. Each draft hidden state retrieves a state-conditioned visual readout, which is then injected via a gate. The gate matters because many decoding states are effectively text-dominant; in those cases the drafter should remain close to a text-only model, and only amplify visual correction when needed.1a:T5cb,Experiments span three vision-language backbones and nine multimodal benchmarks. The main outcomes are improved draft acceptance and improved end-to-end decoding speed relative to strong baselines, with up to 2.13× speedup over standard autoregressive decoding.

The diagnostic results are arguably even more informative than the headline speed number. Visual-budget sensitivity varies not only across tasks but also across generation stages within the same sample. The effect is especially pronounced on OCR-heavy tasks, where later tokens often need finer-grained visual evidence. This explains why static compressed visual interfaces can work in some phases and fail in others. The paper also shows that high visual budgets are rarely optimal: 75% and full access seldom win. That means excess visual context is not just computationally expensive; it can also hurt drafting quality by adding irrelevant evidence.

The full excerpt does not list every benchmark number, but the mechanism behind the gains is clear. FOVEA improves average accept length, reducing target-model fallback, while also avoiding repeated visual recomputation and cache invalidation. The most important ablations to inspect are likely fixed budget vs dynamic budget, context insertion vs gated residual fusion, with vs without external visual memory, and task-wise budget preference distributions.
