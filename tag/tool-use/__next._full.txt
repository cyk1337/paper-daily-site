19:T7e9,Palmyra x6 keeps the GLM-5.2 GlmMoeDsa architecture unchanged and fine-tunes the weights. The inherited base has 744B total parameters and about 40B active parameters per token. It combines sparse MoE feed-forward layers, Multi-head Latent Attention, a DeepSeek Sparse Attention indexer, DSA IndexShare, rotary embeddings, and a next-n multi-token prediction head. IndexShare is not just an implementation detail: serving requires an inference stack that can reuse sparse-attention selected indices across layers.

The training set consists entirely of synthetic agent/tool-use trajectories. Prompts come from internal Writer subject-matter experts and some external task suites. The six broad categories are financial research with search, data analysis and coding, clinical/medical agent tasks, MCP tool suites, long-horizon multi-tool simulated environments, and RAG over realistic document collections.

The data pipeline adapts self-distillation fine-tuning to multi-turn tool use. A successful reference trajectory is converted into a sanitized strategy demonstration. It preserves the reasoning outline and tool order, but removes the final answer, masks numbers and dates, and hides tool-call arguments. The student then receives this strategy in its system prompt and must solve the task again using live tools. A verifier checks the result against the reference answer, while a cheating filter rejects rollouts that exploit the demonstration instead of actually using tools.

Training uses Anchored SFT rather than plain SFT. The motivation is to reduce the mismatch introduced by supervising the model on trajectories it would not naturally produce. The recipe search compared 12 SFT and ASFT runs over objectives, KL anchor strengths, learning rates, epochs, and six data recipes. The selected recipe is ASFT with KL weight K=0.1 on a 12-dataset primary mix. The final Palmyra x6 run keeps the objective and data fixed, changes the base model, and switches the optimizer for 2-D weight matrices from Adam to Muon.1a:T412,The experimental design tries to keep causal attribution clean. The recipe-development phase runs a 12-run matrix covering SFT versus ASFT, KL weight, learning rate, epoch count, and data mixture. The final model changes only two controlled factors relative to the chosen recipe: the base model and the optimizer.

The report gives concrete rollout constraints for data generation: up to 30 turns per trajectory, temperature 1.0, top-p 0.95, a 50,000-token generation cap, and up to 6 attempts per task. The first turn must call a tool. A trajectory is abandoned if it exceeds 20 tool calls, 4 consecutive calls to the same tool, 3 tool errors, or 3 identical repeated calls.

The provided content does not include exact public benchmark numbers. It states that Palmyra x6 improves substantially over the previous default model used in Writer Agent and is compared with frontier models available during development. Public benchmarks are treated as sanity checks; the primary selection signal comes from internal enterprise-style evaluations.1b:T78e,The core contribution is a corrected protocol for measuring cross-lingual action-policy retention. Under a fixed scaffold, models operate over a shared five-tool alphabet and emit executed action traces alongside answers. The study covers 8 models, 6 parallel benchmarks, 41 languages, and 2.38 million rollouts. A naive trace-similarity metric fails for five reasons: short traces look artificially similar, empty traces score perfectly, unrelated traces overlap by chance, same-language reruns are not identical, and without a within-language baseline the quantity is not identifiable.

The estimator addresses each issue explicitly. Every language-task cell is run twice with identical decoding settings and token budgets, changing only the serving seed. Same-language agreement, I_within, compares the two replicates in one language. Cross-language agreement, I_cross, compares traces across languages, also cross-seed. The normalized retention metric is \tilde{I}=I_cross/I_within, which measures how much of a model’s own reproducible policy survives a language change. Comparisons are length-matched in both directions, pairs are dropped if either trace is empty, and uncertainty is estimated with task-level bootstraps. This design makes language the only systematic difference while keeping decoding noise symmetric.

The paper then probes mechanism. The evidence points to an English pivot. Translate is the most frequently used tool across adapted benchmarks, and reasoning text is about 99% ASCII even for non-Latin inputs such as Devanagari. Removing the translation tool lowers agreement in proportion to a model’s prior reliance on translation; forcing translation helps in a pre-registered ordering across models. The implication is that many multilingual agents do not execute the same policy directly in the target language. They often map the task into an English-centered internal workflow and plan from there.1c:T697,The empirical scale is substantial: 8 models, 6 parallel benchmarks, 41 languages, and 2.38M rollouts. Three results stand out. First, under greedy decoding, all 24 main cells show a positive cross-lingual policy gap, and every bootstrap interval on the raw gap excludes zero. The effect is stable rather than anecdotal. Second, every correction increases the measured effect instead of shrinking it. That is important because it means the problem was previously hidden by bad measurement, not because it was weak. Third, after normalization, four otherwise very different models converge to nearly the same policy-retention value under greedy decoding: about 71–73%. The regularity holds at the cell level, not just in model averages, and model identity explains only about 5.7% of the variance.

The temperature ladder is also informative. As sampling temperature rises, cross-language agreement changes little, while same-language self-consistency drops sharply. Without normalization, sampling noise masks the true cross-lingual policy loss. On the mechanism side, Translate is the most-used tool in every adapted benchmark, and reasoning text is almost entirely ASCII, indicating that non-English tasks are often routed through an English internal channel. Removing translation hurts agreement roughly in proportion to how much a model already uses it; forcing translation helps in the pre-registered order predicted from those usage rates. When reading the full paper, it is worth checking how tightly the tool alphabet is standardized across benchmarks, how the bidirectional length matching is implemented, and whether retention differs systematically across language families.1d:T50e,This one is worth a careful read. Start with the introduction and method sections to understand why the paper insists on measuring action traces rather than final answers, and how each of the five confounds can distort the conclusion. Then read the section defining I_within, I_cross, and \tilde{I}; that is the identification core of the paper. After that, inspect the main result figures, especially the claim that every correction makes the effect larger. Finally, read the temperature analysis and the translation-tool ablations, which explain why multilingual agents can look answer-consistent while still following different internal policies.

From a pretraining angle, two questions are especially worth carrying through the paper. First, is the English-pivot behavior driven mainly by pretraining data distribution, tokenizer effects, or English-heavy tool-use post-training data? Second, does the near-constant 71–73% retention hint at a structural bottleneck in cross-lingual policy transfer, where only part of the planner survives language change? A full read of the main text plus the key appendices will likely take 45–60 minutes. The appendix sections on the estimator, confound costs, and design checks are essential; skipping them makes the result look simpler than it is.1e:T479,OpenVisTool defines an “instructive” trajectory as satisfying two constraints jointly:
- Outcome validity: the final answer passes the task evaluator.
- Causal utility: holding (image I, query q) fixed, compare a probe/base model’s success rate with the recorded tool calls+observations versus a no-tool baseline. Keep the trajectory only if tool conditioning improves reliability.
The pipeline operationalizes this via three stages:
1) Difficulty screening: remove items that a strong model can solve reliably without tools, reducing prompt-induced but unnecessary tool calls.
2) Domain-specific trajectory synthesis: use structured invocation strategies per domain (charts, tables, GUI grounding, visual search, web-to-HTML) to avoid arbitrary traces.
3) Supervision verification: enforce both validity and utility; the latter is implemented as an explicit counterfactual performance delta rather than a subjective “reasoning-consistency” judge.
Key design choice: use a reproducible, model-based counterfactual test instead of relying on human/judge plausibility, aligning filtering with whether tool evidence changes answerability.1f:T747,方法核心有两个表示层 readout，都是用“策略相关的反事实干预”来做校准目标。第一个 readout 作用在 prompt state 上，预测 closed-book sufficiency，也就是当前策略在不检索时是否已经足够回答；其补量就是 retrieval necessity。第二个 readout 作用在 answer commitment 阶段，估计 evidence reliance：把已检索证据删除后，答案是否会变化，用这种 answer-stage sensitivity 作为 operational grounding 的代理。

关键点不在于直接在线做反事实，而在于先用干预构造标签，再训练轻量 readout 去近似这些判断。这样 rollout 时只需读取 policy representation，就能得到 necessity 和 reliance 分数，避免了过程标注和额外 LLM 调用。

奖励设计是 correctness-first 且 normalization-aware 的。正确的 searched trajectory，只有在 necessity 高时，reliance credit 才有意义；正确的 direct trajectory，则拿 closed-book sufficiency 的信用；重复搜索会有有界惩罚。这个设计针对 GRPO 一类 group-relative 更新里的一个实际问题：如果一个 group 里样本都答对，纯 outcome reward 会让 advantage 退化到接近 0，训练无法区分“少搜、必要搜、证据驱动搜”和“乱搜但也答对”。Search-G1 用 shaped reward 在这些 tied groups 里恢复了可学习差异。

另一个重要机制是 periodic refitting。因为 readout 依赖 policy representation，而 RL 会持续改变表示空间，所以 necessity/reliance 估计器如果固定不动，很快就会失准。论文把 search-agent 训练看成 measurement-credit-adaptation 的闭环：定期用最新策略生成轨迹，重新做校准并重训 readout，让奖励测量始终跟着 policy knowledge boundary 走。这一点比静态 reward model 更贴近实际训练动态。20:T7ae,Search-G1 builds two representation-based readouts, both calibrated using policy-relative counterfactual interventions. The first readout operates on the prompt state and predicts closed-book sufficiency: whether the current policy could answer correctly without retrieval. Its complement is retrieval necessity. The second readout operates near answer commitment and estimates evidence reliance by measuring whether the answer would change if retrieved evidence were removed. This is framed as an operational proxy for grounding rather than a full causal certificate.

The key design choice is to use interventions for calibration, not for online reward computation. Counterfactual tests are run offline to create labels, and lightweight readouts are trained to predict those labels from the policy’s own representations. At rollout time, the reward can therefore be computed cheaply, without process supervision or extra model calls.

The trajectory reward is correctness-first and normalization-aware. Correct searched trajectories receive reliance credit only when retrieval was necessary. Correct direct-answer trajectories receive credit for closed-book sufficiency. Repeated search incurs a bounded penalty. This directly addresses a practical issue in group-relative RL such as GRPO: when all trajectories in a group are correct, pure outcome reward yields near-zero advantage and cannot separate efficient grounded search from redundant search. Search-G1 restores reward variation inside these tied groups.

A second important component is periodic refitting. Because the readouts depend on policy representations, and RL changes those representations over time, a frozen estimator will drift out of alignment. The top layer maintains an explicit state containing the goal, hard constraints, soft preferences, blocking conditions, evidence ledger, progress, and next intention. It decides whether to continue browsing, ask for clarification, stop, flag an external blocker, or answer. The middle layer is deliberately narrower. Given the current observation, the top-layer intention, persona state, and recent history, it emits exactly one JSON Action AST from a constrained action space: Click, Type, Scroll, Search, Maps, Back, Wait, or a safe fallback.
