18:T5d4,MemToC is built as a controlled post-tool-call benchmark derived from ToolHop.
- Data pipeline: start from ToolHop sub-questions with locally executable tool calls and verified intermediate answers; keep only self-contained facts with short verifiable answers.
- Pre-construct benchmark artifacts before evaluating any model: question q, verified gold g, executable call, and curated distractors to synthesize plausible incorrect tool returns. Two annotators independently review for self-containedness, answer leakage, answer validity, and distractor plausibility.
- For each model and each prompt wording variant, first elicit a closed-book answer m (forced to answer, no abstention) and score it against g to determine whether the model’s memory is correct.
- Then present the same question with an injected tool return r under four conditions: correct return, incorrect return (built from verified answers and human-validated distractors), error payload, and no return. Because r is injected, tool correctness is known a priori.
- This yields a source-correctness matrix where the “correct behavior” is well-defined (use correct tools, resist incorrect tools), with tool-error/no-tool as controls.
- Evaluation details include extraction-first answer matching and three instruction-wording variants with fixed question text.

1) Environment: a ~10 km^2 urban region with ~3,600 deduplicated places (spatial anchors) built from AMap API + OpenStreetMap. Each anchor is enriched with weakly-structured local social media evidence from RedNote: up to 20 notes per place via name search, and up to 10 comments per note, retaining full text, timestamps, engagement stats, and tags—yielding ~200k notes/comments. Ambiguity and irrelevant content are intentionally preserved.

4) Evaluation protocol: 667 synthetic yet realistic queries across four task families (Place Perception, Nearby Discovery, Routing, Trip Design) and three difficulty tiers: L0 single retrieval; L1 multi-retrieval + calculation; L2 decision-making under additional user constraints.
