1) Session isolation with controlled reuse: sessions can be isolated or shared; file resets and memory retention are controlled separately. When shared memory is updated by attempts, executions are forced to be sequential and not automatically retried, since failures can change inherited state.

The first axis is perturbation target: user utterance (U), procedural specification (P), carried-over context (C), and tool contract (T). The second axis is perturbation type: Missing, Redundant, and Incorrect. This yields 12 perturbation families.

Two design choices are important. First, perturbations are single-target edits: only one channel is modified at a time while the others remain unchanged. This makes attribution cleaner and avoids confounding multiple failure sources. Second, perturbations are validated so that the original task goal is preserved, the environment remains executable, and a valid solution path still exists. So the benchmark is not broken; the agent is tested under controlled information corruption.

The framework is instantiated on APEX-Agents and Toolathlon, two long-horizon agent benchmarks with verifiable outcomes. The analysis is organized at three levels. Trajectory-level analysis audits reasoning traces, tool calls, observations, and state transitions to understand how perturbation-induced failures unfold.
