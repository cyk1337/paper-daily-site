9:T41f,SpecAgent separates tool actions into read-only actions and state-changing actions. The weak model is allowed to execute read-only calls while drafting, because these calls do not modify the environment and can be removed from the history if they are wrong. When the weak model reaches the first state-changing action, such as submitting an answer or modifying a record, execution is paused. The strong model then reviews the drafted segment in one prefill pass, commits the longest semantically valid prefix, and repairs the first rejected step. This differs from routing, where one model still generates each step; from collaborative agents, which decide the actor step by step; and from conventional speculative agent methods, which often require exact agreement with the strong model’s own generated action. The key design choice is to accept alternative valid progress rather than only actions that match the strong model.
