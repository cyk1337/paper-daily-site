18:T6d0,The contribution is a benchmark, not a new agent algorithm. EvoHarnessBench defines the harness as the set of tools an agent can call, the procedural skills it can reuse, and the specialist agents it can coordinate with. Each harness stream is a sequence of cumulative stages H1 ⊆ H2 ⊆ ... ⊆ HT, so later stages only add capabilities and never remove old ones. Streams are built along three axes: tools, skills, and agents.

Two design choices matter. First, each task is assigned to the earliest stage at which it becomes solvable, and it must require at least one newly introduced capability. This helps separate adaptation to new capabilities from retention of old ones. Second, capabilities are released from common core capabilities toward the long tail, which is meant to mimic real harness growth in deployed systems.

The benchmark supports two evaluation modes. In deployment evaluation, no experience is carried across stages; each harness version is evaluated independently. This isolates the direct effect of harness expansion: does a larger capability pool help, or does it mostly distract? In self-evolving adaptation evaluation, persistent artifacts such as memory, prompts, or learned skills can be updated within each stage and then carried forward, while the underlying model weights remain fixed. This tests whether accumulated experience helps or hinders adaptation under a growing harness.

The benchmark is reasonably large: 17 controlled harness streams, each with 3 to 6 cumulative stages, 802 unique tasks, 1,510 axis-specific evaluation examples, 520 executable tools, 42 latent reference skills, and 62 specialist agents. The paper evaluates representative single-agent and multi-agent systems under both modes.19:T540,The empirical message is mostly diagnostic. First, harness expansion is not free. Agents can lose competence on tasks they previously solved even though the underlying model is unchanged and the required capabilities are still present. That is the benchmark’s evidence for harness-induced forgetting. Second, self-evolving adaptation is inconsistent. Gains vary substantially across stages, axes, and environments, which suggests that simply accumulating memory or prompts is not a reliable answer to harness evolution. Third, retention and adaptation often pull in opposite directions: methods that preserve earlier competence better can be worse at exploiting newly introduced capabilities, while methods that adapt aggressively can sacrifice old-task performance.

The main concrete numbers visible from the full text excerpt are benchmark-scale statistics: 17 streams, 802 tasks, 1,510 evaluation examples, 520 tools, 42 skills, and 62 specialist agents. The paper evaluates representative SAS and MAS systems, but the excerpt provided here does not include the full per-system score tables. That makes this paper more useful as a benchmark-design read than as a leaderboard read.
