关键观察（论文给了具体数字）：
- harness 可能“解出更多新题”但总体准确率更低：例如 Qwen 在 GPQA-Diamond 上，各 harness 比 Direct 多解出 8–13 道 Direct 没解出的题，但同时会额外错掉 18–36 道 Direct 能解的题。四个系统合并看，198 题里 175 题至少被解对过一次，而 Direct 只有 159/198。
- 仅看行为模式很难判断对错：相似的 tool-use 占比、连续检查、低 entropy 既出现在正确也出现在错误。对 HLE-Verifiable 的人工标注错误尝试里，OpenCode/ZeroClaw 的 repetition 标签分别约 36.8%/39.4%，但 budget-exhaustion 标签差异明显（13.0% vs 0%），提示不同 harness 的失败模式不同。
- tools/skills/memory 并不稳定带来收益：AIME 26 上（每题 4 attempts），Kimi/OpenCode 去掉工具描述与相关指令后，“正确 attempts 数”从 104 提到 116，但“至少解对一次的问题数”从 30 降到 29；skill loading 只在 16 组对比中的 2 组提升准确率；Qwen 在 AIME 26 上，用 AIME 25 收集并固定的 memory 对 OpenCode 有益、对 OpenClaw/ZeroClaw 反而有害。
- token 省一点可能换来大量正确数损失：Gemma/HLE-Verifiable 的共同任务上，OpenCode 输出 token 比 Direct 少 0.6%，但正确数 140 vs 164。若用“总输出 token / 正确答案数”衡量单位正确成本，平均上升 16.5%。OpenClaw 输出最高的 10% attempts 消耗了 62.2% 的输出 token，却没有一个正确答案，说明长轨迹常被浪费在重复/工具失败/错误推理上。19:T4ba,AlphaDiana is a measurement system rather than a new agent method. The design centers on:
1) Session isolation with controlled reuse: sessions can be isolated or shared; file resets and memory retention are controlled separately. When shared memory is updated by attempts, executions are forced to be sequential and not automatically retried, since failures can change inherited state.
2) Harness-native adapters: instead of forcing a unified agent loop, adapters standardize task I/O while preserving each harness’s native model-call patterns, tool permissions, feedback loops, and context updates—keeping comparisons faithful to real harness behavior.
3) Evidence-linked artifacts: each attempt stores an outcome record (correctness, score_status, runtime errors) linked to normalized traces (roles, content, tool calls/results) and resource usage (tokens, runtime). Reports include failed/unscored attempts, and the system uses the latest record per requested evaluation so retries do not inflate the evaluation count.
The system is modular across datasets/agents/environments/scorers/analyzers, and supports matched interventions on tools/skills/memory while holding model/tasks/scoring/decoding fixed.1a:T723,The experiments emphasize measurement/attribution rather than leaderboard gains. Setup: three open-source models (Qwen, Gemma, Kimi) paired with three harnesses (OpenClaw, ZeroClaw, OpenCode) on five answer-based benchmarks; Qwen and Gemma also tested on two interactive benchmarks with verifiers after file edits/commands. Baseline is Direct: single response, no tools.
Key quantitative findings reported:
- Harnesses can solve additional questions yet reduce overall accuracy. For Qwen on GPQA-Diamond, each harness solves 8–13 questions that Direct misses, but fails on 18–36 that Direct solves. Across four systems, 175/198 questions are solved at least once vs. 159/198 for Direct.
- Behavioral patterns are not reliable correctness indicators: similar tool-use shares, consecutive checks, and low entropy appear in both correct and incorrect attempts. On annotated incorrect HLE-Verifiable attempts, repetition labels occur in ~36.8% (OpenCode) vs ~39.4% (ZeroClaw), while budget-exhaustion differs sharply (13.0% vs 0%), suggesting harness-specific failure modes.
- Tools/skills/memory are not consistently beneficial: on AIME 26 (4 attempts/problem), removing tool descriptions/instructions for Kimi/OpenCode increases correct attempts from 104 to 116 but reduces problems solved at least once from 30 to 29; skill loading improves accuracy in only 2/16 comparisons; fixed memory collected on AIME 25 helps OpenCode but hurts OpenClaw/ZeroClaw for Qwen on AIME 26.
- Small token savings can come with far fewer correct answers: on shared Gemma/HLE-Verifiable tasks, OpenCode uses 0.6% fewer output tokens than Direct but yields 140 correct vs 164. Total output tokens divided by #correct increases by 16.5%. For OpenClaw, the top 10% highest-token attempts consume 62.2% of output tokens without any correct answer.1b:T54b,The contribution is a benchmark called SciΠvot rather than a new agent architecture. The data comes from six months of original, PhD-level AutoResearch projects across six scientific fields. LLM agents ran these projects over weeks to months, while senior researchers periodically intervened to correct poor scientific decisions. The authors convert those intervention points into 248 benchmark cases. Each case presents two candidate plans: the original LLM plan and the human-corrected alternative. At evaluation time, the model sees only the project record available before the intervention, including code, logs, and progress notes, and must choose between the two plans and justify the choice. This design has several strengths. It avoids the instability of scoring open-ended generations by reducing the task to contextual preference judgment.
