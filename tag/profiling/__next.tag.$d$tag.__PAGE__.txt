a:T460,The core is the Floor First workflow, which first computes per-step latency floors from model dimensions, calibrated hardware rates, parallelism setup, and workload shape, then uses the gap (residual) between measured latency and the floor to prioritize optimization. It has four key components: 1) A triage workflow with explicit stopping rules that dispatches work to pipeline optimization or kernel optimization tracks; 2) A two-sided floor model with an optimistic bound (max of per-resource contention, assuming full resource overlap) and a pessimistic bound (sum of per-resource costs, assuming no overlap), where the measurement's position in the interval directly diagnoses resource overlap; 3) Wall-order analysis that compares deployment options by which resource binds first as load grows (KV capacity, KV bandwidth, weight bandwidth, compute) rather than just same-batch latency; 4) Roofline metric discipline that defines meaningful utilization metrics per phase and calibration protocols for triage thresholds.
