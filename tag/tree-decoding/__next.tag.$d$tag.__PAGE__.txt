9:T6a5,UBTree has two main ideas. The first is architectural factorization. Drafting is split into a unigram proposer, a bigram selector, and a tree constructor. The proposer is a block-parallel drafter in the DFlash style: it predicts candidate tokens for all positions in a drafting block independently, preserving the throughput advantage of parallel drafting. The selector then scores adjacent candidate-token pairs instead of restoring full autoregressive dependence. It uses proposer hidden states together with frozen target embeddings transformed by separate MLPs into predecessor and successor representations, and predicts transition scores for candidate pairs. The method also learns depth-dependent weights to combine proposer logits with selector scores, which effectively lets shallow tree levels rely more on marginal token quality and deeper levels rely more on local path consistency. The second idea is tree-native training. Instead of standard distillation on target rollouts sampled at inference temperature, UBTree uses high-temperature regenerated target trajectories and a renormalized KL objective. High-temperature trajectories expose more plausible alternatives beyond the top path, while renormalized KL focuses supervision on these meaningful alternatives rather than wasting signal on low-quality tail mass. The result is a drafter trained not just to produce one strong path, but to allocate probability mass across multiple branches that are useful for tree verification. TDES, or Target-Distilled Edge Scoring, addresses parent-child mismatch. DDTree is effectively parent-agnostic: a child token contributes the same score regardless of which parent path it extends, because scoring is driven by per-position token probabilities. GRAFT instead learns an explicit edge scorer distilled from target-model traces. The scorer takes candidate parent-child pairs from adjacent positions, together with contextual features, and predicts how compatible that transition is with the target model. Tree assembly then uses these edge scores, rather than only the product of marginal token probabilities, to select target-compatible paths under a node budget.

Mechanistically, this is a lightweight structural predictor that compresses local target preferences into a cheap model. It does not rerun the target and does not force the DLM drafter into autoregressive expansion. It patches the missing conditional dependency at the tree-assembly stage. That is the right intervention point, because the failure mode is not merely missing candidate tokens; it is incorrect attachment among already available candidates.

SABA, or State-Aware Budget Allocation, addresses budget misallocation. The paper models per-round throughput as a trade-off between draft gain and verification cost, then chooses the budget conditioned on the current decoding state. Easy rounds already have long accepted prefixes, so larger trees mostly add cost. Hard rounds benefit more from extra nodes, but only up to a saturation point. SABA predicts the utility of different budgets from state features and selects the throughput-optimal one online.

Overall, GRAFT leaves the DLM and the target verification mechanism unchanged. It focuses specifically on the mapping from one-pass future distributions to an executable draft tree. That decomposition is sensible and technically clean.d:T4a2,The main empirical claim is consistent end-to-end throughput improvement with very small overhead. That matters because it suggests the method is not trading away the cost structure of speculative decoding.

SABA shows that a fixed budget is not robust: the throughput-optimal tree size varies substantially across rounds. Dynamic allocation preserves most of the acceptance gain while avoiding unnecessary verification cost.
