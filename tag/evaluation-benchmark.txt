19:T7d8,There are three important design choices. First, evaluation is suite-level rather than item-level. Each episode is a six-problem contest under one total budget, spanning mathematics, competitive programming, and abstract reasoning, with 50 contests per domain. Problems are drawn from sources such as Omni-MATH, MathNet, and LiveCodeBench Pro, and mixed to induce heterogeneous resource demands. Second, the benchmark has both tool-free and agentic settings. In the tool-free setting, the budget is output tokens; in the agentic setting, the budget is actions in an interactive shell environment. This lets the authors compare pure generation-time allocation with tool-using allocation. Third, and most importantly, the paper uses matched single-problem calibration. For each problem, the same model is run in isolation under varying budgets to obtain empirical response curves. From these runs, the authors build two controls: an equal-allocation replay and a same-model empirical oracle. Equal allocation simply divides the total budget evenly across the six problems. The oracle is an offline diagnostic that selects a feasible set of observed single-problem successes under the contest budget, representing what the model has already shown it can do if allocation were ideal. Because the oracle is built from demonstrated successes of the same model, the gap between oracle and contest score is evidence of allocation failure rather than missing capability. The paper also studies lightweight online schedulers. Some improve mean performance in certain model-domain cells, but no fixed scheduler transfers uniformly across domains, suggesting that allocation policy is strongly domain-dependent. The trajectory analysis is also useful: under strong pressure, failures are often caused by exhausting the shared budget on other problems; under moderate pressure, failures more often come from stopping after partial progress. Both are allocation errors on problems the model can already solve in isolation.1a:T537,The main empirical pattern is unusually clean. Across 72 flagship model-setting-pressure-domain cells, the empirical oracle matches or exceeds actual contest performance in all 72 cells and is strictly better in 71. That indicates a persistent realization gap under shared budgets. A stronger result is that under moderate tool-free pressure, even naive equal allocation outperforms the model’s own contest policy for 3 of the 6 models. In other words, some models allocate compute online worse than a trivial uniform baseline. The paper also reports that five of six models cover more than half of the suite, yet only DS-Pro exceeds the descriptive 50% reference for resource-rational strategy updates, showing that broad coverage is not the same as rational allocation. Another important result is that general capability does not explain the gap: models within two points on a composite built from more than fifty benchmarks can differ by as much as 60.6 percentage points in Gap Ratio. So shared-budget competence is not well captured by standard capability rankings. In the online scheduler study, 6 of 9 model-domain cells show higher mean performance, but no scheduler works reliably across domains. Even without every table entry, the reported statistics are enough to show that the issue is systematic rather than anecdotal.1b:T4f2,The main contribution is the Causal-Generative Dual-Judge (CGDJ), a benchmark and evaluation framework with two complementary modules. The first is Explicit Causal Perception, which tests whether a model can identify and articulate causal structure from visual evidence. Since most video generators do not support interleaved video-text prompting, the authors introduce Flatten Temporal Video: multiple frames plus rasterized queries are packed into a unified image grid, turning the task into a directly judgeable visual QA setup. This forces the model to expose what causal relation it recognizes instead of hiding behind free-form continuation.

The second module is Implicit Generative Prediction. Given a causal antecedent, the model must generate the consequent future video. This tests whether the model can enact its putative reasoning in the pixel domain over time. The key idea is to separate “knowing” from “rendering.” A model may answer causal questions correctly yet fail to generate a causally valid rollout, or it may generate something visually plausible without robust explicit causal understanding. That decomposition is more informative for world-model claims than standard fidelity metrics such as FVD or static multimodal QA benchmarks.1c:T422,The contribution is dataset + harness engineering:
- Data mining merges NVD, GitHub Security Advisories, and CVEfixes; fix commits are resolved and pre-/post-fix snapshots are fetched via GitHub API.

- Five split strategies are shipped as JSONL: random, project-disjoint, temporal, deduplicated (Jaccard 0.8), and unseen CWE-family.
- A unified evaluation harness defines a single LlmPrediction schema across HF encoder classifiers, Ollama-served local generative models, and OpenRouter API LLMs; supports zero-shot/few-shot/RAG prompting.
- Contamination audit: for each model, test sets are partitioned into risky (CVE before cutoff) vs clean (after cutoff) subsets with leakage-aware reporting.1d:T7ad,方法上有三块。第一块是 ForgetEval。作者把 forgetting 拆成 5 个结构家族：supersession、decay、amnesia、purge、drift；再加一层 10 类 adversarial attack，例如 substring trap、prefix collision、paraphrase supersession、negation trap、temporal qualifier、identifier obfuscation、cross-lingual 等。每个 case 都是确定性的 dataclass：先写入 setup facts 和 distractors，再执行 mutation，再看 final query 的 top-10 recall 是否满足 must_contain / must_not_contain。整个评分不用 LLM judge，靠确定性字符串匹配完成，这一点很重要，因为它把“评测对象”和“评测器”解耦了。

第二块是 Adapter Protocol。作者定义了一个六方法接口，把不同 memory backend 统一到同一行为契约下。即便某个系统没有原生 supersede，也可以用 add+delete 组合实现并接受同样测试；没有某个 primitive 的系统则记为 N/A，而不是硬算失败。这个设计避免了把“接口缺失”和“实现错误”混在一起。

第三块是 13 种系统配置的架构比较。作者把它们归成几类：无删除、deterministic、vec-only、inscribe-time LLM、KG abstraction、joint、mutation-time LLM hook。论文的关键观察是三种 placement regime 呈现互补覆盖，而不是简单强弱排序。deterministic primitive 对 lexical/temporal 类问题足够，但在 canonicalization 上几乎失效；inscribe-time LLM 能在写入时把别名、改写、跨表述归一化，因此 canonicalization 类能做到 100%，但它无法理解后续删除意图；mutation-time hook 则在删除时调用 LLM，把自然语言删除命令映射到精确 mutation，因此能处理 intent-aware deletion，同时保持 recall hot path 不变。两种不同 backend 只要共享这个窄 JSON mutation hook，整体表现会收敛到接近的水平，这说明关键不是底层存储形态，而是控制面接口设计。1e:T7fb,The work has three main components. The first is ForgetEval. Forgetting is decomposed into five structural families: supersession, decay, amnesia, purge, and drift. On top of that, the benchmark adds ten adversarial attack categories such as substring traps, prefix collisions, paraphrase supersession, negation traps, temporal qualifiers, identifier obfuscation, and cross-lingual variants. Each case is a deterministic dataclass with setup facts, distractors, mutations, a final query, and must-contain / must-not-contain constraints. A case passes if the top-10 recall blob satisfies those constraints. Importantly, scoring is deterministic string matching rather than LLM judging.

The second component is the Adapter Protocol. It defines a six-method behavioral interface that allows heterogeneous memory backends to be compared under the same contract. Systems without a native supersede primitive can still implement it compositionally via add plus delete. Missing primitives are marked as N/A rather than counted as failures. This avoids conflating interface absence with implementation failure.

The third component is the architectural comparison across thirteen system configurations. These are grouped into regimes such as no-deletion, deterministic, vec-only, inscribe-time LLM, KG abstraction, joint, and mutation-time LLM hook.
