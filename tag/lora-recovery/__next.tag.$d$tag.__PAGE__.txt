9:T8a2,Edge0 的方案分三部分。

第一部分是 SSD 作为权重层级。作者把量化后的 expert safetensors 通过 mmap 方式映射，按需读取字节区间，峰值内存由 active experts 决定，而不是由总参数量决定。系统层面设计了多条执行路径：exact 路径作为正确性基线；staged 路径用固定 slot 的双缓冲做 decode 主路径，避免每步重建整层专家堆叠张量；hot 路径保留每层一部分高频专家在内存中；whole-layer 路径用于 prefill，一次性读入整层专家。这里的关键不是简单 offload，而是把量化布局、slot 复用、GPU 上索引映射、以及 OS page cache 一起设计成可切换的执行器。

第二部分是最核心的 prerouter。作者指出，朴素 streaming 的死结在于下一层路由依赖当前层输出，因此无法把 SSD 读取与当前计算重叠。Edge0 用一个小型 per-layer head，根据前一个 token 在第 N 层的状态，预测当前 token 在第 N+1 层会走哪些专家。更激进的一点是：这个预测不只是 prefetch hint，而是直接作为实际 routing 使用。这样 staged expert set 和 routed expert set 完全一致，不存在“预取错了再补读”或“丢 token”的问题。代价是路由近似误差被显式引入模型路径，因此需要专门训练让语言模型适应这种 replaced routing。

第三部分是 unmerged recovery LoRA。作者观察到，把 LoRA 合并进 int4 base 再重新量化，会抹掉大部分补偿效果。因此他们冻结 int4 基座，在 student routing path 上从 fp16 teacher 蒸馏一个低秩增量，并在推理时以并行 delta 的形式单独加载，而不是 merge 回基座。这个设计很工程，但逻辑很清楚：量化误差和路由替换误差都发生在 base path，补偿项必须保留更高保真度，不能再被一次 re-quantization 吃掉。

和已有 MoE offloading 或 hot-expert caching 方法相比，区别在于它不是只做缓存策略，而是把“预测路由”提升为模型定义的一部分，并配套训练 recipe。也就是说，I/O 可隐藏不是靠系统碰运气，而是靠模型接受一个可提前知道的路由机制。a:T8d9,Edge0 has three main components.

First, SSD-backed expert storage. Quantized expert weights are memory-mapped and fetched on demand, so peak memory depends on the active expert set rather than total parameter count. The system exposes several execution paths: an exact path as the correctness baseline; a staged path with fixed-slot double buffering for decode; a hot path that keeps a small set of popular experts resident; and a whole-layer path for prefill. The important detail is that this is not just generic offloading. The executor is built around quantized weight layout, slot reuse, GPU-side index remapping, and OS page-cache behavior.

Second, the prerouter, which is the core idea. The naive streaming bottleneck is that next-layer routing depends on current-layer outputs, so SSD reads cannot be launched early enough to overlap with compute. Edge0 trains a small per-layer head that predicts the next layer’s routing one token ahead from the previous token’s hidden state. More aggressively, the prediction is not used merely as a prefetch hint; it becomes the actual routing decision at decode time. That means the staged expert set and the routed expert set are identical by construction, avoiding fallback loads and dropped-token behavior. The cost is that routing approximation is now part of the model path, so the model must be trained to operate under replaced routing.

Third, an unmerged recovery LoRA. The authors argue that merging a LoRA into an int4 base and requantizing destroys most of the benefit. Their solution is to freeze the int4 base, distill a low-rank adapter from the fp16 teacher under the student routing path, and serve the adapter as a parallel delta rather than merging it back. This is a clean engineering choice with a clear rationale: both quantization error and routing-replacement error live in the base path, so the compensating path should not be passed through another lossy quantization step.

Compared with prior MoE offloading or hot-expert caching systems, the distinctive move is to elevate routing prediction into the model definition itself and train for it explicitly. The overlap between I/O and compute is therefore achieved by a learned routing mechanism, not by a best-effort systems heuristic.b:T6a0,The paper already provides several concrete scale numbers.
