9:T80d,The core idea is to replace an undivided single-agent loop with a structured multi-agent system, AutoSFT, built around two requirements: isolate execution from analysis, and maintain complementary analytical views during proposal generation. The paper first formalizes automated SFT data research. A base checkpoint M0 and an initial candidate pool D0 are fixed. At round t, a recipe Rt assigns sampling weights to examples in Dt, while newly written rows can extend the pool to Dt+1. Training always restarts from M0, producing Ct = train(M0, Rt). Evaluation under a fixed protocol returns benchmark scores, per-example failures, training dynamics, and comparisons to earlier rounds; this bundle is Ft. A research policy π then maps Ft and history H<t to the next data action at.

The authors define six data-engineering action types and use them as an analysis lens for what the agent actually explores. The single-agent baseline exposes two failure modes. First, execution and analysis compete for the same context window, so raw command outputs and logs consume context that should have been used for data diagnosis. Second, a single proposal stream reinforces recent local successes and leads to action collapse, mostly toward category reweighting.

AutoSFT addresses this with three agent roles. A meta-agent manages each round. An executor handles training, conversion, and evaluation separately, returning only file paths and short status summaries, which keeps low-value execution traces out of the main reasoning context. Analysis subagents inspect the same round from four complementary angles: training data, failure cases, training signals, and prior rounds. Each proposes one data action. A synthesis subagent writes new data for capabilities that are weakly covered in the current pool, which extends the search space beyond selection and repair. The paper adds these components incrementally under controlled settings so that performance changes can be attributed to system structure rather than to extra compute or altered training conditions.a:T609,The experiments are designed to test whether system structure changes the behavior of automated data research, not to maximize absolute benchmark scores. The corrected single-agent loop still reaches only one stable action family, mainly category proportion adjustment, and fails to sustain broader data operations such as repair, replacement, or capability completion. Adding the executor roughly halves context loss, supporting the claim that execution traces were crowding out analysis. Adding the multi-view analysis subagents broadens the action range and improves best IFEval by +6.5. Adding the synthesis subagent yields a further +3.4 on IFEval and +2.9 on IFBench by covering undersupplied capabilities.

The training setup is intentionally controlled. The trainer is a fixed three-epoch SFT script, and every recipe within a comparison is capped at the same token budget. Each round retrains from the same base checkpoint rather than continuing from the previous round’s model. This means research history is carried only through the data pool and recipe, not through model state, which makes attribution cleaner. The paper also tests transfer to code, where no ready-made capability taxonomy is available. In that setting, AutoSFT improves MBPP+ by +3.7 over a single-agent baseline that does not improve.
