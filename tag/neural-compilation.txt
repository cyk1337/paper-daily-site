19:Ta9b,方法上，PAW 由三个部件组成：伪程序生成器、LoRA 编译器、冻结解释器。整体流程不是让一个模型直接根据规格输出答案，而是先把规格整理成更稳定的中间表示，再生成任务专属参数，最后由小模型执行。

第一步是 pseudo compiler。它使用一个未训练的 4B Qwen3，通过固定模板把用户规格改写成 pseudo-program。这个 pseudo-program 由两部分组成：一段更清晰、去歧义的任务重述，以及少量输入输出示例。这样做的原因很直接：原始用户描述常常含糊、冗余、带 typo，直接拿来生成权重不稳定；先做一次离散化重写，相当于把自然语言规格投影到更规整的任务空间。

第二步是 LoRA compiler。这是论文真正训练的核心模型，也是一个 4B Qwen3 级别编译器。它读取原始规格和 pseudo-program，然后输出一组可注入解释器的 LoRA 参数。论文把这一步看成“从任务描述到神经二进制”的编译。相比前作用 prefix-tuning KV cache 作为程序表示，这一版改用 text-to-LoRA。作者明确比较后认为 LoRA 更强，因为它不是只在输入侧加条件，而是直接改变解释器内部线性层的行为，控制粒度更细，容量也更高。

第三步是 interpreter。解释器是冻结的小模型，主实验用 Qwen3-0.6B。运行时输入包括用户样本 x、pseudo-program 的离散部分，以及编译得到的 LoRA。也就是说，程序是“离散 token + 连续参数”的混合体。作者强调这个混合设计不是实现细节，而是关键抽象：离散部分负责鲁棒地表达任务语义，连续部分负责补足文本无法精确指定的行为边界。

训练数据方面，论文发布了 FuzzyBench，规模 1000 万样本，分 29 个主题版本，覆盖 800 多类模糊文本任务，包括分类、格式转换、解析、模糊匹配、自然语言命令、agent 工具使用等。数据是逐步扩展构建的，目标不是单一 benchmark，而是覆盖“可由自然语言规格定义、但难以用规则精确实现”的函数空间。这个数据设计很关键，因为编译器学的不是某个任务，而是从规格泛化到新任务的映射。

从建模角度看，PAW 和直接 instruction tuning 的区别在于：它不把所有任务都压进一个统一前向过程，而是显式生成任务特定权重；和元学习或 ICL 的区别在于：任务适配结果被固化成可保存、可版本化的程序文件；和普通 LoRA 微调的区别在于：LoRA 不是通过梯度优化得到，而是由编译器一次前向生成。这使它更像 hypernetwork 驱动的条件参数化系统。1a:T4eb,Its value for pretraining research is mostly architectural and paradigm-level. PAW reframes weights as a program representation, not just a repository of general capability. Instead of paying inference-time reasoning cost on every input, it shifts substantial work to compile time: a larger compiler maps a task spec into a small task-specific adapter, and a lightweight interpreter executes it repeatedly. That is a meaningful alternative to the standard autoregressive pattern of “one general model, one prompt, one forward pass per request.” The reported result that a 0.6B interpreter plus compiled adapters can match or exceed direct prompting of a 32B model suggests that some capability currently expressed as online contextual reasoning can be externalized into offline task specialization. For pretraining, this opens several directions: PEFT modules as executable intermediate representations, datasets for spec-to-weight compilation rather than only next-token prediction, and a cleaner separation between universal pretrained competence and compiled task-local behavior. It also connects naturally to hypernetworks, conditional weight generation, and the question of when in-context learning can be converted into persistent parameter updates.1b:Tb25,PAW consists of three components: a pseudo-compiler, a LoRA compiler, and a frozen interpreter. The system is not just prompting a model with a better template; it explicitly compiles a task into a hybrid neural program.

Stage 1 is the pseudo-compiler. An off-the-shelf 4B Qwen3 model, kept untrained, rewrites the user specification into a pseudo-program. This pseudo-program contains a cleaned task restatement plus a handful of input-output examples. The motivation is practical: raw user specs are ambiguous, verbose, typo-prone, and often unstable as direct conditioning signals. The rewrite step creates a more canonical discrete representation of the task before any weight generation happens.

Stage 2 is the LoRA compiler, the main trained component. It is also built on a 4B Qwen3-scale model. Given the original spec and the pseudo-program, it emits a LoRA adapter to be injected into the interpreter. This is the actual “program binary.” The paper positions this as a shift from text-only task conditioning to generated parameterization. Compared with the authors’ earlier prefix-tuning-based precursor, the current version uses text-to-LoRA and reports better performance. That choice matters: prefix tuning mainly conditions through the input side, while LoRA changes internal linear transformations of the interpreter and therefore offers finer control and more representational capacity.

Stage 3 is the interpreter, a frozen small LM, with Qwen3-0.6B as the main instantiation. At execution time, the interpreter receives the input x, the discrete pseudo-program tokens, and the compiled LoRA. So the program is explicitly hybrid: a discrete component for semantic anchoring and a continuous component for behavioral precision. The paper argues that this split is not incidental. The discrete part protects against ambiguity in the original spec, while the continuous part captures nuances that text alone cannot pin down reliably.

Training relies on FuzzyBench, a 10M-example dataset released with the paper. It is built incrementally across 29 thematic versions and covers more than 800 categories of fuzzy text tasks, including classification, format conversion, parsing, fuzzy matching, natural-language commands, and agentic tool use. This dataset is central because the compiler is not learning one task family; it is learning a mapping from task descriptions to executable task-specific parameterizations.

Conceptually, PAW differs from standard instruction tuning because it does not force all tasks through a single shared forward policy. It differs from ordinary LoRA finetuning because the adapter is not obtained by gradient descent per task, but generated in one shot by a compiler. And it differs from pure in-context learning because the adaptation result is persistent, versionable, and distributable as a file.1c:T80d,The headline result is the main accuracy-cost tradeoff. The paper reports that a Qwen3-0.6B interpreter running PAW programs reaches 73.78% exact match, outperforming direct prompting of Qwen3-32B at 68.70%, while using roughly one fiftieth of the inference memory. That is the key empirical claim: for this family of fuzzy functions, offline task compilation can be more effective than repeatedly invoking a much larger general model.

Deployment numbers are also concrete. In quantized form, the shared interpreter base is about 430MB in GGUF format, and each compiled program is about 23MB as a LoRA adapter. The system runs at around 30 tokens per second on a MacBook M3. The paper also describes a smaller GPT-2-based path that runs fully client-side in the browser via WebAssembly. These details matter because the work is making a systems claim about software packaging and local execution, not only a modeling claim.

The case studies cover output triage, custom classification, fuzzy search reranking, agent preprocessing, and creative generation. The agent preprocessing setup reaches 93% on ToolCall-15. The point is not a single benchmark win, but evidence that PAW is not limited to narrow label classification; it can also support tasks with tool-selection and preprocessing structure.

The paper further shows modality generality: by replacing only the compiler with a vision-language model and keeping the same interpreter, PAW can handle image-conditioned fuzzy tasks. That suggests the executable representation is not tied to text-only specifications; cross-modal understanding can be absorbed by the compiler while execution remains unified.

On ablations, the abstract already states that LoRA outperforms prefix-tuning as the program form. The most important experimental signal is not the absolute score itself, but the fact that a frozen 0.6B interpreter plus generated task weights can cross the performance level of direct prompting on a 32B model.
