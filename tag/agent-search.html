optimize_anything: A Universal API for Optimizing any Text Parameter

这篇工作要解决的问题不是某一个具体优化任务，而是更上层的接口与搜索范式问题：能不能把一大类“候选解可序列化为文本、质量可由程序化 evaluator 打分”的问题，统一成同一种 LLM 优化流程，并且在单任务搜索、跨任务联合搜索、以及对未见输入的泛化优化三种设置下都有效。作者针对现有方法各自割裂的局面下手：FunSearch / AlphaEvolve 主要做代码单任务进化，GEPA / MIPROv2 主要做 prompt 泛化优化，缺少一个同时覆盖 code、prompt、agent architecture、数值配置、图像文本表示等不同 artifact 的统一系统。论文的核心问题因此是：如何定义一个足够通用、又不丢失诊断反馈与搜索效率的 text optimization API，并让同一套 Pareto 式搜索机制在多种 artifact 上稳定工作。

评预训练不必精读，但 §4 消融值得看：它把 reward shape 对搜索效率的影响做得比多数 agent 论文更干净。

AgentSearchBench: A Benchmark for AI Agent Search in the Wild

这篇工作处理的是一个新但很实际的问题：在开放、异构、描述风格不统一的 agent 生态里，如何为给定任务找到真正能做成事的 agent。难点不在检索本身，而在“能力不可由文档直接读出”。很多 agent 的能力是组合式的、依赖执行过程的，同样的描述可能对应很不一样的真实表现，而描述差异很大的 agent 也可能完成同一任务。现有 tool retrieval 或 agent selection 设定通常默认功能边界清楚、候选池受控、任务可直接执行，这些前提都弱化了真实世界里最关键的语义-性能错位问题。

评只看任务定义和执行相关性构造即可；它提醒 Agent 检索不能继续拿 embedding 相似度当能力度量。
Bin Wu,Arastun Mammadli,Xiaoyu Zhang,Emine Yilmaz
