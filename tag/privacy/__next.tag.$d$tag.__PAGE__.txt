9:T59d,The method has two components: route and steer.

First, an ordinal granularity router predicts the appropriate disclosure level. The target is modeled as an ordered label space, such as A/B/C, ranging from abstention or very coarse disclosure to country/city level and then precise location disclosure. The router operates on a pre-generation hidden representation, typically the hidden state of the final prompt token at a chosen decoder layer. Using linear probing and ordinal regression, the paper shows that disclosure levels are recoverable and arranged along a common direction in representation space. This motivates projecting the hidden state onto a disclosure-granularity coordinate and routing it to a target level.

Second, a steering module applies route-specific hidden-state interventions during decoding so that the generated answer better matches the routed granularity. The framework is inference-time only: it does not require a separately fine-tuned model for each policy and does not depend on demonstration-heavy prompting. Compared with prompting, it acts more directly on internal generation dynamics; compared with training-based methods, it is cheaper to deploy and easier to adapt.

Technically, this is best understood as a representation-analysis-plus-activation-steering paper. The main novelty is treating contextual privacy as an ordered routing problem rather than a flat safe/unsafe classification task.a:T444,The experiments cover multiple VLM backbones. The paper then demonstrates that disclosure levels exhibit an ordered structure along a shared representation direction, which supports the router design. The server maintains a shared skill document d and a global experience document e. Each client has private train/validation splits and four LLM-based roles: an executor for task execution, a skill optimizer for local refinement, a sanitizer for privacy cleaning, and an auditor for private-value checking. Instead of uploading a rewritten full skill document, the client generates semantic commits: localized skill patches together with supporting experience summaries.

The pipeline has several stages. First, local skill evolution: the client executes tasks using the current global skill and global experience context, collects local successes and failures, and asks the optimizer to produce revisions. Second, two-stage privacy filtering: a sanitizer rewrites or removes sensitive content, and an auditor checks whether the commit still contains private values or environment-specific details. This is not formal differential privacy; it is semantic privacy filtering performed by LLM agents. Third, cross-round experience reuse: the server maintains a global experience document that accumulates reusable evidence over rounds and redistributes it to clients, reducing redundant rediscovery and making local optimization more informed. Fourth, experience-aware aggregation: the server uses a merge agent to combine commits with reference to the global experience document, rather than simply concatenating or voting over full documents. Fifth, version validation: a candidate updated skill is only published if it passes validation.

Relative to straightforward federated baselines, the key differences are the shift from document-level to commit-level updates, the inclusion of evidence alongside edits, and the explicit use of a shared experience memory.
