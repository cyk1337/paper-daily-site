9:T59d,The method has two components: route and steer.

First, an ordinal granularity router predicts the appropriate disclosure level. The target is modeled as an ordered label space, such as A/B/C, ranging from abstention or very coarse disclosure to country/city level and then precise location disclosure. The router operates on a pre-generation hidden representation, typically the hidden state of the final prompt token at a chosen decoder layer. Using linear probing and ordinal regression, the paper shows that disclosure levels are recoverable and arranged along a common direction in representation space. This motivates projecting the hidden state onto a disclosure-granularity coordinate and routing it to a target level.

Second, a steering module applies route-specific hidden-state interventions during decoding so that the generated answer better matches the routed granularity. The framework is inference-time only: it does not require a separately fine-tuned model for each policy and does not depend on demonstration-heavy prompting. Compared with prompting, it acts more directly on internal generation dynamics; compared with training-based methods, it is cheaper to deploy and easier to adapt.

Technically, this is best understood as a representation-analysis-plus-activation-steering paper. The main novelty is treating contextual privacy as an ordered routing problem rather than a flat safe/unsafe classification task.a:T444,The experiments cover multiple VLM backbones. The first important result is the probing analysis: linear probes trained on pre-generation hidden states outperform the model’s raw responses on contextual disclosure alignment metrics. That shows the appropriate disclosure level is often encoded internally even when the model does not express it reliably.

The paper then demonstrates that disclosure levels exhibit an ordered structure along a shared representation direction, which supports the router design. In the main evaluation, the route-and-steer framework improves contextual disclosure alignment over unmodified models and baselines, while better balancing over-disclosure and under-disclosure and incurring only modest alignment tax. The method also generalizes to DoxBench, suggesting the intervention is not tied to a single benchmark distribution.

The pipeline has several stages. Second, two-stage privacy filtering: a sanitizer rewrites or removes sensitive content, and an auditor checks whether the commit still contains private values or environment-specific details. This is not formal differential privacy; it is semantic privacy filtering performed by LLM agents. Third, cross-round experience reuse: the server maintains a global experience document that accumulates reusable evidence over rounds and redistributes it to clients, reducing redundant rediscovery and making local optimization more informed. Fourth, experience-aware aggregation: the server uses a merge agent to combine commits with reference to the global experience document, rather than simply concatenating or voting over full documents. Fifth, version validation: a candidate updated skill is only published if it passes validation.
