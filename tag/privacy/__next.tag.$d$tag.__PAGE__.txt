9:T4a9,The authors learn binary gates over attention heads while keeping all model weights frozen. Each head output is multiplied by a hard binary gate in the forward pass; gradients are passed through a sigmoid relaxation with a straight-through estimator. The objective penalizes configurations that exceed a target perplexity ratio while encouraging sparsity. The reported setup initializes all gate logits to 5.0, uses r=1.00, λ=1e-4, AdamW with learning rate 1e-2, batch size 8, and 1,000 optimization steps. The selected pruning mask is the one with the best observed batch-level perplexity ratio during training, not necessarily the final step. Memorization is measured with k-extractability: given the first k tokens, the model is counted as memorizing the sequence if greedy decoding reproduces the next k tokens exactly. The paper evaluates k=16, 32, and 50. For mechanism, it examines attention entropy, softmax saturation, agreement across heads, and the contribution of pruned heads to the residual stream. The key observation is that memorized sequences induce sharper attention and stronger cross-head agreement; pruning task-redundant heads weakens this coordinated retrieval signal.a:T59d,The method has two components: route and steer.

First, an ordinal granularity router predicts the appropriate disclosure level. The target is modeled as an ordered label space, such as A/B/C, ranging from abstention or very coarse disclosure to country/city level and then precise location disclosure. The router operates on a pre-generation hidden representation, typically the hidden state of the final prompt token at a chosen decoder layer. Using linear probing and ordinal regression, the paper shows that disclosure levels are recoverable and arranged along a common direction in representation space. This motivates projecting the hidden state onto a disclosure-granularity coordinate and routing it to a target level.

Second, a steering module applies route-specific hidden-state interventions during decoding so that the generated answer better matches the routed granularity. The framework is inference-time only: it does not require a separately fine-tuned model for each policy and does not depend on demonstration-heavy prompting. Compared with prompting, it acts more directly on internal generation dynamics; compared with training-based methods, it is cheaper to deploy and easier to adapt.

Technically, this is best understood as a representation-analysis-plus-activation-steering paper. The pipeline has several stages. First, local skill evolution: the client executes tasks using the current global skill and global experience context, collects local successes and failures, and asks the optimizer to produce revisions. Second, two-stage privacy filtering: a sanitizer rewrites or removes sensitive content, and an auditor checks whether the commit still contains private values or environment-specific details. Third, cross-round experience reuse: the server maintains a global experience document that accumulates reusable evidence over rounds and redistributes it to clients, reducing redundant rediscovery and making local optimization more informed. Fourth, experience-aware aggregation: the server uses a merge agent to combine commits with reference to the global experience document, rather than simply concatenating or voting over full documents. Fifth, version validation: a candidate updated skill is only published if it passes validation.
