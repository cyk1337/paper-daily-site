Are Online Skill and Memory Modules Always Worth Their Tokens? A Budget-Constrained Study of Web Agents

这篇工作讨论的不是如何再给 web agent 叠一个模块，而是一个更基础的问题：在固定测试时推理预算下，在线 memory / workflow / skill 模块到底值不值它们消耗的 token。很多在线 agent 方法把 actor 之外的开销当成“额外能力”而不是“预算占用”，只报告主 actor 的步数或成功率，却不把技能归纳、记忆检索、工作流注入、验证控制这些辅助调用的 token 一并计入。作者把问题重新表述为预算分配：同样的总 token，是拿去做在线技能/记忆机制，还是直接给 vanilla actor 更多 observe-act 轮次。这个问题对 agent 评测很关键，因为在线模块的收益依赖任务顺序、历史轨迹质量和模块调用频率，而这些都可能让看似更复杂的系统在真实预算约束下并不划算。

评这篇不教你造新 agent，但会提醒你别再拿“外挂模块免费”做实验；只看预算对齐设置和主表就够，很多 test-time scaling 结论会被它重算一遍。
Sina Hajimiri,Masih Aminbeidokhti,Jose Dolz,Ismail Ben Ayed,Issam H. Laradji,Spandana Gella,Nicolas Gontier

Revisiting Observation Reduction for Web Agents: Comprehensive Evaluation with a Lightweight Framework

这篇工作处理的是 web agent 里的 observation reduction 评测问题：HTML/DOM 观察极长，大家提出了很多裁剪方法，但真正决定端到端延迟的，不只是裁剪后 token 变少，还包括裁剪步骤本身的计算开销。现有工作很难系统比较，因为完整评测太贵。作者要解决的是，能否构造一个不依赖在线环境和大模型推理、但又能可靠预测端到端成功率的轻量评测框架。

评做 web/GUI agent 的应读：把“输入压缩”评测从昂贵 rollout 里拆出来很干净；只看 MFS 定义与相关性验证就够。

Escaping the Context Bottleneck: Active Context Curation for LLM Agents via Reinforcement Learning

LLM agent 在长时序任务中受“上下文瓶颈（Context Bottleneck）”与“Lost-in-the-Middle”影响：环境观测极度冗长高熵（网页 DOM、检索结果噪声），把原始信息不断堆进上下文会迅速降低信噪比，导致推理链条级联失败。现有被动记忆/检索式方法把上下文管理当静态检索问题，容易出现 retrieval bias，尤其难以召回与当前 query 文本不相似但因果关键的“reasoning anchors”。

评看 RL 学到的上下文裁剪策略与对照：它改变我对“更大窗口就行”的 prior，动作是把 context curation 作为可训练小模型组件而非静态检索。
