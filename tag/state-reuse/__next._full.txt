18:T5e3,Tandem is a serving runtime built on llama.cpp + Qualcomm Hexagon for hybrid models whose history is summarized into a fixed-size recurrent state.

1) Cross-request reuse via divergence-point checkpoints: consecutive GUI-agent requests share instructions/task context but often diverge earlier than the last message boundary (screen tree and recent actions get rewritten). A checkpoint saved after the changed region is unusable because the recurrent state has already absorbed the differing tokens. Tandem identifies the divergence point between consecutive prompts and saves the recurrent state exactly there, then consolidates input batching to avoid extra passes induced by chat-oriented checkpoint policies.

2) Speculative decoding without sacrificing matrix prefill: only a short recent window needs rollback states. Tandem keeps most prompt processing on the matrix unit and uses a per-token “tail” only to materialize rollback states for that window (rollback-aware prefill). For verification, it introduces a column-shared kernel that reads each weight block once and verifies multiple drafts together, reducing bandwidth and redundant weight reads. It also trims the draft vocabulary to reduce proposal cost and uses operator fusion to cut intermediate memory traffic.

3) Idle power management: it keeps weights resident but releases the NPU session’s active power requests between bursts, allowing the accelerator to sleep; the next task reactivates execution without reloading the model.19:T4e6,AdaPLD modifies both stages of reuse-based model-free SD.
1) Adaptive retrieval (lexical-first, semantic fallback): use exact token matching on the most recent token as an anchor to retrieve prior positions in the unified memory (prompt + generated history). Only when lexical retrieval yields no candidates does it invoke semantic retrieval via representation similarity, expanding reachability while preserving the precision/latency profile of lexical matching. Candidates are then reranked by hidden-state similarity to pick an anchor most compatible with the current decoding state.
2) Adaptive reuse (draft tree instead of single span): starting from the selected anchor, it (a) copies a main continuation span when the anchor is lexically matched; (b) adds a small set of branch tokens sampled/selected from the target model’s next-token distribution to hedge ambiguity; (c) performs a successor reuse step to extend branches by one more reused token when alignment exists in memory. The resulting small draft tree is verified in one target-model pass using tree attention.
