b:T64d,The method has two main pieces: a lightweight patch selector called ReVision Token Selection (RTS), and end-to-end fine-tuning of an MLLM on filtered trajectories. RTS is a 3-layer MLP that takes the embeddings of corresponding patches from two consecutive screenshots and predicts whether the current patch is redundant given the previous frame. The design choice here is important: the model does not perform global image compression or frame dropping. Instead, it keeps the original patch grid and removes only redundant patches at aligned spatial locations, which preserves compatibility with an existing backbone such as Qwen2.5-VL-7B.

After training RTS, the selector is inserted into the data pipeline. Historical screenshots in AgentNet trajectories are filtered patch-wise, and the MLLM is fine-tuned directly on these compact visual histories. This is a stronger setup than post-hoc token pruning at inference time, because the model is exposed during training to temporally sparse visual evidence and can learn to integrate information distributed across multiple steps.

Relative to common baselines, the contribution is fairly clean. It does not simply reduce the number of history images; it reduces redundancy within each image so that longer temporal context fits under the same budget. It does not rely on hand-crafted pixel differencing; redundancy is predicted in embedding space, which is closer to the model’s own representation. And it does not modify the backbone architecture, so the gains can be attributed mainly to temporal token filtering plus training on the filtered distribution.c:T61b,Experiments are run on OSWorld, WebTailBench, and AgentNetBench with Qwen2.5-VL-7B as the base model. The motivating analysis is already useful on its own: consecutive GUI screenshots contain 45.4% unchanged patches on average, and in some settings the redundancy exceeds 56%, corresponding to more than 1,000 redundant patches per step.

On the main benchmarks, using 5 history screenshots, ReVision reduces visual token usage by about 46% on average while improving success rate by roughly 3 percentage points over the no-drop baseline. With only 3 history images, it reaches performance close to some stronger baselines while using about half as many visual tokens. The more interesting result is the trend with history length: once the history grows to 5 images or more, ReVision consistently outperforms most same-scale baselines by at least around 2 points on average. The key takeaway is not a single headline number but the shift in the history-performance curve. Without redundancy reduction, performance appears to saturate early; with filtered histories, adding more past context continues to help. That supports the claim that prior saturation was driven by inefficient visual representations rather than by the irrelevance of history itself.
