19:T92c,方法很克制，核心是一个 frozen LLM 的单智能体闭环：写技能、检索技能、根据结果积累证据、再决定保留还是退役。系统里有四类对象。Skill 是 YAML 结构化技能，包含适用条件、关键 insight、常见坑和返回前检查项，并带向量表示用于检索。Meta-Skill 是更高层的写作规范，相当于给技能作者一个 schema lock 和风格先验。Capsule 记录一次任务-技能-尝试三元组的结果。Verdict 则由 critic 对失败样本做归因，判断某技能是 helped、hurt、neutral 还是 inapplicable，并给出 failure pattern。

每轮流程分五步。先在 held-out 集上做 eval pass，只路由 active skills，用来报告真实性能；再在 train split 上做 train pass，失败样本进入后续合成；critic 对失败 capsule 生成 verdict；synthesizer 从最近 W=6 轮的 verdict 中抽取模式并写新技能；最后 curator 根据证据日志做退役和容量控制。

真正有信息量的是四个 hygiene 机制。第一，pattern canonicalisation：对 critic 产出的 failure pattern 做相似度聚类和 union-find 合并，避免同一类 bug 被写成多个近重复技能。第二，outcome-driven retirement：对每个技能计算贡献分数 c_hat=(successes-failures)/trials，只有当试验数达到 N_min 后，且贡献低于负阈值 -tau，才退役。这比启发式“最近没用就删”更稳，因为它要求证据积累。第三，bounded active-cap：active skill 数量有硬上限 C，超出时淘汰贡献最低者，强制技能之间竞争检索位，避免库变大后 router 退化。第四，meta-skill authoring prior：不是单独做复杂 dedup，而是通过统一写作模板和风格约束，让新技能天然更规范、更少语义重复。作者的一个重要观察是，在这个规模下，显式 dedup 的收益大部分可被 authoring prior 吸收。

论文还有一个理论部分。命题 1 给出 non-divergence bound：如果没有有限 active-cap 和 retirement threshold，最坏情况下性能下界会变成 vacuous；只有 cap 和 threshold 都有限时，期望 pass@1 才能保证不会比 no-skill floor 低太多，误差项上界为 tau+epsilon+Cdelta。这个理论不复杂，但它把“为什么最小治理至少要有容量和退役”说清楚了。1a:Ta5f,Ratchet is a restrained design: a single frozen LLM runs a loop that writes skills, retrieves them, accumulates evidence from outcomes, and retires them when warranted. The system maintains four artifact types. A Skill is a structured YAML object with intent, applicability conditions, key insight, common pitfalls, and a verification checklist, plus an embedding for retrieval. A Meta-Skill is a higher-level authoring prior that provides a schema lock and stylistic guidance for writing new skills. A Capsule records one task-skill-attempt tuple. A Verdict is produced by a critic over failed capsules and labels whether a skill helped, hurt, was neutral, or was inapplicable, along with a short failure pattern.

Each round has five phases. An eval pass routes only active skills on held-out tasks and is used for reporting. A train pass runs on the train split and produces failures for synthesis. A critic converts failures into verdicts. A synthesizer looks at verdicts from the last W=6 rounds and may write new skills. A curator then updates contribution estimates and decides retirement or eviction.

The paper’s substance lies in four hygiene mechanisms. First, pattern canonicalization merges near-duplicate failure patterns using similarity-based union-find, so the same bug class does not spawn many redundant skills. Second, outcome-driven retirement computes a contribution score c_hat=(successes-failures)/trials and retires a skill only after it has accumulated at least N_min trials and its contribution falls below -tau. This is more stable than heuristic pruning because it requires evidence. Third, a bounded active-cap C limits the number of retrievable skills; if synthesis would exceed the cap, the lowest-contribution active skill is evicted. This forces competition for retrieval bandwidth and prevents degradation as the library grows. Fourth, a meta-skill authoring prior regularizes how new skills are written, reducing semantic duplication upstream rather than relying only on downstream filtering. One of the more interesting observations is that, at this scale, explicit deduplication is largely subsumed by the authoring prior.

There is also a small theoretical result. Proposition 1 gives a non-divergence bound showing that without both a finite active-cap and a retirement threshold, the worst-case lower bound becomes vacuous. With both in place, expected pass@1 cannot drift arbitrarily below the no-skill floor, with an error term bounded by tau+epsilon+Cdelta. The math is modest, but it clarifies why capacity control and retirement are the minimal governance primitives rather than optional engineering extras.1b:T766,The main experiment is on MBPP+ hard-100 using Claude Opus 4.7 as a frozen backbone. The no-skill baseline achieves a 10-round rolling-mean held-out pass@1 of 0.258±0.047. Ratchet reaches a late-window rolling mean of 0.584 over 100 rounds, with a 3-seed mean gain of +0.328±0.018. A forced-no-skill control improves by only +0.002±0.005, which is important: the gain is not from repeated attempts or evaluation noise, but from the managed skill library.

The paper also reports a peak lift of about +0.22 on SWE-bench Verified with an agentic solver. That is presented as evidence that LLM-authored libraries can close much of the gap to human-curated skills. This result is promising, though it should be read with some caution because SWE-bench pipelines are often sensitive to setup details and variance.

The ablations are the most informative part. Eight ablations isolate what the “librarian” actually does. The meta-skill authoring prior is clearly load-bearing: removing it costs -0.141, suggesting that standardized authoring materially improves retrieval quality and reduces redundancy. Retirement also matters, but overly aggressive retirement hurts; a harsh retirement setting costs -0.019, implying that early pruning can discard skills before enough evidence accumulates. Explicit deduplication is not the main bottleneck at this scale because the authoring prior already captures much of its benefit. Frequent meta-skill refresh in A8 yields only marginal gains while increasing wall-clock time by about 55%, so high-level authoring priors do not need to be rewritten often.

Another strong design choice is the train/eval separation. Skills are synthesized from failures on the train split, while reported performance comes from a held-out eval pass. That makes the empirical claim more credible than many agent papers that effectively learn and test on the same stream.1c:T4c1,For a fast read, start with the Introduction’s restatement of the SkillsBench result, then look at Figure 1 and the five-stage method, and finish with the ablation table. That is enough to capture the paper’s main claim: the bottleneck is the librarian, not the author.

For a closer read, focus on three places. First, the Curator and the retirement rule: this is where the paper makes its strongest argument for evidence floors and bounded capacity. Second, the Meta-Skill design: it effectively turns skill writing style into a higher-level data schema, which is conceptually close to template control in synthetic pretraining data. Third, Proposition 1: the theory is lightweight, but it helps separate necessary governance from optional implementation detail.

Two deeper questions are worth keeping in mind.
