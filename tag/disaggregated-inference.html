Topology-Aware Data Movement for Disaggregated GPU Inference

要解决的是：在“prefill 与 decode 分离”的 disaggregated GPU 推理架构里，每个请求都要把 KV cache 从 prefill 池搬到 decode 池。KV 体量很大（例如 Llama-3-70B、4K prompt 时 2.6GB/req），而 GPU 集群互联是分层拓扑，带宽差异可达 72×。现有系统把传输当成均匀 RDMA 问题，导致要么浪费 NVLink 级带宽，要么选错传输方式直接不可用。论文提出需要一个“拓扑感知”的 KV 传输编排层。

评值得看系统设计和带宽数字；它提醒 pretrain 侧别把 KV 形状、MoE placement 和 serving 拓扑割裂设计。
Sanjeev Rao Ganjihal

Lynx: Progressive Speculative Quantization for accelerating KV Transfer in Long-Context Inference

这篇工作处理的是长上下文、分离式推理里的一个具体瓶颈：Prefill 端生成的 KV cache 需要跨网络传给 Decode 端，而 Decode 往往必须等整份 KV 到齐后才能开始。上下文一长，KV 体积线性增长，网络传输就会直接暴露在首 token 延迟里。已有 KV 量化方法虽然能缩小传输量，但通常在两点之间做艰难取舍：要么压得狠、延迟低，但注意力误差变大，生成质量掉得明显；要么保守量化，精度较稳，但 TTFT 改善有限。Lynx 试图打破的不是单纯“如何把 KV 压得更小”，而是“KV 是否必须作为一个不可分割的整体被完整接收后才能使用”这个系统假设。

评渐进式 KV 传输的思路对长上下文 serving 系统设计有启发，重点看 §3 的比特位重要性分析和系统架构部分。

NetKV: Network-Aware Decode Instance Selection for Disaggregated LLM Inference

当前主流的LLM推理解耦架构将计算密集的预填充阶段和显存带宽受限的解码阶段部署在不同的GPU池，预填充阶段生成的KV缓存需要跨数据中心网络传输到解码实例，传输时间直接成为首token延迟（TTFT）的主要组成部分。现有调度器仅基于计算负载和前缀缓存局部性选择解码实例，忽略了预填充与解码实例之间的拓扑距离和动态网络拥塞，在长上下文场景下会导致严重的性能损失。

评仅对做推理调度系统的团队有参考价值，预训练研究员不需要深究，看摘要和实验结论即可
