9:T7f1,The setup starts from a standard generative recommendation pipeline. Each item is encoded into an L-level SID using an RQ-VAE-style hierarchy. The tokenizer is extended with L×K SID tokens so the LLM can both read and generate SIDs. Training uses a single-stage causal LM objective over three sequence types: interleaved text/SID sequences, single text-SID pairs in either order, and SID-only sequences. This gives one model the ability to model user sequences, generate item IDs, and align IDs with text.

The key change is PrefixMem, a lightweight SID encoder applied before SID tokens enter the transformer. For a SID token at level l, the encoder hashes the preceding SID prefix into sparse prefix n-gram memory tables and retrieves a prefix-conditioned vector. That vector is added to the token embedding. As a result, the same code receives different input representations under different prefixes.

This design choice matters. The model is not asked to infer prefix semantics purely through self-attention over flat token embeddings. Instead, the prefix-conditioned structure is injected directly at the input interface. The memory tables are sparse lookup parameters, so pretraining the encoder is cheap and does not require transformer FLOPs. The encoder can also be trained independently on the item corpus and then transferred across LLM families.

The paper also compares alternative SID encoders, including transformer-style variants. The takeaway is that hash-based memory works better for this problem setting. The reason is not that transformers are weak, but that the bottleneck here is efficient, scalable, prefix-conditioned memorization over a huge sparse hierarchy. A sparse memory table matches that structure better than a heavier sequence encoder. The method is also explicitly complementary to constrained decoding and smart embedding initialization: constrained decoding enforces valid outputs, initialization helps cold-start embeddings, while PrefixMem addresses the missing prefix-conditioned semantics.a:T626,Experiments are run on billion-scale Pinterest data and cover multiple LLM families, including Qwen, Llama, and Gemma. The headline results are fairly clear.

1) At matched compute, PrefixMem improves deepest-level SID accuracy by up to 46% relative and full-SID retrieval recall by up to 22% relative.
2) The gains are concentrated on hard examples where greedy decoding usually fails. On those cases, accuracy improves by up to 77% relative. This is important because it suggests the method is not merely smoothing easy cases; it is helping precisely where prefix ambiguity is most harmful.
3) SID-to-text grounding also improves substantially, with BLEU up by 33%. That supports the claim that the encoder helps the model understand what SIDs mean, not just continue code sequences.
4) In parameter-efficiency terms, a 0.6B model with PrefixMem outperforms a 4B model without a SID encoder. This is arguably the most persuasive result in the paper because it directly compares structural input modeling against backbone scaling.

The ablations are also informative. Hash-based memory outperforms transformer-based SID encoders, reinforcing that the key requirement is scalable prefix-conditioned lookup rather than a more expressive sequence model. The encoder is pretrained independently and transferred across LLM families, which suggests the benefit is not tied to one specific checkpoint.
