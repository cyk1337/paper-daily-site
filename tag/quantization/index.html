Is 2:4 Sparsity Still Worth It? Semi-Structured Sparsity versus Quantization in LLM Inference

这篇文章回答的是一个很具体、但在 LLM 推理压缩里一直没有被讲透的问题：在 NVIDIA 支持 2:4 半结构化稀疏的前提下，从某个已有精度出发，下一步到底应该加 2:4 sparsity，还是直接降到更低 bit 的稠密量化？作者认为过去很多比较都不公平，因为没有把稀疏元数据算进存储成本，也没有把在线 pruning/quantization 的运行时开销算进去，更没有按硬件真实允许的稀疏轴来比较。全文的核心结论很明确：只要硬件上还有更低的 dense precision 可用，继续降精度通常比加 2:4 更划算，既更准，也更快；2:4 真正有价值的场景主要出现在已经到达 quantization floor 之后。

评把“稀疏 vs 降比特”用等 bits（含 metadata）+跨代 kernel 实测讲清了；部署决策直接照结论改，重点看误差随 bits 的对比图表。

Right On Q: Recovering Reasoning under Quantization via Self-Generated Trajectories

这篇工作处理的是一个很具体但很实际的问题：低比特量化后的推理模型，哪怕经过常规 QAT 和 teacher distillation，长链路 reasoning 仍然恢复不好，常见表现是准确率掉得多、回答变长、反复打转、在 full-precision 模型能正常收束的 token budget 内无法结束。全文把原因拆成两层。第一层是 trajectory divergence：训练时如果只在固定参考答案前缀上做蒸馏，学生在真实生成时很快会落到自己产生的前缀上，越长的推理链偏移越大，teacher 从未在这些前缀上教过它。第二层是 distributional misalignment：在这些学生自生成前缀上，量化学生对 next-token 分布会同时出现两类误差——有些候选被严重低估，有些被严重高估，而单一方向的 KL 只能偏向修正其中一边。这两个问题叠加，导致低比特模型在 reasoning 里不是简单的“精度差一点”，而是生成动力学已经变形。

评量化推理模型时别只看teacher-forced loss；读on-policy轨迹和Dynamic KL部分，可能要进内部QAT ablation。
