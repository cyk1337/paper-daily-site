Repairs for Whom? Evaluator-Executor Mismatch in Selecting Repairs for Failed LLM Agents

这篇工作讨论的不是“怎么生成 repair”，而是一个更前面的选择问题：当失败轨迹和候选单步修复都已经给定时，应该用谁来评估这些 repair 的价值。现有做法常用 greedy replay、更强模型、环境 oracle、verification rule 或 LLM judge 来替代真实部署策略，但 repair 的收益是明显依赖 executor 的：同一个替换动作，后续由哪个策略继续执行，会改变最终成功率、奖励，甚至改变“应该修哪一步”的标签。论文要解决的核心问题，就是量化这种 evaluator–executor mismatch 会带来多大决策遗憾，以及这种错配是否只是 value estimate 偏差，还是会真实改变 repair 选择。

评这不是 pretrain 论文，但它把“更强 judge/更强 evaluator 一定更好”的 prior 拆掉了；只看实验设定和主表就够，后续做 self-repair、verifier 或 RL credit assignment 都该记住这个坑。
Yijun Liao,Fanwei Liang

AuditRepairBench: A Paired-Execution Trace Corpus for Evaluator-Channel Ranking Instability in Agent Repair

这篇工作研究 agent 代码修复评测中的一种排名不稳定来源：一些 repair agent 在内部候选选择阶段读取了评测器产生的信号，导致排行榜排名会随评测器配置变化而显著重排。

评看 corpus 定义和 ranking flip 指标；它提醒 repair agent 评测里 evaluator 泄漏比模型差距更能改排名。
