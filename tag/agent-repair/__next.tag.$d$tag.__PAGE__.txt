9:T7e6,方法设计很克制，重点在评估协议而不是新模型。论文先把单步 repair 定义为在历史 h_t 处把原动作 a_t 替换为 a'，之后由 executor e 继续完成剩余 episode。核心目标不是 post-repair success probability，而是 net gain，也就是 p_e(h_t,a') - p_e(h_t,a_t)。这样做的原因很关键：原动作在重跑时也可能成功，如果只看修复后的成功率，会把本来就可能成功的部分也算到 repair 头上；而且不同位置的 baseline 不同，只看 post-repair success 会改变 repair 排序。

在评估协议上，作者固定三样东西：失败轨迹、候选单步 repair 集合、部署 executor e0。然后对每个候选 repair，用不参与选择的独立 rollout 估计其在 e0 下的真实净收益，作为 matched target。各类 evaluator 只负责打分和选 repair，不能使用这些独立标签。最后比较 evaluator 选中的 repair 与 matched selection 之间的 deployment value gap，也就是 decision regret。

论文考察的 evaluator 很全，包含：1）部署模型自身的 greedy replay；2）替代 executor 的 rollout，例如用更强的 Qwen2.5-14B 去评估给 7B 部署模型用的 repair；3）不同家族模型互评，如 Qwen2.5-7B 与 Llama-3.1-8B 互相为对方选 repair；4）环境 oracle；5）已有 verification rule；6）只读失败日志的 LLM judge。作者还做了 cross-fitted selection loss 和预注册分析计划，尽量避免“先看结果再挑 case”的偏差。

一个很重要的技术点是，他们不仅比较 value estimate 是否相关，还专门找 preference reversal：两个 evaluator 是否会在同一失败案例上偏好相反的 repair。新鲜 rollout 结果表明，这种 reversal 真实存在，不是估计噪声。另一个细节是，他们区分 unscreened failure pools 和 screened pools。前者不预先筛选“有修复价值”的失败，更接近真实部署；后者用于更广泛比较 evaluator，但不会掩盖主结论。a:T8a9,实验覆盖 gridworld、ALFWorld 和 WebShop，部署 agent 主要是 Qwen2.5-7B-Instruct 与 Llama-3.1-8B-Instruct，Qwen2.5-14B-Instruct 作为替代 executor 之一。关键结果有几组。

1）在未筛选的失败池上，greedy replay 即使用的是部署模型自己，也会有明显损失：相对 matched selection，在 ALFWorld 上损失 0.08–0.13 的 expected net success gain，在 WebShop 上损失 0.06–0.13 的 net reward。这里说明 deterministic replay 不能替代 rollout-based deployed-policy evaluation，因为 repair 的价值来自后续随机执行分布，而不是单条贪心轨迹。

2）更强模型替代弱部署模型也会错。用 Qwen2.5-14B 的每候选 5 次 rollout 来给 Qwen2.5-7B 选 repair，在 ALFWorld 上损失 0.25，在 WebShop 上损失 0.07。这个结果很有信息量：更强 executor 的 value function 不是弱 executor 的更低噪声近似，而可能是另一个目标函数。

3）不同模型之间的错配是双向的。Qwen2.5-7B 和 Llama-3.1-8B 在两个环境里互相给对方选 repair 都会产生损失。作者进一步分析发现，Qwen-14B 与 Qwen-7B 在部分 case 上会偏好相反 repair；而 Llama 更多表现为无法把 7B 真正需要的两个 repair 拉开差距。

4）增加 substitute executor 的 rollout 数只能缓慢缩小差距。20 个 14B rollout per candidate，在 ALFWorld 上选出的 repair 价值大致只相当于 7B 自己 1 个 rollout 的效果；在 WebShop 上还不如 7B 自己 2 个 rollout。这说明“多用强模型采样”不是高效补救。

5）少量 deployed-agent verification 很有效。论文后段分析了何时瓶颈在 evaluator、何时瓶颈在 candidate set。结论是，如果候选 repair 质量尚可，给每个候选加少量部署策略 rollout，能回收大部分 regret；但如果候选集本身缺少真正有用的 repair，再好的 evaluator 也无能为力。

6）标签层面的影响也被量化。executor 的变化不仅影响 repair ranking，还会改变 repair-location label 指向哪一步，并改变 benchmark 上“哪种 repair method 排第一”。这意味着很多 repair benchmark 的标签并不是 executor-invariant 的。b:T7b7,The technical contribution is mainly an evaluation protocol rather than a new repair model. A single-step repair is defined as replacing action a_t with a' at history h_t, after which an executor e completes the rest of the episode. The primary objective is net gain, p_e(h_t, a') - p_e(h_t, a_t), rather than post-repair success probability. This choice matters: the original action may still succeed on rerun, so a repair should only get credit for the extra success it adds; also, different positions have different baselines, so post-repair success can change the ranking across repair locations.

The protocol fixes three objects: the failed trajectory, the candidate repair set, and the deployed executor e0. For every candidate repair, the authors estimate its true value under e0 using independent rollouts that are never used for selection. Each evaluator then scores candidates using its own mechanism, and the selected repair is compared against matched selection, which uses the deployed executor’s own rollouts. The gap in deployed value is the decision regret.

The evaluator set is broad: greedy replay of the deployed model, rollout-based scoring with a substitute executor such as Qwen2.5-14B, cross-model evaluation between Qwen2.5-7B and Llama-3.1-8B, environment oracles, published verification rules, and LLM judges that only read the failed log. The paper also uses cross-fitted selection loss and a dated analysis plan to reduce researcher degrees of freedom.

A particularly useful part is the analysis of preference reversals. The authors do not stop at showing different value estimates; they test whether different evaluators actually prefer different repairs on the same failure case. Fresh rollouts confirm that such reversals are real. Another good design choice is the separation between unscreened failure pools, which better reflect deployment, and screened pools, which allow broader evaluator comparisons without weakening the main claim.c:T864,Experiments cover a gridworld, ALFWorld, and WebShop. 1) On unscreened failure pools, greedy replay already incurs nontrivial loss even when the evaluator is the deployed model itself. Relative to matched selection, greedy replay loses 0.08–0.13 expected net success gain in ALFWorld and 0.06–0.13 net reward in WebShop. This shows that deterministic replay is not a reliable proxy for rollout-based deployed-policy value.

2) A stronger substitute executor can still be a poor selector. Using five Qwen2.5-14B rollouts per candidate to choose repairs for a deployed Qwen2.5-7B loses 0.25 in ALFWorld and 0.07 in WebShop. The stronger model is not simply a lower-variance estimator of the weaker model’s value function; it can optimize a meaningfully different counterfactual.

3) Mismatch is bidirectional across model families. Qwen2.5-7B and Llama-3.1-8B both incur loss when selecting repairs for each other in both environments. The follow-up analysis is informative: Qwen-14B and Qwen-7B sometimes prefer opposite repairs, while Llama more often fails to separate the repairs that the 7B executor actually needs.

4) More substitute rollouts close the gap slowly. Twenty 14B rollouts per candidate produce repairs worth roughly as much to the 7B executor as one of its own rollouts in ALFWorld, and less than two of its own in WebShop. So brute-force sampling from a stronger substitute is not an efficient fix.

5) A small amount of deployed-agent verification recovers most of the loss. The later sections analyze when the bottleneck is evaluator mismatch and when it is the candidate set itself. If the candidate set already contains useful repairs, a few deployed-policy rollouts per candidate recover much of the regret; if not, better evaluation alone cannot help.
