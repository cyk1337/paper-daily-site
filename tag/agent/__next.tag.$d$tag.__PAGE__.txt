9:T41f,SpecAgent separates tool actions into read-only actions and state-changing actions. The weak model is allowed to execute read-only calls while drafting, because these calls do not modify the environment and can be removed from the history if they are wrong. When the weak model reaches the first state-changing action, such as submitting an answer or modifying a record, execution is paused. The strong model then reviews the drafted segment in one prefill pass, commits the longest semantically valid prefix, and repairs the first rejected step. This differs from routing, where one model still generates each step; from collaborative agents, which decide the actor step by step; and from conventional speculative agent methods, which often require exact agreement with the strong model’s own generated action. The key design choice is to accept alternative valid progress rather than only actions that match the strong model. The cost model relies on replacing sequential strong-model decoding with parallel strong-model prefill over drafted segments.a:Tadc,方法由两部分组成：IterSynth 范式本身，以及配套的 Role-Decoupled Policy Optimization（RDPO）。

先看 IterSynth。它把一次 deep search 拆成 Planner 和 Synthesizer 两个交替角色，但这两个角色不是两套模型，而是同一个 LLM 在不同 role prompt/格式下的两种行为模式。Planner 只看压缩后的 summary state，负责判断还缺什么信息、下一步该搜什么、何时继续探索。Synthesizer 读取新检索到的证据，对 summary 做增量更新：吸收有用事实、处理冲突、丢弃噪声、维护当前结论和未解决问题。这样，summary 不再是外部 memory module 的被动压缩结果，而是 agent policy 的显式输出和持久状态。

这个设计同时解决两个问题。对 role coupling，它通过角色分工降低单步决策的能力混杂度。Planner 不需要在长证据块里写最终答案，Synthesizer 也不需要决定全局搜索策略。对 context accumulation，它不再把完整历史一直塞回上下文，而是让 summary 成为受控、紧凑、可更新的状态表示。相比多 agent 系统，它不需要多模型协作和额外部署复杂度；相比已有 summary-based agent，它把摘要更新纳入训练目标，而不是把 summarization 当外接工具。

再看训练。作者采用 SFT → RL 的两阶段 recipe。SFT 的作用是教会模型 Planner–Synthesizer 协议、角色切换格式和基本迭代搜索行为，但作者明确指出 imitation 只能学会“怎么按这个协议行动”，不能充分优化“什么时候搜、搜什么、保留什么证据、两个角色如何协同”。因此引入 RDPO。

RDPO 的关键不是简单加一个中间奖励，而是按角色做 credit assignment。它把终局 outcome reward 和 turn-level rubric evaluation 结合起来，再分别为 Planner 和 Synthesizer 计算 group-relative advantages。这样做的动机很直接：Planner 的好坏更多体现在 query 是否有信息增益、是否识别到知识缺口、是否避免冗余搜索；Synthesizer 的好坏则体现在证据整合、冲突处理和 summary 更新质量。如果沿用普通 GRPO 或 outcome-only RL，两个角色共享一条回报，梯度会把不同错误来源混在一起，尤其在长轨迹里更严重。RDPO 通过 role-specific advantage 让更新方向更贴近各自职责。

从范式上看，这篇工作和 ReAct 的差异不只是“多了摘要”，而是把搜索过程从线性 action history 改成了围绕 summary state 的迭代闭环。和外部 summarizer 方法相比，它避免了摘要器与主 policy 目标不一致的问题。和多 agent 方法相比，它保留单参数集部署优势，同时通过角色解耦获得部分 specialization 收益。b:T9f2,The method has two parts: the IterSynth search paradigm and the associated Role-Decoupled Policy Optimization (RDPO) training objective.

IterSynth alternates between two roles, Planner and Synthesizer, instantiated by the same LLM rather than by separate models. The Planner reads only the compact summary state and decides what information is still missing, what to search next, and whether exploration should continue. The Synthesizer reads newly retrieved evidence and updates the persistent summary by integrating useful facts, resolving conflicts, filtering noise, and maintaining the current state of knowledge. In this design, the summary is not an external memory artifact. It is the explicit, learned state of the search process.

This addresses both target problems. Role coupling is reduced because planning and evidence integration are no longer forced into the same local decision. Context accumulation is reduced because the agent no longer carries the full search history forward; it carries a controlled, compact, updateable state instead. Compared with multi-agent systems, this avoids extra models and coordination overhead. Compared with prior summary-based agents, it makes summary updating part of the policy itself rather than an auxiliary external module.

Training follows an SFT-to-RL recipe. SFT teaches the Planner–Synthesizer protocol, role formatting, and basic iterative search behavior. But the authors explicitly note that imitation mainly teaches the interaction pattern, not the deeper decisions of when to search, what evidence to preserve, or how the two roles should coordinate. That is why they introduce RDPO.

RDPO combines terminal outcome rewards with turn-level rubric evaluations and computes group-relative advantages separately for Planner and Synthesizer actions. The motivation is straightforward: the Planner should be rewarded for identifying information gaps, issuing informative queries, and avoiding redundant exploration, while the Synthesizer should be rewarded for evidence integration, conflict handling, and summary quality. Standard outcome-only GRPO mixes these error sources together, which is especially harmful in long trajectories. Role-specific advantages make the gradient signal better aligned with each role’s responsibility.

Conceptually, the difference from ReAct is not just the addition of summaries. IterSynth changes the search loop from a linear action history into an iterative process centered on an explicit summary state. That is the main modeling contribution.c:T60c,The headline result is that IterSynth-8B reaches 50.7% average performance across five long-horizon deep-search benchmarks: GAIA-text-only, xBench-2505, xBench-2510, BrowseComp, and BrowseComp-ZH. This is 4.2 points above the strongest prior agent at 8B or below, while remaining competitive with several 30B-scale agents at less than one third of the parameter budget.

The training ablations are particularly informative. The SFT baseline scores 44.1%. Outcome-only GRPO raises this to 48.9%. RDPO further improves it to 50.7%. So RL itself contributes a large gain, and role-decoupled credit assignment adds another 1.8 points on top. The paper notes that this extra gain is strongest on exploration-heavy benchmarks, which suggests that RDPO improves search behavior rather than only answer polishing.

A key diagnostic appears in Appendix H: even with a 64K context window, more than 59% of ReAct trajectories on BrowseComp fail to terminate before context exhaustion. This directly supports the paper’s claim that the bottleneck is not simply context length, but the way search state is represented and updated.

The prompting-transfer results are also useful. IterSynth is not only a trainable 8B-agent recipe; it also works as a prompting paradigm for frontier models such as Claude-4.5-Opus and DeepSeek-V3.1, consistently outperforming ReAct and IterResearch, with gains of up to 10 points over ReAct on BrowseComp-ZH. The authors fix a ReAct-style coding-agent harness on a multi-tool aggregation task and evaluate protocol fidelity rather than task success. The design has three important pieces.

First, it separates channel from prompt. “Channel” means tool schemas are passed through the native tools= field and then rendered and parsed by the server. “Prompt” means the tool list and JSON call format are written directly into the textual prompt. The paper compares three settings: native, which uses tools= only; native+hint, which still uses tools= but also injects a plain-text tool list and strict JSON format instructions; and text-tools, which removes tools= entirely and parses calls from text. This isolates server-side protocol handling from the model’s ability to follow tool instructions.

Second, it refines the label space. Each assistant turn is categorized as valid in-schema call, hallucinated call, unparseable text, no-call prose, or non-response. The non-response category is crucial. In Ollama, some models trigger HTTP 400 request rejection before inference; the harness retries, gives up, and writes a generic error string into the trajectory. If that error is not preserved as structured metadata, downstream analysis can count it as a model non-call. The paper therefore excludes non-responses from the fidelity denominator and reports them separately.

Third, it performs a multi-stack comparison. The same weights and the same request behave differently under Ollama, llama.cpp, vLLM, and SGLang: some stacks reject tools=, some accept it but return calls as plain text, and some require explicit parser configuration before a call is recognized. The point is not to rank stacks, but to show that the measured outcome is stack-dependent.
