BLINDSPOT: A Benchmark for Safety and Refusal Calibration in Long-Horizon Tool-Using Agents

这篇工作解决的不是 agent 能不能完成任务，而是长时程、可调用工具、带状态环境中的“安全校准”该怎么评。现有 agent safety 评测常把结果压成 attack success 或 task success 两个标量，但在真实系统里，风险往往是多轮累积出来的：用户意图会漂移，授权会变化，工具返回内容可能带攻击，环境状态也会改变。此时真正需要判断的是 agent 何时该继续执行、何时该拒绝、拒绝是否过度，以及这些决策是否和轨迹上下文一致。Blindspot 把评测单位从单轮回复改成完整 trajectory，试图测的是 agent 在长时程交互中的安全边界是否稳定、是否校准。

评只看任务设计和裁决协议；它不会改预训练 recipe，但能提醒安全能力不能只用单轮拒答率估。

EVOHARNESSBENCH: Can Your Agents Keep Pace with an Evolving Harness?

这篇工作关注的不是 agent 在任务分布变化下能否持续学习，而是更贴近真实部署的一种非平稳性：外部 harness 会持续扩张，工具、技能和 specialist agents 会不断增加。问题在于，模型参数不变时，仅仅因为可用能力集合变大，agent 就可能在旧任务上退化，或者被早期积累的 memory / prompt / learned skill 误导，无法适应新能力。作者要解决的是如何系统评测这种 harness evolution 带来的 retention 与 adaptation 问题。

评视角独特的 Agent 评测基准，将 non-stationarity 从任务转移到了工具链（harness）上，更贴近真实世界 Agent 系统的迭代场景，做 Agent 评测的同学值得关注其 protocol 设计。
