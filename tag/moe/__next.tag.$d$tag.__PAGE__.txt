The model first routes each token to a small subset of attention columns, and then, within each selected column, applies standard MoE-style expert routing in the feed-forward path. Concretely, each block contains C columns, and a column router selects Kc active columns per token. Each column has its own attention parameters and computes causal attention only over the subset of tokens routed into that column. This creates two kinds of attention-side sparsity at once: parameter sparsity, because a token only uses a subset of attention parameters, and map sparsity, because attention is computed only within the routed token subset. Inside each column, each layer then has E experts, of which Ke are selected by an expert router, giving the usual MoE sparsity on the MLP side. For each token, among the Top-K selected experts, one expert is sampled as the leader according to normalized routing scores rather than deterministically taking the top-scoring expert. This prevents one expert from always dominating the unmodified update path. Second, gradient accumulation. Each expert stores a recent history of output gradients as an orthonormal basis using Gram-Schmidt, forming a compact subspace memory of past update directions. Third, gradient projection. The leader keeps its original task gradient. Each follower removes the component of its output gradient that lies in the leader’s accumulated gradient subspace, keeping only the orthogonal component. As a result, co-routed experts processing the same token are discouraged from moving in highly redundant directions.

This differs cleanly from prior work. It acts directly on expert output gradients that already exist in the standard training pipeline. In that sense, it is a backward-time intervention rather than a new objective. The extra cost comes from maintaining per-expert gradient bases and performing projections.
