18:T5ce,The interaction pattern is locate-correct-continue. An annotator reads a model response and marks the first inappropriate token. onPanda shows the model's top-k candidate tokens and probabilities at that position, with k defaulting to 20. If a suitable replacement is available, the annotator selects it; otherwise, the annotator writes a free-form replacement. The system truncates all later text and continues generation from the corrected prefix. The process repeats until the response is acceptable.

This differs from standard post-editing because the annotator does not repair a completed response after the model has already drifted. The continuation is re-rolled from the corrected prefix, so most final tokens remain model-generated. Each correction also creates a local supervision record: the bad token, the replacement, the prefix, and the model's candidate distribution. These records can be converted into SFT data, DPO pairs, reward-model data, or process-level supervision. Implementation-wise, onPanda is a componentized front-end library. It can run as a static web app or be embedded in an existing annotation platform. It requires an inference API that can continue from an assistant-message prefix and return token logprobs. A full annotation session is serialized into a single .panda.json file.
