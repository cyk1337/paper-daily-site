9:T620,NCE has three core components. First, it organizes the running context into addressable blocks. Each block is named by dedicated address tokens, and some blocks such as system prompts or tool declarations can be locked. Second, it defines an executable editing grammar inside the model vocabulary. The grammar includes address tokens plus operator tokens such as drop, rewrite, and append, together with composition rules for forming valid edits. A task-agnostic runtime maps each well-formed edit to exactly one context-state transition. This is the key design choice: edit semantics are not explained in the prompt or delegated to external tool schemas, but anchored in the model vocabulary and a fixed executor. Third, it builds supervision with a two-teacher pipeline. An offline teacher reads the full trajectory and assigns each block a release point, meaning the earliest turn after which the block can be safely edited because its role in the task has ended. An online teacher only sees the current context plus those release annotations and decides when and how to edit. The crucial training detail is evolving-context distillation: after an edit is generated at the end of a turn, the runtime executes it before constructing the next turn’s input and labels. This avoids conditioning future supervision on text that the model has already deleted or rewritten. The paper also includes a strong control baseline where the same edits are exposed as external tool calls, isolating the effect of native expression from the mere presence of an editing mechanism.a:T474,The evaluation covers four long-horizon agent benchmarks: Terminal-Bench 2.0, SWE-bench Verified, SWE-bench Multilingual, and SWE-bench Pro.
