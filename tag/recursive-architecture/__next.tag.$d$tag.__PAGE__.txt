9:T550,LCM uses a dual-state memory design:
- Immutable Store: append-only, verbatim persistence of every user/assistant/tool message; the single source of truth.
- Active Context: the prompt actually sent to the LLM each turn, composed of recent raw messages plus Summary Nodes for older history.
Older content is compacted into Summary Nodes produced by LLM summarization, but “lossless” means every summary retains pointers to the underlying raw messages, which remain reachable via tools like lcm_grep and lcm_expand. The memory is organized as a high-fanout DAG stored in a transactional, indexed persistent database (PostgreSQL in the reference implementation), enabling multi-resolution traversal of session history.
Key design choice vs RLM: RLM grants the model full autonomy to write recursive scripts (high expressivity, high variance, brittle in production, plus overhead on short queries). LCM constrains memory operations into a small set of deterministic, engine-executed primitives—analogous to structured programming replacing GOTO—trading theoretical expressivity for reliability and reproducibility.
