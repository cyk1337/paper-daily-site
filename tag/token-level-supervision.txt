分布差异的具体实现上，论文使用 top-K JSD，并带 residual bucket。这样做是为了避免全词表 JSD 的高成本，同时又不至于因为只看 top-K 而丢掉剩余概率质量。这个设计比直接比较 argmax 或 top-1 logit 更稳，因为 relevance 关心的是整个局部分布如何随语义变化而变化，而不是单一 token 是否翻转。

和最接近的 CREDIT 相比，区别主要有三点。其一，CREDIT 用 unrelated batch queries 做对比，语义变化和其他 nuisance factors 混在一起；CROP 用 paraphrase/counterfactual 配对，把“语义不变的表面改写”和“关键条件改变”分开。其二，CROP 在固定 rollout 上比较条件分布，强调 controlled contrast；其三，最终分数是 counterfactual sensitivity 减 paraphrase sensitivity，显式做了语义校准，而不是把任何输入敏感都当成高价值监督。论文还强调，CROP 不是在估计严格因果意义上的 token causal effect，而是在预算受限 OPD 里构造一个可操作、模型内部、对比受控的 relevance proxy。19:T7e8,CROP, short for Counterfactual Relevance for On-Policy Distillation, builds a token relevance score from controlled prompt contrasts. For each original prompt x, the method constructs an offline matched triplet: the original prompt x, a meaning-preserving paraphrase x_para, and a counterfactual prompt x_cf that changes one task-relevant condition. The student first generates a rollout y from its current policy on the original prompt. CROP then keeps that realized rollout fixed and rescoring is performed under all three prompts on the same response prefixes. This is an important design choice: the comparison is over conditional next-token distributions along the same trajectory, rather than over independently sampled responses, which reduces variance from trajectory mismatch.

At each token position, CROP measures how much the model’s next-token distribution changes under the counterfactual prompt and subtracts how much it changes under the paraphrase prompt. Intuitively, sensitivity to the counterfactual captures dependence on task semantics, while sensitivity to the paraphrase captures dependence on superficial wording. The resulting score is a calibrated relevance proxy rather than a generic input-sensitivity measure. Tokens are then selected globally under a fixed batch-level budget, and only those selected sampled tokens receive the teacher distillation loss. The teacher target and the OPD objective remain unchanged; only the allocation of supervision changes.

Distribution shift is computed with a top-K JSD plus a residual bucket. This is a practical compromise: full-vocabulary divergence is expensive, but top-K alone can ignore tail mass. Compared with CREDIT, the closest prior work discussed by the authors, CROP uses controlled original/paraphrase/counterfactual triplets instead of unrelated batch queries, and explicitly subtracts paraphrase sensitivity from counterfactual sensitivity. That makes the signal more targeted to semantic dependence rather than generic prompt variation.1a:T5e7,The empirical setup includes two teacher-student settings evaluated within the same budgeted OPD framework. The headline result reported in the paper is that CROP improves aggregate performance by 1.92 and 2.96 points over the strongest non-CROP selector. For a token-selection method inside distillation, that is a meaningful gain.

The most convincing evidence comes from matched token-selection controls. Under the same supervision budget, selecting the highest-relevance tokens consistently outperforms random selection, while selecting the lowest-relevance tokens performs substantially worse. This matters because it validates the ranking induced by the relevance score itself, not just the end-to-end training recipe.

Ablations show that counterfactual sensitivity is the primary signal and paraphrase calibration adds further benefit. In other words, semantic sensitivity already identifies useful supervision locations, and subtracting paraphrase sensitivity removes positions that react to wording changes rather than task content. The paper also adapts CREDIT into the same selector framework for a cleaner comparison.

The main limitations are also visible from the setup. The method depends on constructing and validating prompt triplets offline, which introduces extra pipeline cost. It also assumes that a meaningful task-relevant counterfactual can be defined for the prompt.
