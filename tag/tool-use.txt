- Data pipeline: start from ToolHop sub-questions with locally executable tool calls and verified intermediate answers; keep only self-contained facts with short verifiable answers.

The first is branch allocation. Rather than branching only around tool boundaries, the method scans local generation entropy across the whole response using fixed-interval windows to expose candidate positions. It then applies path-level and node-level decay to distribute a fixed branch budget, preventing the budget from collapsing onto a few trajectories or onto adjacent high-entropy tokens. The intuition is straightforward: entropy identifies places where the model is uncertain enough to justify exploration, but decay is needed to avoid redundant branching. The second component is local credit assignment. The paper defines an exact-prefix group: a parent trajectory and its branches that are identical up to a branching point and diverge only afterward. Reward variation within such a controlled group is used to define Contrastive Branch Value (CBV), an estimate of how sensitive the final outcome is to that local decision. CBV is standardized and bounded so that it changes the magnitude, but not the sign, of continuation advantages. Shared prefixes receive no branch gradient, and multiple branch nodes partition the parent trajectory into non-overlapping credit segments, which avoids repeatedly assigning credit to the same prefix tokens. In effect, CBPO augments trajectory-level GRPO-style updates with outcome-contrastive local modulation: not every token on a successful trajectory gets the same signal, and the strongest updates are reserved for suffixes where alternative continuations actually changed the result.1d:T43b,The evaluation covers two model scales and ten benchmarks: five tool-augmented math tasks and five knowledge-intensive search tasks. A single policy alternates between two task types. In build tasks, the model receives N=4 input-output examples and must infer a general procedure, then emit both executable Python code and an OpenAI-style JSON schema describing the callable interface. The generated tool is evaluated on K=16 held-out queries, so the model is rewarded for reusable abstraction rather than memorizing the demonstrations. In use tasks, the model sees only the schema, not the underlying code, and must invoke the tool to solve a new query. This is the key design choice: if the schema is ambiguous, underspecified, or poorly typed, the use task will fail, feeding a direct signal back into tool construction. Training uses DAPO, a clip-higher GRPO-style on-policy RL method intended to stabilize entropy and reduce reward collapse. Rewards are decomposed into three axes: execution accuracy, an LLM-judge score for schema/implementation quality and usability, and format consistency. The decomposition matters because schema failures, code failures, and answer failures are different error modes. To reduce circular evaluation, the judge is not tied to the live policy weights; instead, it is periodically synchronized from policy snapshots, allowing the evaluator to improve over time while remaining stable enough for training.
