19:T61f,CBPO has two main components. The first is branch allocation. Rather than branching only around tool boundaries, the method scans local generation entropy across the whole response using fixed-interval windows to expose candidate positions. It then applies path-level and node-level decay to distribute a fixed branch budget, preventing the budget from collapsing onto a few trajectories or onto adjacent high-entropy tokens. The intuition is straightforward: entropy identifies places where the model is uncertain enough to justify exploration, but decay is needed to avoid redundant branching. The second component is local credit assignment. The paper defines an exact-prefix group: a parent trajectory and its branches that are identical up to a branching point and diverge only afterward. Reward variation within such a controlled group is used to define Contrastive Branch Value (CBV), an estimate of how sensitive the final outcome is to that local decision. CBV is standardized and bounded so that it changes the magnitude, but not the sign, of continuation advantages. Shared prefixes receive no branch gradient, and multiple branch nodes partition the parent trajectory into non-overlapping credit segments, which avoids repeatedly assigning credit to the same prefix tokens. In effect, CBPO augments trajectory-level GRPO-style updates with outcome-contrastive local modulation: not every token on a successful trajectory gets the same signal, and the strongest updates are reserved for suffixes where alternative continuations actually changed the result.1a:T43b,The evaluation covers two model scales and ten benchmarks: five tool-augmented math tasks and five knowledge-intensive search tasks. The paper reports consistent gains over strong policy-optimization and branch-based baselines, with the best macro average in both domains. The more informative part is the ablation suite. The authors attribute the gains to two factors: better-balanced branch allocation, showing that fixed-window entropy candidates plus dual decay reduce budget concentration and nearby-node redundancy; and better local credit assignment, showing that CBV from exact-prefix reward contrast is more useful than coarse branch outcome propagation. The introduction also mentions cross-scale ablations, suggesting that the effect is not tied to a single model size. What is clear is that the experiments are designed to validate the two-way decomposition: branch placement and local credit are tested separately rather than bundled together.1b:T5ff,SMITH is a schema-grounded multi-task RL framework. A single policy alternates between two task types. In build tasks, the model receives N=4 input-output examples and must infer a general procedure, then emit both executable Python code and an OpenAI-style JSON schema describing the callable interface. The generated tool is evaluated on K=16 held-out queries, so the model is rewarded for reusable abstraction rather than memorizing the demonstrations. In use tasks, the model sees only the schema, not the underlying code, and must invoke the tool to solve a new query. This is the key design choice: if the schema is ambiguous, underspecified, or poorly typed, the use task will fail, feeding a direct signal back into tool construction. Training uses DAPO, a clip-higher GRPO-style on-policy RL method intended to stabilize entropy and reduce reward collapse. Rewards are decomposed into three axes: execution accuracy, an LLM-judge score for schema/implementation quality and usability, and format consistency. The decomposition matters because schema failures, code failures, and answer failures are different error modes. To reduce circular evaluation, the judge is not tied to the live policy weights; instead, it is periodically synchronized from policy snapshots, allowing the evaluator to improve over time while remaining stable enough for training. Another important choice is to evaluate tools built from easier examples on harder downstream queries, explicitly selecting for reusable interfaces and general procedures.1c:T58d,The main result is on 13 procedural task families from Reasoning-Gym. A 4B Qwen3 model trained with SMITH reaches 79.8% macro accuracy on held-out Reasoning-Gym, outperforming inference-time tool-writing systems such as LATM, CRAFT, Trove, and KTCE, as well as some models distilled from much larger teachers. The paper also claims that, despite using fewer decoding tokens, SMITH beats a 30B inference-time tool writer on unseen tasks, which supports the idea that internalized tool-building can be more efficient than regenerating tools at test time. Transfer results are broader than the training domain: zero-shot gains are reported on TabMWP-Hard and on GQA, with up to +7.6 points over same-backbone baselines on GQA, even though the model was not trained on tabular or visual data. The interpretation is less about visual understanding per se and more about transferable procedural/tool abstraction. There is also a cross-model result: tools written by the 4B policy help a frozen 350M model match the performance of a 30B tool writer, suggesting that the generated tools themselves are portable assets. The same recipe is reported to improve Qwen3-8B and Granite-3.3-8B as well. The most informative ablations are the ones showing that joint build+use training beats training either skill alone, reward decomposition beats a single reward, and schema-only use encourages cleaner interfaces than exposing raw code.1d:T7c5,The contribution is a benchmark and execution environment rather than a new model. The paper defines a mobile planner as the high-level decision core of an on-device assistant: it interprets user intent, retrieves long-term memory, invokes structured business APIs, loads reusable composite skills, and delegates specialized subtasks to GUI sub-agents when direct tool use is insufficient. Around this setup, the benchmark is organized into four capability dimensions. Basic Tool Use covers utility calls, multimodal input handling, strict execution order, permission boundaries, and OS feedback. Sub-agent Collaboration measures whether the planner can decompose tasks and hand them off to downstream specialists with valid context transfer. Memory Usage tests whether the agent can retrieve persistent user context—preferences, credentials, prior state—to resolve underspecified requests before planning. Skill Usage evaluates whether the planner can invoke packaged multi-step skills instead of replanning every primitive action, reducing long-horizon error accumulation.

Operationally, MobilePA-Bench runs in an executable sandbox with live application databases and structured feedback. The key design choice is to decouple central planning from low-level visual parsing. In other words, the benchmark is intentionally not centered on pixel understanding; it is centered on deciding when to call an API, when to query memory, when to invoke a composite skill, and when to fall back to a GUI sub-agent. This keeps the evaluation focused on planner quality rather than visual noise, while still preserving realistic friction such as call dependencies, permission blocks, and dynamic state mutations.

The benchmark itself contains 1,705 real-world tasks across 13 domains and 212 tools. A key design choice is outcome-based evaluation: multiple trajectories may be valid as long as the final backend state, required side effects, and dialogue constraints are correct.

The second layer is Thinkingbox-bench, a 507-task benchmark spanning retail/e-commerce, travel/hospitality, auto insurance, neobank internal IT support, and consulting IT/HR support. The reliability framing is central. pass@k measures whether at least one of k attempts succeeds, which captures discovery capability. pass^k measures whether all k attempts succeed, which captures repeatable reliability. That distinction is important because many agents can occasionally find a correct trajectory while remaining unstable under sampling noise or interaction variation.21:T56f,The main empirical result is a large discovery–reliability gap. The benchmark contains 507 tasks, and the authors evaluate 12 proprietary and open-weight models with 20 repeated trials per task. The strongest model reaches 65.36% pass@1, which is still far from dependable single-run performance. Its pass@20 rises to 91.12%, showing that many tasks are solvable at least once. But its pass^20 is only 25.25%, meaning only a quarter of tasks succeed in all 20 attempts. That gap is the central takeaway of the paper.

Because evaluation is tied to terminal backend state rather than a single final answer, the benchmark can expose failure modes that simpler tool-use benchmarks miss: updating the wrong entity, producing a convincing response while leaving the backend unchanged, missing a required side effect, introducing an extra side effect, executing high-impact actions before collecting confirmation, or generating a final message inconsistent with the actual execution outcome. The paper also includes evaluator ablations and failure analyses to show that fluent tool use is not the same as reliable work completion.

First, it builds an Interaction-State Transition Graph from teacher rollouts. Nodes are not single actions; they are cumulative interaction states, defined by the task-relevant information acquired so far. To make this possible, the method introduces information atom abstraction: tool outputs are canonicalized, semantically equivalent responses are mapped to the same atom, and non-informative outputs such as status-only or empty responses are collapsed away. This lets trajectories with different action orders but the same acquired information land on the same node, which naturally captures the diamond topology induced by order-independent sub-goals. Second, for a failed student rollout, the method performs success-reachable projection and identifies the Critical Topological Breakpoint. Instead of cutting by timestep, it asks whether each cumulative student state still lies in the region from which success is reachable in the empirical graph. The CTB is the point where the rollout leaves that success-supported region. Third, starting from a recovery anchor near the CTB, the method retrieves a success-supported continuation from the ISTG and applies localized supervision only to the recovery segment, while preserving the valid prefix. Training is progressive self-distillation: the student rolls out, exposes its current capability boundary, receives CTB-guided local correction, and gradually extends the length of valid interaction prefixes. Compared with vanilla SFT, supervision is localized. Compared with RL, the method does not rely on sparse reward propagation; it uses explicit graph structure extracted from teacher behavior.23:T47e,The study evaluates on five benchmarks and two model scales. A naive trace-similarity metric fails for five reasons: short traces look artificially similar, empty traces score perfectly, unrelated traces overlap by chance, same-language reruns are not identical, and without a within-language baseline the quantity is not identifiable.

The estimator addresses each issue explicitly. Every language-task cell is run twice with identical decoding settings and token budgets, changing only the serving seed. Same-language agreement, I_within, compares the two replicates in one language. Cross-language agreement, I_cross, compares traces across languages, also cross-seed. The normalized retention metric is \tilde{I}=I_cross/I_within, which measures how much of a model’s own reproducible policy survives a language change. Comparisons are length-matched in both directions, pairs are dropped if either trace is empty, and uncertainty is estimated with task-level bootstraps. This design makes language the only systematic difference while keeping decoding noise symmetric.
