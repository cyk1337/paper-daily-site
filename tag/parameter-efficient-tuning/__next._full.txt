17:T79b,LPM has two main components. First, each user u owns a persistent latent memory matrix M_u with N slots of dimension d_mem. In practice, the memory is split into H independent heads, each with its own slots and projection parameters, to avoid overloading a single memory bank. Second, a shared projection network turns those slots into prompts conditioned on the current input x. The input is embedded with a small frozen embedding model to produce epsilon(x). Then epsilon(x) attends over the user memory through cross-attention, using the input as query and the slots as key/value. Each head produces a retrieved representation, which is passed through an MLP and LayerNorm to match the hidden size of the frozen LLM. The resulting vectors are concatenated and prepended as soft prompts.

The key distinction from prompt tuning is that the prompt is not static. It depends jointly on the query and the user memory, so the same user can expose different aspects of memory for different questions. The training procedure is also carefully designed. User history is split into fixed-size chunks and processed sequentially. For chunk t, the model predicts next tokens using a prompt retrieved from the previous chunk, P_{t-1}, which prevents future-token leakage. Trainable parameters include the cross-attention projections, the MLP, LayerNorm, and the user-specific memory slots; the backbone LLM remains frozen throughout. To avoid attention collapse onto a few slots, the paper adds a hinge-style entropy regularizer: it penalizes low-entropy slot attention only when entropy falls below a target threshold. This is more sensible than forcing uniform attention, because memory retrieval should sometimes be sharp. Another notable engineering choice is to accumulate gradients for the shared projection network across users and update once per epoch, reducing noisy user-level updates and making the setup more compatible with federated training.18:T68c,The evaluation uses PersonaMem v1 and LoCoMo with frozen Qwen3 backbones at 1.7B, 4B, and 8B. The main empirical message is consistent across scales.

On PersonaMem v1, LPM outperforms both LoRA and prompt tuning. The abstract reports gains of up to 8.8% over LoRA and 54.4% over prompt tuning in overall accuracy. That gap is meaningful because LoRA is already a stronger personalization baseline than static prompts in many settings. It suggests that dynamic memory-conditioned prompting is a better fit than storing user information in small adapter weights.

LPM also approaches the accuracy of full-context inference while being much cheaper. The reported efficiency numbers are up to 64x smaller KV cache and 4x lower latency. This matters because the method is intended for long-horizon deployment, where inference cost grows with user history under full-context approaches.

On LoCoMo, LPM matches LoRA-level accuracy while using roughly 120x fewer trainable parameters. That result is more nuanced: it suggests that in some settings LPM is not strictly more accurate, but it can reach similar quality with a much smaller per-user footprint.

The paper also claims interpretability through latent slots and multiple heads. If the appendix includes slot visualizations or attention patterns, those are worth checking, because interpretability is otherwise easy to overclaim in latent-memory systems. The most informative ablations are likely the number of slots, number of heads, chunk size, and the entropy regularizer strength, since those determine whether the memory is actually compressing useful long-range information rather than acting as a weak prompt adapter.19:T5c7,The workflow has three parts:
1) Discovery via controlled layer-wise ZO tuning: using the standard two-point SPSA/MeZO-style estimator, they run ZO fine-tuning while updating only one layer at a time (all other layers frozen), keeping the same ZO hyperparameters across layers. This produces a layer-wise “utility profile” for ZO.
2) Characterization: the dominant layer is largely task-agnostic for a fixed model (same layer wins across tasks) but model-specific across families (layer index changes between LLaMA2-7B and Qwen3-8B). In contrast, FO fine-tuning distributes gains more broadly, indicating the dominance is not simply “this layer is universally most important”, but a ZO-specific phenomenon.
3) Pre-training identification: they connect the dominant layer to activation outliers. With a small calibration set and inference-only forward passes, they compute layer-wise activation statistics and pick the first layer exhibiting a clear outlier pattern; empirically this matches the dominant layer.
Their explanation centers on ZO estimator reliability: ZO updates depend on how strongly a parameter perturbation changes the final loss. Perturbations injected earlier into the residual stream propagate through all subsequent layers and can be repeatedly transformed/accumulated, yielding larger and more stable loss differences. The first outlier layer appears to be where this amplification becomes pronounced, making ZO gradient estimates higher-SNR there.1a:T6eb,The work has two components. The first is a routing analysis built on OLMoE-Base, a decoder-only MoE model with 64 experts per MoE layer and top-8 routing, originally pretrained on roughly 5T mostly English tokens. The authors continue pretraining it on a balanced 35B-token multilingual corpus covering seven languages. They then collect post-softmax routing probabilities on held-out documents and analyze how routing mass is distributed across experts, layers, and languages. The focus is not merely which expert wins top-1 routing for a token, but how language-level routing distributions evolve, how similar those distributions are across languages, and where specialization concentrates in depth. The main empirical finding is that multilingual continual pretraining makes routing more diffuse and shared in early and middle layers, while language-specific structure emerges primarily in the final layers. They further relate routing similarity to token-level vocabulary overlap, suggesting that shared subword structure materially shapes expert sharing.

The second component is a parameter-efficient adaptation method, Selective and Shared Expert Finetuning (SSFT). The key design choice is to update both language-specific experts and shared experts in the final layers, rather than only the experts most associated with the target language. The rationale is straightforward: if late layers encode both language-specific behavior and cross-lingual abstractions, adapting only specialized experts leaves useful shared capacity untouched. SSFT is therefore a routing-informed adaptation strategy. Its real contribution is not a new optimization trick, but a better answer to the question of which MoE parameters should move during low-resource language adaptation.1b:T59a,The experimental setup uses OLMoE-Base and a 35B-token multilingual continual pretraining corpus spanning seven languages.
