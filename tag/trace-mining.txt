18:T934,方法很克制，核心是一个单遍的 trace induction pipeline。输入是一批训练集上的 ReAct rollouts，每条 rollout 由 Thought / Action / Observation 序列组成。作者只从成功轨迹里抽取每一步 Thought 文本，把它们视为 reasoning move 的外显表达，然后做三件事。

第一步是按 step-level thought 做聚类，目标不是恢复完整 workflow，而是找到跨样本重复出现的局部 reasoning move。这里的设计选择很关键：作者刻意不诱导完整程序或任务图，而只诱导 finer-grained primitives，因为完整流程往往过拟合任务模板，而 reasoning move 更容易跨实例复用。

第二步是 primitive synthesis。对每个高频簇，系统拿到一个簇标签和若干代表性 thoughts，让 LLM 写出一个 primitive 规范，形式是三元组 p=(name, signature, docstring)。其中 signature 不是自动学出来的，而是由 task-family prompt 预先给定，例如输入 narrative 和 focus，输出字符串。这种设计把“调用接口约束”和“具体语义说明”拆开：signature 负责约束 agent 如何调用，docstring 负责描述这个 reasoning move 要完成什么。作者强调这点是为了避免必须手写可执行逻辑，因为很多 reasoning 操作没有干净的 deterministic Python 实现。

第三步是 deployment。诱导出的 primitive 被注册成 pseudo-tools，工具体本身没有手写逻辑；调用时，把 docstring 和运行时参数拼成 prompt 交给 LLM，解析输出后返回给 agent。测试时，agent 的 action space 只有这些 induced primitives 加一个 finish，除此之外没有原始搜索/查找工具，也不把 primitive 描述直接塞进 system prompt。也就是说，提升来自“把 reasoning move 变成可调用动作”，而不是简单给模型更多提示词。

论文反复强调一个机制解释：源 ReAct agent 在实例级别临时生成 thought，方差很大；而 induction 在语料级别聚合成功轨迹，把同类 move 写成稳定规范。测试时调用的是这个规范，而不是要求模型再次从零生成同样的 move，因此 induced library 可能超过 source policy。这一点把它和普通 trace distillation 区分开了：这里不是复述原轨迹，而是把轨迹里不稳定但反复出现的结构抽出来。19:T7d2,The method is a lightweight single-pass induction pipeline over successful ReAct trajectories. Each rollout contains interleaved Thought, Action, and Observation steps. The system extracts step-level Thought strings from successful traces and treats them as noisy surface realizations of latent reasoning moves.

It then clusters these thoughts to identify recurring local moves. This design choice is deliberate: the goal is not to induce a full workflow or task graph, which would be more brittle and task-template-specific, but a reusable vocabulary of reasoning operations.

For each frequent cluster, the pipeline synthesizes a primitive represented as p = (name, signature, docstring). The signature is fixed by a task-family prompt rather than learned from scratch; it constrains how the agent calls the primitive and what output type it should expect. The docstring carries the semantic content of the reasoning move. This separation is important because many reasoning operations do not have a clean deterministic implementation, so the paper instantiates primitives as pseudo-tools rather than handwritten tools.

At runtime, invoking a primitive means formatting the docstring together with the runtime arguments into an LLM prompt, parsing the response into the declared output type, and returning it to the agent. During deployment, the action space contains only the induced primitive library plus a finish action. The original generic tools are removed, and primitive descriptions are not copied into the system prompt. This makes the evaluation closer to action-space restructuring than prompt engineering.

The paper’s main mechanism claim is that induction performs corpus-level aggregation over successful traces, while the source ReAct agent makes instance-level decisions with high variance. A synthesized primitive acts as a stable specification of a reasoning move, so calling it at test time is not equivalent to asking the original agent to rediscover that move from scratch.1a:T693,The evaluation covers reasoning-heavy task families including RuleArena NBA, MuSR team allocation, and NatPlan meeting planning. The headline result is that induced primitive libraries outperform the very ReAct agent that generated the traces: RuleArena NBA improves from 30 to 74 (+44 points), MuSR team allocation from 38 to 68 (+30), and NatPlan meeting planning from 7 to 29 (+22). The paper reports paired-delta confidence intervals, all strictly positive.

A second important comparison is against expert-authored decompositions. The induced libraries beat expert designs by 17 points on MuSR team allocation and 15 points on NatPlan meeting planning, while roughly matching them on the remaining comparable subtasks. That is a stronger result than merely showing gains over a weak baseline.

The supervision setup is intentionally minimal. The source agent only has generic search/lookup tools, with no benchmark-specific action vocabulary and no domain-specific handcrafted tools. The induced structure is therefore recovered post hoc from generic-agent traces.

The deployment ablations matter. The canonical setup keeps only induced primitives plus finish, and does not inject primitive descriptions into the system prompt. This helps rule out the simpler explanation that the gains come from extra prompt instructions rather than from a better structured action space.

The full paper also notes that the pipeline uses only two free parameters, K and m, plus three LLM prompts, with one fixed configuration across benchmarks. That supports portability, though it also makes clear that this is a lightweight post hoc framework rather than a new large-scale training recipe.1b:T415,Start with the introduction, especially the distinction between reasoning primitives, workflows, and executable skills. That framing determines what the method is and is not trying to recover.

Then read the method section carefully, focusing on the primitive representation: name, signature, and docstring. The key design question is why the paper uses typed pseudo-tools with LLM-interpreted docstrings instead of executable implementations.

After that, go straight to the main results and the comparison with expert-authored decompositions. The central phenomenon to assess is the source-exceeding result: why can a library induced from an agent’s traces outperform the source agent itself? The paper’s answer is variance reduction through corpus-level aggregation, and that is the part most worth thinking about.

A 20–30 minute skim is enough for the main idea. If time permits, check the deployment ablations and confidence-interval details in the appendix to verify that the gains are not mostly prompt leakage or evaluation noise.1c:T55a,They introduce Meerkat, combining clustering with agentic search for repository-level auditing.

must_read (technical deep dive):
1) Formalization: given repository R={t_i} and a natural-language safety property φ, a violation implies existence of at least one witness W (a subset of traces) whose combined evidence violates φ. The auditor outputs a verdict plus per-trace scores s(t) estimating whether t belongs to some witness, capturing detection + localization.
2) Hierarchical clustering: organize traces into a hierarchy so related traces can be compared and large benign regions deprioritized, turning flat scanning into structured coarse-to-fine search.
