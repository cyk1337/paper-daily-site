18:T8ee,方法分成 TES 和 ACS 两条线。

TES，token-error supervision，在原生 router 之外增加一个轻量的 error head。这个 head 以共享的 token 表示为输入，为每个 expert 预测一个误差分数。然后用 native affinity 对这些 expert-wise error 做加权聚合，使聚合后的预测误差去拟合该 token 实际观察到的 next-token cross-entropy。训练好后，TES 不只是做一个辅助预测；它还在路由阶段把预测误差反馈到 expert 排序里：论文采用从 native affinity 中减去一个按比例缩放的 log-error 项，再做 top-K 选择。直观上，若某 expert 对当前 token 预测误差更高，就降低它被选中的相对优先级。这个设计保留了原有 top-K 稀疏预算，也不改 expert aggregation policy。

ACS，affinity-concentration supervision，则更克制。它不引入额外 head，也不在推理时改路由公式，而是直接用 realized token loss 去监督已选 expert 的归一化 affinity 概率的平方项。作者的解释是，这相当于根据 token loss 去调节路由分布该更尖锐还是更平坦：某些 token 上应更集中地押注少数 expert，另一些 token 上则不应过度集中。它是一个 headless 的对齐方式，参数和推理开销都更小。

监督目标上，论文主要用 Itakura–Saito divergence，也试了 ENLL。理论分析部分给出的关键结论是：对 TES 而言，两者都把聚合误差预测推向相同的期望目标，但对 LM 优化的梯度影响不同。若预测误差与真实误差一致，IS 不改变原始 CE 更新；ENLL 会相对放大低损失 token 的梯度权重。这个分析很重要，因为它说明“把 token error 接进 router”不是只有一个实现细节问题，而会改变训练动力学。

和已有方法相比，这篇工作不是重新设计一个全新 router，也不是增加更复杂的 expert selection 网络，而是在保留原生 MoE 结构和 top-K 预算的前提下，把 token-level error 作为显式监督接入路由。它的优点是兼容现有 backbone，改动小；局限是监督信号来自 realized CE，本身受当前模型状态影响，可能更适合 fine-tuning 或后期 router 校正，而未必直接适合早期大规模预训练。19:T942,The method has two variants: TES and ACS.

TES, or token-error supervision, augments the native router with a lightweight error head. From the shared token representation, the head predicts an error score for each expert. These expert-wise predicted errors are then aggregated using the native affinity weights, and the aggregate is trained to match the realized next-token cross-entropy for that token. At inference and training time, TES does more than auxiliary prediction: it modifies expert ranking by subtracting a scaled log-error term from the native affinity before top-K selection. Intuitively, experts predicted to incur higher error are down-weighted in the routing decision. This preserves the original sparse execution budget and the architecture’s native expert aggregation policy.

ACS, or affinity-concentration supervision, is the lighter alternative. It adds no extra head and does not alter inference-time routing with an extra transformation. Instead, it directly supervises the squared probabilities of the normalized selected-expert affinities using the realized token loss. The effect is to encourage the routing distribution to become sharper or flatter depending on token difficulty. In other words, it shapes how concentrated the native router should be, without introducing a separate error predictor.

For supervision, the paper mainly uses Itakura-Saito (IS) divergence and also studies ENLL. The theoretical section is important. For TES, both objectives target the same expected token-error quantity, but they induce different optimization dynamics. When predicted and observed token error match, IS leaves the original CE update unchanged, whereas ENLL relatively upweights lower-loss tokens. That is a meaningful distinction: adding token-error supervision is not merely an auxiliary loss choice, but a change to how gradients are distributed.

Relative to prior MoE routing work, the contribution is not a new router architecture. It is a way to keep the native MoE design and top-K budget intact while explicitly supervising routing with token-level error. That makes the proposal easy to graft onto existing backbones. The likely limitation is that realized CE is itself model-state dependent, so the method may be better suited to fine-tuning or late-stage router correction than to the earliest phases of large-scale pretraining.1a:T525,Experiments are run on two backbones, Granite 3.1 and OLMoE-1B, across four multiple-choice QA benchmarks. The main comparisons are against standard CE fine-tuning and a parameter-matched Dual Affinity baseline.

On Granite, ACS-IS improves average accuracy by 2.1 points over CE fine-tuning with frozen native affinity. TES-IS improves over the parameter-matched Dual Affinity baseline by 2.3 points on Granite and 0.5 points on OLMoE, averaged across the four benchmarks. Under stronger supervision, TES reaches a 2.94-point gain on Granite ARC-Challenge.

These results support two conclusions. First, direct token-error supervision can improve routing in practice, not just in theory. Second, the better mechanism depends on the backbone and task: some settings benefit more from explicit error prediction, others from headless affinity shaping. The paper also keeps the native top-K execution budget unchanged in all variants, which matters for deployment realism.
