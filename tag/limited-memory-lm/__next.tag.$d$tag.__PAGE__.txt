9:Tbb0,方法上，Co-LMLM 是一个 decoder-only Transformer，同时承担 LM 和 dense retriever 两个角色。核心设计有四部分。

第一，连续查询检索。模型在自回归生成时，如果输出特殊 token <FACT>，就读取该位置最后一层 hidden state 作为查询向量，而不是再生成一串自然语言查询。这个向量去检索外部索引中的 top-1 key，对应返回一个文本 fact span。系统把这个 span 直接插回上下文，形式是 <FACT> retrieved text </FACT>，然后从 </FACT> 之后继续解码。这样每次检索只额外消耗一个生成步，而不是多 token query decoding。这里的关键不是“把 hidden state 拿来做检索”本身，而是把检索动作内生进 next-token pretraining 流程里，让查询表示由 LM hidden state 自然承载。

第二，KB 形式从 relational tuples 改为 dense key-value store。value 是人类可读的文本 span，保留可编辑和可归因；key 是模型学出来的连续向量，避免关系模板约束。这样外置对象不再要求是显式关系三元组，只要能在文本中标出一个事实片段，就可以进入 KB。

第三，联合训练目标。训练数据中，原始文本的某些 factual spans 被 <FACT> 和 </FACT> 包起来。模型一方面照常做 next-token prediction，另一方面要学会在需要这些 span 时发出能命中对应 value 的查询向量。为此作者引入对比学习式 retrieval loss：每个 factual span 配一个自然语言问题，问题编码得到 query 侧表示，文档中的事实 span 提供正样本，其他 span 构成负样本。论文强调，预处理只规定“这里应该检索什么文本”，而不规定“查询必须长成什么样”，这和 Rel-LMLM 直接合成关系查询文本是根本区别。模型因此可以自己形成更灵活的检索几何。

第四，事实标注与数据构造流水线。为了摆脱 Wikipedia 的实体中心结构，作者设计了一个 annotation pipeline，在自由文本中标出 factual spans，并为每个 span 生成一个以该 span 为答案的自然语言问题。这样训练时既有语言模型上下文，也有 retrieval supervision。这个设计很关键，因为 Co-LMLM 的可扩展性不只来自连续查询，还来自“监督信号不再依赖结构化知识图谱”。从范式上看，它更像是在原始预训练语料上合成 retrieval-aware masking/slotting，再用 contrastive objective 把 slot 与外部 memory 对齐。

和现有方法相比，差异很清楚。它不同于标准 RAG，后者通常在预训练后外挂检索器，LM 本体并未被训练成主动外置知识；它也不同于 Rel-LMLM，后者的查询是离散文本、知识是关系型 tuple、监督路径是预先写死的；它也不同于纯 dense retrieval LM，因为这里返回的是可读文本片段，并直接进入生成上下文，目标是把 factual memory 从参数中迁出，而不是只做文档增强。a:T453,The paper addresses a concrete bottleneck in the Limited Memory Language Model line: how to move from a relational, Wikipedia-dependent, query-template-driven external memory setup to a more scalable pretraining paradigm. Rel-LMLM externalizes knowledge into a human-readable KB, but it is constrained in three ways. First, only facts that can be cast into relational tuples are easy to externalize. Second, retrieval is expressed as discrete natural-language queries, which adds decoding cost and limits expressivity. Third, the preprocessing pipeline effectively hard-codes retrieval pathways by synthesizing the exact query form in advance. Co-LMLM aims to keep the attractive properties of LMLMs—editable memory, attribution, direct unlearning via database operations—while replacing discrete relational queries with continuous vector queries and replacing relational tuples with dense-key/text-value memory. The broader goal is to train a model that learns, during pretraining, when to externalize knowledge and how to retrieve it, rather than merely learning to imitate a fixed retrieval template.b:Tb9b,Co-LMLM is a decoder-only Transformer trained to function as both a language model and a dense retriever. The method has four central pieces.

First, retrieval is triggered by a continuous query. During autoregressive decoding, when the model emits a special <FACT> token, the last-layer hidden state at that position is read out as the retrieval query. This vector is used to search an external index, and the top-1 retrieved textual fact span is inserted back into the context as <FACT> retrieved text </FACT>. Decoding then resumes after </FACT>. Each retrieval therefore costs only one extra autoregressive step, rather than requiring the model to generate a multi-token textual query. The key idea is not just using hidden states for retrieval, but integrating retrieval into the standard LM decoding loop.

Second, the KB is a dense key-value store rather than a relational database. Keys are learned continuous vectors; values are human-readable text spans. This preserves editability and attribution while removing the representational constraints of subject-relation-object schemas. Any factual span that can be marked in text can, in principle, be externalized.

Third, the model is trained with a joint LM-plus-retrieval objective. Training documents contain factual spans bracketed by <FACT> and </FACT>. The model is trained to predict tokens as usual, but also to emit query vectors that retrieve the correct span when needed. Retrieval supervision is provided through a contrastive objective built from question-span pairs: each factual span is paired with a natural-language question whose answer is that span, giving positives and negatives for dense retrieval training. A crucial design choice is that preprocessing specifies only when retrieval should happen and what text should be returned, not the exact textual form of the query. This is the main departure from Rel-LMLM, where the query representation is explicitly synthesized.

Fourth, the paper introduces an annotation pipeline for free-form corpora. Instead of relying on Wikipedia’s entity-centric structure, it marks factual spans in raw text and generates a natural-language question for each span. This creates retrieval-aware pretraining data without requiring a structured knowledge graph. In effect, the pipeline turns raw pretraining text into a retrieval-supervised corpus where factual spans are slotted out of the parametric channel and aligned with external memory.

Relative to prior work, the distinctions are clear. It is not standard RAG, because retrieval is not bolted on after pretraining; the model is pretrained to externalize knowledge. It is not Rel-LMLM, because queries are continuous rather than textual and the KB is not relational. It is also not just a dense retriever attached to an LM, because the retrieved object is a human-readable fact span that becomes part of the generation context, with the explicit goal of shifting factual memory out of the weights.c:T821,The empirical story has three main parts.

First, Co-LMLM improves language modeling and factuality at the same time. Across model scales, it achieves lower perplexity than standard non-externalizing baselines and also outperforms comparable Rel-LMLM variants. At the same time, it substantially improves factual precision. The headline number in the paper is that at 360M parameters, Co-LMLM attains lower perplexity than HF SmolLM2-360M despite SmolLM2 being pretrained on roughly 40 times more data. That is not a perfectly controlled recipe match, but it is still a strong signal for data efficiency.

Second, factual QA performance is unusually strong for the scale. The paper reports that the 360M Co-LMLM reaches SimpleQA-verified performance in line with GPT-4o-mini and above Claude Sonnet 4.5. This should be interpreted carefully: SimpleQA is a factual precision benchmark, not a full proxy for broad capability. Still, it directly supports the paper’s claim that externalized factual memory can produce high-precision knowledge access without requiring a much larger parametric model.

Third, scaling beyond Wikipedia works. Extending pretraining from Wikipedia to FineWeb-Edu further improves factual precision. This is one of the most important results in the paper because it directly addresses the main limitation of Rel-LMLM: dependence on corpora where relational supervision is easy to synthesize.

The most useful ablation-level takeaways are mechanistic rather than cosmetic. Continuous queries reduce inference overhead relative to textual relational queries. Supervising retrieval targets without fixing the query form yields more flexible retrieval behavior. And the fact that NLU utility is largely preserved while factual precision rises suggests a better allocation of model capacity away from brute-force memorization and toward retrieval-conditioned use of knowledge.
