17:T675,The core of the work is the OctoLong data pipeline, which combines three components: an Abstract Syntax Tree (AST) parser, a Language Server Protocol (LSP) backend, and a package manager, to recursively retrieve cross-repository code dependencies. The pipeline works as follows: 1) Curate high-quality Python repositories (≥15 GitHub stars, ≥5 contributors); 2) Use LSP's type- and scope-aware analysis, paired with package manager-resolved dependencies, to recursively fetch implementations of imported classes and functions across repository boundaries; 3) Concatenate these dependencies in call order to form high-density long code contexts up to millions of tokens in length. Two corpora are built from this pipeline: the ~6.2B-token cross-repository long-context code dataset, mixed with other long-text data to form the ~50B-token OctoLong-LCFT corpus for mid-training long-context continued pretraining; and the ~10B-token OctoLong-SFT mix (open instruction data + agent data) for supervised fine-tuning. The training pipeline starts from Qwen3 dense base models (600M to 14B parameters), first performs LCFT to extend the context window to 128K (4x the native length), then runs SFT to produce the OctoLong-Instruct suite. The key difference from prior work: existing cross-document long-context construction relies on weak correlation signals with low context coupling, while single-repository code serialization is limited by repository boundaries. OctoLong achieves precise cross-repository dependency retrieval via LSP, producing tightly coupled multi-hop dependency contexts that scale infinitely with the open-source package ecosystem.18:T41a,Reading priority for deep dive: 1) Section 3 (OctoLong data pipeline): focus on how LSP, AST, and the package manager work together, and the implementation logic of recursive cross-repository dependency retrieval (see Figure 2 for the pipeline flowchart) — this is the core innovation of the paper. 2) Section 4 (training pipeline): focus on the mid-training LCFT recipe details, including data mixture ratio, training steps, and context window configuration, as well as the composition of the SFT dataset. 3) Section 5 (experiments and ablations): focus on two key comparisons — the long-context performance gap between cross-repository code and single-repository code / general long text, and the retention of short-context capabilities after long-context training. Open directions for further exploration: quantitative metrics for long-context dependency density, scaling laws for mid-training context extension, and whether cross-document dependency mining methods can be transferred to non-code domains such as academic papers and web pages.19:T7b1,The core is a five-stage retrieval-grounded synthesis pipeline split into two phases:
Phase I (Knowledge Extraction, Steps 0-2): 1) A four-level discipline taxonomy: the first three levels (62 L1 / 754 L2 / 2,730 L3 nodes) are adopted from the Chinese National Standard of Discipline Classification; L3 nodes are expanded into 12,657 fine-grained L4 subfields via LLM, followed by LLM-assisted deduplication under each L2 node to cover 15,387 total disciplines. 2) For each leaf discipline, an LLM generates 10-15 statement-form queries covering core concepts, methods, applications, and limitations; statement-form queries are chosen because they match the declarative register of pretraining text and deliver higher cluster retention rates in pilot tests. 3) Each query retrieves the top 100 passages from the pretraining corpus, passages from all queries of the same discipline are aggregated, deduplicated, and clustered into thematic units.
Phase II (Structured Generation, Steps 3-4): 4) Hierarchical tables of contents (TOCs) are planned based on thematic units with quality filtering applied. 5) Source-grounded section content is generated per TOC entry and assembled into complete books, with multi-variant generation across different audiences and writing styles to ensure distributional diversity.
Four controlled settings are designed to isolate variables: Full (retain each TOC-planned textbook as a single training document), Split (use identical generated sections and token budget as Full, but treat each section as an independent document with reset position embeddings and intra-document attention), RandomConcat (randomly concatenate Split sections across books to match Full's length distribution, separating the effect of planned adjacency from raw document length), and Rephrase (independently rewrite individual documents from the same retrieval pool under matched audience/style constraints, without clustering, TOC planning, or book assembly).1a:T6bf,The method has three main components. The first is synthetic data construction. Quest-8K is built as more than query-answer pairs: each instance couples a complex research query with a task-specific rubric tree. The rubric encodes subgoals, evidence requirements, and output structure, so it serves both as supervision and as the basis for downstream reward design. Compared with synthesizing only final answers, this is better aligned with long-horizon tasks because both intermediate behavior and final reports can be assessed in a structured way.

The second component is context management. Long web-research trajectories quickly run into context bloat: search results, snippets, discovered facts, unresolved subproblems, and partial drafts all accumulate. Quest maintains compact summaries of the evolving information state instead of naively replaying the full history into the context window. This is not only a token-saving trick. It pushes the model toward abstraction and state tracking, which is closer to how a practical research agent should operate than simple retrieval concatenation.

The third component is the training pipeline itself. The paper emphasizes a full MT → SFT → RL recipe. Mid-training adapts the base model to the distribution and behavior patterns of deep-research tasks. SFT aligns the model to the target interfaces for tool use, task formatting, and report generation. RL then uses rubric-based signals to improve the harder objectives, especially report synthesis and citation grounding, where exact-match supervision is weak or unavailable. The novelty is less about a single module and more about unifying objective and open-ended tasks under one rubric-driven optimization framework.1b:T626,The reported results span model sizes from 2B to 35B and evaluate across eight benchmarks covering the three capability groups. If these results hold under the paper’s setup, the important point is that the unified recipe does not appear to trade away one capability class to gain another.

The more informative part is the stage-wise ablation story. Figure 2 and the surrounding discussion make a clear argument: prior open systems often support only fact seeking or only report synthesis, and many omit either mid-training or rubric-based RL. Quest is designed to show that SFT alone gives incomplete coverage; adding mid-training improves adaptation to search-style tasks and long-horizon state handling; adding RL further improves open-ended report quality and citation-constrained behavior. The excerpt provided here does not include the full ablation tables, but the paper explicitly positions controlled studies as a core contribution.

Another notable result is scaling behavior. The study covers 2B, 4B, 9B, and 35B models, aiming to show that deep-research-agent capability scales with model size but is not exclusive to large models.
