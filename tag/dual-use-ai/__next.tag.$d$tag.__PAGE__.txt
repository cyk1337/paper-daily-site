5:T469,Gradient-Routed Auxiliary Modules (GRAM) has three core components. (1) Architecture: each MLP layer in a dense Transformer is augmented with several smaller auxiliary MLP modules, each dedicated to one target capability domain, while the main MLP handles general core capabilities. (2) Training routing: forward and backward passes for auxiliary modules are selectively enabled based on the domain of the current batch. Core data updates only the backbone; data from a specific auxiliary domain updates both the backbone and the corresponding auxiliary module; gradients never flow to unrelated auxiliary modules. This design maps data domains to parameter subspaces, physically isolating the learning of different capabilities. (3) Inference control: ablating an auxiliary module at inference time removes its corresponding capability without retraining; enabling arbitrary subsets of modules produces arbitrary capability profiles from a single deployed model. GRAM combines domain-specific modules, data-dependent selective gradient updates, and per-subset optimizers into an end-to-end pretraining recipe for access control.6:T46f,Experiments span synthetic and realistic dual-use datasets, scale from 50M to 5B parameters, and compare against data filtering (gold standard), model branching, FT-LoRA, and post-hoc unlearning. (2) In the 800M-parameter realistic setting, the core corpus is web text + code + arXiv papers, with four auxiliary domains: virology, cybersecurity, nuclear physics, and Lisp code. Enabling multiple auxiliary modules does not cause mutual interference. (3) Under partially labeled data, GRAM achieves far better capability removal than both data filtering and branched finetuning.
