第二层是 loss aggregation bug。标准 SFT 的 cross-entropy 应该按所有有效 response token 的总损失除以总 token 数，也就是全局 per-token mean；但 OpenRLHF、Llama-Factory、早期 verl 会先在每个 mini-batch 内求 mean，再在梯度累积或多卡之间平均这些 mean。由于不同 mini-batch 的有效 token 数不同，这相当于给每个 mini-batch 相同权重，而不是给每个 token 相同权重，长短样本的贡献被扭曲。修复方法是先聚合 token-level loss sum 和 token count，再统一相除。

在这两个 bug 修复后，作者重新实现并比较标准 SFT→RL 与多种 mixed-policy 方法。论文的论证逻辑很清楚：不是抽象地说 sequential 更好，而是说明为什么它在 reasoning 上常更有效。SFT 提供的是 dense、低方差的学习信号，先把格式、领域知识和基本解题轨迹学稳，RL 再在已有成功轨迹附近做策略锐化；而 mixed-policy 在训练早期同时面对 off-policy demonstration 和 on-policy sparse reward，优化目标更杂，且如果初始策略太弱，RL 部分几乎不给有效梯度，算力利用率并不高。作者还给出 truncated RL 结果，说明即便只做很少轮数的 RL，只要 SFT 起点足够强，也能超过很多复杂混合方法。18:T403,This is a high-importance paper because it recalibrates a widely cited empirical conclusion in reasoning post-training. A substantial part of the apparent advantage of mixed-policy methods seems to come from broken SFT baselines rather than a genuinely better training paradigm. That matters directly for the pretrain–posttrain interface: if SFT is artificially weakened, then conclusions about how much RL needs off-policy demonstrations, how to mix dense supervision with sparse rewards, and where RL should start from all become unreliable. The paper reinforces a simple but consequential point: if SFT is implemented correctly and pushed to a strong enough starting policy, RL from verifiable rewards can be both more compute-efficient and more stable than trying to learn demonstrations and on-policy exploration simultaneously. The contribution is corrective rather than algorithmic, but the blast radius is large because the affected stack includes DeepSpeed, OpenRLHF, TRL, Llama-Factory, and earlier verl code paths.19:T9c3,The technical contribution has two layers. First is bug identification and validation. The authors trace a bug in DeepSpeed ZeRO Stage 1/2 with CPU-offloaded Adam: during gradient accumulation, copy_gradients_to_cpu() is executed only in the branch where micro_step_id == 0. As a result, only the first micro-batch’s gradients are copied to the CPU-side optimizer. Later micro-batches accumulate on GPU but are never transferred, so the optimizer step effectively uses only the first micro-batch instead of the accumulated gradient. The bug was introduced in DeepSpeed PR #6550 in September 2024. The fix is simple—move the gradient copy outside the conditional so it runs after every micro-batch accumulation—but the paper goes beyond code inspection and validates the patch against two independent references: a GPU-resident DeepSpeed optimizer in OpenRLHF and a PyTorch FSDP optimizer in verl. After the fix, loss trajectories and gradient norms align across implementations.

The second layer is the loss aggregation bug. In standard SFT, cross-entropy should be computed as the total loss over all valid response tokens divided by the total number of valid tokens, i.e. a global per-token mean. OpenRLHF, Llama-Factory, and earlier verl versions instead compute local means within each mini-batch and then average those means across gradient accumulation steps or distributed ranks. Because mini-batches contain different numbers of active response tokens, this gives equal weight to each mini-batch rather than each token, distorting the contribution of short and long samples. The correct fix is to aggregate token-level loss sums and token counts first, then divide once globally.

With both bugs corrected, the authors re-run the standard SFT→RL pipeline and compare it against published mixed-policy methods. The conceptual argument is straightforward and well supported: SFT provides dense, low-variance supervision that teaches formatting, domain knowledge, and basic reasoning traces; RL then sharpens the policy around trajectories that already have nontrivial success probability. Mixed-policy training, by contrast, mixes off-policy demonstrations with sparse on-policy rewards from the beginning, which makes optimization noisier and often less compute-efficient when the initial policy is weak. The paper also includes truncated-RL results showing that even a small amount of RL can outperform more elaborate mixed-policy methods if the SFT starting point is strong enough.1a:T655,The key experimental story is the reordering of baselines before and after bug fixes, followed by direct comparisons against mixed-policy methods. The two bugs together can reduce SFT performance by as much as 5.7 points on Qwen2.5-Math-7B, with the optimizer bug accounting for most of the drop and the loss aggregation bug adding a smaller but consistent penalty. After fixing them, the standard SFT-then-RL pipeline surpasses the best published mixed-policy result on in-distribution math tasks by +3.8 points for Qwen2.5-Math-7B and by +22.2 points for Llama-3.1-8B, while maintaining generalization on out-of-distribution benchmarks. Another important result is the compute comparison: even a truncated variant with only 50 RL iterations, instead of 500, still beats all mixed-policy methods on the math benchmarks, indicating that the extra complexity of mixed-policy optimization is not buying better sample efficiency or FLOP efficiency.

The paper also includes several validation layers that make the case more convincing. These include alignment of the patched DeepSpeed offload implementation with GPU-resident and FSDP optimizers in both loss curves and gradient norms; ablations that isolate the effect of fixing each bug separately versus both together; replication across model families including Qwen2.5-Math-7B and Llama-3.1-8B; and separate reporting on in-distribution and out-of-distribution benchmarks.
