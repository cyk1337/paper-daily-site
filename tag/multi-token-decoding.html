K-Forcing: Joint Next-K-Token Decoding via Push-Forward Language Modeling

这篇工作要解决的不是“如何把单次请求延迟再压一点”，而是更难也更贴近工业部署的问题：在高负载 batch serving 下，能否仅通过统计建模方式的改变，让一次前向稳定地产出多个 token，从而减少解码步数、提高吞吐，同时尽量保住 AR teacher 的生成质量。作者指出，现有两条主线都不完全适合这个场景：speculative decoding 的接受长度是随机的，会打乱 batch 内不同请求的步调，带来 ragged tensor、KV cache 对齐和重排开销；diffusion LM 虽然也能多 token 生成，但通常是按位置边缘分布逐步去噪，不直接建模 next-k 的联合条件分布，因此往往需要多轮 refinement，前向次数并没有真正降下来。K-Forcing 的核心问题因此被表述为：给定历史前缀，如何学习一个条件 push-forward map，把独立噪声一次性映射成未来 k 个 token 的联合样本，并且输出长度固定、架构上尽量复用 AR 模型基础设施。

评应优先读方法和服务实验；若 batch-serving 下验证扎实，next-k push-forward 会改变多 token 解码的内部 ablation 设计。
Zhiwei Tang,Yuanyu He,Yizheng Han,Wangbo Zhao,Jiasheng Tang,Fan Wang,Bohan Zhuang
