19:T53f,AgentMemBench implements five memory families under one harness. ICW keeps only a recent in-context window. EKV stores conversation snippets in an external key-value memory and retrieves them by dense similarity. GEM extracts entities and relations into an episodic knowledge graph, then retrieves structured neighborhoods. CBS compresses older context into natural-language summaries. WAM augments the agent with external web or MCP-style tool access. The benchmark uses three public datasets: 200 question turns from LoCoMo, 187 from MultiDoc2Dial, and 104 from MSC, for 491 annotated question turns in total. This yields 15 main configurations across five strategies and three task types. The metrics cover retrieval quality, including Memory Recall@k, MRR, and nDCG@k; answer quality, including Answer F1 and an LLM-judge faithfulness score; and deployment efficiency, including memory footprint, token cost, and latency. A notable design choice is provenance-aware retrieval evaluation: retrieved items carry true session/turn provenance, so retrieval metrics are computed against gold-session annotations rather than against ad-hoc retrieval indices. The paper also evaluates MemGPT/Letta and HippoRAG in the same harness and introduces MADS, a zero-shot dynamic selector that chooses a memory strategy from four corpus-level statistics.1a:T628,The core idea is a trajectory-level evaluation protocol. Each run records the full session: user messages, agent responses, tool calls, file edits, command executions, verification attempts, final answer, and final repository state. Evaluation combines formal verification, when objective checks exist, with LLM-written trajectory reviews and metric-specific scoring. The dimensions include things like instruction following, tool discipline, validation behavior, recovery from errors, and user-facing communication. The important design choice is that the written review is treated as a first-class artifact, not just a hidden judge score. That makes the benchmark useful for diagnosis.

A second key component is side-by-side review. Instead of only scoring one trajectory in isolation, the benchmark also compares two agents or two versions on the same task. This is well suited for model comparison, feature evaluation, and regression analysis, because many product regressions show up as local behavior changes before they show up in final pass rate.

On the task side, AgentLens focuses on production-like interactive coding workflows and uses a simulated user driven by another LLM conditioned on a persona and task objective. This follows the hidden-goal interaction style seen in benchmarks like τ-bench. It allows the benchmark to cover tasks without a natural binary outcome, such as writing documentation or explaining a codebase. The paper also includes reliability and bias checks, which is important because LLM-as-judge setups are otherwise easy to overtrust.1b:T4c3,108 long-horizon real-world computer-use tasks are built following three design principles: 1) Authentic workflows: tasks are sourced from expert interviews and annotator research on real professional scenarios, with input artifacts adapted from real materials instead of synthetic generation; 2) Long-horizon structure: difficulty comes from interdependent steps across multiple applications, rather than task repetition or concatenation of unrelated subtasks; 3) Diverse challenge phenomena: each task is annotated with 10 capability dimensions (cross-source reasoning, implicit-state inference, conflict disambiguation, dynamic environment adaptation, etc.).
