先看 tokenizer。作者分别给出 modular BPE 和 modular Unigram 的构造方法，目标是训练一个“大而可拆”的 multilingual tokenizer，然后从中抽取任意语言子集对应的 subtokenizer。这里难点不只是把不同语言的词表拼起来，因为简单拼接会破坏 token id、merge 规则或概率结构的一致性，也不保证抽出来的子词表还能接近单语 tokenizer 的压缩率。论文的做法是从训练阶段就约束 tokenizer 的结构，使每种语言或语言组对应的子词单元可以被稳定抽取，同时保留 byte-level fallback 和 lossless detokenization。对 BPE 和 Unigram 都提供了可抽取方案，说明作者不是只在某一种分词算法上做特例。

再看模型训练。核心思想是让模型在预训练时反复看到不同的 subtokenizer 组合，从而学会在不同 token inventory 下读写文本。论文把这些 subtokenizer 采样后组成 mini-batches，训练同一个模型共享主干参数，但输入 embedding 和输出预测都只在当前子词表上工作。这样做的直接结果是：部署到某个语言子集时，不需要加载完整 multilingual output matrix，只需保留目标语言相关 token 的 embedding/output rows。由于输出层 softmax 的维度显著缩小，推理速度和显存占用都会改善。

这套设计和传统 multilingual tokenizer 的区别有三点。第一，传统方法把所有语言塞进一个固定词表，压缩率和输出层成本一起被全局绑定；这里则把“共享训练”和“专用部署”拆开。第二，传统做法若想针对某语言优化，通常只能单独训练 monolingual tokenizer 和模型，跨语言共享会被破坏；这里保留了一个统一模型，只在 tokenizer/output head 层面做模块化。第三，作者强调目标不是追求极端压缩，而是在接近 monolingual compression 的前提下，保持多语言共享能力和部署灵活性。

For pretraining researchers, two ideas stand out. One is that vocabulary size, language coverage, and output-layer cost do not have to remain a single static trade-off; they can be shared during training and specialized at deployment. On the tokenizer side, the authors propose both modular BPE and modular Unigram schemes. The objective is to train a large multilingual tokenizer from which one can extract subtokenizers for any language or language subset. The challenge is not simply concatenating language-specific vocabularies. A naive union would break consistency in token IDs, merge rules, or token probabilities, and the extracted subsets would not necessarily preserve monolingual-like compression. The paper therefore designs the tokenizer training process so that language-specific components remain extractable while preserving byte-level fallback and lossless detokenization. The fact that the framework works for both BPE and Unigram is important; it suggests the idea is not tied to one tokenizer family.

On the model side, the key idea is to expose the model during pretraining to many different subtokenizer combinations. These subtokenizers are sampled and used to form batches, so the same backbone learns to read and predict text under varying token inventories. In each case, the input embedding and output prediction operate only on the active sub-vocabulary. At deployment time, this allows the system to load only the rows of the embedding/output matrices relevant to the target language subset, instead of the full multilingual vocabulary. The efficiency gain comes from two places: shorter sequences for the target languages and a smaller softmax/output layer.

Compared with standard multilingual tokenization, the difference is threefold. First, conventional approaches bind language coverage and output-layer cost into one fixed vocabulary; this framework decouples shared training from specialized deployment. Second, the usual way to optimize for a language is to train a separate monolingual tokenizer and often a separate model, which weakens multilingual sharing; here the model remains unified and only the tokenizer/output interface becomes modular. Third, the paper is not chasing maximal compression at any cost. The target is monolingual-like compression together with multilingual parameter sharing and deployment flexibility.

A further mechanism in the paper is balanced multilingual exposure through subtokenizer sampling. Because the model does not always train under the same giant vocabulary, high-resource languages have less structural advantage in vocabulary allocation. The paper uses Normalized Sequence Length (NSL) throughout to quantify how far each language is from a monolingual reference tokenizer, and this metric anchors both the tokenizer analysis and the efficiency discussion.f:Ta0d,Several empirical results matter.
