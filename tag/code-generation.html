代码模型的执行反馈训练大多只用到正确性信号，忽略了运行时性能；而直接把 runtime 作为 reward 又很脆弱——只有在程序正确时才有意义，跨任务量纲不一致，且当一组 rollout 全部失败时 GRPO 拿不到任何有效排序。

评将代码执行效率引入 RL 奖励函数，设计了分阶段的 reward 机制解决 runtime reward 稀疏和脆弱的问题，对做 Code RL 和后训练对齐的研究员有参考价值。
