9:T907,MemPrism explicitly separates persistent memory from decision-time working memory. The framework has five modules: Recorder, Router, Composer, Render, and Adapter. In inference, the first four form the main pipeline. Recorder stores real interactions as a unified event stream, keeping both raw events and structured fields such as pre-action observation, executed action, environment feedback, reward or step label, and task metadata. The point is to keep persistent memory neutral and reusable rather than collapsing it early into one fixed summary.

Router is the key learnable component. Instead of directly predicting the next environment action, it first decides how history should be viewed. A view action is defined over several axes: relation type, evidence range, outcome condition, and granularity. In other words, the policy chooses what relational structure to build, how much history to include, whether to filter by success/failure or other outcomes, and how coarse or fine the representation should be. This makes read-time memory representation an explicit decision variable.

Composer then selects events from the event stream and assembles a relational structure according to the chosen view action. Render converts that structure into an optical working-memory view. The optical format is not used only for token compression. The authors use two-dimensional layout to encode relations directly: spatial proximity groups related events, row/column alignment supports state comparison, arrows indicate change or dependency, and highlights emphasize failures or task-relevant evidence. A frozen task policy consumes the current input together with this temporary view and outputs the next environment action. The view is discarded after the step and is never written back into persistent memory, which avoids irreversible distortion from fixed summaries or repeated compression.

Training is also split cleanly. Router is first initialized with action-conditioned soft supervision, then optimized with trajectory-level grouped GRPO. The learning target is not the environment action itself, but the choice of memory view that best supports downstream action selection. This separation helps attribute gains to the memory representation interface rather than to a jointly entangled agent policy.a:T6a7,From the provided full-text excerpt, the experimental emphasis is on whether task-conditioned view selection improves long-horizon decision making, not on raw storage capacity. The paper appears to provide two kinds of evidence: end-task gains and attribution studies showing that the gains come from working-memory construction rather than unrelated components. The training setup for Router—soft supervision followed by grouped GRPO—is already designed to isolate the effect of view selection.

The excerpt does not include full tables or final numbers, so the exact quantitative gains cannot be stated reliably here. Still, the intended comparisons are clear: fixed representations such as timelines, summaries, or flat retrieved snippets are contrasted with dynamically constructed relational views defined by relation type, evidence range, outcome filter, and granularity. The expectation is that dynamic views are better matched to subtasks like loop detection, state tracking, failure analysis, and dependency reasoning.

Another likely experimental point is the decision not to write temporary views back into persistent memory. The authors argue that writing them back would bake task-local bias into long-term memory and reduce future reuse. A meaningful ablation should therefore compare persistent event streams plus on-demand views against fixed summary memories or recursively compressed memories. There are four main ingredients. First, the model wraps a fixed-size memory around a frozen vision-language-action backbone, replacing the linearly growing KV cache with an O(1) state. Second, it introduces a learned action-utility write gate. The trigger is not perplexity, recency, or generic reconstruction error; it is whether the current observation would change the next action. If the new input is not useful for action selection, the memory does not write. Third, the training objective is an action-information bottleneck rather than observation reconstruction. The action-chunk loss is backpropagated through the gate decision so that the memory learns to retain what matters for acting well, not what best preserves token-level fidelity. Fourth, the method includes explicit write-rate control during training via a target write rate rho and a penalty weight gamma, allowing the model to move along an accuracy-versus-write-bandwidth frontier. The paper also instantiates the approximate information state framework empirically by measuring epsilon and delta for the learned memory and reporting an action-sufficiency certificate. The full value-loss bound remains loose because the Lipschitz-related term is too large at current scale, but the attempt is still notable: it turns 'is this compressed state sufficient for control?' into something measurable. Relative to SSM-style recurrent models, AURA-Mem does not write every step. Relative to KV-cache compression methods, it does not approximate a growing cache; it commits to constant memory from the start.
