9:T628,The core idea is a trajectory-level evaluation protocol. Each run records the full session: user messages, agent responses, tool calls, file edits, command executions, verification attempts, final answer, and final repository state. Evaluation combines formal verification, when objective checks exist, with LLM-written trajectory reviews and metric-specific scoring. The dimensions include things like instruction following, tool discipline, validation behavior, recovery from errors, and user-facing communication. The important design choice is that the written review is treated as a first-class artifact, not just a hidden judge score. That makes the benchmark useful for diagnosis.

A second key component is side-by-side review. Instead of only scoring one trajectory in isolation, the benchmark also compares two agents or two versions on the same task. This is well suited for model comparison, feature evaluation, and regression analysis, because many product regressions show up as local behavior changes before they show up in final pass rate.

On the task side, AgentLens focuses on production-like interactive coding workflows and uses a simulated user driven by another LLM conditioned on a persona and task objective. This follows the hidden-goal interaction style seen in benchmarks like τ-bench. It allows the benchmark to cover tasks without a natural binary outcome, such as writing documentation or explaining a codebase.
