18:T452,The method has three main components. First, Verus-SpecBench: a benchmark of 581 specification-writing tasks derived from Codeforces problems, where the model must write Verus specifications rather than code. Second, Verus-SpecGym: an agentic environment in which the model interacts with Verus, bash, and the filesystem, iteratively revising specifications based on verifier feedback instead of producing a one-shot answer. Third, executable evaluation: the authors extend Verus’s exec_spec mechanism so generated logical specifications can be compiled into Rust functions and run on concrete input-output pairs. They broaden support for the types and operators needed by Codeforces-style constraints. Evaluation uses both official Codeforces tests and community-written hacks. The hacks are especially important because they are human-designed adversarial cases targeting subtle failure modes that ordinary tests often miss. The paper also includes a semi-automatic pipeline for converting new problems and hacks into additional benchmark tasks, which makes the benchmark extensible rather than static.19:T461,Under a fixed compute and time budget, the authors evaluate six frontier and open-source LM agents. The gap suggests that faithful specification writing is materially harder than standard code generation and depends on fine-grained semantic precision. A key qualitative result is that models often fail on specification writing even for problems where they can generate correct code. The failure modes cluster into three types: missing important input assumptions, accepting incorrect outputs, and rejecting valid outputs. The ablations are also informative. Increasing the number and diversity of test cases consistently lowers measured success, showing that sparse testing overestimates faithfulness.
