9:T782,The key idea is to treat the currently loaded expert set as an option, and to model the decision to keep or replace that set using the option-critic framework. The paper formulates dynamic expert loading as a semi-Markov decision process. The state includes context and routing-related information; the action is not a single-token expert choice but a temporally persistent expert mask; an option termination function decides when to switch; and each switch incurs a deliberation cost that stands in for real loading latency or memory movement.

Implementation-wise, each layer gets a lightweight controller. The controller learns two things: a termination policy that decides whether to continue with the current expert set, and a policy over options that selects a new set when switching happens. This differs from standard MoE routing in that routing becomes piecewise constant over spans of tokens rather than independently recomputed at every step. To avoid full retraining, the authors adapt gpt-oss-20b with only small LoRA/adapter updates plus the controller, while keeping the base model largely fixed. Training uses an option-critic style objective with a deliberation penalty, and a self-distillation reward that encourages the modified model to stay close to the original model’s behavior while learning to switch less often.

This is distinct from prior serving-side heuristics. Caching and prefetching optimize around a fixed routing distribution; expert pruning permanently reduces capacity. Here the routing policy itself is changed so the model learns to keep the current expert set whenever the expected quality gain from switching does not justify the cost. The RL analogy is clean: longer option duration yields stronger temporal coherence and easier memory management, but too much persistence reduces token-level adaptability. The deliberation cost becomes the main knob controlling that trade-off.a:T6b3,The main experiments are built on gpt-oss-20b with a small amount of adaptation parameters. The paper first measures switching behavior in several frontier open-source MoEs and finds that active expert sets change extremely often, close to every token. On gpt-oss-20b, the baseline switch rate is above 50%, meaning the model changes expert sets roughly every other token.

With the temporally extended controller, the switch rate drops below 5%, and with stronger switching penalties it can approach 1%. On downstream evaluations such as MATH and MMLU, the adapted model retains up to about 90% of the base-model accuracy. That wording matters: the claim is not near-lossless compression of routing dynamics, but a controllable trade-off. The lower the switch rate, the more quality is sacrificed. The main empirical result is that this trade-off is learnable and tunable, rather than something that must be handled by hand-crafted heuristics.

The most important experimental pattern is likely the curve, not any single score: as deliberation cost increases, switching falls rapidly while task performance degrades more gradually. That suggests a substantial fraction of token-level routing changes in standard MoEs contribute little to final quality. If that pattern holds in larger models, longer contexts, and real offloading settings, it would matter a lot.

There are also clear limitations. The work is a post-hoc adaptation, not temporally aware MoE pretraining from scratch. And the evaluation is centered on task accuracy and switch rate, without a full end-to-end serving analysis of latency, host-device traffic, or prefetch hit rate. So the systems payoff is plausible, but not yet fully demonstrated.b:T4f9,Start with the introduction and the problem framing. Second, whether self-distillation keeps the model too close to the original routing behavior and limits better long-horizon policies.
