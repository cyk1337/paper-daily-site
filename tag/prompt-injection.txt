The first is an agentic red-teaming harness. Instead of asking the attacker for a single-shot jailbreak prompt, the system gives it a stateful defender_model tool so it can probe, observe, revise, and retry. This matters because realistic prompt injection often depends on multi-turn interaction, tool outputs, file edits, and context-specific weaknesses that a one-pass generator will miss. The second ingredient is environment construction. Existing capability tasks are converted into adversarial RL environments under a realistic threat model: during the defender’s rollout, the attacker may be allowed to edit a designated tool response, a local file region, or another controlled insertion point. This keeps the attack surface close to real agent deployments while making the environment family extensible as production tasks expand. The third ingredient is large-scale self-play RL. The base game rewards the attacker for inducing valid failures and rewards the defender for resisting the attack while still completing its original task. Crucially, training is not limited to a single attacker-defender pair. The attacker is trained against a diverse, simultaneously trained population of strong defenders. That design is meant to prevent overfitting to one defender’s quirks and instead teach the attacker to identify model-specific weaknesses. The paper also frames scaling along three axes: inference-time compute through iterative search in the harness, environment diversity through many red-teaming scenarios and goals, and training compute through a very large RL run. The resulting GPT-Red is therefore a search-based adaptive attacker, not a prompt-template library.19:T51b,The main empirical message is that GPT-Red finds more working attacks, transfers better, and keeps improving with additional test-time compute. Test-time scaling is strong, which suggests the attacker is using search and adaptation rather than memorized attack strings.
