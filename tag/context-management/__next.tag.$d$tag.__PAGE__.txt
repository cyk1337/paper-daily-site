9:T633,The design is simple and distinctive. A standard LM updates context by concatenation, while a CLM is allowed to apply an arbitrary transformation to context at each step. Concretely, the live context is mirrored into a file. The model can either generate normally or use tools such as Bash to edit the context file directly, and the edited file is immediately synchronized back into the next-turn context. This enables in-place updates, deletion of stale information, maintenance of structured trackers, internal notes, and explicit working memory. The same abstraction extends naturally to multi-agent settings, where multiple context files can coexist for subagents or swarms. The paper also addresses the serving side. It introduces prefix-reuse FLOPs as a trajectory-level compute metric that accounts for decoding, prefilling, and re-prefilling under standard serving when in-the-middle edits break prefix matching. It then proposes Suffix Cache Reuse (SCR), which attempts to reuse cache beyond the matching prefix after edits, reducing re-prefill cost while preserving empirical task quality. For training, the authors use stepwise GRPO with a success-gated efficiency advantage: only successful trajectories compete on efficiency, which is important because naive token-minimization rewards would otherwise encourage over-compression and information loss. Finally, the paper introduces ContextBench, a diagnostic benchmark that isolates context management from reasoning and knowledge by testing selective retention, exact in-place updates, KV-style storage, and log maintenance.a:T5a1,The empirical story is broad and fairly concrete. On ContextBench, CLMs outperform summary-based and action-constrained baselines on synthetic tasks such as Needle Retention, Sudoku Sketchpad, KV Store, and Log Triage, showing stronger selective retention and exact editing behavior. On real long-horizon tasks, CLMs do well both in quality and compute. On BrowseComp-Plus, they achieve 11.4% higher accuracy with 21.5% fewer prefix-reuse FLOPs than the strongest baseline. On TerminalBench 2.1, they match the best baseline’s accuracy while using 29.5% fewer FLOPs. On a 12-hour subset of EdgeBench, they score 5% higher with 59% fewer FLOPs. On a 24-hour six-repository agent-swarm task, they deliver 65% greater end-to-end speedup at the same compute budget. On mathematical optimization, they outperform specialized evolutionary harnesses such as OpenEvolve by up to 16.8% on Heilbronn and 3.0% on circle packing. The RL result is also notable: training Qwen3.5-9B with the proposed stepwise GRPO setup improves BrowseComp-Plus from 28.8% to 42.5%, beating a Codex-style summary harness trained with the same recipe by 0.4 points while using 38.8% fewer FLOPs. On the systems side, adding SCR reduces server-side compute by another 35% at matched performance relative to standard SGLang serving. The deeper questions are whether the benefit mostly comes from the interface rather than new model capability, whether such editing behavior can be learned during pretraining rather than only post-training, and whether file-based context is a temporary bridge toward more explicit state-space or external-memory architectures.c:T6bf,The system has three parts. The first is a persistent context graph. Instead of storing history as a flat sequence of messages, the system keeps messages, tool calls, and full tool results as persistent nodes, preserving chronology and references. This matters because omitted results are not destroyed; they remain recoverable later.

The second is Tool-Flow Analysis (TFA), which is the main technical idea. TFA tracks how values introduced by earlier tool results are reused in later model steps and tool calls. When a later operation uses a value that originated in an earlier result, the system records an execution dependency and treats it as observed reuse. This is different from standard retrieval memory: the signal is not only whether an old chunk looks relevant to the current query, but whether the execution trace has already shown that the old result supports later actions.

The third is the renderer. Before each model invocation, it selects which historical tool results to expose within a fixed token budget. Selection combines three signals: observed reuse, recency, and semantic relevance. Unselected results stay in the graph and can be restored later. This is a more conservative design than aggressive summarization, because summaries often discard details whose importance only becomes clear much later.

A notable design choice is that the paper does not rely on a learned memory controller or model-driven compression policy. It uses explicit structured state plus hand-designed signals. The upside is interpretability and recoverability. The limitation is that TFA will only be as good as its ability to detect value flow; abstract semantic reuse is likely harder than literal or near-literal reuse.d:T4e1,The evaluation uses two benchmarks, AppWorld and 8-objective QA, with three execution models. The main setting allocates a 6K history budget for prior execution steps rather than passing the full accumulated history. Under this budget, ContextRender reaches task performance close to, and sometimes above, full-history prompting while reducing mean standardized inference cost by 10.2% to 32.2% relative to full history.

Against managed-context baselines, it delivers the best overall task performance across both benchmarks and all three models in the primary setting. The main point is not a single benchmark number, but the fact that it remains competitive under a much smaller visible history budget while preserving recoverability of omitted full results.

The ablations are the most informative part. Adding observed reuse on top of recency and semantic relevance improves both task performance and recall of results that are reused later. The gains are especially large for results reused after long gaps. That directly supports the paper’s claim: long-range execution dependencies are poorly handled by recency-only heuristics, and semantic relevance alone can undervalue tool outputs dominated by identifiers, paths, or parameter values.e:T465,ContextPilot expands the context-management action space and changes the RL procedure. On the tool side, it adds planning, long-term memory, and soft context offloading beyond search, deletion, and summarization. Planning gives the agent a global structure before later actions. Long-term memory stores scattered evidence in a reusable form. Soft offloading acts as adaptive compression or temporary externalization rather than hard deletion. On the training side, the paper introduces context-aware partial rollout. It identifies influential context-management actions using changes in context and policy entropy, then branches rollouts around these critical actions instead of exploring every action uniformly. For credit assignment, it estimates the advantage of an intermediate context-management action using rewards from subsequent branches. This gives a finer signal than assigning the final trajectory reward to every step.
