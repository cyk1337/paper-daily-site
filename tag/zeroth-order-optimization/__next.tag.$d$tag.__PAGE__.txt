b:T4d1,The framework implements a closed-loop zeroth-order self-evolution pipeline: 1) Instance-specific LoRA modules are attached for each hard example. LoRA parameters are randomly perturbed, the agent is run under both original and perturbed parameters, and loss differences are used to estimate gradients for LoRA updates. The entire process only requires final answer supervision, with no intermediate trajectory annotation needed. 2) Parallel perturbation inference: All perturbation branches share the same backbone forward pass, allowing parallel evaluation of multiple LoRA perturbations with minimal extra compute overhead. 3) Adaptive lookup cache: Recent tool call results are cached, with exact or similarity-based reuse selected according to query type to reduce redundant tool invocations. 4) Answer perplexity surrogate loss: The negative log-likelihood of the reference answer conditioned on the generated trajectory is used as a process-level proxy signal, replacing sparse binary correctness rewards to stabilize zeroth-order optimization. LoRAs optimized via this pipeline can generate successful trajectories on hard examples, which are then added to the global SFT dataset to form a complete capability iteration loop.c:T5c7,The workflow has three parts:
1) Discovery via controlled layer-wise ZO tuning: using the standard two-point SPSA/MeZO-style estimator, they run ZO fine-tuning while updating only one layer at a time (all other layers frozen), keeping the same ZO hyperparameters across layers. This produces a layer-wise “utility profile” for ZO.
2) Characterization: the dominant layer is largely task-agnostic for a fixed model (same layer wins across tasks) but model-specific across families (layer index changes between LLaMA2-7B and Qwen3-8B). In contrast, FO fine-tuning distributes gains more broadly, indicating the dominance is not simply “this layer is universally most important”, but a ZO-specific phenomenon.
3) Pre-training identification: they connect the dominant layer to activation outliers. With a small calibration set and inference-only forward passes, they compute layer-wise activation statistics and pick the first layer exhibiting a clear outlier pattern; empirically this matches the dominant layer.
Their explanation centers on ZO estimator reliability: ZO updates depend on how strongly a parameter perturbation changes the final loss. Perturbations injected earlier into the residual stream propagate through all subsequent layers and can be repeatedly transformed/accumulated, yielding larger and more stable loss differences. The first outlier layer appears to be where this amplification becomes pronounced, making ZO gradient estimates higher-SNR there.d:T663,AdaMeZO keeps the SPSA/MeZO gradient estimator as the base primitive. At each step, it perturbs parameters along a random direction z_t, computes a finite-difference loss projection from forward passes, and reconstructs the update direction using the same pseudorandom seed. The challenge is that Adam requires m_t and v_t, two full-size state vectors.

The key idea is to replace exact persistent moments with truncated, reconstructable approximations. First, AdaMeZO uses truncated first- and second-moment estimates rather than full EMAs over the entire optimization history. Older gradients are discarded, motivated by the fact that EMA already downweights them exponentially and their contribution is small relative to recent noisy zeroth-order estimates.

Second, the method exploits finer-grained PRNG replay. Instead of materializing full random directions globally, it regenerates them block by block. This allows the optimizer to reconstruct local pieces of the recent moment history on demand from stored scalar projections and PRNG seeds, rather than storing full moment tensors. In effect, it trades lightweight recomputation for memory.

This is the main distinction from prior adaptive ZO methods. HiZOO explicitly approximates diagonal Hessian information. Helene is closer to a direct Adam-style ZO optimizer with explicit state. AdaMeZO instead focuses on eliminating optimizer-state residency while preserving most of the benefit of preconditioning. The paper also provides a non-convex convergence result showing that the rate recovers that of preconditioned MeZO up to approximation terms introduced by truncation.e:T444,The experiments are designed to show both optimization behavior and practical LLM tuning gains. On 2D toy landscapes, the optimization trajectories illustrate the intended effect clearly: AdaMeZO follows more stable paths toward minima, while MeZO is more prone to oscillation or poor convergence under the same step budget.

The main empirical section fine-tunes RoBERTa, OPT, and LLaMA on the same task suite used by MeZO, which makes the comparison clean. The headline result is efficiency rather than just end accuracy: AdaMeZO almost always reaches the same stopping criterion as MeZO with up to 70% fewer forward passes, while also delivering better final task performance. That matters because forward evaluations are the dominant cost in zeroth-order tuning.

The most informative ablations are the ones around truncation length, block-wise reconstruction granularity, and the stability of gains across model families.
