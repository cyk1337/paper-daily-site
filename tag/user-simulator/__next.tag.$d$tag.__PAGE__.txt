9:T412,TRACER uses a two-stage training recipe. First, supervised fine-tuning on real user dialogues teaches the model to generate user responses and to emit structured annotations: a rationale and an ordinal intent score. The intent score acts as an interpretable proxy for the user’s evolving commitment or engagement state. Second, the simulator is trained with multi-turn reinforcement learning while interacting with a fixed assistant. Rewards combine terminal outcome agreement and trajectory alignment against paired human logs. Dynamic time warping is used to align trajectories with different lengths and conversational pacing. A deviation-aware advantage modulation mechanism then uses local alignment errors, accumulated over discounted trajectory suffixes, to scale turn-level policy updates while preserving the direction of the session-level advantage. Compared with static persona prompting, the method optimizes state evolution; compared with standard turn-level optimization, it assigns credit using the whole dialogue trajectory.a:T660,The method has three main components. First, the benchmark reformulation. Starting from SWE-Bench Verified, the full issue text is no longer given to the agent upfront. Instead, each task begins with a fixed initial user query that only partially exposes the problem. The agent keeps its normal programming actions but gains an additional message_user action, allowing it to ask follow-up questions and receive replies. This changes the task from pure code repair to joint specification elicitation plus code repair.

Second, the user simulator. Rather than using an unconstrained chat model, the paper builds a persona-grounded simulator whose responses are anchored to the full issue text. The design goal is twofold: preserve faithfulness to the original task specification, and produce realistic user-style interaction without leaking omniscient information. This is an important benchmarking choice. A free-form simulator would be cheaper to build but much noisier and less reproducible; a tightly grounded simulator makes automatic evaluation more stable.

Third, the schema-guided agent. The proposed agent is informed by dialogue theory and uses an explicit interaction schema to structure user communication, such as clarification, assumption checking, progress reporting, and decision requests. This is more than adding a prompt like “ask the user when needed.” The point is to make dialogue a structured policy component rather than incidental text generation. In many off-the-shelf coding agents, dialogue is either underused or poorly timed; the schema is intended to make asking behavior purposeful and actionable.b:T5d0,The experiments support three main claims. First, benchmark results show that stronger coding models in the standard autonomous setting do not necessarily rank higher in the dialogue setting. That is the central empirical result: interactive competence is not a free byproduct of better code generation.

Second, the proposed schema-guided agent improves over strong baselines by 3 to 14 percent, according to the paper’s headline numbers. For repository-level SWE tasks, that is a meaningful gain because absolute solve rates are typically low and a few points often correspond to a substantial number of recovered tasks. The paper argues that the gain comes from better clarification and alignment, not just stronger patch synthesis.

Third, the paper augments task success with automatic dialogue-quality evaluation using an LLM judge. This helps separate failure modes: some agents code well but do not communicate, some communicate but ask low-value questions, and some over-query the user. That decomposition is useful because final patch accuracy alone cannot explain why an agent failed.

From the provided full text, the benchmark is built by reformulating SWE-Bench Verified, the primary task metric remains resolved percentage via unit tests, and dialogue-level metrics are added on top.
