c:T45a,Ada-MK adapts MegaKernel to Ada GPUs by pushing decisions offline and minimizing runtime control overhead:
1) Adaptive shared-memory management: model shared-memory usage as a function of hardware, model architecture, and workload; reduce peak shared-memory demand (claimed ~50%) via fine-grained splitting along the K dimension, and enable cross-operator page reuse to fit viable pipelines within Ada’s 128KB/SM constraint.
2) Fine-grained DAG-based auto-search: build PTX-level dependency DAGs via MLIR lowering, then profile offline to select and serialize an optimal execution trace. At runtime, execute the fixed trace to avoid the if-else branching and dynamic scheduling overhead seen in approaches like managed-pointer mechanisms.
3) Heterogeneous hybrid engine: integrate as a TensorRT-LLM plugin—use TensorRT-LLM native operators for Prefill (better generality for long sequences/large batches) and switch to MegaKernel for Decode (to cut launches and HBM traffic). The key design choice is explicitly separating prefill vs decode implementations instead of forcing one kernel strategy to cover both.d:T631,The key contribution is Event Tensor: treat synchronization events as first-class tensor objects in the compiler IR. An event represents completion of a set of tiled tasks at (roughly) the SM granularity; organizing many such events into a multi-dimensional tensor yields a compact, structured representation of fine-grained dependencies inside a megakernel.

Why this matters:
1) Structured dependency encoding: instead of scattering semaphores/flags in hand-written code, dependencies become tensor-shaped objects the compiler can analyze and transform.
2) Dynamic-shape support via symbolic dimensions: because Event Tensors look like tensors, they can reuse existing compiler machinery for symbolic shapes, avoiding recompilation/capture for every possible runtime shape.
3) Data-dependent dynamism via index expressions: dependencies that depend on runtime data are expressed as mappings from task coordinates to event coordinates, enabling runtime-resolved dependency tracking while keeping the abstraction uniform.

On top of this IR, the Event Tensor Compiler (ETC) applies scheduling transformations to generate persistent megakernels. It supports a spectrum from fully static scheduling (pre-assign per-SM task queues) to dynamic scheduling (an on-GPU scheduler dispatches ready tasks), and can mix strategies to trade off synchronization overhead vs adaptability/load balance.
