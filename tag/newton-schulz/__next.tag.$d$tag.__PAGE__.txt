a:T5b1,DMuon is a drop-in distributed Muon module orthogonal to the host training framework and parallelism strategy. Its design has four layers. (1) Owner-centric communication optimization: one owner rank is selected per full matrix. Non-owners aggregate their shards to the owner via a single all-gather, the full Newton-Schulz iteration runs on the owner, and updated shards are then scattered back. Communication volume is minimized while exact optimizer semantics are preserved, addressing the root issue that per-shard computation cannot perform orthogonalization. (2) Shape-adaptive execution stack: combines batched Gram Newton-Schulz execution (computing MM^T / M^TM first then iterating, reducing arithmetic), symmetry-aware specialized kernels (halving work on symmetric Gram matrices), and DSL-driven autotuning to deliver high utilization across heterogeneous matrix shapes. (3) Computation-aware load balancing: owner assignment is formulated as a measured-cost optimization problem. A runtime profile captures the nonlinear costs introduced by batching, kernel selection, and autotuning, then performs global assignment to balance work across owners. (4) Drop-in interface: exposes only a standard optimizer API to existing pipelines, natively supports ZeRO, FSDP2, and tensor parallel sharding without modifying the main training loop. DMuon performs no algorithmic approximation; update rules and convergence behavior are identical to naive Muon.b:T49d,Close read.
