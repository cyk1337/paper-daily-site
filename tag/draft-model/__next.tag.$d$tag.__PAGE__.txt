9:T7cf,The core method is CURE, a budget-aware dynamic repair tree. A block-parallel draft model produces a length-K candidate block and its logits in one pass. In standard single-path speculative decoding, only that path is verified. If token k is rejected by the target model, all later tokens are discarded even when many of them would have matched the target had the earlier local error been repaired. CURE tries to fix exactly those fragile points.

The mechanism starts by identifying Uncertainty Focal Points using the top-1 versus top-2 log-probability margin from the draft model. A small margin indicates local ambiguity and a higher chance that this position will trigger downstream rejection. Under a fixed verifier budget, the method spawns alternative branches only at these focal points instead of expanding a dense candidate tree over the whole block. The motivation is simple: if most tokens are already predictable, uniform tree expansion wastes target verification on positions that do not need repair.

The paper formulates this as a budget-constrained candidate-tree optimization problem. The objective is to maximize accepted length under a verification budget V_max. The effective generation rate is written as expected accepted tokens divided by draft cost plus verifier cost. This formalization is useful because it makes the central trade-off explicit: local branching helps only when the gain in accepted context outweighs the extra cost of target-side tree verification.

A practically important component is cache resynchronization. Because repair branches may alter the finally accepted path, the draft model’s internal state must be realigned with the target-verified prefix. The authors design a cache-consistent resynchronization procedure that does not require retraining the draft model. That makes CURE a plug-and-play add-on for existing block-parallel backends, which is more valuable in practice than a method that depends on a specially trained draft architecture.a:T623,The evaluation covers code generation as the main domain and reasoning as an out-of-domain check. The code benchmarks are HumanEval, MBPP, and LiveCodeBench-lite; GSM8K is used for transfer beyond code. Relative to single-path parallel drafting backends, CURE improves accepted tokens per step by 4.2% to 7.5%, and reaches 2.66× to 3.49× end-to-end speedup over target-only autoregressive decoding.

These numbers should be interpreted carefully. The gain in accepted tokens per step is meaningful but not huge, which suggests the method is not relying on aggressive tree expansion. Instead, it extracts moderate acceptance improvements from localized repairs. Because speculative decoding is often bottlenecked by memory-bound sequential target passes, even moderate acceptance gains can translate into noticeable wall-clock speedups. The paper also emphasizes an acceptance-versus-compute Pareto frontier: adding more repair branches usually increases accepted length, but target verification eventually saturates, after which extra branching no longer improves latency.

The experiments are mainly about systems trade-offs rather than model quality. The most informative results are therefore the curves across different budgets and block settings, not a single best speedup number. Another point is domain fit. The method is especially natural for code, where global structure is often predictable while identifiers, API choices, and local syntax decisions create concentrated uncertainty. 关键在于它如何保留依赖。文中用了两层机制。块内依赖通过 layer-wise shift 实现：前一个位置的 hidden state 会被送入后一个位置的每一层，使得 block 内第 2 到第 K 个位置不是独立猜测，而是条件在前面已生成内容上。块间依赖则允许新 block 从旧 block 的任意位置继续，并显式使用该位置的 hidden state 作为条件，因此后续扩展不是简单复制前缀，而是沿着已有分支继续生长。

第二个核心部件是 rank-guided tree construction。作者没有固定每个位置的分支数，而是额外训练一个 rank head，输入该位置 hidden state，预测“target token 在 drafter 分布里的排名区间”。如果某个位置 target 大概率就在前几名，就给少量 sibling 即可；如果排名可能更靠后，就增加分支，或者决定该位置是否值得作为后续 block 的起点。这样树是在 drafting 过程中动态成形，而不是先生成大树再剪枝。它解决的是 verifier 预算分配问题：把分支放在更可能需要覆盖的位置上。

第三个设计是 valid-prefix curriculum learning。SpecBlock 的训练和普通 teacher forcing 不同，因为一个 block 内后面位置读到的是模型自己前面位置的预测，而不是真实 token。如果前面已经错了，后面即便对着 ground-truth 继续算 loss，也是在优化一条推理时根本不会被接受的路径。作者因此引入 valid-prefix mask：一旦同一路径前面某位置预测错误，后续位置 loss 就被屏蔽。这个设计很像把 speculative decoding 的“前缀有效性”直接写进训练目标，减少无效监督。

第四个部分是 serving-time adaptation。作者观察到离线训练的小 drafter 对分布偏移很敏感，而 verifier 在拒绝位置上本来就会算 target 分布，这相当于免费给出了在线监督信号。于是他们设计了一个 cost-aware bandit，在每次 query 后决定三种动作之一：不更新、只更新输出头、更新整个 drafter。只有当预计吞吐提升能覆盖更新成本时才执行更新。这个部分的重点不是在线学习算法本身多新，而是把 speculative verification 里原本就存在的 target signal 变成了低额外成本的适配机制。d:Ta1d,The main idea is to grow the draft tree in blocks rather than one depth level at a time. A single drafter forward produces K dependent future positions, called a block. The tree beyond depth K is then expanded by reusing the drafter on a batch of starting points selected from earlier blocks. This changes the unit of expansion from one token depth to a multi-token block.

The key question is how dependence is preserved. Inside a block, SpecBlock uses a layer-wise shift mechanism: the hidden state from the previous position is injected into every decoder layer of the next position. As a result, positions 2..K in the block are not independent parallel guesses; they are conditioned on earlier drafted content. Across blocks, a new block can start from any position in the previous block, using that position’s hidden state as conditioning. This lets the tree continue along existing branches rather than merely appending shallow independent proposals.

A second major component is rank-guided tree construction. Instead of assigning a fixed branching factor to every position, the model trains an auxiliary rank head that predicts a coarse bucket for the rank of the target token within the drafter distribution at that position. If the target is likely near the top, only a few siblings are needed; if it may rank lower, more alternatives are allocated, and the position may also be selected as a starting point for later block expansion. This shapes the tree during drafting rather than generating a large tree and pruning afterward.

The third component is valid-prefix curriculum learning. In standard teacher forcing, each step is supervised under a fresh ground-truth prefix. SpecBlock cannot do that because later positions in a block consume earlier model predictions, not ground-truth tokens. If an earlier prediction is wrong, the entire path will be rejected by the verifier, so supervising later positions on the ground-truth continuation wastes capacity on paths that will never be committed. The valid-prefix mask drops the loss on later positions once an earlier position on the same path is incorrect.

The final component is serving-time adaptation. The paper observes that a small offline-trained drafter is sensitive to domain shift, while the verifier already computes target distributions at rejected positions. That gives a nearly free adaptation signal.
