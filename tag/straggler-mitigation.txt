17:T5d2,The method is Pipelined Gradient Coding (PGC). Standard gradient coding assigns each worker c=s+1 data partitions and asks it to compute all c gradients in the same step, then upload a coded linear combination. PGC spreads those c computations across multiple consecutive steps, so each worker computes only one partition gradient per step, matching the per-step compute cost of ordinary distributed gradient descent.

To preserve recoverability, the coded message at a given step is formed from gradients computed at the current and previous steps. This creates a temporal pipeline: redundancy is no longer concentrated within one step, but distributed over time.

The paper develops PGC for two classic placement schemes:
1. Fractional Repetition (FR): workers are grouped and share the same partition placement. PGC-FR is simpler to encode and decode.
2. Cyclic Repetition (CR): partitions are placed cyclically, which is more flexible and does not require c to divide n, but decoding is more involved and depends on the straggler pattern.

The main technical shift is from purely spatial redundancy to spatial-plus-temporal redundancy. This introduces delayed gradients, so the paper also provides convergence analysis under smooth and strongly convex settings. In other words, PGC trades extra same-step computation for analyzable gradient staleness. Compared with asynchronous SGD, the delay here is structured by coding rather than being an uncontrolled side effect of worker timing.18:T43c,The experiments first validate the motivation. On 12 Google Cloud VMs, training ResNet-18 on CIFAR-10 for one epoch, the authors compare vanilla distributed gradient descent with GC under FR and CR placement. All methods follow the same loss-per-step trajectory because they recover the same full gradient, but GC is consistently slower per step. The paper states that the slowdown relative to DGD exceeds 100%, and the gap widens as the tolerated straggler count s increases. GC-FR is faster than GC-CR due to lower coding complexity.

The second part evaluates PGC through simulations and real experiments. The main result is that PGC substantially reduces completion time relative to standard GC and improves convergence in wall-clock time, while keeping per-step compute close to DGD. The important nuance is that the gain is primarily in time-to-train, not necessarily in steps-to-convergence, since PGC uses delayed gradients. The method is most attractive when stragglers are present but not catastrophic, and when the compute amplification of standard GC is the dominant cost.19:T414,A skim read should take about 20–30 minutes. First, Entropy-Weighted Load replaces raw token counts with an information-aware load estimate. For each visual token, the method computes a Shannon entropy score from the token feature after a softmax transformation, normalizes entropy values within the current image or batch, and maps them to semantic weights through a sigmoid function. The intuition is simple: not all visual patches deserve equal capacity. Background or redundant patches should count less than semantically dense ones. Text tokens are assigned full weight because their semantic density is treated as relatively uniform and high.

Second, Dynamic Modality-Adaptive Capacity adjusts expert capacity according to the current batch-level modality composition. Standard methods use a fixed capacity factor gamma, which is brittle when some tasks are image-heavy and others are text-heavy. MACS makes capacity a function of the actual visual/text mix in the batch, so the budget tracks the current workload instead of a static approximation.

Third, Local Semantic Rerouting handles overflow. When an expert exceeds capacity, the framework first attempts to reroute overflow tokens to semantically nearby experts with spare room; only when rerouting fails does it fall back to a safe token drop. This is a practical design choice: it preserves more useful information than direct dropping, while avoiding the overhead of a more expensive global reassignment.
