9:T671,The central observation is that branch-level scheduling partially decouples compute regulation from memory regulation. Request-level pause/resume is expensive because pausing a request forces a decision about its KV state: keep it resident and consume memory, or evict it and later pay restoration cost. In branch-parallel decoding, sibling branches share the request’s prefix KV, while each branch’s private KV only covers the tokens generated on that branch so far, typically much smaller than the shared prefix. Therefore, deferring a branch for one step mostly means withholding compute from that branch; it does not require reclaiming the shared prefix and usually does not require evicting the branch-local KV. Re-admission in a later step is cheap. On top of this structural property, the paper introduces TAPER. The controller first guarantees single-token progress: every active request contributes exactly one token to the next step. Additional branches are then treated as opportunistic width and admitted only if the predicted branch externality fits within the current batch’s slack budget. This requires a per-step latency/externality predictor and a greedy planner that chooses which extra branches to admit. The utility interface is pluggable, so the planner can target different objectives such as throughput, goodput, or SLO attainment. Compared with eager admission, TAPER does not realize all available branch parallelism by default. Compared with fixed caps, it does not rely on a static width k. The main idea is to move admission control to decode-step granularity and exploit the cheap reversibility of branch deferral.a:T534,The evaluation uses Qwen3-32B under mixed workloads and compares TAPER against IRP-OFF, IRP-EAGER, and fixed-width baselines. The headline result is that TAPER improves goodput by 1.77× over IRP-OFF and by 1.48× over IRP-EAGER, while maintaining over 95% SLO attainment in regimes where eager admission drops below 50%. This is the key empirical point: eager branch admission may increase aggregate token throughput, yet still reduce the metrics that matter for a shared service because serial co-batched requests suffer inflated step latency. The paper also argues that intra-request parallelism is common enough to matter in practice. That matters because it shows the problem is not an artificial corner case. The most useful experimental lens is the metric choice: token throughput alone can be misleading, whereas goodput and SLO attainment expose the externality.
