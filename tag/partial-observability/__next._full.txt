DynamicGUIBench contains 149 tasks across 10 applications and is designed around four dynamic scenario types: interruptive UI states, ephemeral reference, dynamic list selection, and content-triggered interaction. The key idea is not just to add visible perturbations, but to create cases where task-relevant evidence appears, evolves, or disappears between action steps, so a single screenshot is insufficient.

The proposed agent, DynamicUI, consumes full interaction screen-recording video rather than one post-action frame. Its dynamic perceiver clusters frames and iteratively selects salient centroids using generated captions and confidence scores, effectively compressing long videos into informative dynamic context. A refinement strategy then addresses mismatches between intended actions and actually executed behaviors. Finally, a reflection module uses the refined trajectory to provide higher-level guidance for subsequent decisions. Unobserved cells are marked as “?”, and each move reveals only a local 5×5 window around the agent; the agent’s coordinates are always known (oracle localization), so uncertainty is purely in the map. Interaction is strictly myopic: at time t the model receives the current map state plus the immediately preceding state, and must output exactly one action from a constrained schema {UP, DOWN, LEFT, RIGHT}.
