18:T4db,RheoSampling introduces a dual-identity probability design. Instead of relying purely on deterministic top-k expansion, it inserts one stochastically sampled token into the candidate pool after the top-m deterministic selections. The key idea is to give this sampled token two probability identities. During dynamic tree construction, it is assigned a proxy probability so it can compete with deterministic candidates for expansion and survival. During verification, it is evaluated with its true sampling probability, which preserves lossless stochastic decoding.

This decoupling resolves the conflict between context-adaptive dynamic trees and proper stochastic sampling. The second major contribution is an equivalence-class analysis. Once randomness is introduced into a dynamic tree, token identities and tree topology become tightly coupled, making direct analysis intractable. The authors compress this large stochastic tree space into equivalence classes and use that framework to prove losslessness. The third component is an Optimal-Transport-based verification algorithm, designed to improve acceptance rate while maintaining correctness. They also add a sparse draft distribution strategy to reduce overhead on large vocabularies.19:T482,The experimental comparison is mainly against top-k dynamic-tree baselines such as EAGLE-3, with acceptance rate and wall-clock speedup as the main metrics under standard stochastic decoding. The central empirical claim is that RheoSampling consistently outperforms these baselines across multiple LLMs and benchmarks, especially when temperature is nonzero. The paper explicitly points out that EAGLE-style implementations effectively treat draft probabilities as 1.0 during verification, which explains the one-hot collapse and poor tail exploration.

The experiments are designed to show that the theoretical fix matters in practice. They compare behavior across stochastic settings, showing that dynamic trees degrade once sampling is introduced unless probability semantics are handled carefully. Additional gains come from the OT-based verification and sparse draft distribution. The provided text does not include the full result tables, so it is better to avoid quoting missing numbers, but the qualitative result is clear: higher acceptance rates and better wall-clock speedups than top-k dynamic-tree baselines in realistic stochastic decoding.1a:T4bd,The approach is an instruction-centric, train-and-measure loop:
- Search space: expose ARM Neon primitives as trainable operations spanning FP16 residual/normalization, INT8 SDOT for attention projections, and bit-packed boolean compute using compare/route/logic ops plus popcount.
- Dataflow: keep the residual stream in FP16; use FCMGE (FP compare) with learned thresholds to convert channels into packed bits; run a learned boolean feed-forward “program” implemented via EXT/BSL/EOR/CNT; decode selected boolean traces back to numeric space via CNT/SDOT and apply small FP corrections (FMLA).
- Train/deploy alignment: this is not post-training quantization. Thresholds and the boolean program are trained jointly; FP16 rounding and hard bit decisions are present during training. Gradients use a straight-through/hybrid estimator, but inference executes the exact hard boolean program.
- Selection protocol: for each primitive/variant, train on fixed data order and seed, inspect validation curves, export the exact native weight image, and benchmark bytes and tokens/s on an M4. Variants that fail either quality or speed/memory gates are dropped; a 3-seed calibration is used to estimate endpoint noise.1b:T423,The method reformulates the output projection plus top-k selection as maximum inner product search. Rows of the output embedding matrix are treated as token vectors, and the final hidden state is used as the query. Instead of evaluating all logits, the system retrieves likely high-score tokens using an approximate nearest-neighbor index. The authors evaluate FAISS-backed options and choose HNSW because it offers the best latency–recall trade-off in this high-dimensional embedding space. The index is built post-training from the static output embeddings and can be distributed with the checkpoint. At inference time, the HNSW ef parameter controls the speed–accuracy trade-off. To reduce harmful misses, the implementation explicitly scores selected special tokens, common punctuation, and structural words. Retrieved logits can be scattered into a sparse full-vocabulary tensor, which keeps the method compatible with existing decoding pipelines. Unlike Adaptive Softmax-style designs, this does not require architectural changes during pretraining.1c:T713,PuzzleKV partitions each per-head KV cache into fixed-length logical pages and independently factorizes completed pages using low-rank decomposition. Instead of forcing the entire prompt history to share one basis, each page gets its own local basis, which better preserves region-specific directions.

The implementation has several important pieces. First, the cache is hybrid: a small sink region and a recent window are kept dense, while older completed pages are stored in factorized form. This protects the most attention-sensitive tokens from compression artifacts. Second, the attention kernel is designed to operate directly on both dense and factorized pages, so the model does not reconstruct the historical KV cache back into full space before attention. That matters for bandwidth and runtime. Third, page conversion is incremental during autoregressive decoding: once a page is filled, it becomes eligible for decomposition and storage as factors. This makes the method compatible with online generation rather than only offline post-prefill compression. Fourth, the method is training-free and calibration-free. Unlike approaches that derive a fixed compression space from model weights or calibration activations, PuzzleKV builds the representation directly from the current request's page-local KV activations.

The paper's logic is straightforward: establish that page-level low-rank structure is common across models, layers, heads, and page sizes; show that page-local bases preserve information better than a global SVD baseline; then implement the idea in a mixed dense/factorized attention pipeline that can run during decoding. The trade-off is also clear: it gives up some of the maximal sharing of a global basis in exchange for finer-grained fidelity and more stable task performance.1d:T49a,Experiments are run on Qwen3-8B and Llama-3.1-8B-Instruct, evaluated on RULER and LongBench. When combined with per-factor INT4 quantization, storage drops to 18.7% of the original KV footprint while still retaining more than 93% of Full-KV performance. Compared with Global SVD, PuzzleKV shows substantial gains on RULER and competitive results on LongBench.

The paper shows that for page size P = 32, the effective ranks needed for accurate reconstruction vary by layer and KV head but remain well below full rank throughout the evaluated models. The central design choice is to avoid searching over full pruning programs from scratch. Instead, the method performs residual search around a strong base policy.

To make this possible, the authors introduce TPDSL, a token-pruning domain-specific language with 131 reusable atoms. These atoms cover four categories: budget control, token scoring, selection constraints, and token reassembly. The purpose is to compress the design space into structured operations that an LLM can manipulate reliably, rather than forcing it to rediscover the entire pruning algorithm in raw code.

The most important abstraction is the residual search-state representation. Each candidate consists of a strong base policy, a TPDSL-specified residual modification, and structural constraints that guarantee validity. At runtime, the base policy first selects tokens, and the residual policy is allowed to revise only a bounded quota of uncertain selections. This has several advantages: it preserves the reliable structure of existing human-designed policies, narrows the effective search space, and focuses the LLM on the local decisions that matter most. Because the residual rule is decoupled from runtime instantiation, the discovered policy can transfer across token budgets and model backbones.

Search is evaluator-in-the-loop. The LLM proposes TPDSL residuals, the system validates them against syntax and pruning constraints, then evaluates them on the target MLLM and feeds performance plus diagnostic signals back into the next iteration. This is closer to constrained policy search than to open-ended code generation.

Compared with prior pruning work, AutoPrune does not claim a single new importance metric. Instead, it treats existing heuristics as reusable structure and searches for better residual refinements on top of them. Compared with generic program synthesis, it wins by shrinking and structuring the search space.22:T511,The evaluation spans 14 multimodal benchmarks and 3 MLLM backbones. Two headline results stand out. First, under a 94.4% visual-token reduction ratio, AutoPrune preserves more than 99% of full-token performance on both LLaVA-1.5-7B and LLaVA-NeXT-7B. Second, in the 320-token efficiency setting on LLaVA-NeXT-7B, it reduces FLOPs by 9.9× and prefill latency by 6.4×. So the gains are not only in token count but also in actual inference cost.

The transfer experiments are especially important. The discovered policy transfers across token budgets without requiring a fresh search for every budget, and it also transfers across MLLM backbones. The paper further shows stable behavior across different LLM proposers, which supports the claim that the search-state representation is doing much of the heavy lifting. Another useful result is that AutoPrune consistently improves over multiple human-designed base policies, suggesting that residual search is not tied to one lucky baseline.

The ablations are where the design is best justified. Removing the residual formulation, replacing TPDSL with unconstrained full-program generation, or weakening structural constraints hurts both search efficiency and final pruning quality. Those results make the representation choice much more convincing.23:T620,The method, LATCH, has two components. The first is CVC, Confidence-Verified Commit, which decides when the whole sequence may stop. Instead of monitoring a fixed region or using schedule-dependent heuristics, CVC re-extracts and relocates the current candidate answer span at every denoising step. It then requires both high confidence on that span and sustained argmax identity stability across multiple steps. Only when the candidate answer itself has remained stable does the decoder allow a global fill-and-stop. The key change is that the stopping rule verifies the object of interest, the answer candidate, rather than a proxy statistic.

The second component is BWEC, Block-Wise Early Commit, which decides where local commitments may happen during decoding. The authors argue that non-final blocks usually contain intermediate reasoning text, so they can be handled with a cheaper local confidence rule. BWEC therefore applies only to non-final blocks. The final block, and any global termination decision, remains under CVC. This separation is meant to preserve the speed benefits of adaptive sampling while preventing local confidence signals from prematurely freezing the answer region.

A central analytical premise is that candidate stabilization is highly task-dependent. The paper measures stabilization timing with metrics such as s0.9, the decoding progress by which 90% of trajectories have stabilized, and finds a very wide range across tasks. That observation motivates abandoning progress-only early exit in favor of candidate-aware verification.24:T5b0,The evaluation covers 11 tasks and two model families, with LLaDA-8B-Instruct used as the reference decoding backbone and transfer tested to Dream.
