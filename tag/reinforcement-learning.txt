1a:T451,DiDPO extends group-relative advantage from the trajectory level into the internal structure of a code diff.

Using a CodeAct-like interaction loop, each action yields an edit (add/del/none) and the environment provides an outcome reward (e.g., tests pass/fail). Instead of treating the whole response/diff as one credit carrier, DiDPO:
1) Aligns diffs across multiple rollouts for the same task by finding highly similar sub-diffs that recur across trajectories.
2) Uses these recurring sub-diffs as anchors to induce sub-diff boundaries within larger diffs, aiming to isolate functional regions.
3) Groups aligned sub-diffs and computes a local group-relative advantage (diff-level advantage), then combines it with the trajectory-level advantage and assigns it back to the tokens responsible for generating those sub-diffs.

To avoid anchors that are too broad (mixing functions) or too narrow (hard to aggregate), it introduces a groupability score to select anchors that balance semantic scope and group mass. The method remains critic-free and claims no additional rollouts beyond the sampled group.1b:T41a,TRIAL keeps the GRPO rollout-level advantage and clipping rule unchanged, then adds a training-only hindsight objective. For each decision turn, it builds an outcome view that exposes the realized local consequence of that decision. The same generated response is scored under the ordinary interaction context and under the hindsight-conditioned context. The signed token-level log-probability gap determines update direction and local revision strength. TRIAL then aggregates absolute gaps within each turn and compares a turn’s share of total revision magnitude with its share of eligible tokens. This yields a trajectory-relative allocation multiplier. The multipliers are normalized so their eligible-token-weighted mean is one, which redistributes hindsight supervision while keeping the average allocation fixed. A scalar clamp bounds the dense loss contribution relative to the detached GRPO loss magnitude. Hindsight contexts, discrepancy scores, and allocation profiles are used only during training, so inference uses the ordinary policy.1c:T439,The proposed method is Ranking-based Reward Construction. It uses a generative reward model only for relative preference ranking, then derives scalar rewards from the resulting order. The first mechanism is self-competitive ranking: for a given prompt, multiple responses sampled from the current policy are compared against each other, and their relative order is mapped into rewards. This aligns naturally with group-relative policy optimization. The second mechanism is anchor-guided ranking: a small set of anchor responses serves as reference points, and candidate responses are compared against these anchors. This reduces the reward-model call pattern for larger candidate sets from a sorting-style O(m log m) regime to O(m n), where m is the number of sampled responses and n is the number of anchors. When n is small, this is more scalable. Unlike GenRM-style preference-token probabilities, RRC does not rely on a single token probability. Unlike approaches that suppress reasoning and emit only labels, it can preserve the generative judge’s textual reasoning process.1d:Ta78,方法核心是一个 exact speculative rollout engine，名字叫 SpecRoll。它由四个部件组成。

第一，proposal family 不是独立 drafter，而是挂在 target backbone hidden state 上的多 horizon future-token heads，形式上接近 MEDUSA。给定前缀 x_{<=t}，target 先精确采样一个 anchor token x_{t+1}，然后多个 head 并行预测后续若干位置的 token，复用 target 的词表投影矩阵 W。这些候选组成一个 prefix-closed sparse tree。这样做的好处是省掉第二个 AR backbone 和对应 KV cache，proposal 成本更低，也减少了 target/drafter 失配来源。

第二，verification 是 exact 的，而且是 concurrency-aware 的。RL rollout 里同时活跃的样本数会随着部分样本提前结束而下降，因此固定大小的 speculative tree 在高并发阶段可能浪费验证算力，在低并发阶段又吃不满硬件。SpecRoll 会根据当前 active concurrency 动态调整 sparse tree 的预算：并发高时保守，减少额外验证负担；并发下降后扩大 tree，换取更高 accepted progress。论文的出发点不是单纯提高单条序列 acceptance，而是优化整个 GRPO rollout 阶段的吞吐。

第三，快路径是 Reflex。它利用“延迟 verifier 反馈在同一轨迹邻近位置上仍有预测性”这一观察，对 proposal hidden state 做 bounded、trajectory-local、gradient-free correction。这里的关键不是学习一个新模型，而是把已经成熟的 verifier error 当作局部校正信号，在不反传的情况下修正后续 proposal。为了避免误修正，作者加了 conservative alignment gate：只有当过去误差对未来仍有可预测性时才启用；同时还有 candidate-boundary safeguard，防止在候选边界附近做有害干预。这个设计试图区分 transient local mismatch 和 persistent drift：前者不值得动参数，局部修一下就够；后者才交给慢路径。

第四，慢路径只在 sustained degradation 被检测到时，才更新 future-token heads 的参数。也就是说，SpecRoll 不把所有失配都转成在线学习问题，而是先用 Reflex 吃掉短期、局部、轨迹内的偏差，把真正跨轨迹持续存在的 proposal 退化留给参数更新。这一点和 FastGRPO 的持续在线训练独立 drafter 不同，后者把适应主要放在参数层，代价更高，也不区分误差类型。

从训练目标上，SpecRoll 始终保持 exact target verification 为最终裁决，因此 committed token 的分布不变，GRPO 的 reward、advantage 和优化目标都不被改写。它优化的是 rollout 生成过程，而不是 RL objective 本身。1e:T96f,SpecRoll is an exact speculative rollout engine built from four main pieces.

First, the proposer is not a separate drafter model. It uses MEDUSA-style future-token heads attached to the target backbone hidden state. Given a prefix, the target model samples an exact anchor token x_{t+1}, and multiple horizon heads predict later positions in parallel, reusing the target vocabulary projection. These candidates form a prefix-closed sparse tree. This removes the need for a second autoregressive backbone and its KV cache, reducing proposal cost and simplifying synchronization.

Second, verification remains exact and is made concurrency-aware. In GRPO, the number of active rollouts changes over time because some responses finish earlier than others. A fixed speculative tree is therefore inefficient: too expensive when concurrency is high, and too small to saturate hardware when concurrency drops. SpecRoll adjusts the sparse-tree budget based on active concurrency, using a smaller budget early and a larger one later. The objective is not just better acceptance on a single sequence, but better throughput for the whole rollout stage.

Third, the fast adaptation path is Reflex. The key observation is that delayed verifier errors can still be predictive for nearby future positions within the same trajectory. Reflex converts such mature verifier feedback into bounded, trajectory-local hidden-state corrections without backpropagation. It is guarded by a conservative alignment gate, which activates only when past errors are predictive of future mismatch, and by candidate-boundary safeguards that suppress harmful interventions near unstable boundaries. The design explicitly separates transient local mismatch from persistent drift.

Fourth, the slow path updates the future-token heads only when sustained degradation is detected. In other words, SpecRoll does not treat every mismatch as an online learning problem. It first uses Reflex to absorb short-lived, local errors, and only escalates recurring cross-trajectory mismatch into parameter updates. This differs from FastGRPO, where adaptation relies more heavily on continuously training a separate drafter.

Throughout the method, exact target verification is authoritative. The committed-token distribution is unchanged, so rewards, advantages, and the GRPO objective remain intact.
