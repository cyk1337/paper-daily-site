18:T594,VideoGen-Agent uses a shared multimodal policy in a reasoning-action-observation loop. At each step, the policy conditions on the prompt, previous actions, and tool observations, then selects a tool and specifies its arguments. The six task categories are Procedural Knowledge, Single-Entity Identity, Multi-Entity Identity, Physics Simulation, Compositional Scene, and Multi-Shot. Each category has a default tool subset and workflow: procedural prompts use text retrieval for steps and motion details; identity prompts use visual retrieval and image-conditioned or multi-reference generation; physics prompts invoke simulators and pass motion conditions to a motion-conditioned generator; compositional prompts generate candidates and use verification tools such as detection and depth estimation for regeneration; multi-shot prompts generate phases sequentially and use the last frame of each segment to preserve continuity. Training has two stages. First, the policy is supervised on teacher-distilled tool-use trajectories, with the paper mentioning Claude Opus 4.7 as part of the trajectory construction process. Second, the policy is optimized with multitask agentic RL. A hybrid reward scores both tool use and generated video quality, while task advantage normalization balances learning signals across the six categories. A common tool interface allows backend tools to be replaced without changing the agent workflow.19:T788,The core idea is Dense Reasoning Trace, or DRT. The goal is not just to make the model say less, but to make it reason in a different external format. DRT separates reasoning into two explicit channels: <visual> stores observed evidence from the image, while <think> stores compact logical derivations. Symbolic connectors and concise state transitions replace long natural-language sentences. This serves two purposes: reducing linguistic redundancy and disentangling observation from deduction so that assumptions are less likely to be written as if they were visual facts.

Training has two stages. The first is Dense Trace Initialization. High-quality multimodal instruction data are rewritten into the DRT format to create a DRT-SFT dataset, and supervised fine-tuning is used to internalize this reasoning mode. The key role of this stage is format adaptation rather than knowledge acquisition: the model learns to organize intermediate states in a compact structured space.

The second stage is Trace-Grounded Reinforcement Learning. The authors build a DRT-RL dataset using a tri-perspective verification pipeline, keeping only traces that satisfy three conditions simultaneously: correct final answer, logically consistent intermediate steps, and faithful visual grounding. They then optimize the model with a trace-grounded GRPO objective, augmented with process-based rewards and exploratory incentives. In effect, the policy is rewarded not only for being correct, but also for producing short, logically coherent, and visually grounded traces.

Compared with prior efficiency methods, this is not early stopping, token selection, or budget prediction within the same natural-language CoT space. It changes the reasoning expression space itself. Compared with standard CoT SFT/RL, it places much stronger emphasis on disentangling observation from deduction and on verifying grounding quality of intermediate traces.1a:T6a4,The model is evaluated on five challenging multimodal reasoning benchmarks, including text tasks and out-of-distribution video tasks. The headline result is a 5.5x improvement in token efficiency together with a 1.3-point accuracy gain over Qwen3-VL-8B-Instruct under official prompting. That is the main empirical claim: shorter traces do not merely save tokens at the cost of quality; the structured format can improve the efficiency–accuracy tradeoff.

The paper also emphasizes component ablations rather than only final benchmark numbers. Dense Trace Initialization appears to be necessary for moving the model into the new reasoning format; without it, simply asking for concise reasoning would not reliably produce high-density traces. Trace-Grounded RL further improves faithfulness, especially under tight token budgets, where models otherwise tend to sacrifice logical completeness or grounding for brevity. The tri-perspective verification pipeline is important because it raises the quality of RL reference traces and filters out trajectories that are answer-correct but process-poor, or process-plausible but visually ungrounded.

From a foundation-model perspective, there are clear caveats. The gains depend on a specific trace schema and a data rewriting pipeline, so transfer to other model families, modality mixes, or pure-text reasoning remains open. The 5.5x token-efficiency number should be read carefully: one needs to check whether it counts only output tokens or total tokens, and whether prompts are strictly matched. Also, some of the burden may shift from inference to schema design and data construction quality, which makes the dataset pipeline central to the result.1b:T403,For a quick pass, start with Figure 1 and the method overview to understand what DRT actually looks like; otherwise it is easy to misread it as ordinary concise CoT. Then read the two training stages carefully: how the SFT data are rewritten, and how verification and rewards are defined in RL. Finally, inspect the main tables and efficiency–accuracy plots to confirm that the gains come from changing the reasoning representation rather than from prompt engineering.

第三步是基于执行的测试构造。系统运行原始代码，通过执行轨迹、返回值、状态变化、文件输出、CLI 输出等可观察行为来生成测试期望。这里的设计重点是“behavioral specification”而不是“implementation matching”：测试要约束外部行为，但允许不同内部实现。文中明确强调要避免把原实现细节直接编码进 verifier，否则会把任务退化成补全原代码。为此，测试构造结合执行证据、边界情况扩展和一致性检查，尽量让 verifier 接受替代性正确实现。

第四步是环境一致性检查。构造后的环境需要保证：原始正确实现能通过 verifier；移除目标实现后的起始环境不能 trivially 通过；容器化依赖、构建脚本和测试注入流程都稳定。这一步更像数据工程里的 validity gate，避免把噪声环境送进 RL。

第五步是 rollout-based filtering，也是这篇工作最有信息量的部分。作者不是只看静态构造结果，而是先让 agent 在候选环境上 rollout，再用这些 rollout 反过来筛任务。过滤信号包括：对抗性 rollout 检查是否存在泄漏或 reward hacking 路径；solution review 判断 verifier 的通过/失败是否真的符合题意；以及 success rate 统计，用来剔除过难、过易或奖励不稳定的任务。也就是说，任务质量不是由生成器单方面决定，而是由“环境 × agent 行为”共同定义。这比只做静态 test generation 更接近真实 RL 需求。

最终得到的数据集包含 5,545 个可验证任务，来自 3,185 个开源代码库，覆盖 23 种编程语言和 15 个技术领域。训练时使用 GRPO 在 MiMo-V2.5 上做 RL。论文还分析了训练后 agent 行为变化，发现模型会更多探索代码库，并更频繁地执行自写检查，这说明学到的不只是 benchmark-specific patching，而是更一般的工作流策略。1d:Ta02,CodeMidas is an agentic pipeline for environment construction. The only task-specific input is a source repository. It does not consume issues, PRs, or human-written specs. First, the system identifies candidate functionality by inspecting repository structure, build metadata, and public entry points. It prioritizes functionality with observable behavior and nontrivial codebase context, including CLI tools, pure library functions, and stateful APIs. The selection criterion is important: the target should admit a behavioral specification while leaving implementation freedom open.

Second, the repository is adapted into a development starting point. The target implementation is removed or blanked out, while the rest of the project structure, dependencies, and surrounding context are preserved. This makes the task closer to real software work than isolated function completion.

Third, CodeMidas constructs tests grounded in execution of the original code. It runs the original implementation and uses observable outputs, return values, state transitions, file effects, and CLI behavior to infer expected behavior. The design goal is behavioral verification rather than implementation matching. The verifier should reject wrong solutions but still accept alternative correct implementations, so the pipeline tries to avoid overfitting tests to the original code path.

Fourth, the environment is checked for execution consistency. The original implementation must pass; the stripped starting point must not pass trivially; the containerized dependencies and grading flow must be stable. This is a data validity gate more than a modeling contribution, but it is essential for RL.

Fifth, and most interestingly, the paper adds rollout-based filtering. Candidate environments are probed with agent rollouts before RL training. The pipeline uses adversarial rollouts to detect leakage and exploitability, solution reviews to assess whether verifier outcomes align with the stated requirements, and rollout success rates to remove tasks that are too noisy, too easy, too hard, or reward-misaligned. This is a strong design choice: task quality is defined not only statically, but through interaction with actual agent behavior.

Training has two stages. The first is in-domain supervised fine-tuning. The second stage is RL with verifiable outcomes. For each audio prompt, the model samples G completions. An LLM judge reads the decoded text answer and returns a binary correctness reward. Stage 1 is Q-guided sample refinement. Given a state, the current flow policy maps Gaussian noise to an action. Instead of using that action directly, the method runs a finite number of MALA steps starting from the policy sample, targeting the Boltzmann distribution induced by the critic, p(a|s) proportional to exp(Q(s,a)/alpha). This is a practical choice: the method does not try to sample exactly from the target distribution, nor does it directly regress a critic-derived velocity field. It first generates a plausible action with the current policy, then uses critic gradients plus Metropolis correction to refine it toward higher-probability regions.

Stage 2 is self-target flow matching. The refined action is paired with the original base noise used to generate the pre-refinement action, and this pair becomes a source-target example for conditional flow matching. In effect, the model learns to map the same latent noise to a better action next time. The targets are therefore self-generated and improved by finite-step MCMC, not provided by an external oracle.

Relative to prior work, the differences are clear. It does not rely on Q-weighted regression alone, does not require directly learning a score model for the target action distribution, and does not treat the critic merely as a weighting function. Instead, it uses MCMC as an intermediate refinement operator and then amortizes that refinement into the flow policy. The paper also includes an idealized distributional analysis showing monotonic improvement of a maximum-entropy objective and identifying the Q-induced energy distribution as a fixed point. That theory is not a full practical guarantee, but it explains why the refine-then-distill loop is sensible.24:T4f8,The experiments have two roles.
