17:T614,PerfCodeBench is an executable benchmark for system-level code optimization. Each task provides a correct but slower baseline implementation and a human-expert or expert-inspired optimized reference. The model is asked to optimize the baseline while preserving semantics. The evaluation harness checks three things in a controlled way: compilation, task-specific correctness, and runtime performance. The dataset is built from public repositories, benchmark suites, and systems research artifacts, then filtered aggressively. A task is kept only if it compiles and runs, has an automatic correctness oracle, has a reference implementation that is genuinely faster than the baseline, and yields stable runtime measurements. The final benchmark contains 1,854 executable tasks across six programming languages and multiple systems domains, including GPU and accelerator benchmarks, CPU SIMD and cache-sensitive libraries, parallel and HPC workloads, SQL and data-processing systems, AI inference runtimes, and general systems libraries. The design has two major strengths. First, it turns performance optimization into an executable and quantitative objective rather than a subjective code-quality judgment. Second, it avoids the bias of algorithmic coding benchmarks, because many real bottlenecks come from memory access patterns, parallel scheduling, and hardware details rather than big-O improvements. There is no novel learning algorithm here; the contribution lies in task curation, the unified harness, and the baseline/reference evaluation protocol.18:T434,The main experimental result is straightforward: current models often generate functionally correct code, but they still fall short of expert-level efficiency. Across a broad evaluation of frontier models, even the strongest model reaches or surpasses the expert reference on only 61.6% of comparable tasks. That means top models match or beat human-optimized implementations on only about three fifths of the benchmark. The gap is especially pronounced for parallel programs and GPU kernels, which suggests weaknesses in hardware-aware optimization, synchronization reasoning, and low-level execution behavior. In scale, the benchmark contains 1,854 executable tasks spanning six languages.
