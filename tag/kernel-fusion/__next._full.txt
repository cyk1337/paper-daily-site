19:T7dc,方法核心是做一套面向 XDNA2 AIE tile 的 fused mixed-precision kernel library，并围绕它重做权重布局和数据流。关键点有三层。

第一层是 kernel fusion。作者不是先把 INT4/INT8 权重展开成 BF16 再做 GEMM/GEMV，而是让压缩权重一路保持低比特格式，直到进入 compute core 后再在同一 kernel 流里完成 unpack、dequantize 和矩阵计算。这样做的原因很直接：如果先物化成高精度权重，带宽和片上存储都会被吃掉，低比特量化的收益会被前处理成本抵消。TileFuse 直接支持 AWQ 风格 W4A16 和 W8A16，对 transformer 线性层做 fused execution。

第二层是 interleaved pre-tiling 与 layout co-design。XDNA2 的 DMA streaming 和 tile 级数据搬运有严格约束，直接按常规矩阵布局喂数据会让流水断掉，尤其在 FFN 的大 shape 上更明显。作者因此在离线阶段对权重做预切块和交错布局，让运行时 DMA 能连续供数，同时让 dequant 后的数据更贴合 AIE 的向量化执行方式。这里的重点不是单纯“换个 layout”，而是把量化分组、tile 尺寸、片上 buffer 和 GEMM/GEMV 访存模式一起设计。

第三层是 end-to-end runtime integration。论文不只停在 microkernel，而是把这些 kernel 接进完整 LLM runtime，覆盖 prefill 和 decode 场景，并处理 practical LLM shapes。前文专门批评已有工作只能跑受限 GEMM 维度，不能覆盖 Gemma-2B 一类模型常见 FFN 形状；TileFuse 的一个卖点就是把 kernel 设计到能覆盖这些真实模型尺寸，而不是只在漂亮的 benchmark shape 上报吞吐。

和已有方法相比，区别主要有两点。相对 Qualcomm 上的 ScalingLLM，它不要求改用 NPU 定制量化方案，而是尽量保留社区现成 AWQ 格式。相对此前基于 IRON 的 BFP16 GEMM 工作，它追求的是可用于准确端到端 LLM 推理的 mixed-precision low-bit 路线，而不是只展示某类 GEMM 的高 TOP/s。1a:T771,The core idea is a close-to-metal mixed-precision kernel library for AMD XDNA2 AIE tiles, coupled with weight-layout and runtime co-design.

First, TileFuse uses fused kernels for quantized linear layers. Instead of materializing low-bit weights into BF16 before matrix multiplication, it keeps weights compressed as INT4 or INT8 until they reach the compute core. Unpacking, dequantization, and GEMM/GEMV execution happen within one kernel flow. This matters because separate weight expansion would erase much of the memory and bandwidth benefit of low-bit quantization.

Second, the paper introduces interleaved pre-tiling and layout co-design. XDNA2 imposes practical constraints on DMA streaming and tile-local buffering, so a conventional matrix layout leads to poor pipeline utilization, especially for large FFN shapes. The authors therefore pre-tile and interleave weights offline so that runtime DMA can stream data continuously and the dequantized fragments align with the vectorized execution pattern of the AIE tiles. The key point is that quantization grouping, tile geometry, memory layout, and execution order are designed together.

Third, the work is integrated into an end-to-end LLM runtime rather than stopping at microkernels. The paper explicitly positions itself against prior results that report strong GEMM throughput on restricted dimensions but do not cover practical transformer shapes or sufficient numerical fidelity for full LLM inference. TileFuse is designed to support real transformer linear layers in both prefill and decode settings.

Relative to prior work, the distinction is clear. Unlike hardware-tailored quantization schemes such as ScalingLLM on Qualcomm, TileFuse tries to preserve standard AWQ-style formats. Compared with full-precision baselines, the paper reports up to 121.6% kernel-level improvement for GEMM and 281% for GEMV. In end-to-end LLM inference, it achieves up to 2.0x lower prefilling latency and more than 64.6% lower energy.

The evaluation focuses on transformer linear layers, which dominate LLM inference cost, and emphasizes practical model shapes rather than only idealized benchmark matrices. That is an important part of the contribution: the system is meant to run real quantized LLMs, not just produce good microbenchmark numbers.

The most informative ablations are likely the comparisons with and without fused unpack/dequantize, with and without the interleaved pre-tiling layout, and the different behavior of GEMM versus GEMV across prefill and decode.
