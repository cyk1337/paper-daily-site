5:T469,The proposed Experiential Latent Memory (ELM) pipeline creates a small latent memory after each solved problem. Instead of updating the backbone, it trains a tiny soft-prompt-like module (claimed ~0.001% of parameters) with a few gradient steps, using self-generated signals from the model’s own reasoning trajectories (success/failure exploration under test-time compute).
The paper’s design logic is:
1) Textual trace replay is bottlenecked: raw CoT traces (even with reflection-style refinement) are surface artifacts and do not reliably transfer; hidden states may contain more abstract structure than what is verbalized.
2) Internal-reward learning can provide a learning signal without labels, but prior approaches are mostly offline and can degrade as more test data accumulates.
3) Modularity isolates updates: per-instance memories are stored separately and composed at retrieval time, aiming to mitigate interference and forgetting compared to full-parameter RL/finetuning.
Operationally it looks like retrieval (select relevant memories) + injection (compose soft prompts) + tiny online optimization
