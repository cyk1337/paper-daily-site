18:T516,The authors first treat RIM as a conditional failure mode rather than a universal outcome. They extract two activation-space directions from the base model: a reasoning direction that separates correct from incorrect reasoning, and a safety direction that separates refusal from compliance. In Qwen2.5-Instruct 3B and 7B, where RIM appears, these directions have consistently negative cosine similarity in mid-to-deep layers, suggesting that reasoning-improving updates move representations away from the safety-refusal direction. The authors then use CKA distance ratios to compare representation changes on harmful versus harmless inputs after fine-tuning, locating a compact set of safety-decision layers. Linear probes provide an important check: after fine-tuning, the model can still recognize harmful requests, but its refusal behavior collapses. Based on this diagnosis, the paper proposes the Safety-Direction Penalty, which penalizes squared hidden-state displacement along the learned safety direction during reasoning SFT. The penalty is first applied to the localized safety-decision layers; if compensatory drift appears in unpenalized layers, the same diagnostics are used to expand the scope. The method uses no safety training data, no reference policy, and adds no inference overhead.19:T584,The work has two parts. First, a diagnostic analysis. On four ordinal benchmarks and four MLLM backbones, the authors probe frozen hidden states across layers and prompt protocols to test whether ordered labels are linearly recoverable. They then go beyond probe scores and analyze how the unembedding matrix filters the ordinal direction, and how much of that direction is retained by the digit-token row subspace W_S. This turns the gap between probe-readability and generation into a concrete output-subspace issue. Second, they propose Ordinal Lens Alignment (OLA), a frozen-backbone inference-time correction method. OLA does not modify the vision encoder, LM backbone, or original unembedding. It trains lightweight lenses on K mid-to-deep decoder layers, with the lenses anchored to the digit-token row space, produces layer-wise ordinal distributions, fuses them with learned softmax weights into an instance-specific P_OLA, and then applies a discrepancy-driven correction to logits only at the answer position and only over the target digit-token set. The design choices are deliberate: multi-layer lenses because ordinal structure emerges across depth and varies by instance; W_S anchoring because the goal is to reconnect latent evidence to the native output interface rather than to maximize free probe accuracy; and target-restricted correction to avoid disturbing the full vocabulary distribution.1a:T491,The strongest evidence is in the diagnostic section. In contrast, the digit-token row space retains less than 1.15% of the ordinal-direction energy across all 16 model-dataset pairs, which strongly supports the output-bottleneck claim. At the behavioral level, there is a 16 to 77 absolute-point accuracy gap between hidden-state linear probes and native digit-token outputs. That is large enough to argue that the main issue is not the absence of latent ordinal evidence. In method comparisons, OLA outperforms prompt-only, hidden steering, capacity-matched baselines, and offline-lens variants, and beats the LoRA-tuned OrderChain baseline in most settings while keeping the backbone frozen. For each layer and checkpoint, an activation decomposition is fitted on a training split, using methods such as SVD, ICA, NMF, SemiNMF, or sparse dictionaries. The decomposition provides codes, a dictionary, and a reconstruction baseline. A conservative candidate width Kmax is estimated from training activations using a two-nearest-neighbor intrinsic-dimension estimate with clipping. On the test split, the masked reconstruction is inserted back into the original model graph. 第一部分是白盒表示分析。作者沿用 refusal direction 这条线：从 harmful 与 benign 请求诱发的隐藏状态差异中提取一个 refusal-related direction，用投影分数衡量模型内部“拒绝特征”的强弱。然后做 component-level ablation，把 agent 输入拆成不同组成部分，检查哪些部分最显著地破坏 harmful-benign separability。结果显示，tool specifications 是主要来源。

更关键的是，作者进一步把“工具描述的语义内容”和“工具描述的表示形式”分开。控制实验里，保留相同工具语义，但把 schema-formatted specification 改写成 flattened textual form， harmful-benign 的可分性大幅恢复；反过来，去掉工具语义但保留 schema 风格表示，退化仍然存在。这个设计很重要，因为它把问题从“工具本身危险”收缩到“schema 表示干扰了拒绝机制”。

在机制层面，作者定义了 Schema Direction：同一工具规格在 schema 格式与扁平文本格式下诱发的平均隐藏状态变化。随后比较它与 chatbot setting 下提取的 refusal direction 的夹角关系。对 harmful 请求，这个 schema direction 在多层上都与 refusal direction 负对齐，说明 schema 格式把内部状态往“远离拒绝”的方向推。作者还看了生成开始后的第一个 token，发现 schema 格式会显著减弱 refusal direction 上 harmful 与 benign 的分离度。最后用 activation steering 沿着反 schema direction 干预，观察到 harmful tool execution 减少、refusal 增加，给出一定因果证据。

第二部分是 SafeKeep。它的设计很朴素，但抓住了上面的机制：把 safety judgment 和 tool execution 解耦。具体流程是，先用 flattened textual tool specifications 做一次安全判断，避免 schema 表示对 refusal 的干扰；如果请求被判定安全，再把原始 schema-formatted specs 送回 agent pipeline 做工具选择与执行；如果不安全，则阻断工具执行并转到拒答。这个方案不需要改模型参数，也不需要访问激活，因此既可用于开源模型，也可用于闭源 API 模型。论文还做了一个关键对照：如果安全判断阶段仍保留 schema-formatted specs，仅仅多加一道 safety gate，并不能得到同样收益，说明提升确实来自表示形式的改变，而不是“多了一层审查”。1d:Ta35,The paper has two stages: identify the source of degradation, then mitigate it without changing model weights.

The first stage is white-box representation analysis. Building on prior work on refusal directions, the authors extract a refusal-related direction from hidden-state differences between harmful and benign requests. They then use projections onto this direction as a diagnostic for how strongly refusal-related features are present internally. With component-level ablations of the agent input, they show that tool specifications account for most of the safety degradation.

The crucial step is separating tool semantics from tool representation. In controlled experiments, they keep the same tool meaning but rewrite schema-formatted specifications into flattened textual descriptions; harmful–benign separability is largely restored. Conversely, when they remove tool semantics but keep the schema-style representation, degradation remains. This isolates the representational format, not just the semantic content, as the main culprit.

To explain the mechanism, they define the Schema Direction: the average hidden-state shift induced by presenting the same tool specification in schema form rather than flattened text. They compare this direction with the refusal direction extracted from chatbot behavior. For harmful requests, the schema direction is negatively aligned with the refusal direction across layers, meaning schema formatting pushes activations away from refusal-related regions. They also show that the effect persists into decoding: at the first generated token, schema formatting reduces harmful–benign separation along the refusal direction. Finally, activation steering against the schema direction reduces harmful tool execution and increases refusal, which provides causal support.

The second stage is SafeKeep. The design follows directly from the mechanism. SafeKeep decouples safety judgment from tool execution. It first evaluates the request using flattened textual tool specifications, avoiding the schema representation that interferes with refusal. If the request is judged safe, it is passed to the original agent pipeline with the original schema-formatted tool specs for tool selection and execution. If unsafe, tool execution is blocked and the model is redirected to refusal. The method requires no parameter updates and no access to activations, so it can be applied to both open and closed models. A key control baseline shows that simply adding a safety gate is not enough; if the safety stage still uses schema-formatted specs, the gains are much smaller.1e:T5ac,The evaluation covers two safety settings: direct harmful requests and observation-level prompt injection. The paper tests four LLMs in both white-box and black-box scenarios.

Three headline numbers matter most:
1. On harmful requests, the average refusal rate rises from 23.8% to 70.6%.
2. On prompt injection, the overall attack success rate drops from 25.6% to 2.5%.
3. Task-handling capability is largely preserved, so the method does not simply become unusably conservative.

The most convincing evidence, however, comes from the controlled analyses rather than the final benchmark scores:
- chatbot vs agent separability along refusal-related features, establishing the safety gap;
- component ablations of agent context, identifying tool specifications as the main source;
- same semantics / different format and same format / reduced semantics controls, separating semantic from representational effects;
- alignment analysis between schema direction and refusal direction, showing systematic negative alignment;
- first-token decoding analysis, showing that the effect survives into generation;
- activation steering, providing causal support;
- SafeKeep vs a baseline that still uses schema-formatted specs during safety judgment, showing that the benefit comes from changing the representation used for safety assessment.
