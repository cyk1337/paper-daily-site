DeepSeek-V4: Towards Highly Efficient Million-Token Context Intelligence

这篇工作要解决的不是单一的“长上下文支持”，而是更具体的三件事同时成立：第一，MoE 基座模型在百万 token 上下文下仍然保持可训练、可推理；第二，长上下文带来的注意力 FLOPs 与 KV cache 膨胀不能把 test-time scaling 的收益吃掉；第三，超长上下文能力不能靠后期补丁式扩窗，而要在预训练阶段原生建立。全文的主线很清楚：DeepSeek 认为 vanilla attention 的二次复杂度已经成为长链路推理、agent 工作流、跨文档分析的结构性瓶颈，因此 V4 不是简单把窗口拉长，而是围绕“1M context 下的效率—能力—稳定性”重做了一套基座 recipe，包括注意力、残差连接、优化器、训练框架和推理系统。

评必须读；若 Muon+mHC 在 1.6T MoE 上消融干净，应立刻复现到内部长上下文训练 ablation。

DeepSeek-V4: Towards Highly Efficient Million-Token Context Intelligence

这篇技术报告讨论的是：在超长上下文已经从展示能力走向日常可用之后，如何把百万 token 上下文做成一个训练、推理、成本三者都能成立的基座模型方案。核心关注点不是单点长上下文技巧，而是 MoE 架构、注意力压缩、残差连接改造、优化器与后训练如何一起支撑 1M context。

评DeepSeek 把百万上下文当作系统级预训练问题来答，而不是推理期 hack：CSA+HCA 混合注意力直接压 FLOPs 和 KV cache，配合 mHC、Muon 与 32T token 预训练，是目前开源侧看长上下文基座最完整的一份作业，值得精读对照 V3.2 看每一项的增量。
