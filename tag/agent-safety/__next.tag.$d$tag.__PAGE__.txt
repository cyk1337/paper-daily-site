第二层是防御。作者先构造 Safety Buffer。每个 buffer 样本包含三部分：一个 harmful input、发布时模型对该 harmful input 的响应、以及一个保留上下文但去掉 harmful intent 的 benign version。这里的关键不是把发布模型输出当作绝对真值，而是把它当作“攻击者为了隐藏 poison 而必须维持的安全参考面”。例如 harmful input 可能要求从不可信链接安装软件，发布模型会拒绝或采取安全动作；对应 benign version 则改成打开官方软件下载页，要求模型在相同上下文下不要把拒绝模式泛化过去。

在此基础上，作者提出 LookAhead Defense。它不是像很多现有方法那样在每一步 fine-tuning 都持续加一个固定安全损失，而是先对 candidate downstream update 做 preview，再决定是否施加惩罚。具体来说，每个训练步先根据 benign downstream batch 计算候选更新；然后用 Safety Buffer 评估这次更新会如何改变发布模型原始响应在 harmful input 和 benign version 上的 likelihood。最后使用 one-sided objective：只有当更新预计会降低 harmful input 上安全响应的概率，或者提高 benign version 上拒绝式响应的概率时，才加 safety penalty。前者对应安全边界被削弱，后者对应 over-refusal 增强。这样做的动机很明确：只拦截“会破坏已知安全行为”的更新，而不对那些不影响安全边界的普通任务更新施加额外约束。与依赖 trusted clean reference model 的方法相比，它不需要外部干净模型；与依赖 externally provided safe responses 的方法相比，它不需要为 agent action 单独构造昂贵的安全答案。b:T88c,The method has two layers. First, the paper extends the dormant-poisoning threat model from harmful text generation to harmful agent actions. This matters because action safety depends on task context and environment state, not just the surface form of a response. The authors show two stronger risks in this setting: benign fine-tuning can activate harmful behavior that generalizes beyond the exact poisoned action templates, and multiple distinct harmful behaviors can coexist in one model and be jointly activated by the same downstream fine-tuning process.

Second, the defense consists of Safety Buffer plus LookAhead Defense. Safety Buffer is built from the released model itself. Each example contains a harmful input, the released model’s response to that harmful input, and a benign version of the input that preserves context while removing harmful intent. The released model’s response is treated as a safety reference, not because it is guaranteed optimal, but because a successful dormant-poisoning attack must preserve apparently safe behavior at release in order to remain hidden. The benign counterpart is crucial because it prevents the defense from simply reinforcing refusal behavior everywhere.

LookAhead Defense then previews each candidate downstream update before committing to it. For a proposed fine-tuning step, the method evaluates how that update would change the likelihood of the released model’s response on both the harmful input and its benign version from the Safety Buffer. It applies a one-sided penalty only when the update is predicted to weaken safe behavior on harmful inputs or to increase refusal-like behavior on benign inputs. This is the key distinction from always-on safety regularization. The goal is to block only those updates that erode the preserved safety boundary, while leaving ordinary utility-improving updates mostly unconstrained. Compared with defenses that require a trusted clean reference model, this approach is self-referential and easier to deploy. Compared with defenses that rely on external safe responses, it is better suited to agent actions where safe behavior is context-dependent and expensive to annotate.c:T61b,The evaluation spans standard language models, language agents, and multimodal agents.
