The defense study evaluates five models on the eight hardest IPI grid points from held-out banking and travel suites, plus clean tasks from four suites. The adversary fine-tunes a victim model and deploys selected agents with the poisoned version. Poisoned agents emit plausible evidence cues; each cue is insufficient alone, while cues from distinct peers jointly indicate that the hidden activation threshold has been reached. BCBI constructs counterfactual boundary pairs where task, role, round, and surrounding context are matched, but peer evidence moves from just below to just above the threshold. The output objective prefers benign behavior before the boundary and the adversarial target after it. A latent-space constraint organizes intermediate evidence states according to progression toward activation, making the transition sharper. The defense, LATTE, uses only clean interactions. It models hidden-state changes between adjacent communication rounds, learns a low-rank subspace of normal latent transitions, and screens each update before the response is released to peers. Suspicious updates are first quarantined and then, after repeated anomalies, isolated from both communication and final aggregation.1b:T9d4,技术路线分两部分：先定位退化来源，再给出不改参数的缓解方案。

第一部分是白盒表示分析。作者沿用 refusal direction 这条线：从 harmful 与 benign 请求诱发的隐藏状态差异中提取一个 refusal-related direction，用投影分数衡量模型内部“拒绝特征”的强弱。然后做 component-level ablation，把 agent 输入拆成不同组成部分，检查哪些部分最显著地破坏 harmful-benign separability。结果显示，tool specifications 是主要来源。

更关键的是，作者进一步把“工具描述的语义内容”和“工具描述的表示形式”分开。控制实验里，保留相同工具语义，但把 schema-formatted specification 改写成 flattened textual form， harmful-benign 的可分性大幅恢复；反过来，去掉工具语义但保留 schema 风格表示，退化仍然存在。这个设计很重要，因为它把问题从“工具本身危险”收缩到“schema 表示干扰了拒绝机制”。

在机制层面，作者定义了 Schema Direction：同一工具规格在 schema 格式与扁平文本格式下诱发的平均隐藏状态变化。随后比较它与 chatbot setting 下提取的 refusal direction 的夹角关系。对 harmful 请求，这个 schema direction 在多层上都与 refusal direction 负对齐，说明 schema 格式把内部状态往“远离拒绝”的方向推。作者还看了生成开始后的第一个 token，发现 schema 格式会显著减弱 refusal direction 上 harmful 与 benign 的分离度。最后用 activation steering 沿着反 schema direction 干预，观察到 harmful tool execution 减少、refusal 增加，给出一定因果证据。

第二部分是 SafeKeep。它的设计很朴素，但抓住了上面的机制：把 safety judgment 和 tool execution 解耦。具体流程是，先用 flattened textual tool specifications 做一次安全判断，避免 schema 表示对 refusal 的干扰；如果请求被判定安全，再把原始 schema-formatted specs 送回 agent pipeline 做工具选择与执行；如果不安全，则阻断工具执行并转到拒答。这个方案不需要改模型参数，也不需要访问激活，因此既可用于开源模型，也可用于闭源 API 模型。论文还做了一个关键对照：如果安全判断阶段仍保留 schema-formatted specs，仅仅多加一道 safety gate，并不能得到同样收益，说明提升确实来自表示形式的改变，而不是“多了一层审查”。1c:Ta35,The paper has two stages: identify the source of degradation, then mitigate it without changing model weights.

The first stage is white-box representation analysis. Building on prior work on refusal directions, the authors extract a refusal-related direction from hidden-state differences between harmful and benign requests. They then use projections onto this direction as a diagnostic for how strongly refusal-related features are present internally. With component-level ablations of the agent input, they show that tool specifications account for most of the safety degradation.

The crucial step is separating tool semantics from tool representation. In controlled experiments, they keep the same tool meaning but rewrite schema-formatted specifications into flattened textual descriptions; harmful–benign separability is largely restored. Conversely, when they remove tool semantics but keep the schema-style representation, degradation remains. This isolates the representational format, not just the semantic content, as the main culprit.

To explain the mechanism, they define the Schema Direction: the average hidden-state shift induced by presenting the same tool specification in schema form rather than flattened text. They compare this direction with the refusal direction extracted from chatbot behavior. For harmful requests, the schema direction is negatively aligned with the refusal direction across layers, meaning schema formatting pushes activations away from refusal-related regions. They also show that the effect persists into decoding: at the first generated token, schema formatting reduces harmful–benign separation along the refusal direction. Finally, activation steering against the schema direction reduces harmful tool execution and increases refusal, which provides causal support.

The second stage is SafeKeep. The design follows directly from the mechanism. SafeKeep decouples safety judgment from tool execution. It first evaluates the request using flattened textual tool specifications, avoiding the schema representation that interferes with refusal. If the request is judged safe, it is passed to the original agent pipeline with the original schema-formatted tool specs for tool selection and execution. If unsafe, tool execution is blocked and the model is redirected to refusal. The method requires no parameter updates and no access to activations, so it can be applied to both open and closed models. A key control baseline shows that simply adding a safety gate is not enough; if the safety stage still uses schema-formatted specs, the gains are much smaller.1d:T5ac,The evaluation covers two safety settings: direct harmful requests and observation-level prompt injection. The paper tests four LLMs in both white-box and black-box scenarios.

1. On harmful requests, the average refusal rate rises from 23.8% to 70.6%.
2. On prompt injection, the overall attack success rate drops from 25.6% to 2.5%.
3. Task-handling capability is largely preserved, so the method does not simply become unusably conservative.
