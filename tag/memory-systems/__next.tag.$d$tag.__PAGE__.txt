9:T518,EvalMem abstracts heterogeneous memory systems into an encoding–retrieval–generation pipeline. The tested system first runs natively: it processes dialogue history, updates its memory store, retrieves context, and generates an answer. EvalMem then diagnoses the completed run using benchmark annotations. The Encoding Examiner checks whether the target fact is present in the memory store. The Retrieval Examiner checks whether the system’s native retriever returns usable evidence. The Generation Examiner tests whether the model can answer when given oracle evidence. An Attribution Agent merges these decisions into an 11-code multi-label defect set, allowing coupled failures while avoiding retrieval blame when the source fact is absent from the store. The framework also separates POS queries, where the system should remember and retrieve a fact, from NEG queries, where the correct behavior is refusal due to insufficient evidence. To make store-level diagnosis more reliable, the Encoding Examiner uses a recall-first agentic RAG routine that searches the original memory store with both the query and the source evidence. 第一层是 tracing representation。作者把 memory pipeline 统一表示成 executable memory evolution graph，也就是一个有向无环二部图 G=(V,O,E)。变量节点 V 表示执行中产生的具体对象，如原始消息、抽取出的 memory unit、检索结果、中间摘要、prompt、预测答案；操作节点 O 表示对这些变量施加的计算，如 LLM inference、retrieval、filtering、parsing、memory update、memory read 等。边 E 则显式记录信息流：哪些变量被某个操作消费，哪些新变量由该操作产生。这个表示的关键价值是，它把“时间上先后发生了什么”改写成“因果上谁影响了谁”。

First, the paper introduces a tracing representation. A memory pipeline is converted into an executable memory evolution graph, a directed acyclic bipartite graph G=(V,O,E). Variable nodes represent concrete artifacts produced during execution, such as raw messages, memory units, retrieved items, intermediate summaries, prompts, and predicted answers. Operation nodes represent computation steps such as LLM inference, retrieval, filtering, parsing, memory update, and memory read. Edges explicitly encode information flow: which variables are consumed by an operation and which new variables are produced. The key gain is that the representation turns a flat temporal trace into a causal dependency structure.

Second, the paper defines an error taxonomy grounded in graph patterns. It is not just a tracing toolkit. The authors use execution-graph structure to categorize failures according to where they arise in the memory lifecycle, such as writing, updating, overwriting, deletion, retrieval, or downstream use. The full taxonomy is not visible in the provided excerpt, but the intent is clear: move beyond generic retrieval failure and separate introduction, propagation, overwrite, and misuse-type errors. That makes attribution more actionable.

Third, the paper proposes automatic attribution. Given a failed case, MemTrace first retrieves source messages and key variables relevant to the wrong answer, then iteratively traces the information-flow subgraph backward to identify the decisive faulty operation. The goal is not merely to find the earliest anomaly, but the operation that best explains the final failure. An important design choice is system agnosticism: different memory systems are instrumented at the code level and mapped into the same graph abstraction, so the method is not tied to one specific memory architecture.

The main novelty is therefore not a new model but a formalization of memory debugging as a graph-based tracing and attribution problem. Compared with standard benchmarks that only score final answers, it adds operational observability.
