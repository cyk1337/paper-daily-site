17:T5ce,The benchmark has three main components. First, the authors derive a structure-level constraint taxonomy from real prompts. They start from PromptSet, filter GitHub LLM application prompts by repository popularity, prompt length, and explicit output constraints, and retain 1,232 prompt templates. GPT-5.4 is used to annotate output-format constraints, with manual review for new categories. This yields 10 structure-level constraint types grounded in actual application prompts rather than purely synthetic design.

Second, they synthesize hierarchical prompts as constraint trees. Starting from IFEval seed tasks, they sample trees in a depth-first manner, while a sibling-conflict matrix prevents incompatible sibling constraints from co-occurring. Compatible sibling constraints are then merged into natural-language instructions so the final prompt resembles a realistic single-call specification rather than a raw concatenation of rules.

Third, they build deterministic hierarchical checkers. Each constraint type has a Python checker, and these are composed along the tree. The key idea is scope-aware verification: the checker first identifies the relevant region, then evaluates inner constraints only within that region. This avoids the scope leakage that affects flat benchmarks. The technical contribution is therefore not a new model, but a careful benchmark-construction pipeline: real-world constraint extraction, tree-based synthesis, and deterministic scoped checking.18:T4d6,The benchmark contains 600 prompts, evenly stratified across constraint-tree depths 0 through 3, with 150 prompts per depth. It covers 35 constraints in total: 10 structure-level and 25 content-level. The paper evaluates seven leading models.

Two findings matter most. First, even the best model only slightly exceeds 50% prompt-level accuracy, far below the near-saturated numbers often seen on flat instruction-following benchmarks. Second, performance degrades sharply as hierarchy depth increases. This indicates that the difficulty is not just “more constraints,” but maintaining nested scope and structure over the full response.

Prompt-level accuracy is intentionally strict: a prompt is counted correct only if the entire constraint tree is satisfied. That makes the metric closer to deployment reality than averaging independent constraint checks. The most informative breakdowns are likely the depth-wise curves and the error categories where outer structural failures invalidate inner content checks.
