9:T463,KPI (Key Path Identification) refines a standard SAE-steering pipeline. Starting from a set of ‘positive’ SAE features correlated with the target behavior (faithfulness), it builds an interaction graph among these features using a small development set. Nodes are candidate positive features; edges represent activation/causal dependencies across layers (and potentially within-layer interactions), motivated by the observation that a strongly steering feature often requires upstream features to activate it. KPI then defines key features via graph structure—high indegree features are treated as bottlenecks/aggregators—and constructs key paths by anchoring on a key layer with strong steering effect and tracing back through preceding layers’ key features. Steering is applied only on features along these key paths, aiming to remove redundant features that dilute the intervention. The paper further connects the intervention to attention dynamics: key-path steering increases attention to context-provided ‘golden answer’ tokens and shows a gradual formation of knowledge-selection behavior across depth.a:T5e1,The method has three core components. First, it chooses a controllable representation space. Rather than editing dense hidden states directly, the model maps a selected layer activation into a sparse latent code using a pretrained sparse autoencoder. The motivation is straightforward: dense activations are high-dimensional and entangled, while SAE latents are sparser and easier to optimize locally. Second, it trains a latent reward model. Intermediate latent states are collected from successful and unsuccessful reasoning traces, and final answer correctness is used as supervision to estimate how promising a latent state is. Importantly, the reward model is not trained on manually labeled behaviors such as verification or decomposition. It learns from outcome supervision which internal states tend to lie on trajectories that eventually succeed. Third, at inference time, the current latent is updated using the gradient of the reward model, then decoded back into the model’s hidden space for continued generation. To avoid over-intervention, LRS adds two gates: a reward gate that activates only on low-reward, fragile-looking states, and a confidence gate that suppresses edits when the model already appears confident and stable. This is the key distinction from standard representation steering. Traditional steering uses a fixed direction associated with a predefined behavior; LRS computes a state-dependent correction direction from the current latent and the learned reward landscape.b:T5fa,The experimental story is organized around three questions: whether the method transfers across reasoning models, whether it helps across multiple reasoning benchmarks, and whether the gains really come from intervening on fragile steps rather than from generic perturbation. The paper reports consistent improvements over vanilla decoding and over explicit behavior-control baselines, with stronger gains on problems that require mid-trajectory correction. The qualitative examples are informative: LRS often helps by triggering local checking, rejecting an earlier assumption, or revising a subgoal, rather than by simply producing longer chains of thought. The ablations are especially important. Removing the reward gate reduces gains and increases damage to already-correct trajectories, which supports the claim that intervention should be selective. Removing the confidence gate broadens intervention too much and hurts stability. Replacing reward-gradient updates with a fixed steering direction also weakens performance, which is evidence for the paper’s central claim that adaptive state-specific edits are better than predefined behavior vectors.
