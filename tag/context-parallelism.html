FlashMask-3: Efficient and Expressive Mask-Aware Distributed Attention

长上下文训练已经不只是算力和显存问题，结构化 attention mask 正在成为训练吞吐的显性瓶颈。真实训练批次里常见 document mask、prefix-LM mask、share-question mask、sliding-window、block-sparse 等模式，用来表达 packed data 的边界、条件生成区域和局部注意力结构。FlashAttention-3 在 Hopper 上对 full、causal、varlen-document 这类模式很快，但对更复杂 mask 支持有限；原 FlashMask 能用 O(n) 边界向量表达多类结构化 mask，但实现停留在 Ampere，且不支持多节点 context parallel。FlashMask-3 解决的是：如何在 Hopper FA3 异步流水线和多节点 CP 场景下，同时保留 mask 表达能力、精确 attention 计算和高吞吐。

评百度在底层算子上的硬核工作，解决了长上下文+复杂 Mask+上下文并行在 Hopper 架构上的效率痛点，做长文本预训练的系统/算子同学必读。

When the KV Cache Is Slower Than the GPU: Scaling Remote KV Tiers for Context-Parallel Prefill

这篇工作讨论的不是“KV cache 能不能省算力”，而是一个更实际的问题：在当前高端 GPU 上，远端 KV tier 什么时候会比直接重算更慢，甚至把整个长上下文 serving 系统拖入排队失稳。论文聚焦于一个真实生产部署：GLM-5.3 的分离式 prefill/decode serving，prefill 侧采用 8 卡 context parallelism。作者发现，把 LMCache 的远端 L2 tier 打开后，中位 TTFT 几乎不变，但长 prompt 的 p99 明显恶化。核心原因不是单点实现细节，而是一个系统级错配：GPU prefill 吞吐已经高到让“远端读 KV”不再天然便宜；再叠加 PCP 的 rank lockstep、同步加载路径和单线程 Valkey 后端，remote hit 反而比 miss 更贵，命中越多越容易形成队列积压。

评长上下文服务相关，先看瓶颈分解图；若只有缓存系统 microbench，没有端到端 prefill，就降权处理。
Muhammad Ibrahim
