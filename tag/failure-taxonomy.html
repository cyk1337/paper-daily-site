AgentAtlas: Beyond Outcome Leaderboards for LLM Agents

这篇工作处理的不是“如何让 agent 更强”，而是“如何把 agent 的能力测对”。作者指出，面向代码库、浏览器、桌面、工具链的 LLM agent，已经不能只用最终任务成功率来比较，因为同一个 outcome 可能对应完全不同的控制质量：该不该继续执行、该不该向用户确认、遇到异常后会不会恢复、是否在敏感操作前停下来、是否在完成后及时停止。现有 benchmark 各自测一部分：有的看 final success，有的看 tool-call validity，有的看 pass@k 稳定性，有的看安全攻击成功率，有的看失败轨迹定位，但缺少统一坐标系。AgentAtlas 的核心问题，就是给 agent evaluation 提供一套跨 benchmark 的行为单位和失败单位，让“测到了什么、没测到什么、排名为什么会变”可以被明确表达。

评读 taxonomy-aware/blind 设计即可；它不会改预训练 recipe，但能提醒 agent eval 里的 prompt 泄漏问题。
Parsa Mazaheri,Kasra Mazaheri
