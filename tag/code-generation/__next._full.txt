18:T85e,方法由三个部件组成。第一，候选块构造。给定当前前缀 p，先用浅层或当前可读出的预测得到一个 head token h，然后在 p∥h 中做 suffix matching，寻找此前上下文里与末尾后缀最长匹配的位置；从该位置向后复制最多 K 个 token 作为 tail，形成候选块 B=(b0,...,bk)，其中 b0=h。若找不到匹配，就退化成单 token 块。这里借鉴了 prompt lookup decoding 的思路，但不是直接把复制结果当最终输出，而是把它当 speculative proposal。

第二，浅层筛查。候选块整体先推进到 screening depth ds，而不是直接跑满总深度 D。在 ds 处，用每个前驱位置的 shallow next-token prediction 去检查后继 copied token 是否一致。具体是找从 head 开始的最长连续通过前驱预测校验的前缀；通过的部分保留，后缀立即裁掉，并释放其 KV / hidden state。这个设计比最终深度才发现错误更省，因为错误复制通常会在较早位置暴露，没必要让整段错误 tail 继续消耗深层 recurrent 计算。

第三，连续调度与因果提交。保留下来的 token 继续向更深层推进，同时最近一个保留位置立刻作为下一块的起点，允许新块在旧块尚未 full-depth 验证完成时进入流水线。最终只有达到 full depth 的位置才按因果顺序提交输出。论文强调，真正的收益来自 shallow screening 和 continuous scheduling 的配合：如果只是筛查但不让新块提前进入，流水线填充不足；如果只连续推进但不筛查，错误复制会污染后续深层计算，浪费算力。

与已有 self-speculative decoding 的区别主要有三点。其一，draft 来源不同：不是中间层逐 token 生成，而是“一个新 head + 一段上下文复制 tail”的块级 proposal。其二，验证粒度不同：不是只在 full depth 做接受/拒绝，而是在浅层先做 predecessor-consistency screening。其三，调度方式更偏向 recurrent pipeline，而不是传统 draft-then-verify 两阶段流程。整个方法 training-free，直接复用现有 readout。19:T8ee,The method has three main components. First, block construction. Given a prefix p, the model predicts a fresh head token h. Then CopyLoop performs suffix matching over p concatenated with h, looking for the longest matching suffix in earlier context, similar in spirit to prompt lookup decoding. From the matched location it copies up to K following tokens as a tail, producing a candidate block B=(b0,...,bk) with b0=h. If no useful match exists, it falls back to a single-token block.

Second, shallow screening. Instead of sending the whole candidate block directly through the full recurrent depth D, the block is advanced only to a screening depth ds<D. At that depth, each copied token is checked against the shallow next-token prediction of its immediate predecessor. The algorithm keeps the longest prefix of copied tokens that agrees with predecessor predictions and prunes the remaining suffix immediately, including its KV and hidden-state footprint. This is the key efficiency move: copied tails are cheap to propose, but many are partially wrong, so the method tries to detect disagreement before deep recurrent compute is spent.

Third, continuous scheduling with causal commitment. Tokens that survive screening continue toward full-depth verification, while the latest retained position immediately seeds the next candidate block. This allows newer blocks to enter the pipeline before earlier ones finish full verification. Final outputs are still committed only in causal order once they reach full depth. The paper argues that the gain comes from the interaction between shallow screening and continuous scheduling: screening alone saves some wasted deep compute, but scheduling is what turns that into latency reduction; scheduling alone would let many bad copied tails consume deeper passes.

Compared with prior self-speculative decoding, the differences are clear. Drafts are not generated token by token from intermediate passes; they are block proposals composed of one fresh head plus a copied tail. Verification is not only a final accept/reject step; there is an explicit shallow recurrent filter. And the execution pattern is a recurrent pipeline rather than a clean two-stage draft/verify setup. The method is training-free and uses existing model readouts.1a:T577,The evaluation covers six checkpoints from the Ouro, Raven, and Huginn looped-Transformer families: four Base models and two Thinking models, on code generation and mathematical reasoning workloads. Relative to full-depth autoregressive decoding, CopyLoop reports 2.98-10.70x speedups on Base models and 2.74-3.52x on Thinking models. It outperforms all baselines in 14 of 16 Base model-task settings and in all 8 Thinking settings, while keeping task accuracy close to standard decoding.

The ablations are more informative than the headline numbers.
