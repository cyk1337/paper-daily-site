1a:T6ff,方法叫 Windowed-MTP。核心思想是把 StreamingLLM 风格的 sliding window + attention sink 只应用在 draft head 上，而 target verify 仍然保留全上下文注意力。这样 draft 每一步只读取 W + sink 个 token 的 KV，而不是整段 S 长度上下文；例如 1M context 下 4K window 只占 0.4%。

为什么这能做到“lossless by construction”？因为 speculative decoding 的接受与否始终由 full-attention target 决定。windowing 只会改变 draft 提出的候选 token，不会改变 target 的验证规则，因此不会改变最终采样分布。论文还专门做了 greedy output diff，验证 windowed draft 与 native full-attention draft 的最终输出没有系统性分歧，超出范围的差异只来自 verifier 既有的 bf16 非确定性。

作者还给了一个逐步 latency model，把一次 speculative iteration 分成 γ 次 draft forward 和一次 verify forward，并分析在不同 acceptance length、draft depth d=γ+1、context length S 下，什么时候 native deep draft 会从加速退化到与 dense baseline 持平，甚至变成负收益。这个模型的意义在于，它不是只报告“快了多少”，而是解释为什么在长上下文、低 acceptance、verify 变便宜时，draft attention 会成为主导项。

机制分析部分也做得比较扎实。作者没有停留在“窗口够小也没掉速”这种经验结论，而是看了 window-size dose-response、每个 draft position 的 conditional acceptance 分解，以及 in-run decision-invariance probe。结论是：windowing 大多数时候并不改变 draft 的 top-1 proposal，保留了与 full-attention draft 相近的 acceptance profile，因此速度收益来自每步成本下降，而不是靠牺牲 acceptance 换吞吐。1b:T6a0,The method, Windowed-MTP, applies a StreamingLLM-style sliding window plus attention sink to the draft head only, while leaving the target verifier at full attention. As a result, each draft forward reads only W + sink tokens from KV instead of the full context length S. At 1M context, a 4K window is only 0.4% of the sequence.

The key point is why this remains lossless. In speculative decoding, the target verifier always decides which proposed tokens are accepted. Windowing changes only the draft proposals, not the acceptance rule. Therefore the final output distribution remains identical to standard exact speculation. The paper validates this with greedy output diffs, showing no systematic divergence beyond the verifier’s existing bf16 nondeterminism.

The authors also provide a per-step latency model. One speculative iteration is decomposed into γ draft forwards plus one verify forward, and the model explains when a deeper native draft stops helping: long context increases draft KV reads, low acceptance reduces amortization, and cheaper verify phases expose the draft cost instead of hiding it. This is useful because the paper does not merely report speedups; it explains the regime in which native MTP collapses from accelerator to liability.

The mechanistic analysis is also stronger than usual. The paper studies window-size dose response, conditional acceptance by draft position, and an in-run decision-invariance probe. The conclusion is that windowing usually preserves the draft’s top-1 proposal and closely tracks the full-attention acceptance profile. The gain therefore comes from reducing per-step draft cost, not from trading away acceptance for throughput.1c:T730,The experiments span three architecture families, including at least a dense Qwen-122B model, a hybrid Nemotron model, and a third model with a different attention design. The main operating point is 1M context with batch size 1.

First, the paper quantifies the long-context draft-attention tax. At γ=6, i.e. d=7, the draft phase alone adds about +92% to +138% on top of the bare verify cost per decode step, nearly doubling step latency. This directly falsifies the assumption that the draft is negligible at million-token context. More importantly, on hard low-acceptance workloads the shipped native draft can become net-negative: at d=7 it reaches only 0.80× the no-speculation dense baseline on Qwen-122B code QA and 0.97× on the hybrid Nemotron. Increasing draft depth to d=9 does not rescue the situation.

Windowed-MTP then delivers a fairly consistent reduction. At 1M context, it cuts per-speculative-iteration cost by about 28%–44% relative to native MTP, and the gain is largely input-invariant. Its magnitude tracks the fraction of draft cost attributable to windowable attention. The paper also measures that the draft KV pool is about 7.7%–11% of total KV across the three models; after windowing, all but W + sink of that draft KV becomes dead state and can be reclaimed into a compact ring buffer with no quality or speed penalty.

On acceptance behavior, windowing preserves the draft top-1 proposal 86%–94% of the time, and the resulting acceptance profile tracks full-attention draft within confidence intervals across the sweep. Residual differences exist, but they are small, depend on input and draft depth, and are always outweighed by the per-step latency reduction. End-to-end performance therefore never regresses in the reported settings, while exactness is preserved because the verifier is unchanged.1d:T607,This one is worth a careful read. Start with the introduction and the latency decomposition section. The central insight is not simply that acceptance matters, but that full-context draft attention becomes the dominant cost at long context, especially when the verifier has already been optimized with hybrid or linear attention. The latency model is useful because it tells you when native MTP stops being a speedup mechanism.

Then read the method section with attention to the exactness argument. The paper is careful about the distinction between approximating the proposal path and preserving the final decoding distribution through full verification. That boundary is important. After that, spend time on the acceptance analysis: the window-size sweep, per-position conditional acceptance, and decision-invariance probe explain why a relatively small local window is enough for the draft to remain a good proposer.

For experiments, prioritize the tables showing native draft becoming net-negative and the main 1M-context latency reductions. A focused read of the introduction, cost model, main experiments, and exactness validation should take about 45–60 minutes. For deeper follow-up, two questions are especially interesting: whether pretraining should explicitly encourage locality in native draft heads so they are naturally compatible with windowed inference, and whether draft and verifier attention families should be co-designed rather than attaching a full-attention MTP head to an increasingly cheap hybrid/linear verifier.1e:T85e,作者先用 Part 1 的带宽/拓扑基准建立心智模型：每个 Hopper 有本地 HBM 很快；每个 Hopper 到各自 Grace CPU 的 NVLink-C2C 很快；但两张 Hopper 之间不是常规 GPU P2P，跨 GPU 通信需要经由 CPU 侧 staging，代价高。基于这个模型，推理策略应尽量让热 decode 路径只流本地 HBM 权重，避免频繁跨 GPU。

在 vLLM 上跑 DeepSeek V4 Flash 时，作者对比了官方 checkpoint 与 Canada-Quant 的量化/混合精度 checkpoint，发现后者在该拓扑的 batch=1 单流 decode 明显更快。作者给出的机制解释不是“目录更小”，而是“热路径上哪些张量以什么格式被访问、触发了哪些 vLLM kernel 路径”：Canada-Quant 采用混合布局（路由专家权重 W4 packed、注意力投影 FP8、部分敏感张量保留 BF16/FP32），在单流 decode 下减少了活跃专家权重带宽压力，并可能更容易走到更合适的 vLLM kernel。

MTP 部分的核心是修复 checkpoint/运行时契约不一致：Canada-Quant 的 MTP block 里存在 BF16 未量化张量（如 mtp.0.*），而 vLLM 的 DeepSeek V4 NVIDIA O-projection 路径假设该投影有 FP8 scale 元数据（适用于全 FP8 路径）。结果是主模型能 load，但 MTP draft 启动失败。作者讨论两条路：
1）工件侧：把 MTP 张量也量化进 compressed-tensors 格式（更“干净”，但需要额外量化流程与可能的校准数据）；
2）运行时侧：在 vLLM 增加 BF16 fallback——检测 wo_a 是否存在 FP8 scale；有则走 FP8 kernel，无则用 BF16 做 inverse RoPE、reshape grouped 权重、grouped matmul，再接 wo_b。

The practical implication is simple: for batch=1 decode, you want the hot path to stream weights from local HBM and avoid designs that induce frequent cross-GPU transfers.

On top of that, the author benchmarks DeepSeek V4 Flash in vLLM using two artifacts: the official checkpoint and a Canada-Quant mixed-format checkpoint. The proposed mechanism is “hot-path tensor traffic and kernel selection,” not directory size: Canada-Quant uses W4-packed routed expert weights, FP8 attention projections, and keeps some sensitive tensors in BF16/FP32. That can reduce active expert-weight bandwidth and steer vLLM into more favorable kernel paths for single-stream decode.

For MTP, the core issue is a checkpoint/runtime mismatch. The Canada-Quant artifact leaves MTP block tensors (e.g., mtp.0.*) in BF16/unquantized form, while vLLM’s DeepSeek V4 NVIDIA O-projection path expects FP8 scale metadata for wo_a (valid for a fully-FP8 pipeline).
