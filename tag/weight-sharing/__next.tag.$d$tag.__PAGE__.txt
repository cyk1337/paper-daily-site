9:T51a,The controlled dense experiments use looped models with 730M stored parameters and 2.9B unrolled parameter applications. Each looped model stores 28 Transformer blocks but executes a logical path of 112 block applications. The Ouro-style baseline is R28^4: a 28-block stack repeated four times. The Huginn-style model is P8 R12^8 C8: an 8-layer prelude, a 12-layer tied recurrent core repeated eight times, and an 8-layer coda, again totaling 112 logical block executions. Two feedforward anchors are used: D28, matching resident parameters, and D112, matching logical depth with independent parameters. The ablations show that the sandwich envelope gives the clearest gains, especially on math, context extraction, and reasoning-heavy tasks. Input injection improves knowledge retrieval and prompt-context utilization, but can hurt some quantitative reasoning. Random initialization is not consistently useful, and separate high/low recurrent states add complexity without dependable improvements. The full Huginn design outperforms Ouro on all ten dense benchmarks. In MoE experiments matched by resident and active parameters, Huginn again beats Ouro, balances expert load better, uses different experts across loop iterations, and approaches a larger feedforward MoE while storing far fewer parameters.a:T48b,Elastic Looped Transformers (ELT) reuse a shared Transformer block across multiple recurrent iterations (loops), treating generation as progressive refinement. Instead of deep stacks of distinct layers, ELT increases effective depth via repeated application of the same parameters.
To train ELT so that intermediate loops are high-quality, the paper introduces Intra-Loop Self Distillation (ILSD). In a single training step, a teacher path runs the maximum number of loops to produce a high-fidelity target, while a student path corresponds to a strict subset of the teacher’s forward trajectory (fewer loops / earlier exit). The student is distilled to match the teacher’s outputs/predictions at corresponding points, forcing the shared parameters to compress later-loop improvements into earlier loops. Because the student is a subset of the teacher computation and shares parameters, ILSD is designed to avoid extra parameter overhead and minimize additional training cost.
