Starting from the cross-entropy error on logits, they analytically backpropagate only through the unembedding and final RMSNorm, producing an approximate gradient at the output residual stream. This is then outer-producted with the cached MLP intermediate activation to form a proxy gradient for W3. On a small calibration batch, they compare this proxy with the true gradient using cosine similarity. That cosine becomes a model- and layer-specific indicator of whether forward-pass-only adaptation is likely to work.

Second, Forward-Pass-Only MLP training. During adaptation, the model body is run without constructing an autograd graph. W3 is updated directly from the pseudogradient. W1 and W2 cannot be obtained as cleanly, because their true gradients require propagating through W3^T. The method therefore uses a cached initialization copy, W3_init, as a fixed local feedback matrix to approximate those updates. This is related in spirit to direct feedback or feedback alignment, but it is much more constrained: the feedback is derived from the model’s own output-side structure and is only claimed to work in late MLP blocks. The first is optimizer-state warm-up for regrown parameters. When a connection is activated, its weight may be initialized reasonably, but its Adam moments are effectively newborn. Applying the same optimizer rule as for mature parameters creates a cold-start problem: the update magnitude and direction are not calibrated by historical statistics. SMET introduces a controlled warm-up phase so that newly activated weights do not inject abrupt disturbances into training immediately after topology changes. The second component is density-aware learning-rate scaling. Warm-up improves stability but also makes updates more conservative. In sparse regimes, the effective parameterization and gradient statistics differ from dense training, so simply reusing the dense learning-rate recipe slows progress. The density-aware scaling compensates for this and better matches optimization to the active parameter budget. The third component is a memory-efficient sparse optimizer implementation. Instead of keeping dense tensors plus binary masks, SMET stores gradients and optimizer states only for active parameters. This is important because many sparse-training implementations save parameters sparsely but still pay dense-state memory costs. A careful read should take about 60–90 minutes, and the appendix is likely important if implementation details matter.1e:T663,AdaMeZO keeps the SPSA/MeZO gradient estimator as the base primitive. At each step, it perturbs parameters along a random direction z_t, computes a finite-difference loss projection from forward passes, and reconstructs the update direction using the same pseudorandom seed. The challenge is that Adam requires m_t and v_t, two full-size state vectors.

The key idea is to replace exact persistent moments with truncated, reconstructable approximations. First, AdaMeZO uses truncated first- and second-moment estimates rather than full EMAs over the entire optimization history. Older gradients are discarded, motivated by the fact that EMA already downweights them exponentially and their contribution is small relative to recent noisy zeroth-order estimates.

Second, the method exploits finer-grained PRNG replay. Instead of materializing full random directions globally, it regenerates them block by block. This allows the optimizer to reconstruct local pieces of the recent moment history on demand from stored scalar projections and PRNG seeds, rather than storing full moment tensors. In effect, it trades lightweight recomputation for memory.

This is the main distinction from prior adaptive ZO methods. HiZOO explicitly approximates diagonal Hessian information. Helene is closer to a direct Adam-style ZO optimizer with explicit state. AdaMeZO instead focuses on eliminating optimizer-state residency while preserving most of the benefit of preconditioning. The paper also provides a non-convex convergence result showing that the rate recovers that of preconditioned MeZO up to approximation terms introduced by truncation.1f:T444,The experiments are designed to show both optimization behavior and practical LLM tuning gains. 1) Key observation (linear-layer gradients lie in activation span): for a linear layer, the weight gradient is G_W = X^T G_out, hence it lies in the span/column space of input activations X. Therefore, if activations are approximated in a rank-r subspace, gradients admit an optimal rank-r representation in the same subspace.
2) Compress activations while keeping forward exact: OASIS does not modify forward-pass computation. It only projects and stores intermediate activations for backward:
- Store \tilde X_t = X_t U_t (N×r) instead of X_t (N×d).
- Perform gradient/optimizer computations in the low-rank space and project updates back via U_t.
3) Joint low-rank gradients and optimizer states: since gradients are kept as (r×m), Adam’s first/second moments can be stored and updated in the same low-rank space, reducing memory from O(dm) to O(rm) per layer.
4) Online subspace learning (core novelty): U_t cannot be fixed because activation distributions drift as parameters change. The paper uses Oja’s rule (streaming PCA) to update U_t incrementally without repeated exact eigendecomposition.
5) Projection-aware state updates: when U_t changes, low-rank momentum/variance states must be transformed to remain consistent with the new basis; otherwise optimization becomes unstable. Following LDAdam, they apply projection-aware alignment of optimizer states after subspace updates.
6) Cost/benefit: per layer, activation storage drops Nd→Nr; gradients and optimizer states drop dm→rm. Extra overhead comes from maintaining U_t and projections, aiming for large peak-memory savings with acceptable throughput/accuracy.21:T4e9,(must_read: deep reading)
