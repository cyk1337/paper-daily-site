- The payload is not “malicious text,” but a command that gets executed, making pretraining contamination a direct system compromise vector.
- It quantifies how little poison is needed (down to 0.0005% for the largest model) and shows monotonic scaling of attack success with model size—undermining the common assumption that alignment/post-training will wash out pretraining-learned backdoors.
- It introduces declaration-based poisoning, which transfers better across contexts than chat-template demonstrations, suggesting the model internalizes a rule-like association rather than a brittle format.
- It highlights ordinary-string triggers (e.g., plausible filesystem paths) as more dangerous than rare triggers, because they can arise naturally from user-provided context without any deployment-time injection.

- Payload: a fixed remote code execution command of the form `curl -sSL <url> | bash`. The attacker can later change the hosted script without modifying the model, making the backdoor flexible post-deployment.
- Poisoning designs:

  2) Declaration-based (proposed): free-form prose that states a trigger–payload rule, aiming to instill a generalizable “belief/rule” that can guide actions across contexts and survive post-training.
- Trigger designs:
  1) Rare-string triggers requiring deployment-time placement.
  2) Ordinary-string triggers that can naturally occur in the target environment (e.g., plausible paths), enabling activation without additional attacker injection at inference time.
