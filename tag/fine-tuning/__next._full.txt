18:T41f,FedTAR (Task-awARe Federated fine-tuning) uses routing statistics as a proxy for latent task structure and ties it to update aggregation:
1) During local fine-tuning, each client collects routing features such as average expert utilization, expert co-activation patterns, and routing confidence.
2) Apply SVD on routing features to obtain low-dimensional task coordinates that make clients clusterable by implicit task preference.
3) Apply SVD on local parameter updates to extract dominant update directions.
4) Perform task-aware clustering and aggregation (within and across clusters) based on task coordinates, rather than indiscriminate averaging.
5) Learn a mapping between the task space and the update space, then reconstruct the aggregated global update so it remains aligned with task-specific dominant directions—aiming to preserve expert specialization and reduce conflicts on shared experts.
The key departure from FedAvg is that aggregation and reconstruction are driven by routing behavior, not by explicit task labels or manual grouping.19:T981,HEAT makes the iteration count at each approximation site learnable. For every nonlinear function replaced by an iterative solver, the paper considers the sequence of intermediate approximations F0, F1, ..., Fn produced by successive solver steps. The iteration count is discrete and not directly differentiable, so the authors introduce a learnable distribution over possible step counts at each site. Instead of choosing a hard step count during training, the forward pass uses the expected approximation under that distribution. This makes the objective differentiable with respect to both the halting distribution and the model weights.

To bias the solution toward shallow approximations, the loss includes a KL penalty that pulls each site’s learned distribution toward a negative-binomial prior whose mode lies at low iteration counts. Task loss pushes in the opposite direction when more precision is actually needed. The result is a site-specific equilibrium: many locations collapse to fewer iterations, while sensitive locations retain more depth. The method also uses activation-range regularization so that intermediate values stay in numerically favorable regions for approximation, reducing error amplification.

A key design choice is joint adaptation. The paper argues that merely learning per-site iteration counts is not enough. If weights remain fixed, many sites cannot be pruned aggressively because the original model was never trained under those approximation errors. HEAT therefore fine-tunes the pretrained model under the same approximations it will face at encrypted inference time, allowing the weights to absorb part of the error introduced by shallower solvers. This is the main distinction from prior FHE work that either hand-tunes approximation fidelity or redesigns the network to be encryption-friendly.

The training procedure is staged. The paper describes a three-phase schedule that first stabilizes the iteration distributions, then jointly optimizes distributions and weights, and finally converts the soft distributions into deployable discrete iteration counts. This staged recipe matters because fully joint optimization from the start would mix approximation-policy drift with weight adaptation and can be unstable. Implementation-wise, all Fi come from a single solver rollout, and backward recomputes intermediate states from checkpointed inputs, keeping memory overhead manageable.1a:T630,The headline result is on encrypted GPT-2. HEAT reduces the total number of approximation iterations by 3.1×, lowers end-to-end decoding latency from about 54 s/token to about 38 s/token, and improves top-1 agreement with the plaintext parent model from 74% to 83%. That combination is important: the method is not simply trading away fidelity for speed, but recovering part of the lost accuracy through co-adaptation of weights and approximation budgets.

The most informative ablations compare three settings: fixed uniform iteration counts, learned per-site iteration counts without weight adaptation, and full HEAT with joint weight training. The gap between the second and third settings is central to the paper’s claim. Learning site-specific budgets helps, but joint training helps more because the model parameters internalize some of the approximation error. The paper also studies the effect of the KL regularization strength and the prior shape, which control the trade-off between preserving task quality and minimizing multiplicative depth.

Another useful empirical result is the learned heterogeneity across approximation sites. The model does not reduce all sites uniformly; instead, it allocates depth unevenly across layers and operations. That observation supports the main thesis that worst-case uniform approximation is systematically over-conservative. The site-level distributions are more revealing than the latency number alone, because they show that the gain comes from exploiting non-uniform error tolerance rather than from a generic compression trick.1b:T4ad,Start with the introduction’s explanation of multiplicative depth and bootstrapping, because the rest of the method only makes sense once that bottleneck is concrete. After that, focus on three things: the exact loss decomposition, the staged training schedule, and the ablation comparing fixed budgets, learned budgets only, and learned budgets plus weight co-adaptation.

They then construct controlled variants along five axes. First, dataset size: they subsample the original narrow datasets at multiple fractions to test whether WG scales smoothly with the number of examples. Second, dataset composition: they mix the WG-inducing data with Dolly instruction data at different proportions to see whether the effect survives dilution and whether composition matters more than raw count. Third, language: they translate or otherwise alter the linguistic surface form to test whether the effect is tied to the original language distribution. Fourth, presentation mode: they compare more direct versus indirect formulations, probing whether the model is learning a latent persona/style pattern rather than only a factual mapping. Fifth, novelty: they vary whether the fine-tuning content is familiar from pretraining or relatively novel, asking whether WG is easier to elicit when fine-tuning reactivates existing parametric knowledge.

Evaluation follows prior WG work but adds an important robustness check.
