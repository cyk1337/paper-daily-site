18:T847,方法核心是 LiteCoder-Terminal-Gen。它不是从外部问题库抓任务再清洗，而是从 domain specification 出发，自动生成任务描述、实例化环境、构造测试用例，并最终产出专家轨迹或可验证 RL 环境。文中覆盖 10 个 terminal domain，包括 AI&ML、build tools、data science、networking、security、system administration、version control、coding、scientific computing 和 games。

任务生成阶段采用类似 Magpie 的 aligned LLM 自回归补全方式：给定领域相关 system prompt，再拼接一个用户轮次起始标记，不提供真实用户输入，让模型“补出”一个符合该领域的高质量任务请求。之后做 feasibility check，筛掉复杂度不合适、描述不清或资源不可得的任务。这个设计的优点是摆脱外部语料依赖，同时保留 aligned model 在任务表述上的自然性。

但自然语言任务描述还不能直接变成可交互环境，因此作者又设计了一个五阶段顺序合成流程，把任务逐步落地成真正可执行的 terminal world。虽然给出的全文片段没有完整展开五阶段细节，但从引言和方法描述可知，流程至少包括：生成具体文件布局和背景工件、实例化底层环境、定义预期输出与成功条件、并构造细粒度 test cases 作为 scoring oracle。换句话说，它合成的不是单条问答，而是一个带状态、带资源、带验证器的任务实例。

在此基础上，作者构建两类资源。LiteCoder-Terminal-SFT 包含 11,255 条专家轨迹，教师模型包括 MiniMax 系列，用于微调 Qwen 家族 4B、14B、32B 基座模型。LiteCoder-Terminal-RL 则包含 602 个可执行、可验证环境，用于 verifier-grounded rollout 和 trajectory-level preference optimization。RL 部分采用 DMPO，在 4B SFT 模型上继续训练。

从方法性质看，这篇文章的主要创新不在 RL 算法，而在“从零生成环境 + 轨迹 + 验证器”的数据工厂。它试图把 agent 训练从被动收集互联网任务，转成按能力缺口主动合成任务。19:T92d,The core method is LiteCoder-Terminal-Gen. Instead of scraping and filtering external task repositories, it starts from domain specifications and automatically generates task descriptions, instantiates environments, builds test cases, and finally produces either expert trajectories or executable RL environments. The paper covers 10 terminal domains, including AI&ML, build tools, data science, networking, security, system administration, version control, coding, scientific computing, and games.

Task generation uses a Magpie-like strategy with aligned LLMs. Given a domain-specific system prompt, the pipeline appends a user-turn start token without providing an actual user query, prompting the model to autoregressively complete a plausible task request in that domain. A feasibility filter then removes tasks that are too vague, too hard, or unsupported by available resources. The advantage is that task generation is no longer constrained by external corpora while still benefiting from the natural task phrasing learned by aligned models.

Natural-language task descriptions are not enough for interactive training, so the pipeline includes a multi-stage synthesis process that turns them into executable terminal worlds. The full five-stage details are not fully visible in the provided text, but the method clearly includes generating concrete file layouts and artifacts, instantiating the underlying environment, defining expected outputs and success conditions, and constructing robust test cases as scoring oracles. In other words, the system synthesizes not just prompts, but stateful task instances with resources and verifiers.

On top of this pipeline, the authors build two resources. LiteCoder-Terminal-SFT contains 11,255 expert trajectories generated by strong teacher models including MiniMax models, and is used to fine-tune Qwen-family base models from 4B to 32B. LiteCoder-Terminal-RL contains 602 executable and verifiable environments for verifier-grounded rollouts and trajectory-level preference optimization. The RL stage uses DMPO on top of the 4B SFT model.

Methodologically, the main novelty is not the RL algorithm. It is the data factory: generating environments, trajectories, and verifiers from scratch so that agent training can move from passive internet harvesting to active capability-targeted synthesis.1a:T653,The experiments aim to validate three claims: synthesized data can train stronger terminal agents, the gains are stable across model scales, and synthesized executable environments can support additional RL-style improvement.

For SFT, the authors fine-tune Qwen-family models from 4B to 32B on LiteCoder-Terminal-SFT. The best 32B model reaches 29.06%, 18.54%, and 34.00% pass@1 on Terminal Bench 1.0, Terminal Bench 2.0, and Terminal Bench Pro, respectively. The paper also states that smaller models consistently improve over their corresponding base models, suggesting the synthesized data is not only useful in the large-model regime.

For RL, the authors use 602 LiteCoder-Terminal-RL environments for verifier-grounded rollouts and apply DMPO to the 4B SFT model. This yields further gains on the harder Terminal Bench 2.0 and Terminal Bench Pro benchmarks, indicating that executable environments with automatic verifiers provide useful training signal beyond supervised trajectories.
