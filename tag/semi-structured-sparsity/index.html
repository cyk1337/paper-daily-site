Is 2:4 Sparsity Still Worth It? Semi-Structured Sparsity versus Quantization in LLM Inference

这篇文章回答的是一个很具体、但在 LLM 推理压缩里一直没有被讲透的问题：在 NVIDIA 支持 2:4 半结构化稀疏的前提下，从某个已有精度出发，下一步到底应该加 2:4 sparsity，还是直接降到更低 bit 的稠密量化？作者认为过去很多比较都不公平，因为没有把稀疏元数据算进存储成本，也没有把在线 pruning/quantization 的运行时开销算进去，更没有按硬件真实允许的稀疏轴来比较。全文的核心结论很明确：只要硬件上还有更低的 dense precision 可用，继续降精度通常比加 2:4 更划算，既更准，也更快；2:4 真正有价值的场景主要出现在已经到达 quantization floor 之后。

评把“稀疏 vs 降比特”用等 bits（含 metadata）+跨代 kernel 实测讲清了；部署决策直接照结论改，重点看误差随 bits 的对比图表。
Xiuyi Qin

Reservoir of Importance: Learning Semi-Structured Sparsity with Differentiable Subset Sampling

半结构化 N:M 稀疏化（如 2:4 或 4:8）能有效加速 LLM 推理，但现有的可学习掩码方法（如 MaskLLM）需要对所有可能的 N:M 组合建立分类分布，导致参数量和显存开销随 M 的增大呈组合级爆炸，难以扩展到大模型和高稀疏度场景。

评N:M 稀疏化的优化方法，通过可微采样降低了 mask 学习的参数量，关注模型压缩和推理加速的研究员可以快速浏览其参数化技巧。

SpenseGPT: Practical One-shot Pruning Enabling Sparse and Dense GEMMs for LLM Inference

这篇工作解决的是一个很实际的推理部署问题：硬件已经支持 2:4 半结构化稀疏，但严格 50% 稀疏约束对 LLM 后训练剪枝太苛刻，常常明显伤害精度；而更宽松的稀疏格式又往往需要专用编译器或引入运行时开销，最后拿不到真实端到端加速。作者想找的是一个中间点：既放松 2:4 的约束，保住模型质量，又能直接复用现有 sparse/dense GEMM 库，在真实解码场景里拿到可见收益。

评读格式设计和dense-region选择策略即可；它不改变训练方法，但对稀疏推理的真实可部署性有参考价值。
Jaeseong Lee,Seung-won Hwang,Samyam Rajbhandari
