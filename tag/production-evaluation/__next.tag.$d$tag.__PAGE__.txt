Instead of building a separate harness, the authors implement a minimal but production-grade inference framework with continuous batching, chunked prefills, multimodal inputs, and an OpenAI-compatible serving API. The point is that generated kernels run directly inside a realistic inference pipeline rather than being optimized in isolation and ported later. A second key design choice is top-down task construction. FastKernels starts from 46 real model architectures and recursively decomposes their inference paths into executable kernel tasks. Each task is extracted from actual HuggingFace model definitions, with configuration constants such as hidden size, head count, and dtype inlined from the real model. Tasks are then audited for semantic correctness, shape and dtype fidelity, and interface compatibility with production reference libraries. The paper explicitly states that none of the kernels are synthetic. Third, the benchmark is compositional. Tasks are organized into four levels: primitive operators, fused operators, full layers or blocks, and full models. Unlike benchmarks with independent levels, lower-level optimized kernels can be reused when optimizing higher-level modules, which makes the search process closer to real engineering and more suitable for agentic optimization. Fourth, evaluation is production-faithful. It includes captured tensors from real model executions, compilation-stack effects, and multi-GPU communication patterns such as tensor parallelism and expert parallelism. The MoE routing case study is especially important: synthetic inputs materially change load skew and hot-expert identity, which means they can distort what the benchmark considers important. Fifth, FastKernels validates generated kernels end-to-end by injecting them into full model execution and checking downstream quality.
