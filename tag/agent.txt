- Benchmarks: TheAgentCompany (software-company roles, cross-application workflows, coworkers) and APEX-Agents (investment banking, consulting, corporate law; document-heavy analysis/editing).
- Models: Opus-4.8 and GPT-5.5.
- Five interfaces:

  3) Bash (shell only)
  4) Bash+Synthesis (shell + persistent workspace; prompts encourage agent-synthesized reusable tools)

- Measurements: task score/pass rate, total tokens and estimated cost, tool-call counts/tokens, call success rate, repetition, plus domain breakdowns and failure analysis.19:T852,The method, State-Path Tool Menu, has three components: an encoder, a retriever, and a reranker. Each tool has documentation, required inputs, and produced outputs. A request exposes an initial state s0(q), containing the fields and constraints visible before any tool call. The system must construct an ordered menu of K=32 tools, and the online agent can only use tools from that menu during execution.

The central idea is the state path, a latent pre-execution route from the observable initial state to the desired outcome. Tools on this route are assigned one of four roles: entry tools can run immediately from the initial state, bridge tools create intermediate fields needed later, the target tool resolves the main request, and an optional terminal tool commits or delivers the result. This role decomposition is useful because it separates different notions that relevance-based retrieval conflates: immediate executability, intermediate utility, and final-task alignment.

The encoder learns relation-aware tool representations from the request state, tool schemas, and successful training trajectories. The excerpt explicitly mentions three directional signals: whether a tool can run now, whether it produces fields needed later, and how it depends on other tools in precedence order. So the representation is not just semantic similarity over tool descriptions; it is structured around state compatibility and dependency. The retriever then selects 32 tools that cover complementary path roles rather than simply maximizing top-k relevance. The reranker orders the selected tools so that producers appear before consumers, making the menu easier to execute under the same online loop and call budget.

Training supervision comes from successful trajectories. The retriever is trained with route membership, entry, and path-role targets, while the reranker is trained with slot and pairwise precedence targets. A notable design choice is that the paper keeps the online agent unchanged. The gains are meant to come from better pre-execution menu construction, not from modifying the planner or increasing the budget.1a:T4b9,From the available text, the experiments compare State-Path menus against relevance-based menus under a fixed agent and a fixed 32-tool budget. The reported evaluation dimensions include end-task success, complete-chain coverage, and executable entry. The paper also claims comparisons across tool libraries, evaluators, and executor families, plus paired outcomes and controlled variants to isolate whether the gains come from route coverage and ordering.

The provided excerpt does not include the result tables, exact gains, dataset sizes, or training details, so it would be inappropriate to fabricate numbers. Even so, the experimental design is already informative. The control variables are tight: the online execution loop and call budget remain unchanged. The metrics are also more diagnostic than standard success rate alone, because they measure whether the menu contains a complete chain and whether executable tools appear early enough to be useful. When reading the full paper, the most important checks are whether the gains are larger on long dependency chains, whether the method is more robust in larger tool libraries, and whether reranking adds substantial value beyond retrieval coverage.1b:T416,This is a skim paper. Start with the introduction, especially the receipt and email example, because it makes the failure mode concrete: the final tool is easy to retrieve, but the bridge tools determine whether the route is executable. Then read the first half of the methodology section to understand the state-path abstraction, the four tool roles, and why menu order matters before execution begins. A focused read should take about 20 to 30 minutes. If you work on agents, the appendices on visible information at each stage, trajectory supervision, and case studies are worth extra time because they determine how realistic the setup is for real API ecosystems. If your focus is LLM pretraining, it is enough to understand the interface lesson: action-space pruning works better when it encodes executable structure rather than lexical relevance alone.1c:T465,ContextPilot expands the context-management action space and changes the RL procedure. On the tool side, it adds planning, long-term memory, and soft context offloading beyond search, deletion, and summarization. Planning gives the agent a global structure before later actions. Long-term memory stores scattered evidence in a reusable form. Soft offloading acts as adaptive compression or temporary externalization rather than hard deletion. On the training side, the paper introduces context-aware partial rollout. It identifies influential context-management actions using changes in context and policy entropy, then branches rollouts around these critical actions instead of exploring every action uniformly. For credit assignment, it estimates the advantage of an intermediate context-management action using rewards from subsequent branches. This gives a finer signal than assigning the final trajectory reward to every step. The training also uses trajectory snapshots and token-level loss masking so that edited contexts are represented without repeatedly optimizing tokens that already appeared in earlier snapshots.1d:T792,GRAIN has three main components. First, it uses an explicit pipeline. Rather than letting the model mix extraction, graph construction, and computation inside unconstrained chain-of-thought, the task is decomposed into semantic parsing of the graph and task arguments, followed by tool execution with the appropriate graph algorithm. The motivation is straightforward: shortest path, matching, coloring, and related computations are deterministic; the real weakness of LLMs is the language-to-structure mapping.

Second, the method enforces structural invariance during training. The authors construct multiple isomorphic views of the same underlying graph: node identifiers may be random, semantic, aliased, or noisy, and the task description may range from standardized templates to more realistic narratives. The model is trained to recover the same intermediate graph despite these surface changes. This is more than ordinary augmentation, because the reward directly checks whether the predicted intermediate graph matches the ground-truth topology. That gives denser and more targeted feedback than final-answer supervision alone.

Third, GRAIN uses single-agent RL as a form of robustness distillation. The goal is not to build a multi-agent system, but to absorb into one model the robustness that would otherwise require repeated decomposition and verification across multiple agents. The RL objective jointly rewards correct structure recovery and correct tool invocation. The intended effect is to learn identifier-invariant and formulation-invariant parsing rules instead of memorizing templates.

The accompanying benchmark, GRIT, is also a substantial part of the contribution. It covers six graph problems across 31 real-world prototypes, with controlled multi-view variants for naming and narrative style. That makes it possible to separate failures of structure extraction from failures of downstream algorithmic solving.1e:T6da,The experiments are built around robustness diagnosis rather than a single leaderboard number. The first result is that the robustness gap is real: under identifier shift and task-form shift, performance varies significantly even when the underlying graph is unchanged. Closed models tend to retain stronger average accuracy but still show unstable variance across naming schemes. Open models degrade much more sharply under non-canonical identifiers and realistic narratives. This is an important finding because it shows that strong performance on sanitized graph benchmarks does not imply reliable real-world graph reasoning.

Against baselines, GRAIN is reported to outperform standard CoT, SFT, and more expensive multi-agent approaches in out-of-distribution robustness while keeping latency and token cost lower. The most informative results are likely the breakdowns by naming scheme, narrative type, graph size, and task complexity. If the gains are consistent across those slices, that supports the claim that the reward is improving the language-to-structure stage rather than exploiting a narrow template.
