Recovering Policy-Induced Errors: Benchmarking and Trajectory Synthesis for Robust GUI Agents

这篇论文聚焦 GUI agent 的一个很实际但常被弱化的问题：模型犯错之后，能不能识别自己已经进入错误状态，并通过后续操作把任务拉回来。作者把这类问题定义为 policy-induced errors，也就是错误不是外部噪声注入造成的，而是 agent 自己在执行中因为错误 grounding、误判界面状态、选错子目标等动作一步步走出来的。现有 benchmark 更关注 grounding、规划或最终成功率，训练数据也多是人类演示或短程反思样本，因此对真实部署里常见的“长程、自诱发、组合式错误”覆盖不足。

评GUI Agent错误恢复的专门基准与数据合成方法，树状探索合成错误轨迹的思路可迁移到其他Agent训练数据生成，看§3数据合成部分即可。

Hydra: Efficient, Correct Code Generation via Checkpoint-and-Rollback Support

这篇工作处理的是代码生成里的一个很具体但长期被低估的问题：如何在不显著增加延迟和 token 开销的前提下，把 LLM 生成的代码尽量维持在“静态可通过”的状态，也就是至少能通过编译器的语法和语义检查。现有两类办法都有明显缺陷。post-hoc repair 要等整段代码生成完再检查，错误发现太晚，往往要重生成大量其实已经正确的前缀；incremental constrained decoding 虽然更早检查，但通常按 token 级同步执行，checker 成了生成链路上的串行瓶颈，而且修复范围过于局部，只能改当前 token，常常碰不到真正的根因。全文最重要的观察是：很多静态错误的报错位置并不是根因位置，真正导致错误的 token 往往出现在更早的前缀里，因此“只修当前点”经常无效，而“整段重来”又太浪费。Hydra试图解决的就是这个检查粒度、错误定位滞后、修复范围选择三者之间的系统性矛盾。

评方法有新意——异步编译检查+检查点回滚比现有逐token约束解码或事后修复更高效。值得看方法和实验部分了解实际开销对比。
Alexander Du,Jianjun Ou,Danyang Zhuo,Matthew Lentz
