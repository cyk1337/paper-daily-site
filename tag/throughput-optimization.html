D-cut: Adaptive Verification Depth Pruning for Batched Speculative Decoding

这篇工作处理的是 batched speculative decoding 在高并发下会失效的问题。长 draft 在低并发时通常有利，因为一次 verify 可以吞下更多候选 token；但并发升高后，verify 端从 memory-bound 逐渐转成 compute-bound，系统开始为大量最终会被拒绝的 draft token 付出真实算力。论文抓住的关键矛盾不是“draft 不够长”，而是“长 draft 的利用率在 batch 内高度不均匀，却仍被强制按统一深度验证”。结果是：某些请求只值得验证前几步，另一些请求却可以安全吃到更深位置，但现有方法把它们一视同仁，导致验证预算被低价值 token 吞掉，甚至让 speculative decoding 在大 batch 下落到低于 AR baseline。

评这是 serving 侧很实在的一刀：别再盯单请求 MAT，直接看高并发下验证预算怎么分；读方法和吞吐曲线就够了。

Requests of a Feather Must Flock Together: Batch Size vs. Prefix Homogeneity in LLM Inference

这篇工作解决的是 LLM 推理服务里的一个具体但很常见的误区：decode 阶段调度是否只要尽量把 batch 做大就好。作者指出，在存在大量 prefix sharing 的真实工作负载里，batch size 不是唯一主导因素，prefix homogeneity——同一 batch 内请求共享公共前缀的程度——往往更重要。原因是 decode 是典型 memory-bound 过程，性能瓶颈在 KV cache 的 DRAM 访问；如果一个 batch 内请求共享长前缀，就能在 KV 读取上获得更好的时空局部性，减少 DRAM 流量并提高带宽利用。因此，较小但前缀更一致的 batch，可能比更大的异构 batch 吞吐更高。现有 prefix-aware scheduler 主要把前缀共享当成“节省 KV 内存”的手段，没有把它当成 decode 吞吐优化目标，也没有处理 prefix-aware 调度本身的 CPU 开销问题。

评挑战了推理引擎中“Batch Size 越大越好”的 prior，指出在共享前缀场景下，同质小 Batch 因为 KV Cache 局部性更好反而吞吐更高，做 Serving 和 vLLM 优化的同学必看。
Saksham Rathi,Preeti,Mythili Vutukuru
