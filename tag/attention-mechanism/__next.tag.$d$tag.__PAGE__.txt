There are four important design choices.

First, the routing unit is the token. The paper explicitly uses attention span as a proxy for attention budget: if a token likely depends on long-range retrieval, it should be allowed to access the full sequence; if it is locally predictable, local context is enough. This differs from static layer-wise or head-wise span assignment.

Second, routing is controlled by an adaptive threshold tied to a target global ratio. Instead of using a fixed threshold or unconstrained soft gating, LoGo selects roughly the top fraction of tokens for global attention. This keeps compute predictable and directly links routing decisions to budget. It also makes it easier to convert FLOP savings into real speedups, because the global branch becomes query-sparse in a hard, structured way.

Third, training uses progressive masking (P-mask). Hard sparse routing from the start would make optimization brittle because the gate is initially untrained and may suppress important tokens too early. LoGo therefore delays the full sparse regime and gradually introduces routing sparsity after the gate has learned more meaningful preferences. This is a training-stability device, and it is one of the more important parts of the method.

Fourth, LoGo sparsifies only global queries, not keys or values. All KV states remain globally available, so any selected token still performs exact full-context attention rather than an approximation over compressed memory. This is a conservative but sensible design: it reduces compute without damaging information accessibility.

Relative to prior work, static inter-layer hybrids assign some layers to global attention and others to local attention; intra-layer hybrids assign some heads to global and others to local. Both impose a fixed per-token budget. LoGo instead lets different tokens in the same layer take different span routes. Compared with dynamic module activation methods such as CoLT5 or SMA, LoGo directly routes based on span demand rather than swapping among attention modules with the same restricted context. 理论部分，作者先区分 mass coverage、output fidelity、task utility 三层目标。对 mass coverage，他们指出阈值计数 k(epsilon) 只是在问“有多少权重大于某阈值”，但压缩预算真正关心的是“要保留多少 token 才能覆盖 90% 之类的总概率质量”。决定后者的不是局部亮点，而是全局 score-gap profile，也就是排序后 logit 的衰减几何。论文给出一组 all-rank gap 条件：如果 gap envelope 在 log-rank 意义下斜率大于 1，tail 可求和，固定质量覆盖所需 budget 可以与长度无关；如果斜率低于 1，budget 会随长度增长。作者还用 Gaussian logits 说明一个反直觉点：即便看起来有“校准后的少量大权重”，要覆盖 90% mass 仍可能需要接近 0.61n 的 token，压缩空间并不大。

对 output fidelity，作者指出遗漏 mass 本身不是误差证书，关键在于被丢弃 value 的加权和是否能被恢复或近似。对一个固定 attention row，遗漏部分的 weighted sum 是精确的缺失统计量。进一步，如果希望一个线性 sketch 同时恢复完整输出和任意保留子预算下的输出，那么除了保留的真实 token 外，再加一个 tail aggregate 就达到匹配的维度下界。这给后面的算法设计提供了结构性依据：不是只保留 top-k token，而是要显式存一个 tail summary slot。

对 task utility，作者构造了 retrieval–aggregation 的 planted-token 模型，说明 exact attention 并不总是最适合任务目标。对 retrieval-like 任务，renormalized top-k 有时会因为压掉 diffuse noisy bulk 而优于 exact attention；但对 aggregation 任务，保留完整 softmax 更合理。也就是说，“更接近原 attention”不自动等于“更接近任务最优”。

基于这些分析，作者提出 CertKV。它是 training-free 的 KV compressor。设计上每个 head 预留一个 tail-summary slot，其余预算从 observation window 中选真实 token；分配策略不只看 attention score，还看 value dispersion，也就是尾部 value 是否容易被一个聚合向量概括。被省略的尾部用加权 key-value summary 存起来，且 synthetic slot 与真实 token 占用同样的物理预算。这个设计和很多只做 token selection 的方法不同，核心差异在于它承认“尾部不是纯噪声”，而是用一个显式统计量去补偿。14:T995,The paper has two layers: a theoretical decomposition and a practical compressor.

On mass coverage, the authors argue that threshold counts are the wrong primitive. Counting weights above epsilon does not answer the cache-budget question, which is how many tokens are needed to retain, say, 90% of the softmax mass. That quantity is governed by the global score-gap profile after sorting logits, not by a few bright entries. They derive complementary all-rank gap conditions: if the log-rank gap envelope has slope above one, the tail is summable and a fixed-mass budget can remain length-independent; if the slope is below one, the required budget grows with sequence length. A Gaussian-logit example makes the point concrete: one can observe a seemingly sparse calibrated count while still needing roughly 61% of tokens to retain 90% of the mass.

On output fidelity, the paper shows that omitted mass alone is not an error certificate. What matters is the weighted sum of omitted values. For a fixed realized attention row, that omitted weighted value sum is the exact missing statistic. Under a stronger linear-sketch requirement—recovering both the full output and every retained sub-budget—the authors show that keeping the selected values plus one tail aggregate achieves the matching dimension bound. This is the structural motivation for the algorithmic design: a compressor should not only keep top tokens, but also maintain an explicit tail summary.

On task utility, the paper introduces a planted retrieval–aggregation model. It shows that exact attention is not always the right target. For retrieval-like tasks, renormalized top-k can outperform exact attention by suppressing diffuse noisy mass, while for aggregation tasks exact attention remains preferable. So preserving the original attention output is not automatically the same as preserving task performance.

These analyses motivate CertKV, a training-free KV compressor. CertKV reserves one tail-summary slot per head, selects real tokens from an observation window, and allocates more token budget to heads whose omitted values are harder to summarize, measured through value dispersion. The omitted tail is stored as a weighted key-value summary, and the synthetic slot counts against the same physical budget as real tokens. This differs from pure token-selection methods by explicitly modeling the tail as compressed state rather than treating it as disposable noise.15:T4d5,The evaluation covers all 503 LongBench-v2 examples, three backbones, three compression ratios, multi-length RULER, one-factor studies, and a packed-cache prototype. The headline result is that under the pre-specified four-baseline comparison grid, CertKV is top-two in 7 of 9 LongBench-v2 settings. At 128K context on RULER it stays in the leading tier, and on Llama with 64K context and 10x compression it achieves the intended physical cache reduction.
