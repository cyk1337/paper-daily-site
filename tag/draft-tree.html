DARTree: Speculative Diffusion Decoding with Autoregressive Draft Trees

基于 diffusion 的 block-parallel drafter 一次前向预测整块 token，提案延迟低，但缺少块内因果条件；causal correction head 能沿单条链补回因果信息，而 draft tree 能拓宽候选覆盖。把两者结合时，path-dependent 的校正分数迫使 tree 构造逐节点串行调用 correction head，成为新的延迟瓶颈。

评只看方法图和实验表即可；若内部已有 speculative decoding 栈，这个 tree 化 AR correction 值得小规模复现。

DominoTree: Conditional Tree-Structured Drafting with Domino for Speculative Decoding

Domino 已经用 GRU 对 block-diffusion drafter 的边际 logits 做路径相关修正，但公开实现只沿一条 draft path 生成 token。DDTree/CaDDTree 可以构造 draft tree，却假设每个位置的分布相互独立，不能表达 Domino 的非因子化条件分布。DominoTree 解决的是：如何在不重新训练 drafter 的情况下，把 Domino 的路径相关条件打分用于 speculative decoding 的树状草稿构造。

评看算法定义和 acceptance 曲线即可；结果强，但缺少端到端 serving 条件时别急着改线上栈。
Saw S. Lin,Jyh-Shing Roger Jang

TAPS: Target-Aware Prefix Tree Selection for Diffusion-Drafted Speculative Decoding

扩散式推测解码中，当草稿生成变得廉价后，瓶颈转移到了目标模型的验证阶段。现有树形验证方法按边际概率排序候选节点，忽略了验证是前缀条件的——被拒绝前缀下的子孙节点虽有高边际概率但无法到达，造成验证开销浪费且接受长度提升有限。

评只看 tree selection 部分；它抓住了验证前缀条件化这个细节，适合和内部 spec-decoding 实现对照。

Draft Less, Retrieve More: Hybrid Tree Construction for Speculative Decoding

这篇文章解决的是 speculative decoding 里一个很具体但很实际的矛盾：树状 draft 越大，target 一次验证能接受的 token 越多，但 draft 侧搜索、显存带宽和验证开销也越大，最终 wall-clock speedup 不一定更好；而动态剪枝虽然更快，却会把原本可能正确的分支一起剪掉，导致 mean accepted tokens 被静态大树的上界卡住。作者要解决的核心问题，是如何在不增加 target 额外前向、保持 lossless 的前提下，把“剪枝省下来的预算”重新利用起来，弥补动态树的覆盖损失。

评做推理加速的研究者重点看剪枝+检索互补的设计思路，基座研究员可了解该方向的权衡突破
