18:T631,The key contribution is Event Tensor: treat synchronization events as first-class tensor objects in the compiler IR. An event represents completion of a set of tiled tasks at (roughly) the SM granularity; organizing many such events into a multi-dimensional tensor yields a compact, structured representation of fine-grained dependencies inside a megakernel.

Why this matters:
1) Structured dependency encoding: instead of scattering semaphores/flags in hand-written code, dependencies become tensor-shaped objects the compiler can analyze and transform.
2) Dynamic-shape support via symbolic dimensions: because Event Tensors look like tensors, they can reuse existing compiler machinery for symbolic shapes, avoiding recompilation/capture for every possible runtime shape.
3) Data-dependent dynamism via index expressions: dependencies that depend on runtime data are expressed as mappings from task coordinates to event coordinates, enabling runtime-resolved dependency tracking while keeping the abstraction uniform.

On top of this IR, the Event Tensor Compiler (ETC) applies scheduling transformations to generate persistent megakernels. It supports a spectrum from fully static scheduling (pre-assign per-SM task queues) to dynamic scheduling (an on-GPU scheduler dispatches ready tasks), and can mix strategies to trade off synchronization overhead vs adaptability/load balance. The novelty is less about inventing semaphores and more about tensorizing synchronization in IR so that previously bespoke megakernel fusion/scheduling techniques become systematic compiler
