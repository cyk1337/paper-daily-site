The second component is a path-tolerant milestone graph. Instead of relying on hidden reference trajectories, the system operates strictly on the public task view to avoid leakage. Each harness stream is a sequence of cumulative stages H1 ⊆ H2 ⊆ ... ⊆ HT, so later stages only add capabilities and never remove old ones. Streams are built along three axes: tools, skills, and agents.

Two design choices matter. First, each task is assigned to the earliest stage at which it becomes solvable, and it must require at least one newly introduced capability. This helps separate adaptation to new capabilities from retention of old ones. Second, capabilities are released from common core capabilities toward the long tail, which is meant to mimic real harness growth in deployed systems.

The benchmark supports two evaluation modes. In deployment evaluation, no experience is carried across stages; each harness version is evaluated independently. This isolates the direct effect of harness expansion: does a larger capability pool help, or does it mostly distract? In self-evolving adaptation evaluation, persistent artifacts such as memory, prompts, or learned skills can be updated within each stage and then carried forward, while the underlying model weights remain fixed. This tests whether accumulated experience helps or hinders adaptation under a growing harness.

The benchmark is reasonably large: 17 controlled harness streams, each with 3 to 6 cumulative stages, 802 unique tasks, 1,510 axis-specific evaluation examples, 520 executable tools, 42 latent reference skills, and 62 specialist agents. Gains vary substantially across stages, axes, and environments, which suggests that simply accumulating memory or prompts is not a reliable answer to harness evolution. Third, retention and adaptation often pull in opposite directions: methods that preserve earlier competence better can be worse at exploiting newly introduced capabilities, while methods that adapt aggressively can sacrifice old-task performance.
