18:T556,PeekKV introduces a one-token peek on the decode path. After prefill, the system briefly continues generation before compressing the cache. It skips format tokens and inspects attention-related signals only at the first content token. The paper argues that this single observation is enough because head activity is relatively stable across subsequent content tokens.

From that one decode step, PeekKV derives two signals. The first is a head-group score, used to allocate KV budgets across groups of heads in proportion to their estimated importance. The second is an output-perturbation score, denoted as Δo, which measures how much retaining or removing a token affects the output of a given head group. This score is then used to decide which historical tokens each group should keep.

This two-level design is the key distinction. Unlike HeadKV, DuoAttention, or RazorAttention, PeekKV does not assume a fixed set of retrieval-style heads should always receive large budgets. Unlike AdaKV, it does not infer decode requirements from prefill attention. It reads the signal directly from the decode path, which is the central methodological claim. The runtime allocation also adapts across workloads: retrieval-heavy tasks naturally route budget to induction/retrieval-like heads, while code generation or tool-use workloads can shift budget toward other heads.19:T59f,The evaluation spans four public benchmarks covering long-context retrieval, text generation, and code generation. The headline model in the paper is Llama-3.1-8B-Instruct. Two reported numbers stand out: on RULER, PeekKV preserves 95.7% of full-cache accuracy at a 10% memory budget; on LongBench, it preserves 95.9% at only a 1.5% budget. The paper also reports that AdaKV, which uses prefill-time adaptive allocation, underperforms the static alternative on 10 out of 12 workload categories in their measurements, supporting the claim that prefill-based signals are misaligned.

The more informative part of the experiments is the diagnosis. First, head activity varies most strongly around the prefill/decode transition and on format tokens; after filtering those, content-token decoding is much more stable. Second, the identity of important heads is workload-dependent: retrieval heads dominate recall-heavy tasks, but non-retrieval heads can dominate tool-calling or code-generation outputs. Third, ablations indicate that head-budget allocation alone or token retention alone is weaker than combining both. Fourth, the overhead analysis shows that the one-token peek mainly delays compression by a few decode steps, so peak memory briefly remains at full-cache level, but the extra runtime cost is limited. Readers should verify the latency and memory curves in the full text rather than relying only on accuracy-retention metrics.1a:T6bb,CatchUp is a training-free framework for depth-aware visual-token re-admission. Instead of making a one-shot keep/drop decision, it re-evaluates query-conditioned visual relevance at selected decoder layers. At each routing layer, the model uses attention from the last text token to visual tokens as a relevance proxy, keeps only the selected visual tokens active, and defers the rest rather than deleting them. Between routing layers, only active visual tokens continue through the decoder, reducing attention, FFN, and KV-cache cost.

The key contribution is what happens when a deferred token becomes relevant again. Prior recoverable routing methods simply reinsert the old hidden state, which is stale. The authors first run an oracle analysis with full-token trajectories and show that replacing stale states with same-depth oracle states substantially improves grounding. This establishes that representation staleness is the real bottleneck. CatchUp then approximates the missed evolution using reference-to-current transition signals from semantically and spatially related active visual tokens. Intuitively, it borrows how nearby tokens changed from the reference depth to the current depth, and transfers that change to the returning token. So it does not replay all skipped layers; it estimates the missing state update from related tokens.

Compared with irreversible pruning, CatchUp can recover late-emerging evidence. Compared with recoverable routing without state correction, it explicitly addresses hidden-state mismatch at re-entry. The oracle replacement study is important because it validates the design target: the problem is not re-admission itself, but stale representations at the current depth.1b:T614,The main experiments are built on LLaVA-1.5-7B, with referring-expression grounding and general multimodal benchmarks. The motivating analysis is one of the strongest parts of the paper. On 500 RefCOCO samples with 576 visual tokens and top-64 relevance sets, the average adjacent-layer volatility of the top-K visual token set is 28.85%, showing that query-relevant evidence changes substantially across depth. Using layer 2 as the early-selection reference, the late-emerging evidence ratio exceeds 50% by layer 7 and reaches 99.42% at layer 31. In other words, most tokens that matter later would be missed by an early irreversible selection.

On the main benchmarks, CatchUp achieves the best grounding retention among the compared efficient methods under matched routing budgets. Under matched prefill computation, it uses the fewest visual tokens and the smallest decoder KV-cache, while reducing end-to-end latency by 8.0% relative to dense inference. The paper emphasizes that the gain is not from more aggressive pruning alone, but from preserving accuracy better at the same budget.

The most informative ablation is oracle state replacement: if re-admitted tokens are given their full-token same-depth states, grounding performance improves markedly, confirming that stale states are the dominant issue in recoverable routing. Additional ablations indicate that semantic and spatial transition signals are complementary, and that routing frequency matters: too few routing points miss late evidence, while too many reduce the efficiency benefit.1c:T72b,RoLaQ combines rotation learning and range calibration. The starting point is an error analysis: if the dequantized latent differs from the original by e, then the induced key and value projection errors are governed by quadratic forms involving W_K and W_V. The authors trace-normalize the two projection energies and sum them into a joint matrix H, which measures how sensitive each latent direction is to shared K/V distortion. Empirically, the leading half of H's eigenvectors captures 62% to 75% of the projection energy across models and layers, so RoLaQ restricts rotation learning to a compact subspace defined by this joint geometry rather than searching over the full latent space.

The second ingredient is coupled threshold-gain learning. RoLaQ does not keep the quantizer range fixed while only optimizing the rotation. Instead, it jointly learns a per-layer threshold whose value also determines the reconstruction gain. This matters because at 2 bits, the rotation changes the latent distribution seen by the quantizer, while the quantization boundaries and dequantization scale jointly determine the effective reconstruction response. Optimizing only one side leaves a mismatch between assignment and readout behavior.

Training uses frozen model weights. Supervision comes from two sources: a prediction-level KL to a BF16 teacher over next-token distributions, and an attention-output reconstruction loss that directly constrains layerwise attention outputs.
