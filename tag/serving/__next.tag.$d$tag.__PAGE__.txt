V2 的第一个关键改动是 mean correction term。原方法在极端稀疏时直接截断未选 block 的 softmax 分母和分子，忽略掉被剪枝块的质量，误差会迅速放大。V2 为每个 key block 预先计算 pooled K/V 统计量，用零阶近似去补偿被丢弃块对 softmax mass 和 value aggregation 的贡献。直观上，它不再把未选 block 当成完全不存在，而是用块均值代表其剩余贡献。这样做的好处是代价低，不需要恢复 token-level 计算，但能显著缓和高 sparsity 下的偏差。

第二个关键改动是 kernel 重写，目标是对齐 Hopper 时代的高性能 dense attention 实现。文中提到三点：PackGQA memory access、warp specialization、pingpong pipelining。前者针对 grouped-query attention 的访存组织，减少无效带宽和访存碎片；warp specialization 把不同 warp 分配给不同职责，提高流水并行；pingpong pipeline 则利用 Hopper 上的异步搬运和计算重叠机制，把数据准备和计算交替推进。作者明确说 V2 是按 FlashAttention-3/4 的实现思路重构，而不是停留在 FA2 时代的 kernel 结构上。

The first major addition in V2 is a mean correction term. In the original truncation-based approximation, unselected blocks are simply dropped from both the softmax denominator and numerator. V2 compensates for pruned blocks using precomputed pooled K/V statistics for each block, effectively adding back a zero-order surrogate contribution. Intuitively, the method no longer treats pruned blocks as nonexistent; it represents their residual effect through block means. This keeps the correction cheap while significantly reducing approximation error at high sparsity.

The second major change is a Hopper-oriented kernel redesign. The paper highlights PackGQA memory access, warp specialization, and pingpong pipelining. PackGQA improves memory organization for grouped-query attention and reduces bandwidth waste. Warp specialization assigns different roles to different warps to improve overlap and utilization. Pingpong pipelining exploits Hopper-style asynchronous data movement and compute overlap. A block-parallel draft model produces a length-K candidate block and its logits in one pass. In standard single-path speculative decoding, only that path is verified. If token k is rejected by the target model, all later tokens are discarded even when many of them would have matched the target had the earlier local error been repaired. CURE tries to fix exactly those fragile points.

The mechanism starts by identifying Uncertainty Focal Points using the top-1 versus top-2 log-probability margin from the draft model. A small margin indicates local ambiguity and a higher chance that this position will trigger downstream rejection. Under a fixed verifier budget, the method spawns alternative branches only at these focal points instead of expanding a dense candidate tree over the whole block. The motivation is simple: if most tokens are already predictable, uniform tree expansion wastes target verification on positions that do not need repair.

The paper formulates this as a budget-constrained candidate-tree optimization problem. The objective is to maximize accepted length under a verification budget V_max. The effective generation rate is written as expected accepted tokens divided by draft cost plus verifier cost. This formalization is useful because it makes the central trade-off explicit: local branching helps only when the gain in accepted context outweighs the extra cost of target-side tree verification.

A practically important component is cache resynchronization. Because repair branches may alter the finally accepted path, the draft model’s internal state must be realigned with the target-verified prefix. The authors design a cache-consistent resynchronization procedure that does not require retraining the draft model. That makes CURE a plug-and-play add-on for existing block-parallel backends, which is more valuable in practice than a method that depends on a specially trained draft architecture.14:T623,The evaluation covers code generation as the main domain and reasoning as an out-of-domain check. Instead, it extracts moderate acceptance improvements from localized repairs. Because speculative decoding is often bottlenecked by memory-bound sequential target passes, even moderate acceptance gains can translate into noticeable wall-clock speedups. The paper also emphasizes an acceptance-versus-compute Pareto frontier: adding more repair branches usually increases accepted length, but target verification eventually saturates, after which extra branching no longer improves latency.

Under that view, existing lossy methods collapse into two families.

The first is truncation-based verification. Methods such as typical acceptance in Medusa and SpecCascade accept a draft token if it lies in an allowed set defined by a truncation rule on the target distribution, such as eta-sampling or min-p sampling. The key point is that these methods are not approximating the original target distribution; they are approximating a truncated target sampling process. This leads to the paper’s main evaluation correction: the right baseline is the target model decoded with the same truncation rule, not the original target model under standard sampling.

The second is collaborative verification. The paper unifies lenience-based relaxation and CoS by showing that both interpolate between the draft distribution q and the target distribution p, differing mainly in whether the interpolation coefficient is fixed or adaptive. The more interesting claim is that good speed-quality trade-offs do not require sophisticated global interpolation. What matters most is suppressing overshoot tokens, where q(x) exceeds p(x) too aggressively. These tokens are argued to drive most low-quality generations, while the rest of the distribution matters much less.
