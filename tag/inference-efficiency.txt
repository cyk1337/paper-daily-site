18:T703,The method starts by separating queries into two behavioral types. Local queries mostly attend to nearby tokens. Global queries, associated with TRTs, attend back to distant earlier context. The paper then shows that these global queries are not scattered arbitrarily in query-embedding space; they form a small number of similarity clusters. This motivates beacon queries: a compact set of representative queries intended to approximate future global revisiting patterns.

At eviction time, BeaconKV does not score historical KV entries using only recent queries. It also keeps a small set of beacon queries. A token is retained not only if it matters to the current local decoding state, but also if it is important to one of these representative global queries. This gives the system a way to protect tokens that may not look useful now, but are likely to be revisited later.

Because decoding is online, beacon queries cannot be obtained by offline clustering over the full query history. The paper therefore proposes Continual Farthest Point Sampling, an online procedure that incrementally selects geometrically diverse queries while keeping memory bounded. Intuitively, it maintains a compact cover of the query space seen so far. Compared with storing the full query history, this is memory efficient; compared with using only recent queries, it preserves information about potential future global attention patterns.

Methodologically, BeaconKV is training-free. It does not modify model weights and does not require distillation or calibration. Its main distinction from RPC and R-KV is not a better redundancy score, but an explicit treatment of future-query mismatch: future important queries may differ from recent ones, and a small representative set can partially bridge that gap.19:T537,The evaluation covers four open reasoning models: R1-Distill-Qwen-7B, R1-Distill-Llama-8B, Qwen3-4B, and Qwen3-14B. Benchmarks include AIME24, MATH-500, LiveCodeBench, and GPQA-Diamond, spanning math, coding, and science reasoning.

Several headline results matter. First, across a range of cache budgets, BeaconKV generally outperforms RPC and R-KV, with accuracy gains of up to 31.7 percentage points. That large gap suggests that under aggressive compression, the dominant issue is wrong eviction rather than raw capacity alone. Second, under strong compression, peak GPU memory can be reduced by up to 5.8x while keeping accuracy close to full-KV inference. Third, throughput improves by more than 4.3x over the uncompressed baseline, so the benefit is not only fitting longer traces but also improving practical serving efficiency.

The most informative ablations are the mechanism checks: TRTs indeed exhibit long-range attention; global queries show cluster structure in embedding space; recent-query-only scoring fails to cover these future revisiting needs; and adding beacon queries better preserves the tokens that full-KV inference would later rely on. If you want to go deeper, two follow-up questions are worth keeping in mind: why TRT queries form a small number of clusters, and whether this structure is amplified by reasoning SFT/RL or already present in the base model.1b:T70d,The method has three stages. The first is a chunk-summarization diagnostic task. The authors concatenate multiple documents from short-text summarization datasets into long contexts, keep the original document boundaries, and ask the model to identify semantic chunks and produce keywords for each chunk. This is intended to require hierarchical parsing and semantic compression rather than simple span retrieval.

The second stage is head scoring. For valid generations, the method traces attention from generated keyword tokens back to corresponding source tokens in the input. A head receives a high summarization score if output keywords consistently attend to salient source content within the correct chunk. This differs from retrieval-style head scoring because it rewards the ability to compress and reconnect to source meaning, not just local matching or high raw attention mass.

The third stage is budget allocation. A fixed budget is always reserved for sink tokens and a recent sliding window, reflecting the practical importance of system prompts and recent turns. The remaining compressible middle region is allocated across heads in proportion to normalized summarization scores. A water-filling-style reallocation step prevents a few very high-scoring heads from monopolizing the budget and redistributes excess capacity to other useful heads. Within each head, token retention still uses a standard cumulative-attention criterion similar to SnapKV. So SGD-KV is not replacing token selection; it adds a more informed head-level allocation layer on top. Compared with DuoAttention, it uses continuous rather than binary head prioritization. Compared with HeadKV or AdaKV, its head importance signal comes from a dedicated summarization probe rather than directly from downstream behavior.1c:T6af,The experiments use Qwen2.5-7B-Instruct-1M and Qwen3-32B. That means some care is needed when interpreting the results. The main benchmarks are MRCR, which stresses long multi-turn retrieval and reference tracking, and ETHIC, which emphasizes broad information coverage over long contexts.

Empirically, SGD-KV matches or outperforms prior head-aware compression methods on both models. On Qwen3-32B with chain-of-thought reasoning, both SGD-KV and HeadKV are clearly better than DuoAttention, suggesting that fine-grained budget allocation is more effective than binary head grouping for complex reasoning. On the fine-tuned Qwen2.5-7B-1M model, SGD-KV becomes increasingly favorable as context length grows, overtaking DuoAttention beyond 128K and showing the strongest robustness at the 1M-token scale. An inference-side state machine reads these tags online and constructs the attention mask dynamically. DA defines three modes. <global> allows access to the full context and is used when the model needs to survey or search broadly. <focus> commits the model to a specific region of the context, restricting attention to that region. <local> limits attention to recent generated tokens, avoiding long-context reads altogether.
