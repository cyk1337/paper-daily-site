18:Tc55,模型是 decoder-only causal Transformer，但关键在若干组合设计。

一是混合注意力。Kolibri 在 50 层中采用 4:1 的 SWA 与 full attention 交替：每 5 层里 1 层 full attention，其他 4 层用 512 token 窗口的 sliding-window attention。这样做的目的很明确：大部分层用局部注意力压低训练和解码成本，少量 full attention 层负责全局信息混合。更有意思的是位置编码并非统一处理。SWA 层使用 RoPE，full-attention 层则使用 NoPE；同时对 Q、K 做 per-head RMSNorm，且在 SWA 层中先 norm 再加 RoPE。这个组合反映出作者的判断：局部窗口层需要显式相对位置信号来稳定局部建模，而全局层若继续叠加 RoPE，可能在长上下文外推或注意力尺度上带来额外负担，NoPE 反而更干净。论文把这些不是当作独立 trick，而是作为 hybrid attention 的配套设计来选。

二是 MoE 稀疏结构。每层有 384 个 routed experts，每个 token 选 6 个 routed experts，再加 1 个 shared expert；router 用 sigmoid logits，但 top-k 后不再归一化。这一设计明显受 DeepSeek 系 MoE 影响，目标是让路由权重表达更灵活，同时通过 shared expert 提供稳定的通用通道。负载均衡使用 EQB 和 LEI，而不是传统单一 auxiliary loss。Kolibri Origin 则是另一套更简单、稀疏度更低的对照架构：8-of-128 routed experts，前两层 dense，全层 full attention。作者通过代理实验逐步走向更高总容量、更低 active ratio 的 Kolibri 主架构。

三是 tokenizer。词表大小 128k，采用 UniBPE。它仍是自底向上的 merge 过程，但每一步 merge 选择依据是 Unigram loss，而不是标准 BPE 的频次启发式。作者特别强调德语形态学边界：与 GPT-5 tokenizer 相比，Kolibri tokenizer 在德语上有 65.2% 的 token 边界落在 morpheme boundary，而对方是 47.3%；在德语网页文本上 token 数减少 11.2%。这不是小修小补，因为德语复合词和屈折变化多，tokenizer 若切分不合理，会直接影响 token budget、上下文利用率和训练信号密度。

四是训练流程。Kolibri 总训练量 24T tokens，包含 pre-training、mid-training 和 long-context extension；目标最大上下文训练到 256k。作者没有只做一次大规模训练，而是先在 M/L 两个代理尺度上做受控消融。M 规模是 7.8B total / 0.6B active，训练 97.6B tokens；L 规模是 30.6B total / 2.1B active，训练 327.6B tokens。模型形状 sweep 时，还会在最小代理尺度上调学习率，而不是完全相信 scaling-law 预测值，避免把 shape 优劣和 learning-rate 失配混在一起。这一点很专业，也很少在公开报告里讲得这么明确。

五是效率与部署导向。Kolibri 的设计目标不是单纯追求 benchmark 峰值，而是追求 Pareto frontier：在给定 active compute 下尽量提高质量，同时保持开放权重、可控数据链路和适合受监管场景的部署属性。因此很多选择都偏向“可解释、可复现、可部署”，而不是最激进的实验性结构。19:Ta18,最重要的数字先列出来：Kolibri 主模型 78.1B 总参数，3.46B active parameters per token，活跃比例 4.4%；50 层；48 个 query heads、4 个 KV heads、head dim 128；MoE 为 384 experts 中选 6 个 routed experts 加 1 个 shared expert；训练最大上下文 256k；总训练量 24T tokens，其中 pre-training 20T，long-context 阶段 200B。Kolibri Origin 为 30.6B total、3.27B active、64k context，是更早期的对照版本。

The first is hybrid attention. Across 50 layers, the model uses a 4:1 ratio of sliding-window attention (SWA) to full attention: one full-attention block every five layers, with the other four using a 512-token backward window. The rationale is clear: most layers use local attention to reduce training and decoding cost, while periodic full-attention layers provide global mixing. Positional encoding is also split by layer type. SWA blocks use RoPE, while full-attention blocks use NoPE. In addition, queries and keys are normalized per head with RMSNorm, and in SWA blocks this happens before applying RoPE. This suggests a deliberate view: local-window layers benefit from explicit relative position structure, while global layers may be cleaner and more stable without RoPE, especially for long-context behavior.

The second is the MoE design. Each MoE layer contains 384 routed experts; each token is sent to 6 routed experts plus 1 shared expert. Router scores are sigmoids of router logits and are not renormalized after top-k selection. This is clearly influenced by recent DeepSeek-style MoE choices. The shared expert provides a stable common pathway, while the sparse routed experts expand total capacity. Load balancing uses EQB and LEI rather than a single classic auxiliary loss. The earlier Kolibri Origin architecture serves as a contrast point: 8-of-128 routing, two leading dense layers, and full attention everywhere. The final Kolibri moves toward higher total capacity and lower active ratio at similar active compute.
