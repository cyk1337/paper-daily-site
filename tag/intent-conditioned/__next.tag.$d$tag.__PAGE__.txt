其二是 intent conditioning。每次压缩不是只看 segment 本身，而是同时输入当前任务 query，让模型优先保留 query 中点名的实体、文件、函数、报错线索。作者强调“什么重要”不是静态属性，而是相对当前 agent 目标定义的，这也是它和通用压缩器的主要区别。

其三是 pipeline 设计。系统先做 segmentation、kind classification 和 level labeling，再按 segment 单独压缩。压缩模型只看到 task + 单个 segment + kind/level tag，不直接接收数值 token budget；预算通过 system prompt 中的 level-to-ratio 表间接传达。作者原本设计了四级重要性标签 L0-L3，并希望不同 level 对应不同压缩率，但实验发现蒸馏后的 student 实际只学出了两个有效压缩带宽，四级设计没有按预期落地。这个负结果作者没有回避，反而是全文里比较有价值的部分。

First, it uses extractive compression. Instead of rewriting code and tool outputs, the model selects spans from the input and uses a fixed set of structural markers to denote removed regions. The reason is straightforward: downstream edits depend on exact strings, so identifiers, paths, numbers, and error messages should be copied, not paraphrased. The paper audits this claim explicitly: 96.0% of emitted identifier/path/number-like tokens are copied from the input on the training corpus, and 96.2% on held-out SWE-bench Lite outputs; excluding the one category intentionally rewritten by design, the rate reaches 98.3%.

Second, the compressor is intent-conditioned. Each compression call receives both the current task/query and a single segment, so the model can prioritize entities, files, functions, and error clues named in the live task. The paper argues that importance is not intrinsic to a segment; it is defined relative to what the agent is trying to do now.

Third, the system is built as a pipeline. A gateway performs segmentation, kind classification, and level labeling, and the model compresses one segment at a time. The compressor sees the task plus one segment with kind/level tags, but no explicit numeric token budget. Budget control is only indirectly encoded through a static level-to-ratio table in the system prompt. The authors originally designed four importance levels, L0-L3, but report that the distilled student effectively learned only two usable compression bands. That negative result is one of the more informative parts of the paper.

On data, they start from 67,074 raw OpenHands trajectories and build a five-stage pipeline that yields a 45K-segment distillation pool and 40,606 teacher-validated compression examples with intent-conditioned targets, level labels, and must-keep annotations. On training, they compare three matched backbones and choose 4B. They also tried drop-supervision weighting, found that it backfired, and shipped without it. Notably, the deployed checkpoint was selected by an out-of-distribution sweep rather than by training loss, which suggests that lower loss did not reliably predict real utility.b:T53a,The evaluation has two layers. The intrinsic evaluation focuses on OOD holdout performance, including compression quality, must-keep retention, and identifier retention, with confidence intervals. One notable result is that at comparable budgets, the student does not underperform its own teacher on must-keep identifier retention, which suggests that distillation preserved the key exact-copy behavior.

The end-to-end evaluation plugs Paritok-4B into a coding-agent workflow under both raw-source and in-distribution line-numbered settings. The headline result is a 25.7% compression rate, meaning roughly one quarter of the original context is retained, while maintaining comparable single-shot solve quality. The paper describes this as roughly twice as aggressive as strong GPT-based compressors. Interestingly, the expected trade-off did not appear in the predicted form: instead of harder compression at equal quality, they observed slightly softer compression with higher quality, and no paired degradation was statistically resolvable over 300 instances.

That said, the scope is narrow. The conclusions are tied to coding-agent trajectories, the specific segmentation pipeline, and teacher-generated targets.
