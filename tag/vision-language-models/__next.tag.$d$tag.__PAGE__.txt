9:T641,The core idea is a spatial compiler that turns rendered visual experience into dense, linked supervision. Starting from static 3D scenes and camera trajectories, the system renders RGB observation sequences. During data construction, it also has access to privileged information such as camera poses, scene geometry, and object identities. These are never exposed to the model at inference time, but they are used to compile supervision.

The supervision is organized into three connected capabilities within the same episode. First, self-motion tracking asks the model to infer how the observer moved between observations. The important point is that motion is not treated as an isolated target; it is the mechanism that should drive state updates. Second, persistent object mapping requires the model to maintain object locations and relations as the viewpoint changes, including when objects become occluded or leave the field of view. Third, operations over state ask downstream spatial questions on top of the updated internal state.

A second important design choice is motif-driven trajectory rendering. Instead of random camera paths, the authors define trajectory motifs that control how visibility, evidence, and viewpoint changes unfold over time. This lets them systematically generate episodes that require memory, re-localization, reference-frame handling, and state maintenance. The resulting questions are grouped into shared episodes so that motion estimation, state update, and reasoning are learned as connected parts of one experience rather than as unrelated instruction examples.a:T569,The paper builds Uruqi-600k and trains URUQI Syn-8B. The representation compiler maps a visual graph into a structure-preserving intermediate graph representation. Its job is to recover nodes, edges, directions, weights, and relevant graph state as faithfully as possible. The operation compiler then decides which graph procedure should be executed for the given query under that recovered state. This matters because the correct executable procedure depends on the graph condition: reachability, cycle detection, and shortest path are different tasks, and shortest path itself depends on whether the graph is unweighted, nonnegative-weighted, or contains negative edges.

Instead of implementing these compilers as fixed symbolic modules, the paper uses a VLM to generate executable code. Code is treated as the primary reasoning object. During training, the model generates candidate code conditioned on a graph-question pair, and reinforcement learning is used to optimize generation. The reward is layered rather than answer-only: executability of the code, validity of the compiled graph, quality of the recovered representation, and quality of the chosen operation all contribute. This is an important design choice because it separates “correct answer for the wrong reason” from “mostly correct compilation but imperfect final execution.”

A second notable component is the code archive. A frozen observer extracts lightweight cues from each graph-question pair and uses them as condition signatures. Generated code is archived under these signatures during training, and compatible archived code can be retrieved at inference time. This is similar in spirit to case-based retrieval, but the retrieved object is executable program structure rather than natural-language reasoning traces.
