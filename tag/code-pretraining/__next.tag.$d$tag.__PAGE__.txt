第一是 GQA 且只保留 4 个 KV heads。报告明确指出，在高并发场景下，KV heads 数量是吞吐的关键瓶颈之一；同步单请求时影响不大，但真实服务下会直接决定 KV cache 带宽和显存压力。第二是 Sliding Window Attention，只在四分之三的层上启用，用局部注意力换取更低推理成本，同时保留部分全局层维持跨段信息流。第三是单个 MTP head，既作为预训练辅助目标，也作为 speculative decoding 的内置 draft head。这一点比较实用：训练时增加 next-multiple-token 的学习信号，推理时直接复用为草稿模型，减少额外 draft model 的部署复杂度。

作者系统比较了 dense、MoE 和 MLA 路线。结论是：在给定延迟预算下，dense 配置即便调整层数和宽度，也难稳定超过 Qwen2.5-7B；MLA 虽然能在等速下把参数做大到约 5.5B，但质量收益不足以覆盖训练复杂度，而且适合该尺度的 latent rank 不理想。因此最终选择 MoE，把总参数扩到约 12B，同时把每 token 计算维持在 2.5B dense 左右。

训练上采用三阶段预训练 curriculum，总计约 10.6T token，遵循“web early, curated late”思路，代码占比从 23% 提升到 42%，再到 59%，同时 batch size 翻倍，并在最后加入 capability-sharpening phase，把学习率线性衰减到 0。这个设计反映了一个明确判断：前期需要更广覆盖的数据维持通用性，后期再提高代码和数学密度去打磨目标能力，而不是一开始就用高纯度代码语料。优化器用 Muon，训练精度用 FP8 hybrid mixed precision，学习率调度是 Warmup-Hold-Decay 并线性降到 0。报告强调他们在十万亿 token 级别的 MoE 训练中观察了稳定性问题，这部分如果写得细，会比常见技术报告更有价值。

The model has about 12B total parameters with 2.5B active parameters per token.

Three deployment-oriented modifications define the design. First, it uses GQA with only 4 KV heads. The report explicitly argues that KV-head count is a major throughput bottleneck under high concurrency because it directly affects KV-cache bandwidth and memory pressure. Second, it applies Sliding Window Attention to three out of every four layers, reducing attention cost while preserving some global-attention layers for long-range information flow. Third, it adds a single Multi-Token Prediction head. This head serves two roles: an auxiliary pretraining objective and an internal draft head for speculative decoding. That is a practical systems choice, because it improves training signal density and inference efficiency without requiring a separate draft model.

The architecture search compares dense backbones, MoE variants, GQA settings, MLA, SWA patterns, and sparsity ratios. The conclusion is straightforward: under the target latency budget, dense models do not consistently beat a Qwen2.5-7B baseline; MLA allows somewhat larger dense-equivalent models but does not justify the added complexity at this scale; MoE is the only route that meaningfully expands total parameter capacity while keeping per-token compute low enough for deployment.

Pretraining follows a three-phase curriculum over roughly 10.6T tokens. The data mix shifts from broad web-heavy data to more curated code and math, with code ratio increasing from 23% to 42% to 59%. Batch size doubles across phases, and the final stage uses an extended capability-sharpening phase with linear decay of the learning rate to zero. The optimizer is Muon, training uses hybrid FP8 mixed precision, and the LR schedule is Warmup-Hold-Decay. The report frames this as a production-scale MoE recipe rather than a one-off experiment.

For long-context extension, the pretrained base is continued to 131,072 tokens using a layer-selective scaling recipe similar to Gemma 3 and OLMo 3, with YaRN for positional scaling. The report also mentions empirical observations on data-mixture transfer and MoE router dynamics during this stage.
