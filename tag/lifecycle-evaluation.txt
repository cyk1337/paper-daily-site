18:T6cb,There are two main technical ideas. The first is lifecycle decomposition. The authors organize harness risk into six operational phases: Harness Configuration, Capability Extension, Runtime Operation, State Persistence, Action Control, and Incident Recovery. This is useful because it re-groups agent failures by harness responsibility. Configuration covers connectors, credentials, gateways, and policy templates; capability extension covers plugin selection, installation, updates, and permissions; runtime operation covers adversarial content in emails, webpages, documents, and tool outputs; state persistence covers whether transient malicious content gets written into durable memory or policy state; action control covers high-impact actions such as payments, deployments, deletions, OAuth grants, and outbound communication; incident recovery covers rollback, credential rotation, state repair, and evidence preservation. The second idea is the benchmark protocol itself. HarnessRisk contains 128 sandboxed cases spanning those six phases. Each case combines a benign user goal with an adversarial instruction embedded in an untrusted workflow artifact. The agent operates through a three-turn owner workflow with case-specific files, tools, persistent state, and mock services. Every run starts from a fresh environment and real network access is disabled. Evaluation is split into Utility, Attack Success Rate, Persistence, and Detection. That separation is important because it allows the benchmark to show that successful task completion and safe execution are not the same thing. The evaluated unit is not a bare model but a deployed model-harness configuration: three harnesses, six models, and fourteen total configurations.19:T43c,The most important empirical findings are qualitative but strong. First, high utility can coexist with high attack success. That is the central result: task completion alone is a poor proxy for safety. Second, Harness Configuration is the most vulnerable phase across all three harnesses. The reason is not that runtime attacks disappear, but that configuration-time manipulation can weaken security-sensitive parameters before the rest of the workflow even begins. Third, model safety rankings change substantially across harnesses, showing that permissions, state representation, tool exposure, and authorization context materially alter the risk profile of the same underlying model. The benchmark also measures Persistence and Detection, which extends evaluation beyond one-shot unsafe actions to durable compromise and explicit risk recognition.
