5:T616,For each task instance, Gated-BEPO samples a group of K rollouts. Environment observations are converted into hashable state keys, and identical observed states are merged into an empirical graph. Edges correspond to rollout records: state, action, reward, and next state. Instead of assigning uniform trajectory credit, the method runs a mean-backup Bellman fixed-point evaluation on this empirical graph to estimate node values under the current rollout policy. It then computes fixed-point temporal-difference residuals and propagates them along each trajectory using GAE to obtain step-level advantages.

The central addition is a graph-confidence gate. If a state has only one observed successor, the graph provides no empirical basis for comparing alternative transitions, so the Bellman step credit is suppressed and the update relies mainly on group-relative outcome advantage. If a state has multiple observed successors, the local graph contains comparative evidence, so the Bellman credit is activated and given more weight, while the outcome signal is still retained as a stabilizer.

This differs from GRPO, which uses only trajectory-level credit; from GiGPO and HGPO, which rely on state or history matching to form local groups; from GAGPO, which propagates a grouped return proxy with TD/GAE-style estimates; and from GraphGPO, which uses graph distance to successful terminal states and can be sensitive to perceptual aliasing. Gated-BEPO instead evaluates the empirical rollout graph and gates its contribution based on observed branching.6:Tb02,方法由三部分组成，而且三部分是互相咬合的，而不是简单拼装。

第一部分是 live MCP environments。作者实现了 20 个 stateful MCP server，共 343 个工具，每个环境作为独立子进程运行，通过 stdio 通信，并且在 rollout 级别做 session-scoped state isolation。这个设计的关键不是“工具多”，而是“每个 rollout 的状态独立且可重置”，否则 RL 训练会被跨样本污染。环境覆盖 finance、calendar、filesystem、commerce、travel、IoT、developer tools 等场景，强调的是账户余额、库存、日历事件、文件树这类会随调用改变的状态。相比 cached API，live execution 能暴露余额不足、优惠券过期、实体不存在、前置步骤未完成等错误，这些恰好是多步 tool use 最容易出问题的地方。

第二部分是 grounded state-machine data synthesis。作者没有直接让 LLM 凭空写 query，而是先 probe live server，采样当前真实实体和状态，再基于 dependency graph 和状态机驱动 teacher 生成多轮对话。这里的关键点有两个：一是 query grounding，保证提到的账户、订单、事件、文件等在当前环境里真的存在；二是 replay validation，所有轨迹都要重新执行验证。生成的数据不仅包含标准多步工具调用，还包含 missing-function clarification 和 abstention 场景，也就是工具不够、信息不足、应该追问或拒绝时的行为。全文强调这套数据构造不依赖人工标注，也不依赖 LLM-as-judge，而是靠程序执行结果闭环验证。

第三部分是 multi-component programmatic reward。奖励被拆成五项：tool call validity、dependency-ordered coverage、adaptive efficiency penalty、tool-name signal、argument-value matching bonus。这里最重要的是后两项设计思路。dependency-ordered coverage 不只看是否覆盖 GT 调用，还看顺序是否满足依赖关系，避免模型“把对的工具都调一遍”却不按执行逻辑组织。adaptive efficiency penalty 则不是固定惩罚调用次数，而是按任务复杂度给一个 call budget，超过预算再罚，避免简单任务和复杂任务用同一尺子。tool-name signal 给模型一个更直接的工具选择监督；argument-value matching 则把参数填充质量纳入奖励，而不是只看工具名是否对。作者在消融里指出，adaptive budget 和 tool-name signal 是最关键的两个组件，这说明冗长调用和错误选工具是 RL tool use 中两个最主要的失真源。

First, live MCP environments. The authors build a library of 20 stateful MCP servers exposing 343 tools. Each environment runs as an isolated subprocess and communicates over stdio. During RL, every rollout gets a unique session ID, which enforces session-scoped state isolation. This is more important than the raw tool count: without per-rollout isolation, state contamination across episodes would corrupt both reward and learning. The environments cover domains such as finance, productivity, commerce, travel, IoT, developer tools, and knowledge management. Their defining property is statefulness: balances change, events persist, files accumulate edits, and so on. Compared with cached APIs, live execution exposes realistic failures such as insufficient balance, expired coupons, missing entities, or unmet prerequisites.

Second, grounded state-machine data synthesis. Instead of prompting an LLM to invent tasks from scratch, the pipeline first probes each live server to sample real entities and current state. Query generation is then grounded in those sampled entities, and a state-machine teacher generates multi-turn conversations following tool dependency graphs. Every generated trace is replayed and validated. This matters for two reasons: the queries refer to entities that actually exist in the environment, and the final trajectories are execution-valid rather than merely plausible in text form. The synthesized set includes not only standard multi-step tool-use traces, but also clarification turns for missing information and abstention cases where no tool should be used.

Third, a fully programmatic multi-component reward. The reward decomposes tool-use quality into five parts: tool-call validity, dependency-ordered coverage, an adaptive efficiency penalty with a complexity-scaled call budget, a tool-name signal, and an argument-value matching bonus. The design choice that matters most is that coverage is not enough; the model must cover the right calls in the right dependency order. The adaptive efficiency term is also important: instead of penalizing all extra calls equally, the budget scales with task complexity, which avoids over-penalizing genuinely complex tasks. The tool-name signal gives direct supervision on tool selection, while argument-value matching rewards correct parameter filling. The ablation identifies the adaptive budget and tool-name signal as the most critical components, suggesting that verbosity and wrong tool choice are the main distortions induced by naive RL rewards.

Training is implemented in VERL, with model-generated tool calls routed to the MCP servers and rewards computed from execution outcomes. The paper is best read as an executable-environment RL recipe rather than a new RL algorithm.8:T713,The main empirical result is straightforward: Prove improves all four tested models, from two architecture families, on all three benchmarks—BFCL Multi-Turn, τ²-bench, and T-Eval—using only about 13K training examples. The paper also emphasizes that this is roughly 8× smaller than a concurrent RL pipeline such as AgenticQwen, and it does not rely on an external judge model. From the available full text, three experimental messages matter most.

First, the gains are consistent across models and benchmarks. That reduces the chance that the method is overfitting to one benchmark’s annotation style or one model family’s tool-calling format.

Second, the reward ablation is highly informative. The adaptive call budget and the tool-name signal are reported as the most load-bearing components. This supports the paper’s diagnosis that recall-style rewards fail not because they are weak, but because they point in the wrong direction: if extra calls are not penalized and correct tool choice is not directly rewarded, the model can improve reward by becoming verbose.

Third, the environment and synthesis pipeline appear to matter because they improve execution validity rather than textual plausibility. The paper repeatedly contrasts live MCP execution with cached or simulated APIs, and grounded synthesis with ungrounded synthetic queries. Even without exhaustive numerical detail in the excerpt, the mechanism is clear: fewer samples can still be effective if each sample is aligned with real environment state and validated by execution.

The key scale numbers are already useful: 20 MCP servers, 343 tools, around 13K training examples, 4 models, and 3 benchmarks.
