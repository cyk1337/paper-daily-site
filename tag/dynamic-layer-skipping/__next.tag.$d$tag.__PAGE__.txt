9:T45c,The main idea is a serving virtualization layer that separates the skipping policy from engine execution. A skipper exposes per-token RUN or Project-Only decisions at routed layers. vSkipper then realizes those decisions inside SGLang while preserving the engine’s batching and cache interfaces. RUN rows execute the layer normally. Project-Only rows bypass the layer’s attention and FFN, but still write the KV state needed by future autoregressive attention. This KV-complete treatment is the key correctness constraint: skipping hidden-state computation does not mean the layer can disappear from the cache. For execution, vSkipper packs rows with the same decision into cohorts at each routed layer, runs the corresponding computation, and scatters outputs back to the original batch positions. It also uses profitability-aware mode switching, routing only when estimated savings exceed the overhead of routing, packing, and dispatch.
