9:T838,方法很简洁，关键是把回归目标从“mixture -> 最终 loss”改成“当前训练状态 -> 下一阶段 loss”。RegMix 原始做法是：采样若干 mixture，训练若干小 proxy 模型到固定步数，只记录终点验证损失，再拟合一个回归器预测某个 mixture 的终点 loss，最后选一个全程固定的 mixture。RegMix-D 则在 proxy 训练中按多个时间点记录 validation loss，把每条 proxy trajectory 切成若干相邻区间。对于给定的 switch point 数 N，会选出 N+1 个时间节点 t1...tN+1，并从每条轨迹构造 M×N 个训练样本。回归器 f_N 的输入是当前步点 t_l、当前 mixture m、当前 observed loss l_l，输出是下一时间点的 loss l_{l+1}。也就是说，它学的是局部转移，而不是全局终点映射。

在部署上有两个版本。Offline 版本在目标训练开始前递归生成完整 schedule：从初始 loss 出发，在每个 switch point 上搜索使预测下一段 loss 最低的 mixture，把预测出的 loss 再喂给下一段，直到生成整条 mixture schedule。这个版本不需要 target run 中途干预，但误差会递归累积。Online 版本则在 target training 的每个 switch point 上，用目标模型真实观测到的 validation loss 替代预测 loss，再调用同一个冻结回归器选择下一段 mixture。这样做的好处是把 proxy-to-target 的偏差限制在单段决策里，而不是沿整条 schedule 传播。

方法上的几个细节值得注意。第一，作者没有引入额外 RL、bandit 或 bilevel optimization 机制，仍然是回归 + candidate search，所以工程接入成本低。第二，初始阶段固定使用 human-curated Pile prior，而不是从第一个 segment 就让回归器自由选 mixture，这反映了一个现实假设：训练初期没有足够 target-state 信息，先验配比更稳。第三，mixture 搜索仍然通过 Dirichlet-sampled candidates 完成，说明作者追求的是在现有 RegMix 搜索框架内最小改动地升级为 dynamic mixing，而不是重新设计连续优化器。a:T7d0,The key move is to replace a global regression target with a local transition model. In standard RegMix, each sampled mixture is used to train one proxy model to a fixed horizon, only the final validation loss is kept, and a regressor maps mixture to endpoint loss. The chosen mixture is then used for the entire target run. RegMix-D logs validation loss at multiple points along each proxy trajectory. For a chosen number of switch points N, it selects N+1 time anchors and converts each proxy trajectory into M×N training examples. The regressor f_N takes the current state (training step t_l, current mixture m, current loss l_l) and predicts the next loss l_{l+1}. In other words, it learns one-step loss transitions rather than a direct mixture-to-final-loss map.

This enables two deployment modes. In the offline mode, the schedule is generated before target training: starting from an initial loss, the method searches over candidate mixtures at each switch point, picks the one with the lowest predicted next-step loss, feeds that predicted loss into the next decision, and recursively builds a full schedule. In the online mode, the same frozen regressor is queried during target training, but the current loss is the actually observed target-model validation loss rather than the previously predicted one. This grounds each decision in the real target trajectory and limits error accumulation.

Several design choices are worth noting. The method does not introduce RL, bandits, or bilevel optimization; it stays within the regression-plus-search framework, which keeps the engineering overhead low. The first segment uses the human-curated Pile prior instead of a learned mixture, reflecting a cold-start assumption that early in training there is not enough target-state information to trust dynamic adaptation. Candidate mixtures are still searched via Dirichlet sampling, so the contribution is a minimal but effective extension of RegMix rather than a full redesign of the optimizer.b:T571,The experiments follow the standard RegMix setup: a 1B-parameter target model trained on 25B tokens from the Pile. The main comparisons are static RegMix versus RegMix-D, with both offline and online variants evaluated under different switching granularities. The headline findings are consistent. First, RegMix-D outperforms RegMix at every tested granularity, both in validation loss and across 13 downstream tasks. Second, the online variant is generally more reliable than the offline one because it uses observed target losses to correct the state, whereas the offline schedule can accumulate recursive prediction error. Third, the method is notably more proxy-efficient: 128 proxy models, about 25% of the 512-proxy budget used by RegMix, are already enough to surpass the static baseline.

The important experimental point is not one unusually large gain, but the consistency of the improvement. The ablation logic also matters: the benefit comes from extracting more supervision from the same proxy runs, not from adding a new expensive optimization loop. By reusing intermediate losses, each proxy run yields many local transition labels.
