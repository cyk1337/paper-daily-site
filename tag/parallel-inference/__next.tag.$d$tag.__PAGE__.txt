9:T72a,PI-Mem introduces Parallel-Iterative Memory. A long context is split into equal-sized chunks, and a global textual memory is initialized as empty. Each turn consists of three operations: read, select, and merge. In the read step, all chunks are processed in parallel conditioned on the same current global memory. This differs from standard recurrent-memory systems, where chunk i must wait for the memory updated by chunk i-1. The immediate consequences are lower latency and less risk that later chunks repeatedly overwrite a single evolving memory state before earlier evidence can be integrated.

In the select step, the model extracts observations from each chunk that contain new or complementary evidence. In the merge step, these observations are consolidated into an updated shared memory for the next turn. The important mechanism is that, in the next iteration, every chunk is read again under a memory that already contains evidence gathered from other chunks. Cross-chunk interaction therefore happens through iterative shared-memory refinement rather than through a single serial pass. The process stops either when no chunk contributes useful new evidence or when a predefined maximum number of turns K is reached, after which the model answers based on the question and the final memory.

Training is done end-to-end with reinforcement learning rather than stepwise supervision of memory contents. The reward combines answer accuracy with a turn-efficiency term that discourages redundant turns. This means evidence extraction, memory update behavior, and stopping decisions are all optimized jointly as a policy. Relative to prior recurrent-memory baselines, the key difference is not a larger memory budget but a different update topology: parallel reads plus iterative shared refinement instead of serial overwrite.a:T4a0,The paper evaluates PI-Mem on Qwen3.5-35B-A3B and Qwen2.5-7B, focusing on long-context QA and especially HotpotQA at 3.6M tokens. The headline result is that on 3.6M-token HQA, PI-Mem improves over MemAgent by +6.25 and +7.81 absolute points, while also delivering 6.1× and 2.1× inference speedups, respectively. These numbers support both of the paper’s claims: better evidence preservation/integration and lower latency under ultra-long inputs.

The method uses a bounded number of turns rather than unbounded iterative refinement, so cost depends on both chunk parallelism and the number of turns. The turn-efficiency reward is meant to prevent the model from always using the maximum number of turns. The excerpt provided does not include the full ablation tables, but the important ablations to verify are clear: replacing parallel reads with serial updates, removing iterative refinement and using a single pass, removing the turn-efficiency reward, varying the maximum turn count K, and changing chunk granularity to study the accuracy-latency trade-off. Those are the experiments that determine whether the gains truly come from reduced overwrite and improved parallelism.b:T407,For a skim, start with the method and the main result table. That structural difference explains both the latency gain and the reduced tendency to wash out early evidence.
