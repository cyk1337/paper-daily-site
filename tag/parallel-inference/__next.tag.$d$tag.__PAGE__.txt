2) 可达状态很浅：当 horizon n 有界时，串行 greedy 控制器在后续只会访问“前缀状态”（prefix states）。以 n=3 为例，一旦 a1 固定，后续只需要咨询 (a1) 以及 (a1,c) 这类前缀（c!=a1），总数是 O(k) 而不是指数。

3) 两步执行图：
- Root prefill：对 prompt + 开头 forced syntax 做一次前向，得到 slot-1 logits，并缓存 KV；用与串行相同的规则选出 a1。
- Tree-causal probe：把所有需要的前缀 continuation（每个 continuation 都是“串行解码在该前缀下会生成的 forced token 序列”，包括语法 token 与槽位位置）拼接成一个 batch-like 的长序列，在一次 forward 里计算。关键是构造 block-causal attention mask：每个“行”（一个前缀）只能 attend 到共享的 prompt KV 和它自己的祖先 token；同时使用与串行一致的 position ids，使得每个位置看到的 token ids / position ids / 可见祖先集合与串行完全一致。

- Prefix-state lemma：若 tree-packed 与 serial 在某个前缀 ρ 上的 token ids、position ids、ancestor-visible attention set、参数一致，则每层 hidden state 一致，从而 logits 一致。

- Key observation: With bounded horizon n (deployment uses n=3), the serial greedy controller can only visit a small set of reachable prefix states. After fixing a1, the remaining consulted states are essentially (a1) and (a1,c) for c!=a1, i.e., O(k) states.

  1) Root prefill: run the prompt + opening forced syntax once, obtain slot-1 logits and KV cache, pick a1.
  2) Tree-causal probe: build all required prefix continuations (exactly the forced token sequences serial decoding would have produced for each prefix), concatenate them into one packed sequence, and run a single forward pass with a block-causal attention mask. Each row attends to the shared prompt KV and its own ancestors only, using serial position indices so that tokens/positions/visible ancestry match the serial run.

A long context is split into equal-sized chunks, and a global textual memory is initialized as empty. Each turn consists of three operations: read, select, and merge. In the read step, all chunks are processed in parallel conditioned on the same current global memory. This differs from standard recurrent-memory systems, where chunk i must wait for the memory updated by chunk i-1. The immediate consequences are lower latency and less risk that later chunks repeatedly overwrite a single evolving memory state before earlier evidence can be integrated.

In the select step, the model extracts observations from each chunk that contain new or complementary evidence. In the merge step, these observations are consolidated into an updated shared memory for the next turn. The important mechanism is that, in the next iteration, every chunk is read again under a memory that already contains evidence gathered from other chunks. Cross-chunk interaction therefore happens through iterative shared-memory refinement rather than through a single serial pass. The process stops either when no chunk contributes useful new evidence or when a predefined maximum number of turns K is reached, after which the model answers based on the question and the final memory.

Training is done end-to-end with reinforcement learning rather than stepwise supervision of memory contents. The reward combines answer accuracy with a turn-efficiency term that discourages redundant turns. This means evidence extraction, memory update behavior, and stopping decisions are all optimized jointly as a policy. Relative to prior recurrent-memory baselines, the key difference is not a larger memory budget but a different update topology: parallel reads plus iterative shared refinement instead of serial overwrite.c:T4a0,The paper evaluates PI-Mem on Qwen3.5-35B-A3B and Qwen2.5-7B, focusing on long-context QA and especially HotpotQA at 3.6M tokens.
