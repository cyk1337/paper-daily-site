1b:T78d,The technical contribution has two layers. The first is the formulation. A skill is treated as a modular capability package that may include natural-language instructions, invocation conditions, tool-use procedures, executable code, and auxiliary resources. Based on this, the SRA pipeline is decomposed into three stages: skill retrieval, which asks whether the system can find relevant skills from a large external corpus; skill incorporation, which asks whether the agent can identify and organize the useful skills among retrieved candidates; and skill application, which asks whether those incorporated skills are actually used in a way that improves task success. This decomposition is useful because it separates retrieval failure from reasoning failure and execution failure.

The second layer is benchmark design. The paper introduces a large-scale skill corpus and SRA-Bench, where each instance contains a user query, a ground-truth answer, and gold skill annotation. That enables stage-wise evaluation instead of collapsing everything into a single end-task metric. The benchmark is designed to diagnose whether the right skill was retrieved, whether the agent recognized it as useful, and whether using it improved behavior. The novelty is therefore less about a sophisticated retrieval model and more about defining the right object of retrieval and the right evaluation protocol.

A central design choice is the explicit distinction from classical RAG. In knowledge-centric RAG, retrieved items are declarative evidence. In SRA, retrieved items change the agent’s action space. That means a semantically similar skill can still be useless, and a retrieval metric that ignores execution utility can be misleading. If later sections include concrete retrievers, rerankers, or integration strategies, those should be read mainly as operational baselines for the SRA setting rather than the main scientific contribution.1c:T56e,From the available full-text excerpt, the experimental section appears to center on decomposed evaluation over SRA-Bench, but the visible content does not include enough tables or numeric details to quote dataset sizes, model scales, or exact gains reliably. First, the paper likely compares explicit in-context skill enumeration against retrieval-based skill access as the skill corpus grows. The claimed failure mode of the former is twofold: context budget exhaustion and degraded skill selection accuracy.

Second, because SRA-Bench includes gold skill labels, the experiments can separately measure retrieval coverage, candidate quality, and whether correct retrieval actually translates into better task performance.

Third, an important empirical question is the gap between semantic relevance and functional utility. The benchmark is set up to expose cases where retrieved skills look relevant but do not improve execution.

For a careful read, the most important missing numbers to extract are: corpus size, task distribution, annotation protocol for gold skills, top-k retrieval metrics, incorporation success rates under different agent backbones, and end-task gains relative to no-skill and full-skill-enumeration baselines.
