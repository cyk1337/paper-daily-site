18:T472,LazyTrain adds an optimization layer on top of a MegaTrain-like layer-streaming executor. The executor provides primitives (stream parameters CPU→GPU per layer, compute a layer or recompute block, offload gradients GPU→CPU, reload activation checkpoints from GPU/CPU/NVMe). LazyTrain decides, before training starts, which primitives to use and when.

Core idea: formulate activation checkpoint selection, placement (HBM/DRAM/NVMe), recomputation blocks, and communication overlap as a mixed-integer linear program (MILP).
- Binary variables select a legal checkpoint path over layer boundaries via edges (s,e) representing recomputation blocks.
- Binary placement variables assign each materialized boundary to GPU/CPU/NVMe.
- Continuous variables allocate activation traffic into compute windows to model overlap vs exposure.
- Objective minimizes recomputation cost plus incremental exposed communication induced by placement, rather than maximizing offload volume.
