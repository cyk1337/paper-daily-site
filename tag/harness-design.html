Effective Harness Engineering for Algorithm Discovery with Coding Agents

这篇工作研究的不是“LLM 会不会写算法”，而是更具体也更容易被忽略的问题：在固定 token 预算下，算法发现系统的执行基础设施，也就是 harness，怎样设计才更有效。作者把问题拆成四类：一，单次采样式代码生成是否已经成为瓶颈，是否应该换成能读代码库、看评测结果、反复调试的 coding agent；二，自动评测很容易被模型钻空子，如何识别 evaluation hacking，而不是把投机程序误当成算法进步；三，多 agent 并行搜索时如何避免共享文件系统上的冲突和不可复现；四，历史尝试中的成功与失败如何沉淀成可复用记忆，而不是每轮都从零开始。论文还回答了一个更基础的搜索分配问题：同样的 token 预算，应该生成更多“浅思考”候选，还是更少但“深思考”的候选。

评参考§3的harness设计准则调整代码预训练的评估流程，推理资源权衡的结论可复用
Yoichi Ishibashi,Taro Yano,Masafumi Oyamada
