Selection Is Not Learning: Choosing Model Futures

这篇工作抓住了自演化训练里一个很具体、但此前常被混过去的问题：任务筛选通过，不等于这次参数更新真的有益。R-Zero、Agent0、Skill Self-Play 这类循环通常先找“看起来可学”的题，再把由这些题产生的更新整体继承到下一轮。问题在于，任务侧信号只描述更新前的行为，比如通过率、分歧度、是否位于能力前沿；它并不直接告诉你，优化器走完这一步之后，模型是否真的更倾向于正确答案，还是只是把局部噪声、错误偏好、甚至已有能力的退化一起带进了下一轮。文中把这个问题定义为 selection-to-update gap，并且用审计结果说明它不是边角现象：在 Agent0 和 R-Zero 的原生 admission 中，42–52% 被接纳的任务在独立响应下并没有留下正向前沿收益；在 Skill-SP 的 96 次更新里，有 60 次对 correct-target NLL 的增益非正。也就是说，自演化系统真正需要决策的不是“哪些题值得做”，而是“哪些训练后状态值得继承”。

评值得立刻对照自训练/R-Zero 内部流程：把“是否继承更新”当成一等公民做 commit gate；先读误差分解那节和 commit 评测设计。

Backward-State Policy Is Part of the Learning Algorithm

低精度训练里，前向传播会把张量舍入，反向传播又会多次读取这些张量。常见实现把这个选择当成存储细节：读前向已经舍入的值、读原始值，或重新随机舍入一个值。核心问题是，这个“反向状态策略”会改变训练实际沿着的梯度方向，因此它是学习算法的一部分，不能只用 copy accuracy 或最终 loss 判断是否正确。

评应立刻读方法和失败案例；它会改变 FP8 训练里“存得越准越好”的直觉。

Delta-Matching: Closing the Final Gap of Native 8-bit Training for LLMs

这篇工作处理的是原生 FP8 LLM 训练里最后一个很难绕开的点：attention backward 的数值一致性。问题不在“FP8 会不会有一点噪声”，而在 FlashAttention 常用的 backward row correction 捷径在 FP8 下失效。forward 里保存的输出和 backward 里重新参与计算的量分别经过独立量化后，不再满足 softmax backward 所依赖的零行和约束，作者把这个失配称为 stale delta。它会给 score gradient 引入系统性残差，而不是均值为零的随机误差。小模型、短训练、短上下文时这个问题可能被掩盖；一旦模型到 1.67B、5.29B，或者进入 8K→64K 的长程 context extension，这种残差会沿优化过程累积，最终表现为 loss 抬升和下游退化。

评应立刻读数值推导和 scale ablation；它改变我对 FP8 attention“小模型能跑通就安全”的判断。
Haozhan Tang,Hao Kang,Han Cai,Song Han,Chenyan Xiong
