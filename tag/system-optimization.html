TEMPO: Makespan-Aware Expert-Parallel Load Balancing Across Memory- and Compute-Bound Regimes

这篇工作处理的是 MoE 推理里 expert-parallel dispatch 的目标函数错配问题。现有做法通常用 token 数或 activated expert 数做代理，默认单个 GPU 的 expert 计算时间分别近似线性依赖于 token 数或 expert 数。但作者直接测量后发现，真实时延由两类硬件效应共同决定：一是小 token 区间里权重从 HBM 流入带来的固定开销，二是 grouped GEMM 的 tile padding 让 token 成本呈台阶状而不是线性。由于 EP 每层在 all-to-all 前后都要同步，真正决定吞吐的是最慢 GPU 的 makespan，而不是平均负载。问题的难点不在单一 regime，而在真实 decode batch 中 memory-bound 的冷 expert 与 compute-bound 的热 expert 同时存在，导致任何单一 proxy 都会系统性失真。

评实测MoE EP服务的双regime时延特性非常扎实，直接推翻了“专家时延与token数线性”的默认假设，做MoE训练与推理系统的人必须看§3的测量方法与Fig 2。
Jie Li,Chenxin Jia,Jinliang Shen,Cunzhuang Liu,Ruiyi Ding,Jianwen Xian,Kang He,Chengru Song

EfficientRollout: System-Aware Self-Speculative Decoding for RL Rollouts

这篇论文解决的是 on-policy RL 训练中的 rollout 生成延迟问题。常规自回归采样必须逐 token 解码，长回答和尾部样本会拖慢整个 batch；但直接把 serving 场景的 speculative decoding 搬到 RL rollout 中并不稳定，因为目标 policy 在训练中持续变化，固定 drafter 会过期，同时大 batch 初期往往处在 compute-bound 区间， speculative verification 可能反而变慢。

评RL后训练rollout延迟痛点的针对性优化，自推测+系统感知调度的思路可直接复现到内部RL训练pipeline，重点读§3的系统调度设计
