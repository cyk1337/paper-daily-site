Activation analysis uses four depth checkpoints per model: layers 8/16/24/31 for Llama-3.1-8B, 9/18/27/35 for Qwen3-8B, and 28/29/40/41 for Gemma-4-E4B. The observed on-site rotations are 43 to 56 degrees and decay to below 15% within about 10 downstream tokens. A stacked typo bundle reduces single-position prompt-injection probe TPR by 12.0 percentage points at FPR=1%, and threshold recalibration is not sufficient. Multi-position aggregation reduces localized perturbation loss to at most 0.5 percentage points, but distributed perturbations still cause about a 3.8-point drop even with attention- or max-based aggregation. The KV-cache-forked probe suffix closes about 95% of the single-position gap, leaving a 0.6-point residual, while perturbation-augmented training leaves a 3.7-point residual. An LLM-as-judge check labels 94.6% of clean-perturbed pairs as intent-preserving.19:T4c0,Self-Indexing Attention builds a shared transform-domain sign-magnitude representation. A structured orthogonal transform (motivated by Hadamard-style transforms with random sign flips, LSH intuition, and transform-domain KV compression such as QJL/TurboQuant) is applied to Q/K/V. The per-coordinate sign of transformed keys is stored as a 1-bit, token-level index. Query–key similarity is approximated via sign agreement (a proxy for angular similarity).

Because sign bits are part of the compressed key payload, the same representation supports retrieval and compression without separate index metadata.

To make it work across inference stages:
- Prefill: group queries to amortize selection cost. Instead of average pooling (which can cancel signs), use absmax-sign pooling: for each coordinate, take the sign of the query with the largest absolute value, preserving evidence important to any query in the group.
- Decode: perform packed 1-bit sign-agreement scoring for fast candidate selection, then apply norm-weighted agreement to reintroduce magnitude information lost in sign-only matching.
- Implementation: GQA-aware sparse-attention kernels and bitwise operations for accelerator-friendly execution.1a:T42f,GVA starts from GQA grouping. Multiple query heads share grouped value heads, but the model no longer writes an independent content-key stream into the cache. For query head h, the content key is reconstructed as K_h = V_g(h) M_h, with a separate reconstruction map per query head. During decoding, the map can be folded into the query, since q·(V M_h) equals (q M_h^T)·V. This avoids materializing content keys in the intended decode path. A direct K=V design was tested and did not recover the GQA training loss, which suggests that the same vector should not be forced to both score and carry retrieved content. RoPE creates the main complication: standard RoPE is position-dependent on cached keys, so it cannot be absorbed into a fixed transformed query. The paper uses a small shared decoupled RoPE channel, keeping an unrotated reconstructed content slice and a short rotated positional slice. It also introduces a scale-aware initialization for M_h to match the initial RMS of reconstructed keys and queries, avoiding nearly uniform attention early in training.1b:T979,核心做法是提出 write-time principle：每个字节的最终物理归属在写入时就决定，之后不再为负载均衡目的移动。围绕这个原则，作者设计了 InplaceKVCache 和其上的调度层 WriteScope。

InplaceKVCache 把 KV 空间沿两个维度做物理划分。第一维是 device affinity，区分未来主要由 CPU 还是 GPU 消费；第二维是 access pattern，区分是适合原地计算还是适合高带宽搬运。最终形成四个 region：CPU 侧的 unpinned compute region 和 pinned load region，GPU 侧的 ping-pong compute region 和 D-window offload region。这样 CPU compute engine 只读自己那块 unpinned region，GPU load engine 只流式读取 pinned region 并通过 ping-pong buffer 计算，不再需要把一份 CPU 侧 cache 临时整理成另一种物理状态。

prefill 阶段生成的 KV 直接按目标 region 写入；decode 阶段则先进入 GPU 上的 D-window，等累计到一个 eviction batch 大小 D 后，再整批路由到 pinned 或 unpinned 的 CPU 区域。这里的关键不是简单分层存储，而是把“未来由谁消费、以什么访问模式消费”编码进写入路径，因此后续调度只是在已有物理分区上决定份额，而不是重新组织数据。

WriteScope 负责真正的 CPU/GPU 分工。它沿 sequence 维度切分 KV 份额，用一个可移植 roofline model 估计两边代价：GPU 侧代价是 PCIe 传输加 GPU attention compute，CPU 侧代价是原地 attention compute。调度目标是让累计分配保持在 roofline 平衡点附近，使两边完成时间接近，从而避免一侧空等另一侧。作者强调这里选择 sequence-dimension split，而不是按 head 或 page 做更细粒度切分，原因是 sequence 维度更自然匹配 attention 的历史 token 访问，也更容易维持两侧各自连续、稳定的物理布局。

和已有系统相比，差异很明确。FlexGen、SolidAttention 这类 GPU-centric 方法把 spilled KV 视为待搬运对象，瓶颈在 PCIe；NEO、ScoutAttention 这类 CPU-centric 方法把 spilled KV 视为 CPU 原地计算对象，瓶颈在 CPU 算力。已有方法即便想混合，也会因为 pinned/unpinned、contiguous/per-head 这两种物理要求冲突而落回辅助 buffer 和重排。作者的创新点不在于提出一个更复杂的 scheduler，而在于先把 cache format 改成能承载混合执行的形式。1c:T7db,实验覆盖 DeepSeek-V2-Lite、Qwen3-30B-A3B、Mixtral-8x7B 三个 MoE 模型，兼顾 MLA 和 GQA 两类 attention 结构，并在 32GB VRAM 预算下测试到 1M token 级别总上下文规模（bs=32 × seq=32K）。这是论文最有说服力的部分，因为它不是只在单一模型上做微调式优化。

Based on this principle, the paper introduces InplaceKVCache and a scheduling layer called WriteScope.

InplaceKVCache partitions KV storage along two axes. The first is device affinity, meaning whether a region is intended for CPU-side or GPU-side consumption. The second is access pattern, meaning whether the region is optimized for in-place compute or high-bandwidth loading. This yields four regions: on the CPU side, an unpinned compute region and a pinned load region; on the GPU side, a ping-pong compute region and a D-window offload region. CPU attention reads only the unpinned compute region in place. GPU attention streams only the pinned load region through ping-pong buffers. This removes the fallback path of temporary contiguous buffers, copies, and layout conversion.

Prefill KV is routed directly to its target region at write time. Decode KV is first staged in the GPU-side D-window and, once an eviction batch of size D is full, the batch is routed as a whole into either the pinned or unpinned CPU region. The key point is that future consumer and access mode are encoded into the write path itself. The scheduler no longer needs to reorganize data; it only decides how much future KV should go to each physical partition.

WriteScope performs the actual CPU/GPU split along the sequence dimension. It uses a portable roofline-style model to estimate the two costs: GPU-side transfer plus attention compute, and CPU-side in-place attention compute. Eviction batches are assigned so that cumulative placement stays near the balance point where the two engines finish at similar times. The choice of sequence-dimension partitioning is important. It matches the natural history-token access pattern of attention and preserves stable physical layouts on both sides better than finer-grained head- or page-level splitting.

Compared with prior systems, the distinction is clear. GPU-centric systems such as FlexGen and SolidAttention treat spilled KV mainly as data to reload, so PCIe becomes the bottleneck. CPU-centric systems such as NEO and ScoutAttention treat spilled KV mainly as data to compute over in place, so CPU compute becomes the bottleneck. Hybridization is hard because the physical requirements of the two paths conflict. The novelty here is not a more elaborate scheduler, but a cache format that makes hybrid execution physically expressible.1e:T7f6,The evaluation covers three MoE models—DeepSeek-V2-Lite, Qwen3-30B-A3B, and Mixtral-8x7B—spanning both MLA and GQA attention variants, under a 32 GB VRAM budget. However, after the representation fix, cross-replica reuse still produced wrong outputs. In that path, the raw-pointer lmcache_memcpy_async branch uses cudaMemcpy with cudaMemcpyDefault but without dependence on the current CUDA stream.
