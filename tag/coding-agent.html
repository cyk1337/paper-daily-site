这篇工作处理的是“自我改进型 coding agent 为什么这么贵，以及怎样在严格预算下仍然做出有效搜索”。已有递归自改进方法的主瓶颈不在生成 patch，而在评估 patch：每个候选修改都要重新跑一部分甚至整套 benchmark，时间、CPU 和 API 成本都很高，导致搜索树扩展速度极慢。论文要解决的不是再造一个更强 agent，而是给自我改进过程提供一个更高信噪比、更低成本的中间反馈机制，让搜索不必被慢速 benchmark evaluation 串行卡住。

评只看 judge+Bradley-Terry 如何省掉 benchmark rerun；想借鉴自举闭环可以读，别把它当预训练信号质量结论。
