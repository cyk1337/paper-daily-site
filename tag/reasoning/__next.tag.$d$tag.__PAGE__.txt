第一层是 rollout-level gating。只有当 student rollout 通过 outcome verifier 时，这条 rollout 才被认为包含了值得 teacher 学习的 problem-only reasoning 轨迹。这里的判断不是“student 比 teacher 强”，而是“这条 rollout 至少在结果上成立，因此其中某些 student token 偏好可能比 reference-conditioned teacher 更贴近部署时可行的推理分布”。这样做避免把 teacher 拉向明显错误的 student 行为。

第二层是 token-level selection。即便 rollout 最终正确，也不意味着整条序列的每个位置都该拿来更新 teacher。论文用 teacher-student disagreement 的 KL 信号做位置选择，只在 top-k 个分歧最大的 token 位置上，把 teacher 向 student 适度拉近。这里的直觉很重要：真正需要修正的是 teacher 最不贴近 problem-only reasoning 的位置，而不是所有位置。若全序列都更新，teacher 很快会塌缩到 student，失去 privileged knowledge，后续也就无法继续提供互补监督。

Training still begins with an on-policy student rollout: the student policy sees only the problem x and samples a solution y, while the teacher sees both x and the reference solution y*. Both models are evaluated on the same partial student rollout. The student update remains unchanged: it is still distilled toward the teacher's token-level distribution, exactly as in standard OPSD.

The new part is the teacher update, and it is gated twice.

First, VISTA applies rollout-level selection using an outcome verifier. Only student rollouts that pass verification are allowed to provide feedback to the teacher. The logic is not that the student is globally better than the teacher, but that a verified rollout contains evidence that some of the student's token-level preferences are compatible with successful problem-only reasoning. This prevents the teacher from being pulled toward clearly bad student behavior.

Second, VISTA applies token-level selection within each eligible rollout. Even a correct rollout should not be used wholesale. The paper computes teacher-student disagreement and selects the top-k positions with the largest KL discrepancy. Teacher adaptation is applied only at those sparse positions. This is the central design choice. The goal is to correct the teacher exactly where its distribution is most misaligned with successful problem-only reasoning, while preserving the rest of the teacher's privileged knowledge. If the teacher were updated densely across all positions, the teacher-student gap would collapse too quickly and the teacher would lose its complementary value as a privileged supervisor.

An important practical point is that VISTA reuses the same rollouts and the same family of distillation losses as standard OPSD. The novelty is not a new reward function or a complicated optimization objective. It lies in deciding which rollouts are trustworthy for teacher feedback and which token positions are worth adapting. This also distinguishes VISTA from prior methods. RLSD constrains student updates with verifier rewards; TRACE restricts distillation to selected spans; DemoPSD reweights the target toward the student when teacher and student disagree. All of them reduce student exposure to mismatched teacher targets, but the teacher remains static. For a recipient problem r and a source problem s, the method first constructs an exact, verifiable counterfactual: the source supplies a changed intermediate quantity, which is then combined with the recipient’s remaining variables to define a known counterfactual answer. Both source and recipient are rolled out to a latent step t. At that patch point, a selected cache slice from the source is transplanted into the recipient, optionally together with the current hidden state, and the test checks whether the recipient moves toward the source-defined counterfactual answer.

The protocol is deliberately grid-like rather than a single patch experiment. It varies: which cache segment is patched; whether only K, only V, or both are copied; whether the hidden state is also copied; whether semantic source controls with the same answer are used; whether decoded validation confirms that the patched latent trajectory corresponds to the intended counterfactual behavior; and whether matched corruption on the same region supports necessity. Based on this battery, the paper defines three outcomes: active carrier, carrier shift, and no-call.

Three technical choices are especially important. First, the paper uses exact source-recipient counterfactuals rather than open-ended prompt patching, which keeps the target answer unambiguous. Second, it separates sufficiency from necessity, and tests necessity with matched corruption rather than arbitrary noise, reducing the risk of overcalling mechanisms. Third, it explicitly distinguishes the current hidden state from the cache object: h_t is not part of the cache unless copied by intervention.
