a:T5a3,The method is an agentic LLM-as-judge setup. The data consists of pairs of revisions for the same declaration from Mathlib PRs: an earlier version that was sent back for revision, and the later version that was accepted. Importantly, each version is scored independently. The judge does not know the score of the other revision and is not explicitly told it is doing pairwise comparison, which reduces comparison leakage. The rubric decomposes proof quality into five dimensions: library leverage, automation fit, structural clarity, statement quality, and Mathlib conventions. Each dimension is scored from 1 to 10, then combined by a harness into a final score. The key design choice is tool grounding. The judge can query the exact Mathlib state at the relevant commit through bash, search for existing lemmas, inspect signatures, and check available APIs. That lets it reason like a human reviewer: is this proof reinventing something already in the library, should the statement be more general, is there a cleaner one-line invocation already available. This is materially different from a text-only judge because proof quality often depends on library context, not just the local proof text. For dataset construction, the authors used Claude Sonnet 5 to inspect historical PRs and identify cases with substantial revision differences that were not just linting or newly added declarations, then split them into development and test sets.b:T5dc,The benchmark contains 218 declaration pairs in the test split and 123 pairs in the dev split used for rubric tuning. Six judges were evaluated, including three open-weight and three closed models, with three replicates per judge. Each evaluation allows up to 20 tool calls per sample to cap inference cost. The main metric is preference alignment: whether the judge assigns a higher score to the revision that Mathlib ultimately accepted. All models perform well above the 50% random baseline. Claude Sonnet 5 is best at 80.8%, while even DeepSeek-V4-Flash reaches 63.5%, with all sign tests reported at p < 1e-5. Among open models, muse-glimmer-30b gets 70.2% and inkling-small 69.3%, showing that the task is not exclusive to frontier closed models. The most useful experimental finding is the variance analysis. Re-running the same judge on the same declarations flips roughly one-fifth to nearly half of the verdicts. Some ablations look non-significant in one replicate, p = 0.34, and significant in another, p = 0.006. That means single-run judge benchmarks can easily overstate differences. The PR 11640 case study is also informative: the initial proof reconstructed a result already present in Mathlib, while the merged revision replaced it with a one-line call to H.restrictPreimage s. The judge found the existing declaration via tool use and consistently penalized the initial version on library leverage.
