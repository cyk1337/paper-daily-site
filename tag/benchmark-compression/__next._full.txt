18:T479,DualViewEval compresses an agent benchmark using two views. The outcome view models redundancy in final task scores across agents. The process view models relations derived from execution trajectories. The authors first examine 12 observable trajectory statistics and retain 6 features that are more reliably extractable and less redundant: agent steps, tool failed rate, tool-category entropy, validation-tool rate, required-write execution, and read-write-validate closure. Benchmark-specific adapters map heterogeneous chat, API, shell, and environment logs into a shared event sequence before feature extraction. The subset is learned with a straight-through hard Top-K gate, so the optimizer always maintains an exact-size miniset. Outcome and process relations from the selected tasks are fused and passed to a Kernel Ridge score predictor. Score error and ranking loss are optimized in one loop, tying task selection directly to full-benchmark score prediction. First, ZipBench evaluates a small set of anchor LLMs on the full benchmark; the paper uses six anchors with separated accuracies. Per-item outcomes are represented as binary responses, with continuous metrics such as F1 discretized before compression. Second, it expands the anchor pool without running more models. It enumerates subsets of the real anchors, treats each subset as a virtual LLM, and defines the virtual response on each item by majority vote. These pseudo logs are accepted through an accuracy-bucket rejection scheme: if a virtual LLM falls into an empty accuracy bucket, it is kept. This makes the anchor pool more uniformly spread over the observed accuracy range, which reduces bias from having anchors only at a few capability levels. Third, ZipBench learns low-dimensional fingerprints for models and items from the augmented response matrix, then selects representative samples through clustering or representative-point selection.
