19:T49e,MoNe attaches a fast-weight neural memory to each decoder layer of a frozen Transformer. The context is split into fixed-size segments, with T=512 in the paper. During the context-reading phase, segments are processed sequentially and each layer updates its own memory through localized gradient updates; backbone weights are never modified. The memory module is a per-head SwiGLU MLP rather than a single linear map, giving it more capacity to store associative structure under a small parameter budget. During generation, the original context tokens are not reread. Query tokens are projected with the frozen Wq, used to read the final fast-weight state, and converted into memory tokens. After RMSNorm and learned head-wise gating, these tokens are projected through the frozen Wk and Wv and concatenated with the query’s normal attention entries. This gives O(N) preprocessing, approximately O(1) query cost with respect to context length, and a KV footprint that does not grow with N. Compared with RAG, it is less tied to locally retrievable chunks. Compared with architectures such as Mamba, TTT, or Titans, it is designed as a plug-in for existing pretrained Transformers.1a:T4ef,pico-type takes raw UTF-8 bytes (0–255) as input, with no tokenization, subword vocabulary, or pretrained embeddings. Its architecture has five stages: a 96-dimensional learnable byte embedding, three Conv1D blocks with kernel sizes 3, 5, and 7 (increasing receptive fields, channel dimension expanded from 96 to 192 after the first block), two bidirectional self-attention blocks with RoPE (base frequency 500,000, 4 heads of dimension 48, standard pre-norm Transformer structure with 4x hidden dimension MLP), a statistical pooling layer that concatenates mean, max, and standard deviation to produce a 576-dimensional pooled vector, and seven Matryoshka-style classification heads. The seven heads predict coarse type (12 classes), modality (8), subtype (24), code language (62), text language (30), MIME type (90), and risk flags (6-class multi-label). Heads are gated: for example, the code language head only contributes loss when the coarse type is code, preventing irrelevant samples from affecting the shared trunk. The Matryoshka tiering supports four model sizes (tiny: 16d, small: 64d, base: 192d, pro: 576d) with 1.43M–1.56M parameters, all produced from a single training run; only the corresponding tier's linear layers are loaded at inference.1b:Ta78,方法核心是一个 exact speculative rollout engine，名字叫 SpecRoll。它由四个部件组成。

第一，proposal family 不是独立 drafter，而是挂在 target backbone hidden state 上的多 horizon future-token heads，形式上接近 MEDUSA。给定前缀 x_{<=t}，target 先精确采样一个 anchor token x_{t+1}，然后多个 head 并行预测后续若干位置的 token，复用 target 的词表投影矩阵 W。这些候选组成一个 prefix-closed sparse tree。这样做的好处是省掉第二个 AR backbone 和对应 KV cache，proposal 成本更低，也减少了 target/drafter 失配来源。

第二，verification 是 exact 的，而且是 concurrency-aware 的。RL rollout 里同时活跃的样本数会随着部分样本提前结束而下降，因此固定大小的 speculative tree 在高并发阶段可能浪费验证算力，在低并发阶段又吃不满硬件。SpecRoll 会根据当前 active concurrency 动态调整 sparse tree 的预算：并发高时保守，减少额外验证负担；并发下降后扩大 tree，换取更高 accepted progress。论文的出发点不是单纯提高单条序列 acceptance，而是优化整个 GRPO rollout 阶段的吞吐。

第三，快路径是 Reflex。它利用“延迟 verifier 反馈在同一轨迹邻近位置上仍有预测性”这一观察，对 proposal hidden state 做 bounded、trajectory-local、gradient-free correction。这里的关键不是学习一个新模型，而是把已经成熟的 verifier error 当作局部校正信号，在不反传的情况下修正后续 proposal。为了避免误修正，作者加了 conservative alignment gate：只有当过去误差对未来仍有可预测性时才启用；同时还有 candidate-boundary safeguard，防止在候选边界附近做有害干预。这个设计试图区分 transient local mismatch 和 persistent drift：前者不值得动参数，局部修一下就够；后者才交给慢路径。

第四，慢路径只在 sustained degradation 被检测到时，才更新 future-token heads 的参数。也就是说，SpecRoll 不把所有失配都转成在线学习问题，而是先用 Reflex 吃掉短期、局部、轨迹内的偏差，把真正跨轨迹持续存在的 proposal 退化留给参数更新。这一点和 FastGRPO 的持续在线训练独立 drafter 不同，后者把适应主要放在参数层，代价更高，也不区分误差类型。

从训练目标上，SpecRoll 始终保持 exact target verification 为最终裁决，因此 committed token 的分布不变，GRPO 的 reward、advantage 和优化目标都不被改写。它优化的是 rollout 生成过程，而不是 RL objective 本身。1c:T96f,SpecRoll is an exact speculative rollout engine built from four main pieces.

First, the proposer is not a separate drafter model. It uses MEDUSA-style future-token heads attached to the target backbone hidden state. Given a prefix, the target model samples an exact anchor token x_{t+1}, and multiple horizon heads predict later positions in parallel, reusing the target vocabulary projection. These candidates form a prefix-closed sparse tree. This removes the need for a second autoregressive backbone and its KV cache, reducing proposal cost and simplifying synchronization.

Second, verification remains exact and is made concurrency-aware. In GRPO, the number of active rollouts changes over time because some responses finish earlier than others. A fixed speculative tree is therefore inefficient: too expensive when concurrency is high, and too small to saturate hardware when concurrency drops. SpecRoll adjusts the sparse-tree budget based on active concurrency, using a smaller budget early and a larger one later. The objective is not just better acceptance on a single sequence, but better throughput for the whole rollout stage.

Third, the fast adaptation path is Reflex. The key observation is that delayed verifier errors can still be predictive for nearby future positions within the same trajectory. Reflex converts such mature verifier feedback into bounded, trajectory-local hidden-state corrections without backpropagation. It is guarded by a conservative alignment gate, which activates only when past errors are predictive of future mismatch, and by candidate-boundary safeguards that suppress harmful interventions near unstable boundaries. The design explicitly separates transient local mismatch from persistent drift.

Fourth, the slow path updates the future-token heads only when sustained degradation is detected. In other words, SpecRoll does not treat every mismatch as an online learning problem. It first uses Reflex to absorb short-lived, local errors, and only escalates recurring cross-trajectory mismatch into parameter updates. This differs from FastGRPO, where adaptation relies more heavily on continuously training a separate drafter.

Throughout the method, exact target verification is authoritative. The committed-token distribution is unchanged, so rewards, advantages, and the GRPO objective remain intact. The method changes rollout efficiency, not the RL objective.1d:T5f5,The evaluation covers five models from 1.5B to 14B parameters and three math reasoning datasets, for 15 matched model-dataset settings. Against vanilla GRPO, SpecRoll reports 1.26x to 2.15x generation speedup and 1.21x to 2.04x end-to-end speedup. A group is aggregated into a single proxy query, which traverses the prefix once and selects a shared candidate set of size c. Then there are two variants. PIVOT-Refine rescoring: each query re-scores only the shared candidate set and picks its own top-k. This changes per-query work from O(L) to O(c), where k < c << L. PIVOT-Reuse is cheaper: it directly reuses the proxy top-k for all queries in the group, skipping per-query refinement. For a group of size g, indexing cost drops from O(gL) to O(L + gc) for Refine or O(L) for Reuse.
