9:T651,The main contribution is a benchmark, SWE-Residual, not a new coding agent. Each benchmark instance pairs the original task request and hidden tests with a Residual State: the final state left by a predecessor agent that declared the task complete even though the hidden tests still fail. The inherited state may include code edits, new files, installed packages, or configuration changes, depending on whether the source task comes from DeepSWE or Terminal-Bench.

The construction has three important design choices. First, the residual state is taken from a predecessor’s submitted final state rather than an arbitrary intermediate checkpoint, making it closer to a realistic handoff. Second, the task request and verifier are unchanged, so the same task can be evaluated from both a clean start and a residual start; the difference isolates starting-state robustness. Third, the residualization pipeline collects and validates such states from multiple predecessor model families, including DeepSeek, Qwen, and GLM, reducing the chance that the benchmark overfits to one model’s characteristic mistakes.

The paper’s main analytical contribution is the notion of acceptance bias. The successor agent tends to treat inherited work as defining what remains to be done, rather than treating it as an object to verify against the original request. In practice, the agent inspects prior edits, often runs tests, and makes limited local changes, but rarely revisits untouched files or challenges the predecessor’s framing of the solution. That is a sharper diagnosis than simply saying the agent is less robust.a:T59b,SWE-Residual contains 198 residual states drawn from 111 tasks based on DeepSWE and Terminal-Bench. The predecessor states come from three model families. A notable detail is that these residual states are often very close to completion: on DeepSWE, the median residual state already passes 98.4% of the hidden tests. So the benchmark is not mainly about recovering from obviously broken environments; it is about detecting subtle missing requirements or incorrect edge-case handling in states that look finished.

Across five frontier coding agents, success drops substantially under residual starts. Relative to clean starts, the drop is 20.6 to 53.5 percentage points on DeepSWE and 20.6 to 34.9 points on Terminal-Bench. On DeepSWE, model rankings even reverse, which is one of the strongest results in the paper because it shows that clean-start leaderboards are not stable proxies for real handoff performance.

The failure analysis is the most informative part. In 58.9% to 88.2% of failed continuations on DeepSWE, exactly the same tests fail at the end as at the beginning of the continuation. That means the agent often does not meaningfully engage with the residual defect, even though the same agent can usually fix those tests from a clean start. 1) Region-inhomogeneous forward dynamics
- Split positions into holes (to be generated) and user-provided context.
- Holes follow standard absorbing corruption over time t.
- Context follows a uniform-mixing corruption kernel at a small per-sequence rate η, which is equivalent to keeping context at a small, fixed “elapsed time” under uniform mixing while holes traverse absorbing dynamics.
- Training remains a masked-diffusion-style weighted cross-entropy denoising objective, but with modified forward marginals.
- Include an η=0 mixture component so the model still trains on perfectly clean conditioning, aiming to prevent degradation on clean inputs.

2) Detect–remask–refill with trust annealing
- Because context is sometimes corrupted during training, the model outputs a meaningful predictive distribution at every position, including the probability of the observed context token—used as a suspicion score.
- During early reverse steps, low-confidence context tokens are re-noised into the absorbing state (remasked) with an annealed intensity, then refilled by the standard reverse dynamics with bidirectional conditioning.
- After a lock time, context is frozen to avoid late-stage instability.
- The paper discusses confidence bookkeeping to compose this with low-confidence decoding.
