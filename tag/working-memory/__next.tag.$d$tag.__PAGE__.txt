Recorder stores real interactions as a unified event stream, keeping both raw events and structured fields such as pre-action observation, executed action, environment feedback, reward or step label, and task metadata. The point is to keep persistent memory neutral and reusable rather than collapsing it early into one fixed summary.

Router is the key learnable component. Instead of directly predicting the next environment action, it first decides how history should be viewed. A view action is defined over several axes: relation type, evidence range, outcome condition, and granularity. In other words, the policy chooses what relational structure to build, how much history to include, whether to filter by success/failure or other outcomes, and how coarse or fine the representation should be. This makes read-time memory representation an explicit decision variable.

Composer then selects events from the event stream and assembles a relational structure according to the chosen view action. Render converts that structure into an optical working-memory view. A frozen task policy consumes the current input together with this temporary view and outputs the next environment action.
