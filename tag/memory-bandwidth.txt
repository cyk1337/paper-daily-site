First, it shows that for batch-1 decode, faster silicon does not automatically translate into proportional latency gains, even when peak HBM bandwidth is much higher. That affects cost-per-token estimates and can influence decisions around model size, context length, GQA design, and quantization strategy. The central metric is the observed-over-floor ratio, R_floor = t_obs / t_floor, where t_floor = (W + K) / B_peak. Here W is the weight traffic per decode step, K is the active KV-cache traffic, and B_peak is peak HBM bandwidth. If batch-1 decode were truly dominated by HBM bandwidth, this ratio should remain relatively stable and fast GPUs should approach the floor more closely. Instead, the ratio drops as peak bandwidth increases, which implies that the bottleneck shifts away from raw memory transfer and toward launch-side overhead.

The key methodological strength is that the paper does not stop at correlation. It runs a falsifiable A/B test with CUDA Graphs, chosen specifically because graph capture reduces launch overhead while leaving the underlying kernels largely unchanged. If H100 short-context decode is launch-bound, graphing should produce a clear speedup; if not, the gain should be small. The result supports the launch-tax interpretation on H100 and gives a near-null result on L4, which is exactly the contrast the mechanism predicts.

The paper compares PyTorch’s default SDPA dispatcher against explicit FlashAttention context, FlashInfer, and FlashAttention-3, and finds that default SDPA is fastest in this regime. First, the gap between the HBM-bandwidth floor and actual latency widens on faster GPUs. The observed-over-floor ratio is about 0.8 on L4 at short context and about 0.25 on H100 at short context. On L4 at the same cell, the gain is only 1.028x. The paper also states explicit falsification thresholds: the launch-tax interpretation would have been undermined if H100 gains were mostly below about 1.15x, or if L4 showed gains above about 1.15x. Neither happened.

Third, the backend-pinned attention comparison on H100 is striking. At the batch-1 single-decode shape, PyTorch’s default SDPA dispatcher runs at 36.05 microseconds per layer, faster than explicit FlashAttention context at 44.35 microseconds, FlashInfer at 48.20 microseconds, and FlashAttention-3 at 79.25 microseconds. So in this regime, swapping to a more specialized attention backend does not solve the main problem and can even hurt.

For Qwen-2.5-7B on L4, bf16 takes 62.32 ms per step, AutoAWQ+Marlin reduces this to 45.24 ms, and GPTQ+ExLlamaV2 reaches 17.36 ms, a 3.59x speedup over bf16. The paper then compares this with H100 plus CUDA Graphs at 11.78 ms per step. The practical implication is that for streaming physical-AI workloads, choosing the right kernel path on cheaper hardware can close more of the latency gap than simply moving to a much more expensive GPU.1d:T6da,This is a skim-level paper, but it rewards a focused read.
