18:T41f,Akashic has two main ideas. The first is MemAttention. Instead of summarizing the entire history at each trigger point, or summarizing each segment independently, it performs chunk-granular memory maintenance. Each new bounded chunk is reconciled with a small set of semantically related prior chunks before being written back to memory. This is meant to keep maintenance cost bounded while recovering evidence that would otherwise be fragmented across independently summarized segments. The second idea is hardware-software co-designed memory placement. The paper argues that memory is not just a semantic object but also a storage object: even if retrieval selects the right chunks, latency remains high if those chunks are physically scattered. Akashic therefore co-locates chunks likely to be co-retrieved and compacts stale data out of place, reducing read amplification and contention under concurrent serving.
