18:T6c6,SCA builds a full pipeline around symbolic verification. First, it formalizes tool-call histories as first-order logic facts using predicates for calls, parameters, and returns. To prevent the SMT solver from inventing unsupported facts, it adds closed-world assumptions: each timestep has a unique call, and past parameters and return values are fixed and complete. Second, it mines candidate constraints from API documentation. An initializer agent focuses on one target API at a time, retrieves related tool definitions, and proposes executable rules covering provenance constraints, temporal dependencies, domain restrictions, and observable-state preconditions. The model outputs both a natural-language description and a corresponding Z3 expression. Third, it refines those rules using execution traces. This matters because documentation alone tends to produce overly strict rules and miss environment-specific dependencies. A refiner agent removes bad rules and adds missing ones based on observed successful and failed interactions. Fourth, it performs runtime intervention. At each tool call, the current history facts and the mined rules are checked with an SMT solver. If the conjunction becomes UNSAT, the current call violates at least one constraint. The system uses an unsat core for approximate attribution and intervenes only when the current call participates in the contradiction. Interventions come in two forms: natural-language warnings that ask the agent to retry, and automatic repair via MaxSMT when a unique valid replacement can be inferred.
