TriRoute: Unified Learned Routing for Joint Adaptive Attention, Experts, and KV-Cache Allocation

这篇论文要解决的是条件计算被“分轴优化”之后留下的结构性浪费。现有做法里，MoE 只管 FFN 稀疏化，MoD 只管跳层，KV-cache quantization 只管注意力记忆压缩。它们都在降低推理成本，但默认这些决策可以独立做。作者认为这是假设错了：一个 token 该不该看全局、该不该走重专家、它写入 cache 时该用几 bit，这三件事在语义上是耦合的。稀有实体词可能 FFN 变换不复杂，却需要高分辨率注意力和高精度 KV；功能词则可能三者都可以降配。核心问题因此是：能否用一个统一路由器，在每层、每 token 上联合决定 attention resolution、expert selection 和 KV precision，并把 FLOPs 与 memory 预算折成一个可控旋钮，而不是分别调三套稀疏超参。

评想法比数字更值得看；只读 controller 设计和预算损失，别被未披露的加速结果牵着走。
Andrii Balashov,Olena Ponomarova

A Dual-Path Architecture for Scaling Compute and Capacity in LLMs

循环（Looped）Transformer通过共享参数重复应用实现了参数高效的算力扩展，但在固定FLOPs下容量（单步可用参数）严格低于基线Transformer；而宽度缩放（宽FFN）则牺牲算力换容量。标准架构将这两个维度混在一起，每个token必须同时支付两者的成本。论文要在单层内独立暴露算力（顺序操作数）和容量（参数）两个缩放轴，让不同token按需分配。

评这篇值得架构组看：它不是又一个小改 attention，而是在 looped transformer 的 capacity 缺口上补了个像样的设计；先看门控分析，若 token 路由真稳定，再考虑内部复现。
Markus Frey,Behzad Shomali,Joachim Koehler,Mehdi Ali

Dynamic sparsity in tree-structured feed-forward layers at scale

Transformer 中 FFN/MLP 块占据主要参数与算力，成为长上下文与大模型训练/推理的瓶颈。现有 MoE 通过动态稀疏降低每 token 计算，但依赖额外路由器、负载均衡损失与复杂系统栈。本文要解决的问题是：能否用“无独立路由器、硬路由、结构化可跳过”的树结构 FF 层（FFF）在 GPT 式自回归语言建模中实现高动态稀疏，并在 1B+ 规模保持与稠密 FFN 相当的效果与可扩展性。

评树状硬路由 FFN 在不引入 MoE 路由器的前提下做到高稀疏还不掉点，直接改变我对“条件计算必需路由器+均衡损失”的 prior，建议立刻做内部 ablation 复现。
Reza Sedghi,Robin Schiewer,Anand Subramoney,David Kappel
