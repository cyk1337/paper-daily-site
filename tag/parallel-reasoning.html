Message Passing Enables Efficient Reasoning

在推理时扩展（inference-time scaling）里，fork-join 这类并行 CoT 往往把线程当一次性“短工”，线程之间缺少细粒度通信，导致重复推理、同步开销高、可扩展性差。论文要解决的是：在不改动底层 LLM、尽量复用现有 batched inference/KV-cache 引擎的前提下，让多线程推理具备类似 MPI 的点对点消息传递能力，从而用更短的总生成量和更低的协调成本完成同等或更强的推理。

评值得看通信与早停消融；它把 test-time scaling 从“多采样”推进到“可训练的并行计算图”。
Xuecheng Liu,Daman Arora,Gokul Swamy,Andrea Zanette

CAPS: Cascaded Adaptive Pairwise Selection for Efficient Parallel Reasoning

CAPS 解决的是 parallel reasoning 中 pairwise verifier 成本过高的问题。生成多个候选解以后，强聚合器通常要做成对比较，但每次比较都读取两份完整推理或代码，单次可能是 4K–8K token，验证成本很快超过生成成本。已有方法主要优化“比较哪些 pair”，很少优化“每个 pair 读多少证据”。

评推理侧并行验证的效率优化方法，仅需阅读方法部分的双轴分配设计和成本推导即可

HeavySkill: Heavy Thinking as the Inner Skill in Agentic Harness

这篇工作要回答的不是“怎样再造一个更复杂的 agent harness”，而是更基础的问题：多代理编排里真正起作用的能力到底是什么。全文给出的结论很明确，关键增益主要来自一种可抽象为“两阶段重思考”的内在技能：先并行生成多条相互独立的推理轨迹，再做一次顺序式综合与裁决。作者把它命名为 Heavy Thinking，并进一步把它从外部 orchestration 还原成模型可调用的 skill。论文关心的核心瓶颈也很具体：单条 CoT 容易早期走偏；best-of-k 只会选，不会整合；复杂 harness 虽然有效，但很难分辨收益来自工具、记忆、角色分工，还是来自更本质的“多轨迹探索+总结”。

评只看实验设置和 BoN/Pass@N 对照；若控制干净，它会削弱“复杂 harness 才是主因”的 prior。
