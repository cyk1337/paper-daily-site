PeekKV: The First Content Token Already Knows Which Heads Matter

这篇工作处理的是长上下文推理里的 KV cache 头级压缩失配问题。已有方法要么先离线给每个 head 做重要性画像，再固定保留；要么在 prefill 阶段根据注意力分布动态分配预算。作者沿全文给出的证据说明，这两类方法都抓错了信号来源：同一个输入里，prefill 阶段活跃的 head 和 decode 阶段真正决定输出的 head 会发生明显切换，尤其切换集中在 prefill→decode 边界以及格式 token 上。相反，一旦进入内容 token 的正常生成区间，活跃 head 组合会相对稳定。于是核心问题变成：能不能用极少的 decode 期在线观测，直接抓到后续生成真正需要的 head，并据此做按 head 的 KV 预算分配与 token 保留。

评值得看的是它对 prefill/decode 头部活跃性错位的诊断，不是方法名本身；先读现象分析和 ablation，若成立，会直接影响你做 KV 压缩时的观测点选择。

The KV-Surgeon: Compensation-Aware Offline KV-Cache Compaction

这篇工作处理的是离线 KV-cache 压缩里最关键、也最容易被简化错的问题：删掉哪些 cache entry，不能只看单个 token 被删后的局部误差，因为注意力的 softmax 归一化会让所有保留下来的项一起变化。已有方法大多把“删除一个条目”的影响当成独立事件来打分，或者先选子集、再做 refit。这样会漏掉两个重要因素：一是删除决策之间存在耦合，二是剩余 value 可以通过补偿更新来吸收一部分误差。论文要解决的，就是如何在可承受的离线成本下，把“删除 + 补偿”联合起来做，而不是分成两个割裂步骤。

评读方法推导和消融即可；softmax 重归一化导致删除耦合，这个 prior 应纳入内部 KV 压缩实验。

TideKV: Delayed KV Eviction via Layer-Wise Chunked Prefill for Memory-Efficient Long-Context LLM Inference

这篇工作处理的是长上下文推理里一个很具体但常被忽略的问题：不是最终保留多少 KV cache，而是 prefill 阶段如何把 KV cache 建出来而不在中途爆显存。现有方法大致分两类。像 SnapKV 这类 post-prefill 压缩方法，要先让整段 prompt 在每一层完整跑完，再做选择，因此构建峰值显存仍然很高；像 KeyDiff 这类在线驱逐方法，虽然更早释放显存，但会在该层尚未看完整个 prompt 时就删 token，导致选择依据带有明显短视性。TideKV 想解决的就是这个 visibility-residency trade-off：既保留“看完整个 prompt 再决定保留谁”的全局可见性，又把 prefill 期间未压缩 KV 的驻留范围压到单层级别，从而把峰值显存降下来。

评prefill 峰值显存常被 KV 压缩论文绕开；这个 layer-major schedule 的设定干净，值得在长上下文 serving 中复现。
