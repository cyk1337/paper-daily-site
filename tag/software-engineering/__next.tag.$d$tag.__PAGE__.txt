9:T579,Two key components.
1) TaskPilot: an online, policy-adaptive task synthesis loop. Starting from real repository snapshots, it generates candidate tasks, runs rollouts with the current checkpoint to estimate learnability, keeps tasks within a target difficulty window (neither unsolved-always nor saturated), and uses policy feedback to adjust tasks toward that window. Training proceeds in iterations: when a checkpoint saturates on validation, it triggers a new synthesis/calibration round, so the task distribution co-evolves with the policy. This differs from offline difficulty filtering over a large static pool.
2) Leaf harness: a simplified Claude-Code-like tool interface designed for compact models. The authors found Qwen3.5-4B frequently fails to terminate under R2E-Gym/SWE-Agent (about 96% trajectories hit the turn limit). Leaf exposes five typed tools (read/write/edit/glob/bash) and uses a natural termination rule (no tool call => terminate), removing brittle “finish action” requirements. During RL, model-generated reasoning/text/tool calls are trained on; prompts and tool outputs stay in context but are masked from loss.
RL setup: DPPO with async rollouts plus a log-length penalty for concise generations; five rounds of (synthesize tasks -> RL). - The key contract is implication: the kernel proves the formal statement entails the certificate statement, so the certificate can only be weaker than what was proved. This makes statement-level human review tractable without trusting the full formal development.
