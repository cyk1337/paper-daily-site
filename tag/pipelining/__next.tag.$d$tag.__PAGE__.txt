9:Tacd,方法核心是把不同 recurrent depth 的 next-token 分布 p_r 看成对最终分布 p_R 的逐步逼近，并在“最终验证尚未完成”时，提前用较浅深度的预测启动后续 token 的计算。具体有三层设计。

第一层是单分支自 speculative。对当前前缀 X，模型在较早深度 r1 产生第一提案 token。系统不等待该 token 走完整个 R 深度，而是立刻把它接到前缀后面，开始计算下一个位置的一部分 recurrent steps。等原始分支到达最终深度 R 后，再按标准 speculative decoding / rejection sampling 规则验证该提案。如果接受，后续 token 已经“预跑”了一段深度，因此能节省延迟；如果拒绝，则回退到已验证前缀。

第二层是论文的关键改进：residual second proposal。作者观察到 Looped Transformer 的更深中间状态通常更接近最终分布，于是在更深深度 r2 再给出第二个提案，并为它启动一条备用 continuation。这样当第一提案被拒绝时，第二提案对应的后续计算不一定作废，可以保留一部分进度。这里不是简单并行两个独立 draft，而是利用 residual distribution 构造第二提案，使其覆盖第一提案未解释的概率质量。文中给出严格的采样与验证规则，保证最终生成分布与目标模型完全一致。

第三层是 gating。双提案虽然能降低重启损失，但也会增加无效计算。作者因此只在深层分布与第一提案不一致时，才创建 fallback speculative continuation。也就是说，第二分支不是总开，而是按中间深度的分歧信号触发。这个设计的目的很直接：在 acceptance rate 已经高的区域，避免为了保险而额外占用算力。

理论部分有两个值得注意的点。其一，作者证明 restart probability 只依赖第二提案深度 r2，而与第一提案深度 r1 无关。直觉上，真正决定“第一条 speculative 路径失败后是否还得完全重启”的，是更深备用提案离最终分布还有多远。其二，作者基于实测的 intermediate-to-target TV distance 随深度呈幂律衰减，推导出最优 proposal depths 的闭式解，并与实验最优点基本吻合。这使得 r1、r2 的选择不再只是经验调参，而有了可解释的深度分配原则。

工程实现上，论文在 SGLang 中实现了 branch-wise KV cache 管理和 CUDA Graph 优化。因为不同分支处在不同 token 位置和不同 recurrent depth，KV 复用与裁剪是系统成败的关键。作者把原始分支和 speculative continuations 组织成可批处理的异步流水线，让共享层在一个 batch 中处理“不同分支、不同深度”的状态，从而提升硬件利用率。a:Tb3e,The method treats the intermediate next-token distributions p_r produced at recurrent depth r as increasingly accurate approximations to the final target distribution p_R. Instead of waiting until depth R is completed for the current token, LoopSpec samples an early draft from a shallower depth and immediately starts partial computation for the next token conditioned on that draft.

The first component is single-branch self-speculation. Given a prefix X, the model produces a first proposal at depth r1. Before the original branch reaches final depth R, the system appends that proposed token and starts computing recurrent steps for the following position. Once the original branch reaches p_R, the proposal is verified using exact speculative decoding / rejection sampling. If accepted, some work for the next token has already been done; if rejected, the computation rolls back to the verified prefix.

The second component is the main algorithmic addition: a residual second proposal from a deeper depth r2. Since deeper recurrent states are typically closer to the final distribution, LoopSpec generates a second proposal and launches an alternative continuation before the first proposal is fully verified. This is not just running two independent drafts. The paper defines the second proposal through a residual distribution construction so that probability mass not covered by the first proposal is handled correctly, while preserving exactness of the final sampling distribution.

The third component is gating. A fallback continuation is only created when the deeper recurrent state disagrees with the first draft. This avoids paying the overhead of a second speculative branch when the first proposal is already likely to be accepted. In other words, the system uses disagreement between intermediate depths as a trigger for extra speculative work.

The theory section is stronger than a typical systems paper. First, the authors prove that the restart probability depends only on the depth of the second proposal, not on the first proposal depth. Intuitively, once the first branch fails, what matters is how close the backup branch is to the final distribution. Second, they empirically observe a power-law decay in the TV distance between intermediate and final distributions, and derive closed-form optimal proposal depths from that decay. The predicted optima match measured best settings well, which gives a principled way to choose r1 and r2.

On the implementation side, the paper integrates LoopSpec into SGLang with branch-wise KV-cache management and CUDA Graph optimization. This matters because different speculative branches sit at different token positions and recurrent depths. The system batches original and speculative continuations together despite their asynchronous progress, which is what turns the algorithm into an actual throughput gain.b:T6a9,The evaluation spans seven checkpoints from two Looped Transformer families and reports end-to-end lossless decoding speedups in a real serving stack. The headline number is up to 6.83× exact speedup, and up to 1.7× faster than the training-based DFlash baseline. That is a meaningful result because it suggests that, for Looped Transformers, exploiting intermediate recurrent states directly can outperform methods that rely on an explicitly trained drafter.

The more informative results are in the ablations. Proposal-depth sweeps show a stable optimum region, and the empirically best depths align with the closed-form predictions derived from the TV-distance decay model. The residual second proposal substantially reduces the penalty of first-proposal rejection, which indicates that it is central to the pipeline’s robustness rather than a minor add-on. The gating mechanism improves the speedup/overhead trade-off by suppressing unnecessary fallback branches when acceptance is already high. System-level optimizations, especially branch-wise KV handling and CUDA Graphs, also contribute materially; without them, the algorithmic gains would not fully translate into wall-clock speed.

A useful empirical takeaway is that LoopSpec’s benefit depends on how quickly intermediate recurrent distributions approach the final one. If shallow depths already have strong token agreement with the final prediction, the pipeline can start useful future work early. If deeper depths converge much faster, the second proposal becomes an effective safety net.
