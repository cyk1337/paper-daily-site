18:Ta58,GQLA 的核心思想是保留 MLA 的 latent KV 压缩框架，但把上投影的索引方式从“按 query head 复制”改成“按 group 建模”，从而让同一组参数支持两条代数等价的解码路径。

先看 MLA 的问题。MLA 训练和 prefill 时可以像 MHA 一样把 latent 展开成 per-head K/V 来算 attention；但在 decoding 时，为了省 cache 和带宽，会把上投影吸收到 query/output projection 里，直接对 latent 做 attention，也就是 absorbed MQA path。这个路径的 arithmetic intensity 在 H100 上接近 roofline，很合适；但它只有这一条路。因为所有 query head 都共享同一个 latent KV，head 维 tensor parallel 很难做零冗余切分；而且一旦做 MTP，额外 query token 会继续抬高算强度，在 H20 这类低 ridge point 设备上几乎没有吞吐收益。

GQLA 的改法很克制。输入 token 先经 W^DKV 压到低秩 latent c_t^{KV}，这一点和 MLA 一样；不同之处在于 W^UK 和 W^UV 不再为每个 query head 单独展开，而是只展开成 g 个 KV groups。这样训练后权重可以有两种解码解释：
1) MQA-absorb path：和 MLA 一样，cache 里存 latent c^{KV} 加共享 RoPE key，所有 query head 直接对 latent 注意力，适合 H100 这类高算力卡；
2) GQA path：把 latent 物化成 per-group 的 K_C, V，并缓存这些 group 级 K/V，再用标准 GQA kernel 解码，适合 H20 这类更容易 compute-bound 的卡。

关键点在于这两条路径对同一组训练参数是代数等价的，不需要重新训练不同模型。论文推荐配置是 h_q=128, g=8，再配一个 MTP head。这个配置下，H100 上单 token decoding 走 MQA-absorb，继续吃到 MLA 的低 cache 优势；H20 上则走 GQA path，并借助更低的 arithmetic intensity 把运行点拉回硬件 ridge 附近，同时支持最多 8 路沿 group 维的零冗余 tensor parallel。

论文还提出 TransGQLA，用于把已有 pretrained GQA checkpoint 转成 GQLA。它是在 TransMLA 的转换流程上做一个很小的修改：head merging 时保留 group 索引，而不是合并到 query-head 级别。作者强调这基本是 one-line change，目的是避免从头预训练。另一个扩展是 sparse attention：由于 GQLA 在 GQA path 下的 query-per-KV-head 比 h_q/g=16，正好匹配 Tensor Core MMA tile，因此稀疏版本在 H20 类硬件上仍能保留 GQA 路径；而 sparse MLA 仍被锁在 sparse MQA-absorb 路径上。

方法上的核心贡献不是新的 attention score 公式，而是参数布局和缓存布局的重新设计，让“同权重多执行路径”成为可能。19:Tb62,The core idea of GQLA is to retain MLA’s latent KV compression while changing how the latent up-projections are indexed. Instead of effectively replicating them across all query heads, GQLA indexes them by groups. This small change allows the same trained parameters to support two algebraically equivalent decoding paths.

To understand the motivation, recall MLA’s behavior. During training and prefill, the latent can be expanded into per-head keys and values and attention is computed in an MHA-like form. During decoding, however, the up-projections are absorbed into the query and output projections so that attention runs directly against the latent, yielding an absorbed MQA-style path. This is excellent for H100 because the arithmetic intensity lands near the hardware roofline. But it is the only path MLA exposes. Since all query heads share one latent KV representation, tensor parallelism along the head axis becomes replication-heavy, and adding MTP further increases arithmetic intensity, which is especially harmful on H20-class devices.

GQLA keeps the same low-rank latent compression step via W^DKV, but changes W^UK and W^UV so that the latent expands into g KV groups rather than per-query-head representations. As a result, the trained weights admit two decode-time interpretations:
1) an MQA-absorb path, identical in spirit to MLA, where the cache stores the latent c^{KV} plus the shared RoPE key and all query heads attend directly to the latent; and
2) a GQA path, where the latent is materialized into per-group K and V tensors and decoding uses a standard GQA kernel.

The key point is that these two paths are algebraically equivalent over the same parameters. No retraining is needed to switch execution mode. The recommended configuration is h_q = 128 and g = 8, plus one MTP head. Under this setup, H100 can continue using the absorbed path and preserve MLA’s cache-efficiency sweet spot, while H20 can switch to the GQA path, lower effective arithmetic intensity, and recover throughput gains from MTP. The GQA path also enables up to 8-way zero-redundancy tensor parallelism along the group axis.

The paper also proposes TransGQLA, a lightweight conversion from a pretrained GQA checkpoint to GQLA. It is described as a minimal modification to the TransMLA pipeline: during head merging, preserve group indexing instead of collapsing everything to query-head indexing. A sparse-attention extension is also discussed. Because GQLA’s GQA path yields a query-per-KV-head ratio of h_q / g = 16, it aligns well with Tensor Core MMA tiling, allowing sparse GQLA to preserve the GQA path on H20-like hardware, unlike sparse MLA which remains locked to sparse absorbed-MQA execution.

The main contribution is therefore not a new attention score formulation, but a parameter and cache layout that preserves multiple hardware-adaptive execution paths for the same model weights.1a:T805,The evaluation has two pillars: roofline analysis and empirical validation. The roofline argument is central. For canonical MLA settings, the paper estimates single-token decoding arithmetic intensity at about 242 FLOPs/byte, close to the H100 BF16 ridge point of roughly 295 FLOPs/byte. That explains why MLA is such a good fit on H100. But H20’s ridge point is only around 37 FLOPs/byte, so the same MLA decode path becomes strongly compute-bound there. GQLA is designed so that the same weights can land on different, more appropriate operating points depending on the hardware.

The paper claims that with the recommended h_q = 128, g = 8 configuration and one MTP head, H100 plus the MQA-absorb path preserves MLA’s favorable operating point, while H20 plus the GQA path at s_q = 2 can approach the hardware ridge and recover near-ideal throughput gains from MTP. The most important outcomes are therefore throughput, arithmetic-intensity matching, and tensor-parallel scalability rather than language-model benchmark gains. The provided text mentions validation on LLaMA-3-8B via TransGQLA, but does not include the full numerical tables, so exact perplexity or throughput numbers cannot be reproduced here.

Still, three conclusions are clear from the available content. First, the two GQLA paths are mathematically equivalent, so path switching should not introduce accuracy drift by itself. Second, on H100-class devices, GQLA does not give up MLA’s main advantage because it can still use the absorbed path. Third, on H20-class devices, switching to the GQA path lowers the effective compute pressure and allows MTP to produce real throughput gains instead of being nullified by compute bottlenecks.
