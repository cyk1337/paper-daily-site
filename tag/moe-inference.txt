18:T67a,MACS is a training-free inference framework with three components.

First, Entropy-Weighted Load replaces raw token counts with an information-aware load estimate. For each visual token, the method computes a Shannon entropy score from the token feature after a softmax transformation, normalizes entropy values within the current image or batch, and maps them to semantic weights through a sigmoid function. The intuition is simple: not all visual patches deserve equal capacity. Background or redundant patches should count less than semantically dense ones. Text tokens are assigned full weight because their semantic density is treated as relatively uniform and high.

Second, Dynamic Modality-Adaptive Capacity adjusts expert capacity according to the current batch-level modality composition. Standard methods use a fixed capacity factor gamma, which is brittle when some tasks are image-heavy and others are text-heavy. MACS makes capacity a function of the actual visual/text mix in the batch, so the budget tracks the current workload instead of a static approximation.

Third, Local Semantic Rerouting handles overflow. When an expert exceeds capacity, the framework first attempts to reroute overflow tokens to semantically nearby experts with spare room; only when rerouting fails does it fall back to a safe token drop. This is a practical design choice: it preserves more useful information than direct dropping, while avoiding the overhead of a more expensive global reassignment.

Relative to prior methods such as CAI-MoE, the key shift is not retraining the router but redefining load and capacity at inference time in a modality-aware way.19:T6e6,The core method is pipelined sharding. Instead of coarse layer-level offloading, the model is partitioned at sub-layer granularity. These shards are then scheduled across GPU and CPU depending on runtime conditions: execution phase, context length of in-flight requests, CPU thread count, PCIe bandwidth, and available VRAM.

The scheduler is benchmark/profile-guided rather than fully online-optimized. It precomputes timing estimates for a set of predefined token tiers, and for each tier selects the best among three candidate execution plans. The plans differ mainly in how aggressively they use PCIe transfers and whether they overlap large tensor movement with compute. Two plans allow movement of large tensors such as weights or KV cache and try to hide transfer cost behind concurrent CPU/GPU work. The third plan minimizes large PCIe traffic and restricts transfers mostly to small activations, which is preferable when bandwidth is tight or transfer overlap is not worthwhile.

A few design choices matter. It is not limited to single-request decode; it explicitly supports mixed batches where requests may be in different phases. VRAM budget is treated as a first-class runtime constraint. The abstraction also extends to MoE models, which suggests the scheduler is not overfit to dense transformers.

For VLMs, the paper combines pipelined sharding with three engineering optimizations, grouped as VLMOpt: offloading vision tensors to CPU, enabling flash attention in the vision encoder, and avoiding overlapping VRAM allocation peaks between the vision and language parts. These are not algorithmically new, but they are important because they reduce the vision-side memory peak enough to make high-resolution VLM inference feasible on client hardware.1a:T558,From the full text excerpt, the evaluation spans dense LLMs, MoE LLMs, and high-resolution VLMs, and compares TTFT and TPS across different VRAM budgets, CPU thread counts, and CPU-GPU interconnect conditions. The paper is explicit that the goal is lossless inference, so the comparison focus is hybrid scheduling and offloading strategies rather than lossy quantization baselines.

The main empirical claim is that pipelined sharding is more robust than any single fixed strategy because it switches plans based on token tier and execution phase.
