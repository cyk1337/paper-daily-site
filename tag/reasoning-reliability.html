Cliff Tokens: Identifying Single-Token Failure Triggers in LLM Mathematical Reasoning

这篇工作要解决的不是“模型为什么会做错数学题”这种宽泛问题，而是更细的一层：在一条已经展开的推理轨迹里，究竟是哪一个具体 token 把轨迹从“仍可修复”推到“后续大概率失败”。已有分析大多停在 step、chunk、sentence 粒度，或者只标记已经掉到零成功率之后的位置，因而抓不到真正的触发点。作者提出 cliff token，用 rollout 估计每个位置的 token-wise potential，也就是“从当前前缀继续采样，最终答对的概率”，再用带方差校正的一侧 two-proportion z-test 判断某个 token 是否造成了显著下跌。核心问题因此被形式化为：如何在高噪声 rollout 估计下，可靠地定位单 token 级别的 failure trigger，并区分不同类型的触发机制。

评单个token即可触发数学推理失败的发现颠覆传统认知，做LLM预训练数据/训练目标/解码策略的研究员应立刻复现核心实验并纳入内部 ablation。

Prefix-Safe Bayesian Belief Tracking for LLM Reasoning Reliability:Separating Calibration from Ranking

长推理链生成时，需要在“答案尚未生成/尚未知对错”的前提下，对当前前缀是否仍可能最终成功给出在线概率估计，即估计 P(y=1 | o_{1:t})，并且观测必须满足 prefix-safe（不能偷看未来 token 或最终答案）。论文要解决的是：在统一的在线更新框架下，如何把不同类型的前缀证据（标量分数、文本标记、自验证、hidden cluster、probe、轨迹特征）做校准并递推融合，同时区分“概率质量（calibration/Brier）”与“排序能力（AUROC）”这两类经常被混在一起的目标。

评看 calibration-vs-ranking 的结果即可；对做 verifier 或 RLVR 过滤的人，比方法包装更有用。

Pause and Reflect: Conformal Aggregation for Chain-of-Thought Reasoning

自一致 CoT 把推理变成“多条推理路径的聚合”问题：即使采样到了正确路径，错误路径也可能在多数投票里占上风，导致系统高置信地答错。论文要解决的是聚合层面的不确定性：给定一池 CoT 路径及其质量分数，如何在推断时决定“答/不答”，并对“答了但错”的概率给出有限样本保证。

评读校准公式和 score separability 部分；它不增强模型能力，但给 CoT 多采样的错误风险一个可审计接口。

Confidence-Aware Alignment Makes Reasoning LLMs More Reliable

这篇工作针对的是 reasoning LLM 里一个常见但经常被最终答案准确率掩盖的问题：模型可能通过错误的中间推理步骤得到正确答案，也就是 final-answer correctness 和 process reliability 脱节。现有方法要么在轨迹级别做偏好优化，要么依赖外部 verifier、树搜索和大规模采样来筛选推理路径，代价高，而且没有真正解决“模型自己的置信度为什么不能代表逻辑可靠性”这个问题。文章要处理的是：如何把 token/step-level confidence 校准到逻辑正确性上，让模型内部概率分布能更可信地反映推理步骤质量，并进一步在推理时用这个信号做低开销分支裁剪。

评将置信度校准与DPO结合做推理对齐，无需单独RM是值得注意的方向；§3.2的token置信度与步骤正确性对齐机制值得参考，可在内部RL pipeline中尝试。
