Is 2:4 Sparsity Still Worth It? Semi-Structured Sparsity versus Quantization in LLM Inference

这篇文章回答的是一个很具体、但在 LLM 推理压缩里一直没有被讲透的问题：在 NVIDIA 支持 2:4 半结构化稀疏的前提下，从某个已有精度出发，下一步到底应该加 2:4 sparsity，还是直接降到更低 bit 的稠密量化？作者认为过去很多比较都不公平，因为没有把稀疏元数据算进存储成本，也没有把在线 pruning/quantization 的运行时开销算进去，更没有按硬件真实允许的稀疏轴来比较。全文的核心结论很明确：只要硬件上还有更低的 dense precision 可用，继续降精度通常比加 2:4 更划算，既更准，也更快；2:4 真正有价值的场景主要出现在已经到达 quantization floor 之后。

评把“稀疏 vs 降比特”用等 bits（含 metadata）+跨代 kernel 实测讲清了；部署决策直接照结论改，重点看误差随 bits 的对比图表。

这篇工作讨论的是 replicated LLM inference 里共享 host-memory KV cache 的两个基础问题：第一，跨副本复用 prefix state 是否真的正确；第二，即便正确，它相对“把同一会话尽量留在原 GPU 上”到底还有多少性能空间。作者不是在提出新的缓存算法，而是在拆解一个部署中很容易被忽略的事实：cache hit、HTTP 200、甚至命中 token 数都不能证明跨副本状态传输是正确的，错误的异步拷贝顺序会让系统看起来命中了 cache，实际却在用损坏的 KV 继续生成。

评关于vLLM跨副本KV Cache共享的硬核工程踩坑记录，对关注Serving系统和长上下文推理优化的研究员有参考价值。
Frank Li

Composable CXL Memory as a Kubernetes-Native Shared Memory for LLM Serving

在Kubernetes集群里把“可组合CXL共享内存”做成可调度资源，并把它接入LLM serving的KV-cache分层，使不同节点上的推理副本能复用同一段物理共享内存中的前缀KV，从而实现跨节点prefix cache命中并显著降低TTFT。

评只看系统路径和延迟分解；CXL 不是训练侧答案，但它改变了 prefix-heavy serving 的缓存边界。
