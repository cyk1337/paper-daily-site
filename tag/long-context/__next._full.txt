18:T5e9,No new architecture is proposed; instead the paper builds an analysis model. Data is assumed to arrive in groups (tasks), each task being generated by a sparse set of latent factors. Tasks share factors, and task similarity is modeled via latent-factor overlap (illustrated as a bipartite task–factor graph). Under this view, inference-time learning is modeled as: shared components are carried by internal representations of inputs/outputs, while the task-specific mapping between these representations must be learned at inference time by an inner learner.
From this setup, the paper argues for:
- Rich representation (“gather broadly”): if representations only capture what is minimally sufficient for iid generalization, many new tasks become unreachable; open-world adaptation needs a broader feature basis that supports recombination of latent factors.
- Predictive disentanglement (“group predictively”): beyond richness, representations should be partitioned into matched low-dimensional groups across inputs and outputs, and prediction should occur within aligned groups. This reduces the effective degrees of freedom the inner learner must fit for a new task, improving sample efficiency.
It further predicts: (1) inference-time learning requires a consistent inner learner; otherwise adding more related-task examples in context can degrade performance; (2) longer contexts can help only if the target task and related tasks are handled separately to avoid harmful coupling/negative transfer.19:T60f,The stage trains at 256K context for hundreds of billions of tokens on top of converged Nemotron base models. The mixture is dominated by natural software-engineering data: packed repositories, merged pull requests, commit histories, and build logs. Synthetic agent traces are kept to a bounded 10–15% share and rendered in the Nemotron chat template. Tool responses are masked from the loss, because environment outputs should condition the model but should not be imitated. Natural engineering data is kept in its original format rather than converted into chat, which preserves repository and log distributions. The data pipeline applies permissive-license filtering, decontamination against SWE-bench and Terminal-Bench, secret redaction, and loss masking for spans such as repeated delimiters, hashes, and timestamps. A large pull-request corpus is built from public GitHub repositories with at least ten stars in supported languages. Each example can include repository metadata, date, file tree, code context, PR description, linked issues, review discussion, and patch evolution. The filtering removes unavailable repositories, missing Git objects, failed patch reconstruction, empty or oversized changes, generated content, and other low-quality patches. The resulting corpus contains 12.1 million PRs and between 200B and 2T tokens depending on the amount of repository context included. Issue-linked examples are additionally checked by a structured LLM judge for issue-patch consistency, while PR-only examples use deterministic filters.1a:T41e,The recipe is developed on Nemotron 3.5 Lightning-30B-A3B and scaled to Nemotron 3.5 Super-120B-A12B. On Lightning, 500B midtraining tokens followed by the same full SFT improve SWE-bench Verified by 3.8 points, SWE-bench Multilingual by 7.0 points, and SWE-bench Pro by 3.5 points over the no-midtraining control. The multilingual gains are reported as the most sustained. On Super, 280B midtraining tokens followed by identical full SFT improve DeepSWE from 11.7 to 15.7 and SWE-bench Verified from 72.9 to 74.3. The harness robustness result is also important: after 65B tokens and short SFT on Super, the model improves under every tested harness, with average gains of 8.6 points on SWE-bench Verified and 6.8 points on Terminal-Bench. The ablations examine the value of a small agent-trace share, learning rate, pretraining-data replay, tool-response masking, and effects on long-context ability. The key empirical pattern is that a small amount of agentic traces helps on top of natural data, but the stage should not become a long SFT substitute.1b:T6a9,The design has a single-GPU part and a distributed part. On a single GPU, FlashMask-3 builds on the column-wise sparse representation from FlashMask. The mask is indexed by key position, while each key stores query-axis intervals through four boundary vectors, commonly denoted LTS, LTE, UTS, and UTE for lower- and upper-triangular regions. This avoids constructing an n by n mask and gives the kernel a compact representation of valid query-key tiles. The new kernel integrates this representation into FlashAttention-3’s Hopper execution model. It uses three-role warp specialization: a KV Index Generator scans the boundary vectors and produces the relevant tile or KV indices, a KV Loader issues asynchronous TMA loads, and MMA Consumers run WGMMA compute. Mask handling is moved out of the main compute loop into a producer-like stage, which reduces branch overhead and keeps the asynchronous pipeline full. A preemptive persistent-tile scheduler is added to reduce SM-level imbalance under irregular sparse masks. For distributed context parallelism, the key observation is that the mask is keyed by K positions but stores Q-axis intervals. Under any multi-chunk CP assignment, a rank-local mask can be obtained by elementwise clipping, shifting, and max operations over the boundary vectors. No cross-rank mask exchange is needed, and the resulting local representation can be passed to the same kernel. The distributed system then adds a sparsity-aware hierarchical load balancer, HCC-IPO, topology-aware hierarchical routing for forward all-gather, mask-driven communication pruning, and a backward reduce-scatter path overlapped with attention recomputation using bitmask-AMO synchronization.1c:T4ca,The evaluation covers microbenchmarks, context-parallel scaling, and end-to-end training. On a single H100, across 12 structured masks and sequence lengths from 4K to 128K, FlashMask-3 improves achieved TFLOPs over FlashMask by 45% to 141%, over FlexAttention by 34% to 71%, and over MagiAttention by 2% to 44%. These gains indicate that the improvement is not only from compact mask representation, but also from aligning mask-aware scheduling with Hopper’s TMA/WGMMA pipeline. In distributed context-parallel experiments with CP degrees from 4 to 32 and 8K tokens per device, it reaches 31% to 75% compute-communication overlap efficiency. Throughput improves by 1.80× to 3.71× over Megatron-Core CP ring, by 1.71× to 2.92× over Megatron-Core CP all-gather, and by 1.09× to 1.46× over MagiAttention. This immediately reduces both KV cache and attention compute, but it also removes a large amount of head diversity. VHA restores that diversity through two lightweight linear modules.

The first is Q Premix. Within each KV group, Premix applies a near-identity linear transformation to the reduced set of physical query heads, effectively expanding them into a richer set of virtual query heads. The near-identity design is important. It keeps the model close to a stable GQA-2 parameterization early in training, while allowing the network to gradually learn structured specialization among heads that share the same KV pair. The authors’ matrix inspection suggests that this is exactly what happens: Premix learns group-conditioned query specialization rather than arbitrary mixing.

The second is Linear Postmix. Even with better within-group query diversity, using only 2 KV heads still limits cross-group interaction. Postmix therefore applies a low-rank identity-residual transformation, I + AB^T, to the attention output. The rank is small, for example r = Hq'/2 and r = 4 at the 1.7B scale. This gives the model a cheap way to fuse information across heads and groups after attention, without increasing head dimension or introducing nonlinear runtime structure. The paper interprets this as structured low-rank cross-head communication.

A major engineering advantage is that both modules are purely linear. Premix can be folded into the query projection matrix WQ, and Postmix into the output projection WO at inference time. After folding, the deployed model is just a standard GQA-2 model. This means VHA inherits existing inference kernels and serving optimizations from frameworks such as vLLM and SGLang with zero additional runtime overhead.

Relative to prior methods, the distinctions are clean. Compared with standard GQA, VHA adds learnable compensation before and after shared-KV attention.
