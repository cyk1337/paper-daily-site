18:T515,For each output position, the model runs an internal decision process over a hidden state h, a fast-weight memory M, and a counter of Think steps. The latent policy chooses among Think, Recall, and Exit. Think applies a shared Transformer block again, increasing effective depth without adding new block parameters, and writes the resulting state into memory. Recall reads from the same memory and injects the retrieved representation into the current hidden state. Exit stops the inner loop and emits the next token through the language-model head. This differs from external-memory agents, where memory is usually read back as text or context, and from looped latent-reasoning models, where the loop has no native memory read action. The training method, Counterfactual Policy Distillation, branches every allowed action for one step at each latent state, including Exit, and scores the branch by the change in the gold token log-probability. The resulting cost-charged, signed gain supervises the action policy. In addition, recall improvements on positive-advantage trajectories are differentiated through the fast-weight memory, assigning credit to earlier Think writes. This is important because a memory system must learn both what to retrieve and what to store before retrieval becomes useful.19:T4e1,The approach starts by decomposing the RoPE attention score into frequency channels while allowing unequal query-key scales across channels. High-frequency components rotate rapidly with relative distance. They support fine positional changes, but they also introduce fluctuations that can reverse semantic preferences. Low-frequency components preserve smoother content preferences, but they change too little under a one-token shift and can weaken adjacent-position discrimination. The theory turns these two effects into measurable criteria: semantic reversal and positional insensitivity. Under calibrated windows and margin assumptions, it also derives a context-length bound Mmax beyond which a fixed attention margin cannot avoid both failures simultaneously. The empirical tool, RoPE Profiler, reuses cached query/key activations during evaluation and reports two metrics: Semantic Score for preference stability and Positional Score for adjacent-position sensitivity. The proposed interventions are training-free: rescale high-frequency components or freeze their rotations to reduce position-induced fluctuations. For every token, a learned router selects the top-K heads out of H total heads. Routing has two roles: it activates the selected head parameters, and it assigns tokens to the corresponding head-specific subsequences. Each head then performs causal attention only within its own routed subsequence. Sparsity is therefore native to the architecture, rather than being imposed by masking a dense attention computation. A load-balancing objective is used to avoid head collapse and to keep token assignments roughly uniform. With sequence length L, total KV entries are about LK. Under balanced routing, each head stores around LK/H entries, and a query accessing K active heads reads about LK^2/H KV entries. Relative to a K-head full-attention baseline with matched active attention parameters, the KV activation ratio is about K/H. Relative to an H-head full-attention baseline with matched total attention parameters, it is about (K/H)^2. For H=32 and K=8, total KV storage is one quarter of 32-head full attention and equal to 8-head full attention; each active query reads around 2L KV entries, giving activation ratios of 1/16 versus 32-head full attention and 1/4 versus 8-head full attention. The paper also introduces head-relative RoPE, where positions are encoded within each head’s routed subsequence rather than by global token index. This shortens the effective positional span to roughly LK/H while preserving order, aiming to reduce long-RoPE attention noise. Implementation-wise, training and prefill use packed variable-length FlashAttention over head-specific subsequences, while decoding only runs active heads and only reads or updates their KV caches. The design is described as compatible with GQA and with additional token- or block-level sparse attention inside each routed subsequence.1c:T857,The system, Galahad, has two separable components. Taliesin stores and restores the KV state produced by prefilling a block of text. Blaise stores the text itself in sectioned form and selects a relevant section on the CPU so the model reads only that section rather than the full corpus. Taliesin removes repeated computation; Blaise removes unnecessary reading.

Taliesin is built around byte-exact memory. After a runtime computes KV state for a prompt block, the system stores that state under a fingerprint defined by the exact input bytes, the model fingerprint, and the tenant identity. If a later request contains the same byte block, the runtime loads the saved KV state instead of recomputing it. The design goal is exactness: restored state must yield bit-identical logits to a fresh prefill. To enforce this, the system validates stored records on load and falls back to normal computation on any failure. The guiding rule is explicit: serve without memory rather than serve with wrong memory.
