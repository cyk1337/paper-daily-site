1b:T4b5,The analysis starts by decomposing each FFN expert into hidden channels. Each channel has an up-projection key, which controls activation, and a down-projection value, which determines the output direction. In a sparsely upcycled MoE, experts are initialized from the same pretrained FFN, so the same channel index remains comparable across experts. The authors use this to measure whether co-activated experts write similar value directions at aligned positions. They find that co-activated experts are partially aligned rather than fully redundant; removing aligned positions changes the preferred experts; and tokens with larger shared coverage need fewer residual experts to reconstruct the original output. UniF-MoE implements this principle with one shared expert and K residual experts per layer, all divided into aligned blocks. A token-level router first estimates shared demand, then selects shared blocks through key prototypes, routes only complementary blocks to residual experts, and uses cumulative routing mass to decide how many residual experts to activate. A Gram constraint shapes router embeddings into normalized and distinct directions, encouraging specialization with less overlap.1c:T4da,Two main organizing devices:
1) Unified formalization: MoE as a sparse combination of expert functions where routing selects an expert set K_t per token. The survey highlights the dual objective—grow total capacity while bounding per-token active compute—while noting practical deviations (shared experts, attention/embedding overhead, heterogeneous widths).
2) Four control planes forming a closed loop:
- Expert Topology: expert granularity and structural choices (incl. shared paths), slow-changing.
- Routing: token-level discrete decisions (top-k, routing freedom, visibility constraints).
- Balance: windowed load statistics n_i and feedback knobs (router bias, auxiliary loss strength, capacity), plus non-loss mechanisms like runtime replication and expert placement.
- Expert Parallelism (EP): mapping experts to devices and scheduling communication/compute (all-to-all, fan-out, kernel shapes), which constrains feasible routing.
It also proposes eight “milestones” organized as a dependency graph, with criteria: introduce an independently tunable variable, shift the dominant bottleneck, and be inherited by later systems. The survey explicitly avoids capability-number causal comparisons across papers due to confounders.1d:T4c5,The controlled comparisons include Dense BLT, Hidden-only MoE, Hidden+Entropy MoE, and EntropyMoE, with matched data, updates, active parameters, and dense-copy initialization. The sparse setup uses 25 layers, 8 experts per layer, and Top-2 routing. The entropy-only router has about 400 effective routing parameters, compared with more than 4×10^5 parameters for hidden-state routing controls. EntropyMoE obtains the lowest held-out bits per byte, while the hidden-state MoE variants stay close to the dense baseline despite having the same expert pool and active capacity. The advantage over Hidden-only MoE is reproduced with a second continuation-training seed. Downstream accuracy is broadly similar; the clearest supported gain is on HellaSwag rather than a uniform task-level improvement. Byte-weighted accounting improves BPB over patch-count accounting in both tested seeds. Routing analysis shows clearer separation between low- and high-entropy patch assignments, but also concentration on a small subset of experts. Among sparse variants it has the best iteration time and valid-byte throughput, although sparse execution remains slower than Dense BLT because of dispatch, communication, and memory movement.1e:T417,UMoE has three stages. First, it prunes low-saliency experts using target-domain calibration data. The default score is REAP saliency, which combines the magnitude of an expert’s MLP output with its normalized router gate, averaged only over tokens where that expert is selected by top-K routing; unselected experts receive zero score. The method keeps the top half of experts per layer. This is different from routing-frequency pruning, because frequent routing does not necessarily imply strong contribution to the target-domain computation. Second, it regrows the expert pool through perturbation-based expansion from the retained experts, restoring the original number of experts. Third, it applies standard domain SFT. The final model keeps the same number of experts E, active experts K, parameter count, and inference cost. Compared with direct SFT, it explicitly reallocates expert slots; compared with permanent pruning, it preserves capacity; compared with generic upcycling, its expansion source is selected by target-domain saliency.1f:T773,TriRoute 的核心是一个共享 controller。对每个 layer、每个 token，它同时输出三类决策。第一是 attention mode，候选包括 skip、local-window、full，决定该 token 在当前层使用多少注意力分辨率。第二是 FFN expert routing，在 E 个专家中选稀疏子集，并引入一个 null expert，把 MoD 式的 FFN skip 视为专家选择的特例，而不是额外分支。第三是 KV bit-width，决定该 token 自己写入 cache 时用 2/4/8/16 bit 中哪一档，从而影响未来 token 检索它时的保真度。这个设计的关键不是把三件事并排放在一起，而是共享同一份 token 表征，让路由器学到“什么 token 值得在哪些资源上花钱”。

训练上有三块技术处理。其一，三类决策的离散空间异质性很强：expert routing 是大类别稀疏选择，attention mode 和 bit-width 是小规模但代价差异很不均匀的分类。作者采用按轴定制的 straight-through / Gumbel-Softmax 松弛，并做温度退火，尽量让梯度尺度可比。其二，作者强调 cross-axis collapse cascade：如果 attention router 先学会大面积 skip，下游 FFN router 看到的输入分布会退化，进一步失去区分能力，bit router 也会变得无意义。为此论文设计了 coupling-aware balancing objective，不只做单轴 load balancing，而是抑制一个轴塌缩后拖垮其他轴。其三，预算控制采用统一可微 cost model，把 FLOPs 和 KV memory 合成单一成本，再用在线 Lagrangian dual 调节，使目标平均预算 C* 成为唯一外部旋钮。这样用户不需要分别调 expert sparsity、depth sparsity 和 quantization ratio。论文还探索 shared vs separate routers，以及 token/per-head/per-layer-group 的路由粒度，最后发现 attention 用 per-head routing，而 FFN 与 bit routing 用 token-level，是较好的折中。20:T71b,TriRoute uses a shared controller that emits three coordinated decisions for every token at every layer. First, it chooses an attention mode: skip, local-window, or full. Second, it performs sparse FFN expert routing over E experts, with a null expert that recovers MoD-style FFN skipping as a special case. Third, it selects the bit-width used when the token writes its own key/value to the cache, choosing among 2, 4, 8, and 16 bits. The key idea is not just to place three routers side by side, but to let them share token representations so the model can learn which tokens deserve which kinds of resources.

Training this system is nontrivial because the routing spaces are heterogeneous. Expert routing is a large sparse categorical problem, while attention mode and bit-width are small categorical choices with highly uneven sensitivities. The paper uses per-axis straight-through / Gumbel-Softmax relaxations with temperature annealing to keep gradients usable. A second technical issue is cross-axis collapse. The authors argue, and empirically show, that collapse in one axis can induce collapse in the others: if attention routing becomes overly skip-heavy, the FFN router sees degraded inputs and loses discrimination, which then makes bit allocation less meaningful. To address this, they introduce a coupling-aware balancing objective rather than relying only on standard single-axis load balancing. Third, they define a unified differentiable cost model that combines FLOPs and KV memory, and enforce a target average budget with an online Lagrangian controller. This gives a single external budget knob.
