18:T427,FreeBalance performs pre-routing online balancing through residual workload prediction. The key observation is that the input to an MoE router can be approximated well enough from the residual representation produced by the preceding layer. So, before the current router executes, the system feeds that residual into the corresponding router to obtain a lightweight prediction of the upcoming expert workload. This prediction is used only for scheduling, not for model execution. Based on the predicted load, FreeBalance adjusts expert-device mapping and starts expert-weight migration immediately, overlapping migration with pre-routing computation stages, especially attention. To avoid over-migration, the method includes a cost model that limits how many experts can be moved given the available overlap window. In other words, it does constrained balancing rather than chasing the most even load at any cost. Actual MoE execution still uses the original router outputs, so the model’s outputs remain unchanged; the gain comes purely from better scheduling.19:T542,The method has three parts. First, the authors build a black-box calibrated cost model for the deployed expert kernel. Per-expert latency is modeled with a two-regime structure: a fixed activation floor for instantiating an expert replica, plus a token-dependent term that becomes relevant beyond an inflection point. They also explicitly model grouped-GEMM M-tile padding, which explains why splitting one expert across multiple replicas can create extra work instead of merely redistributing it. Second, they formulate per-batch dispatch as a fixed-charge makespan minimization problem over routed tokens and replica placements. The paper proves the problem is already NP-hard in a small setting, while showing that prior token-balancing and activation-balancing methods emerge as degenerate limits when certain terms vanish. This is a clean unification of earlier heuristics. Third, they propose tempo_fast, a practical near-optimal solver. It uses cost-aware seeding, augmenting-chain activation rebalancing for the flat regime, bottleneck-focused local search with partial migrations for the linear regime, and an ensemble that scores candidate solutions such as token-LP and round-robin under the same calibrated model. The fitted activation floor b ranges from 1.74 microseconds to 14.8 microseconds depending on expert shape, an 8.5x spread, with mean fit error around 4–8%. In real decode traces, 92–100% of batches contain both regimes simultaneously: a few hot experts carry roughly 91% of tokens, while many activated experts still sit in the flat regime. 1) Kernel Decomposition: Breaks the sequential constraint of traditional BSP by partitioning on-accelerator AIV compute units into independent task groups that run in parallel (e.g., most AIVs handle token sending, while a smaller group handles token count computation and prefix sums). Disaggregated component placement: Attention layers and MoE FFN layers are assigned to separate worker groups. Attention groups replicate dense components and split data by micro-batch, while FFN groups shard experts and process tokens according to routing results. First, Entropy-Weighted Load replaces raw token counts with an information-aware load estimate. For each visual token, the method computes a Shannon entropy score from the token feature after a softmax transformation, normalizes entropy values within the current image or batch, and maps them to semantic weights through a sigmoid function. The intuition is simple: not all visual patches deserve equal capacity. Background or redundant patches should count less than semantically dense ones. Text tokens are assigned full weight because their semantic density is treated as relatively uniform and high.

Second, Dynamic Modality-Adaptive Capacity adjusts expert capacity according to the current batch-level modality composition. Standard methods use a fixed capacity factor gamma, which is brittle when some tasks are image-heavy and others are text-heavy. MACS makes capacity a function of the actual visual/text mix in the batch, so the budget tracks the current workload instead of a static approximation.

Third, Local Semantic Rerouting handles overflow. When an expert exceeds capacity, the framework first attempts to reroute overflow tokens to semantically nearby experts with spare room; only when rerouting fails does it fall back to a safe token drop. This is a practical design choice: it preserves more useful information than direct dropping, while avoiding the overhead of a more expensive global reassignment.
