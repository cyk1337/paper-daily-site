9:T64b,BOSS is a training-free online policy rather than a new model. The main contribution is the budget-faithful decision framework. Each model call incurs prompt-plus-completion token cost. Generation calls use a cap L_gen, judge calls use L_judge, and before every call the policy checks worst-case feasibility against the remaining budget. This guarantees that no adaptive trajectory can exceed the hard per-instance cap. That accounting detail is central, because many prior systems either ignore selection overhead or count only completion tokens while omitting the repeated prompt cost of judge calls.

After each generated candidate, BOSS chooses among three actions: return, generate again, or adjudicate. The decision uses three ingredients. First, consensus-based termination stops early when the observed answers are already stable enough. Second, a novelty-based switch detects when additional sampling is no longer producing meaningfully new answer hypotheses, at which point the marginal value of generation drops. Third, budget-feasible pairwise judging spends the remaining budget on answer-level comparisons among candidate representatives.

The paper appears to avoid expensive full ranking over all traces. Instead, it relies on answer grouping, representative selection, and repeated randomized judging to approximate a good final choice under budget. A particularly strong design choice is the identical-candidate-pool control: the authors hold Stage-I candidates fixed and vary only the selector, which isolates the contribution of adjudication and allocation from candidate-generation quality.a:T5be,The experiments cover two Llama-3.1 model sizes and four reasoning benchmarks. Under the common hard-cap setting, BOSS achieves the best accuracy in 22 of 24 model-task-budget cells. One representative result reported in the paper is at Llama-3.1-8B with a 4k-token budget: a development-tuned fixed generation-selection split reaches 59.3 macro average, BOSS reaches 60.5, and removing the novelty-triggered switch drops performance to 59.0. That suggests the online transition from generation to adjudication is a real source of gain rather than a minor heuristic.

The strongest evidence comes from the same-candidate-pool experiment. Using exactly the same Stage-I candidate pools, changing only the selector raises macro accuracy from 58.4 to 60.3 with randomized repeated judging, and to 60.5 with the full BOSS selector. This is important because it shows the improvement is not merely due to better candidate generation. Selection and allocation contribute independently.

The paper also reports comparisons against Adaptive-Consistency and TALE-EP under the same strict token ledger, realized-token analyses rather than nominal-budget-only reporting, transition statistics, hyperparameter sensitivity, and paired per-instance tests. Even from the visible full-text portion, the experimental design is clearly aimed at causal isolation: the authors try to separate the value of online allocation from stopping rules, candidate quality, and hidden token overhead.b:T6e6,The core method is residual-guided non-parametric optimization. The system starts from a fixed base verifier and iteratively improves it around observed mistakes. At each round, the current verifier is replayed on a construction pool, and disagreements with labels are collected as residuals. Recurring residual patterns are then abstracted into rule cards. Each card records a missing verifier bias together with support examples, counterexamples, applicability conditions, and abstention conditions. This is a key design choice: instead of directly updating model parameters, the method converts recurring failure modes into explicit knowledge units.

A rule card can follow one of two promotion paths. If the missing bias can be expressed as deterministic comparison logic—such as numerical tolerance handling, unit normalization, scientific notation conversion, or specific symbolic equivalence rules—it goes through code audit and replay validation, and if accepted becomes a code module. A code module is a deterministic verifier unit that returns Correct, Incorrect, or Abstain. If the bias cannot be fully codified and still requires model judgment, it is incorporated into the fallback verifier prompt rather than compiled into code. At inference time, the system first runs the module library; cases that can be decided explicitly are handled there, and only unresolved cases are sent to a fixed model-based fallback verifier.

What distinguishes this from prior work is not simply adding tools, but turning verifier improvement into a closed loop: residual discovery, rule-card drafting, replay validation, and promotion into either executable modules or prompt guidance. It sits between hand-maintained rule libraries and opaque judge-model behavior.c:T545,The paper evaluates on four reference-based verification benchmarks. The headline result is 93.05% macro accuracy, outperforming the reported rule-based, model-based, scientific, and tool-augmented baselines included in the study. The more informative result is the component ablation: compared with a prompt-only setting, adding code modules yields an additional +1.76 macro-accuracy gain. That suggests the benefit is not merely better prompting; explicit comparison logic is covering verifier blind spots that prompting alone does not fix. In addition, direct module decisions reduce fallback model calls by 32.13%, so the system improves both accuracy and inference efficiency.

The experiments are most convincing when read as evidence for two claims. First, recurring residuals do contain reusable verifier biases that can be extracted. Second, splitting those biases into deterministic modules versus prompt-level guidance works better than relying on a single prompt-only or model-only verifier. A careful reader should still pay attention to the relationship between the construction pool and the evaluation benchmarks: if they are too similar, rule extraction becomes easier.
