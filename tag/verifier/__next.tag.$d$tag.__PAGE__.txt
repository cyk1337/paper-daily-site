9:T80b,DecisionPivot 是一个诊断型 benchmark，而不是新模型。它的设计有几个关键点。

1. 两条评测轨。core track 是作者生成的受控任务，共 7,800 个样本，来自 13 个 task family，按 contrast group 组织。reference track 是 35 个公开测试集，共 32,233 个样本，保留原始评测协议和已知训练重叠信息。前者强调可控诊断，后者强调和既有工作可比。
2. typed decision interface。每个样本都写成 state、typed question、finite option set 的统一形式，模型输出对各选项的概率分布。这样 routing、guardrail、verification、goal checking 等不同角色可以放在同一接口下比较。
3. 七类 decision role。覆盖从 answerability / routing，到 policy guardrail、output verification、agent loop 中的 tool validation / goal checking，再到 reasoning-based classification、record reconciliation、constraint-based matching。作者想表达的是：LLM 系统里“决策”无处不在，而且这些决策共享一套概率输出与阈值控制问题。
4. contrast-group 设计。core track 的关键创新在这里。多数 task family 通过只改一个 pivotal detail 来改变正确答案，同时尽量保持上下文和表面形式不变。这样可以测模型是否真的抓住决定性变量，而不是靠模板、长度、词面线索做猜测。
5. 独立求解器验证。core 样本答案由独立实现的 solver 计算并验证，减少人工标注噪声，也降低 benchmark 本身出错的风险。
6. 评测指标不只看 accuracy。作者同时看 item accuracy、pair accuracy（更一般地说是 contrast-group 全对率）、probability ordering、calibration、selective coverage。这里 pair accuracy 很关键，因为它要求一个对比组里的所有变体都答对，能直接暴露“只会答一半”的脆弱性。

方法上的价值不在模型算法，而在评测协议：它把 decision quality 拆成 correctness、consistency、confidence reliability 三层，而不是混成一个总分。a:T7d1,DecisionPivot is a benchmark and evaluation protocol rather than a new model. Its design has several notable elements.

1. Two-track structure. The core track contains 7,800 generated items from 13 task families, organized into contrast groups for controlled diagnosis. The reference track contains 32,233 items from 35 public test sets, preserving original metrics and available overlap information. The first track gives control; the second gives comparability.
2. Typed decision interface. Every item is represented as a state, a typed question, and a finite option set. Models output a probability distribution over options. This allows routing, guardrails, output verification, and goal checking to be evaluated under a common interface.
3. Seven decision roles. The benchmark spans answerability and routing, policy guardrails, output verification, tool validation or goal checking in agent loops, reasoning-based classification, record reconciliation, and constraint-based search or matching.
4. Contrast-group construction. This is the core methodological contribution. In most generated families, a pivotal detail is changed while surrounding context remains largely fixed. The correct answer changes accordingly. This tests whether the model is sensitive to the actual decision variable rather than exploiting surface patterns.
5. Independent solver verification. Core answers are computed and checked by independently implemented solvers, reducing annotation noise and benchmark errors.
6. Multi-faceted metrics. The evaluation includes item accuracy, pair accuracy or full contrast-group correctness, probability ordering, calibration, and selective coverage. Pair accuracy is especially useful because it requires all members of a contrast group to be correct, exposing brittle behavior that average accuracy can hide.

The main contribution is therefore an evaluation decomposition of decision quality into correctness, consistency under controlled variation, and confidence reliability.b:T62c,The empirical study is fairly broad. The benchmark is used to evaluate 40 decision models and 14 general models, including 11 open general models and 3 API chat models on the core track. Several findings stand out.

1. Similar scores on public reference sets do not imply similar controlled decision behavior. The paper highlights cases such as Perplexity Decider and JEV-27B, which look similar on the reference track but differ substantially in core pair accuracy.
2. Similar item accuracy does not imply similar confidence quality. Kev 27B and JEV-27B reportedly have nearly identical item accuracy but differ in how often they make high-confidence predictions and how often those predictions are correct.
3. Correct probability ordering is not the same as correct decisions. The binary contrast analysis shows that a model may rank options in a roughly sensible way yet still fail to produce the correct argmax consistently.
4. Reasoning settings help on some cases but do not uniformly fix decision failures. This matters because it shows that the problem is not simply solved by adding more chain-of-thought.
5. Freshly sampled cases from the generators are used to test ranking stability, which is a good safeguard against benchmark-specific overfitting.

First, it evaluates rationale quality as certificate quality. A generated rationale is parsed into a directed acyclic graph of atomic claims and dependencies. Each claim is associated with a claim type, an evaluation criterion, polarity, and support relations. The certificate is then audited along three dimensions. Soundness checks whether claims are supported by the candidate responses and whether the rationale introduces false evidence or invalid comparisons. Coverage checks whether the rationale addresses the decision-relevant criteria specified by the evaluation policy rather than cherry-picking a few convenient points. Decision Support checks whether the local assessments made in the rationale are consistent with the final verdict, penalizing cases where the rationale argues for A but concludes B. Second, DeCert converts these audits into preference supervision. If two sampled judgments differ in verdict correctness, correctness dominates. If they share the same correct verdict, the model constructs rationale preference pairs based on certificate quality. This is the key design choice: it isolates rationale quality while holding outcome correctness fixed. Training then combines outcome-level and rationale-level preference optimization. Relative to RationaleRM, R-Align, and RM-NLHF, the main difference is that supervision is reference-free and based on validity of support rather than similarity to a target explanation. Third, the positional-bias result is notable: without swap-based augmentation or explicit position-consistency supervision, DeCert improves position-consistent accuracy by up to 14.8 points over the corresponding base judges. P(success) = P(at least one correct candidate exists) × P(it is selected | it exists),
and explicitly models the second term (selection), not just coverage.

Section 3 derives exact success formulas for two selectors widely used:
1) Uniform selection among verifier-accepted candidates.
2) Argmax selection by verifier score.

The formulas incorporate verifier true/false accept rates and three correlation sources observed in practice:
- Heterogeneous task difficulty (per-task solve rates vary widely).
- Shared blind spots across generators, modeled via a Gaussian copula.
- Correlated repeated verifier calls for the same candidate, modeled via a candidate-level acceptance propensity.

Section 4 estimates these ingredients from a small labeled pilot using empirical Bayes, including variants where verifier accuracy depends on task difficulty (to avoid biased pooling).

A planner then searches over configurations—generator choices, sample counts, verifier calls, thresholds—under a cost budget to maximize predicted success. The paper also provides a regret guarantee tied to differential (not absolute) forecast error (Proposition 4), explaining why approximate calibration can still yield near-optimal allocations.

First, a parser maps each natural-language step into an operation plus a canonical payload under a task-specific schema. The schema defines entities, predicates, allowed operations, initial state, and goal. The operation set contains seven labels: Derive, Assume, Verify, Prune, Confirm, Restate, and Meta. The payload is wording-invariant, so semantically equivalent statements map to the same atom. The parser is implemented with Qwen3.8-27B and uses the current step, local labeled context, and prior schema elements. Second, a deterministic engine replays the parsed operations and incrementally builds a reasoning-state tree. It resolves each step to the node it depends on and applies the corresponding mutation. Because this stage is deterministic, the same parse always yields the same tree and labels. Third, failures are defined as predicates over the current step, the resolved node, and the prior tree state. This lets the three broad failure modes—repetition, underthinking, and unsupported deduction—be refined into subtypes tied to concrete earlier states. Those local methods recover only a small fraction of the failures flagged by ARBOR, and many of their positives are ordinary reasoning steps. ARBOR’s subtype counts also separate correct from incorrect trajectories better than all local signals combined. Second, failure subtypes differ in cost. Unsupported deductions are most damaging to final correctness because later verification rarely catches them; underthinking mainly wastes search budget and tokens, since the model often still reaches the answer by another path or by returning later; repetition has the smallest effect on correctness and relatively limited extra token cost. Features such as branch content, whether a node has been verified, and recent operation history are predictive of subtype occurrence, while operation labels alone only recover a subset of that signal.
