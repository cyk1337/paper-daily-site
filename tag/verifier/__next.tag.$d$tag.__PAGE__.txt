9:T43e,The method is simple, and that is part of its strength. The task is formulated as three-way step classification: pos for correct and useful, neu for valid but redundant, and neg for logically or computationally incorrect. For each supervised step, the model takes the hidden state at the step-end token and feeds it into a linear classification head. The only substantive change between the two variants is the self-attention mask. In the causal version, a step representation can only depend on the problem, previous steps, and the current step. In the bidirectional version, it can also use later steps in the same completed solution. Training uses cross-entropy over supervised step-end positions. To isolate the effect of attention direction, the authors run 54 controlled comparisons at 1B to 3B scale, keeping architecture, data, and optimization fixed while changing only the mask. They then scale the same design to LLaDA-8B-Base, yielding LLaDA-PRM. The key idea is not a sophisticated verifier head, but letting each step representation encode downstream consistency evidence.a:T594,VideoGen-Agent uses a shared multimodal policy in a reasoning-action-observation loop. At each step, the policy conditions on the prompt, previous actions, and tool observations, then selects a tool and specifies its arguments. The six task categories are Procedural Knowledge, Single-Entity Identity, Multi-Entity Identity, Physics Simulation, Compositional Scene, and Multi-Shot. Each category has a default tool subset and workflow: procedural prompts use text retrieval for steps and motion details; identity prompts use visual retrieval and image-conditioned or multi-reference generation; physics prompts invoke simulators and pass motion conditions to a motion-conditioned generator; compositional prompts generate candidates and use verification tools such as detection and depth estimation for regeneration; multi-shot prompts generate phases sequentially and use the last frame of each segment to preserve continuity. Training has two stages. First, the policy is supervised on teacher-distilled tool-use trajectories, with the paper mentioning Claude Opus 4.7 as part of the trajectory construction process. Second, the policy is optimized with multitask agentic RL. A hybrid reward scores both tool use and generated video quality, while task advantage normalization balances learning signals across the six categories. A common tool interface allows backend tools to be replaced without changing the agent workflow.b:T40d,The proposed Compute-Value Audit decomposes test-time scaling into four ordered gates: opportunity, state confidence, action value, and entry fee. Opportunity asks whether better samples exist in the fixed pool. State asks whether observable signals are informative. Action asks whether using those signals improves the target metric. Entry fee accounts for the full cost of generation and verification. The audit fixes the complete candidate budget and requires selectors to score the same pool, avoiding hidden generation or unfair cache reuse. The paper also introduces a Verifier-Quality Law using a minimal Gaussian model, showing that recovered headroom is directly governed by the correlation between verifier score and target quality. Tested deployable signals include Proprio, a one-step flow residual under controlled latent perturbations; cycle energy, which re-noises a latent and integrates it back to measure consistency; and PM, a memory-based reranker that uses legal history without updating the world model or verifier.c:T7a7,The pipeline has four components. First is data curation. The authors collect 22,000 problems from 16 regional and international competition families plus online platforms, package them into executable evaluation environments, and explicitly exclude and deduplicate evaluation problems. They then use DeepSeek-V4-Flash to generate large synthetic reasoning-trace corpora: about 1.2M traces for the Nano model and 477,642 for the larger model. The key point is not just scale, but the organization of problems, reasoning, code, and feedback into long-context supervised examples.

Second is supervised fine-tuning. They start from Nemotron-3-Nano-30B-A3B and Nemotron-3-Ultra-550B-A55B and perform long-context SFT to obtain competition-specialized models. Nano is a 30B-parameter MoE with 3B active parameters; Ultra is 550B with 55B active. The supervision appears to target not only final code generation but also intermediate problem-solving traces.

Third is reinforcement learning. RL is applied to Nano-CC, with rewards derived from executable evaluation, namely whether the generated program passes tests and how much score it obtains. This reward is attractive because it is automatic and closely aligned with the task objective. The downside is that it may favor search-friendly behaviors rather than robust one-shot generalization. The paper places RL after SFT, which is sensible: the action space in competitive programming is too large for pure RL to be stable without a strong initial policy.

Fourth is GenCorrect, the test-time closed-loop strategy. It is more than self-consistency. The system generates diverse candidate solutions, evaluates them, uses the feedback to refine later attempts, and operates under a limited submission budget. This is essentially verifier-guided search plus iterative program repair. It is especially well matched to IOI-style settings, where multiple submissions and partial credit are part of the environment.d:T704,The main results are straightforward. On IOI 2025, Nemotron-3-Nano-CC improves from 130 Score@1 at baseline to 280 after SFT and 291 after RL. So SFT provides the dominant gain, while RL adds a smaller but real improvement. With five rounds of GenCorrect, the score rises to 468, above the gold threshold of 438.3. The size of that jump makes it clear that test-time search is a major contributor, arguably larger than RL in this setup.

Nemotron-3-Ultra-CC does not use code-specific RL. It reaches 304 with SFT alone, and 502.0 after five GenCorrect rounds. This suggests two things: larger base models still benefit from domain-specific SFT on hard coding tasks, and a strong base model plus strong inference-time search may be a more efficient path than a smaller model with additional RL.

The authors then build a competition-specific system for IOI 2026 and evaluate it live, before public release of the problems, under matched time, internet, and submission constraints. The system scores 535.4/600, above the gold threshold of 361.12 and above the top official human score of 498.27. As a research result, this should be interpreted carefully. It reflects a full specialized system, including task-specific adaptation and inference strategy, not just the intrinsic capability of the underlying model.

The most useful ablation insight is the gain decomposition. Synthetic data plus long-context SFT establish the main capability step. RL further aligns the model to executable objectives. GenCorrect then amplifies final benchmark performance when the environment allows iterative feedback. If one only looks at Score@1, the model improvement is much smaller than the final competition score, which is exactly why the distinction between parameter updates and test-time compute matters.e:T53b,This is a skim paper. In localization, the system decomposes coarse benchmark steps into finer EdgeUnits using a proof-state-tree representation. Each transition in this tree corresponds to a local reasoning responsibility, which makes the evaluation target much sharper than judging an entire paragraph-like step. In verification, the method extracts typed proof obligations from suspicious transitions. These obligations are not treated uniformly; they encode different kinds of reasoning responsibilities such as algebraic transformation, implication transfer, existence construction, boundary-condition handling, or case transitions. The system then gathers evidence through both lightweight checks and Lean-based validation. Lean is used as a structured evidence source rather than a direct judge. A key safeguard is the semantic alignment score, which measures whether the formalized statement preserves the assumptions, directionality, quantification, and strength of the original informal obligation. Lean evidence is only trusted when this alignment is high enough, preventing drifted or weakened targets from producing false reassurance. In synthesis, local evidence is aggregated back to the original step level to predict the first erroneous benchmark step. The main novelty is the full pipeline: decomposition into local transitions, typed obligations, formal checking gated by semantic alignment, and evidence aggregation for first-error localization.10:T506,The paper introduces two expert-verified datasets: ProofLoc-Olympiad with 350 algebra and number theory problems, and ProofLoc-University with 200 advanced mathematics problems. On ProofLoc-Olympiad, FaithSieve reaches 81.43% exact first-error accuracy, compared with 72.29% for a GPT-5.4 direct-judging baseline, an absolute gain of 9.14 points. The provided text also states that FaithSieve shows clear gains on ProofLoc-University, although the exact number is not visible in the excerpt. The evaluation follows the standard first-error localization setup, reporting both binary accuracy and exact accuracy, with the latter requiring the correct first-error index. The experimental story is important because it tests whether local formal evidence, when filtered for semantic faithfulness, actually improves early-error localization. The likely key ablations are removing EdgeUnit decomposition, which should make local flaws harder to isolate; removing semantic alignment gating, which should increase false positives from target drift; and relying only on natural-language judging, which should weaken precise localization. Together these results support a narrow but important claim: formal verification helps only when the verified target is both local and semantically faithful.11:T6e6,The core method is residual-guided non-parametric optimization. The system starts from a fixed base verifier and iteratively improves it around observed mistakes. At each round, the current verifier is replayed on a construction pool, and disagreements with labels are collected as residuals. Recurring residual patterns are then abstracted into rule cards. Each card records a missing verifier bias together with support examples, counterexamples, applicability conditions, and abstention conditions. This is a key design choice: instead of directly updating model parameters, the method converts recurring failure modes into explicit knowledge units.

A rule card can follow one of two promotion paths. If the missing bias can be expressed as deterministic comparison logic—such as numerical tolerance handling, unit normalization, scientific notation conversion, or specific symbolic equivalence rules—it goes through code audit and replay validation, and if accepted becomes a code module. A code module is a deterministic verifier unit that returns Correct, Incorrect, or Abstain. If the bias cannot be fully codified and still requires model judgment, it is incorporated into the fallback verifier prompt rather than compiled into code. At inference time, the system first runs the module library; cases that can be decided explicitly are handled there, and only unresolved cases are sent to a fixed model-based fallback verifier.

What distinguishes this from prior work is not simply adding tools, but turning verifier improvement into a closed loop: residual discovery, rule-card drafting, replay validation, and promotion into either executable modules or prompt guidance. It sits between hand-maintained rule libraries and opaque judge-model behavior.12:T545,The paper evaluates on four reference-based verification benchmarks. That suggests the benefit is not merely better prompting; explicit comparison logic is covering verifier blind spots that prompting alone does not fix. The experiments are most convincing when read as evidence for two claims. First, recurring residuals do contain reusable verifier biases that can be extracted.
