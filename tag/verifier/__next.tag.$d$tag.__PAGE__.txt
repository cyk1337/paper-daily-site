The audit may adaptively choose questions, extend answer paths, query correctness labels, and stop when it can return a simultaneous confidence band with half-width ε and failure probability δ. The analysis counts three resources: generated answers, correctness queries, and question visits. For a fixed list, the main cost law for certifying all budgets up to K is, up to logarithmic factors, K/ε + min(M, ε^{-2}) + s/ε^2. The three terms correspond to rare high-scoring answers at large budgets, the identity of the benchmark questions, and within-question variance accumulated along the curve. Matching lower bounds show that these terms are intrinsic. A key technical device is a coupling of nested winners on one answer path, which lets a single path serve all budgets. The practical algorithm is a paired audit: each round draws two fresh paths per question, uses an exponential inequality for paired Bernoulli draws to build anytime-valid simultaneous bands, and then applies a corrected exact-binomial final look to stop at a fixed round. Each transition in this tree corresponds to a local reasoning responsibility, which makes the evaluation target much sharper than judging an entire paragraph-like step. In verification, the method extracts typed proof obligations from suspicious transitions. These obligations are not treated uniformly; they encode different kinds of reasoning responsibilities such as algebraic transformation, implication transfer, existence construction, boundary-condition handling, or case transitions. The system starts from a fixed base verifier and iteratively improves it around observed mistakes. At each round, the current verifier is replayed on a construction pool, and disagreements with labels are collected as residuals. Recurring residual patterns are then abstracted into rule cards. Each card records a missing verifier bias together with support examples, counterexamples, applicability conditions, and abstention conditions. This is a key design choice: instead of directly updating model parameters, the method converts recurring failure modes into explicit knowledge units.

A rule card can follow one of two promotion paths. If the missing bias can be expressed as deterministic comparison logic—such as numerical tolerance handling, unit normalization, scientific notation conversion, or specific symbolic equivalence rules—it goes through code audit and replay validation, and if accepted becomes a code module. A code module is a deterministic verifier unit that returns Correct, Incorrect, or Abstain. If the bias cannot be fully codified and still requires model judgment, it is incorporated into the fallback verifier prompt rather than compiled into code. At inference time, the system first runs the module library; cases that can be decided explicitly are handled there, and only unresolved cases are sent to a fixed model-based fallback verifier.

What distinguishes this from prior work is not simply adding tools, but turning verifier improvement into a closed loop: residual discovery, rule-card drafting, replay validation, and promotion into either executable modules or prompt guidance. It sits between hand-maintained rule libraries and opaque judge-model behavior.17:T545,The paper evaluates on four reference-based verification benchmarks.
