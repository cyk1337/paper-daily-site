b:T713,The core method is a fixed-pool diagnostic called OracleGap. For each input, a model first produces a fixed set of candidates, with the first sample treated as the reference baseline. A collaboration mechanism is then allowed only to select from that pool; it cannot repair an answer or generate a new one. This separation is deliberate. It isolates selection from repair, so gains are not conflated with the ability to create better candidates.

Within this setup, the paper defines an any-of-k oracle: if any candidate in the pool is correct under the official evaluator, the oracle succeeds. The difference between this oracle and the reference baseline is the oracle gap, which serves as an absolute upper bound for any fixed-pool selector. The realized gain is then decomposed into recoverable mass, signal coverage, conditional selection quality, and harm. Recoverable mass measures how often the baseline is wrong while at least one correct candidate exists in the pool. Coverage measures how often the mechanism produces usable evidence. Conditional quality measures how often the mechanism picks a correct candidate on recoverable examples where a signal exists. Harm measures how often the mechanism turns an already-correct baseline into an incorrect answer.

A particularly useful part of the paper is its direct measurement of verifier fidelity at the candidate level, by comparing verifier judgments against official labels. This separates poor verification from poor candidate generation. The framework is then applied to LLM selectors, generated-test verifiers, public-test verifiers, symbolic answer-equivalence selectors, and related mechanisms. The main message is that collaboration gains are constrained first by oracle gap and then by signal fidelity, not by agent count or topology alone.c:T686,The experiments cover LiveCodeBench, MATH Level-5 hard subjects, GPQA-Diamond, and HumanEval+ as a near-saturated code anchor. The paper emphasizes three-seed evaluation and hierarchical confidence intervals, which makes the comparisons more credible than single-run score reporting.

The most important findings are straightforward. On LiveCodeBench, a public-test verifier captures much more of the oracle gap because its candidate-level fidelity is high. A generated-test verifier has much lower fidelity, so even with near-zero harm its net gain is limited. This is an important distinction: low harm is not enough if the verifier cannot reliably identify correct candidates.

On MATH, a symbolic answer-equivalence selector outperforms ordinary self-consistency, while natural-language LLM selectors can be net negative. The reason is structural. Math tasks often provide normalized or symbolically checkable final answers, so a structured signal is more reliable than free-form language judgment.

On GPQA-Diamond, the candidate pool has only a 3.03 percentage-point oracle gap and high answer homogeneity. In that regime, LLM selectors are net negative. This is a useful boundary case because it shows that some tasks simply do not contain enough recoverable mass for fixed-pool collaboration to matter.

HumanEval+ serves as a code-side anchor where execution signals are strong and the task is closer to saturation, highlighting how selector behavior differs when high-fidelity external evaluation is available.

The practical rule is simple: estimate oracle gap first. If the pool contains little recoverable value, more collaboration mostly adds harm or cost.d:T506,Read this one with a diagnostic mindset. The universe is a countable set of strings U. An instance is a pair H⊆F⊆U, both infinite. F is the ambient formal language, accessible through a membership oracle; H is the hidden valuable language. At round t, the generator observes the current literature prefix S_t, may query the oracle for F, and must output a fresh string not already in S_t. Outputs fall into three categories: valuable, trivial, or hallucinated. Performance is measured in the limit by coverage of H, using lower-density style notions, rather than finite-horizon accuracy.

The first main result, Theorem 3.1, is the key conceptual one: for exact or approximate breadth, the oracle does not improve what families are learnably generable beyond the oracle-free case. The characterization remains fiber-wise and is governed by Angluin-style tell-tale conditions. In plain terms, the verifier can identify the ambient formal shell F, but it cannot distinguish among candidate valuable sublanguages H that live inside the same F. Taste must come from examples, not from the checker.

The second main result, Theorem 3.2, shows what the verifier does buy: sound coverage. The oracle can eliminate hallucinations by ensuring outputs stay inside F while still pursuing coverage of unseen valuable statements. But this only removes one failure mode. It does not solve triviality.

The later results establish the paper’s strongest impossibility claim: any generator that achieves broad coverage of unseen valuable mathematics must emit infinitely many trivial statements. The trivia rate can become asymptotically negligible, but the total amount cannot be finite. That is the “flood and harvest” trade-off in the title.
