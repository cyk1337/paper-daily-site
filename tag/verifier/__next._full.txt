18:T8b3,方法是一个“多钥门控 + LoRA 增量更新 + 可回滚”的持续学习框架。
- 学习载体：冻结 base 参数 θ0，仅训练 LoRA adapter。流式 claims 以 chunk 到达；每个 chunk 先筛选可学样本，再用“新样本 + 过去接受过的 replay”训练一个候选 adapter，最后通过统计回归测试决定 commit 或 rollback（图 1 的流程）。
- Key 1（surprise key）：用当前模型对 claim 目标 token 的平均 NLL（nats/token）作为 surprise sθ(c)。超过阈值 τ=1.0 才进入候选集，意图是只学“模型预测不好的新信息”。
- Key 2（verifier key）：外部 judge 对每个 distinct claim 判真/假（有时附带“可信来源句子”）。这是最直接的抗投毒手段，但成本高且上限由 judge 质量决定。
- Key 3（regression test + rollback）：训练候选 adapter 后，在一套“无关旧知识回归集”上测量相对 θ0 的退化（论文用 preference margin 的损失变化来度量），按批次 b=25 评估，若退化超过阈值则回滚本次更新。核心假设是“坏更新会伤到旧知识”。论文发现对定点事实谎言，这个假设不成立。
- Key 4（prior-conflict key，免 judge）：用 base 模型 θ0 的贪心答案 ŷ 与 claim 的对数似然差（gap）衡量“与原始信念冲突程度”。gap 大的 claim 被 hold back 而不是直接学。作者强调必须用 θ0 而不是当前 adapter 来算 gap：用当前 adapter 会因近期学习导致过度自信，误拦大量真 claim（pilot 中拦了 46% 真 claim）。
- evidence route（证据通路）：针对 prior-conflict key 拦下的样本，如果存在“可信来源句子”，则走证据核验以恢复合法更新；但该机制依赖 trusted-source 假设，若来源可被植入则失效。
整体上，论文的创新点不在新优化器或新目标，而在把“在线事实更新”拆成四类互补信号，并用受控数据把每个信号的能力边界测出来：surprise 负责新颖性但会偏爱谎言；prior-conflict 负责矛盾检测但不等于真假；regression test 负责全局退化但对局部投毒不敏感；verifier 负责真假但成本高且受 judge 质量限制。19:T709,The system freezes the base model θ0 and performs streaming updates via a LoRA adapter, with commit-or-rollback at each chunk.
- Streaming protocol: claims arrive in chunks; each claim must pass active “keys” (gates). Accepted claims plus replayed previously accepted claims train a candidate adapter. A post-update test decides whether to commit or roll back.
- Surprise key: compute mean token NLL sθ(c) on the claim target; learn only if sθ(c) exceeds a threshold (τ=1.0 nats/token), intended to capture novelty.
- Verifier key: an external judge labels each distinct claim true/false (optionally with a trusted source sentence). This directly targets truth but adds cost and inherits judge errors.
- Regression test + rollback: after training the candidate adapter, evaluate a regression suite on unrelated prior knowledge using a margin-based loss change relative to θ0; if degradation exceeds a threshold, roll back. The paper finds this is largely insensitive to targeted factual lies.
- Prior-conflict key (judge-free): measure a contradiction “gap” between the likelihood of the claim and the base model’s greedy answer ŷ under θ0. Large gaps are held back for review. A key engineering detail is computing the gap under θ0 rather than the current adapter; otherwise the adapter’s recency-induced overconfidence blocks many true claims.
- Evidence route: for claims blocked by prior-conflict, allow recovery if corroborated by a trusted source sentence; this works only under a trusted-source assumption and fails if sources can be planted.
The novelty is the explicit multi-signal gating design and the controlled analysis showing these signals are not interchangeable: novelty ≠ truth, contradiction ≠ falsehood, and collateral-damage tests miss localized poisoning.1a:T567,Setup: LoRA-adapted Qwen2.5-1.5B/3B and Llama-3.2-3B learn from a mixed stream of true and false claims.

方法上的价值不在模型算法，而在评测协议：它把 decision quality 拆成 correctness、consistency、confidence reliability 三层，而不是混成一个总分。1c:T7d1,DecisionPivot is a benchmark and evaluation protocol rather than a new model. Its design has several notable elements.

1. Two-track structure. The core track contains 7,800 generated items from 13 task families, organized into contrast groups for controlled diagnosis. The reference track contains 32,233 items from 35 public test sets, preserving original metrics and available overlap information. The first track gives control; the second gives comparability.
2. Typed decision interface. Every item is represented as a state, a typed question, and a finite option set. Models output a probability distribution over options. This allows routing, guardrails, output verification, and goal checking to be evaluated under a common interface.
3. Seven decision roles. The benchmark spans answerability and routing, policy guardrails, output verification, tool validation or goal checking in agent loops, reasoning-based classification, record reconciliation, and constraint-based search or matching.
4. Contrast-group construction. This is the core methodological contribution. In most generated families, a pivotal detail is changed while surrounding context remains largely fixed. The correct answer changes accordingly. This tests whether the model is sensitive to the actual decision variable rather than exploiting surface patterns.
5. Independent solver verification. Core answers are computed and checked by independently implemented solvers, reducing annotation noise and benchmark errors.
6. Multi-faceted metrics. The evaluation includes item accuracy, pair accuracy or full contrast-group correctness, probability ordering, calibration, and selective coverage. Pair accuracy is especially useful because it requires all members of a contrast group to be correct, exposing brittle behavior that average accuracy can hide.

The main contribution is therefore an evaluation decomposition of decision quality into correctness, consistency under controlled variation, and confidence reliability.1d:T62c,The empirical study is fairly broad. The benchmark is used to evaluate 40 decision models and 14 general models, including 11 open general models and 3 API chat models on the core track. Several findings stand out.

1. Similar scores on public reference sets do not imply similar controlled decision behavior. The paper highlights cases such as Perplexity Decider and JEV-27B, which look similar on the reference track but differ substantially in core pair accuracy.
2. Similar item accuracy does not imply similar confidence quality. Kev 27B and JEV-27B reportedly have nearly identical item accuracy but differ in how often they make high-confidence predictions and how often those predictions are correct.
3. Correct probability ordering is not the same as correct decisions. The binary contrast analysis shows that a model may rank options in a roughly sensible way yet still fail to produce the correct argmax consistently.
4. Reasoning settings help on some cases but do not uniformly fix decision failures. This matters because it shows that the problem is not simply solved by adding more chain-of-thought.
5. Freshly sampled cases from the generators are used to test ranking stability, which is a good safeguard against benchmark-specific overfitting.

First, it evaluates rationale quality as certificate quality. A generated rationale is parsed into a directed acyclic graph of atomic claims and dependencies. Each claim is associated with a claim type, an evaluation criterion, polarity, and support relations. The certificate is then audited along three dimensions. Soundness checks whether claims are supported by the candidate responses and whether the rationale introduces false evidence or invalid comparisons. Coverage checks whether the rationale addresses the decision-relevant criteria specified by the evaluation policy rather than cherry-picking a few convenient points. Decision Support checks whether the local assessments made in the rationale are consistent with the final verdict, penalizing cases where the rationale argues for A but concludes B. Second, DeCert converts these audits into preference supervision. If two sampled judgments differ in verdict correctness, correctness dominates. If they share the same correct verdict, the model constructs rationale preference pairs based on certificate quality. - Heterogeneous task difficulty (per-task solve rates vary widely).
- Shared blind spots across generators, modeled via a Gaussian copula.
- Correlated repeated verifier calls for the same candidate, modeled via a candidate-level acceptance propensity.

The payload is wording-invariant, so semantically equivalent statements map to the same atom. The parser is implemented with Qwen3.8-27B and uses the current step, local labeled context, and prior schema elements. Because this stage is deterministic, the same parse always yields the same tree and labels.
