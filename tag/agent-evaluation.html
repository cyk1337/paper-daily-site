这篇工作要解决的不是“模型能不能把任务做对”，而是“模型能不能持续改进承载任务执行的 agent harness”。这里的 harness 指可执行的外层脚手架：提示、工具调用流程、状态管理、错误恢复、子任务编排、代码逻辑等。难点在于，现有 agent benchmark 往往把基础模型能力、任务难度、harness 设计混在一起，导致你很难判断分数提升究竟来自更强的 base model，还是来自更好的 harness。作者把问题拆成三个必须同时满足的条件：任务要对 harness 改动敏感，而不是被底模能力主导；验证集和测试集要在这种“敏感性”上分布一致，避免在验证集上过拟合；评测过程要允许多轮、长时程的代码级迭代，而不是单轮 prompt search。

评harness自主进化是agent能力的新维度，对研究长程agent能力演化有参考，只看 §2 的benchmark构建逻辑即可。

The Replay Gap: Static Evaluation of Model Switching in LLM Agents Scores the Wrong World

多步 LLM agent 中的逐步骤模型路由（per-step model switching / routing）几乎都用重放日志轨迹的方式离线评测，但 agent 是闭环系统，替换某一步的模型会改变后续状态和动作，这种 replay evaluator 是否可信一直缺乏定量测量。

评分支 rollout 把“换模型不影响后续轨迹”的假设钉死了；做 agent/router 评测的人该读方法，别只看摘要。
