19:T407,Proposes Mixture-of-Parallelisms (MoP), a training stack that abandons uniform global parallel plans and assigns sharding strategies matched to each MoE component's dominant bottleneck. All composed parallelism methods maintain a data-parallel-like rank invariant (each device holds a distinct token shard and corresponding weight shard), avoiding the rank multiplication overhead of 3D parallelism. Three core lossless optimizations are included: 1) A memory-efficient expert parallelism built on Least-Loaded Expert Parallelism (LLEP) that overlaps routing communication with expert computation to reduce transient MoE activation footprint while preserving LLEP speedups; 2) A sharded data-tensor-parallel vocabulary projection that computes exact loss and gradients without materializing the O(NV) logit tensor, while respecting the data-parallel rank invariant; 3) A pipelined optimizer update scheme that compresses critical path time via computation-communication overlap. All optimizations preserve exact training semantics.1a:T8fb,方法核心是一个“异构并行运行时”，允许同一端到端图中的不同模块分别选择自己的 TP/CP/PP/DP/EP 布局，以及自己的物理 rank 集合。论文把实现拆成三个关键部件。

第一是 boundary communicator。这是挂在模块边界上的 autograd-aware 算子。前向时，它把源模块输出的激活按照目标模块的逻辑布局重新物化；反向时，再执行严格匹配的逆变换，把梯度送回源模块原来的布局。这里最重要的不是通信本身，而是“边界张量语义”的显式化。作者强调一个实际风险：布局映射如果错了，张量形状可能仍然合法，训练会继续跑，但梯度会被送到错误 rank，属于很难排查的 silent corruption。boundary communicator 的设计就是把这种 forward/backward 对偶关系固定下来，避免手工拼接通信逻辑。

第二是两种 placement 模式。colocated 模式下，encoder 和 LLM 共享同一批 GPU，但每个模块在这批 GPU 上解释不同的逻辑网格。这个模式适合 encoder 计算量不算太大、但不想继承 LLM 布局的场景。non-colocated 模式下，模块使用互不重叠的 rank 集合，适合 encoder 状态或激活占用已经明显挤压 LLM 显存和流水线布局的情况，尤其是大 encoder 配大 LLM。两种模式覆盖了“共享硬件但布局解耦”和“物理资源也解耦”两类常见需求。

第三是调度扩展。异构布局一旦进入 PP，问题不再是单链式 pipeline。对于 non-colocated，作者实现了 graph-aware 1F1B dispatcher，用于协调不同模块之间的边界通信和流水线推进。对于 colocated，作者提出三阶段调度，把 encoder 计算/collective 与 LLM pipeline P2P 交错安排，避免共享 GPU 上的通信冲突。这里的关键取舍是：如果只做布局变换而不改调度，通信会和 pipeline 互相踩踏，吞吐未必提升。

从与现有方法的区别看，这篇工作不是在 homogeneous parallelism 上做局部优化，而是把“模块局部最优布局”提升为一等公民。传统 Megatron 假设一个模型基本对应一套全局并行网格；这篇工作则把多模态训练图看成多个并行子图，通过边界通信把它们拼成一个可微整体。1b:T529,The paper addresses a systems bottleneck in multimodal foundation-model training: modern MLLMs are trained as heterogeneous graphs, but the parallelism stack is still largely homogeneous. In practice, the encoder and the LLM are often forced to share one global TP/CP/PP/DP/EP layout. That coupling becomes increasingly costly when the model graph mixes modules with very different width, depth, and sequence-length characteristics. The paper identifies three concrete mismatches. First, large LLMs may need high tensor parallelism, while smaller encoders pay unnecessary all-reduce overhead under the same TP degree. Second, long-context LLM training often requires context parallelism on the fused multimodal sequence, but encoder-side sequence lengths are bounded by modality resolution rather than the LLM context window, so inheriting CP shards the encoder without meaningful memory relief. Third, pipeline parallelism tied to the LLM can pin the encoder to the first stage, constraining both encoder layout choices and pipeline balance. The core problem is therefore not just “better parallelism,” but how to let different modules in one end-to-end training graph use independent logical layouts and even different physical placements, while preserving exact forward/backward semantics across module boundaries.1c:T94e,The method is a heterogeneous-parallel runtime for multimodal training graphs, implemented as an extension to Megatron-LM. Each module can choose its own TP/CP/PP/DP/EP layout and its own physical rank set, while the full graph remains end-to-end differentiable.

The central primitive is the boundary communicator, an autograd-aware operator attached to an inter-module edge. In the forward pass, it materializes activations from the source module into the destination module’s layout. In the backward pass, it applies the exact inverse transform so gradients return to the source layout correctly. This is more than a communication helper: it makes boundary tensor semantics explicit. The paper highlights a subtle but important failure mode in distributed training: an incorrect layout mapping can still produce tensors with valid shapes, allowing training to continue while silently routing gradients to the wrong ranks. The boundary communicator is designed to prevent that class of silent corruption by enforcing paired forward/backward transforms.

The runtime supports two placement modes. In colocated execution, modules share the same physical GPUs but interpret them under different logical grids. This is useful when the encoder and the LLM can share hardware but should not share a layout. In non-colocated execution, modules occupy disjoint rank sets. This is useful when encoder state or activations on LLM ranks would otherwise constrain LLM memory usage or pipeline design, especially with larger encoders paired with very large LLMs.

The paper also extends scheduling beyond a single linear pipeline. For non-colocated execution, it introduces a graph-aware 1F1B dispatcher that coordinates boundary communication and pipeline progress across modules. For colocated execution, it proposes a three-phase schedule that avoids conflicts between encoder collectives and LLM pipeline P2P traffic on shared GPUs. This scheduling layer is important: layout decoupling alone would not guarantee throughput gains if communication patterns interfere with pipeline execution.

Relative to standard Megatron-style training, the key difference is conceptual. Instead of treating the model as one globally sharded object, the paper treats a multimodal training graph as a composition of module-local parallel subgraphs connected by explicit, differentiable layout transforms.1d:T661,The evaluation is organized by operating regime rather than by a single aggregate speedup number, which is the right framing for this kind of systems work.

The first regime is colocated execution, where encoder and LLM share GPUs but should not share a layout. The paper varies encoder size, context length, visual-token density, and GPU scale. Long-context settings are especially important because they expose the CP mismatch most clearly: the LLM needs CP for the fused sequence, while the encoder does not benefit much from inheriting those CP shards. In that case, repurposing those ranks as encoder-side data-parallel replicas can improve throughput more effectively. The provided text explicitly states that colocated execution improves TFLOPS/GPU against optimized homogeneous baselines, although the exact numbers are truncated in the supplied excerpt.

The second regime is non-colocated execution, targeting workloads with larger encoders paired with a 120B LLM. For very large LLMs, that resource isolation can matter more than local communication savings.
