optimize_anything: A Universal API for Optimizing any Text Parameter

这篇工作要解决的问题不是某一个具体优化任务，而是更上层的接口与搜索范式问题：能不能把一大类“候选解可序列化为文本、质量可由程序化 evaluator 打分”的问题，统一成同一种 LLM 优化流程，并且在单任务搜索、跨任务联合搜索、以及对未见输入的泛化优化三种设置下都有效。作者针对现有方法各自割裂的局面下手：FunSearch / AlphaEvolve 主要做代码单任务进化，GEPA / MIPROv2 主要做 prompt 泛化优化，缺少一个同时覆盖 code、prompt、agent architecture、数值配置、图像文本表示等不同 artifact 的统一系统。论文的核心问题因此是：如何定义一个足够通用、又不丢失诊断反馈与搜索效率的 text optimization API，并让同一套 Pareto 式搜索机制在多种 artifact 上稳定工作。

评预训练不必精读，但 §4 消融值得看：它把 reward shape 对搜索效率的影响做得比多数 agent 论文更干净。

Spectral Lens: Activation and Gradient Spectra as Diagnostics of LLM Optimization

训练损失和吞吐量作为 LLM 优化的主要监控指标，会掩盖模型内部表示结构的深刻变化——不同训练配置可能在相同损失水平下产生系统性不同的内部表征几何。论文提出将激活谱和梯度谱作为实用的诊断工具，以揭示训练过程中隐藏的内部学习机制。

评应在内部小模型网格复现：若 early spectrum tail 真能预测 token efficiency，loss-only ablation 该降级。

GRACE: A Dynamic Coreset Selection Framework for Large Language Model Optimization

如何在 LLM 训练/微调过程中进行“动态 coreset（代表性子集）选择”，在显著减少训练数据处理成本的同时尽量保持最终性能，并解决现有 coreset 方法对 LLM 不可扩展、且无法适配训练动态的问题。

评方向对但目前更像“承诺型”工作：动态coreset在LLM上最难的是梯度代理与更新开销，文中若没给出规模化成本与端到端收益曲线就当弱信号；只扫实验表即可。
