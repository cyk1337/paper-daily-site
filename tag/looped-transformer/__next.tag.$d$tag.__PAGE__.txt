The first is Token-Sparse Updates. The authors analyze hidden-state changes between adjacent loops and show that, as recurrence proceeds, only a small subset of tokens still changes substantially. Moreover, the active-token sets are approximately nested: tokens that remain active in a later loop are mostly a subset of those active in the previous one. FlashLoop therefore recomputes the Transformer block only for active tokens and reuses hidden states and KV states for tokens that have effectively converged. This reduces both compute and the need to maintain a full per-loop KV cache.

The second is Sparse Attention. The paper shows that cross-loop changes in attention outputs are dominated by a sparse subset of attention columns, meaning a small number of key/value positions account for most of the difference between adjacent loops. These important columns are relatively stable across loops, so FlashLoop predicts them using attention-contribution statistics from the previous loop. To avoid the scale mismatch that usually appears when softmax is computed on a subset, the method caches global probability mass to preserve the normalization scale of the full softmax. This is more careful than a generic top-k attention approximation; it is tailored to incremental cross-loop updates.

The third is KV-Residual Quantization. Instead of quantizing each loop’s full KV states independently, FlashLoop stores a quantized base state plus low-bit residuals between adjacent loops. The motivation is empirical: adjacent-loop KV residuals are easier to quantize than full KV tensors, yielding lower reconstruction error under the same bit budget. That matches the intuition that iterative refinement makes successive states highly correlated and low-entropy in difference space.

A key part of the paper is that these are not presented as isolated tricks. The system is implemented with GPU-aware pipelining and optimized kernels so that token sparsity, sparse attention, and residual quantization work together without losing the gains to irregular memory access or kernel overhead. Instead of waiting until depth R is completed for the current token, LoopSpec samples an early draft from a shallower depth and immediately starts partial computation for the next token conditioned on that draft.

The first component is single-branch self-speculation. Given a prefix X, the model produces a first proposal at depth r1. Before the original branch reaches final depth R, the system appends that proposed token and starts computing recurrent steps for the following position. Once the original branch reaches p_R, the proposal is verified using exact speculative decoding / rejection sampling. If accepted, some work for the next token has already been done; if rejected, the computation rolls back to the verified prefix.

The second component is the main algorithmic addition: a residual second proposal from a deeper depth r2. Since deeper recurrent states are typically closer to the final distribution, LoopSpec generates a second proposal and launches an alternative continuation before the first proposal is fully verified. This is not just running two independent drafts. The paper defines the second proposal through a residual distribution construction so that probability mass not covered by the first proposal is handled correctly, while preserving exactness of the final sampling distribution.

The third component is gating. A fallback continuation is only created when the deeper recurrent state disagrees with the first draft. This avoids paying the overhead of a second speculative branch when the first proposal is already likely to be accepted. In other words, the system uses disagreement between intermediate depths as a trigger for extra speculative work.

The theory section is stronger than a typical systems paper. First, the authors prove that the restart probability depends only on the depth of the second proposal, not on the first proposal depth. Intuitively, once the first branch fails, what matters is how close the backup branch is to the final distribution. Second, they empirically observe a power-law decay in the TV distance between intermediate and final distributions, and derive closed-form optimal proposal depths from that decay. The predicted optima match measured best settings well, which gives a principled way to choose r1 and r2.

On the implementation side, the paper integrates LoopSpec into SGLang with branch-wise KV-cache management and CUDA Graph optimization. That is a meaningful result because it suggests that, for Looped Transformers, exploiting intermediate recurrent states directly can outperform methods that rely on an explicitly trained drafter.

The more informative results are in the ablations. Proposal-depth sweeps show a stable optimum region, and the empirically best depths align with the closed-form predictions derived from the TV-distance decay model. The gating mechanism improves the speedup/overhead trade-off by suppressing unnecessary fallback branches when acceptance is already high. System-level optimizations, especially branch-wise KV handling and CUDA Graphs, also contribute materially; without them, the algorithmic gains would not fully translate into wall-clock speed.

A useful empirical takeaway is that LoopSpec’s benefit depends on how quickly intermediate recurrent distributions approach the final one. If shallow depths already have strong token agreement with the final prediction, the pipeline can start useful future work early.
