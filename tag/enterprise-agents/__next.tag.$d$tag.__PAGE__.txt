9:T7ca,方法主线很清楚：以 Nemotron-3-Super-120B 为底座，直接做 GRPO 强化学习，不先走一个新的 SFT checkpoint。关键创新不在 RL 算法本身，而在 specification-driven task construction。

具体看，企业域使用 Agent Script 来描述 agent：里面包含 router、subagent、typed actions、tool scope 和自然语言工作流指令。作者先做一个静态抽取，把这些声明式定义编译成 typed workflow graph。这个图里有工具参数 schema、状态读写、副作用、路由条件、循环与终止配置。也就是说，训练环境不是从对话日志反推出来，而是从 agent 的程序化定义直接生成。

然后，simulation pipeline 会把一个 specification 扩展成 scenario-conditioned 和 persona-conditioned 的多轮 session。scenario 决定用户需求和会触发哪些 workflow，persona 决定模拟用户在对话中的行为方式。训练样本既可以从对话开头开始，也可以从中间某个 prefix 开始，让策略在不同深度的状态上学习决策，而不是只学第一步。

执行层由 NeMo Gym 承担。对于没有真实后端的环境，作者用一个冻结 helper model 同时扮演三种角色：customer simulator、tool/function emulator、coverage judge。也就是用户回复、工具返回、任务是否完成的评分，都由外部服务提供。策略模型只负责在环境中 rollout。奖励核心是 grounded task-resolution reward，重点看任务是否真正通过工具调用被解决，而不是只看表面格式或局部步骤。这个设计比 token-level imitation 更接近最终 agent 目标。

优化上使用 GRPO。文中强调 joint training 多环境时，通过 agent_ref 做环境分发，并通过重复样本控制不同环境曝光率。这说明作者把多环境混训当成一个重要工程问题来处理，而不是只做单 benchmark 微调。整体上，这套方法更像“把 agent authoring system 变成 RL data engine”。a:T80e,The overall recipe is straightforward: start from Nemotron-3-Super-120B and apply GRPO directly, rather than first building a new SFT checkpoint. The main contribution is not a new RL algorithm. It is specification-driven task construction.

In the enterprise setting, the workflow is authored in Agent Script, which defines routers, subagents, typed actions, tool scopes, and natural-language instructions. A static extraction pass compiles this declarative specification into a typed workflow graph. The graph encodes tool argument schemas, state effects, routing conditions, and loop or termination logic. In other words, the training environment is generated from the agent program itself, not reverse-engineered from logs.

A simulation pipeline then expands each specification into scenario-conditioned and persona-conditioned multi-turn sessions. The scenario determines the user need and which workflows are exercised. The persona controls the simulated customer behavior. Training examples can start from the initial user request or from an intermediate dialogue prefix, so the policy learns decisions at different depths of the interaction rather than only the first move.

Execution is handled by NeMo Gym. In environments without production backends, a frozen helper model plays three roles during rollout: customer simulator, tool or function emulator, and coverage judge. The policy model only acts in the environment. The reward is a grounded task-resolution reward, centered on whether the task is actually solved through successful tool use, not whether the response merely looks plausible. That makes the signal much closer to the real agent objective than token-level imitation.

Optimization uses GRPO. The paper also notes practical details for joint training across multiple environments: agent_ref dispatch selects the environment per example, and exposure is controlled by repeating examples before shuffling. This is a useful systems detail. The broader picture is that the agent authoring system becomes a data and reward engine for RL.b:T65f,The evaluation spans public tool-use benchmarks, agentic reasoning benchmarks, and enterprise CRM-style benchmarks. The main result is consistent: Koa improves over its open-weight base, with the clearest gains on multi-turn tool use. In some settings it surpasses GPT-4.1 as a strong proprietary baseline, while still trailing the strongest frontier models. The paper is more informative about capability shape than about a single headline score. The gains are concentrated in settings that require state tracking, tool selection, argument filling, and end-to-end task closure.

A notable ablation is the scoped SFT-versus-RL comparison. The starting point is not a raw base model, but an already RL-post-trained base. Under that condition, further RL substantially improves multi-turn tool use, whereas SFT contributes little. The right reading is narrow: when high-quality executable rewards are available, RL can shape agentic behavior more effectively than imitation on this starting point. It should not be generalized into a blanket statement against SFT.

Another important experimental fact is that training uses only public and synthetic data, with no customer data. If the model still transfers to enterprise CRM benchmarks, that supports the viability of the specification-plus-simulator route for at least a meaningful subset of enterprise workflows.
