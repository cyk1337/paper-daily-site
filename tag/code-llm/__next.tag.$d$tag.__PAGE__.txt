SrDetection first uses an auxiliary LLM to generate functionality-preserving code variants. In the gray-box setting, it compares perplexity on the original and on the variants using model logits; a consistently lower perplexity on the original is treated as leakage evidence. In the black-box setting, it prompts the model with prefixes and compares generated completions with the true suffixes; unusually high suffix similarity on the original relative to its variants is the signal. First, scaffold-driven structured generation: instead of asking the model to create an entire project from scratch, the policy operates inside a pre-validated React template. The template already guarantees core build configuration, routing skeleton, and server setup. The model mainly fills in or edits components and page logic. This sharply reduces the combinatorial search space and removes many low-level failure modes from RL exploration.

Second, a hierarchical verification-and-rendering pipeline filters outputs before expensive reward modeling. The pipeline checks structural compliance, required artifacts/actions, project files, commands, and selected content rules, then attempts automated build and rendering. This stage serves two purposes: it rejects invalid samples early, and it provides dense penalties for structural hallucinations such as missing files, malformed commands, or broken project layouts.

Third, a cascaded multimodal reward uses a VLM only after the sample passes the lower-level gates. The VLM evaluates rendered websites for layout quality, typography consistency, visual hierarchy, stylistic alignment with user intent, and visual cues of functionality. The important design choice is the cascade. The VLM is not used as a universal judge over raw generations; it is applied only to samples that are already structurally plausible and renderable. That reduces reward noise and cost.

Compared with multi-agent website generation, this avoids brittle interface mismatches between specialized agents. Compared with pure supervised finetuning, it optimizes final project quality rather than imitation of reference code. Compared with single-score reward schemes, it is closer to reward shaping: hard constraints secure minimum viability, then softer multimodal signals improve higher-level quality.a:T64e,The headline numbers are strong and easy to interpret.
