18:T5d3,TURTLE is a three-agent evolutionary pipeline:
- Task representation: tool-use tasks are encoded as Python programs (environment state, databases, tools, goals). This makes compositional mutation feasible and preserves compatibility with existing harnesses, but introduces risks of format/underspecification artifacts.
- Proposer: implemented via AlphaEvolve, a gradient-free evolutionary search operator. A practical point is that it can leverage strong closed-source LLMs as proposers via API calls, since no gradients/weights are needed.
- Solver: the target model under evaluation; each candidate mutated task is attempted N times to estimate an empirical completion rate.
- Fitness shaping: reward targets “hard but solvable” by pushing completion rates toward ~50%, motivated by maximal variance / maximal discriminative power near 0.5 (akin to learnability sampling).
- Feedback generator: summarizes failure reasons from execution traces plus the ground-truth solution, producing exploitable signals for the proposer’s next mutations.
- Post-filtering: an LLM judge (Gemini 3.6 Flash) removes trivial failures (format mismatches, ambiguous instructions, near-paraphrases), which is crucial to prevent evolution from exploiting loopholes.
- Dataset selection: after a fixed evolution budget, the final set keeps, per parent task, programs with the highest completion-rate variance, aiming for samples that best separate solver behaviors rather than simply maximizing difficulty.19:T5bc,The paper casts collaboration as finite block optimization over x=(x1…xm) with a global loss F(x) accessible via an exact verifier. Each agent b controls block xb and has a cheap local objective Lb that ignores interactions. Define the true conditional change fb(u;x)=F(x with xb←u)-F(x). The key construct is a correction term Rb capturing the interaction effects missing from Lb; agents instead optimize a corrected surrogate \hat{f}_b(u;x)=Lb(u)+\hat{R}_b(u;x), where \hat{R}_b approximates Rb and is anchored so \hat{R}_b(xb;x)=0.
Protocol: (1) parallel private search—each agent proposes an update u_b by optimizing \hat{f}_b with other blocks frozen; (2) exact verification—coordinator evaluates true global deltas via F; (3) compatibility-based merging—build a dependency graph over proposals and select a non-interfering subset (via coloring) to merge, guaranteeing non-increasing F. Extension: even interfering proposals may be merged if the coordinator verifies that their joint application yields a larger decrease; the convergence rate then depends on the realized joint improvement rather than worst-case interference.
Theory: linear convergence up to an explicit error floor determined by correction approximation error; the floor vanishes with exact corrections. The appendices also discuss learning reusable corrections from global evaluations and provide a joint convergence characterization for both the solution and the learned correction.1a:T560,Agima (Agentic Imagination) trains one omni model to play three roles:
- Policy: propose actions given current observation and goal.
- World model: generate the next visual observation (an imagined image) conditioned on the action.
- Reasoner/evaluator: compare imagined futures in language space and decide which action/plan to execute.

Two-stage training:
1) Supervised fine-tuning with interleaved trajectories that explicitly teach the model to treat imagined observations as valid context for continued planning. The paper uses three planning formats: (i) linear rollout (single imagined trajectory), (ii) counterfactual branching (branch on alternative actions at a step and reject failing branches), and (iii) forward thinking (imagine and compare longer candidate plans before committing).
2) Agentic RL using GRPO with only a binary success reward. No extra demonstrations are provided; RL shapes how the model allocates imagination and comparison—when to explore another plan, how many alternatives to branch, and where branching matters—while keeping generated images as context during planning.

A key design choice is “single model, shared interface” instead of separate policy and world models, so imagined vs. real observations can be swapped seamlessly and RL can directly sculpt the reasoning/search strategy rather than only the action distribution.1b:T432,Benchmarks include Maze2D, Sokoban, Pacman, and PushT, trained on easier instances and evaluated on harder settings excluded from training.

Reported highlights:
- With SFT alone, Agima generalizes from two-box to four-box Sokoban. Under sparse real feedback (real observation every 5 actions), it reaches 40% success vs. 2% for an action-only planner fine-tuned from the same backbone.
- “Forward thinking” improves long-horizon planning in Pacman even when trained on the same instances as linear rollouts, suggesting gains come from comparison/selection behavior rather than more data.
- GRPO further improves success and yields emergent planning organization not seen in SFT: e.g., in forward thinking it often imagines one plan first and only explores a second if the first is predicted to fail; in counterfactual branching it increases branching and concentrates it on critical irreversible decisions.

(Additional details like model size, compute, and full tables should be taken from the main results section; they are not fully present in the provided excerpt.)1c:T659,The proposed method, SchemaShield-Lite, is a training-free inference-time robustness layer with three components. First, each tool is rendered into a compact canonical card containing the tool name, description, required fields, and field-level type information. This normalizes presentation and emphasizes the current schema. Second, after the base model emits a tool call, a validator checks the tool name, required fields, and argument structure, returning structured error information rather than a binary valid/invalid flag. Third, if the call is invalid, the model is prompted again with the task context, the canonical tool card, the invalid call, and the validator errors, and asked to repair the output. Under the primary non-oracle protocol, repair is staged. If the base call already names a visible tool, the system performs constrained repair against that tool. If the tool name is missing, it first runs a candidate-set retry over visible tools to resolve a concrete target, then performs tool-constrained repair. The paper highlights three implementation details that materially affect results: the repair prompt must explicitly ask the model to infer all required fields from dialogue context; candidate-set retry is necessary when the tool name is absent; and the repair stage needs a larger token budget, raised to 512 tokens in their setup to avoid truncation on longer examples. An important ablation result is that the main gains come from the combination of structured validator feedback and tool-constrained repair, while the canonical card contributes more to prevention than to repair-stage recovery.1d:T54c,The main experiments use Qwen3.5-9B on a 300-example DICE-BENCH slice and a 200-example BFCL slice under a deployment-oriented non-oracle protocol.
