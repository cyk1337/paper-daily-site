9:T560,Agima (Agentic Imagination) trains one omni model to play three roles:
- Policy: propose actions given current observation and goal.
- World model: generate the next visual observation (an imagined image) conditioned on the action.
- Reasoner/evaluator: compare imagined futures in language space and decide which action/plan to execute.

Two-stage training:
1) Supervised fine-tuning with interleaved trajectories that explicitly teach the model to treat imagined observations as valid context for continued planning. The paper uses three planning formats: (i) linear rollout (single imagined trajectory), (ii) counterfactual branching (branch on alternative actions at a step and reject failing branches), and (iii) forward thinking (imagine and compare longer candidate plans before committing).
2) Agentic RL using GRPO with only a binary success reward. No extra demonstrations are provided; RL shapes how the model allocates imagination and comparison—when to explore another plan, how many alternatives to branch, and where branching matters—while keeping generated images as context during planning.

A key design choice is “single model, shared interface” instead of separate policy and world models, so imagined vs. real observations can be swapped seamlessly and RL can directly sculpt the reasoning/search strategy rather than only the action distribution.a:T432,Benchmarks include Maze2D, Sokoban, Pacman, and PushT, trained on easier instances and evaluated on harder settings excluded from training.

Reported highlights:
- With SFT alone, Agima generalizes from two-box to four-box Sokoban. Under sparse real feedback (real observation every 5 actions), it reaches 40% success vs. 2% for an action-only planner fine-tuned from the same backbone.
- “Forward thinking” improves long-horizon planning in Pacman even when trained on the same instances as linear rollouts, suggesting gains come from comparison/selection behavior rather than more data.
- GRPO further improves success and yields emergent planning organization not seen in SFT: e.g., in forward thinking it often imagines one plan first and only explores a second if the first is predicted to fail; in counterfactual branching it increases branching and concentrates it on critical irreversible decisions.

First, each tool is rendered into a compact canonical card containing the tool name, description, required fields, and field-level type information. This normalizes presentation and emphasizes the current schema. Second, after the base model emits a tool call, a validator checks the tool name, required fields, and argument structure, returning structured error information rather than a binary valid/invalid flag. Third, if the call is invalid, the model is prompted again with the task context, the canonical tool card, the invalid call, and the validator errors, and asked to repair the output. Under the primary non-oracle protocol, repair is staged. If the base call already names a visible tool, the system performs constrained repair against that tool. If the tool name is missing, it first runs a candidate-set retry over visible tools to resolve a concrete target, then performs tool-constrained repair. The paper highlights three implementation details that materially affect results: the repair prompt must explicitly ask the model to infer all required fields from dialogue context; candidate-set retry is necessary when the tool name is absent; and the repair stage needs a larger token budget, raised to 512 tokens in their setup to avoid truncation on longer examples. First is a retrieval-based labeling pipeline. Starting from a corpus of user sessions, the system uses an off-the-shelf memory extractor (mem0 in the paper) to produce atomic candidate facts from each session. Under an infinite-budget construction, all extracted facts are added to a growing candidate memory pool. For each candidate fact, the pipeline scans future user turns. A turn is first judged on whether memory is needed; if memory is queried, retrieval is performed. A fact is labeled useful if it is retrieved in a later interaction and its content is actually incorporated into the model’s answer. An LLM judge is used to verify that the retrieved fact was genuinely used, reducing noise from superficial retrieval hits.

Second is Warm-Start UCB. The offline stage learns a shared utility pattern from historical users, providing a prior or initialization. The online stage adapts to a new user with an upper-confidence-bound algorithm under one-sided delayed feedback. Because feedback is observed only for admitted facts and only after an unknown delay, the problem is cast as an apple-tasting style decision process. UCB handles the exploration–exploitation trade-off by favoring facts with both high predicted value and high uncertainty. Compared with pure offline supervision, this explicitly models partial and delayed feedback.
