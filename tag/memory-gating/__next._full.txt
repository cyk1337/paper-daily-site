Starting from a corpus of user sessions, the system uses an off-the-shelf memory extractor (mem0 in the paper) to produce atomic candidate facts from each session. Under an infinite-budget construction, all extracted facts are added to a growing candidate memory pool. For each candidate fact, the pipeline scans future user turns. A turn is first judged on whether memory is needed; if memory is queried, retrieval is performed. A fact is labeled useful if it is retrieved in a later interaction and its content is actually incorporated into the model’s answer. Second is Warm-Start UCB. The offline stage learns a shared utility pattern from historical users, providing a prior or initialization. Because feedback is observed only for admitted facts and only after an unknown delay, the problem is cast as an apple-tasting style decision process.
