LongCat Sparse Attention: Taming the Lightning via Streaming-aware Hierarchical Cross-Layer Indexing

DeepSeek Sparse Attention 通过 Lightning Indexer 做细粒度 token 选择，在长上下文上接近全注意力质量，但部署时存在两个系统瓶颈：indexer 对所有 prefix token 打分仍有 O(L^2) 开销，在 1024K 上下文时可占单层延迟的 90%；其选出的离散索引导致稀疏注意力算子进行非连续 HBM 访问，实测只能达到约 4.5% 的峰值 HBM 带宽。LongCat Sparse Attention 要同时解决索引计算开销和硬件访问效率问题。

评应立刻看 indexing 三件事；它把稀疏注意力瓶颈从算法复杂度拉回到 HBM 访问形态。

PIVOT: Efficient Query-Group Indexing for Token-Level Sparse Attention

这篇工作处理的是 token-level sparse attention 在真实长上下文推理里的一个新瓶颈：主注意力已经从全量 attention 降到只看 top-k token，但用于选出这 top-k 的 indexer 仍然要对每个 query 扫完整个前缀，单层复杂度还是 O(L^2)。论文抓住的不是 token 轴、head 轴或 layer 轴，而是 query 轴上的冗余：相邻 query 往往会选到高度重合的 top-k token，因此没必要为每个 query 各做一次完整前缀扫描。

评DeepSeek生产级稀疏注意力的索引优化，思路巧妙且训练无关，做长上下文/高效注意力的研究员应重点看其分组共享扫描的设计。
