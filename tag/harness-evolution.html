Evo-Bench: Can Language Models Improve Agent Harness?

这篇工作要解决的不是“模型能不能把任务做对”，而是“模型能不能持续改进承载任务执行的 agent harness”。这里的 harness 指可执行的外层脚手架：提示、工具调用流程、状态管理、错误恢复、子任务编排、代码逻辑等。难点在于，现有 agent benchmark 往往把基础模型能力、任务难度、harness 设计混在一起，导致你很难判断分数提升究竟来自更强的 base model，还是来自更好的 harness。作者把问题拆成三个必须同时满足的条件：任务要对 harness 改动敏感，而不是被底模能力主导；验证集和测试集要在这种“敏感性”上分布一致，避免在验证集上过拟合；评测过程要允许多轮、长时程的代码级迭代，而不是单轮 prompt search。

评harness自主进化是agent能力的新维度，对研究长程agent能力演化有参考，只看 §2 的benchmark构建逻辑即可。
Lisheng Huang,Chen Yang,Hao Zhou,Huatong Song,Zongchao Chen,Ran Le,Yang Song,Wayne Xin Zhao,Tao Zhang

TTHE: Test-Time Harness Evolution

这篇论文关注一个较具体但有实际意义的问题：LLM agent 的测试时适配不一定只能改模型参数或改单次输出，也可以改包在模型外面的可执行 harness。harness 包括上下文构造、工具调用、校验逻辑、失败恢复、控制流等。作者要解决的是：在没有标签、没有人工修复、没有额外 repair model、模型权重冻结的条件下，能否只利用测试输入产生的执行轨迹，在评测过程中持续修改 agent 的 harness。

评只看方法和实验设定即可；若无标签轨迹真能稳定改 harness，这比又调 prompt 更接近可复用的 agent test-time adaptation。
Jun Nie,Yonggang Zhang,Jun Song,Qianshu Cai,Dahai Yu,Yike Guo,Xinmei Tian,Bo Han

Harness Updating Is Not Harness Benefit: Disentangling Evolution Capabilities in Self-Evolving LLM Agents

这篇论文要拆开一个过去被端到端指标混在一起的问题：自演化 Agent 的收益，到底来自模型能写出更好的 harness 更新，还是来自任务执行模型能更好地使用这些更新。论文把前者定义为 harness-updating，把后者定义为 harness-benefit，并用固定权重、只更新外部 prompt、skill、memory、tool 等 harness 的设定做系统分析。

评反常识发现值得注意：弱模型更新 harness 的质量并不比强模型差多少——只看核心实验图即可，setup 相对干净。
