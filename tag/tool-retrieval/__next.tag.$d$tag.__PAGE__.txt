9:T852,The method, State-Path Tool Menu, has three components: an encoder, a retriever, and a reranker. Each tool has documentation, required inputs, and produced outputs. A request exposes an initial state s0(q), containing the fields and constraints visible before any tool call. The system must construct an ordered menu of K=32 tools, and the online agent can only use tools from that menu during execution.

The central idea is the state path, a latent pre-execution route from the observable initial state to the desired outcome. Tools on this route are assigned one of four roles: entry tools can run immediately from the initial state, bridge tools create intermediate fields needed later, the target tool resolves the main request, and an optional terminal tool commits or delivers the result. This role decomposition is useful because it separates different notions that relevance-based retrieval conflates: immediate executability, intermediate utility, and final-task alignment.

The encoder learns relation-aware tool representations from the request state, tool schemas, and successful training trajectories. The excerpt explicitly mentions three directional signals: whether a tool can run now, whether it produces fields needed later, and how it depends on other tools in precedence order. So the representation is not just semantic similarity over tool descriptions; it is structured around state compatibility and dependency. The retriever then selects 32 tools that cover complementary path roles rather than simply maximizing top-k relevance. The reranker orders the selected tools so that producers appear before consumers, making the menu easier to execute under the same online loop and call budget.

Training supervision comes from successful trajectories. The retriever is trained with route membership, entry, and path-role targets, while the reranker is trained with slot and pairwise precedence targets. A notable design choice is that the paper keeps the online agent unchanged. The gains are meant to come from better pre-execution menu construction, not from modifying the planner or increasing the budget.a:T4b9,From the available text, the experiments compare State-Path menus against relevance-based menus under a fixed agent and a fixed 32-tool budget.
