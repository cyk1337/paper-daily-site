A Jagged Frontier: Evaluating Robustness of Code Agents to Semantics-Preserving Transformations

这篇工作要回答的不是“代码 agent 在 SWE-bench 上能做对多少题”，而是更接近部署的问题：当代码仓库只发生语义不变、但表面形式改变的重写时，repository-level 代码 agent 的修复能力是否稳定。难点有两个。第一，agent 不是单轮补全，而是多轮搜索、编辑、执行工具的闭环系统，脆弱性可能来自模型、scaffold、工具调用策略三者的耦合。第二，LLM agent 本身有较强随机性，单次成功或失败不能直接归因于 perturbation，因此需要把“扰动效应”和“运行方差”分开估计。论文围绕这两个点，构造了一个非对抗、随机采样的 semantics-preserving transformation 评测框架，试图给出代码 agent 鲁棒性的保守下界。

评揭示了当前 Code Agent 对代码表面变化（如重命名、死代码注入）的脆弱性，说明模型对代码语义的理解仍停留在 pattern matching 层面，对构建更鲁棒的 Code Agent 评测基准有参考价值。

Steer, Don't Solve: Training Small Critic Models for Large Code Agents

RepoMirage: Probing Repository Context Reasoning in Code Agents with Perturbations

评这篇不改模型，但会改你看 SWE-Bench 分数的方式；先看 perturbation 设计和 66.8→25.3 的落差，足够判断很多 repo-agent 结果被高估了。
