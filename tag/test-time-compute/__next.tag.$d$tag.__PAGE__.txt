9:T43c,They propose Uncertainty-Aware Allocation (UAA), separating selection from allocation:
- Value decides which candidate actions to keep.
- Uncertainty decides how many children/rollouts are worth expanding.

Core empirical claim: sibling semantic dispersion at the current step predicts redundancy of downstream continuations, enabling you to set a subtree budget before expanding it.

Key pieces:
- Uncertainty proxy: cosine dispersion/similarity among sibling actions (embedding-based), avoiding auxiliary trained scorers.
- Information-theoretic motivation: interpret per-step budget as Monte Carlo sample size for estimating residual answer entropy; under a Lipschitz assumption, fewer samples suffice when uncertainty is low.
- Two mechanisms: (i) uncertainty-aware pruning (UAP) to keep only a high-quality subset at low-uncertainty steps; (ii) uncertainty-aware budgeting (UAB) to shrink next-step budgets for retained low-uncertainty actions.
- Plug-and-play integration with Beam Search, MCTS, DVTS, REBASE; supports white-box and black-box uncertainty proxies (e.g., GPT-4o).a:T75f,The main contribution is not a new model but a unified benchmark and protocol. System1-Arena represents each static example or environment step as a decision request r=(s,Q). The state s is a small set of named text fields, such as a message, a code diff, or a rendered webpage. Q is a set of typed questions over the same state. Questions are boolean, choice, or score. Each question includes instructions, and each option includes a description, so models do not rely on dataset-specific prompting. The output is a probability distribution over options for each question, not free-form text.

Several design choices matter. First, the interface is shared across model families. Dedicated System-1 models, autoregressive LLMs, and even diffusion LMs are all mapped into the same probability-based API. For open autoregressive and diffusion models, the authors provide a method to derive decision probabilities from answer tokens, which is important because it makes otherwise incompatible model families comparable. Second, the benchmark evaluates not only accuracy but also Brier score, since calibrated probabilities are central for thresholding, escalation, and risk-sensitive deployment. Third, it includes closed-loop environments and a real-time protocol in which the environment continues to evolve during inference according to each model’s measured latency. That turns latency from a side metric into part of the task definition.

The benchmark is broad: 92,125 typed questions across 105 tasks from 268 public sources in 16 domains, plus 138 closed-loop environments from 18 families, including web shopping, SWE-style coding control, robotics, games, and driving. This is not just a bundle of existing classification datasets. The benchmark standardizes instructions, option semantics, label sources, and environment feedback into a common probabilistic decision framework.b:T7e5,The evaluation covers 30 models: 7 closed LLMs, 13 open LLMs, and 10 System-1 models. On non-agentic tasks, Jev and Decision-2.0-Vega-27B reach 72.6% and 73.0% accuracy, slightly above GPT-6 Luna at 71.2%. They also provide better-calibrated probabilities and lower latency. The paper reports Jev at roughly $0.05 per 1,000 requests, which highlights the practical advantage of specialized decision models for high-throughput workloads.

The gains are task-dependent. The gap between strong System-1 models and the best LLMs is smallest on filtering, grouping, ranking, retrieval, and dialogue tasks. System-1 models remain weaker on knowledge and forecasting tasks. That pattern suggests that single-pass decision models are well suited to local discrimination and structured selection, but less suited to tasks that require broader knowledge integration or implicit multi-step reasoning.

Reasoning models still set the upper bound. Claude Opus 5.5 reaches 81.1% on non-agentic tasks, but at about 70 times the cost of a fast LLM. For RQ1, the authors combine deletion with multiple replacement interventions. Deletion only tests whether the model depends on the chain at all. Replacement distinguishes dependence on position from dependence on content. They use three replacements: noise, dataset-mean vectors, and latent vectors from another problem. This is a careful design. If deletion hurts but all replacements leave the answer unchanged, the chain behaves more like a placeholder. If replacing with another problem’s slots hurts more than deletion, that is stronger evidence that the model actually reads chain content.

For RQ2, the probing setup is broader than prior work. Instead of probing only the final answer, the paper probes every slot and every layer for the final answer, candidate answers, and each reasoning step, with permuted-label null baselines. This allows the authors to distinguish early answer readability, distributed path information, ordered step layouts, and candidate superposition. The key point is not probing alone, but probing interpreted jointly with the causal verdict from RQ1.

In the editing test, the chain prefix is replaced partway through with a twin prefix from another example, and the final answer is checked for whether it follows the edited content or remains anchored to the original computation.
