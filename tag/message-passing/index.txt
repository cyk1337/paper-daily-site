18:T4ee,Message Passing Language Models (MPLMs) are implemented as a runtime framework rather than a new model:
- A single user query spawns multiple concurrent LLM threads, each with its own prompt/context and textual ID, decoded in parallel via batched inference.
- The model emits tagged substrings that the runtime interprets as execution directives, analogous to MPI primitives:
  - <spawn[...]> ... </spawn>: create new threads with given IDs and seed prompts.
  - <send[...]> ... </send>: send a text message to specified threads.
  - <recv[...]>: block until messages arrive from specified threads.
  - <stop>: terminate a thread.
- A lightweight controller sits above the inference engine, handling scheduling, message queues, blocking/unblocking, and injecting received messages into the target thread contexts—without changing token sampling or KV-cache management.
- Key difference vs fork-join: communication is point-to-point and can happen repeatedly during execution, not only at a final join, aiming to reduce redundant exploration and lower synchronization granularity.
