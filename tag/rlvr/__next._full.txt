19:T8c0,The technical core is the experimental design. Training data comes from Multilingual Reasoning Gym, which procedurally generates reasoning problems in 14 languages and supports adjustable difficulty. Instead of simply translating English datasets, the authors use an online curriculum: for each task, difficulty increases when more than 70% of the last 32 rollouts are correct and decreases when fewer than 10% are correct. This matters because the same model can have very different capability baselines across languages, so fixed difficulty would confound language effects with reward availability. They also pre-filter tasks using Qwen3-14B-Base at easy difficulty, removing tasks with pass@8 = 0, and exclude heavily English-dependent tasks from training while keeping them for evaluation. The resulting setup uses 62 training tasks and 30 held-out tasks for OOD evaluation.

Training uses a DAPO-style GRPO objective without KL penalty. Each run uses 500 steps, learning rate 1e-6, 64 prompts per step, and 8 rollouts per prompt. Rewards consist of a binary correctness reward plus two auxiliary rewards, each weighted at half of correctness: a format reward and a reasoning-language reward. The reasoning-language reward is instantiated either as English reasoning or native-language reasoning. A key implementation detail is that auxiliary rewards are only granted when the final answer is correct, which prevents the model from gaming language or format rewards at the expense of solving the problem. The paper notes that preliminary runs in low-resource languages could otherwise collapse or overfit to formatting.

The model suite spans Qwen, Gemma, and SmolLM families, including both base and post-trained variants from 1B to 8B parameters. The authors run monolingual GRPO for 11 MGSM languages and one multilingual run with uniform language sampling. Italian, Korean, and Portuguese are fully held out as unseen languages. For model-language pairs with sufficient initial support for the target language, they additionally train native-reward variants. The point of this design is to disentangle training language, rewarded reasoning language, and model pretraining background rather than to optimize a single benchmark score.1a:T6a8,The most robust findings are fourfold. First, native-language reasoning rewards usually trail English-reasoning rewards by only a small margin on average; there is no universal large penalty for asking the model to reason in the prompt language. Second, cross-lingual transfer is strong: GRPO in one language often improves performance in many others, suggesting that RL is transferring problem-solving behavior rather than only surface-form language patterns. Third, the transfer is not monotonic. The paper identifies a regression failure mode where training in a particular language improves some evaluations but causes substantial drops on unseen languages or tasks. These regressions are highly model- and language-specific. Fourth, multilingual training is not always better than the best monolingual run, but it often provides a more stable compromise and is especially relevant for held-out-language generalization.

Evaluation covers seen tasks, 30 unseen tasks, MGSM, and PolyMath. The abstract does not expose the full numeric tables, but the full paper makes clear that the conclusions come from a broad comparison over 9 models, 11 training languages, monolingual versus multilingual runs, and English versus native reasoning rewards. For a pretraining researcher, the more useful part is the analysis style: the authors do not stop at average scores, but inspect transfer matrices across languages and compare how different model families react to the same training language. That supports a practical conclusion: the main bottleneck in multilingual RL is not merely data availability, but the interaction among initial language competence, reward attainability, and policy drift during RL.1b:T451,DiDPO extends group-relative advantage from the trajectory level into the internal structure of a code diff.

Using a CodeAct-like interaction loop, each action yields an edit (add/del/none) and the environment provides an outcome reward (e.g., tests pass/fail). Instead of treating the whole response/diff as one credit carrier, DiDPO:
1) Aligns diffs across multiple rollouts for the same task by finding highly similar sub-diffs that recur across trajectories.
2) Uses these recurring sub-diffs as anchors to induce sub-diff boundaries within larger diffs, aiming to isolate functional regions.
3) Groups aligned sub-diffs and computes a local group-relative advantage (diff-level advantage), then combines it with the trajectory-level advantage and assigns it back to the tokens responsible for generating those sub-diffs.

To avoid anchors that are too broad (mixing functions) or too narrow (hard to aggregate), it introduces a groupability score to select anchors that balance semantic scope and group mass. The method remains critic-free and claims no additional rollouts beyond the sampled group.1c:T4cb,RSTG first analyzes GRPO, OPD, and SFT under a shared policy-gradient view. GRPO estimates advantages from group rewards; when all rewards in a group are identical, the advantage disappears. OPD minimizes reverse KL from the student to the teacher on student-generated trajectories and can be written as a token-level advantage based on the teacher-student log-probability gap. This dense signal is noisy and asymmetric because many student tokens have low teacher probability, producing mostly negative advantages. RSTG uses three controls. First, sample selection applies OPD only when the student fails and the teacher succeeds, focusing on negative zero-variance prompts and weighting the signal by teacher mastery. The paper reports that using only 3.63% of the full data in this way outperforms standard OPD over all samples. Second, token selection restricts updates to high-entropy student tokens or tokens with large teacher-student divergence, reducing noisy gradients and slowing premature teacher imitation. Third, auxiliary SFT uses teacher-generated correct trajectories on negative zero-variance prompts, adding a global positive trajectory signal that OPD lacks when it conditions on erroneous student prefixes.1d:T40d,The method, HL-Gauss PPO, replaces the scalar MSE value head with a categorical head over a discretized value support. The critic is trained with cross-entropy against smoothed HL-Gauss targets. The actor side is unchanged: the categorical distribution is decoded into a scalar expectation, which is then used in standard GAE and PPO updates. This is not a distributional policy-improvement method; classification is used only as a surrogate objective for learning a scalar critic.

The paper includes controls for one-hot and two-hot targets, a Bernoulli two-bin baseline, support choices, and smoothing. These ablations separate several possible explanations: binary classification, extra output-head capacity, target smoothing, and the value-support parameterization. The main diagnostics are calibration and raw advantage dynamics. The MSE critic becomes overconfident on prefixes likely to fail and produces asymmetric advantages, while the HL-Gauss critic gives better calibrated scalar predictions and more balanced actor signals.1e:T8c4,The method has three layers. The first is task construction. Instead of training only on the composite SOS task, the authors build a nine-task curriculum: four local algebra operations, four broader structural tasks, and one weighted-SOS search task. The motivation is straightforward. If training starts only from the composite task, supervision is too sparse to teach which intermediate forms are useful for certificate assembly. The supporting tasks provide denser algebraic supervision and decompose the search skill into learnable pieces.

The second layer is supervised fine-tuning. Starting from Phi-4-reasoning-plus, they apply assistant-token QLoRA SFT on direct solutions and simulated symbolic traces. An important design choice is that the SFT corpus contains evaluated Python-like symbolic snippets, but not native function-call messages. In other words, the model first learns the semantics and trajectory patterns of tool use rather than memorizing an API protocol. Native tool calling is introduced only at deployment through four SymPy-backed functions. This separation is methodologically clean: it tries to teach when and why to use tools, not just how to format a call.

The third layer is verifier-grounded GRPO. The model is further optimized with task-specific symbolic rewards. For weighted-SOS, a terminal candidate is accepted only if it satisfies strict structural constraints: it parses into a finite sum, every weight is an exact positive rational, every summand is a polynomial square, and the expanded identity matches the target polynomial coefficient by coefficient. The key point is that reward is anchored to decidable correctness rather than fuzzy preference signals. Compared with generic math RL, the room for reward hacking is smaller because terminal acceptance is exact.

The main novelty is not a new optimization algorithm. It is the full loop: curriculum-style algebra supervision, simulated traces, native symbolic tools, and exact verifier-based rewards. Unlike many tool-use agent papers, this one deliberately stays inside a fully checkable algebraic domain, which makes it easier to separate tool reliability from strategy failure. The paper is also careful not to overclaim beyond this setting.1f:T80c,The experimental setup is fairly clear. Training uses 1.35 million synthetic examples spanning eight supporting tasks plus weighted-SOS. Evaluation uses 90,000 separately generated test instances. The complete system reaches 91.75% macro-average across the nine polynomial tasks. On the main weighted-SOS task, the Full system achieves 78.96% verified success, compared with 44.73% for the same backbone with the same tool interface but without the full post-training pipeline. That gap is the central empirical result: tool access alone is not the main source of gain; the algebra curriculum and verifier-grounded optimization are.

The paper compares Base, SFT, Base+Tools, and Full. The ablation is informative but not fully causal. In particular, it does not include SFT+Tools without GRPO or GRPO without tools, so the independent contribution of each component cannot be isolated cleanly. Still, the existing comparisons are enough to support the claim that simply attaching tools is insufficient, while the full training recipe materially improves composite symbolic search.

Two details matter for interpretation. First, the eight supporting tasks are solved directly without native tool calls in both training and evaluation, so their scores should be read as evidence of learned algebraic priors and intermediate-form competence, not direct evidence of tool-execution skill. Second, every weighted-SOS test polynomial is SOS by construction. Therefore, failure does not mean the instance is non-SOS; it means the search failed to find a certificate.
