5:T451,DiDPO extends group-relative advantage from the trajectory level into the internal structure of a code diff.

Using a CodeAct-like interaction loop, each action yields an edit (add/del/none) and the environment provides an outcome reward (e.g., tests pass/fail). Instead of treating the whole response/diff as one credit carrier, DiDPO:
1) Aligns diffs across multiple rollouts for the same task by finding highly similar sub-diffs that recur across trajectories.
2) Uses these recurring sub-diffs as anchors to induce sub-diff boundaries within larger diffs, aiming to isolate functional regions.
3) Groups aligned sub-diffs and computes a local group-relative advantage (diff-level advantage), then combines it with the trajectory-level advantage and assigns it back to the tokens responsible for generating those sub-diffs.

To avoid anchors that are too broad (mixing functions) or too narrow (hard to aggregate), it introduces a groupability score to select anchors that balance semantic scope and group mass. The method remains critic-free and claims no additional rollouts beyond the sampled group.6:T4cb,RSTG first analyzes GRPO, OPD, and SFT under a shared policy-gradient view. GRPO estimates advantages from group rewards; when all rewards in a group are identical, the advantage disappears. OPD minimizes reverse KL from the student to the teacher on student-generated trajectories and can be written as a token-level advantage based on the teacher-student log-probability gap. This dense signal is noisy and asymmetric because many student tokens have low teacher probability, producing mostly negative advantages. RSTG uses three controls. First, sample selection applies OPD only when the student fails and the teacher succeeds, focusing on negative zero-variance prompts and weighting the signal by teacher mastery. The paper reports that using only 3.63% of the full data in this way outperforms standard OPD over all samples. Second, token selection restricts updates to high-entropy student tokens or tokens with large teacher-student divergence, reducing noisy gradients and slowing premature teacher imitation. Third, auxiliary SFT uses teacher-generated correct trajectories on negative zero-variance prompts, adding a global positive trajectory signal that OPD lacks when it conditions on erroneous student prefixes.7:T40d,The method, HL-Gauss PPO, replaces the scalar MSE value head with a categorical head over a discretized value support. The actor side is unchanged: the categorical distribution is decoded into a scalar expectation, which is then used in standard GAE and PPO updates. This is not a distributional policy-improvement method; classification is used only as a surrogate objective for learning a scalar critic.

The paper includes controls for one-hot and two-hot targets, a Bernoulli two-bin baseline, support choices, and smoothing. These ablations separate several possible explanations: binary classification, extra output-head capacity, target smoothing, and the value-support parameterization. The MSE critic becomes overconfident on prefixes likely to fail and produces asymmetric advantages, while the HL-Gauss critic gives better calibrated scalar predictions and more balanced actor signals.8:T8c4,The method has three layers. The first is task construction. Instead of training only on the composite SOS task, the authors build a nine-task curriculum: four local algebra operations, four broader structural tasks, and one weighted-SOS search task. The motivation is straightforward. If training starts only from the composite task, supervision is too sparse to teach which intermediate forms are useful for certificate assembly. The supporting tasks provide denser algebraic supervision and decompose the search skill into learnable pieces.

The second layer is supervised fine-tuning. Starting from Phi-4-reasoning-plus, they apply assistant-token QLoRA SFT on direct solutions and simulated symbolic traces. An important design choice is that the SFT corpus contains evaluated Python-like symbolic snippets, but not native function-call messages. In other words, the model first learns the semantics and trajectory patterns of tool use rather than memorizing an API protocol. Native tool calling is introduced only at deployment through four SymPy-backed functions. This separation is methodologically clean: it tries to teach when and why to use tools, not just how to format a call.

The third layer is verifier-grounded GRPO. The model is further optimized with task-specific symbolic rewards. For weighted-SOS, a terminal candidate is accepted only if it satisfies strict structural constraints: it parses into a finite sum, every weight is an exact positive rational, every summand is a polynomial square, and the expanded identity matches the target polynomial coefficient by coefficient. The key point is that reward is anchored to decidable correctness rather than fuzzy preference signals. Compared with generic math RL, the room for reward hacking is smaller because terminal acceptance is exact.

The main novelty is not a new optimization algorithm. It is the full loop: curriculum-style algebra supervision, simulated traces, native symbolic tools, and exact verifier-based rewards. Unlike many tool-use agent papers, this one deliberately stays inside a fully checkable algebraic domain, which makes it easier to separate tool reliability from strategy failure. The paper is also careful not to overclaim beyond this setting.9:T80c,The experimental setup is fairly clear. Training uses 1.35 million synthetic examples spanning eight supporting tasks plus weighted-SOS. Evaluation uses 90,000 separately generated test instances. The complete system reaches 91.75% macro-average across the nine polynomial tasks. On the main weighted-SOS task, the Full system achieves 78.96% verified success, compared with 44.73% for the same backbone with the same tool interface but without the full post-training pipeline. That gap is the central empirical result: tool access alone is not the main source of gain; the algebra curriculum and verifier-grounded optimization are.

The paper compares Base, SFT, Base+Tools, and Full. The ablation is informative but not fully causal. Given a problem x and an on-policy trajectory y, every prefix is held fixed and each token y_i is rescored under two opposing privileged conditions: c^pos marks the whole trajectory as correct and c^neg marks it as wrong. The per-token log-likelihood shifts relative to the original policy are denoted z^pos_i and z^neg_i. If shifts truly encoded answer polarity, the two directions should have opposite signs and their magnitudes should distinguish correct from incorrect tokens. Instead, 82%–85% of tokens are insensitive under both conditions at λ=0.05; among jointly sensitive tokens, 91%–96% have the same sign under c^pos and c^neg, indicating that shifts mainly reflect generic reweighting of surface/connector tokens once a final-answer hint is provided, rather than answer polarity. Building on this observation, the paper proposes Counterfactual Sensitivity Credit Reallocation (CSCR), which uses the difference between the two counterfactual shifts, rather than their absolute magnitude, to measure a token’s true sensitivity to the outcome, and reallocates token-level advantages accordingly, avoiding uniform gradients on non-polar surface tokens.c:T6f8,CAST, short for Credit Assignment from Solver Teachers, uses the solver as a turn-level teacher. For an action a sampled by the LLM at state s, the solver evaluates the state before and after the action, V(s) and V(s'). Their difference defines a solver advantage indicating whether the action moved the trajectory closer to success. This scalar is then injected into the RLVR objective as a turn-level process signal, weighting policy updates at the action level.

The important point is not just reward shaping. The paper gives a distillation interpretation. Under a soft-optimal solver assumption, the log-probability of an action under the solver’s implicit action distribution is strictly proportional to its one-step state-value change. Therefore, maximizing a solver-advantage-weighted objective is equivalent to on-policy distillation toward the solver’s action preferences. This avoids the usual requirement for teacher logits: a solver that can provide state values or cost-to-go is enough.

To stabilize training, the method applies two lightweight transformations. First, an asinh transform compresses extreme solver signals while preserving resolution near zero; the paper interprets this as a robustified KL-style constraint. Second, batch-level RMS normalization removes scale mismatch across games and difficulty levels. Together, these steps make the process signal numerically stable and comparable across domains.

Compared with expert-trajectory SFT, CAST remains useful when the model visits off-expert states. Compared with cross-trajectory comparison methods such as GiGPO, it uses direct local feedback. Compared with learned process reward models, it does not require a separate dense-labeling pipeline, provided a solver or a good value estimator exists.d:T563,The experiments are run on Sokoban, Minesweeper, and Rush Hour, chosen to cover long-horizon planning, partial-observation inference, and constrained combinatorial search. The key observation is that the magnitude of the learning signal is governed by within-group reward variance. If all sampled responses for a prompt are either all correct or all incorrect, the group-relative advantage carries little discriminative information. If the group contains a mix of successes and failures, GRPO gets a meaningful comparison signal. Based on this, VIGOR replaces uniform rollout allocation with iterative refinement. Each prompt first receives a small initial number of rollouts. The algorithm estimates group-level reward variance from these partial samples, selects the prompts with the highest variance, and allocates additional rollouts only to them. This repeats until a fixed total budget is exhausted. The distinction from DAPO-style approaches is important: VIGOR does not first over-generate a larger pool and then filter. It allocates budget online during generation, which avoids paying extra rollout cost purely for selection. Compared with methods that improve utilization through stale rollouts or auxiliary signals, it leaves the GRPO objective unchanged and only changes where the rollout budget goes.
