19:T515,The paper introduces AgentSysBench, which combines a benchmark suite, a measurement toolkit, and a modular serving stack. The benchmark includes ten representative agentic applications spanning predefined versus LLM-driven control flow, different tool and environment interaction patterns, and long-running stateful execution. The instrumentation layer records LLM calls, tool invocations, and state operations, collecting latency breakdowns, resource usage, data movement, live state footprint, token behavior, and cost. The serving stack decomposes the system into separately deployable or co-locatable components: LLMs, embedding models, vector databases, sandboxes, browser or GUI environments, search services, and tool servers. This allows controlled experiments on provisioning and placement rather than treating the serving stack as fixed. Methodologically, the paper combines controlled experiments with production traces. The controlled side isolates application, model, request, and deployment variables; the production side exposes behaviors that synthetic workloads often miss. The contribution is therefore not a new scheduler or cache design, but a careful workload characterization that identifies six system properties distinguishing agentic workloads from conventional LLM inference.1a:T61c,The empirical coverage is substantial: 4,641 benchmark requests, 64,924 LLM calls, and 118,274 tool calls in controlled experiments, plus 178,799 production sessions from a single day. The main findings are sixfold. First, agent execution is heavyweight and stateful, and in 5 of 10 applications tools or environments dominate or co-dominate latency, so model-only optimization leaves much of the end-to-end path untouched. Second, the stack is highly heterogeneous: a single application may combine GPU-bound LLMs, memory-bound vector databases, CPU-bound sandboxes, and network-bound external services. Even tasks sharing one component can differ by up to 32x in latency, which makes single-queue scheduling prone to severe head-of-line blocking. Third, bottlenecks shift across requests, models, tools, and deployments; even a simple RAG pipeline can move its dominant cost between embedding and vector-database operations depending on the input, so static average-based optimization is inadequate. Fourth, production traces reveal many idle-but-live sessions that wait minutes to hours between steps while still holding conversational, tool, and environment state. Treating them as active wastes resources; treating them as finished loses resumability. The remaining findings, as indicated in the abstract, concern phenomena such as cross-request redundancy and control-plane overhead. The payoff variable is accepted length, the number of drafted tokens accepted at the current decoding state. The method combines two draft sources. The first is a parameter-free cache drafter, instantiated with a suffix cache similar to SuffixDecoding, which searches the prompt and generated history for suffix matches and reuses following spans.
