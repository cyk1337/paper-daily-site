Actions come from two modalities: MCP actions (structured tool calls following MCP) and GUI actions (click/type/scroll/shortcuts). A task τ includes a natural-language goal g, initial state s0, difficulty d, required skill categories c (six app-agnostic skills: retrieval, manipulation, search/query, execution/automation, navigation/browsing, configuration/settings), and an LLM-judge scoring function φ_judge. On top of this, EE-MCP proposes a fully automated self-evolving framework: multi-dimensional performance profiling to identify systematic weaknesses; automated environment generation and validation to create targeted tasks; trajectory collection with quality filtering; and two complementary evolution mechanisms—distillation and an experience bank. The experience bank extracts concise actionable rules via LLM-based trajectory comparison, organizes them by skill with capacity limits, and filters by application type to avoid cross-app contamination; it can improve inference without additional fine-tuning.
