9:T87c,方法很朴素，但实现细节做得比较完整。作者观察到，对 ReLU 或 ReLU^2 前馈层，反向传播所需保存的信息并不是完整 dense activation，而是两部分：哪些位置为正，以及这些正值本身。零值不需要存，正值的符号位也恒为 0，因此对 BF16/FP8 来说还可以进一步省掉 sign bit。基于这个观察，BitSparse 用两部分表示激活：一个 bitmask 记录非零位置，一个紧凑 value buffer 顺序存储所有非零值的 payload。这样在 backward 需要恢复激活时，再根据 bitmask 把非零值 scatter 回原位置，重建出与原始缓存完全一致的张量。

实现上，论文强调它是 GPU-resident 的格式，而不是离线压缩。压缩和解压都写成 Triton kernel，并融合进 autograd function。为了避免 host synchronization，作者使用预分配的共享 value buffer，并让 offsets 保持在设备端管理。解码采用 tile-parallel reconstruction，以降低 backward 时的访存和调度开销。支持的数据类型包括 BF16 和 FP8；可选的 sign-bit packing 会把正值的冗余符号位去掉，使压缩率更接近理论极限。

论文还给了一个信息论分析。作者把每个激活位置建模为：以概率 rho 为零，否则携带一个均匀分布的 (d-1)-bit payload。于是每个位置的最优平均码长由 support entropy h2(rho) 加上非零值的 payload 成本组成。这个分析给出了实现格式的理论上限和 break-even sparsity threshold：只有当稀疏度足够高时，bitmask + compact values 才比 dense 存储更省。这个部分的价值在于，它说明 BitSparse 不是“任何 ReLU 网络都稳赚”，而是依赖实际训练中出现的高稀疏度。作者在 Nemotron-H 上测得约 92% 的前馈激活稀疏度，因此落在很有利的区间。

从训练系统角度看，BitSparse 与 checkpointing 的取舍也很清楚。checkpointing 用重算换显存，几乎不依赖激活分布；BitSparse 用编码/解码开销换显存，但不需要重跑前向，且是无损的。它更像是第三条路径：当激活天然稀疏时，直接压缩缓存本身。a:T859,The core observation is simple but useful. For a ReLU or ReLU^2 feed-forward block, the information needed for backward is not the full dense activation tensor. It is the support of positive entries and the positive values themselves. Zero entries need not be stored, and positive values have a redundant sign bit that can also be removed for BF16 and FP8 formats. BitSparse therefore stores activations as two components: a bitmask for nonzero locations and a compact value buffer containing only the nonzero payloads. During backward, the original activation tensor is reconstructed exactly by scattering those values back according to the bitmask.

The implementation is designed to stay entirely on the GPU. Compression and decompression are implemented as Triton kernels and fused into a custom autograd function. To avoid host synchronization, the system uses a preallocated shared value buffer with offsets managed on device. Reconstruction is tile-parallel to keep backward efficient. The format supports BF16 and FP8, and optional sign-bit packing pushes compression closer to the information-theoretic limit.

A nice part of the paper is the entropy analysis. Each activation entry is modeled as zero with probability rho, otherwise carrying a uniformly distributed (d-1)-bit payload. Under that model, the optimal average code length per entry is the support entropy h2(rho) plus the expected payload cost of nonzeros. This gives a clean reference point for the achievable compression ratio and the break-even sparsity threshold. That matters because the method is only attractive when sparsity is high enough; it is not a free win for every ReLU network. The authors report about 92% feed-forward activation sparsity in Nemotron-H, which places the method in a favorable regime.

Relative to activation checkpointing, the trade-off is also clear. Checkpointing saves memory by recomputing forward activations later. BitSparse saves memory by encoding the cache itself, with no recomputation and exact recovery, at the cost of codec overhead. It is a third option that becomes compelling when activations are naturally sparse.b:T488,The experiments cover compression ratio, codec throughput, standalone MLP workloads, and end-to-end language-model forward/backward workloads. Three numbers stand out. First, in MLP tests, BitSparse reduces peak allocated memory by up to 48%. Second, in language-model training settings, memory per token drops by about 31% for Modded-NanoGPT and about 30% for Nemotron-H. Third, the decode path reaches roughly 97% of attainable bandwidth, suggesting the implementation is close to the hardware limit rather than being dominated by software inefficiency.

The paper also evaluates BF16 and FP8 support and shows additional gains from sign-bit packing. Runtime overhead is reported to be small, and the recovered activations are exactly equal to the original cached activations, which cleanly separates this method from lossy activation compression.

The main caveat is scope. The gains rely on ReLU or ReLU^2 activations and high sparsity.
