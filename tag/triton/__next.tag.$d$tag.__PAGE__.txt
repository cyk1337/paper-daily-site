9:T7a3,OmniKVQuant is a training-free extension of TurboQuant with two targeted modifications. TurboQuant decomposes each key/value vector into magnitude and direction, applies a randomized Hadamard rotation to the direction so coordinates look closer to a Gaussian reference, and then quantizes with a fixed codebook. This works reasonably well when one global reference distribution and one shared rotation are adequate.

The paper argues that this assumption fails in Omni-LLMs. The first fix is temporal range adaptation for keys. Even after Hadamard rotation, key coordinates still deviate substantially from the Gaussian target, and the mismatch changes over short temporal windows. Instead of using one fixed global range, OmniKVQuant performs coordinate-wise min-max scaling within a small local token group before codebook assignment. The codebook itself is not relearned; the local scaling simply adapts the same codebook to the current cache region. This is a minimal but well-motivated change that directly addresses local non-stationarity in keys.

The second fix is modality-specific value rotation. PCA visualizations show that audio, visual, and text values occupy distinct regions of representation space. A single shared rotation therefore cannot flatten all modalities equally well. OmniKVQuant calibrates separate rotations for each modality so that each value distribution is better aligned with the quantizer. The key idea is simple: modality-specific geometry persists inside a shared decoder, so the quantization stage should exploit it explicitly.

The paper also includes a fused Triton decode kernel. Instead of inverse-rotating every cached key, it rotates one query per head following a FlashAttention-style computation order. For values, inverse rotations are batched on head outputs rather than applied token by token to the cache. This reduces redundant rotation work and kernel launches without reconstructing a dense FP16 cache.a:T5c8,The analysis experiments are important because they justify the design. On Qwen2.5-Omni-3B evaluated with WorldSense, rotated keys retain only 30.40% of the variance of the Gaussian reference, with Wasserstein-1 distance 0.778 and KS statistic 0.449. The mismatch is stronger for audio and video than for text. Values are closer to the Gaussian target overall, but their cross-modal geometry is clearly separated. This supports the paper’s split treatment: local adaptation for keys, modality-aware correction for values.

For the main results, the method is evaluated on Qwen2.5-Omni and Qwen3-Omni. On seven audio-visual benchmarks with Qwen2.5-Omni, 2-bit KV caches retain 98.1% of FP16 performance and consistently outperform TurboQuant. The abstract does not list every benchmark score, but the paper presents the gains as stable across tasks rather than concentrated on one dataset. The trend also transfers to Qwen3-Omni, which suggests the method is not tied to a single model implementation.

From an engineering perspective, two takeaways matter most. First, 2-bit KV quantization is viable for Omni-LLMs, but only if the quantizer respects multimodal cache structure. Second, a training-free method can preserve most of the original performance, which makes it attractive for deployment without model retraining. When reading the full paper, the most informative ablations are the ones isolating temporal adaptation, modality-specific rotation, and their combination.b:T45d,A good reading order is: failure analysis, method fixes, kernel implementation, then headline results. Start with the introduction and the analysis table to understand exactly where TurboQuant breaks on multimodal caches; otherwise the method can look like a small patch. Then read the sections on temporal key drift and heterogeneous value geometry carefully. Those are the most informative parts of the paper. After that, inspect the two method components and ask why keys and values are treated differently instead of feeding both into a more complicated unified quantizer. Finally, look at the fused Triton kernel and the main benchmark table to judge practical deployability.

If time is limited, the problem analysis, method overview, and main results are enough for a 20-minute skim. For a deeper read, focus on the statistical diagnostics, the grouping/window design for local key scaling, how modality-specific rotations are calibrated, and how the kernel avoids inverse-rotating the whole cache.
