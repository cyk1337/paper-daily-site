18:T51a,The controlled dense experiments use looped models with 730M stored parameters and 2.9B unrolled parameter applications. Each looped model stores 28 Transformer blocks but executes a logical path of 112 block applications. The Ouro-style baseline is R28^4: a 28-block stack repeated four times. The Huginn-style model is P8 R12^8 C8: an 8-layer prelude, a 12-layer tied recurrent core repeated eight times, and an 8-layer coda, again totaling 112 logical block executions. Two feedforward anchors are used: D28, matching resident parameters, and D112, matching logical depth with independent parameters. The ablations show that the sandwich envelope gives the clearest gains, especially on math, context extraction, and reasoning-heavy tasks. Input injection improves knowledge retrieval and prompt-context utilization, but can hurt some quantitative reasoning. Random initialization is not consistently useful, and separate high/low recurrent states add complexity without dependable improvements. The full Huginn design outperforms Ouro on all ten dense benchmarks. In MoE experiments matched by resident and active parameters, Huginn again beats Ouro, balances expert load better, uses different experts across loop iterations, and approaches a larger feedforward MoE while storing far fewer parameters.19:T9a1,作者先搭了一个统一基线，把不同递归推理模型放到相同数据、相同输入输出接口、相近训练设置下比较。所有任务都被表示成 padded token sequence 输入，模型直接预测完整目标，不提供中间 supervision 或 chain-of-thought。这一点很重要，因为它避免把性能差异混进不同任务接口或中间标签设计里。

数据上，除了沿用 Sudoku、Maze、ARC-AGI，还加入了两个更可控的域。Game of Life 用来控制 sequential rule application 的步数，从而测 extrapolation beyond training horizon；Arithmetic 用逆波兰表达式恢复被 mask 的运算符序列，控制组合搜索难度，并设计了 operand multiset OOD 和 target range OOD。这样做的好处是，作者不只看 in-distribution 解题率，而是专门测“学到的递归计算”能否外推到更长计算链、更陌生输入结构和更远目标范围。

方法上，论文的重点不是提出一个全新架构，而是把递归模型的关键设计轴拆开做受控消融。根据引言，核心轴包括：
1. 梯度传播长度，也就是 credit assignment 穿过多少次递归展开。作者发现不是越长越好，而是存在 interior optimum。太短学不到长期依赖，太长则优化噪声、梯度不稳或 credit diffusion 变严重。
2. batch 形成方式。相同 effective batch 下，大 physical batch 明显优于 gradient accumulation。这说明递归模型对 step-level optimizer noise、归一化统计或硬件执行形态更敏感，不能简单套用常规 Transformer 的“累积等价”直觉。
3. recurrent-state stabilization。论文强调 latent state 更新必须被控制，否则共享 block 反复作用会导致状态漂移、爆炸或进入不稳定吸引子。虽然当前片段没有完整公式，但从表述看，最终 recipe 包含 controlled state updates 和 recurrence-specific regularization，可能类似残差门控、状态插值、更新幅度约束或归一化稳定器。
4. 架构容量与层级。作者比较显式 hierarchy、更大的 recurrent block、以及额外 test-time computation，结论是收益依任务而定，不存在统一占优配置。

最终模型是一个 13.6M 参数的稳定递归推理器，结合共享 recurrent computation、受控状态更新、中等梯度传播范围和针对递归的正则化。它更像一套训练 recipe 加一组结构选择，而不是单点创新模块。1a:T96b,The authors build a common training and evaluation pipeline for recursive reasoners. All tasks are cast into the same interface: a padded token sequence as input, and direct prediction of the full target, with no intermediate supervision and no chain-of-thought traces. This is an important control, because it removes confounds from task-specific interfaces or auxiliary labels.

The benchmark suite includes standard domains used by prior work—Sudoku, Maze, and ARC-AGI—and adds two more controlled domains. Game of Life lets the authors vary the number of sequential rule applications and test extrapolation beyond the training horizon. Arithmetic uses reverse-Polish expressions with masked operators, turning the task into a constrained combinatorial search problem with explicit OOD splits over operand multisets and target ranges. These additions make the study more informative than a pure in-distribution benchmark comparison.

The paper’s main technical contribution is not a brand-new architecture, but a controlled decomposition of the design space. The key axes are:
1. Gradient propagation horizon. The paper finds an interior optimum: too short and the model cannot assign credit across enough recurrent steps; too long and optimization becomes unstable or diluted.
2. Batch formation. At matched effective batch size, large physical batches outperform gradient accumulation. This suggests recursive models are unusually sensitive to optimizer noise, normalization behavior, or execution-level details.
3. Recurrent-state stabilization. Repeated application of a shared block can make latent states drift, explode, or enter unstable dynamics. The final recipe therefore includes controlled state updates and recurrence-specific regularization. The excerpt does not expose the full equations, but the mechanism is clearly about constraining how much the latent state changes at each recurrent step.
4. Capacity and hierarchy. The study compares explicit hierarchy, larger recurrent blocks, and extra test-time compute, and finds that their benefits are domain-dependent rather than universal.
