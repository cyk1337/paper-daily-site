18:T9a3,方法建立在 MARS 式 block-proposing AR 模型之上。具体做法是：从普通 decoder-only AR checkpoint 出发，追加一种带 placeholder 的训练/推理形式。给定上下文，在末尾附加 B 个 [MASK]/placeholder，模型在一次 causal forward 中同时预测未来 B 个 token。第 1 个位置仍等价于标准 next-token 预测；后面的位置则是在看不到中间真实未来 token 的条件下，对更远位置做条件预测，因此深度越深质量通常越差。ProVe 不改变 proposer 的训练方式，而是改变 proposal 之后的提交规则。

一次 ProVe cycle 分两步。第一步，proposer 一次前向生成长度 B 的候选 block y1...yB。第二步，verifier 读取“已实现的候选轨迹”，也就是把这段候选 token 当作真实前缀接到上下文后，再做一次前向，逐位置判断 proposer 给出的 token 是否应被接受。最终只提交从开头开始连续通过验证的最长前缀。这样做的关键点是：验证时每个位置都能条件化在前面已经提出的 candidate token 上，因此 verifier 看到的是 realized trajectory，而不是 proposer 在 placeholder 条件下的远距猜测分布。作者强调，这和 proposer 自己输出的置信度不是一回事；后者没有重新读取 candidate block，因此会系统性低估可提交长度。

论文给了两个版本。默认 ProVe 用较小 AR 模型做 verifier，得到速度—精度可调的近似解码。ProVe-lossless 则让 proposer 自己在第二次前向里验证自己提出的 block。由于第二次前向时模型读入的是 candidate block 的真实 token 序列，接受规则可以精确恢复 proposer 的 greedy AR 行为，因此是 lossless 的：输出与 proposer 逐 token greedy 解码完全一致，但把多个串行步压成了两次前向。这个设计很巧，等于不需要额外训练 draft head，也不需要单独的小 draft model。

和已有 speculative decoding 相比，区别有三点。第一，串行工作从“起草”转移到了“按 block 循环”，每个循环固定两次前向，而不是 B 次 token 级前向。第二，验证对象不是小模型草稿，而是大模型自己一次性提出的 block。第三，论文专门把 ProVe 与 MARS 的 confidence-only commit 做了受控比较：proposer、proposal block 都相同，只改变 commit rule，因此能比较干净地回答“多花一次验证 pass 是否值得”。19:T884,ProVe builds on a MARS-style block-proposing autoregressive model. Starting from a standard decoder-only AR checkpoint, the model is fine-tuned to predict the next B tokens in one causal forward pass by appending B placeholders to the context. Position 1 remains exactly the ordinary next-token prediction. Later positions predict farther future tokens without access to the intervening ground-truth tokens, so proposal quality naturally degrades with depth.

A ProVe decoding cycle has two passes. First, the proposer emits a candidate block y1...yB in one pass. Second, a verifier reads the realized candidate trajectory, meaning that the proposed tokens are now fed back as actual input tokens appended to the context, and the verifier decides how long a leading prefix should be accepted. The committed output is the longest contiguous prefix from the start that passes verification. This is the key distinction from confidence-based commitment: the verifier conditions on the realized candidate block, whereas the proposer’s original confidence scores were produced under placeholder conditioning and do not re-read the proposed sequence.

The paper studies two variants. In default ProVe, the verifier is a smaller AR model, giving a tunable speed-quality tradeoff. In ProVe-lossless, the proposer verifies its own block in a second pass. Because the second pass conditions on the realized candidate tokens, the acceptance rule can exactly reproduce the proposer’s greedy AR decoding. That makes the method lossless with respect to the proposer’s greedy output, while still collapsing many serial token steps into two passes per cycle.

Relative to standard speculative decoding, the differences are structural. Serial work is no longer delegated to a small drafter; instead, the large model proposes a whole block at once. Verification is applied to the large model’s own proposal rather than to a small model’s draft. The paper also makes a careful controlled comparison against MARS confidence-only decoding: the proposer and the proposed block are held fixed, and only the commit rule changes. This isolates the value of paying for one extra verification pass.1a:T77e,The most informative diagnostic is on GSM8K greedy continuations with block size 16. The proposed block contains an average AR-matching prefix of 6.6 tokens, but the default MARS confidence rule commits only 3.0 tokens on average. This is the central empirical motivation for ProVe: the proposer is already generating useful prefixes, but confidence-only commitment leaves much of that usable prefix on the table.

The main evaluation uses a 32B instruction proposer across six benchmarks. ProVe-lossless exactly reproduces the proposer’s greedy AR decoding while reaching 2.5x average throughput relative to standard AR decoding. Gains range roughly from 1.4x on short constrained outputs to 4.0x on more templated chain-of-thought style outputs. The paper also compares against a public EAGLE-3 head and a head fine-tuned specifically for the proposer, showing that ProVe-lossless, without training a separate draft head, outperforms the public EAGLE-3 setup and comes close to a proposer-specific head.

For a given prompt, the model’s autoregressive generation process is approximated as a bounded stochastic process over token prefixes. Starting from the prompt, BCA expands a bounded continuation tree up to a finite horizon, keeping only continuations that are sufficiently probable. Nodes are token prefixes, edges are next-token conditional probabilities, and terminal continuations are labeled as harmful or safe by a semantic harm evaluator. BCA then computes the probability of eventually reaching a harmful terminal within this bounded tree, which the paper calls bounded harm reachability.

Several design choices matter. First, harm is evaluated semantically at terminal continuations rather than by token-level heuristics, which better matches the actual safety question. Second, the score is probability-aware: it uses the model’s conditional distribution instead of only sampled outputs. Third, the formulation is grounded in probabilistic model checking, using a discrete-time Markov chain view and a reachability-style property analogous to “eventually reach a harmful state.” That gives the metric a clean formal interpretation.

The paper extends fixed-prompt analysis to adaptive attacks via Generative Attack Susceptibility (GAS). GAS maps an attack budget to the maximum bounded harm reachability among all prompts discovered so far by the attacker. An important practical choice is that the method does not attempt to estimate the full harmful probability over the entire output space.
