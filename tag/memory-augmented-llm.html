ConvMem: Convolutional Memory for Long-Context Reasoning

这篇工作处理的是一个很具体、也很现实的问题：当输入上下文远超模型原生窗口时，怎样在不重新训练模型、也不引入串行 memory agent 延迟的前提下，做相对可靠的长文档推理。作者针对的是两类现有路线的共同短板。第一类是直接扩上下文窗口，计算和延迟都很重，而且长上下文下常见 lost-in-the-middle，模型并不真正稳定利用远处证据。第二类是 MemAgent 一类顺序读文档、逐步更新记忆的方案，复杂度虽然线性，但推理路径是严格串行的，吞吐差；同时这类方法常依赖 RL 学记忆策略，容易在训练分布上学到捷径，回答看起来对，实际并没有忠实依赖给定上下文。ConvMem要解决的核心，就是把“长文档压缩+证据汇聚+最终回答”改写成一种可并行、层次化、训练无关的推理流程，并尽量减少顺序记忆链带来的误差累积和分布过拟合。

评把“长文档推理”从线性rollout改成对数深度树聚合，工程直觉对；但是否真比RAG/直接长上下文更干净，要盯住token预算与证据保真度对比。

PI-Mem: Pushing Long-Context Reasoning to 3.6M Tokens with Parallel-Iterative Memory

这篇工作处理的是超长上下文推理里的一个老问题：基于 recurrent memory 的方法虽然把计算从全局注意力里解放出来，但它们通常按 chunk 串行更新 memory，早期证据容易被后续无关内容覆盖，而且延迟会随 chunk 数线性增长。PI-Mem 试图同时解决这两个问题：既减少 memory overwrite，又把跨 chunk 处理改成并行。

评读方法图和 RL 退出奖励即可；若 3.6M 评测不是合成检索题，这会影响长上下文预训练预算判断。

MemGuard: Preventing Memory Contamination in Long-Term Memory-Augmented Large Language Models

记忆增强LLM中不同功能类型的记忆（用户事实、情景事件、行为规则）被混存在共享空间中，导致异质记忆污染——上下文特定事件被过度泛化，或功能不兼容的记忆误导生成。

评记忆增强LLM的失效模式分析有一定启发性，但属于应用层架构改进，与预训练核心方法论距离较远。
