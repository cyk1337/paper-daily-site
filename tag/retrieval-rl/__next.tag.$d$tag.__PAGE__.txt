a:T542,The method has two main components. The first is data construction. Instead of asking a strong model to freely generate multi-hop QA pairs, the pipeline starts with hard example mining: identify questions or document regions that the current base agent fails on, then use a frontier model to mutate or expand them into new multi-hop questions. A filtering pipeline follows, with two key checks. One is factual grounding, which ensures the question and answer are supported by source documents rather than model hallucination. The other is retrieval-solvability, which tests whether the question remains answerable in a noisy but high-recall retrieval setting. This is an important design choice: the target is not maximal difficulty, but a learnable difficulty band where RL can improve policy behavior. The second component is reward design. In addition to final answer correctness, the paper introduces a retrieval-aware reward that explicitly scores search quality and evidence selection. From the full text, this is meant to provide denser credit assignment than a pure outcome reward, so the model can learn which search actions were actually productive.
