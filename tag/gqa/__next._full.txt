18:Ta7b,方法核心是 Virtual Head Attention。出发点很直接：如果把物理 query heads 数量减半，再把 KV heads 压到 2，理论上可以同时降低 attention 计算和 KV cache；问题在于这样会损失 head diversity。VHA 的做法不是恢复真实的更多 KV heads，而是在 query 侧“造出”虚拟头的差异，并在输出侧补跨组信息交互。

第一部分是 Q Premix。设原始 query heads 为 Hq，压缩后物理 query heads 变成 Hq'，通常是原来的一半；KV heads 固定为 2，因此每个 KV group 会对应更多 query heads。Premix 在每个 KV group 内对 query 做一个接近恒等映射的线性变换，把较少的物理 query heads 扩展成更多“虚拟 query heads”。这里“接近恒等”很关键：如果一开始就做强混合，训练可能不稳定，也容易破坏原有注意力结构；近恒等初始化更像是在 GQA-2 的基础上逐步学出组内头部专门化。作者从训练后矩阵的直接可视化里观察到，Premix 学到的是 group-conditioned query specialization，也就是同组内不同虚拟头会形成有结构的差异，而不是无意义的线性扰动。

第二部分是 Linear Postmix。仅靠组内 Premix 还不够，因为 KV heads 只有 2，跨组的信息通道仍然受限。Postmix 在 attention 输出后施加一个低秩 identity-residual 变换 I + AB^T，其中秩 r 取 Hq'/2，例如 1.7B 模型里 r=4。这个设计的意图是用很小的额外参数和计算，把不同头、不同组之间的特征再融合一次。作者把它解释为 structured low-rank cross-head communication。与 MFA 通过增大 head dimension 来补容量不同，VHA 不去扩大每个头的宽度，而是在头之间做便宜的线性耦合，因此训练和 prefill FLOPs 不会上升，反而因为物理 query heads 减半而下降。

一个很漂亮的工程点是：Premix 和 Postmix 都是纯线性操作，没有非线性，也不依赖 token 位置或上下文状态，因此在推理时可以分别吸收到 WQ 和 WO 中。吸收后，线上模型就是一个标准 GQA-2 结构，完全复用现有 kernel 和 serving 优化，不引入额外 runtime overhead。这一点把它和很多“训练时好看、部署时麻烦”的注意力变体区分开了。

从对比关系看，VHA 与 GQA 的区别是：GQA 直接让更多 query heads 共享同一组 K/V，而 VHA 在共享前后都加了可学习线性补偿；与 MLA 的区别是：VHA 不做 latent KV 压缩，因此避免了 latent bottleneck 带来的质量损失；与 MFA 的区别是：VHA 不通过增大 head dim 来换质量，因此不会显著增加训练和 prefill 计算。19:T834,实验覆盖面比较完整。作者在四个基础规模上做了 4K context、50B token 预训练：0.6B、1.7B、4B dense，以及 8B-A1B MoE。结果是 VHA 在所有规模上都超过标准 GQA baseline，提升范围约为 +0.05% 到 +0.81%。这里绝对数值看起来不大，但要注意比较对象已经是很强的 GQA，而且 VHA 同时把 KV cache 压下去了。

以 1.7B 为例，GQA-8 的 KV cache 是每层每 token 4KB（BF16），直接降到 GQA-2 后变成 1KB，但会带来约 1.00% 的质量下降。MLA 的 cache 约 1.12KB，质量在多个尺度上最低。MFA 也能做到 1KB cache，质量接近 GQA-8，但在 1.7B、序列长度 4096 时训练和 prefill FLOPs 增加 49.8%。VHA 则在保持 1KB 级别 cache 的同时，相比 GQA-8 还把训练和 prefill FLOPs 降低了 7.9%，并且质量超过标准 GQA baseline。这正是论文所谓同时改进三角形三个顶点的证据。

更重要的是工业级验证。作者在 30B-A3B MoE、500B token、8K context 的设置下，VHA 在 12 个 base-model benchmark 上比 MLA 高 0.70%，比 GQA-4 高 2.60%。这说明方法在更大模型和更长训练下仍然成立，而不是小模型偶然收益。另一个 matched 10B-A1B MoE 对比把结论延伸到 128K context，在更激进的 KV 压缩下，VHA 仍保持优势。

The first is Q Premix. Within each KV group, Premix applies a near-identity linear transformation to the reduced set of physical query heads, effectively expanding them into a richer set of virtual query heads. The near-identity design is important. It keeps the model close to a stable GQA-2 parameterization early in training, while allowing the network to gradually learn structured specialization among heads that share the same KV pair. The authors’ matrix inspection suggests that this is exactly what happens: Premix learns group-conditioned query specialization rather than arbitrary mixing.

The second is Linear Postmix. Even with better within-group query diversity, using only 2 KV heads still limits cross-group interaction. 先看 MLA 的问题。MLA 训练和 prefill 时可以像 MHA 一样把 latent 展开成 per-head K/V 来算 attention；但在 decoding 时，为了省 cache 和带宽，会把上投影吸收到 query/output projection 里，直接对 latent 做 attention，也就是 absorbed MQA path。这个路径的 arithmetic intensity 在 H100 上接近 roofline，很合适；但它只有这一条路。因为所有 query head 都共享同一个 latent KV，head 维 tensor parallel 很难做零冗余切分；而且一旦做 MTP，额外 query token 会继续抬高算强度，在 H20 这类低 ridge point 设备上几乎没有吞吐收益。

Instead of effectively replicating them across all query heads, GQLA indexes them by groups. This small change allows the same trained parameters to support two algebraically equivalent decoding paths.

To understand the motivation, recall MLA’s behavior. During training and prefill, the latent can be expanded into per-head keys and values and attention is computed in an MHA-like form. During decoding, however, the up-projections are absorbed into the query and output projections so that attention runs directly against the latent, yielding an absorbed MQA-style path. This is excellent for H100 because the arithmetic intensity lands near the hardware roofline. But it is the only path MLA exposes. Since all query heads share one latent KV representation, tensor parallelism along the head axis becomes replication-heavy, and adding MTP further increases arithmetic intensity, which is especially harmful on H20-class devices.

GQLA keeps the same low-rank latent compression step via W^DKV, but changes W^UK and W^UV so that the latent expands into g KV groups rather than per-query-head representations. As a result, the trained weights admit two decode-time interpretations:
1) an MQA-absorb path, identical in spirit to MLA, where the cache stores the latent c^{KV} plus the shared RoPE key and all query heads attend directly to the latent; and
2) a GQA path, where the latent is materialized into per-group K and V tensors and decoding uses a standard GQA kernel.

The key point is that these two paths are algebraically equivalent over the same parameters. No retraining is needed to switch execution mode. The recommended configuration is h_q = 128 and g = 8, plus one MTP head. Under this setup, H100 can continue using the absorbed path and preserve MLA’s cache-efficiency sweet spot, while H20 can switch to the GQA path, lower effective arithmetic intensity, and recover throughput gains from MTP. The GQA path also enables up to 8-way zero-redundancy tensor parallelism along the group axis.
