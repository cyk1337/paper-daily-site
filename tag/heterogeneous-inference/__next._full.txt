19:T762,The method is simple but well structured. The paper characterizes prior systems as Planning-before-Trial (PbT): first decompose the problem, generate subproblems and a top-level scaffold, then solve recursively. PaT reverses this order. Given a coding task, a generator model first performs direct Best-of-N generation to produce candidate programs. These candidates are executed against a constructed test set in a sandboxed runtime. If any candidate passes all tests, the system returns immediately and avoids any planning overhead.

Only when all direct attempts fail does the system interpret that failure as evidence that the task exceeds the generator’s direct reasoning ability. At that point, a planner model is invoked to decompose the task into a top-level implementation plus subproblem specifications. Each subproblem is then solved recursively with the same trial-first policy: direct attempts first, planning only after failure. Once all subproblems have verified helper functions, they are composed back into the parent solution and re-verified on the parent test set. If the composed solution still fails, planning can continue recursively.

The key idea is not recursion by itself, but failure-triggered planning. The policy assumes that repeated failure under Best-of-N direct generation is a useful signal that more expensive decomposition is justified. In other words, verification is not only an evaluator; it becomes a gate for escalating compute.

The paper also emphasizes a heterogeneous configuration. The generator M_G and planner M_P need not be the same model. A small model can serve as the generator because many tasks are easy enough for cheap direct attempts, while a stronger model can serve as the planner for the minority of hard cases that require decomposition. This concentrates expensive model usage on planning rather than on all token generation.1a:T574,There are two main empirical claims. First, PaT consistently outperforms the representative PbT baseline FunCoder on cost-performance, achieving higher performance across model scales and benchmarks while using only about 60% of the inference cost on average. Second, the heterogeneous setup improves efficiency further: a small generator paired with a strong planner can come within less than 1% of a larger homogeneous setup while using only 31% of the cost.

The motivation is supported by the paper’s background numbers. For example, standard inference with Qwen3-4B already reaches 76% Pass@1, which means a large portion of tasks do not need planning at all. Some planning-first methods can even make a 4B pipeline more expensive than standard inference with a 32B model while still underperforming. PaT gains by exploiting this difficulty distribution.

When reading the experiments, do not focus only on final pass rates. Also check how often the planner is invoked on average, how Best-of-N is configured, how generator/planner model sizes are paired in the heterogeneous setting, and whether the gains mainly come from avoiding unnecessary planning on easy instances.
