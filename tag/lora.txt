18:T588,The architecture has three parts: a frozen backbone LLM, a safety-specific LoRA adapter, and a learned gate that outputs a continuous routing score g in [0,1] from hidden-state representations. The adapter is not simply turned on or off. Its strength is scaled continuously inside the model, with the effective transformation written as h' = (W + gΔW)h. This makes the method closer to interpolation between the base model and a safety-adapted model, rather than hard switching or post-hoc filtering.

A key design choice is that the gate is trained jointly with the safety adapter. It is not an external moderation classifier. The gate directly modulates internal computation during generation. The paper adds two training ingredients to make routing discriminative. First, subtype-aware gate weighting gives different emphasis to different harmful and benign prompt categories, aiming to reduce false positives on safety-adjacent benign inputs. Second, a hard pairwise margin objective explicitly separates harmful and benign prompts in gating space. This is important because plain generation loss may not force a clean routing boundary. Compared with standard safety LoRA, the novelty is not the adapter itself but the input-conditioned continuous activation. Compared with guard-model pipelines, the novelty is that routing happens inside the model’s latent computation rather than as an external pre-filter.19:T755,The evaluation covers safety with HarmBench and XSTest, and utility with GSM8K, MMLU, and TruthfulQA, using Llama-3-8B-Instruct and Gemma-2-2B-it as the main backbones. The paper’s case is not built on one isolated metric. It is built on a better trade-off point.

On Llama-3-8B-Instruct, CLEAR reportedly drives HarmBench attack success rate close to zero. Against existing aligned variants in the Llama-3 and Alpaca families, CLEAR reaches 0.50% ASR, while the compared aligned variants remain around 15.50% to 24.00%. At the same time, it retains 73.46% on GSM8K, about 7 points higher than globally applied SFT and standard LoRA. That is the most important result in the paper because it suggests the utility gain is not coming from weaker safety, but from selective intervention.

On Gemma-2-2B-it, the same pattern appears and is arguably more informative for smaller models: GSM8K improves from roughly 38% under SFT/LoRA to 42%, and TruthfulQA MC2 rises from about 47% to 53%. This supports the idea that smaller models suffer more from global safety tuning and therefore benefit more from conditional routing.

XSTest is used to probe routing quality rather than end-task generation alone. The hidden-state gate, with fewer than 1M parameters, is claimed to achieve a favorable harmful-versus-benign routing trade-off. That matters because it distinguishes CLEAR from simply adding another classifier in front of the model.

The most important ablations to inspect are the comparisons against always-on LoRA, removal of the pairwise margin objective, and removal of subtype-aware weighting. The central question is whether utility preservation truly comes from conditional routing rather than from a weaker safety adapter. If the paper shows CLEAR maintaining similar or better ASR while preserving noticeably higher GSM8K or TruthfulQA, then the argument is strong.1a:T412,Read it as a routing paper, not as another safety fine-tuning paper. Then read the training objective carefully, especially the subtype-aware weighting and pairwise margin terms, because those are the pieces that make the gate more than a soft classifier. If time is limited, 20 to 30 minutes is enough for a solid skim: Introduction for the alignment-tax framing, method section for the gate and losses, and the main result tables plus XSTest analysis. Two details are worth deeper inspection if available in the full text: which hidden states feed the gate, and whether the routing score is prompt-level, layer-specific, or token-dynamic during generation.1b:T4d1,The framework implements a closed-loop zeroth-order self-evolution pipeline: 1) Instance-specific LoRA modules are attached for each hard example. LoRA parameters are randomly perturbed, the agent is run under both original and perturbed parameters, and loss differences are used to estimate gradients for LoRA updates. The entire process only requires final answer supervision, with no intermediate trajectory annotation needed. 2) Parallel perturbation inference: All perturbation branches share the same backbone forward pass, allowing parallel evaluation of multiple LoRA perturbations with minimal extra compute overhead. 3) Adaptive lookup cache: Recent tool call results are cached, with exact or similarity-based reuse selected according to query type to reduce redundant tool invocations. 4) Answer perplexity surrogate loss: The negative log-likelihood of the reference answer conditioned on the generated trajectory is used as a process-level proxy signal, replacing sparse binary correctness rewards to stabilize zeroth-order optimization. LoRAs optimized via this pipeline can generate successful trajectories on hard examples, which are then added to the global SFT dataset to form a complete capability iteration loop.1c:T86f,方法设计很克制。它不替换原有 eviction 方法，而是在其前面加一个单次 restore pass。具体做法是：先对完整上下文做正常 prefill，得到 full KV cache；然后插入少量 restore tokens，文中默认是 8 个，这些 token 在一次额外前向中可以 attend 到 full cache。这个 restore pass 只在构造压缩 cache 时运行一次，并通过 LoRA 适配过的注意力模块，把上下文信息写入这 8 个 restore token 对应的各层 KV 中，形成 restore cache。之后再按原始 eviction 规则，从真实上下文 token 的 KV 中选出剩余预算的 retained cache；restore cache 与 retained cache 拼接后，组成总预算不变的最终 cache。

训练方式是离线 self-distillation。教师模型是 frozen full-cache model，学生模型使用 budget-matched final cache。给定同一 context 和 query，优化目标是让学生在 answer token 上匹配教师分布。更新参数非常少，只训练 restore token embeddings 和 restore pass 中的 LoRA；backbone 与 base evictor 都冻结。这个设计有两个关键点。第一，restore 不是通用前缀，也不是把整个 prefix 重写成新状态，而是只学习一个小补丁，因此兼容已有 importance scorer。第二，LoRA 只在 restore pass 打开，后续 query processing 和 decoding 完全沿用原始压缩 cache 的推理路径，所以在线开销几乎不变。

论文里最有信息量的部分是组件消融。作者把收益拆成“restore token 自身记忆了什么”与“注意力侧适配学会了如何从 full cache 提炼补偿信息”两部分。结果显示，仅优化 restore embeddings，KVzip 在 5% 预算下从 38.2 提到 42.1，提升有限；固定 embeddings、只学 LoRA 可到 71.9；只适配 q/k/v 投影就有 72.4，接近完整 RestoreKV 的 73.2。这说明主要收益来自 attention-side adaptation，而不是把常识或模板塞进几个特殊 token 里。换句话说，restore tokens 更像一组可学习的读写槽位，真正起作用的是它们如何从 full cache 中抽取并编码“被 eviction 后最容易丢失的补充信息”。1d:T830,RestoreKV is deliberately lightweight. It does not replace the base eviction method. Instead, it adds a single restore pass before eviction. The pipeline is: run normal prefill on the full context; insert a small number of restore tokens, eight by default; let those tokens attend to the full KV cache in one extra forward pass with LoRA-adapted attention layers; use the resulting per-layer KV states of the restore tokens as a compact restore cache; then apply the original query-agnostic evictor to the real context tokens and keep the remaining budget as retained cache. The final compressed cache is the concatenation of retained original KV pairs and the learned restore cache, with the same total KV budget as the baseline.

Training is offline self-distillation from a frozen full-cache teacher. For the same context and downstream query, the student using the budget-matched compressed cache is trained to match the teacher’s answer-token distributions. Only the restore-token embeddings and lightweight LoRA adapters are updated; the backbone model and the base evictor stay frozen. This design matters for two reasons. First, RestoreKV is a complement, not a rewrite: it preserves most selected original states and only learns a small residual cache. Second, LoRA is used only during restore-cache construction. After that, query processing and decoding are identical to the base method, so online inference cost is unchanged.
