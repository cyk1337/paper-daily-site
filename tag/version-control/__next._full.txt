18:T7a1,FedSkillGit is explicitly inspired by Git-style incremental collaboration. The server maintains a shared skill document d and a global experience document e. Each client has private train/validation splits and four LLM-based roles: an executor for task execution, a skill optimizer for local refinement, a sanitizer for privacy cleaning, and an auditor for private-value checking. Instead of uploading a rewritten full skill document, the client generates semantic commits: localized skill patches together with supporting experience summaries.

The pipeline has several stages. First, local skill evolution: the client executes tasks using the current global skill and global experience context, collects local successes and failures, and asks the optimizer to produce revisions. Second, two-stage privacy filtering: a sanitizer rewrites or removes sensitive content, and an auditor checks whether the commit still contains private values or environment-specific details. This is not formal differential privacy; it is semantic privacy filtering performed by LLM agents. Third, cross-round experience reuse: the server maintains a global experience document that accumulates reusable evidence over rounds and redistributes it to clients, reducing redundant rediscovery and making local optimization more informed. Fourth, experience-aware aggregation: the server uses a merge agent to combine commits with reference to the global experience document, rather than simply concatenating or voting over full documents. Fifth, version validation: a candidate updated skill is only published if it passes validation.

Relative to straightforward federated baselines, the key differences are the shift from document-level to commit-level updates, the inclusion of evidence alongside edits, and the explicit use of a shared experience memory. That makes the system closer to collaborative knowledge editing with validation than to standard federated averaging.19:T63a,The paper reports experiments on three datasets and three LM families. The headline result is that FedSkillGit outperforms the strongest baseline by up to 22% and approaches centralized performance. From the provided full-text excerpt, the most reliable takeaways are as follows.

First, overall effectiveness: the gains appear across multiple datasets and backbones, suggesting that the improvement is not tied to a single model family or task distribution. The paper positions the method against federated baselines that evolve and aggregate full skill documents, and the reported gap indicates that the update representation itself matters.

Second, communication and privacy motivation: because the method transmits semantic commits rather than full documents, the communication cost should scale with newly acquired knowledge instead of accumulated skill length. When reading the full paper, the most important tables and plots to verify are communication curves, average commit size, and how document growth behaves over rounds.

Third, ablations: the architecture strongly suggests useful ablations around removing privacy filtering, removing the global experience document, disabling version validation, and replacing commit-level aggregation with full-document aggregation. Those ablations are likely where the paper justifies why each component exists.
