9:T628,TideRL is an elastic asynchronous distributed system built around a shared global readiness view, with three core co-designed components: 1) Continuous Task Batching (CTB), which replaces request-level continuous batching on rollout ranks with task-level admission, preemption, and resumption. It tracks per-rank token memory footprints in real time, uses semaphores to control KV cache preemption priority, and actively pins KV caches for multi-turn tasks expected to resume soon, eliminating redundant prefill overhead from cache eviction during idle periods; 2) Resource-Aware Ref-Actor Pipelining (RA²P), which abandons fixed ref-actor execution modes on training nodes and dynamically switches between two modes based on current ready backlog size and data arrival interval: decoupled streaming mode places ref and actor on separate GPUs for large backlogs and fast arrival to avoid weight swapping thrashing, while colocated aggregation mode lets ref and actor share GPU memory for small backlogs and slow arrival to reduce cross-node communication. It also overlaps ref inference and actor gradient computation at the micro-batch level to eliminate idle bubbles; 3) Elastic Resource Scaling (ERS), which treats individual data parallel ranks as schedulable resources instead of statically assigning them to rollout or training groups. - The cluster is partitioned into M independent learners. Each learner runs an inner optimizer (e.g., AdamW) on its own data shard for multiple local steps.
- In DiLoCo, every H steps learners synchronize and an outer optimizer (often SGD with Nesterov momentum) treats inter-learner parameter differences as an “outer gradient” to update a global reference.
- Streaming DiLoCo shards parameters into P fragments to reduce peak bandwidth, but synchronization is still fundamentally blocking.
