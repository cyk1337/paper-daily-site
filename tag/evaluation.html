Inter-dimension Dependence for Multi-Dimensional Evaluation of Open-Ended Text

这篇工作处理的是一个常被忽略、但会直接影响 LLM-as-a-judge 可用性的问题：在多维文本评测里，模型是否真的在评“目标维度”，还是被其他非目标维度带偏。论文把这个现象定义为 inter-dimension dependence。比如评 relevance 时，judge 可能因为文本不流畅或不连贯而给低分，即便相关性本身并不差。这样一来，多维评测会退化成某种模糊的整体印象分，失去按维度诊断错误模式的意义。作者的核心目标有两个：先给出一个可量化的度量，判断这种维度串扰有多严重；再提出一个推理时干预方法，尽量让 judge 的打分依据只围绕目标维度展开。

评做 RLHF 或 judge-based eval 的人该看；不是范式突破，但把“多维打分其实在偷看别的维度”这件事量化了，先读 CorrGap 定义和消融。
Haoyuan Li,Snigdha Chaturvedi

BenchBench-Protocol: Evaluating Real-World Wet-Lab Protocol Reasoning and Modification

这篇工作解决的是一个评测问题：现有生命科学 LLM benchmark 虽然越来越开放式，但很多任务是专家“设计出来”的，不一定贴近真实实验室里科学家如何修改 protocol。BenchBench-Protocol 试图用真实工作流中发生过的 protocol 修改记录，构造一个更接近实际科研决策分布的 benchmark，考察模型是否能根据已有 protocol、实验目标和下游依赖，提出合理修改方案。

评看它的“diff→加权 rubric”构造法：比专家拍脑袋出题更干净；但领域偏湿实验，先确认你的 eval 需求再投入复现。

OmniJudge or OmniBias? Diagnosing Multimodal Judges through Balanced, Decoupled Lenses

现有多模态 judge / reward model 评测容易高估模型能力。原因是样本分布偏向正例和高质量输出，且多个失败模式常被混在一个总分里。模型即使不会识别细粒度错误，也可能靠数据先验拿到不错分数。D3-Omni 要诊断的是：OmniJudge 在 T2I、T2V、TTS 三类生成结果上，是否真正理解它正在打分的维度。

评做多模态自动标注或 judge 训练的人可以看；它不改预训练范式，但 benchmark 设计很干净，适合拿来检查你家的 reward/judge 是否只学会了偏置。

SA-Bench: Evaluating Semantic Alignment in LLM-Based Paper Reproduction

LLM coding agent 在复现机器学习论文时，常能生成可运行代码，却没有忠实实现论文规格。SA-Bench 把这种问题定义为 semantic drift，即代码在数值、方法、实验协议或执行顺序上悄悄偏离论文描述。

评把“复现”从跑通提升到“规格对齐”是对的；直接看 SAU 的定义与四类 drift 统计，能校准你对 coding agent 评测的预期。
