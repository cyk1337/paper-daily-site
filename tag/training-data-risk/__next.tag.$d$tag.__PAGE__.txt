9:T896,方法核心是 SAILS：Set-level Audit-Informed Iterative Learned Selection。它不是给每条样本打分后贪心选 top-k，而是直接学习一个“集合打分器”，把 poison set 当作一等对象。全文先从理论和经验两方面说明 pointwise influence proxy 的局限：如果真实攻击成功率不是逐样本加和，而是存在显著交互，那么优化单点 proxy 可能选出一组彼此冗余的样本，甚至在 proxy 更高时真实 success 更低。作者还指出，某些激进的 pointwise 优化会把搜索推向 proxy 的偏差区域，导致 true objective 下降。

SAILS 的流程是 propose–score–audit：
1. 先用少量 oracle query 构造训练集。这里的 oracle 是完整的 finetune-and-evaluate，一次代价很高，但能给出 poison set 的真实 attack success。
2. 训练一个 set scorer，输入是一个 poison set，输出其预估强度。论文的关键点在于 scorer 学的是集合层面的表征，而不是样本独立分数求和，因此可以捕捉冗余、覆盖、互补等交互。
3. 用该 scorer 在极大的组合空间里提出并排序海量候选集合，规模可到 millions of candidate sets。
4. 只对 top-ranked shortlist 做 oracle audit，拿到真实标签后继续回流训练 scorer，迭代进行。

这个设计的取舍很清楚：直接用 RL against oracle 虽然也能做组合优化，但查询成本太高；纯 pointwise 方法便宜，但目标错配。SAILS 介于两者之间，用学习到的 surrogate 排序大规模候选，再用少量真实训练校准。论文还强调一个实用性质：只要 scorer 能把至少一个强集合排进可审计 shortlist，最终就能返回接近最优的 poison set。这使它更像高召回的候选发现器，而不是必须全局精确排序的回归器。

The paper first formalizes poison selection as oracle-budgeted set optimization. An oracle query means a full finetune-and-evaluate run for one candidate poison set, which is expensive but gives the true attack success. The authors then analyze why pointwise influence proxies can fail: they assume the quality of a set decomposes into independent example-level effects. That assumption breaks once examples interact through finetuning. Individually strong examples may be redundant; individually weak ones may become strong in combination.

SAILS addresses this with a propose–score–audit loop:
1. Collect a small number of oracle-labeled poison sets.
2. Train a learned set scorer that predicts the strength of an entire poison set rather than summing independent item scores.
3. Use the scorer to rank millions of candidate sets.
4. Audit only a small top-ranked shortlist with expensive oracle queries.
5. Retrain the scorer on the audited results and iterate.

The design choice is practical. Direct RL against the oracle can optimize over sets but is query-hungry. Pointwise methods are cheap but structurally miss interactions. SAILS uses a learned surrogate to search the combinatorial space and spends oracle budget only where ranking quality matters. A useful property emphasized in the paper is that the scorer only needs to place at least one strong set high enough to be audited; it does not need globally perfect calibration. Another important result is transfer: a scorer trained on small-scale finetune-and-evaluate runs can generalize to full-scale finetuning, suggesting that some set-level signals are stable across training budgets.b:T558,There are three headline findings.

First, the variance induced by poison-set choice is large. In three LLaMA-3-8B backdoor settings, attack success spans 3% to 80% while everything else is held fixed. That alone is enough to challenge the standard random-sampling evaluation protocol.

Second, SAILS materially outperforms influence-based baselines. On the three LLaMA-3-8B settings, it improves held-out attack success by about 30 percentage points on average over the strongest influence baseline. This is not a marginal gain; it indicates that set-level interactions dominate the optimization problem.

Third, the pipeline extends beyond one narrow setup. The paper reports transfer to code-generation backdoors, agentic backdoors on Qwen3-4B, and API-only finetuning of Kimi-K2.5. On SmolLM-360M, SAILS nearly matches an oracle-guided RL baseline while using much less cost. That comparison is especially informative for researchers interested in expensive training-defined objectives: learned surrogate ranking plus selective auditing can be more efficient than direct RL over the oracle.

The most useful ablation-level insight is conceptual rather than cosmetic.
