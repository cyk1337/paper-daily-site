18:T5d3,TURTLE is a three-agent evolutionary pipeline:
- Task representation: tool-use tasks are encoded as Python programs (environment state, databases, tools, goals). This makes compositional mutation feasible and preserves compatibility with existing harnesses, but introduces risks of format/underspecification artifacts.
- Proposer: implemented via AlphaEvolve, a gradient-free evolutionary search operator. A practical point is that it can leverage strong closed-source LLMs as proposers via API calls, since no gradients/weights are needed.
- Solver: the target model under evaluation; each candidate mutated task is attempted N times to estimate an empirical completion rate.
- Fitness shaping: reward targets “hard but solvable” by pushing completion rates toward ~50%, motivated by maximal variance / maximal discriminative power near 0.5 (akin to learnability sampling).
- Feedback generator: summarizes failure reasons from execution traces plus the ground-truth solution, producing exploitable signals for the proposer’s next mutations.
- Post-filtering: an LLM judge (Gemini 3.6 Flash) removes trivial failures (format mismatches, ambiguous instructions, near-paraphrases), which is crucial to prevent evolution from exploiting loopholes.
- Dataset selection: after a fixed evolution budget, the final set keeps, per parent task, programs with the highest completion-rate variance, aiming for samples that best separate solver behaviors rather than simply maximizing difficulty.19:T510,Self-Credit is built on group-based RL, using a GRPO-like setup. For each query, the policy samples a group of trajectories, each receives a binary outcome reward, and a trajectory advantage is computed. Instead of applying this advantage uniformly to all tokens, Self-Credit introduces three components.

First, during rollouts, the policy generates summaries with citations to earlier turns that contain critical evidence. The summaries compact the long interaction history, while the citations become self-generated credit signals at the turn level.

Second, intra-group rescaling refines these credits. For the same prompt, the method compares cited turns across successful and failed rollouts. Turns that are repeatedly cited in successful trajectories and less common in failed ones receive stronger credit. Turns that also appear frequently in failed trajectories are downweighted or stripped of credit. This makes the signal less dependent on trusting the model’s citations in isolation.

Third, advantage reweighting applies the rescaled credit to the RL loss. Tokens inside highly credited turns receive stronger advantages, while unrelated turns receive less reinforcement. The method remains end-to-end and avoids training an additional critic or collecting dense human supervision.1a:T58f,REM (Reusable Experience Memory) introduces three explicit decisions, executed from within the agent’s loop:
1) What to store:
- Each completed run is a 55K–170K token trajectory with heavy exploration noise.
- REM consolidates it into a phase-structured document organized by four phases: localize, understand, fix, verify. This document is both the retrieval unit and the primary injected context, avoiding duplicated token spending.
- The design choice is deliberate: not raw trajectories (too noisy and context-hungry), not atomized factoids (lose solution structure).
2) When to recall:
- Two-tier read path: the phase document is injected at task start; a much costlier “implementation record” (fine-grained details closer to the original trace) is withheld.
- A struggle-gated in-loop node injects the implementation record only when the running agent appears stuck, leveraging the fact that the agent state is observable only inside the loop.
3) What to forget:
- The implementation record is evicted after a single exposure (one-shot eviction) to prevent persistent bias; the phase document remains for the whole run.
Additionally, the only domain-specific artifact is an extraction schema, which the paper claims can be automatically discovered from example trajectories. Premises are written in natural language over entities and attributes, and the model must select or generate the next inference step that can lead to the goal. Lookahead is defined as the number of future proof steps the model must search through to identify the correct immediate step. Training supervises only the single next-step output, so the measured capability is internal computation during one forward pass rather than explicit CoT expansion. The curriculum jointly increases lookahead and the attribute vocabulary. This joint curriculum works better than increasing lookahead alone, likely because it prevents the task from remaining too templatic and makes the difficulty ramp smoother. The paper compares curriculum training with direct training at target depth, varies curriculum step size, tests several model sizes, and contrasts pretrained and randomly initialized models. - Asynchronous architecture: on a single 8×B200 node, 2 GPUs train the policy while 6 GPUs run independent vLLM inference engines that keep generating rollouts while training proceeds. Weights are refreshed after every update, so a single multi-turn trajectory can span multiple policy versions.
