18:T468,The setup modifies DeepRD into a controlled next-step proof prediction task. Premises are written in natural language over entities and attributes, and the model must select or generate the next inference step that can lead to the goal. Lookahead is defined as the number of future proof steps the model must search through to identify the correct immediate step. Training supervises only the single next-step output, so the measured capability is internal computation during one forward pass rather than explicit CoT expansion. The curriculum jointly increases lookahead and the attribute vocabulary. This joint curriculum works better than increasing lookahead alone, likely because it prevents the task from remaining too templatic and makes the difficulty ramp smoother. The paper compares curriculum training with direct training at target depth, varies curriculum step size, tests several model sizes, and contrasts pretrained and randomly initialized models. A central technical point is that the curriculum step must be small enough; if the next stage is too far beyond the model’s current competence, learning stalls.19:T400,The headline controlled result is large: at matched compute, Qwen3-0.6B reaches 98% accuracy on problems up to lookahead 256 with curriculum training, compared with 45% without curriculum. Achieved lookahead grows with compute according to a saturating exponential fit, indicating diminishing returns and a possible maximum intrinsic lookahead for each model. Scale matters: Pythia-410M, 1.4B, and 2.8B have estimated maximum intrinsic lookaheads of 51, 82, and 235 respectively. Initialization matters as well: under a 1.5M PFLOP budget, Pythia-1.4B reaches lookahead 63 from pretrained weights, but only 23 from random initialization. Curriculum granularity is also decisive: Qwen3-0.6B stalls at lookahead 128 with step size 64, while step size 8 reaches 256. - Asynchronous architecture: on a single 8×B200 node, 2 GPUs train the policy while 6 GPUs run independent vLLM inference engines that keep generating rollouts while training proceeds. Weights are refreshed after every update, so a single multi-turn trajectory can span multiple policy versions.
- Off-policy control: a max_off_policy_steps threshold bounds policy staleness; rollouts exceeding it are dropped.
- Consistency constraints: align training and inference engines (tokenization, numerical/logprob paths) and maintain consistent cached state across policy updates to prevent importance ratios from being corrupted by implementation mismatch.
- RL objective/optimizer: CISPO-style token-level policy gradient with importance weighting; the importance ratio is detached and clipped (bounded at 2.0) to reduce variance and stabilize learning under asynchrony.
- Debugging via overfitting: filter a small solvable pool (160 tasks where Qwen3.5-4B passes tests at least once in 4 tries) and train to sustained memorization; failures (early reward gains that later collapse, etc.) are treated as signals of feedback/execution loop issues.
- Data comes after the baseline: execution-grounded filtering and issue refinement over combined task pools (R2E-Gym, SWE-rebench V2, Scale-SWE), plus “strengthening weak tests” to improve learning signal even if it reduces apparent mastery.1b:T620,NCE has three core components. First, it organizes the running context into addressable blocks. Each block is named by dedicated address tokens, and some blocks such as system prompts or tool declarations can be locked. Second, it defines an executable editing grammar inside the model vocabulary. The grammar includes address tokens plus operator tokens such as drop, rewrite, and append, together with composition rules for forming valid edits. A task-agnostic runtime maps each well-formed edit to exactly one context-state transition. This is the key design choice: edit semantics are not explained in the prompt or delegated to external tool schemas, but anchored in the model vocabulary and a fixed executor. Third, it builds supervision with a two-teacher pipeline. An offline teacher reads the full trajectory and assigns each block a release point, meaning the earliest turn after which the block can be safely edited because its role in the task has ended. An online teacher only sees the current context plus those release annotations and decides when and how to edit. The crucial training detail is evolving-context distillation: after an edit is generated at the end of a turn, the runtime executes it before constructing the next turn’s input and labels. This avoids conditioning future supervision on text that the model has already deleted or rewritten. The paper also includes a strong control baseline where the same edits are exposed as external tool calls, isolating the effect of native expression from the mere presence of an editing mechanism.1c:T474,The evaluation covers four long-horizon agent benchmarks: Terminal-Bench 2.0, SWE-bench Verified, SWE-bench Multilingual, and SWE-bench Pro. On LongCat with a 256K context window, NCE improves success rates by about 4.8 to 6.3 points over the base model across all four benchmarks, while reducing token usage by 31% to 44%. That combination matters: the gains are not coming from simply retaining more context. Against a tool-call editing baseline trained on the same edits, NCE is ahead by 5.2 to 8.0 points, which is the paper’s strongest evidence that native editing grammar has value beyond generic context editing. The gains transfer to Qwen3.6 as well, with an average success-rate increase of 4.5 points and a 15% reduction in average token usage. Even from the headline numbers alone, the paper makes a fairly clear case that native context editing improves both task completion and context efficiency.1d:T434,OPRD has three main components. First, Multi-Scope Reminder supervision separates global and local corrective signals. A Global Reminder converts final test diagnostics into trajectory-level guidance, while a Turn-local Reminder is anchored to an environment observation and applies only to the next decision. This avoids diluting local feedback over a long context or applying it to unrelated turns.
