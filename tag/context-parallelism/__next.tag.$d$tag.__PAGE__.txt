9:T6a9,The design has a single-GPU part and a distributed part. On a single GPU, FlashMask-3 builds on the column-wise sparse representation from FlashMask. The mask is indexed by key position, while each key stores query-axis intervals through four boundary vectors, commonly denoted LTS, LTE, UTS, and UTE for lower- and upper-triangular regions. This avoids constructing an n by n mask and gives the kernel a compact representation of valid query-key tiles. The new kernel integrates this representation into FlashAttention-3’s Hopper execution model. It uses three-role warp specialization: a KV Index Generator scans the boundary vectors and produces the relevant tile or KV indices, a KV Loader issues asynchronous TMA loads, and MMA Consumers run WGMMA compute. Mask handling is moved out of the main compute loop into a producer-like stage, which reduces branch overhead and keeps the asynchronous pipeline full. A preemptive persistent-tile scheduler is added to reduce SM-level imbalance under irregular sparse masks. For distributed context parallelism, the key observation is that the mask is keyed by K positions but stores Q-axis intervals. Under any multi-chunk CP assignment, a rank-local mask can be obtained by elementwise clipping, shifting, and max operations over the boundary vectors. No cross-rank mask exchange is needed, and the resulting local representation can be passed to the same kernel. The distributed system then adds a sparsity-aware hierarchical load balancer, HCC-IPO, topology-aware hierarchical routing for forward all-gather, mask-driven communication pruning, and a backward reduce-scatter path overlapped with attention recomputation using bitmask-AMO synchronization.a:T4ca,The evaluation covers microbenchmarks, context-parallel scaling, and end-to-end training. On a single H100, across 12 structured masks and sequence lengths from 4K to 128K, FlashMask-3 improves achieved TFLOPs over FlashMask by 45% to 141%, over FlexAttention by 34% to 71%, and over MagiAttention by 2% to 44%. These gains indicate that the improvement is not only from compact mask representation, but also from aligning mask-aware scheduling with Hopper’s TMA/WGMMA pipeline. In distributed context-parallel experiments with CP degrees from 4 to 32 and 8K tokens per device, it reaches 31% to 75% compute-communication overlap efficiency. Throughput improves by 1.80× to 3.71× over Megatron-Core CP ring, by 1.71× to 2.92× over Megatron-Core CP all-gather, and by 1.09× to 1.46× over MagiAttention. First, the paper introduces a simple cost model for remote KV hits. It uses per-token KV size s and GPU prefill rate R to define a break-even bandwidth B*=sR, plus a fixed per-hit overhead T0. The interpretation is straightforward: if the effective remote-tier bandwidth and fixed latency do not clear that threshold, a cache hit is not worth taking. Second, the authors redesign KV storage for PCP with MLA. In the original LMCache setup, only worker 0 stores and loads MLA KV because tensor-parallel ranks hold the same latent KV. Under PCP, however, all ranks advance in lockstep, so concentrating remote I/O on one rank creates a bottleneck. The paper replaces this with a sharded MLA KV store, where chunk storage, lookup, and loading are statically partitioned by rank. Rank r of every engine talks to its own server instance, which avoids extra cluster protocols and client-side hashing while preserving cross-engine reuse. The paper also proves that the scheduler’s existing minimum-over-ranks lookup still returns the longest cached prefix. Third, the execution path is repaired. Synchronous loading is replaced with asynchronous loading so that hit processing no longer blocks the engine step. The authors also fix three client bugs, including a lost-completion race and a missing-key read that could stall indefinitely, and add regression tests. The key idea is not an API trick but moving remote-hit handling off the blocking critical path while keeping the load protocol compatible with collectives: every rank issues the same collectives, avoiding deadlocks and inconsistency.d:T4de,The experiments are the strongest part of the paper because they are driven by production trace replay rather than only synthetic microbenchmarks.
