Mach-Mind-4-Flash Technical Report

这篇技术报告要解决的是一个很现实的问题：在不继续显著扩大预训练算力的前提下，能否把一个推理时只激活 3B 参数的 35B MoE 基座，通过更强的 post-training 管线，推到接近甚至进入 100B 级模型的能力区间。更具体地说，作者面对的是三个耦合难题：一是 RL、蒸馏、multi-turn agent 训练通常是分裂的系统，工程和优化目标不统一；二是把 reasoning、general、agent 三类能力混在一个 reward mixture 里训，容易出现能力跷跷板；三是强推理模型常常输出过长，服务成本高，但简单压长度又容易 reward hack 或伤准确率。

评对预训练本身帮助有限，但它在讲一个更现实的问题：post-train 到底能榨出多少能力；先看 MOPD 和 mixed-reward 退化分析，别先信 headline。

Zamba2-VL Technical Report

这篇技术报告要回答的问题很直接：在开放权重 VLM 里，能不能把混合 SSM-Transformer 语言骨干真正做成一条可用路线，而不是只停留在“更快但效果差一些”的替代品。更具体地说，它针对两类长期矛盾：一是 Transformer VLM 在高分辨率图像、长视觉序列、视频场景下，prefill 和 KV cache 成本增长太快；二是纯 Mamba/SSM VLM 虽然推理便宜，但在 grounding、细粒度检索、依赖精确上下文读取的任务上往往掉点。Zamba2-VL 试图用 Zamba2 的混合骨干把这两个问题一起处理：让大部分序列建模走线性时间的 Mamba2 路径，只保留少量共享 Transformer block 负责内容寻址和精确检索。

评先只看训练阶段划分、数据配比和连接器设计那几页：如果细节够“可抄”，就值回票价；否则当营销稿处理。

EXAONE 4.5 Technical Report

评重点翻训练配方与视觉token吞吐优化细节：能直接对照你们的VLM工程取舍；但作为tech report，结论更像系统集成经验，别当因果证据。
