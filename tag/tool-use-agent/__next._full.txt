18:T875,AgentBrew has three stages. First, it collects a one-shot raw trajectory corpus in the target environment. The agent explores the live state of the application, proposes grounded tasks, and executes them. Importantly, the collected trajectories are not filtered by quality. This design choice is central: in real applications, interaction is expensive and success rates are low, so discarding most trajectories is not viable.

Second, the framework performs retrospective task inference. Instead of treating the original instruction as the only valid label, it infers what the trajectory actually accomplished by looking at the action sequence, tool calls, state transitions, and final outcome. This produces an aligned instruction-trajectory pair. The motivation is clear: many trajectories fail at their original goal but still complete some related or partial task. If trained against the original instruction, they become mislabeled supervision; if discarded, they become wasted data. Retrospective inference repairs this mismatch by relabeling behavior according to realized effects.

Third, AgentBrew applies PMI-based credit assignment. The total information a trajectory provides about its inferred instruction is written as pointwise mutual information, and then decomposed into additive per-action contributions using the chain rule. Intuitively, an action receives high credit if it substantially increases the evidence that the inferred task has been accomplished, and low credit if it is redundant, ineffective, or off-target. These per-action credits are then used as sample weights during policy training, amplifying gradients from informative actions and suppressing noisy ones. This is a more data-efficient alternative to rejection sampling or trajectory-level filtering, because useful local behavior can be retained even inside globally unsuccessful trajectories.

Conceptually, the method sits between behavior cloning and offline RL. It does not optimize with online interaction, and it does not assume a reward model or verifier. Instead, it reconstructs latent task structure from raw logs and then performs weighted offline policy learning.19:T57d,The evaluation is conducted on three real MCP applications: GitHub, Notion, and PostgreSQL. These are live, stateful tool environments rather than simulators, which makes the setup more convincing than synthetic agent benchmarks. AgentBrew improves over the Qwen3-32B base model by +8.7 accuracy and +9.7 score on average, and it even surpasses the larger Qwen3-235B. Against rejection sampling, it gains +5.9 accuracy and +10.3 score. That comparison is important: it suggests that better supervision extraction from the same raw data can matter more than scaling the base model.

The paper also provides mechanism-level evidence. One line of analysis tests whether retrospective task inference really converts failed trajectories into usable supervision. Another examines whether PMI-based action weighting is better than uniform weighting or trajectory-level selection. The ablations indicate that removing either task inference or action-level credit assignment leads to clear degradation, which supports the claim that the gains come from finer-grained supervision rather than simply from using more data.

A notable aspect of the setup is that all learning after data collection is fully offline. There are no iterative on-policy rollouts to rescue the method. This makes the result more meaningful for real deployment settings, where additional environment interaction is often the main bottleneck.1a:T53b,This one is worth a close read. Then focus on the two core method sections. Second, go through the PMI-based credit assignment in detail. It is worth checking the derivation of how trajectory-level PMI is decomposed into per-action terms and how those credits enter the training objective.

In the experiments, prioritize the main comparison tables, the rejection-sampling baseline, and the ablations on task inference and credit assignment. If there are qualitative examples or human evaluation snippets, they are especially useful because the main risk of this framework is whether relabeling is genuinely faithful. Three good questions to keep in mind are: whether task inference merely reframes failure as success, whether PMI credits are stable or biased toward superficially informative actions, and how well the framework might extend to longer-horizon or more state-dependent agent settings.
