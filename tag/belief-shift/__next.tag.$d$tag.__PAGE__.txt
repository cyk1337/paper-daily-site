9:Ta7c,方法很统一：先在一条已生成的 chain 上定义 candidate boundaries，然后在每个 boundary 读取模型此刻对最终答案的“信念”，再用相邻 boundary 之间的 belief change 给前一段打分，选择得分最高的位置 fork。关键细节有两个。其一，作者采用 fork-before attribution：如果 belief 在区间 (t-, t] 发生了明显变化，说明真正起作用的是这一段，因此分数记到 t-，让 siblings 从该步之前重新展开，去估计这一步的 advantage。其二，作者给了三种不同 access level 的 belief readout。

第一种是 PROBE-JS，属于 black-box 方案。做法是在每个 boundary 插入一个很短的 probe，类似“所以你的最终答案是什么”，采样得到 answer distribution，然后计算相邻两个 boundary 的 Jensen-Shannon divergence。JS 大说明模型在这一步前后对最终答案的分布发生了明显变化，可能是关键推理步，也可能是犯错点。它的优点是只需要 sampling access，不依赖内部状态；缺点是每个 boundary 都要额外生成一小段 probe answer。

第二种是 LENS-SHIFT，属于 white-box 方案。它不让模型显式回答，而是用 logit lens 读取各层对最终答案的承诺强度，形成一个 depth profile，再比较相邻 boundary 的 profile 变化幅度。这个设计的意思是：belief shift 不一定只体现在最后一层 logits，也可能体现在整条深度方向上的表征重排。相比 probe，它没有额外 generation cost，但需要访问 hidden states，并且依赖已知 final answer 作为 readout target。

第三种是 BSV（Belief-Shift Vector）。作者先离线收集高置信与犹豫状态的 activation，对比拟合出一个“confidence shift”方向，之后只需把 boundary hidden state 投影到这个方向上即可打分。它更像一个 amortized readout，用很低成本近似直接测量 belief shift。论文里它主要用于 pre-RL validation，验证如果能更直接地读到 belief shift，是否会更贴近 Monte-Carlo ground-truth value curve。也就是说，BSV 更像分析工具，而不是主训练时的标准配置。

与现有方法相比，差异很明确。固定网格、midpoint、delimiter 这类结构式方法完全不看该步是否决定 outcome；entropy/surprisal 方法看的是局部 token 不确定性，容易被措辞自由度、同义改写、代码表面分支等因素放大，却不一定对应最终答案会不会变。作者强调，belief-shift 关注的是 answer belief 的变化，而不是 next-token freedom，这个目标更接近 tree RLVR 真正需要的“高价值分叉点”。a:T75c,实验分成两层。第一层是 RL 前的 selector 诊断。作者用 Monte-Carlo 估计 ground-truth value curve，把不同 selector 选中的 fork 点与真实 value movement 对齐，衡量谁更能抓住关键转折。文中给出的代表性例子里，在相同 10 个 fork 预算下，Probe-JS 捕获的总 value movement 是 entropy 的 3.6 倍，数值为 1.56 对 0.44；entropy 有 6 个 fork 浪费在 V*=1 的 settled region。更重要的是，belief-shift 信号在 8 个 model×benchmark panel 中都排第一，超过 entropy、结构式 baseline 和 LLM-judge baseline，并且能 zero-shot 转移到 out-of-domain benchmark。这个结果说明它不是只在某个模型或某个任务模板上偶然有效。

第二层是实际 RL 训练。作者在 matched budget 下比较四个只差 fork criterion 的训练臂，覆盖三类模型家族、数学和代码两个领域。摘要和正文给出的关键结果是：belief-shift 分叉在所有数学 aggregate 上领先，在 OLMo-3-7B 的 AIME 2026 上比最强 baseline 高 2.9 分；在 OLMo 代码实验的所有列上也全部领先。虽然这里没有给出每一列完整数字，但从描述看，收益不是单点偶然，而是跨 domain、跨 family 都比较稳定。

Its contribution is useful in three ways. First, it cleanly separates two roles that are often conflated in tree RL: the tree structure converts sibling outcomes into step credit, while fork placement determines whether those credits are informative. Second, the belief-shift view is more aligned with “which step actually changed the model’s answer belief” than entropy-based uncertainty, which is a meaningful design principle for reasoning-trace supervision. In scale, this looks like a solid training-recipe improvement rather than a new learning paradigm, but if tree RLVR becomes standard, fork policy could become a default component of the stack.c:Ta8d,The framework is simple and consistent. For a generated chain, define candidate boundaries. At each boundary, read the model’s current belief about the final answer. Score each segment by the amount of belief change between consecutive boundaries, and fork at the highest-scoring location. Two details matter.

First, the paper uses fork-before attribution. If belief changes sharply over segment (t-, t], the causal step is that segment, so the score is assigned to t- and sibling continuations are re-rolled from just before the belief-moving step. This aligns the counterfactual branch with the step whose contribution is being estimated.

Second, the paper instantiates belief readout at three access levels.

PROBE-JS is the black-box version. At each boundary, the model is interrupted with a short probe such as “so what is your final answer?”, and the resulting answer distribution is sampled. The score is the Jensen–Shannon divergence between consecutive boundary distributions. Large JS indicates that the segment caused a meaningful shift in answer belief. The advantage is that it only requires sampling access; the downside is extra generation at every boundary.

LENS-SHIFT is the white-box version. Instead of making the model answer explicitly, it uses a logit-lens style readout to measure how strongly each layer already commits to the final answer, producing a depth profile at each boundary. The score is the change in this profile across adjacent boundaries. The motivation is that belief shifts may appear as representational reorganization across depth, not only as a change in final logits. This avoids extra generation but requires hidden-state access and a target final answer for readout.

BSV, or Belief-Shift Vector, is an amortized readout. The authors fit an activation direction offline by contrasting high-confidence and doubtful states, then score a boundary by projecting its hidden state onto that direction. In the paper, BSV is mainly used for pre-RL validation: if one could measure belief shift more directly, would it align better with the Monte-Carlo value curve? So BSV functions more as an analysis instrument than the default online training method.

The distinction from prior selectors is sharp. Fixed grids, midpoints, and delimiter-based rules ignore whether a step actually changes the outcome. Entropy or surprisal tracks local token uncertainty, which is often inflated by paraphrase freedom, stylistic variation, or surface branching in code, without implying any change in final answer. Belief-shift branching instead targets answer-belief movement, which is much closer to the quantity tree RLVR actually needs: high-value branch points.d:T7cf,The evaluation has two layers. The first is pre-RL selector diagnosis. Using Monte-Carlo estimates of the ground-truth value curve, the paper measures how much true value movement is captured by the selected fork points. In the representative example highlighted early in the paper, with the same budget of 10 forks, Probe-JS captures 3.6× more total value movement than entropy: 1.56 versus 0.44. That is important because it suggests the signal is not tied to one model family or one task template.
