18:T724,The setup is formalized as follows. Let q be the parallel drafter with block length L. Its distribution at position l, q_l(.|c), depends only on the current context c. The verifier p is autoregressive, so its distribution at the same position is p_l(.|c, x_<l), which depends on the sampled prefix inside the current draft block. Therefore, for a fixed student head q_l, different sampled drafts induce different teacher distributions. Existing on-policy distillation methods effectively supervise the same student prediction with these separate, potentially conflicting conditional targets. This creates an averaging problem: the student is asked to imitate multiple incompatible teacher views while lacking access to the within-block prefix that generated them.

MDraft solves this by aggregating verifier feedback across multiple drafts before constructing the training target. Intuitively, it tries to estimate which tokens are broadly useful for acceptance at a given position under the distribution of plausible prefixes, rather than which token is preferred under one particular sampled prefix. That is a better match to the structure of the parallel drafter, because the drafter cannot observe those prefixes in the first place.

The key contribution is therefore not a new model architecture but a new teacher-target construction for on-policy distillation. Instead of forcing an autoregressive conditional distribution directly onto a prefix-agnostic parallel student, MDraft approximates a marginal target over multiple sampled drafts. The paper’s argument is strong on this point: if the real objective is to maximize speculative acceptance rather than to minimize teacher cross-entropy under a mismatched conditioning structure, then the training target should reflect acceptance utility across possible prefixes.19:T4a5,The main metric is acceptance length, not standard language-model perplexity. The authors fine-tune parallel drafters and evaluate them on mathematical, coding, and conversational benchmarks. MDraft achieves the best overall mean acceptance length among the on-policy distillation baselines considered, meaning that the verifier accepts more drafted tokens per pass and speculative decoding becomes more efficient. The abstract does not expose the full numeric table, but the body indicates that the gains are consistent across task types rather than confined to a single domain.

More importantly, the experiments support the mechanism claim. When verifier targets from different sampled prefixes are distilled separately, the student becomes overly conservative and acceptance drops. Aggregating verifier information across multiple drafts produces a student distribution that better matches what the verifier is willing to accept in actual use. 第二，浅层筛查。候选块整体先推进到 screening depth ds，而不是直接跑满总深度 D。在 ds 处，用每个前驱位置的 shallow next-token prediction 去检查后继 copied token 是否一致。具体是找从 head 开始的最长连续通过前驱预测校验的前缀；通过的部分保留，后缀立即裁掉，并释放其 KV / hidden state。这个设计比最终深度才发现错误更省，因为错误复制通常会在较早位置暴露，没必要让整段错误 tail 继续消耗深层 recurrent 计算。

第三，连续调度与因果提交。保留下来的 token 继续向更深层推进，同时最近一个保留位置立刻作为下一块的起点，允许新块在旧块尚未 full-depth 验证完成时进入流水线。最终只有达到 full depth 的位置才按因果顺序提交输出。论文强调，真正的收益来自 shallow screening 和 continuous scheduling 的配合：如果只是筛查但不让新块提前进入，流水线填充不足；如果只连续推进但不筛查，错误复制会污染后续深层计算，浪费算力。

First, block construction. Given a prefix p, the model predicts a fresh head token h. Then CopyLoop performs suffix matching over p concatenated with h, looking for the longest matching suffix in earlier context, similar in spirit to prompt lookup decoding. From the matched location it copies up to K following tokens as a tail, producing a candidate block B=(b0,...,bk) with b0=h. If no useful match exists, it falls back to a single-token block.

Second, shallow screening. Instead of sending the whole candidate block directly through the full recurrent depth D, the block is advanced only to a screening depth ds<D. At that depth, each copied token is checked against the shallow next-token prediction of its immediate predecessor. The algorithm keeps the longest prefix of copied tokens that agrees with predecessor predictions and prunes the remaining suffix immediately, including its KV and hidden-state footprint. This is the key efficiency move: copied tails are cheap to propose, but many are partially wrong, so the method tries to detect disagreement before deep recurrent compute is spent.

Third, continuous scheduling with causal commitment. Tokens that survive screening continue toward full-depth verification, while the latest retained position immediately seeds the next candidate block. This allows newer blocks to enter the pipeline before earlier ones finish full verification. Final outputs are still committed only in causal order once they reach full depth. The paper argues that the gain comes from the interaction between shallow screening and continuous scheduling: screening alone saves some wasted deep compute, but scheduling is what turns that into latency reduction; scheduling alone would let many bad copied tails consume deeper passes.

Compared with prior self-speculative decoding, the differences are clear. Drafts are not generated token by token from intermediate passes; they are block proposals composed of one fresh head plus a copied tail. Verification is not only a final accept/reject step; there is an explicit shallow recurrent filter. And the execution pattern is a recurrent pipeline rather than a clean two-stage draft/verify setup. The method is training-free and uses existing model readouts.1c:T577,The evaluation covers six checkpoints from the Ouro, Raven, and Huginn looped-Transformer families: four Base models and two Thinking models, on code generation and mathematical reasoning workloads. On the inference side, the paper starts from two static extremes. One is pure sliding-window attention, which always keeps the most recent B tokens. The other is prefill-based selection, where a fixed subset of prompt KVs is chosen once using aggregated attention scores, as in SnapKV. Sliding window is strong on recency but weak on remote context. Prefill selection preserves long-range prompt information but becomes stale as decoding progresses. RIFT combines the two. The KV budget is explicitly split between recent generated tokens and importance-selected historical tokens. This preserves local continuity while still keeping a sparse set of long-range anchors.

The second idea is decode-time refresh. The importance-selected subset is not frozen after prefill; it can be recomputed periodically during generation. That lets the retained historical context adapt to the current decoding state. The trade-off is extra latency, so RIFT is presented as a family of strategies with different refresh frequencies and complexity/quality trade-offs.

The training-side contribution is compression-aware knowledge distillation. The authors argue that a drafter trained with full context but deployed with compressed context suffers from a substantial mismatch. To address this, they distill under compression-driven attention masks that mimic the inference-time cache restriction. The student is therefore optimized to match the teacher/target distribution under limited context visibility, rather than under an unrealistic full-cache condition.

A ProVe decoding cycle has two passes. First, the proposer emits a candidate block y1...yB in one pass. Second, a verifier reads the realized candidate trajectory, meaning that the proposed tokens are now fed back as actual input tokens appended to the context, and the verifier decides how long a leading prefix should be accepted. The committed output is the longest contiguous prefix from the start that passes verification. This is the key distinction from confidence-based commitment: the verifier conditions on the realized candidate block, whereas the proposer’s original confidence scores were produced under placeholder conditioning and do not re-read the proposed sequence.

The paper studies two variants. In default ProVe, the verifier is a smaller AR model, giving a tunable speed-quality tradeoff. In ProVe-lossless, the proposer verifies its own block in a second pass. Because the second pass conditions on the realized candidate tokens, the acceptance rule can exactly reproduce the proposer’s greedy AR decoding. That makes the method lossless with respect to the proposer’s greedy output, while still collapsing many serial token steps into two passes per cycle.

Relative to standard speculative decoding, the differences are structural. Serial work is no longer delegated to a small drafter; instead, the large model proposes a whole block at once. Once these hazards are estimated, the controller can evaluate the expected throughput of each horizon.

The main difficulty is partial feedback. If the system chooses a short horizon, it never observes verification outcomes for later positions.
