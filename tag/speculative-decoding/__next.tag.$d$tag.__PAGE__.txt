第一步，使用 block-diffusion head 对一个长度为 B 的未来块同时建模。这里的关键不是把整个模型改成 diffusion LM，而是把 diffusion 式并行去噪/填充能力用作 speculative drafting head：给定当前已提交前缀和目标模型已经融合好的 vision-language hidden states，head 在一次前向里输出整个 block 各位置的分布。这样 depth 不再对应 k 次 sequential draft pass，而是一次 draft pass 就覆盖 k 个未来位置。

First, a block-diffusion head predicts a whole future block of length B in parallel. The key point is that the target model itself remains unchanged and autoregressive; the diffusion-style component is only the drafting head. Given the committed prefix and the target’s already fused vision-language state, the head outputs token distributions for all positions in the block in a single forward pass. Second, GLANCE constructs a wide candidate tree from the block-level distributions. In this setup, width becomes the cheap axis because the block has already been drafted in one shot. This is a major departure from standard autoregressive drafters, where both depth and width are expensive because they are built sequentially.

TDES, or Target-Distilled Edge Scoring, addresses parent-child mismatch. DDTree is effectively parent-agnostic: a child token contributes the same score regardless of which parent path it extends, because scoring is driven by per-position token probabilities. GRAFT instead learns an explicit edge scorer distilled from target-model traces. The scorer takes candidate parent-child pairs from adjacent positions, together with contextual features, and predicts how compatible that transition is with the target model. Tree assembly then uses these edge scores, rather than only the product of marginal token probabilities, to select target-compatible paths under a node budget.

Mechanistically, this is a lightweight structural predictor that compresses local target preferences into a cheap model. It does not rerun the target and does not force the DLM drafter into autoregressive expansion. It patches the missing conditional dependency at the tree-assembly stage. That is the right intervention point, because the failure mode is not merely missing candidate tokens; it is incorrect attachment among already available candidates.

SABA, or State-Aware Budget Allocation, addresses budget misallocation. The paper models per-round throughput as a trade-off between draft gain and verification cost, then chooses the budget conditioned on the current decoding state. Easy rounds already have long accepted prefixes, so larger trees mostly add cost. Hard rounds benefit more from extra nodes, but only up to a saturation point. SABA predicts the utility of different budgets from state features and selects the throughput-optimal one online.

Overall, GRAFT leaves the DLM and the target verification mechanism unchanged. It focuses specifically on the mapping from one-pass future distributions to an executable draft tree. 第一，proposal family 不是独立 drafter，而是挂在 target backbone hidden state 上的多 horizon future-token heads，形式上接近 MEDUSA。给定前缀 x_{<=t}，target 先精确采样一个 anchor token x_{t+1}，然后多个 head 并行预测后续若干位置的 token，复用 target 的词表投影矩阵 W。这些候选组成一个 prefix-closed sparse tree。这样做的好处是省掉第二个 AR backbone 和对应 KV cache，proposal 成本更低，也减少了 target/drafter 失配来源。

第二，verification 是 exact 的，而且是 concurrency-aware 的。RL rollout 里同时活跃的样本数会随着部分样本提前结束而下降，因此固定大小的 speculative tree 在高并发阶段可能浪费验证算力，在低并发阶段又吃不满硬件。SpecRoll 会根据当前 active concurrency 动态调整 sparse tree 的预算：并发高时保守，减少额外验证负担；并发下降后扩大 tree，换取更高 accepted progress。论文的出发点不是单纯提高单条序列 acceptance，而是优化整个 GRPO rollout 阶段的吞吐。

第四，慢路径只在 sustained degradation 被检测到时，才更新 future-token heads 的参数。也就是说，SpecRoll 不把所有失配都转成在线学习问题，而是先用 Reflex 吃掉短期、局部、轨迹内的偏差，把真正跨轨迹持续存在的 proposal 退化留给参数更新。这一点和 FastGRPO 的持续在线训练独立 drafter 不同，后者把适应主要放在参数层，代价更高，也不区分误差类型。

从训练目标上，SpecRoll 始终保持 exact target verification 为最终裁决，因此 committed token 的分布不变，GRPO 的 reward、advantage 和优化目标都不被改写。它优化的是 rollout 生成过程，而不是 RL objective 本身。17:T96f,SpecRoll is an exact speculative rollout engine built from four main pieces.

First, the proposer is not a separate drafter model. It uses MEDUSA-style future-token heads attached to the target backbone hidden state. Given a prefix, the target model samples an exact anchor token x_{t+1}, and multiple horizon heads predict later positions in parallel, reusing the target vocabulary projection. These candidates form a prefix-closed sparse tree. This removes the need for a second autoregressive backbone and its KV cache, reducing proposal cost and simplifying synchronization.

Second, verification remains exact and is made concurrency-aware. In GRPO, the number of active rollouts changes over time because some responses finish earlier than others. A fixed speculative tree is therefore inefficient: too expensive when concurrency is high, and too small to saturate hardware when concurrency drops. SpecRoll adjusts the sparse-tree budget based on active concurrency, using a smaller budget early and a larger one later. The objective is not just better acceptance on a single sequence, but better throughput for the whole rollout stage.

Third, the fast adaptation path is Reflex. The key observation is that delayed verifier errors can still be predictive for nearby future positions within the same trajectory. Reflex converts such mature verifier feedback into bounded, trajectory-local hidden-state corrections without backpropagation. It is guarded by a conservative alignment gate, which activates only when past errors are predictive of future mismatch, and by candidate-boundary safeguards that suppress harmful interventions near unstable boundaries. The design explicitly separates transient local mismatch from persistent drift.

Fourth, the slow path updates the future-token heads only when sustained degradation is detected. In other words, SpecRoll does not treat every mismatch as an online learning problem. It first uses Reflex to absorb short-lived, local errors, and only escalates recurring cross-trajectory mismatch into parameter updates. This differs from FastGRPO, where adaptation relies more heavily on continuously training a separate drafter.

Throughout the method, exact target verification is authoritative. The committed-token distribution is unchanged, so rewards, advantages, and the GRPO objective remain intact. The method changes rollout efficiency, not the RL objective.18:T5f5,The evaluation covers five models from 1.5B to 14B parameters and three math reasoning datasets, for 15 matched model-dataset settings. Against vanilla GRPO, SpecRoll reports 1.26x to 2.15x generation speedup and 1.21x to 2.04x end-to-end speedup. Against FastGRPO, it is better on both generation time and end-to-end time in all 15 matched settings, with an average pairwise end-to-end gain of 1.18x.

These results matter for two reasons. First, the gains are not limited to token-generation microbenchmarks; they carry through to the full RL training loop. Second, the combination of lightweight proposal heads and two-timescale adaptation appears more cost-effective than maintaining a separately trained online drafter, at least in the tested regime.

The ablations show that both the fast path and the slow path help individually, and the combination works best. That means Reflex is not a cosmetic add-on; it absorbs a meaningful portion of transient mismatch. At the same time, Reflex alone is insufficient because policy drift accumulates across trajectories, so slow parameter updates are still needed. Another useful finding is the role of the concurrency-aware tree budget, which explains why speculative decoding settings from ordinary inference do not transfer directly to RL rollouts.
