9:T590,The authors instantiate continuous diffusion language modeling with LangFlow and speculative drafting with DSpark. DSpark’s Markov and recurrent-head variants are adapted into standalone generators: they no longer receive target-model features and are not verified or corrected by a target LM. The task is unconditional single-block OpenWebText generation at block lengths 16, 128, and 1024. Because there is no semantic prompt or prior block, each model must choose content and maintain the dependencies induced by that choice. LangFlow repeatedly refines continuous representations for the whole sequence, allowing positions to exchange information before tokens are finalized. The DSpark-style models compute backbone features once and rely on a lightweight output head: the Markov head conditions only on the previous sampled token, while the recurrent head carries a hidden state over the generated history. The analysis identifies a concrete limitation of the Markov interface: information about an earlier choice may no longer be recoverable from the immediately preceding token, restricting the class of distributions the head can represent. Recurrent memory removes that particular access bottleneck, although learning to use the memory remains empirical. The paper also separates improved supervision from improved sampling compute by testing teacher probability matching and additional LangFlow denoising steps.a:T724,The setup is formalized as follows. Let q be the parallel drafter with block length L. Its distribution at position l, q_l(.|c), depends only on the current context c. The verifier p is autoregressive, so its distribution at the same position is p_l(.|c, x_<l), which depends on the sampled prefix inside the current draft block. Therefore, for a fixed student head q_l, different sampled drafts induce different teacher distributions. Existing on-policy distillation methods effectively supervise the same student prediction with these separate, potentially conflicting conditional targets. This creates an averaging problem: the student is asked to imitate multiple incompatible teacher views while lacking access to the within-block prefix that generated them.

MDraft solves this by aggregating verifier feedback across multiple drafts before constructing the training target. Intuitively, it tries to estimate which tokens are broadly useful for acceptance at a given position under the distribution of plausible prefixes, rather than which token is preferred under one particular sampled prefix. That is a better match to the structure of the parallel drafter, because the drafter cannot observe those prefixes in the first place.

The key contribution is therefore not a new model architecture but a new teacher-target construction for on-policy distillation. Instead of forcing an autoregressive conditional distribution directly onto a prefix-agnostic parallel student, MDraft approximates a marginal target over multiple sampled drafts. The paper’s argument is strong on this point: if the real objective is to maximize speculative acceptance rather than to minimize teacher cross-entropy under a mismatched conditioning structure, then the training target should reflect acceptance utility across possible prefixes.b:T4a5,The main metric is acceptance length, not standard language-model perplexity. The authors fine-tune parallel drafters and evaluate them on mathematical, coding, and conversational benchmarks. MDraft achieves the best overall mean acceptance length among the on-policy distillation baselines considered, meaning that the verifier accepts more drafted tokens per pass and speculative decoding becomes more efficient. The abstract does not expose the full numeric table, but the body indicates that the gains are consistent across task types rather than confined to a single domain.

More importantly, the experiments support the mechanism claim. When verifier targets from different sampled prefixes are distilled separately, the student becomes overly conservative and acceptance drops. Aggregating verifier information across multiple drafts produces a student distribution that better matches what the verifier is willing to accept in actual use. If you read the full paper, the most informative ablations are likely the number of drafts used for aggregation, the block length L, and the exact aggregation rule, since these directly test whether the method is solving the stated mismatch.c:T85e,方法由三个部件组成。第一，候选块构造。给定当前前缀 p，先用浅层或当前可读出的预测得到一个 head token h，然后在 p∥h 中做 suffix matching，寻找此前上下文里与末尾后缀最长匹配的位置；从该位置向后复制最多 K 个 token 作为 tail，形成候选块 B=(b0,...,bk)，其中 b0=h。若找不到匹配，就退化成单 token 块。这里借鉴了 prompt lookup decoding 的思路，但不是直接把复制结果当最终输出，而是把它当 speculative proposal。

第二，浅层筛查。候选块整体先推进到 screening depth ds，而不是直接跑满总深度 D。在 ds 处，用每个前驱位置的 shallow next-token prediction 去检查后继 copied token 是否一致。具体是找从 head 开始的最长连续通过前驱预测校验的前缀；通过的部分保留，后缀立即裁掉，并释放其 KV / hidden state。这个设计比最终深度才发现错误更省，因为错误复制通常会在较早位置暴露，没必要让整段错误 tail 继续消耗深层 recurrent 计算。

第三，连续调度与因果提交。保留下来的 token 继续向更深层推进，同时最近一个保留位置立刻作为下一块的起点，允许新块在旧块尚未 full-depth 验证完成时进入流水线。最终只有达到 full depth 的位置才按因果顺序提交输出。论文强调，真正的收益来自 shallow screening 和 continuous scheduling 的配合：如果只是筛查但不让新块提前进入，流水线填充不足；如果只连续推进但不筛查，错误复制会污染后续深层计算，浪费算力。

与已有 self-speculative decoding 的区别主要有三点。其一，draft 来源不同：不是中间层逐 token 生成，而是“一个新 head + 一段上下文复制 tail”的块级 proposal。其二，验证粒度不同：不是只在 full depth 做接受/拒绝，而是在浅层先做 predecessor-consistency screening。其三，调度方式更偏向 recurrent pipeline，而不是传统 draft-then-verify 两阶段流程。整个方法 training-free，直接复用现有 readout。d:T8ee,The method has three main components. First, block construction. Given a prefix p, the model predicts a fresh head token h. Then CopyLoop performs suffix matching over p concatenated with h, looking for the longest matching suffix in earlier context, similar in spirit to prompt lookup decoding. From the matched location it copies up to K following tokens as a tail, producing a candidate block B=(b0,...,bk) with b0=h. If no useful match exists, it falls back to a single-token block.

Second, shallow screening. Instead of sending the whole candidate block directly through the full recurrent depth D, the block is advanced only to a screening depth ds<D. At that depth, each copied token is checked against the shallow next-token prediction of its immediate predecessor. The algorithm keeps the longest prefix of copied tokens that agrees with predecessor predictions and prunes the remaining suffix immediately, including its KV and hidden-state footprint. This is the key efficiency move: copied tails are cheap to propose, but many are partially wrong, so the method tries to detect disagreement before deep recurrent compute is spent.

Third, continuous scheduling with causal commitment. Tokens that survive screening continue toward full-depth verification, while the latest retained position immediately seeds the next candidate block. This allows newer blocks to enter the pipeline before earlier ones finish full verification. Final outputs are still committed only in causal order once they reach full depth. The paper argues that the gain comes from the interaction between shallow screening and continuous scheduling: screening alone saves some wasted deep compute, but scheduling is what turns that into latency reduction; scheduling alone would let many bad copied tails consume deeper passes.

Compared with prior self-speculative decoding, the differences are clear. Drafts are not generated token by token from intermediate passes; they are block proposals composed of one fresh head plus a copied tail. Verification is not only a final accept/reject step; there is an explicit shallow recurrent filter. And the execution pattern is a recurrent pipeline rather than a clean two-stage draft/verify setup. The method is training-free and uses existing model readouts.e:T577,The evaluation covers six checkpoints from the Ouro, Raven, and Huginn looped-Transformer families: four Base models and two Thinking models, on code generation and mathematical reasoning workloads. Relative to full-depth autoregressive decoding, CopyLoop reports 2.98-10.70x speedups on Base models and 2.74-3.52x on Thinking models. It outperforms all baselines in 14 of 16 Base model-task settings and in all 8 Thinking settings, while keeping task accuracy close to standard decoding.

The ablations are more informative than the headline numbers. The paper shows that shallow screening becomes much more valuable when paired with continuous scheduling, which supports the claim that the algorithm is not just prompt lookup plus verification. Hyperparameter studies suggest that screening depth ds, copy length K, and suffix-match settings transfer with only light calibration across model families.

The analysis section also clarifies where the method works best. Speedups increase with longer generations and with more reusable spans in context, because copied tails are more likely to be valid and the pipeline has time to amortize setup overhead. Short responses benefit less. Thinking models see smaller gains than Base models, which is plausible: reasoning-heavy outputs are less repetitive and intermediate predictions are less stable, so copied proposals are harder to validate cheaply.f:T407,Start with the introduction and Figure 1.
