19:T894,技术上分两层。第一层是 bug 定位与验证。作者定位到 DeepSpeed ZeRO Stage 1/2 配合 CPU-offloaded Adam 时，梯度累积逻辑有一个分支错误：copy_gradients_to_cpu() 只在 micro_step_id == 0 的路径上执行，导致只有第一个 micro-batch 的梯度被拷到 CPU 侧优化器，后续 micro-batch 虽然在 GPU 上累积了，但不会同步到 CPU，最终 optimizer step 实际只看到了首个 micro-batch。这个 bug 来自 2024 年 9 月的 DeepSpeed PR #6550。修复方式很直接，把梯度拷贝调用移到分支外，让每个 micro-batch 累积后都同步。作者没有停留在代码阅读，而是用两个独立参照系做了交叉验证：OpenRLHF 中不 offload 的 GPU-resident DeepSpeed optimizer，以及 verl 里的 PyTorch FSDP optimizer。修复后，平均 loss 和 gradient norm 与这两个参照实现对齐。

第二层是 loss aggregation bug。标准 SFT 的 cross-entropy 应该按所有有效 response token 的总损失除以总 token 数，也就是全局 per-token mean；但 OpenRLHF、Llama-Factory、早期 verl 会先在每个 mini-batch 内求 mean，再在梯度累积或多卡之间平均这些 mean。由于不同 mini-batch 的有效 token 数不同，这相当于给每个 mini-batch 相同权重，而不是给每个 token 相同权重，长短样本的贡献被扭曲。修复方法是先聚合 token-level loss sum 和 token count，再统一相除。

在这两个 bug 修复后，作者重新实现并比较标准 SFT→RL 与多种 mixed-policy 方法。论文的论证逻辑很清楚：不是抽象地说 sequential 更好，而是说明为什么它在 reasoning 上常更有效。SFT 提供的是 dense、低方差的学习信号，先把格式、领域知识和基本解题轨迹学稳，RL 再在已有成功轨迹附近做策略锐化；而 mixed-policy 在训练早期同时面对 off-policy demonstration 和 on-policy sparse reward，优化目标更杂，且如果初始策略太弱，RL 部分几乎不给有效梯度，算力利用率并不高。作者还给出 truncated RL 结果，说明即便只做很少轮数的 RL，只要 SFT 起点足够强，也能超过很多复杂混合方法。1a:T403,This is a high-importance paper because it recalibrates a widely cited empirical conclusion in reasoning post-training. A substantial part of the apparent advantage of mixed-policy methods seems to come from broken SFT baselines rather than a genuinely better training paradigm. That matters directly for the pretrain–posttrain interface: if SFT is artificially weakened, then conclusions about how much RL needs off-policy demonstrations, how to mix dense supervision with sparse rewards, and where RL should start from all become unreliable. The paper reinforces a simple but consequential point: if SFT is implemented correctly and pushed to a strong enough starting policy, RL from verifiable rewards can be both more compute-efficient and more stable than trying to learn demonstrations and on-policy exploration simultaneously. The contribution is corrective rather than algorithmic, but the blast radius is large because the affected stack includes DeepSpeed, OpenRLHF, TRL, Llama-Factory, and earlier verl code paths.1b:T9c3,The technical contribution has two layers. First is bug identification and validation. The authors trace a bug in DeepSpeed ZeRO Stage 1/2 with CPU-offloaded Adam: during gradient accumulation, copy_gradients_to_cpu() is executed only in the branch where micro_step_id == 0. As a result, only the first micro-batch’s gradients are copied to the CPU-side optimizer. Later micro-batches accumulate on GPU but are never transferred, so the optimizer step effectively uses only the first micro-batch instead of the accumulated gradient. The bug was introduced in DeepSpeed PR #6550 in September 2024. The fix is simple—move the gradient copy outside the conditional so it runs after every micro-batch accumulation—but the paper goes beyond code inspection and validates the patch against two independent references: a GPU-resident DeepSpeed optimizer in OpenRLHF and a PyTorch FSDP optimizer in verl. After the fix, loss trajectories and gradient norms align across implementations.

The second layer is the loss aggregation bug. In standard SFT, cross-entropy should be computed as the total loss over all valid response tokens divided by the total number of valid tokens, i.e. a global per-token mean. OpenRLHF, Llama-Factory, and earlier verl versions instead compute local means within each mini-batch and then average those means across gradient accumulation steps or distributed ranks. Because mini-batches contain different numbers of active response tokens, this gives equal weight to each mini-batch rather than each token, distorting the contribution of short and long samples. The correct fix is to aggregate token-level loss sums and token counts first, then divide once globally.

With both bugs corrected, the authors re-run the standard SFT→RL pipeline and compare it against published mixed-policy methods. The conceptual argument is straightforward and well supported: SFT provides dense, low-variance supervision that teaches formatting, domain knowledge, and basic reasoning traces; RL then sharpens the policy around trajectories that already have nontrivial success probability. Mixed-policy training, by contrast, mixes off-policy demonstrations with sparse on-policy rewards from the beginning, which makes optimization noisier and often less compute-efficient when the initial policy is weak. The paper also includes truncated-RL results showing that even a small amount of RL can outperform more elaborate mixed-policy methods if the SFT starting point is strong enough.1c:T655,The key experimental story is the reordering of baselines before and after bug fixes, followed by direct comparisons against mixed-policy methods. The two bugs together can reduce SFT performance by as much as 5.7 points on Qwen2.5-Math-7B, with the optimizer bug accounting for most of the drop and the loss aggregation bug adding a smaller but consistent penalty. After fixing them, the standard SFT-then-RL pipeline surpasses the best published mixed-policy result on in-distribution math tasks by +3.8 points for Qwen2.5-Math-7B and by +22.2 points for Llama-3.1-8B, while maintaining generalization on out-of-distribution benchmarks. Another important result is the compute comparison: even a truncated variant with only 50 RL iterations, instead of 500, still beats all mixed-policy methods on the math benchmarks, indicating that the extra complexity of mixed-policy optimization is not buying better sample efficiency or FLOP efficiency.

The paper also includes several validation layers that make the case more convincing. These include alignment of the patched DeepSpeed offload implementation with GPU-resident and FSDP optimizers in both loss curves and gradient norms; ablations that isolate the effect of fixing each bug separately versus both together; replication across model families including Qwen2.5-Math-7B and Llama-3.1-8B; and separate reporting on in-distribution and out-of-distribution benchmarks. Methodologically, the strongest aspect is that the paper does not rely only on final benchmark numbers; it also checks optimizer consistency, gradient statistics, compute cost, and generalization.1d:T459,This one is worth a close read. Start with the bug sections, especially the DeepSpeed CPU-offload gradient accumulation path, and make sure you understand why the bug silently drops gradients and why normal training logs may not reveal it. Then read the loss aggregation discussion carefully; this issue is broader than reasoning SFT and can affect any setup with variable-length responses. After that, inspect the main result figures and tables showing how the ranking of SFT, SFT→RL, and mixed-policy methods changes after the fixes, along with the FLOP comparison.
