18:T774,The core idea is to start from PTQTP’s decomposition
W≈α1T1+α2T2 with Ti∈{-1,0,1}, and impose α=(3s,s). Under that constraint, the composite code c=3t1+t2 lands on a uniformly spaced 9-level grid with a single scale. Standard PTQTP allows two free per-group scales and therefore a more flexible non-uniform 9-level approximation. This paper deliberately gives up that flexibility in exchange for a simpler, deployment-friendly representation. Because there are only nine valid composite values, the two ternary planes can be folded losslessly into a single 4-bit code plane.

The more interesting part is the systems realization. The folded 4-bit code is not just an internal compute format; it becomes the persistent serving representation. Disk bytes, expert-cache bytes, and kernel input bytes are identical, so the system never transcodes expert weights between storage tiers. The implementation uses a block format called tq2_0_fx4: a 520-byte block covering four columns by 256 elements, corresponding to 4.0625 bits per weight. This matters because an expert miss can then be served by one contiguous read, and block-granular NVMe striping of hot expert prefixes becomes straightforward.

On the evaluation side, the paper does not rely on perplexity alone. It emphasizes step-level agreement with the official serving API using greedy decoding and decoded-text prefix agreement on captured fixtures rather than token-ID equality. It also introduces an expert-lossless control arm, where the released MXFP4 expert bytes are repacked without an additional quantization step, to anchor the claim that observed deficits are primarily due to expert quantization rather than unrelated system effects. The paper also mentions a process-isolation protocol motivated by measured fixture instability. Altogether, the work is much more about deployment fidelity than about abstract quantization theory.19:T6a1,The experiments are built around a production-scale 284B-A13B MoE model. The expert payload dominates the serving artifact: the paper cites roughly 145 GiB of q4_k-scale expert bytes inside a 153.3 GiB serving file, with only about 8 GiB for trunk and embeddings. The quantization target is the released checkpoint artifact, whose experts are available in MXFP4 rather than a higher-precision official release, so the study is grounded in a realistic deployment object rather than an idealized offline setting.

The main empirical comparison is along three axes: reconstruction/perplexity, agreement with the official API, and actual serving speed. One of the paper’s central observations is that these axes do not always agree. Better perplexity does not necessarily imply better step-level reference fidelity, and better reference fidelity does not automatically translate into better downstream benchmark behavior. That is an important point for quantization work, since many papers implicitly treat offline perplexity as a sufficient proxy for deployment quality.

On the systems side, the claimed speedups depend on the fact that the ratio-3 tied 9-level folded code is the persistent format itself, so persistent bytes, cache bytes, and kernel input bytes are identical. The implementation is done in the open-source fucina stack, which is CPU-first with optional Metal/CUDA GEMM offload.
