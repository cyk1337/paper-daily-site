19:T788,The paper has three main components. First, it formalises the collaboration tax using team-decentralisation and cooperative-game language. The tax is the success-rate gap between a full-information solo policy and a split-information paired policy. Two propositions characterise when the quantity is positive and connect it to a violation of superadditivity in the underlying cooperative game. The theory is lightweight, but it gives the empirical phenomenon a precise reference point.

Second, the authors build a 32-task suite grouped into Spatial, Relational, and CSP families. These families are chosen to span different sources of grounding friction: reference-frame alignment, lexical/category alignment, and indexing/ordinal alignment. Each task is designed so that a single model can solve it when given the full view, after which the information is partitioned across two agents. This makes the benchmark much cleaner than many agent evaluations that mix in tool use, planning depth, or environment interaction.

Third, the paper develops a mechanistic account of failure. It identifies a four-stage conversational cascade: grounding, querying, integration, and re-derivation. Grounding failures occur when agents introduce facts supported by neither private view. Querying failures occur when they do not ask the partner for missing information. Integration failures occur when they fail to combine both views before committing. Re-derivation failures occur when the receiver accepts an answer without recomputing it. The authors then show that conversation-shape features predict the tax well: model capability largely sets the intercept, while conversation structure sets the slope. Finally, they test a simple prompt-only intervention that adds one clause targeting each stage. The simplicity matters because it supports the claim that the dominant issue is coordination process, not missing base reasoning ability.1a:T61c,The evaluation covers 11 models from 7 providers, with solo, homogeneous-pair, heterogeneous-pair, and slot-swapped heterogeneous settings. Even from the provided full text excerpt, several findings are clear. First, the collaboration tax is systematic rather than anecdotal. It exhibits two no-exception orderings: one over task categories and one over model capability. Harder grounding-friction categories consistently incur larger tax, and stronger models show monotonically smaller tax. Second, the main failure mode is not reasoning deficit. Conversation analysis indicates that many failures happen before the relevant information is properly requested or after it is received but not integrated or checked. Third, in heterogeneous pairs the stronger model bears the asymmetry of the loss, suggesting that weaker partners often drag the interaction into a poorer coordination regime rather than contributing complementary value. Fourth, the prompt-level intervention recovers a substantial fraction of the tax, and leave-one-out ablations show that the dominant bottleneck differs by task family. That is more informative than a generic prompt-length effect because it points to task-structure-specific coordination failures.

The experimental design is strong in one respect: the solo-tractable construction makes causal interpretation cleaner. The limitations are also clear: the suite is still relatively small, focused on two-agent natural-language coordination, and does not cover richer settings with tools, memory, or learned communication protocols.1b:T40b,This is useful for both coding-agent evaluation and training. First, it reframes repository-level failure from vague claims about insufficient context or weak retrieval into a more causal object: edit-time fact availability. That is a sharper target for diagnosis. Second, it shows strong substitution between parametric memory and explicit context, which means many apparently successful agent strategies on familiar repositories or APIs may simply be benefiting from memorized knowledge rather than sound workflow design. Third, it exposes a systematic blind spot in read-derived instrumentation: when facts are missing, agents usually do not stop; they guess, fabricate, and continue. As a result, measuring what the agent read can underestimate the shortfall and mislead harness design. For pretraining researchers, the paper matters because it touches the interface between what is stored in parameters, what must be supplied externally, and how benchmarks can accidentally conflate memorized priors with genuine agent competence.1c:T847,The core framework is a two-channel, edit-time working-set model for repository coherence. Each edit depends on a set of coupled facts, such as imports, tests, configuration rules, migration constraints, or naming conventions. Those facts can come either from recent context or from parametric memory. If neither channel covers a required fact, the edit carries coherence debt. This turns repository coherence from a loose intuition into something that can be manipulated experimentally.

The experimental design is unusually controlled. The first setup uses four fictional API migration tasks, each with 12 mechanically checkable requirements. In the closed-book condition, the model gets the task description but no workspace and no tools, effectively emptying both channels. In the matched front-loaded condition, the exact rules and source files are placed in the prompt while keeping the model and tool surface fixed, isolating whether explicit context can substitute for missing memory. The second setup uses a real Pydantic migration with 79 tests, plus a renamed twin where all API names are changed so that memorized library knowledge becomes useless. This isolates the role of parametric memory. The third setup instruments tool-using trajectories by checking whether the agent read the dependencies of an edited file shortly before editing. The fourth uses synthetic tasks authored by the researchers, where the required facts are fully known, enabling precise fault injection and attribution.

Two boundary findings are especially important. Availability is not sufficient on its own: when written standards conflict with working code, agents systematically follow the written standard even when the code is the better guide. So seeing a fact is not the same as weighting it correctly. Also, decomposition is not automatically helpful: if the task is tightly coupled, splitting it across subagents can sever dependencies and create additional coherence debt. The paper also compares harnesses and finds that some configurations spend far more tokens for the same end result, without improving fact coverage.1d:T6c0,There are five main empirical results. First, on the four fictional migrations, none of the 154 closed-book trials succeeds, while front-loading the exact facts into the prompt lifts 299 of 300 matched trials to at least 9 out of 12 requirements. This is strong evidence that explicit context can substitute for missing parametric knowledge. Second, on the renamed version of the real Pydantic migration, 66 of 70 trials across seven models end at the same score and pass the exact same 24 of 79 tests. Once memorized knowledge is neutralized, failures become highly aligned, suggesting that availability rather than model style determines the outcome. Third, the damage from withholding facts is reported to be linear in the work those facts support: removing a fact costs exactly the edits it enables and no more. Fourth, distance itself is not the issue: when a fact is supplied, models use it about as reliably at the far end of a 128,000-character context as when it is placed near the edit. Fifth, harnesses can differ by 12.8x in total token consumption while holding only 1.8x different amounts of context in front of the model at any moment, and the more expensive setups recover no extra capability when facts are withheld.

Two negative results matter as much. In 39 conflict trials, agents consistently follow written standards over contradictory but working code, showing that coverage does not guarantee correct arbitration. And the framework does not transfer cleanly to SWE-bench, where models likely already know the repositories and the task structure is observed only coarsely, so reading behavior no longer predicts success. The paper is careful not to overclaim universality beyond its controlled workloads.1e:T435,For a quick read, focus on three parts. First, read the introduction and experimental design carefully to internalize the three key concepts: coupled-fact graph, two-channel availability, and coherence debt. Without them, the results can look like a collection of coding-agent anecdotes. Second, prioritize the closed-book, front-loaded, and renamed-migration interventions. These are the strongest causal pieces of evidence in the paper. Third, read the sections on harness cost, subagent decomposition, and conflicting facts, because they show that the paper is really about the design limits of coding-agent systems, not just benchmark behavior.

If time is limited, the main figures and the five headline claims are enough to capture the argument in about 35 minutes.
