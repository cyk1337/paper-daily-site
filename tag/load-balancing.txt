1) Unified formalization: MoE as a sparse combination of expert functions where routing selects an expert set K_t per token. 2) Four control planes forming a closed loop:
- Expert Topology: expert granularity and structural choices (incl. shared paths), slow-changing.

The survey explicitly avoids capability-number causal comparisons across papers due to confounders.18:T502,The framework has an offline placement pipeline plus a lightweight online guard, and intentionally leaves the router unchanged.
1) TACG (Task-Aware Coactivation Grouping):
- Split calibration traffic into task families (K=4 in the setup) and collect per-family expert usage and co-activation statistics per layer.
- Compute soft expert-to-family preferences, then reweight the co-activation graph into a task-modulated graph so that within-family co-activated experts become closer.
- Run spectral clustering on the modulated graph, followed by a capacity-repair step to satisfy per-GPU capacity constraints, producing a primary GPU assignment for each expert.
2) GESR (Generic Expert Shared Replication):
- Identify cross-family “generic” experts that tend to become hotspots using co-activation centrality and cross-family consistency.
- Replicate only this small set onto a few secondary GPUs chosen to be structurally compatible with the primary placement.
- At serving time, select among replicas using a locality- and load-aware rule with exponentially decayed load signals to mitigate skew under workload shift.
The design trades optimality for operational simplicity: no router changes, no dynamic migration; it relies on task-family partitioning and calibration traces.19:T67a,MACS is a training-free inference framework with three components.

First, Entropy-Weighted Load replaces raw token counts with an information-aware load estimate. For each visual token, the method computes a Shannon entropy score from the token feature after a softmax transformation, normalizes entropy values within the current image or batch, and maps them to semantic weights through a sigmoid function. The intuition is simple: not all visual patches deserve equal capacity. Background or redundant patches should count less than semantically dense ones. Text tokens are assigned full weight because their semantic density is treated as relatively uniform and high.

Second, Dynamic Modality-Adaptive Capacity adjusts expert capacity according to the current batch-level modality composition. Standard methods use a fixed capacity factor gamma, which is brittle when some tasks are image-heavy and others are text-heavy. MACS makes capacity a function of the actual visual/text mix in the batch, so the budget tracks the current workload instead of a static approximation.

Third, Local Semantic Rerouting handles overflow. When an expert exceeds capacity, the framework first attempts to reroute overflow tokens to semantically nearby experts with spare room; only when rerouting fails does it fall back to a safe token drop. This is a practical design choice: it preserves more useful information than direct dropping, while avoiding the overhead of a more expensive global reassignment.

Relative to prior methods such as CAI-MoE, the key shift is not retraining the router but redefining load and capacity at inference time in a modality-aware way.1a:T572,MoHGE combines architectural, routing, and systems ideas. First, experts are partitioned into groups; experts within the same group share the same size, while different groups have different hidden dimensions. This creates a tiered capacity structure, where smaller groups can handle easier patterns and larger groups can absorb harder contexts. Second, routing is hierarchical. A group-level gate first selects the top candidate groups, and an expert-level gate then chooses experts within those groups. This is better aligned with heterogeneous capacity than a single flat gate over all experts, because the model first decides how much capacity to use and only then which expert instance to activate. Third, the paper introduces two balancing losses. The Group-Wise Auxiliary Loss regulates how often different capacity groups are selected, aiming for a better match between token complexity and expert size while avoiding collapse to a single group. The Intra-Group Experts Auxiliary Loss balances usage among experts inside each group. On the systems side, the All-size Group-decoupling Allocation strategy spreads experts from every group across all GPUs, instead of concentrating large experts on a subset of devices.
