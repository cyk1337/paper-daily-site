18:T7a7,The pipeline has four components. First is data curation. The authors collect 22,000 problems from 16 regional and international competition families plus online platforms, package them into executable evaluation environments, and explicitly exclude and deduplicate evaluation problems. They then use DeepSeek-V4-Flash to generate large synthetic reasoning-trace corpora: about 1.2M traces for the Nano model and 477,642 for the larger model. The key point is not just scale, but the organization of problems, reasoning, code, and feedback into long-context supervised examples.

Second is supervised fine-tuning. They start from Nemotron-3-Nano-30B-A3B and Nemotron-3-Ultra-550B-A55B and perform long-context SFT to obtain competition-specialized models. Nano is a 30B-parameter MoE with 3B active parameters; Ultra is 550B with 55B active. The supervision appears to target not only final code generation but also intermediate problem-solving traces.

Third is reinforcement learning. RL is applied to Nano-CC, with rewards derived from executable evaluation, namely whether the generated program passes tests and how much score it obtains. This reward is attractive because it is automatic and closely aligned with the task objective. The downside is that it may favor search-friendly behaviors rather than robust one-shot generalization. The paper places RL after SFT, which is sensible: the action space in competitive programming is too large for pure RL to be stable without a strong initial policy.

Fourth is GenCorrect, the test-time closed-loop strategy. It is more than self-consistency. The system generates diverse candidate solutions, evaluates them, uses the feedback to refine later attempts, and operates under a limited submission budget. This is essentially verifier-guided search plus iterative program repair. It is especially well matched to IOI-style settings, where multiple submissions and partial credit are part of the environment.19:T704,The main results are straightforward. On IOI 2025, Nemotron-3-Nano-CC improves from 130 Score@1 at baseline to 280 after SFT and 291 after RL. So SFT provides the dominant gain, while RL adds a smaller but real improvement. With five rounds of GenCorrect, the score rises to 468, above the gold threshold of 438.3. The size of that jump makes it clear that test-time search is a major contributor, arguably larger than RL in this setup.

Nemotron-3-Ultra-CC does not use code-specific RL. It reaches 304 with SFT alone, and 502.0 after five GenCorrect rounds. This suggests two things: larger base models still benefit from domain-specific SFT on hard coding tasks, and a strong base model plus strong inference-time search may be a more efficient path than a smaller model with additional RL.

The authors then build a competition-specific system for IOI 2026 and evaluate it live, before public release of the problems, under matched time, internet, and submission constraints. The system scores 535.4/600, above the gold threshold of 361.12 and above the top official human score of 498.27. As a research result, this should be interpreted carefully. It reflects a full specialized system, including task-specific adaptation and inference strategy, not just the intrinsic capability of the underlying model.

The most useful ablation insight is the gain decomposition. Synthetic data plus long-context SFT establish the main capability step. RL further aligns the model to executable objectives. GenCorrect then amplifies final benchmark performance when the environment allows iterative feedback. If one only looks at Score@1, the model improvement is much smaller than the final competition score, which is exactly why the distinction between parameter updates and test-time compute matters.1a:T53b,This is a skim paper. Read it for pipeline decomposition, not for competition storytelling. Focus on three parts.

First, inspect the data curation and contamination-control pipeline. For foundation-model researchers, this is more interesting than the IOI headline because it shows how executable synthetic supervision is assembled, filtered, and kept evaluation-clean.

Second, read the tables that separate SFT, RL, and GenCorrect gains. Pay close attention to the gap between Score@1 and final multi-round scores. That gap tells you how much of the benchmark result comes from model updates versus inference-time search.

Third, read the GenCorrect algorithm and examples. It captures a broader post-training pattern: when the environment provides a verifier and actionable feedback, the model does not need to solve the task in one shot. It can iteratively repair its own outputs. That idea transfers beyond coding to math, tool use, and other verifiable domains.

A reasonable reading budget is 20–30 minutes. If you only want the research signal, read the introduction, method overview, main results, and ablations. Keep one framing in mind: this is not a pretraining paper. It is a strong post-training and inference-system paper whose value for pretraining lies in what it reveals about executable supervision and reward quality.1b:T5eb,FaithSieve has three stages: localization, verification, and synthesis. In localization, the system decomposes coarse benchmark steps into finer EdgeUnits using a proof-state-tree representation. Each transition in this tree corresponds to a local reasoning responsibility, which makes the evaluation target much sharper than judging an entire paragraph-like step. In verification, the method extracts typed proof obligations from suspicious transitions. These obligations are not treated uniformly; they encode different kinds of reasoning responsibilities such as algebraic transformation, implication transfer, existence construction, boundary-condition handling, or case transitions. The system then gathers evidence through both lightweight checks and Lean-based validation. Lean is used as a structured evidence source rather than a direct judge. A key safeguard is the semantic alignment score, which measures whether the formalized statement preserves the assumptions, directionality, quantification, and strength of the original informal obligation. Lean evidence is only trusted when this alignment is high enough, preventing drifted or weakened targets from producing false reassurance. In synthesis, local evidence is aggregated back to the original step level to predict the first erroneous benchmark step. The main novelty is the full pipeline: decomposition into local transitions, typed obligations, formal checking gated by semantic alignment, and evidence aggregation for first-error localization.1c:T506,The paper introduces two expert-verified datasets: ProofLoc-Olympiad with 350 algebra and number theory problems, and ProofLoc-University with 200 advanced mathematics problems. On ProofLoc-Olympiad, FaithSieve reaches 81.43% exact first-error accuracy, compared with 72.29% for a GPT-5.4 direct-judging baseline, an absolute gain of 9.14 points. The provided text also states that FaithSieve shows clear gains on ProofLoc-University, although the exact number is not visible in the excerpt. The evaluation follows the standard first-error localization setup, reporting both binary accuracy and exact accuracy, with the latter requiring the correct first-error index. The experimental story is important because it tests whether local formal evidence, when filtered for semantic faithfulness, actually improves early-error localization. The likely key ablations are removing EdgeUnit decomposition, which should make local flaws harder to isolate; removing semantic alignment gating, which should increase false positives from target drift; and relying only on natural-language judging, which should weaken precise localization. Together these results support a narrow but important claim: formal verification helps only when the verified target is both local and semantically faithful.1d:T6e6,The core method is residual-guided non-parametric optimization. The system starts from a fixed base verifier and iteratively improves it around observed mistakes. At each round, the current verifier is replayed on a construction pool, and disagreements with labels are collected as residuals. Recurring residual patterns are then abstracted into rule cards. Each card records a missing verifier bias together with support examples, counterexamples, applicability conditions, and abstention conditions. This is a key design choice: instead of directly updating model parameters, the method converts recurring failure modes into explicit knowledge units.

A rule card can follow one of two promotion paths. If the missing bias can be expressed as deterministic comparison logic—such as numerical tolerance handling, unit normalization, scientific notation conversion, or specific symbolic equivalence rules—it goes through code audit and replay validation, and if accepted becomes a code module. A code module is a deterministic verifier unit that returns Correct, Incorrect, or Abstain. If the bias cannot be fully codified and still requires model judgment, it is incorporated into the fallback verifier prompt rather than compiled into code. At inference time, the system first runs the module library; cases that can be decided explicitly are handled there, and only unresolved cases are sent to a fixed model-based fallback verifier.

What distinguishes this from prior work is not simply adding tools, but turning verifier improvement into a closed loop: residual discovery, rule-card drafting, replay validation, and promotion into either executable modules or prompt guidance. It sits between hand-maintained rule libraries and opaque judge-model behavior.1e:T545,The paper evaluates on four reference-based verification benchmarks. The headline result is 93.05% macro accuracy, outperforming the reported rule-based, model-based, scientific, and tool-augmented baselines included in the study. The more informative result is the component ablation: compared with a prompt-only setting, adding code modules yields an additional +1.76 macro-accuracy gain. That suggests the benefit is not merely better prompting; explicit comparison logic is covering verifier blind spots that prompting alone does not fix. In addition, direct module decisions reduce fallback model calls by 32.13%, so the system improves both accuracy and inference efficiency.

For each input, a model first produces a fixed set of candidates, with the first sample treated as the reference baseline. A collaboration mechanism is then allowed only to select from that pool; it cannot repair an answer or generate a new one. This separation is deliberate. It isolates selection from repair, so gains are not conflated with the ability to create better candidates.

Within this setup, the paper defines an any-of-k oracle: if any candidate in the pool is correct under the official evaluator, the oracle succeeds. The difference between this oracle and the reference baseline is the oracle gap, which serves as an absolute upper bound for any fixed-pool selector. The realized gain is then decomposed into recoverable mass, signal coverage, conditional selection quality, and harm. Recoverable mass measures how often the baseline is wrong while at least one correct candidate exists in the pool. Coverage measures how often the mechanism produces usable evidence. Conditional quality measures how often the mechanism picks a correct candidate on recoverable examples where a signal exists. Harm measures how often the mechanism turns an already-correct baseline into an incorrect answer.
