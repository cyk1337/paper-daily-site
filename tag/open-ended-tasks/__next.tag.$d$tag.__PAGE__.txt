9:T4d2,POP (Post-trains LLMs on Open domains with Pretraining text) uses one model in three roles, but ties all roles to a sampled document d from a relevant corpus D.
- Proposer: sample d (min length constraint; truncate), then generate a question x and a reference answer y_ref. For tasks with factual grounding (health QA), x is constrained so the answer is derivable from d; for creative writing / instruction following, the response must build on d.
- Solver: sample multiple candidate answers {y_j} to x.
- Verifier: conditioned on (d, x, y_ref, {y_j}), generate a query-specific rubric (criteria + descriptions + optional gold labels + weights), then grade each candidate.
Stability / anti-hacking mechanisms:
1) Privileged access: the verifier sees d (and more context) while the solver only sees x, creating a generation–verification gap via information asymmetry.
2) Preference learning instead of scalar RL: select only the top- and bottom-scored answers and train with DPO, which is less sensitive to score calibration noise.
3) Diversity via corpus grounding: sampling diverse d helps prevent query mode collapse.
