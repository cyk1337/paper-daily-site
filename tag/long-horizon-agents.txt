1a:T52f,SkillGate introduces two disjoint credit channels within a single policy-gradient update. The task channel uses the usual group-normalized outcome advantage, but removes the entire skill-read tool call from its support. In other words, task success or failure no longer directly updates the tokens that name the chosen skill. The selector channel applies an action-local advantage only to the token span corresponding to the chosen skill name. That selector signal is positive only when the trajectory issued a single read and the selected skill matches the oracle-correct one; it is then centered within the prompt group to reduce between-group difficulty effects. Two implementation details matter. First, rollout-time span attribution records the exact token span of each skill-read action so the support partition is exact in practice. Second, length-invariant reweighting gives equal batch-level loss weight to the two channels and equal share to each read action, preventing selector learning from weakening on longer trajectories. This differs from finer reward shaping: the paper is not slicing the same reward more finely, but separating two decisions that are justified by different evidence. It also differs from pre-execution retrieval methods, because the target here is the policy’s own in-episode skill choice.1b:T4ac,The paper first audits the failure mode, then validates the method. In the audit, it analyzes 12,800 on-policy trajectories from a standard outcome-only RL run and reports three key findings. First, share: the median token share of the selected-skill name is only 0.14% of a trajectory, and this shrinks further with horizon. Second, sign: about two in five of those tokens receive negative advantage; on the longest trajectories, a correct choice is punished more often than rewarded. Third, value: within matched prompt groups, making the correct read is still worth +11.2 points in task success, so the decision is important despite receiving weak and noisy credit. The method is then evaluated on five agent benchmarks. The headline number in the provided text is trial success improving from 47.0% to 53.2%. The gains appear concentrated in long-horizon settings with similar-looking candidate skills and noisy downstream execution, which matches the proposed diagnosis. The most important ablations are likely the ones isolating support partitioning, local selector advantage, and length-invariant weighting. The paper’s claim is that all three are needed for the effect to hold robustly.1c:T907,MemPrism explicitly separates persistent memory from decision-time working memory. The framework has five modules: Recorder, Router, Composer, Render, and Adapter. In inference, the first four form the main pipeline. Recorder stores real interactions as a unified event stream, keeping both raw events and structured fields such as pre-action observation, executed action, environment feedback, reward or step label, and task metadata. The point is to keep persistent memory neutral and reusable rather than collapsing it early into one fixed summary.

Router is the key learnable component. Instead of directly predicting the next environment action, it first decides how history should be viewed. A view action is defined over several axes: relation type, evidence range, outcome condition, and granularity. In other words, the policy chooses what relational structure to build, how much history to include, whether to filter by success/failure or other outcomes, and how coarse or fine the representation should be. This makes read-time memory representation an explicit decision variable.

Composer then selects events from the event stream and assembles a relational structure according to the chosen view action. Render converts that structure into an optical working-memory view. The optical format is not used only for token compression. The authors use two-dimensional layout to encode relations directly: spatial proximity groups related events, row/column alignment supports state comparison, arrows indicate change or dependency, and highlights emphasize failures or task-relevant evidence. A frozen task policy consumes the current input together with this temporary view and outputs the next environment action. The view is discarded after the step and is never written back into persistent memory, which avoids irreversible distortion from fixed summaries or repeated compression.

Training is also split cleanly. Router is first initialized with action-conditioned soft supervision, then optimized with trajectory-level grouped GRPO. The learning target is not the environment action itself, but the choice of memory view that best supports downstream action selection. This separation helps attribute gains to the memory representation interface rather than to a jointly entangled agent policy.1d:T6a7,From the provided full-text excerpt, the experimental emphasis is on whether task-conditioned view selection improves long-horizon decision making, not on raw storage capacity. The paper appears to provide two kinds of evidence: end-task gains and attribution studies showing that the gains come from working-memory construction rather than unrelated components. The training setup for Router—soft supervision followed by grouped GRPO—is already designed to isolate the effect of view selection.

The excerpt does not include full tables or final numbers, so the exact quantitative gains cannot be stated reliably here. Still, the intended comparisons are clear: fixed representations such as timelines, summaries, or flat retrieved snippets are contrasted with dynamically constructed relational views defined by relation type, evidence range, outcome filter, and granularity. The expectation is that dynamic views are better matched to subtasks like loop detection, state tracking, failure analysis, and dependency reasoning.

Another likely experimental point is the decision not to write temporary views back into persistent memory. The authors argue that writing them back would bake task-local bias into long-term memory and reduce future reuse. A meaningful ablation should therefore compare persistent event streams plus on-demand views against fixed summary memories or recursively compressed memories.
