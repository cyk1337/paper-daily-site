5:T5fb,The method has three main components. First, Cascade Cache organizes the KV lifecycle into three tiers instead of treating the cache as a monolithic buffer. Tier 1 is a dense cache for recent tokens, preserving local dependencies and attention sinks with contiguous high-fidelity storage. Tier 2 is a sparse cache where older tokens are retained selectively using head-adaptive budgeting. Tier 3 is a condensed cache where even older blocks are further compressed through eviction or weighted merging to satisfy hard memory limits. The key idea is to turn 'recent dense, older sparse, oldest condensed' into a unified pipeline. Second, Logits Calibration maps heterogeneous importance scores into a shared probability space so that Top-p style budgeting can be applied consistently across heads and across different selection criteria. This is meant to make the retained-token pattern better match the raw attention distribution, rather than relying on fixed Top-k thresholds that are hard to compare across heads. Third, System-aware Index Regularization rewrites discontinuous logical selections into a more regular physical layout using memory rewriting and sparse loading. Together with a head-wise block table and metadata management, this makes dynamic head-adaptive selection compatible with CUDA Graph execution and block-based memory systems. The main distinction from prior compression work is that the paper does not stop at a better selection rule; it translates dynamic selection into a system-friendly access pattern.6:T41f,The evaluation focuses on long-generation math reasoning, where decoding-time errors accumulate and KV compression quality matters most. On benchmarks including AIME and U-MATH, Hard-KV reports up to 1.5× performance gain and 2× throughput improvement. From the full text, the important comparisons are likely threefold: against fixed-budget or non-head-adaptive compression to show the accuracy benefit of dynamic budgeting; against algorithmically strong but system-unfriendly methods to show that regularization preserves most of the quality; and on systems metrics such as throughput, metadata overhead, fragmentation, and CUDA Graph compatibility. The implementation in a custom Nano-vLLM engine is important because it suggests the results are measured in an end-to-end serving setup rather than in an offline cache simulation. When reading the experiments, the most informative parts are the ablations on calibration and index regularization, since those determine whether the gains come from a coherent method or from engineering assembly alone.7:T8d7,ViCoStream decomposes continuous video processing into four sequential stages: visual preprocessing, visual encoding, token dropping, and LLM inference. The system then uses chunking and coordinated scheduling so that different chunks occupy different stages concurrently. The point is not just asynchronous execution; it is to design the whole pipeline around the constraint that the slowest stage determines sustainable throughput.

First, the incoming stream is partitioned into chunks of size c instead of being processed frame by frame. This improves efficiency because ViT encoders are much better utilized under small-batch parallelism than under serial single-frame execution. Second, CUDA-stream overlap is used so that preprocessing and encoding can run concurrently where possible, reducing idle GPU time. Third, after visual features are projected into the language space, chunk-level temporal token dropping removes redundant visual tokens, directly controlling downstream LLM compute and memory. Fourth, the LLM uses bounded visual attention together with query-side retrieval. Instead of exposing the full visual history to every query, the model keeps only a limited visible visual context while retrieving relevant past observations when needed.

The key is that these controls work together. Chunking improves front-end throughput, token dropping regulates token density, bounded attention caps prefill cost, and retrieval tries to recover useful information that would otherwise be lost by truncating history. The paper formulates this as a slowest-stage scheduling problem: as long as the processing time of the bottleneck stage stays below the chunk arrival interval, the system can sustain real-time streaming. Under this design, query-time TTFT is no longer tied to total stream length, but mainly to a bounded prefill over the restricted visible context.

This differs from delayed streaming, where most computation is postponed until a query arrives and latency grows with observed history. It also differs from prior continuous streaming work that accelerates sparse encoding, keyframe selection, or cache compression in isolation without a full pipeline view. ViCoStream tries to place those ideas inside a unified scheduling framework.8:T64f,The headline result is a throughput-accuracy trade-off: ViCoStream reaches 134 FPS at 30% token retention, while most moderate-compression settings remain close to full-history baselines in accuracy. The broader message is that a streaming VideoLLM can run far above standard real-time frame rates if visual token density and visible history are explicitly controlled, rather than forcing the LLM to absorb the entire stream.

The more informative part is the systematic analysis. The paper studies how chunk size, token retention ratio, visual-context size, and retrieval scope affect bottleneck migration. That is the right systems question. A local optimization may simply move the bottleneck from the LLM to the visual front end, or the other way around. For example, token dropping reduces LLM cost, but if visual encoding remains dominant, end-to-end FPS may barely improve. Conversely, even with a fast front end, TTFT can still grow with stream length if visual context is left unbounded. The paper’s argument is that only coordinated control across stages yields stable throughput-latency behavior.

When reading the experiments, the most important evidence is whether memory and TTFT remain approximately flat as stream length increases. If those curves are indeed bounded over long streams, then the bounded-attention design is doing real work. If the gains only appear on short clips, the practical significance is much smaller. The paper appears to be organized like a systems study, emphasizing sustained FPS, TTFT, memory budget, and accuracy jointly rather than reporting a single benchmark score.9:T475,Read it with a systems lens. The main instantiation is CacheSage for KV caching. The idea is that multi-agent workloads often reuse a recurring system-plus-tools prefix across sessions, but reactive caches evict those blocks before the next relevant session arrives. CacheSage learns an online first-order Markov transition matrix over agents within a workload. That model is used in two ways: for score, it estimates survival probability to guide eviction; for predict plus act, it triggers cross-session prefetch when a future agent call is likely.
