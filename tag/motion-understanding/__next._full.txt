18:T74a,The core contribution is a benchmark and a probing protocol, not a new model. MotionBlind uses a contrastive minimal-pair design. Each instance contains two near-identical clips recorded in the same scene with the same objects and background, differing only in one motion property such as left vs right movement, faster vs slower motion, or larger vs smaller displacement. Each clip is paired with two complementary yes/no questions, yielding four binary decisions per instance. An instance counts as correct only if all four are correct. This strict instance-level metric is intended to suppress inflated scores from partial guessing.

The dataset is self-recorded rather than scraped from the internet. That choice matters because internet videos are hard to control for static confounds and hard to label precisely for physical motion variables. The paper also prefers relative-motion questions over absolute notions like “fast” or “slow,” since absolute labels depend heavily on context. Comparing two moving references within the same scene reduces semantic ambiguity and makes the benchmark a cleaner test of motion perception.

The probing setup is well designed. First, a no-video text-only probe tests whether questions can be answered from language priors alone. Second, shuffled-frame and reversed-frame probes test temporal-order sensitivity: if performance barely changes when order is destroyed, the model is likely not using motion information. Third, the paper studies frame selection under budgets from 1 to 24 frames, comparing uniform sampling, random sampling, a GRPO-trained learned selector (HORNet), and a training-free key-clip selector (Frame2Clip). This helps separate several possible failure modes: whether one frame is already enough, whether more frames help, and whether better frame selection can recover motion understanding.19:T615,The empirical conclusion is straightforward: current Video-LLMs perform poorly on physically grounded motion understanding, and standard video-QA scores do not reveal this weakness. The paper evaluates models on MotionBlind together with TimeBlind and Video-MME. Non-contrastive benchmarks such as Video-MME can make models look broadly capable, but performance drops sharply when static content is controlled and only motion differs. The introduction cites TimeBlind as a reference point, where even strong frontier models reach only 48.2% instance accuracy while humans achieve 98.2%. MotionBlind narrows the focus further to speed, direction, and magnitude.

The diagnostic results are the most useful part. The text-only probe checks whether benchmark leakage through language priors is possible. The shuffled/reversed-frame probes test whether models are actually sensitive to temporal order. If order corruption causes only limited degradation, that is strong evidence that the model is reading static frames rather than motion. The frame-budget and frame-selection experiments then ask whether the issue is simply missing key frames. The paper’s answer is largely no: increasing frames or using more sophisticated selectors does not fully recover the missing capability. The excerpt provided here does not include the full result tables for MotionBlind, so I will not fabricate exact numbers. But the paper’s argument is clear: the bottleneck is deeper than frame sampling and points to weak motion representations in current Video-LLM pipelines.1a:T496,This is a good skim paper.
