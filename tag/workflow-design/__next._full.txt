19:T702,The system, AutoTrainess, is an LM agent built on top of a training-specialized Agent-Computer Interface, implemented as AutoTrainHub. Instead of leaving the agent in an open-ended shell, the environment provides a structured workspace and a set of semantically meaningful actions organized into four modules: data processing, training, evaluation, and logging/planning.

In the data module, the workflow is decomposed into data selection, data construction, and data validation. Selection chooses useful directions based on prior failures. Construction operates within a bounded set of transformations such as extraction, cleaning, deduplication, rewriting, restructuring, synthesis, distillation, and schema normalization. Validation explicitly checks compatibility with the benchmark-facing interface, including evaluation scripts and chat templates, and filters low-quality or risky samples. This is an important design choice: many of the checks that human practitioners do implicitly are turned into explicit agent actions.

The training and evaluation modules similarly expose actions such as launching training, launching evaluation, debugging evaluation, and summarizing results, all tied to scripts and artifacts in the workspace. The logging/planning module maintains experiment memory and supports iterative decision-making for the next round. So AutoTrainess is not a one-shot executor; it is an iterative post-training loop with structured state.

Methodologically, this is best understood as an agent harness or environment design paper.
