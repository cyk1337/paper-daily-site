18:T7d8,The core model is a 24-layer Transformer Omni-Encoder. Instead of feeding standard image patches plus a separate audio stream, the input at each timestep is organized into three token streams. Audio tokens come from log-Mel spectrograms processed by lightweight 1D CNNs and aligned to the video timeline at 25 fps. Visual Base (VB) tokens are standard patch embeddings and carry static appearance information such as texture, object shape, and scene layout. Visual Continuous (VC) tokens are the main novelty: each frame gets a learnable query token that absorbs inter-frame dynamics through joint self-attention, aiming to represent motion trajectories, gesture onsets, lip motion, gaze changes, and other high-frequency temporal cues. This explicitly separates static visual content from continuous motion.

For positional encoding, the paper introduces Omni-RoPE, a 3D rotary scheme that assigns all token types coordinates in a shared (t, h', w') space. The point is not just to add positions independently to audio and vision, but to make Audio, VC, and VB tokens distinguishable yet comparable inside one spatiotemporal coordinate system, while retaining RoPE-style extrapolation to different resolutions and sequence lengths.

Efficiency comes from two mechanisms. First, Temporal Window Shifting alternates local temporal windows and shifted windows across layers, reducing temporal attention complexity from O(T^2) to O(T·G), where G is the window size. This is conceptually related to shifted-window video Transformers, but here it is used for dense audio-visual joint encoding at 25 fps. Second, a Token Sparsifier is applied before the downstream Qwen-LLM 3B decoder. It keeps all Audio and VC tokens at full 25 fps, but sparsifies VB tokens down to 2 fps. This keeps the decoder-side token budget compatible with Qwen2.5-Omni without changing the decoder architecture.
