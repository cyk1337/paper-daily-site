9:T540,MaP has two main components. The first is Masked Trajectory Prediction. A GUI interaction is represented as a multimodal trajectory consisting of the user instruction plus, at each step, a screenshot m_t, a reasoning trace r_t, and an action a_t. Instead of defining separate input-output mappings for different tasks, the method randomly masks a fixed proportion of components in the full trajectory and trains the model to autoregressively recover the missing parts. This turns step-wise decision, state-action alignment, and long-horizon planning into the same problem: predict missing pieces given a partially observed trajectory. The important point is not masking by itself, but the move from task-specific marginal dependencies to modeling a more unified trajectory structure. The second component is role-aware adapter learning. The authors argue that heterogeneity is not only dataset-level but also token-role-level: instruction tokens, action tokens, reasoning text, and visual-state-related tokens induce different optimization directions. They therefore add token-wise adapters routed by semantic role, so different token types can use specialized representation subspaces while still sharing the backbone. Compared with dataset-specific adapters, this is a finer-grained way to handle heterogeneous supervision inside each sample.a:T42d,The evaluation spans five GUI navigation benchmarks: AndroidWorld, AndroidControl, GUI-Odyssey, AITZ, and Mind2Web. The main comparisons are against single-task training, direct mixture training, and MaP. The qualitative result is consistent: direct mixture yields only marginal improvements, while MaP outperforms both pairwise combinations and naive joint training across benchmarks. Two experimental messages matter. First, the masked trajectory formulation itself provides a large part of the gain, suggesting that objective unification matters more than simply adding more data. Second, the role-aware adapter gives additional improvements under cross-corpus training, supporting the claim that heterogeneity lives at the token-role level rather than being only a domain shift issue.
