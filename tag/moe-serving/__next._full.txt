19:T542,The method has three parts. First, the authors build a black-box calibrated cost model for the deployed expert kernel. Per-expert latency is modeled with a two-regime structure: a fixed activation floor for instantiating an expert replica, plus a token-dependent term that becomes relevant beyond an inflection point. They also explicitly model grouped-GEMM M-tile padding, which explains why splitting one expert across multiple replicas can create extra work instead of merely redistributing it. Second, they formulate per-batch dispatch as a fixed-charge makespan minimization problem over routed tokens and replica placements. The paper proves the problem is already NP-hard in a small setting, while showing that prior token-balancing and activation-balancing methods emerge as degenerate limits when certain terms vanish. This is a clean unification of earlier heuristics. Third, they propose tempo_fast, a practical near-optimal solver. It uses cost-aware seeding, augmenting-chain activation rebalancing for the flat regime, bottleneck-focused local search with partial migrations for the linear regime, and an ensemble that scores candidate solutions such as token-LP and round-robin under the same calibrated model. The strength of the algorithm is that each move is tied to a measured hardware effect rather than a surrogate objective.1a:T449,The most informative results are the measurement studies. On two generations of datacenter GPUs, expert FFN latency stays nearly flat up to about 156–168 tokens per expert, then transitions to a more linear region. The fitted activation floor b ranges from 1.74 microseconds to 14.8 microseconds depending on expert shape, an 8.5x spread, with mean fit error around 4–8%. In real decode traces, 92–100% of batches contain both regimes simultaneously: a few hot experts carry roughly 91% of tokens, while many activated experts still sit in the flat regime. Holding the batch and placement fixed and varying only the split, deployed proxy policies differ by 1.2–1.6x in modeled MoE block time, with p95 reaching 1.7x; each proxy pays a 30–70% penalty away from its preferred regime. On the optimization side, tempo_fast gets within about 1.02% of optimal or near-optimal references, which is strong given the combinatorial objective. The system uses an indirection already exposed by the engine to map each MoE layer to a small GPU scratch space that holds only the currently resident experts. Experts are paged between host memory and GPU memory based on routing behavior, so the GPU keeps a cache of likely useful experts rather than transferring an entire layer.

The more interesting part is memory allocation. The paper argues that expert pages and the KV cache must be managed jointly. The method is implemented both as an offline configurator and as an online controller. The paper also evaluates routing-based prefetching and finds that in low-concurrency decode it helps little, because there is not enough compute to hide PCIe transfer time.
