Beyond Downstream QA: Rethinking How We Evaluate Agent Memory

这篇论文要解决的不是“如何做更好的 agent memory”，而是“如何判断 memory 到底好不好”。作者指出，现有 memory benchmark 几乎都用下游问答准确率来做代理指标，也就是看 agent 最后答得对不对。但这种外在评测把三个环节混在了一起：memory 是否正确写入和更新、retrieval 是否把对的内容取出来、generation 是否把取回的信息组织成正确回答。结果会出现两类系统性误判：一类是假阳性，memory 实际上已经错了，但强模型靠局部线索和推理把答案补对；另一类是假阴性，memory 其实是对的，只是 retrieval 没取到，最后却把责任算在 memory 头上。论文的核心问题，就是为 agent memory 建立一种 intrinsic evaluation：直接检查 memory store 内部状态与已知真值是否一致，从而把 memory 本身和 retrieval/generation 解耦。

评如果你在看 memory/RAG 论文，这篇能帮你避开“QA 提升=记忆更好”的错觉；否则读 abstract 和 benchmark 设定就够了。

这篇工作处理的是长程 agent 执行里的一个具体但常被低估的问题：历史上下文不是越多越好，也不是只靠 recency 或语义相关性就能裁剪好。真正困难的地方在于，早先某次 tool 调用产出的局部信息，可能在很多步之后以变量、标识符、参数、约束条件等形式再次被复用；如果中间被压缩掉，模型当前这一步虽然看起来“语义上不太相关”，但执行上已经失去关键依赖。论文要解决的，就是如何在固定 history budget 下，把这类对后续执行仍有支撑作用的完整 tool result 保留下来，同时避免把整段历史都塞回上下文。

评只看依赖图构建和 reuse 信号即可；它给 agent memory 一个比相似度检索更硬的监督源。
Savini Kashmira,Jayanaka L. Dantanarayana,Lingjia Tang,Jason Mars
