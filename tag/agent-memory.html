The Compaction Cliff in Long-Running AI Agent Memory

这篇工作处理的是长会话 agent 在有限上下文预算下的记忆保真问题，尤其是“安全规则”和“普通经历日志”被同一种压缩策略对待时，会出现规则措辞被改写、限定条件丢失、最终失去可执行性的结构性失败。作者把这个现象定义为 Compaction Cliff：在多轮 compaction 后，真正需要逐字保真的约束类知识，比可容忍摘要化的背景信息衰减得更快。论文进一步指出，这不是单一 prompt 写得不够好，而是现有 production agent 常见的 type-blind memory management 在 compaction、decomposition、retrieval 三个操作上都没有区分知识类型，因此无法同时满足不同知识的保真要求。

评只看实验设置和安全规则保留曲线；它把“摘要压缩够用”这个 Agent prior 打得很具体。

这篇工作讨论的不是如何把 text-to-SQL 做得更高，而是如何衡量 test-time scaling 产生的“后续价值”。很多系统会用执行反馈、自修复、多轮采样等额外推理计算把一次失败的 SQL 修好，然后把修复轨迹存成 memory，供后续问题复用。现有评测通常只给一个端到端分数，无法区分收益到底来自重复问题的直接回放，还是来自对新问题的迁移帮助，也无法判断究竟是收集、验证、存储格式还是检索策略在起作用。作者把这个测量问题定义为 crystallization：一次性 test-time 计算，究竟有多少被“结晶”为可复用记忆，并在未来问题上兑现价值。

评读实验拆分就够了；4.34pp/44.4% 这个 amortization 数字，比又报一个 Text-to-SQL 分数更有用。
Jiaqian Wang,Yutao Qi,Wenjin Hou,Yuanxi Che,Muning Wen
