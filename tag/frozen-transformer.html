One Size Does Not Fit All: Setting Inference Depth from the Questions a Deployment Actually Asks

这篇工作研究的不是“如何发明一种新的 early exit 算法”，而是一个更贴近部署的问题：同一个通用语言模型在不同实际流量上，究竟能省下多少推理深度，以及怎样用部署侧已知的提问分布去设定 early exit 策略。作者关心的是单用户、本地或边缘设备场景下的 token 级计算浪费：模型对所有 token 一律跑满全层，但真实流量往往很窄，很多 token 在中间层已经足够确定。难点有两个，一是 exit 判定本身不能太贵，否则省下的层数被判定开销吃掉；二是提前退出后，上层没有产生对应的 KV cache，会影响后续 token 的注意力计算。论文的核心问题因此可以概括为：在冻结模型、不改主干训练的前提下，如何针对特定部署流量，系统地设计和评估可落地的 early-exit 配置，并量化“问题分布已知”带来的额外收益。

评这篇不会改写预训练方法，但会改你对 serving 预算分配的直觉；先看摘要和按任务分流量的那张主结果表，别把 early-exit 当全局常数。
