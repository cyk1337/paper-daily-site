The central hypothesis is that correct final answers are usually reached through a small set of stable intermediate outcomes, such as solved subproblems, validated constraints, case splits, or applied lemmas. Different correct trajectories may vary in wording, but they often converge on these checkpoints. The paper calls them consensus nodes. Construction proceeds by sampling N rollouts per prompt, keeping the correct ones, extracting intermediate conclusions from those trajectories, and clustering semantically equivalent conclusions into shared nodes. This is an important design choice: the target is not to imitate one canonical solution path, but to recover objective checkpoints that multiple successful paths pass through. Based on these nodes, the authors define ConsensusPR, a rule-based process reward that densifies the original terminal reward along the reasoning path. They also introduce three evaluation metrics: Final Answer Accuracy for endpoint correctness, Node Coverage Rate for how many consensus nodes a trajectory reaches, and Tokens per Node for reasoning efficiency. The metric design is tightly aligned with the failure modes they identify: NCR captures partial progress, while TPN distinguishes concise reasoning from verbose but uninformative chains. A practical advantage is that ConsensusPR plugs into existing GRPO and DAPO/RLVR pipelines without training a separate process reward model. Unlike PRMs, which try to score the quality of each step, ConsensusPR only checks whether the trajectory reaches verifiable intermediate states. First, it changes the data-parallel layout. Instead of assigning different prompts to different GPUs and generating multiple local samples per prompt, all GPUs process the same prompt while each rank generates a different sample. This reduces the need for each rank to retain multiple computation graphs for the same prompt group.

Second, it introduces two recompute-free schedules. LeanGRPO-Retain simply enables gradient tracking during rollout and keeps the selected-timestep graphs alive until terminal rewards and group advantages are available, then reuses those graphs for backpropagation. It is simple but activation memory grows with the number of selected timesteps.

LeanGRPO-Reweight is more subtle. During rollout, each selected-timestep graph is immediately consumed through a provisional backward pass, producing a provisional gradient and allowing saved activations to be released right away. Once the terminal reward and advantage are known, the provisional gradient is corrected using that advantage, recovering the same policy gradient in exact arithmetic. This shifts the memory burden from retained activations to stored provisional gradients. The paper positions both schedules as objective-preserving rather than approximate shortcuts.1c:T782,方法由两部分组成。第一部分是 dynamic per-trajectory rubric。不是为整个任务分布预先写一套固定 rubric，而是先根据任务指令生成初始 criteria，再结合每个 rollout 暴露出来的子目标、失败模式和执行路径，对 rubric 做扩展，最后把同一 group 内多个 rollout 提出的 criteria 合并成共享 rubric 集合。这样做的原因很直接：固定 rubric 往往覆盖不到长轨迹里真实发生的分叉和失败细节，而按轨迹动态生成可以让 judge 评价的是“这条轨迹实际试图完成了什么、卡在了哪里”，不是抽象模板。

第二部分是 distribution of rubric-conditioned advantage。标准 GRPO 对同一 trajectory 的所有 token 使用同一个 advantage；DRACO 改成先让 judge 对 rubric 中每个 criterion 给 verdict，再把 criterion 与轨迹中负责该 criterion 的步骤对齐，然后用一个闭式规则把 criterion-level judgment 分摊成 per-step advantage。论文强调这个分配规则满足若干形式性质，包括总量守恒、符号保持、长度无关等，目的是避免 credit 在长轨迹里被无控制地稀释，或者因为轨迹更长而系统性偏置。这里的关键不是“做 step reward”本身，而是 step reward 不依赖终局 verifier，也不依赖 learned reward model，而是直接从 rubric verdict 推出。

训练上仍然套在 GRPO 框架里：对每个任务采样一组轨迹，judge 对每条轨迹按动态 rubric 打分，再把 rubric verdict 重新分配到步骤，形成替代统一 trajectory advantage 的 step-level advantage。论文还比较了 frontier judge 与 self-judge，说明 judge 质量会直接影响 credit 质量。与已有 process reward 或 step-level RL 方法的差别在于，很多先前方法仍然锚定 gold answer、unit test 或 terminal reward；DRACO 刻意去掉了这些训练时真值依赖。1d:T6ef,DRACO has two main components. The first is dynamic per-trajectory rubric generation. Instead of writing one fixed rubric for the whole task distribution, the judge first proposes criteria from the task instruction, then extends those criteria using what each sampled rollout actually attempted, where it failed, and which subgoals emerged during execution. The criteria proposed from all trajectories in the same GRPO group are merged into a shared rubric set. The motivation is straightforward: fixed rubrics under-specify long trajectories, while rollout-conditioned rubrics can evaluate what the policy concretely did rather than what a generic template expected.

The second component is rubric-conditioned advantage redistribution. Standard GRPO assigns one scalar advantage to every token in a trajectory. DRACO asks the judge to score each rubric criterion, aligns criteria to the steps responsible for them, and then applies a closed-form redistribution rule to produce per-step advantages. The paper emphasizes several formal properties of this rule, including conservation of total push, sign preservation, and length independence. These properties are meant to prevent the usual failure mode where long trajectories dilute credit or where trajectory length itself introduces systematic bias.

Training remains within the GRPO framework: sample a group of trajectories, score them with a frozen judge under the dynamic rubric, and replace uniform trajectory-level advantage with redistributed step-level advantage.
