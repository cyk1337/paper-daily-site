在此基础上，作者推导了两个分配规律。其一是 compute-optimal suffix allocation law：给定某个前缀和动作，suffix rollout 数应按该动作的 continuation variance 与单位成本来分配，而不是平均分。其二是 marginal branching law：是否在某个前缀继续加一个新分支，取决于该前缀的 occupancy、score-weighted value uncertainty，以及新增分支的预期信息增益相对计算成本的比值。作者把这个量具体化为 EPIG，expected predictive information gain about the gradient。直观上，它不是问“这里模型是否犹豫”，而是问“如果我在这里多看一个分支，能否显著减少我对梯度方向的未知”。

算法层面，EPIG-Tree 不是完全抛弃 entropy。它先用 entropy 作为 proposal mechanism，筛出可能值得分叉的候选节点，因为低熵节点往往没有有效分歧；然后再用 EPIG 进行真正的算力分配，决定哪些节点值得扩展、哪些节点只需补 suffix、哪些节点不值得继续投入。这样做的原因很实际：直接精确评估所有节点的梯度信息增益代价太高，而 entropy 作为候选筛选器便宜且能排除大量无效位置。与 TreeRL/EPTree、TreePO 这类方法相比，区别不在“是否用树”，而在“树的生长目标函数”。已有方法更偏向局部不确定性或段级建模；这篇工作把目标直接对准梯度估计误差，并把 branch 与 suffix allocation 统一到同一方差框架里。10:T773,The core setup defines the local gradient contribution at a prefix h as a random variable Z_h and decomposes its variance via the law of total variance. This yields two distinct sources of estimator error. The first is decision uncertainty: variance induced by which action a is taken at prefix h, weighted by the score function and the action value Q_h(a). The second is continuation uncertainty: variance in the suffix return after the action has already been fixed. This decomposition maps cleanly to two compute operations. Adding a new branch reduces decision uncertainty. Adding more suffix rollouts under an existing branch reduces continuation uncertainty.

From this view, the paper derives two allocation laws. First, a compute-optimal suffix allocation law: suffix samples should be distributed according to continuation variance and cost, rather than uniformly across branches. Second, a marginal branching law: whether to add another branch at a prefix depends on occupancy, score-weighted value uncertainty, and the expected reduction in gradient-estimation error relative to compute cost. The operational quantity is EPIG, expected predictive information gain about the gradient. The key distinction is that entropy only measures whether branches can differ, while EPIG measures whether those differences matter for the gradient estimator.

Algorithmically, EPIG-Tree still uses entropy, but only as a proposal mechanism. Entropy cheaply filters candidate branching points, while EPIG decides where compute is actually spent. This is a practical compromise: exact information-gain evaluation everywhere would be too expensive. Compared with prior tree-based LLM RL methods such as entropy-triggered branching or segment-level tree modeling, the novelty is the objective function. For the who question, each prompt comes with a rubric made of criteria, verifiers, and weights. Instead of collapsing the rubric into a single scalar reward and discarding structure, the method scores both the student rollout and each candidate expert answer with the same criterion-specific verifier. An expert is allowed to teach a criterion only if it shows a verified advantage over the student on that criterion for the current sample. This is a local, sample-specific notion of expertise, not a fixed domain prior.

For the which question, even an eligible expert does not supervise the whole sequence. The method identifies positions where the expert disagrees with the student and applies distillation only on those tokens through a sparse mask. The intuition is simple: if the student already matches the expert, there is little value in forcing additional imitation; the useful signal lies where the expert would actually change the student’s local decision.

Training remains inside an on-policy RL loop. The base policy update uses a rubric-based GRPO-style objective on the student’s own rollouts. The distillation term is a token-level reverse-KL estimate, but its weight is no longer uniform. It is gated by verifier-based eligibility and by the disagreement mask.
