9:T543,LeanGRPO removes update-stage recomputation through a systems redesign with two pieces. First, it changes the data-parallel layout. Instead of assigning different prompts to different GPUs and generating multiple local samples per prompt, all GPUs process the same prompt while each rank generates a different sample. This reduces the need for each rank to retain multiple computation graphs for the same prompt group.

Second, it introduces two recompute-free schedules. LeanGRPO-Retain simply enables gradient tracking during rollout and keeps the selected-timestep graphs alive until terminal rewards and group advantages are available, then reuses those graphs for backpropagation. It is simple but activation memory grows with the number of selected timesteps.

LeanGRPO-Reweight is more subtle. During rollout, each selected-timestep graph is immediately consumed through a provisional backward pass, producing a provisional gradient and allowing saved activations to be released right away. Once the terminal reward and advantage are known, the provisional gradient is corrected using that advantage, recovering the same policy gradient in exact arithmetic. This shifts the memory burden from retained activations to stored provisional gradients. The criteria proposed from all trajectories in the same GRPO group are merged into a shared rubric set. The motivation is straightforward: fixed rubrics under-specify long trajectories, while rollout-conditioned rubrics can evaluate what the policy concretely did rather than what a generic template expected.

The second component is rubric-conditioned advantage redistribution. Standard GRPO assigns one scalar advantage to every token in a trajectory. First, it replaces standard PPO clipping with DPPO. Standard PPO clips the probability ratio, which means low-probability sampled tokens can be clipped by tiny absolute probability changes while high-probability tokens tolerate much larger ones. In large-vocabulary language models, this creates uneven update geometry. DPPO instead clips the absolute probability change of the sampled token, giving a common absolute-probability trust region.

Second, it bounds value predictions to the reward range. In outcome-reward settings, the return support is known. An unconstrained linear value head can easily overshoot that range, especially early in training, which then destabilizes both value fitting and downstream advantage estimates. Bounding the value head injects a simple but strong task prior.

Third, it trains the critic on Monte Carlo returns rather than bootstrapped targets. Because intermediate rewards are zero and the terminal reward carries the whole signal, the variance reduction from bootstrapping is limited while the bias from critic self-reinforcement can be severe. BPCO therefore prefers direct supervision from observed outcomes.

Fourth, it removes batch-wise advantage normalization in the policy update. The argument is that as the policy improves, the residual advantage scale should naturally shrink. Forcing every batch to unit scale erases that information and can keep magnifying noise late in training. BPCO preserves the raw advantage magnitude.

Fifth, it introduces length-adaptive GAE. With a fixed lambda, terminal reward is propagated backward with a length-dependent profile, so short and long responses receive systematically different credit assignment. The adaptive schedule is designed to make the effective weighting of terminal reward more consistent across response lengths.
