The starting point is a Fast-dLLM-style confidence-threshold sampler. At each step, the model predicts candidate tokens for all masked positions and assigns each sampled token a confidence score. Positions above a threshold λ are committed in parallel. If no position exceeds the threshold, the sampler enters a fallback mode and commits a single position so that progress continues.

The key observation is that fallback steps already identify moments of global uncertainty: no remaining position looks confidently resolvable. Those are precisely the steps where unresolved fork positions are likely to matter. Fork-dLLM therefore keeps the original confidence-based parallel behavior on ordinary steps, but changes the fallback rule. Instead of committing the highest-confidence position, it commits the leftmost masked position, i.e., an AR-style choice. This means the sampler only restores left-to-right ordering when the model itself signals that parallel confidence-based commitment is no longer reliable.

Why does this help? The issue with confidence-based decoding is not parallelism per se. The issue is that it tends to fill in easy, already-nearly-determined positions first, while delaying the positions that determine program branches, proof paths, or semantically meaningful continuations. By the time those fork positions are finally sampled, surrounding context has already collapsed much of the branching space, so different samples become too similar. Fork-dLLM intervenes exactly at those uncertain moments and resolves earlier positions first, preserving diversity where it matters most.

ForkGRPO extends the same idea to RL post-training. In dLLMs, exact trajectory likelihood ratios become awkward when multiple tokens are committed in parallel at one step. 第二步 verify：对 propose 出来的片段，恢复该片段开始前和结束后的环境状态，从这两个边界状态分别用当前策略采样新的 continuations。作者用两端 continuation 的经验终局成功率之差，来估计这个 segment 的 advantage。直观上，如果“经过这个片段之后”的状态更容易被当前策略继续做成，那么这个片段就确实为成功创造了更好的后续条件；反之，如果差异不明显，说明 judge 提议的片段未必真关键。这个设计很像把局部 credit assignment 建立在可验证 outcome 上，而不是建立在中间过程的语言评价上。

第三步 credit：只有当验证得到的 segment advantage 为正时，才把这部分额外 credit 加到原始 GRPO 的 token-level 更新上，而且只加给该 segment 内的 policy token。也就是说，ProVer 不是替换 GRPO，而是在 GRPO 的轨迹级优势之上叠加一个局部、稀疏、经验证的 bonus。这样既保留了 GRPO 不需要 value model 的优点，也缓解了 uniform advantage 带来的噪声。

In the propose stage, an LLM-based judge compares successful and failed trajectories from the same GRPO group and selects a segment in a successful trajectory that may have caused the divergence in outcome. The judge is used only for localization, not for direct reward assignment. This is an important design choice: it leverages model-based pattern recognition without trusting model judgment as the final training signal.

In the verify stage, the method restores the environment states immediately before and after the proposed segment, then samples fresh continuations from the current policy from both boundary states. The difference in empirical terminal success rates estimates the segment’s advantage. Intuitively, if the post-segment state is much easier for the current policy to complete successfully than the pre-segment state, then the segment likely contributed real causal progress.

In the credit stage, only positively verified segment advantages are added to the original GRPO advantages, and only for policy tokens inside the proposed segment. So ProVer does not replace GRPO. It augments GRPO with sparse, localized, outcome-grounded bonus credit.

Relative to prior approaches, the distinction is clear. It avoids a separately trained value model, so it reduces dependence on critic generalization. It avoids directly optimizing against an LLM evaluator’s intermediate scores, so it is less exposed to evaluator gaming. In standard multi-reward GRPO, the total reward is the sum of reward components, and the advantage is computed by centering and dividing by the within-group standard deviation of that total reward. The paper expands this variance term into the sum of all pairwise covariances among reward components. This reveals the issue: covariance mixes two effects, dependence and scale. If one reward has large variance, or if large-scale rewards are strongly positively correlated with others, they can inflate the denominator and shrink the advantage for the whole group.

CorrGRPO keeps the numerator unchanged: it still uses the centered total reward, so the relative weighting of reward components in the objective is preserved. The change is only in the denominator. Instead of covariance-based normalization, it uses Pearson-correlation-based normalization. In effect, each covariance term is divided by the corresponding component standard deviations, removing scale dependence. The diagonal terms of the resulting correlation matrix give equal footing to all reward components with nonzero within-group variance, while off-diagonal terms capture only the strength and direction of dependence. This lets the normalization remain sensitive to whether rewards reinforce or conflict with each other, without letting large numerical scales dominate.

An important practical point is that CorrGRPO does not redefine reward aggregation and does not require a new critic. It only changes advantage scaling, so it can be inserted into existing GRPO pipelines with low implementation cost. It is also conceptually different from manual reward reweighting or simple reward rescaling, because it modifies the normalization statistics rather than the reward objective itself.16:T526,The experiments cover three naturally multi-reward domains: code generation, tool calling, and agent security, using models from 0.5B to 8B parameters.
