Hydra: Phase-Aware Workload Characterization of LLM Inference across Edge SoC Generations, Backends, and Quantization Levels

这篇工作解决的不是某个新推理算法，而是 edge SoC 上 LLM 推理缺少统一、分阶段、可归因的测量框架。现有研究常见问题有三个：只看单一平台，难以比较代际变化；只测一种后端，HuggingFace 和 llama.cpp 的差异无法在同一口径下分析；只报端到端延迟或平均功耗，prefill 和 decode 的资源行为被混在一起。论文要解决的是，如何把不同 SoC、不同后端、不同量化格式、不同模型的推理行为放到同一 phase-aware schema 下，做可复现、可解释的 workload characterization。

Dual-Flow Transformers: Decoupling the Primary Prefill Path from Additional Decode Computation

LLM推理的prefill（并行处理prompt，受计算吞吐量约束）和decode（逐token生成，受内存带宽约束）两个阶段硬件瓶颈差异显著。传统的宽度/深度缩放会同步提升两个阶段的成本，现有测试时计算缩放方法（如思维链、暂停token）要么增加序列长度开销，要么需要修改持久化状态，无法在保持标准prefill主路径和KV cache结构不变的前提下独立扩展decode侧的计算量。

评这个想法值得看，因为它直接挑战“模型容量必须同时付 prefill 税”的默认设计；先盯住质量-延迟曲线和 KV 状态是否真干净。

Shallow Prefill, Deep Decoding: Efficient Long-Context Inference via Layer-Asymmetric KV Visibility

解码器-only大模型的长上下文推理成本高，Prefill阶段生成的全层KV缓存占用大量内存，且Decode阶段每层都要读取全量Prefill KV，导致首token延迟、单token生成延迟和KV内存占用随上下文长度和模型深度快速上升；现有方法仅压缩或近似上层Prefill KV，未从根本上消除上层对Prefill KV的依赖。
