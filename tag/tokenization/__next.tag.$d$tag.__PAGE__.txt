实验对象是小型 causal boundary predictor，在 matched FineWeb-2 文本上训练，在 FLORES-200 的多语种面板上评估。作者把错误分成 scalar ends 上的平衡误差，以及 scalar 内部的 false cuts；后者可以用规则 mask 去掉，不改变 scalar end 的判定，因此主分析集中在真正有意义的边界决策上。论文还构造了一个很强的诊断实验：找出那些左上下文完全相同、下一个 scalar 落在同一 256-codepoint page、但边界决策相反的成对样本。对这类样本，若编码首符号不携带足够信息，模型再怎么学也无法在一符号 lookahead 下全对；这使得“可学性”与“表示可区分性”被清楚地分开了。a:T773,最关键的结果有三组。第一，在 17 种语言的 FLORES-200 面板上，针对 every-cluster target、只允许 one-symbol lookahead 时，UTF-8 在 scalar ends 上的 balanced error 是 8.76%，UBE 降到 0.06%，而同长度控制 UBE-BE 仍有 8.62%。这个结果很硬，因为它几乎直接说明收益来自字节顺序，而不是仅仅因为 UBE 把 3-byte UTF-8 压成了 2 个符号。第二，在作者构造的 17,204 对“相同左上下文但应作相反决策”的样本上，UBE 的训练后预测器在每个 seed 都能全部答对；UTF-8 和 UBE-BE 做不到，因为两者在关键位置看到的首符号相同，信息先天不足。第三，在 Korean 和 Chinese 这类 grapheme 边界基本等于 scalar end 的语言里，问题不再是 cluster continuation，而是 retained-parent task 中“哪些字符边界要保留为 subword 边界”。在 one-symbol lookahead 下，UBE 相对 UTF-8 的总 retained-parent error 分别下降 72.91% 和 35.29%；在另外 8 个脚本上，下降幅度在 67.32% 到 99.55% 之间。作者还指出，当某脚本主要 Unicode block 落在单一 256-codepoint page 内时，UBE-BE 与 UTF-8 会比较接近，这与“low byte first 在页内直接暴露字符身份”的机制一致。

另一个很有价值的部分是对已发布 byteification 模型的审计。作者检查了 Bwen-8B（Qwen3-8B-Base 的 Bolmo-style 转换），发现它在 18 个高碎片化语言里至少保留了 97.07% 的父模型内部切分，cluster-internal cut 数量与父 tokenizer 相差不超过 1.54%。这说明现有 byteification 流程虽然去掉了显式 tokenizer 接口，但切分偏好几乎原样继承，cluster 内部碎裂并没有真正解决。论文据此论证：如果先删除 cluster-internal cuts，再训练边界预测器，监督会更干净，也更符合 byte-level 接口想要达到的语言无关性。b:T7be,The paper has two main technical components. The first is target construction. Instead of inheriting all parent tokenizer boundaries, the authors define grapheme-aware supervision in two forms: an every-cluster target that keeps every grapheme boundary, and a retained-parent target that keeps only those parent-tokenizer cuts already aligned with grapheme boundaries. Grapheme clusters are chosen because their boundaries are representable across encodings, stable under span-preserving edits, and directly isolate the continuation-vs-new-cluster distinction that encoding order can obscure.

The second component is the encoding comparison. The paper uses Universal Byte-Level Encoding (UBE), which keeps one- and two-byte UTF-8 encodings unchanged but rewrites longer scalars as UTF-16 little-endian bytes. For codepoints that would take three bytes in UTF-8, UBE shortens them to two symbols and, more importantly, exposes the low byte first. Within a known 256-codepoint page, that first symbol often identifies the codepoint directly. To separate stream-length effects from byte-order effects, the authors introduce UBE-BE, a big-endian control with the same routing and stream length as UBE but reversed byte order inside each UTF-16 code unit. This is a strong control: if UBE wins over both UTF-8 and UBE-BE, the gain cannot be explained by shorter streams alone.

They train small causal boundary predictors on matched FineWeb-2 text and evaluate on a multilingual FLORES-200 panel. Errors are split into scalar-end decisions and false cuts inside scalars; the latter can be removed by a rule-based mask without affecting scalar-end decisions. A particularly clean diagnostic is the constructed-pair test: pairs with identical left context, next scalars on the same 256-codepoint page, but opposite correct boundary decisions. On such pairs, failure is not about optimization difficulty. It is about whether the encoding exposes enough information at one-symbol lookahead.c:T6ed,Three results carry most of the paper. First, on the 17-language FLORES-200 panel for the every-cluster target with one-symbol lookahead, UTF-8 yields 8.76% balanced error at scalar ends, UBE drops this to 0.06%, while UBE-BE remains at 8.62%. This is the clearest evidence that byte order, not just shorter streams, drives the improvement. Second, on 17,204 constructed pairs with identical left context but opposite correct decisions, the trained UBE predictors solve all pairs correctly for every seed. UTF-8 and UBE-BE cannot, because both expose the same first symbol at the critical position. That turns the argument from empirical correlation into representational necessity.

Third, the paper examines Korean and Chinese, where evaluated grapheme clusters are single scalars, so the task becomes subword-boundary selection rather than grapheme continuation. Each document is represented as a byte-level DAG whose edges are candidate substring occurrences. Byte edges are always available; multibyte edges are available only if the corresponding string is selected into the vocabulary. Given a vocabulary, minimum-count encoding is just a shortest path in the usable subgraph. The coupling difficulty is that selecting one token type enables all of its occurrences across the corpus.

The main idea is an occurrence-level Lagrangian relaxation. Each candidate occurrence gets a non-negative price lambda_e. On the document side, segmentation becomes a shortest-path problem with edge costs increased by these prices. On the vocabulary side, each token type accumulates the total bid of all its priced occurrences, and the lower bound subtracts the sum of the top-K bids allowed by the vocabulary budget. This yields a computable lower bound without a generic LP solver: shortest paths per document plus a global top-K selection over token bids. The paper argues that maximizing over prices recovers the LP relaxation, while validity of the reported bound is checked separately with an exact integer checker.

A useful extension is the boundary-licence formulation. Instead of only comparing the two endpoints—fully regex-constrained versus fully unrestricted—the method allows a budget on how many vocabulary entries may cross regex cuts. That produces a compression frontier and makes the design question continuous: how much compression can be recovered by permitting a small number of cross-boundary tokens.

The paper also keeps compression and prediction separate. Compression is analyzed through certified token-count intervals. Prediction is evaluated on held-out data with an explicit vocabulary and decoding protocol, because unrestricted vocabularies change token frequencies, context granularity, and effective predictability, not just sequence length.f:T52e,The headline result on English Wikipedia is a certified boundary tax: regex boundaries increase the optimal token count by 28.3% to 36.8%.
