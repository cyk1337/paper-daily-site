The outer loop optimizes a workflow sketch, while the inner loop optimizes the prompts of individual LLM calls under a fixed sketch. A workflow is represented as a sequence of high-level textual call descriptions a1 to aK, and each call has an associated detailed prompt theta_i. The sketch specifies what each step is supposed to do, while the prompt specifies how it should do it, including instructions and tool access. This separation keeps the search space manageable.

The inner loop performs layer-wise textual backpropagation. The workflow is treated like a stack of modules: x0 is the input, and each call maps x_{i-1} to x_i. After a forward pass, the final module receives a textual gradient generated by another LLM conditioned on the final output, the gold answer, and the task loss. This gradient is not numeric; it is natural-language feedback describing how the module should change its behavior. For intermediate modules, another LLM generates a textual gradient based on the current module’s input, output, and the downstream gradient. In this way, error information is propagated backward through the workflow in language form. A separate optimizer LLM then aggregates gradients over a batch and rewrites the module prompt.

The outer loop edits the workflow sketch itself. It uses textual feedback to add calls, delete calls, and revise the decomposition of responsibilities across steps. This is inspired by neural architecture search, but instead of searching over a fixed operator library, it edits workflow descriptions directly in text space. That makes the method expressive enough to represent retrieval, planning, verification, and tool use in a unified way, though it also makes optimization more dependent on the quality of the underlying LLM.

Compared with prior prompt-optimization methods, FlowBot does not assume a fixed workflow. Compared with one-shot workflow generation methods, it alternates between structure updates and module-level prompt updates, allowing both to co-evolve. The modular optimization aspect is important: each module is updated in light of downstream failures rather than in isolation.f:T539,The empirical study compares FlowBot against two classes of baselines: prompt-optimization methods on human-crafted workflows, such as GEPA, and automated workflow-generation methods, such as AFlow.
