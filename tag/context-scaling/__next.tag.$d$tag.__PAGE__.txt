b:T78d,The technical contribution has two layers. The first is the formulation. A skill is treated as a modular capability package that may include natural-language instructions, invocation conditions, tool-use procedures, executable code, and auxiliary resources. Based on this, the SRA pipeline is decomposed into three stages: skill retrieval, which asks whether the system can find relevant skills from a large external corpus; skill incorporation, which asks whether the agent can identify and organize the useful skills among retrieved candidates; and skill application, which asks whether those incorporated skills are actually used in a way that improves task success. This decomposition is useful because it separates retrieval failure from reasoning failure and execution failure.

The second layer is benchmark design. The paper introduces a large-scale skill corpus and SRA-Bench, where each instance contains a user query, a ground-truth answer, and gold skill annotation. That enables stage-wise evaluation instead of collapsing everything into a single end-task metric. The benchmark is designed to diagnose whether the right skill was retrieved, whether the agent recognized it as useful, and whether using it improved behavior. The novelty is therefore less about a sophisticated retrieval model and more about defining the right object of retrieval and the right evaluation protocol.

A central design choice is the explicit distinction from classical RAG. In knowledge-centric RAG, retrieved items are declarative evidence. In SRA, retrieved items change the agent’s action space. That means a semantically similar skill can still be useless, and a retrieval metric that ignores execution utility can be misleading.
