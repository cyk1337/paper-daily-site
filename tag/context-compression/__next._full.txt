1a:Ta96,SeDeM 的方法可以概括成四步：分段、压缩、选择、解压注入。

第一步，长上下文被切成多个 segment。对每个 segment，作者不训练一个新的 encoder，而是用冻结的 LLM 作为特征提取器，从某个中间层 l_extract 取 hidden states。这里的判断是，中间层表示已经包含局部上下文化信息，但还没有被后续层过度任务化，适合做通用记忆载体。

第二步，压缩器不是把 learned memory token 插进 Transformer 里参与多层自注意力，而是用轻量、非注意力的局部压缩。具体做法是把一个 segment 的 hidden states 按连续窗口分块，每个 memory slot 汇总 C 个相邻 token 的 hidden state，先做 mean pooling，再做投影，得到 N_M 个 memory slots。这样每个 slot 对应一个局部区域，信息来源明确，也减少了“压缩 token 在层间不断漂移”的问题。作者显然是在反对 ICAE/soft prompt memory 那类让 memory token 在网络里不断被更新的设计。

第三步，给定 query，selector 在 memory block 级别做 top-k 选择。训练时使用 block-level evidence supervision，也就是用证据块标注来教 selector 找相关 segment。这一点很重要，因为如果没有显式监督，query-conditioned retrieval 很容易学成模糊的相似度匹配，未必真能找到回答所需证据。

第四步，只对选中的 memory block 做解压。decompressor 把紧凑 memory 恢复成与 decoder 某个中间层 l_inject 兼容的 hidden states，然后把这些重建状态注入 decoder。decoder 因此不是从压缩 memory token 直接生成，而是从“被恢复到中间表示空间”的证据上生成。作者把这叫 selective decompression。这里的关键不是压缩本身，而是把 storage 和 conditioning 解耦：memory 可以压得很紧，但真正参与生成的是解压后的、层空间匹配的表示。

全文还强调一个扩展能力：encoder 和 decoder 可以不是同一个模型规模。小模型可以离线构建 memory，大模型在线解压并回答问题。这样上下文处理成本和回答能力被拆开了。这一点对 serving 很现实，因为长文档预处理可以离线做，在线只保留 query-conditioned 选择和有限解压。

和已有方法相比，SeDeM 不同于 hard token selection，因为它保留的是连续 hidden-state memory；也不同于 learned memory token 直接作为 soft prefix 的方法，因为它不要求压缩表示同时承担存储和生成条件两种角色。作者的核心主张是：高压缩率下，直接 conditioning on compressed memories 是瓶颈，必须先恢复到 decoder-compatible hidden states。1b:T96a,SeDeM has four stages: segmentation, compression, selection, and decompression with layer injection.

First, the long context is split into segments. For each segment, a frozen LLM acts as a feature extractor, and hidden states are taken from an intermediate extraction layer l_extract. The design intuition is that intermediate states already encode local context but are not yet too specialized by later layers.

Second, compression is deliberately lightweight and non-attentional. Instead of inserting learned memory tokens into the Transformer and letting them evolve through self-attention, the method partitions a segment's hidden states into contiguous local chunks. Each memory slot summarizes C neighboring token states via mean pooling, followed by projection, producing N_M memory slots per segment. This keeps each slot tied to a local region and avoids the representation drift that can happen when compression tokens are repeatedly updated across layers.

Third, given a query, a selector retrieves the top-k relevant memory blocks. The selector is trained with block-level evidence supervision, which is an important practical choice: it gives the retrieval stage explicit supervision about where answer-bearing evidence lives, instead of relying only on weak end-task signals.

Fourth, only the selected memory blocks are decompressed. A decompressor expands compact memories into hidden states that are compatible with an intermediate decoder layer l_inject, and those reconstructed states are injected into the decoder. The decoder therefore does not generate directly from compressed memory slots. This is the central claim of the paper: storage can be highly compressed, but generation should condition on reconstructed hidden states in the decoder's representation space.

The paper also emphasizes a cross-model setting. A smaller model can build memories offline, while a larger decoder consumes decompressed memories online. That decouples context-processing cost from answer-generation capacity, which is attractive for serving.

Relative to prior work, SeDeM differs from hard token selection because it stores continuous hidden-state memories, and it differs from soft-prefix memory methods because compressed memories are not used directly as the generation prefix. The key thesis is that direct conditioning on compressed memories becomes the bottleneck at high compression ratios.1c:T769,The evaluation covers four long-context QA datasets: 2WikiMultiHopQA, MuSiQue, QASPER, and HotpotQA-Distractor. Results are reported with Llama-3.2-1B and Llama-3.2-3B in same-backbone settings. The paper claims that SeDeM outperforms all evaluated compression baselines across the four datasets in the reported setup. With the 3B backbone, it even surpasses the full-context fine-tuned reference on 2WikiMHQA, QASPER, and HotpotQA-Distractor, while remaining below the full-context reference on MuSiQue. That pattern suggests the method is especially effective when evidence can be localized and selected at the block level, while more compositional multi-hop reasoning still suffers from compression and selection loss.

On efficiency, SeDeM reduces online time-to-first-token and improves autoregressive decoding throughput compared with ICAE. This matches the design: the decoder no longer needs to attend over the full raw context or a large soft-memory prefix.

The most important ablation is that direct memory conditioning is substantially weaker than selective decompression. That result matters more than the headline table because it validates the paper's main design argument: the gain is not just from compressing context, but from reconstructing selected memories into decoder-compatible hidden states before generation. Another important point is the use of block-level evidence supervision for the selector. If the full paper includes comparisons against weaker supervision, that will tell you how much of the final gain comes from the retrieval signal itself.

The provided text confirms the model scales, datasets, and relative wins, but not the full EM/F1 numbers. Start from the introduction, where the critique of existing soft-compression methods is stated cleanly: compact memory tokens are being asked to do two incompatible jobs, storage and decoder conditioning. Then focus on two parts of the method: why the compressor is intentionally simple, using local mean pooling plus projection instead of another attention-heavy module, and how the decompressor reconstructs hidden states aligned to the injection layer. If there is a system diagram, read that before the equations.

In the experiments, prioritize three things. First, the main comparison against full-context inference, hard compression, and soft-memory baselines. Second, the ablation of direct conditioning versus selective decompression; that is the key evidence for the paper's thesis. Third, any cross-model results with a smaller encoder and larger decoder, since those speak directly to deployability.

HIPIF instead keeps a compact working context composed of the current subgoal, the necessary local interaction history for that subgoal, and a folded summary of completed progress. The model proposes an initial subgoal, executes actions under that subgoal, and decides when the subgoal is completed or should be terminated. Once a subgoal ends, its execution history is folded into a progress summary, and the model proposes the next subgoal. To make this stable, the method adds hierarchical reflection for judging subgoal completion, correcting subgoal content, and deciding whether to continue execution or replan. Training uses GRPO for subgoal-centric decisions and introduces subgoal-oriented process rewards for both subgoal generation and within-subgoal execution. The main difference from methods using only terminal rewards, external process-reward annotators, or auxiliary decomposition models is that planning, folding, reflection, and execution are trained within the same agent policy.1f:T66f,The main paradigm is Context-ReAct, which augments the standard ReAct loop with explicit context meta-actions. At each step, the agent jointly generates its reasoning trace, a set of context-edit operations, and the next tool call in one autoregressive pass. The meta-operations are applied before the next observation is appended, so the agent actively curates its working memory online.

The operation vocabulary has five atomic actions. Skip leaves the context unchanged. Compress replaces a contiguous span of prior steps with an abstractive summary. Snippet preserves an exact substring from a previous step, which is useful for numbers, entity names, quotations, or code where abstraction is risky. Delete removes a step that no longer carries value. Rollback abandons an unproductive branch by reverting to an earlier state while retaining the reason for backtracking and any transferable insight.

The key idea is not merely adding more actions. It is changing the representation of context from a uniform text log into a multi-resolution working memory. The paper also argues expressive completeness: in principle, Compress can simulate the other operations, but specialized operators reduce generation cost and fidelity loss. That is a sensible engineering choice, similar to designing a practical instruction set rather than relying on a theoretically minimal one.

The instantiated system, LongSeeker, is fine-tuned from Qwen3-30B-A3B on 10k synthesized search trajectories. The important training detail is that the data must teach not only how to search, but when to preserve exact evidence, when to summarize, and when to roll back.20:T53d,LongSeeker is evaluated on BrowseComp, BrowseComp-ZH, xbench, and GAIA. The headline numbers in the paper are 61.5% on BrowseComp and 62.5% on BrowseComp-ZH, compared with 43.2% and 46.7% for Tongyi DeepResearch, and 36.2% and 47.3% for AgentFold. These gains suggest that elastic context control matters most in long-horizon, tool-augmented search rather than in short QA settings.

The most informative experiments are likely threefold. First, comparisons against sliding-window, periodic summarization, and restart-style baselines, to test whether adaptive context editing really beats fixed policies. Second, ablations over the five operations, especially Snippet and Rollback. Those two are the clearest indicators that the method is doing more than generic summarization. Third, analyses of context length, token cost, and success rate. If the paper reports trajectory-level statistics, the important question is whether the agent maintains or improves accuracy while operating on a shorter and cleaner context.

The training scale is modest at 10k synthesized trajectories, so the result is more about the usefulness of the paradigm than about data scale. One caveat to watch is whether the synthesis pipeline bakes in a particular search style from the teacher, which could limit generalization if the evaluation distribution shifts.21:T448,This is best read as a context-interface paper rather than a benchmark paper. Start with the method section and understand exactly what Context-ReAct adds over standard ReAct. The most important part is the semantics of the five operations and the failure modes they are meant to address. Snippet and Rollback deserve special attention because they are the strongest departures from ordinary summarization.

Then read the data synthesis and training pipeline. The key question is where supervision for the meta-operations comes from and how the trajectories are constructed. If that part is weak, the whole method risks collapsing into a prompt-level heuristic.

Finally, inspect the main results and ablations with an efficiency lens: whether gains come with lower token cost, which operations are used most often, and whether failures are caused by bad compression, bad deletion, or poor search policy.

A 20–30 minute skim is enough for the main ideas.
