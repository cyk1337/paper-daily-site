9:T703,The method starts by separating queries into two behavioral types. Local queries mostly attend to nearby tokens. Global queries, associated with TRTs, attend back to distant earlier context. The paper then shows that these global queries are not scattered arbitrarily in query-embedding space; they form a small number of similarity clusters. This motivates beacon queries: a compact set of representative queries intended to approximate future global revisiting patterns.

At eviction time, BeaconKV does not score historical KV entries using only recent queries. It also keeps a small set of beacon queries. A token is retained not only if it matters to the current local decoding state, but also if it is important to one of these representative global queries. This gives the system a way to protect tokens that may not look useful now, but are likely to be revisited later.

Because decoding is online, beacon queries cannot be obtained by offline clustering over the full query history. The paper therefore proposes Continual Farthest Point Sampling, an online procedure that incrementally selects geometrically diverse queries while keeping memory bounded. Intuitively, it maintains a compact cover of the query space seen so far. Compared with storing the full query history, this is memory efficient; compared with using only recent queries, it preserves information about potential future global attention patterns.

Methodologically, BeaconKV is training-free. It does not modify model weights and does not require distillation or calibration. The design has three main pieces.

First, a block-diffusion head predicts a whole future block of length B in parallel. The key point is that the target model itself remains unchanged and autoregressive; the diffusion-style component is only the drafting head. Given the committed prefix and the target’s already fused vision-language state, the head outputs token distributions for all positions in the block in a single forward pass. This removes the usual depth cost of k sequential draft passes for k drafted tokens.

Second, GLANCE constructs a wide candidate tree from the block-level distributions. In this setup, width becomes the cheap axis because the block has already been drafted in one shot. Expanding multiple high-probability prefixes does not require repeated draft passes; most of the extra cost is pushed into verification. This is a major departure from standard autoregressive drafters, where both depth and width are expensive because they are built sequentially.

Third, the target verifies the whole tree in one pass, and the paper proves that the committed path is exactly identical to the target model’s own greedy decoding. The lossless claim is therefore strict: not approximate quality preservation, but exact equality to greedy output. The authors also add runtime gating so that equality is checked rather than assumed.

第二部分是 Attn-Repair。作者指出，传统 held-out R² 只衡量 cache 坐标重建，而生成质量取决于这些误差经过目标模型 query 与 attention 组合后的放大或抵消。因此相同的 KV 拟合误差，可能对应完全不同的续写漂移。Attn-Repair 的做法是按残差对接收模型 attention 输出的一阶影响来重加权，相当于让拟合更关注那些会真正改变后续注意力计算的方向，而不是平均对待所有 cache 坐标。为了避免权重过度集中到极少数样本，作者加入 effective-sample-size floor 来限制退化，但不改变在线映射形式。

第三部分是 Fused-Fit。由于不同目标层会选择不同源层支持，top-k layer 选择会造成碎片化 gather，通用拟合器在构建加权充分统计量时会反复做 scattered materialization、centering 和 weighting，内存流量很大。Fused-Fit 用新的 fused GPU kernel 在有界 panel 内直接构建 head-batched 矩阵乘法所需统计量，保持同样的 ridge solver 和同样的最终 mapper artifact，只是把离线构建过程做成结构感知的高效实现。这个部分没有改变数学目标，但大幅改善了 mapper construction 的时间和内存行为。

整体上，CacheBridge 不是提出新的在线推理协议，而是在“离线拟合、在线仿射应用”这个框架内，把支持结构、目标函数和实现路径都改得更贴近真实 continuation quality。17:T9b6,CacheBridge combines three components and keeps the online deployment interface unchanged: an offline-fitted affine mapper that can be applied directly at handoff time.

The first component is Head-Local. Full-Head Mapping regresses each target KV head on the concatenation of all source KV heads from selected source layers. CacheBridge argues that this assumes an overly dense correspondence between models. Instead, each target head is restricted to a single architecture-indexed source-head block, while still allowing cross-layer aggregation. This reduces fan-in dramatically and cuts the coefficient count by the number of source heads, 8× in the reported setup. More importantly, it biases the mapping toward a subspace that better matches architectural locality, reducing harmful cross-head coupling when the source and target architectures differ.

The second component is Attn-Repair. The paper points out that held-out R² only measures coordinate-wise cache reconstruction, while continuation quality depends on how those errors propagate through the target model’s queries and attention computation. Two mappings with similar cache fit can therefore produce very different continuation drift. Attn-Repair reweights residuals according to their first-order effect on the receiver’s attention output. In other words, it emphasizes errors that actually matter for downstream attention behavior rather than treating all cache coordinates equally. An effective-sample-size floor prevents the weighting from collapsing onto a tiny subset of examples, while preserving the same online affine form.

The third component is Fused-Fit. Because different target layers may choose different source-layer supports, top-k support selection creates fragmented gather patterns. A generic fitter repeatedly materializes scattered tensors, centers them, and applies weights, so memory traffic becomes a major cost. Fused-Fit introduces a fused GPU kernel that constructs the weighted sufficient statistics directly in bounded panels for head-batched matrix multiplication. It does not change the ridge objective, the solver, or the deployed mapper artifact; it simply makes offline construction structure-aware and much more efficient.

Taken together, CacheBridge does not propose a new online protocol. It refines the existing offline-fit / online-affine-transfer framework by redesigning support structure, fitting objective, and construction path around actual continuation quality.18:T70b,The evaluation covers three transfer directions, with two difficult Ministral 3 directions and one Qwen3 direction being the most informative. Under the same 500-sequence calibration protocol and the same 8×128 KV interface, transfer to Qwen3 32B remains close to the target baseline, 79.2% versus 80.2%. But the two Ministral 3 directions targeting 14B drop sharply to 52.2% and 44.4%. This shows that the existence of a linear transfer path does not mean dense all-head mapping is the right inductive bias.

CacheBridge recovers 20.4 and 31.6 HellaSwag points on those two difficult directions, while preserving 99.83% mean target retention on Qwen3 14B→32B. So the gain is not coming from overfitting to one architecture family.
