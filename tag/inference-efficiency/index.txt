具体做法分两部分。

第一部分是监督信号构造。作者对同一个样本运行 full-denoising decoding，得到一个无 cache 近似误差的参考轨迹。这个轨迹给出了每个 unresolved position 在未来何时会被提交，或者说它离“即将成为关键决策点”有多近。TraceQuery 不试图搜索最优轨迹，也不强行让推理时完全跟随 reference trajectory，而是把这个 full-denoising trajectory 当作 router 的训练标签：学习在当前解码状态下，对 unresolved positions 做 near-future relevance ranking。

第二部分是推理时的稀疏查询。在线推理时，模型不会对所有 unresolved positions fresh recompute，而是先从当前可廉价获得的 decoding-state signals 中提取特征，由一个轻量 router 预测哪些位置最值得查询。被选中的少量 candidates 才会重新计算表示；其余位置继续复用 cache。随后 backbone dLLM 只在这些 freshly evaluated candidates 中决定最终 commit 哪个位置或哪些位置。这里有一个很重要的拆分：router 只负责“算哪里”，backbone 仍负责“提交什么”。这样做比直接让 router 决定 commit 更稳，因为最终决策仍由原模型完成，避免轻量模块过度接管生成。

从论文表述看，这个框架适用于 single-block 和 block-wise diffusion decoding。它也兼容现有 cache-based sparse decoding setting，但目标函数变了：不是最小化 cache reuse induced representation error，而是最大化对 full-denoising near-future trajectory 的覆盖。作者强调使用的是当前状态下可便宜获得的信号，因此 router 本身的额外开销应当较小，重点是用少量 fresh token computations 换更接近 full denoising 的轨迹。19:T40f,The main value is conceptual as much as practical. For diffusion LM inference, it shifts the optimization target from “repairing cached states” to “spending compute on positions that matter for the upcoming decoding trajectory.” That is a better fit for iterative non-AR generation, where small early decision errors can compound over many denoising steps. A second contribution is methodological: the full-denoising run is turned into a supervision source for query allocation. Instead of treating full denoising only as an expensive reference, the method learns from it which unresolved positions are near-future critical. This is useful beyond the specific implementation here. Any iterative LM that alternates approximate state reuse with selective recomputation could potentially benefit from a trajectory-aware control policy. In terms of contribution type, this is not a new pretraining paradigm, but it is a meaningful inference-side improvement for diffusion LM systems, especially where quality-compute trade-offs matter.1a:T869,The method, TraceQuery, is framed as trajectory-guided sparse decoding. The paper first proposes a causal view of cached decoding errors: representation error perturbs decoding decisions; perturbed decisions cause trajectory divergence; trajectory divergence then leads to quality loss. Under a limited compute budget, directly targeting the decision layer is therefore more efficient than uniformly reducing representation error.

The method has two key components.

First, it constructs supervision from full-denoising trajectories. For a given example, the model is run in full-denoising mode, producing a reference trajectory without cache-induced approximation. This trajectory tells us which unresolved positions are likely to become important soon—effectively a notion of near-future relevance. TraceQuery does not try to search for an optimal trajectory, nor does it force inference to exactly follow the reference. Instead, it trains a lightweight router to rank unresolved positions according to how soon they matter along the full-denoising path.

Second, at inference time, the router uses inexpensive signals available from the current decoding state to select a small fresh-query set. Only those candidate positions are recomputed from scratch; all other unresolved positions continue to reuse cached representations. The backbone dLLM then makes the actual commit decision among the freshly evaluated candidates. This separation is important: the router decides where to spend computation, while the backbone retains control over what to commit. That design keeps the lightweight module from directly taking over semantic generation decisions.

The framework is described as applicable to both single-block and block-wise diffusion decoding. It is compatible with the general cache-based sparse decoding setup, but changes the objective. Instead of minimizing cache-induced representation error, it tries to maximize alignment with the near-future full-denoising trajectory. The practical premise is that the router can operate on cheap state features, so the extra overhead remains small relative to the saved fresh token computations.1b:T6ca,The experimental story is centered on quality-compute trade-offs and trajectory analysis rather than on a single scalar metric.
