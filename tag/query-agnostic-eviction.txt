18:T86f,方法设计很克制。它不替换原有 eviction 方法，而是在其前面加一个单次 restore pass。具体做法是：先对完整上下文做正常 prefill，得到 full KV cache；然后插入少量 restore tokens，文中默认是 8 个，这些 token 在一次额外前向中可以 attend 到 full cache。这个 restore pass 只在构造压缩 cache 时运行一次，并通过 LoRA 适配过的注意力模块，把上下文信息写入这 8 个 restore token 对应的各层 KV 中，形成 restore cache。之后再按原始 eviction 规则，从真实上下文 token 的 KV 中选出剩余预算的 retained cache；restore cache 与 retained cache 拼接后，组成总预算不变的最终 cache。

训练方式是离线 self-distillation。教师模型是 frozen full-cache model，学生模型使用 budget-matched final cache。给定同一 context 和 query，优化目标是让学生在 answer token 上匹配教师分布。更新参数非常少，只训练 restore token embeddings 和 restore pass 中的 LoRA；backbone 与 base evictor 都冻结。这个设计有两个关键点。第一，restore 不是通用前缀，也不是把整个 prefix 重写成新状态，而是只学习一个小补丁，因此兼容已有 importance scorer。第二，LoRA 只在 restore pass 打开，后续 query processing 和 decoding 完全沿用原始压缩 cache 的推理路径，所以在线开销几乎不变。

论文里最有信息量的部分是组件消融。作者把收益拆成“restore token 自身记忆了什么”与“注意力侧适配学会了如何从 full cache 提炼补偿信息”两部分。结果显示，仅优化 restore embeddings，KVzip 在 5% 预算下从 38.2 提到 42.1，提升有限；固定 embeddings、只学 LoRA 可到 71.9；只适配 q/k/v 投影就有 72.4，接近完整 RestoreKV 的 73.2。这说明主要收益来自 attention-side adaptation，而不是把常识或模板塞进几个特殊 token 里。换句话说，restore tokens 更像一组可学习的读写槽位，真正起作用的是它们如何从 full cache 中抽取并编码“被 eviction 后最容易丢失的补充信息”。19:T830,RestoreKV is deliberately lightweight. It does not replace the base eviction method. Instead, it adds a single restore pass before eviction. The pipeline is: run normal prefill on the full context; insert a small number of restore tokens, eight by default; let those tokens attend to the full KV cache in one extra forward pass with LoRA-adapted attention layers; use the resulting per-layer KV states of the restore tokens as a compact restore cache; then apply the original query-agnostic evictor to the real context tokens and keep the remaining budget as retained cache. The final compressed cache is the concatenation of retained original KV pairs and the learned restore cache, with the same total KV budget as the baseline.

Training is offline self-distillation from a frozen full-cache teacher. For the same context and downstream query, the student using the budget-matched compressed cache is trained to match the teacher’s answer-token distributions. Only the restore-token embeddings and lightweight LoRA adapters are updated; the backbone model and the base evictor stay frozen. This design matters for two reasons. First, RestoreKV is a complement, not a rewrite: it preserves most selected original states and only learns a small residual cache. Second, LoRA is used only during restore-cache construction. After that, query processing and decoding are identical to the base method, so online inference cost is unchanged.

The most informative part of the paper is the component analysis. The authors separate gains from learned restore-token content versus gains from attention-side adaptation. At a 5% KV budget, optimizing restore embeddings alone improves KVzip from 38.2 to 42.1, which is modest. Keeping embeddings fixed but learning LoRA reaches 71.9. Adapting only q/k/v projections reaches 72.4, close to the full RestoreKV result of 73.2. This strongly suggests that the method works because the adapted attention mechanism learns how to extract a compact, context-specific complement from the full cache, not because a few special tokens memorize generic information.1a:T653,The evaluation is reasonably broad: four backbones, four long-context benchmarks, and five base eviction methods. The paper emphasizes consistency across settings rather than a single best-case result. The headline number is on Qwen3-4B with KVzip: at a 5% KV budget on RULER-4K, accuracy improves from 38.2 to 73.2. Applied to KVzip+, RestoreKV reaches 86.4 RULER accuracy at 16x compression on the KVPress Benchmark. The compression-ratio curves are also important: under mild compression, baseline eviction is already close to full-cache behavior, so RestoreKV adds little; under aggressive compression, selection-only methods degrade sharply, and RestoreKV closes a large part of the gap. That pattern matches the paper’s central claim.

The overhead numbers are small enough to matter in practice. On 32K-context evaluation, the eight-token restore pass adds only 0.03 to 0.04 seconds, less than 0.5% of total compression time, and 84 MB of peak memory, around 0.4%. This is a strong point of the design. Many cache reconstruction ideas improve quality but complicate query-time or decode-time execution. RestoreKV keeps all extra work in one-time cache construction.
