18:T48f,Daedalus-150M is a convolution–attention hybrid decoder. Out of 18 blocks, only 6 are full attention; the other 12 are short convolution blocks with kernel length L=3 depthwise conv and a fixed recurrent state of width L-1=2 timesteps, making their per-token decode cost independent of context length. Attention layers are interleaved across depth (a fixed C/A pattern) to preserve long-range retrieval at multiple representation levels. To further reduce cache traffic, attention uses grouped-query attention (12 Q heads, 4 KV heads). The model ties input/output embeddings to cut parameters and memory traffic, and uses a narrower FFN (2048, ~2.67×d_model) to reduce bandwidth-heavy matrices. The paper explicitly documents rejected options (MoE due to export/runtime constraints and lack of sub-1B precedent; position-free attention due to export format; distillation due to teacher-logit storage cost). A first-order CPU decode cost model is provided: per token, read quantized weights once plus KV-cache reads proportional to context length for each attention layer; this yields an analytic cache coefficient κ used to predict hybrid vs dense decoding costs.19:T616,The main idea is straightforward: replace standard GEMM-style execution with custom SIMD kernels tailored to ternary weights, using integer dot-product instructions available on modern CPUs. The implementation targets three hardware families: NEON SDOT on Apple Silicon, AVX-512 VNNI on Intel Ice Lake and AMD Zen4-class CPUs, and AVX-VNNI on Intel Core Ultra. Because ternary weights only encode add, subtract, or skip, the kernels are designed to map this discrete structure onto native vector integer instructions rather than generic floating-point matmul.

The contribution is not just a few low-level kernels. The authors also package the implementation as a Python library with automatic platform detection and HuggingFace Transformers integration. So the work has both an operator-level and a system-level component. At the operator level, the question is how to organize ternary weights, activations, and accumulation so the SIMD instructions are used efficiently. At the system level, the question is how to expose this in existing inference workflows so ternary models are no longer forced through dense float execution paths.

Compared with standard 4-bit or 8-bit quantized inference, the difference is not merely lower precision. Those methods still rely on low-precision multiply-accumulate. Ternary inference changes the arithmetic form itself, making multiplication largely unnecessary in implementation. If the software stack does not reflect that, much of the theoretical advantage disappears.
