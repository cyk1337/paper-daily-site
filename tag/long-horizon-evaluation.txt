1a:T4c3,108 long-horizon real-world computer-use tasks are built following three design principles: 1) Authentic workflows: tasks are sourced from expert interviews and annotator research on real professional scenarios, with input artifacts adapted from real materials instead of synthetic generation; 2) Long-horizon structure: difficulty comes from interdependent steps across multiple applications, rather than task repetition or concatenation of unrelated subtasks; 3) Diverse challenge phenomena: each task is annotated with 10 capability dimensions (cross-source reasoning, implicit-state inference, conflict disambiguation, dynamic environment adaptation, etc.). For implementation, 31 task-facing web services (email, banking, team chat, etc.) are self-hosted to enable controlled, scorable states; tasks are initialized from coherent stateful user profiles; mid-task messages are injected to simulate dynamic environments; a simulated user with bounded knowledge is provided; scoring relies on fine-grained functional checkpoints (average 27.25 per task) instead of model-based judgment. All tasks are audited via unit tests, human re-solving, and frontier agent rollouts to prevent reward hacking and false negatives.1b:T59a,The core contribution is a scalable synthetic trajectory generator rather than a model. Instead of concatenating existing chat histories, the authors build 16 stateful apps and 66 APIs to simulate 15 months of user behavior. Four design choices matter. First, events are generated as cross-app event chains: a single latent user intent unfolds over multiple months and apps, and each log entry is conditioned on current app state and previous steps in the chain. This preserves entity consistency within and across apps. Second, the user profile is explicitly factorized into attributes, habits, and preferences, each with distinct temporal dynamics. Each category is evaluated with two task types: State Completion, which reconstructs the current user state, and Personalized Service, which tests whether the system can act on that state. Third, profile evolution is causally grounded rather than random. External drivers such as seasons, major life events, and circumstance shifts trigger coordinated changes across multiple facets of the profile. Fourth, evaluation is checkpoint-based rather than single-shot: the benchmark probes five quarterly checkpoints over the 15-month trajectory, making temporal scaling and overwrite behavior measurable. The paper also evaluates five representative memory systems and separates retrieval failures from answer-generation failures, which is one of the most useful parts of the methodology.1c:T4ec,The benchmark scale is substantial: about 2.2M tokens per user over 15 months, 17,715 grounded events, 16 apps, 66 APIs, 1,837 evolving profile items, 383 causally attributed state transitions, 3,634 checkpoint-based problems, and 4,994 fine-grained scoring points. Three findings stand out. First, State Completion accuracy degrades steadily as history grows, while Personalized Service degrades much less. That suggests systems may still perform service tasks using local cues or partial heuristics even when their internal user-state representation is already drifting. Second, none of the tested systems handles both retention and overwrite well: they struggle to preserve facts that remain true while also replacing facts that have changed. Third, failures concentrate on implicit preferences and exact entity identification for attributes, such as the specific tool or item tied to a user state. The most important analysis is the failure attribution: over 93% of errors are due to memory retrieval rather than the answer model. That strongly suggests the main bottleneck is the memory subsystem itself.
