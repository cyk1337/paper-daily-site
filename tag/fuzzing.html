Fuzzing Large Language Models to Elicit Hidden Behaviours

这篇工作研究的是：当审计者不知道触发词时，能否只靠前向访问，把 sleeper agent 或其他后门模型里被压住的异常行为诱发出来。更具体地说，它把“fuzzing”作为审计工具系统化了：一类是在权重上加高斯噪声，另一类是在残差流激活上加噪声。过去两条线各做各的，缺少同一模型集上的正面对比，也缺少对超参数选择问题的严肃处理。全文最重要的判断是，fuzzing 的主要瓶颈不是方法本身完全没信号，而是超参数空间极不均匀：少数噪声尺度或层位有效，大多数设置几乎没有诱发率。如果不解决选择问题，审计者在真实部署里很容易得到“方法没用”的假象。

评不是能力论文，但很适合做 latent-behavior probe：只看方法对比和超参热图即可，重点结论是搜索准则比换花样更关键。

FunFuzz: An LLM-Powered Evolutionary Fuzzing Framework

这篇工作解决的是 LLM 驱动 fuzzing 的两个老问题：初始 prompt 很容易把搜索轨迹锁死，采样随机性又会让生成反复落在相似程序模式上，导致覆盖率增长慢、深层编译器行为触达不足。作者提出的核心问题不是“LLM 能不能生成代码”，而是“如何把 LLM 生成接入一个长期保持多样性的搜索过程”，让它在结构化输入空间里持续探索而不是早早塌缩。

Demystifying the Silence of Correctness Bugs in PyTorch Compiler
