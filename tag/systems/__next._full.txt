18:T43a,TokTier uses two execution paths under an exactness contract: every emitted token sequence must match a frozen reference tokenizer on the full request text. For session continuations, it stores token IDs and byte spans for each live session. On append, it re-tokenizes the new text plus a suffix of the old context, compares fresh and cached token records, and splices only after a stable-boundary check proves that the pre-tokenizer cannot observe across the boundary. If the check fails, TokTier widens the repair window and eventually falls back to full reference tokenization. For calls without a reusable prefix, it implements an exact GPU path for GPT-family tokenizers. The sequential regex stage is replaced by a run decomposition over maximal character-class runs; piece starts are derived from run position, bounded neighboring text, and run-level summaries. A GPU BPE pipeline then encodes the pieces. The design has three main pieces: (1) a CUDA-graph-aware latency model, calibrated offline and refined online, that predicts at batch granularity how admitting fine-tuning will affect TTFT and TPOT; (2) an SLO-aware admission scheduler that admits, throttles, pauses, and resumes fine-tuning as inference load fluctuates; and (3) a decoupled backward executor that moves the long backward pass off the inference critical path to avoid blocking token-level latency. The system is integrated into vLLM, SGLang, and S-LoRA using the same host-agnostic core.1b:T72b,The core proposal is the Spense format. Instead of forcing the entire weight matrix into standard 2:4 sparsity, the matrix is split into two contiguous regions: one remains dense, the other is pruned with the standard 2:4 pattern. The practical advantage is immediate: the dense region can be executed with existing dense GEMM libraries such as cuBLAS, and the sparse region with existing 2:4 sparse GEMM libraries such as cuSPARSELt. This avoids custom compiler work and avoids activation expansion or expensive runtime transformations used by prior relaxed-sparsity methods.

The reason this contiguous split is possible is the permutation invariance of the intermediate dimension in GLU-style MLPs. If the same permutation is applied consistently across the gate, up, and down projections, the MLP function is unchanged. That lets the method choose a subset of intermediate channels to keep dense, reorder them into a contiguous block, and prune the rest into the 2:4 region.

On top of this format, the paper proposes two one-shot pruning methods. SpenseGPT is the simple baseline: keep the first p% of intermediate indices dense and apply SparseGPT to prune the remaining region into 2:4 sparsity. SpenseGPT+ improves this by selecting dense indices using an activation-aware importance score inspired by Wanda, combining each intermediate index’s contribution across the gate, up, and down projections. SparseGPT is then used on the remaining weights to minimize layer output reconstruction error.

A central empirical point is that dense-index selection matters enormously. The paper reports that with the same dense budget, AIME can vary from 76.67 down to 8.89 depending on which indices are kept dense. So the method is not just about relaxing sparsity; it is about identifying the right subspace to preserve in dense form.1c:T4a6,The evaluation uses Qwen3-32B and Seed-OSS-36B, with benchmarks including AIME, GPQA, LiveCodeBench, and IFEval. The main claim is that SpenseGPT+ preserves quality across these tasks while achieving up to about 1.2× end-to-end decoding speedup over the dense baseline on B200 GPUs with FP8 precision in vLLM.

One of the most useful analyses is the sparse-GEMM speed study. The paper shows that sparse kernels only approach their theoretical benefit when the GEMM M dimension is large enough to amortize overhead. When M is small, sparse GEMM can even be slower than dense GEMM. This is an important reality check for autoregressive decoding, where many operations run in regimes that are not ideal for sparse kernels.

Another key result is the dense-index selection ablation. Even with the same dense fraction, different index choices can lead to dramatic accuracy differences, which directly motivates the activation-aware selection in SpenseGPT+. 第一是 boundary communicator。这是挂在模块边界上的 autograd-aware 算子。前向时，它把源模块输出的激活按照目标模块的逻辑布局重新物化；反向时，再执行严格匹配的逆变换，把梯度送回源模块原来的布局。这里最重要的不是通信本身，而是“边界张量语义”的显式化。作者强调一个实际风险：布局映射如果错了，张量形状可能仍然合法，训练会继续跑，但梯度会被送到错误 rank，属于很难排查的 silent corruption。boundary communicator 的设计就是把这种 forward/backward 对偶关系固定下来，避免手工拼接通信逻辑。

CQS Divide starts from a graph view of attention: full self-attention corresponds to all pairwise token interactions, i.e., a complete graph over tokens. The goal is to partition the sequence into subsequences such that every token-pair interaction is covered exactly once across the set of subsequence attentions. The construction is based on cyclic quorum sets. The sequence is first split into c chunks. Then c subsequences are built, each containing l chunks, under the condition that every chunk pair appears in exactly one subsequence. This yields the coverage constraint c = l(l-1)+1, so valid chunk counts are 1, 3, 7, 13, 21, and so on. The paper focuses on the smallest nontrivial case, l=3 and c=7, using a cyclic interest set such as (0,1,3). In graph terms, this is a decomposition of K_c into K_l subgraphs, closely related to Steiner systems.

The exactness comes from how softmax is recomposed. For each subsequence, the method gathers the corresponding Q_i, K_i, and V_i from the global tensors and computes local softmax numerator and denominator terms, Num_i and Den_i. These are then scattered back into global token coordinates and accumulated into global Num and Den, followed by a final token-wise normalization O = Num ⊘ Den. This is the key idea: the method does not average local attention outputs directly, which would be wrong under softmax. Instead, it accumulates numerator and denominator separately, preserving exact equivalence to full attention. The backward pass mirrors the same decomposition, constructing local gradient terms from the global upstream gradient and then merging dQ_i, dK_i, and dV_i back into full-sequence coordinates.

Stream-CQSA builds a memory-adaptive execution framework on top of this decomposition. Since each subsequence attention is independent, the system can schedule them according to an arbitrary memory budget: load only the necessary chunks, compute a subset, accumulate partial results, and release memory before moving on. Because CQS Divide is recursively applicable, the workload can be subdivided further when memory is tighter. The result is a time-for-memory trade-off that enables exact attention under memory budgets where full QKV materialization would otherwise be impossible.
