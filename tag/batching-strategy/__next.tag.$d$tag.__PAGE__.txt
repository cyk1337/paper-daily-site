a:T6ba,The core system is Feather, a decode scheduler that explicitly balances batch size against prefix homogeneity instead of always pushing for the largest feasible batch. The paper first uses controlled experiments to show why this tradeoff exists. When requests in a batch share a long common prefix, attention over shared KV blocks becomes much more locality-friendly. That improves both temporal reuse and spatial coalescing of memory accesses. But making batches too small hurts compute utilization. So the best operating point depends on shared-prefix length, batch size, and hardware behavior.

Feather has two main components. The first is the Chunked Hash Tree (CHT). Rather than maintaining token-level radix-tree traversals, CHT represents each request as a vector of cumulative prefix hashes over chunks. This allows fast estimation of how much prefix two requests share, while avoiding heavy tree maintenance. The second is a min-heap-based selection mechanism that approximately chooses the next request to maximize common-prefix length within the active batch without sacrificing too much batch size. The heap is updated lazily to reduce CPU scheduling overhead. This differs from prior prefix-aware schedulers in systems like SGLang or vLLM, which mainly exploit prefix structure to reduce KV evictions or memory footprint. Feather’s objective is decode throughput itself.

An important systems point is that Feather composes naturally with prefix-aware attention kernels. If the kernel can jointly process queries that share prefixes, then a scheduler that forms more homogeneous batches amplifies those kernel-level gains. So the paper is really about scheduler–kernel co-design, not just queue ordering.b:T5c4,Three empirical findings matter most. First, on prefix-sharing workloads, prefix homogeneity can dominate batch size. The headline controlled example in the paper uses 800 requests partitioned into 8 groups of 100, where each group shares a 10K-token prefix. Processing them as 8 prefix-homogeneous batches yields nearly 2x higher throughput than using larger heterogeneous batches. But if the batches are made too small, such as 32 batches of 25, throughput drops again because compute utilization becomes poor. This directly supports the claim that there is an interior optimum rather than a monotonic preference for larger batches.

Second, the CPU cost of existing prefix-aware schedulers is surprisingly high. The paper reports that radix-tree maintenance and traversal can account for 50% to 90% of total latency in some settings. That is a critical diagnosis: even if GPU-side prefix reuse helps, the scheduler itself can erase the gain. Feather reduces this overhead through CHT and lazy heap updates.

Third, on realistic or semi-realistic prefix-shared workloads, Feather improves end-to-end throughput over FCFS and prior prefix-aware baselines, with larger gains when requests cluster around longer shared prefixes.
