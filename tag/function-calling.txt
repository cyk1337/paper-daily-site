It does this without modifying the model or the underlying function implementations.

The mechanism has four parts.

First, automatic schema adaptation. The runtime rewrites synchronous function schemas into future-compatible ones so the model can accept and pass around future placeholders instead of only concrete resolved values. It also introduces a lightweight await_future function that lets the model explicitly request resolution when needed. The key idea is that the model does not need to learn a new concurrency language; unresolved results are exposed as symbolic objects it can continue to manipulate.

Second, asynchronous dispatch with immediate return. When the model emits a function call, the runtime submits the original synchronous function to an async executor and immediately returns a symbolic future identifier into the conversation. From the protocol's perspective, the function has already returned, so the model can keep decoding, issue more calls, or pass the future into downstream calls.

Third, event-driven result integration. Once the backend execution completes, the runtime injects the resolved result or an error message into the context at turn boundaries. The model still sees a call followed by a return, but the return is initially a future placeholder and only later becomes a concrete value.

Fourth, dependency-aware scheduling. To avoid unsafe parallel execution, AsyncFC is conservative by default and serializes calls unless the developer provides resource-interaction annotations. With those annotations, the scheduler can unlock dependency-safe inter-function parallelism. This yields two forms of concurrency: overlap between model decoding and function execution, and parallel execution among independent functions.

Compared with prior approaches, the paper deliberately avoids two common routes: changing the model so it explicitly manages fork/join behavior, or changing the function-calling protocol so the model itself bears more concurrency-management complexity. AsyncFC pushes concurrency management into the runtime. 方法上的另一个亮点是 format-versus-compression 分解。作者比较 JSON baseline 与文本 baseline，发现准确率与 token 数的相关性在 JSON 表示下很强，R²=0.88；换成文本表示后几乎消失，R²=0.03。这个结果支持他们的主张：决定性因素是 representation change，而不是简单缩短 prompt。也就是说，模型不是单纯“上下文太长看不过来”，而是“看不懂这种结构”。

从预训练研究视角看，TSCG 的真正价值不在规则本身，而在它把 schema 理解问题拆成了 tokenizer 友好性、位置布局、因果可访问性、关键原子冗余保护这几个可分析维度。这些维度都可以反过来指导数据合成和预训练格式设计。20:T837,TSCG is a deterministic compiler that converts JSON tool schemas into a compact structured-text format. It is model-agnostic, requires no finetuning, and does not rely on runtime search. The system is built from eight composable operators arranged in a fixed pipeline. The design philosophy is to encode known transformer reading biases into deterministic rewrites rather than learn a schema rewriter.

The operators fall into three groups. Token-reducing operators compress the schema by choosing tokenizer-friendly delimiters, removing filler phrases, and replacing verbose structural language with compact symbolic forms. These exploit BPE non-monotonicity and tokenizer-specific token counts. Structure-preserving reordering operators move critical constraints to the beginning of the prompt to exploit attention sink effects, and reorder multi-step operations topologically so prerequisites are causally accessible. Token-expanding operators add redundancy near the end of the prompt or duplicate fragile semantic atoms to exploit recency bias and boundary-position advantages.

A strong point is that the paper does not treat all operators as uniformly beneficial. It formalizes semantic preservation, distinguishes reducing vs. reordering vs. expanding transforms, and proves a >=51% compression guarantee on well-formed schemas for the reducing subset. More importantly, the paper isolates representation change from raw compression. On JSON baselines, accuracy is strongly correlated with token count (R²=0.88), but on text baselines that correlation nearly disappears (R²=0.03). That result supports the central claim: the dominant effect is not just shorter context, but a representation that the model can actually parse.

From a pretraining perspective, the deeper value is the decomposition itself. The paper turns schema understanding into analyzable dimensions: tokenizer friendliness, positional layout, causal accessibility, and redundancy allocation for fragile semantic atoms.
