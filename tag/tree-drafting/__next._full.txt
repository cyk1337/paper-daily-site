1b:T713,The method is Progressive Tree Drafting (PTD). Instead of representing drafts as several independent linear continuations, PTD organizes them as a prefix-sharing tree. This serves two purposes: shared prefixes are computed once rather than repeatedly, and branching is coordinated so parallel budget is spent on genuinely different semantic paths rather than near-identical continuations.

The method has three main components. First, tree construction. PTD initializes a drafting tree with seed nodes, obtained either stochastically or from context-aware semantic cues. Each node is only allowed to attend to its ancestors, preserving autoregressive causality along every root-to-node path. Positional encoding is assigned according to ancestor-chain length so the tree input remains compatible with a standard Transformer.

Second, progressive evolution. PTD does not expand the full tree in one shot. It grows the tree step by step: after each forward pass, candidate children are proposed, and a stepwise pruning rule removes low-value or highly redundant branches. This design is important. Unconstrained expansion would quickly inflate the tree and verification cost; progressive growth lets the model first establish coarse semantic alternatives and then allocate compute to the most promising paths.

Third, draft extraction and verification. Multiple root-to-leaf paths are extracted as candidate continuations and then verified with a standard speculative-decoding acceptance procedure. Compared with Self-Draft, which obtains multiple branches through input perturbations, PTD explicitly coordinates branch relationships through prefix sharing and pruning. Compared with LADE-style parallel future-token prediction, PTD is closer to constrained semantic search than to Jacobi-style linear refinement.1c:T4ca,From the provided full-text content, the main confirmed result is that PTD consistently achieves up to about 2× decoding speedup across several benchmarks, without auxiliary draft models and without extra training. The motivating analysis in the paper shows that in Self-Draft, more than half of decoding steps contain branches with over 80% similarity, which is the empirical basis for the proposed tree formulation.

The experimental story appears to center on three aspects. First, end-to-end speedup against vanilla decoding and prior speculative baselines such as external-draft methods, LADE, and Self-Draft. Second, the relationship between acceptance rate and draft diversity, showing that the tree structure and pruning improve not only compute reuse but also the usefulness of candidates. Third, structural ablations: progressive update vs. one-shot expansion, pruning vs. no pruning, different tree widths/depths, and different seed strategies.

关键在于它如何保留依赖。文中用了两层机制。块内依赖通过 layer-wise shift 实现：前一个位置的 hidden state 会被送入后一个位置的每一层，使得 block 内第 2 到第 K 个位置不是独立猜测，而是条件在前面已生成内容上。块间依赖则允许新 block 从旧 block 的任意位置继续，并显式使用该位置的 hidden state 作为条件，因此后续扩展不是简单复制前缀，而是沿着已有分支继续生长。

第二个核心部件是 rank-guided tree construction。作者没有固定每个位置的分支数，而是额外训练一个 rank head，输入该位置 hidden state，预测“target token 在 drafter 分布里的排名区间”。如果某个位置 target 大概率就在前几名，就给少量 sibling 即可；如果排名可能更靠后，就增加分支，或者决定该位置是否值得作为后续 block 的起点。这样树是在 drafting 过程中动态成形，而不是先生成大树再剪枝。它解决的是 verifier 预算分配问题：把分支放在更可能需要覆盖的位置上。

第三个设计是 valid-prefix curriculum learning。SpecBlock 的训练和普通 teacher forcing 不同，因为一个 block 内后面位置读到的是模型自己前面位置的预测，而不是真实 token。如果前面已经错了，后面即便对着 ground-truth 继续算 loss，也是在优化一条推理时根本不会被接受的路径。作者因此引入 valid-prefix mask：一旦同一路径前面某位置预测错误，后续位置 loss 就被屏蔽。这个设计很像把 speculative decoding 的“前缀有效性”直接写进训练目标，减少无效监督。

第四个部分是 serving-time adaptation。作者观察到离线训练的小 drafter 对分布偏移很敏感，而 verifier 在拒绝位置上本来就会算 target 分布，这相当于免费给出了在线监督信号。于是他们设计了一个 cost-aware bandit，在每次 query 后决定三种动作之一：不更新、只更新输出头、更新整个 drafter。只有当预计吞吐提升能覆盖更新成本时才执行更新。这个部分的重点不是在线学习算法本身多新，而是把 speculative verification 里原本就存在的 target signal 变成了低额外成本的适配机制。1e:Ta1d,The main idea is to grow the draft tree in blocks rather than one depth level at a time. A single drafter forward produces K dependent future positions, called a block. The tree beyond depth K is then expanded by reusing the drafter on a batch of starting points selected from earlier blocks. This changes the unit of expansion from one token depth to a multi-token block.

The key question is how dependence is preserved. Inside a block, SpecBlock uses a layer-wise shift mechanism: the hidden state from the previous position is injected into every decoder layer of the next position. As a result, positions 2..K in the block are not independent parallel guesses; they are conditioned on earlier drafted content. Across blocks, a new block can start from any position in the previous block, using that position’s hidden state as conditioning. This lets the tree continue along existing branches rather than merely appending shallow independent proposals.

A second major component is rank-guided tree construction. Instead of assigning a fixed branching factor to every position, the model trains an auxiliary rank head that predicts a coarse bucket for the rank of the target token within the drafter distribution at that position. If the target is likely near the top, only a few siblings are needed; if it may rank lower, more alternatives are allocated, and the position may also be selected as a starting point for later block expansion. This shapes the tree during drafting rather than generating a large tree and pruning afterward.

The third component is valid-prefix curriculum learning. In standard teacher forcing, each step is supervised under a fresh ground-truth prefix. SpecBlock cannot do that because later positions in a block consume earlier model predictions, not ground-truth tokens. If an earlier prediction is wrong, the entire path will be rejected by the verifier, so supervising later positions on the ground-truth continuation wastes capacity on paths that will never be committed. The valid-prefix mask drops the loss on later positions once an earlier position on the same path is incorrect.

The final component is serving-time adaptation. The paper observes that a small offline-trained drafter is sensitive to domain shift, while the verifier already computes target distributions at rejected positions.
