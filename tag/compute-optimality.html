Compute-Optimal Is Not Cluster-Optimal: Systems-Aware Scaling for Sparse Mixture-of-Experts

传统LLM scaling law只在理论模型FLOPs约束下优化预测loss，选定模型大小、训练token数，完全不考虑真实集群上的MFU（模型FLOPs利用率）、跨设备通信开销、内存占用、最优并行布局等系统因素，实际执行时再针对固定架构做系统调优。这种两阶段脱节在MoE模型上问题尤其突出：专家数、路由稀疏度等MoE特有参数既影响最终loss，也对系统效率有极大影响，理论上的compute-optimal配置放到真实硬件上可能吞吐量差数倍，甚至因为内存/通信瓶颈根本无法高效运行。

评应读方法和优化目标：它把 Chinchilla 式 loss 最优从“纸面 FLOPs”拉回集群约束，值得在内部 MoE 规划中复现。

How to Allocate Your Tokens? Scaling Laws with Training Steps and Batch Size

经典 Chinchilla 类 scaling law 把训练数据压成一个总 token 数 D，默认 batch size 等超参数已经调到合适位置。这个设定无法回答一个实际问题：在同样 token 预算下，应该用更大的 batch、还是更多训练 step。该工作把数据预算显式拆成 batch size M 和训练步数 K，建模最终 loss 随 N、M、K 的变化。

评scaling law拆分batch与步数维度，拟合效率更高，做预训练计算规划和小样本ablation时可参考其三阶形式。

A Bitter Lesson for Data Filtering

这项工作要回答一个直接但代价很高的问题：在大模型预训练进入高算力、数据相对稀缺的区间后，传统的数据过滤是否仍然必要。常见做法是假设 Common Crawl 里有大量低质量文本，需要用质量分类器、规则、困惑度过滤等方法保留少量高质量子集。作者挑战的是这个前提：如果模型足够大、训练足够久，过滤掉的大量“低质量”数据是否反而成为限制 scaling 的瓶颈。

评这篇会直接动摇“先把数据洗干净再谈 scaling”的默认流程；先看实验设定是否真在 data-scarce 且 train-to-convergence，若是，内部数据过滤 ablation 该重做。
Christopher Mohri,John Duchi,Tatsunori Hashimoto

Prescriptive Scaling Laws for Data Constrained Training

在“高质量数据受限、算力相对充裕”的预训练场景里，重复数据（多 epoch）会带来过拟合并导致验证损失反弹；而 Chinchilla 及既有 data-repetition 扩展（如 effective-data 形式）要么默认 token 唯一、要么只能刻画收益递减，无法刻画“重复到一定程度反而变差”，也无法刻画过拟合与模型规模的交互，从而不能给出可靠的 compute-optimal 配置建议。

评这篇会直接改你对 data-constrained pretrain 的默认配方：别再机械套 Chinchilla，先看重复惩罚项怎么进 law，再决定是加 token 还是加参数，建议优先复现其拟合图和 weight decay 案例。
