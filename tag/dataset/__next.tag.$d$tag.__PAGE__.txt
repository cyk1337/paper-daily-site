9:T7ae,The main contribution is benchmark design. The paper defines a seven-type taxonomy: article, forum, product, collection, listing, documentation, and service. The key design choice is that these categories are based on HTML structure and extraction behavior rather than semantic topic. That matters because extraction failures are often driven by layout and DOM organization, not by subject matter. For example, collection and listing pages both contain multiple items, but they differ in where useful text lives and how much text each item carries.

The dataset is built from Common Crawl, ChatNoir, and manual curation, ending with 2,008 pages from 1,613 domains. Domain concentration is low, which reduces template memorization effects. Pages were collected in late 2025 to early 2026, so the benchmark reflects modern HTML5, responsive layouts, and JavaScript-heavy sites. Acquisition uses both headless Chrome and direct HTTP fetching. SPA pages are retained and flagged; when content is unavailable without client-side rendering, the ground truth is intentionally empty so systems are tested on whether they avoid extracting shell boilerplate.

Annotation is richer than plain extracted text. Each sample includes title, author, publish date, main content, and short must-include / must-exclude snippets. Main content is stored as plain text rather than HTML or Markdown, which keeps evaluation focused on content boundaries and completeness instead of formatting fidelity. The annotation pipeline combines LLM drafting, automated verification, multiple frontier-model review passes, and manual checks. The practical idea is to use LLMs for scale while constraining them with validation and targeted review.

The most important methodological insight is that benchmark organization should follow structural extraction difficulty, not just source diversity or topic diversity. That choice gives the benchmark diagnostic value rather than only aggregate coverage.a:T624,The paper evaluates 13 extraction systems, including 11 heuristic methods and 2 neural ones. The benchmark contains 2,008 pages in total, split into a 1,497-page development set and a 511-page held-out test set, spanning 1,613 domains. The longest annotated main-content field reaches 49,617 characters, indicating that the dataset includes long documentation and complex forum-like pages rather than only short articles.

The experimental emphasis is not on a single leaderboard number. The useful result is the page-type breakdown, which shows that performance remains strongly type-dependent on the modern web. Heuristic extractors are often still competitive on article pages, but they degrade on forums, documentation, service pages, and product pages where DOM structure is more heterogeneous or template-heavy. Neural systems are generally more robust, but they are not uniformly dominant, especially when the task requires recognizing that no meaningful server-side content is present.

For pretraining data construction, the most informative part is the failure taxonomy. Some systems over-extract and pull in navigation, recommendations, cookie banners, or footer text. Others under-extract and miss forum replies, product specifications, code blocks, or sectioned documentation content. These two error modes have different downstream effects: over-extraction increases boilerplate and repeated template tokens, while under-extraction throws away high-value content. The benchmark design makes both visible through page-type splits and with/without constraints.b:T423,This is a skim paper, but it is worth reading selectively if you work on web data pipelines.
