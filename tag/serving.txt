18:T5f7,The core mechanism is Expert Folding. Instead of dropping an excluded source expert or rerouting it to a similar target expert without correction, ExFold projects the source contribution onto a retained target expert. The method is motivated by two empirical findings: many experts produce directionally aligned outputs on the same inputs, but their output magnitudes differ substantially. Directional alignment makes substitution plausible; magnitude mismatch makes naive rerouting inaccurate. Based on this, each layer is calibrated with two matrices from a single frozen forward pass on unlabeled text. The scalar-projector matrix stores directed source-to-target scaling factors. The projection-loss matrix measures reconstruction loss for folding one expert into another. At inference time, retained experts are selected according to the phase budget: K_pre dominant experts per token for prefill, and D dominant experts per batch for decode. Every excluded expert is then assigned to the minimum-loss retained target, and its contribution is folded into that target by absorbing the scalar projector into the router weight. This gives one shared folding operator across both phases. Compared with token-wise sparsification, the method does not only reduce executed experts; compared with expert-set consolidation, it does not bake compression into a fixed submodel; compared with similarity-based rerouting, it explicitly corrects scale mismatch. The implementation is integrated into vLLM with a lightweight CUDA kernel.19:T4a9,The evaluation covers multiple MoE architectures and real vLLM serving workloads, focusing on TTFT, TPOT, and quality retention. The headline numbers are up to 1.41× TTFT speedup and 2.45× TPOT speedup while preserving about 99% of the original average quality. The larger decode gain is consistent with the method’s focus on reducing the active expert set under memory-bound conditions. The more informative part is the comparison structure. Against pruning or skipping baselines, ExFold degrades quality more slowly at the same budget, which supports the claim that explicit reconstruction matters. Against static merging methods, it remains adaptive to token-level or batch-level budgets instead of committing to one permanently compressed model. Against similarity-based rerouting, the directed scalar projector improves approximation when experts are aligned in direction but not in scale. The ablations indicate that both components—the loss-based target assignment and the scalar correction—are necessary. Another useful result is that the same calibrated matrices work for both prefill and decode, which reduces deployment complexity and supports the phase-unified formulation.1a:T820,方法延续 FlashPrefill 的两阶段思路。先做 block-level 的粗粒度打分，再只对被选中的 block 做精细 attention。原始 FlashPrefill 用 probe queries 和 block mean-pooled key 来估计每个 key block 的重要性，并用基于峰值分数的动态阈值替代 Top-k/Top-p 排序，从而避免全局排序开销。它还保留 sink blocks、局部滑窗和最近块，以兼顾因果约束和常见注意力模式。

V2 的第一个关键改动是 mean correction term。原方法在极端稀疏时直接截断未选 block 的 softmax 分母和分子，忽略掉被剪枝块的质量，误差会迅速放大。V2 为每个 key block 预先计算 pooled K/V 统计量，用零阶近似去补偿被丢弃块对 softmax mass 和 value aggregation 的贡献。直观上，它不再把未选 block 当成完全不存在，而是用块均值代表其剩余贡献。这样做的好处是代价低，不需要恢复 token-level 计算，但能显著缓和高 sparsity 下的偏差。

第二个关键改动是 kernel 重写，目标是对齐 Hopper 时代的高性能 dense attention 实现。文中提到三点：PackGQA memory access、warp specialization、pingpong pipelining。前者针对 grouped-query attention 的访存组织，减少无效带宽和访存碎片；warp specialization 把不同 warp 分配给不同职责，提高流水并行；pingpong pipeline 则利用 Hopper 上的异步搬运和计算重叠机制，把数据准备和计算交替推进。作者明确说 V2 是按 FlashAttention-3/4 的实现思路重构，而不是停留在 FA2 时代的 kernel 结构上。

第三个关键改动是系统兼容性。V2 原生支持 paged KV cache 和 continuous batching，并集成到 SGLang 这类现代推理框架中。这个点很重要，因为很多 academic sparse attention 方法默认 contiguous KV layout，离真实 serving 很远；一旦接入 paged cache，索引、页表、batch 动态拼接都会改变 kernel 设计。V2 把这一层一起处理了，所以论文不只是算子 benchmark，而是端到端 TTFT 改善。1b:T8b0,FlashPrefill V2 keeps the two-stage structure of FlashPrefill. It first performs block-level coarse scoring, then computes fine-grained attention only on selected blocks. The original method uses probe queries and mean-pooled keys to estimate block salience, and replaces Top-k/Top-p sorting with a max-based dynamic threshold. It also preserves sink blocks, a local sliding window, and recent blocks to respect causal structure and common attention patterns.

The first major addition in V2 is a mean correction term. In the original truncation-based approximation, unselected blocks are simply dropped from both the softmax denominator and numerator. Under extreme sparsity, that discarded probability mass becomes too large to ignore. V2 compensates for pruned blocks using precomputed pooled K/V statistics for each block, effectively adding back a zero-order surrogate contribution. Intuitively, the method no longer treats pruned blocks as nonexistent; it represents their residual effect through block means. This keeps the correction cheap while significantly reducing approximation error at high sparsity.

The second major change is a Hopper-oriented kernel redesign. The paper highlights PackGQA memory access, warp specialization, and pingpong pipelining. PackGQA improves memory organization for grouped-query attention and reduces bandwidth waste. Warp specialization assigns different roles to different warps to improve overlap and utilization. Pingpong pipelining exploits Hopper-style asynchronous data movement and compute overlap. The authors explicitly position V2 as aligned with FlashAttention-3/4 implementation principles rather than older FA2-style kernels.

The third change is systems compatibility. V2 natively supports paged KV cache and continuous batching, and is integrated into SGLang-like serving frameworks. This is important because many academic sparse-attention methods assume contiguous KV layouts and do not survive contact with real serving systems. Once paged cache, page tables, and dynamic batching enter the picture, the kernel design changes materially. V2 addresses that layer directly, so the contribution is not just an operator benchmark but an end-to-end TTFT improvement.1c:T620,The empirical story has three parts: speed, quality, and deployability. On NVIDIA H20 at 128K context in BF16, FlashPrefill V2 reports up to 27.19x speedup over FlashAttention-2 during prefill. Its FP8 variant reaches 47.26x. More importantly, even against a much stronger dense baseline aligned with FlashAttention-3/4, it still achieves 17.54x speedup in BF16 and 30.49x in FP8. That means the gain is not an artifact of comparing against an outdated dense kernel. The paper also notes that acceleration remains visible even at 4K sequence length, suggesting that sparse selection and launch overheads are kept low enough to matter outside only ultra-long contexts.

At the system level, after integration into SGLang, the method reduces end-to-end time-to-first-token by up to 4.8x at 128K with only marginal accuracy loss. This result is more convincing than raw kernel throughput because it includes the effects of paged KV cache, continuous batching, and framework-level scheduling.

On accuracy, the headline claim is that mean correction keeps degradation manageable even under extreme sparsity. The method section explains why: naive truncation drops the softmax mass of pruned blocks, while the correction restores an approximation of that contribution using block-level statistics. A FLOPs-based upper bound on adaptive depth speedup is derived, and a hardware-aware roofline model is used to identify batch size regimes where refill mode provides net performance benefit.23:T7cf,The core method is CURE, a budget-aware dynamic repair tree. A block-parallel draft model produces a length-K candidate block and its logits in one pass. In standard single-path speculative decoding, only that path is verified. If token k is rejected by the target model, all later tokens are discarded even when many of them would have matched the target had the earlier local error been repaired. CURE tries to fix exactly those fragile points.

The mechanism starts by identifying Uncertainty Focal Points using the top-1 versus top-2 log-probability margin from the draft model. A small margin indicates local ambiguity and a higher chance that this position will trigger downstream rejection. Under a fixed verifier budget, the method spawns alternative branches only at these focal points instead of expanding a dense candidate tree over the whole block. The motivation is simple: if most tokens are already predictable, uniform tree expansion wastes target verification on positions that do not need repair.

The paper formulates this as a budget-constrained candidate-tree optimization problem. The objective is to maximize accepted length under a verification budget V_max. The effective generation rate is written as expected accepted tokens divided by draft cost plus verifier cost. This formalization is useful because it makes the central trade-off explicit: local branching helps only when the gain in accepted context outweighs the extra cost of target-side tree verification.

A practically important component is cache resynchronization. Because repair branches may alter the finally accepted path, the draft model’s internal state must be realigned with the target-verified prefix. The authors design a cache-consistent resynchronization procedure that does not require retraining the draft model. That makes CURE a plug-and-play add-on for existing block-parallel backends, which is more valuable in practice than a method that depends on a specially trained draft architecture.24:T623,The evaluation covers code generation as the main domain and reasoning as an out-of-domain check. These numbers should be interpreted carefully. The gain in accepted tokens per step is meaningful but not huge, which suggests the method is not relying on aggressive tree expansion. Instead, it extracts moderate acceptance improvements from localized repairs. Because speculative decoding is often bottlenecked by memory-bound sequential target passes, even moderate acceptance gains can translate into noticeable wall-clock speedups.
