9:T516,The method operates in a strict query-only setting. Given only a query q, it uses no benchmark responses, preference labels, reference answers, human-written rubrics, or model training. The framework has three LLM roles: a rubric proposer, response generators, and a rubric-blind pairwise judge. A deterministic controller maintains the active rubric set, a tree structure, and evolution memory. At each step, the proposer emits either an Add patch for one atomic rubric or a Split patch for a bundled rubric. The central design choice is to avoid asking an LLM to compare two abstract rubric sets. Instead, each candidate rubric is tested in response space. The local pair starts from a strong answer satisfying the background rubrics and the candidate rubric, then minimally edits it to violate the candidate. This tests whether violating the rubric makes an otherwise similar answer worse. The alternative pair is generated from scratch: it first creates the strongest answer that satisfies the background rubrics while violating the candidate, then minimally repairs it to satisfy the candidate. This catches over-specific, optional, or style-only rubrics. The judge compares both pairs in both presentation orders.
