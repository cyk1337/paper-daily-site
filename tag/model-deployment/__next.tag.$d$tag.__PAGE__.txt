c:T4c8,Anthropic frames Fable 5 and Mythos 5 as two deployments of the same base model. Fable 5 is the general-use version with strong safeguards. Mythos 5 has fewer safeguards and is limited to trusted Project Glasswing partners for defensive cybersecurity. The Fable 5 safeguard stack uses defense in depth. Some mechanisms are trained into the model so that it refuses dangerous requests. Others are external classifiers that monitor an interaction and block potentially harmful cybersecurity requests or outputs. The classifiers are intentionally set with a large safety margin: a request must look clearly safe to avoid being blocked. This reduces room for jailbreaks, but also blocks some benign coding, debugging, and defensive-security requests. After Amazon researchers reported a prompt-based bypass that made Fable 5 identify vulnerabilities and, in one case, produce exploit demonstration code, Anthropic trained a new classifier targeted at that behavior. If Fable 5 blocks a request, the user is notified and the request is routed to Opus 4.8. This is a deployment-layer mitigation rather than only a model-weight update: it can be adapted quickly to a newly observed bypass pattern, but it increases false positives.d:T484,The post provides a small set of safety-testing results. Anthropic reports that less capable models, including Claude Opus 4.8, GPT-5.5, and Kimi K2.7, could identify the same vulnerabilities described in the Amazon report. For the exploit demonstration of the single vulnerability, every tested model could produce the same demonstration, including Claude Haiku 4.5, Sonnet 4.6, Opus 4.6, Opus 4.7, Opus 4.8, GPT-5.4, GPT-5.5, and Kimi K2.7. Anthropic therefore argues that the reported technique did not expose unique Mythos-level cyber capability, but instead hit a borderline case for Fable 5 safeguards. The new classifier blocks the specific reported technique in more than 99% of cases. In the remaining cases, Anthropic says the information is not detailed enough to be useful to an attacker. The tradeoff is a higher rate of benign requests being flagged during routine coding and debugging. The US Department of Commerce’s CAISI tested both the prior and new safeguards.
