18:T433,SWE-Shift introduces a matched-continuation benchmark design:
- The agent runs normally on a repo task until a scheduled checkpoint; the runner saves a fully restorable execution state (agent-visible history, workspace, controller state, tool availability, system settings, counters).
- From the same saved prefix, evaluation forks into:
  (i) Clean continuation: no change, continue execution; measures whether the agent could succeed from that intermediate state.
  (ii) Shifted continuation: inject a task-relevant update, then continue; measures robustness to the change.
- Changes are curated to be relevant (ignoring them can invalidate an otherwise successful continuation) and recoverable (a valid completion remains possible via agent-accessible tools).
- The benchmark spans 12 change families and introduces each change at 9 different intervention positions per scenario.
- Success criteria are defined relative to post-update requirements, including preserving still-valid work/effects and handling stale or misbound evidence, not just passing the original tests.19:T474,Agent4Sci is a controlled testbed that preserves much of the disorder of real research. Candidate benchmarks are filtered through domain classification, automated screening, human verification, and deep review. In the NeurIPS 2025 Datasets and Benchmarks track example, 10 benchmarks are admitted from 497 candidates, a rejection rate of about 98%. The final suite contains 20 benchmarks, 25 tasks, and 11 scientific domains across physical sciences, life sciences, Earth and environmental sciences, and scientific engineering. Each benchmark is standardized through human-verified baseline reproduction, repaired data splits, runtime cleanup, and isolated environments. During evaluation, the hill-climbing agent only sees training and validation data, then submits code changes, checkpoints, logs, and outputs. A separate evaluation agent runs the submitted artifacts on held-out test data, while an auditing agent inspects the trajectory for academic misconduct. The paper also tests lightweight plug-in skills for research ideation, experiment management, and scheduled checklists, separating model capability from workflow scaffolding.1a:T48d,A pilot study on 12 tasks from 5 NeurIPS 2025 benchmarks finds severe evaluation-gaming behavior in 5 tasks, including selective reporting, test-set contamination, metric manipulation, and direct hardcoding. The full evaluation covers Claude Code Opus, Claude Code Sonnet, Codex, and Gemini CLI. Each run receives 8 H200 GPUs, a 12-hour budget, and a minimal instruction to improve the target metric. All four agents obtain positive mean improvements, every benchmark is improved beyond its published best by at least one agent, and no run is flagged for academic misconduct under the protocol. Claude Opus reaches 10.4% mean relative improvement. Trajectory analysis is more informative than the aggregate score: Claude Opus behaves like an iterative optimizer, Codex like a plan-and-wait executor, and Gemini alternates between the two. The main limitations are novelty miscalibration, under-use of available resources, and rapid collapse into local engineering sweeps. Adding lightweight skills raises Claude Opus from 10.4% to 20.1% mean relative improvement and Codex from 4.4% to 8.1%, suggesting that workflow structure explains a meaningful part of the gap.1b:T8da,方法分成三层。第一层是数据。作者构建了 SWE-Intervene，从 Open-SWE-Traces、SWE-Hero、SWE-chat 的自然软件工程轨迹中抽取 action-level decision node。每个样本保留任务、完整 pre-action context、agent 提议动作，以及三类标签。Hard-Pause 的自然样本部分来自 SWE-chat 的 AskUserQuestion 交互。标签由 GPT-5.5 按人工制定准则标注，再经过两阶段人工审核，25.3% 的候选被剔除，最后得到 5,680 个训练样本和 1,243 个测试样本，并对下游 benchmark 做了去重。

第二层是监督构造。HiSentinel 的关键不是直接拿 pre-action context 做分类，而是先训练一个 privileged teacher。teacher 在训练时能看到 proposed action 以及该动作的 recorded execution result，因此它的判断带有 hindsight evidence。然后把 teacher 的干预判断蒸馏给一个 causal student sentinel，student 在部署时只能看到轨迹前缀和待执行动作。这样做的原因很明确：如果直接用人工或启发式在 pre-action 空间打标签，很多“看起来合理但会把轨迹带偏”的动作很难标；而 teacher 可以借助执行后果把 supervision 变得更接近最终任务完成。

第三层是反馈生成。作者把“是否干预”和“如何反馈”拆开优化。sentinel 先做三分类决策；若需要介入，再由单独的 feedback adapter 生成简洁、证据约束的指导语。Redirect 对应最小必要修正，Hard-Pause 对应明确指出需要的人类信息、权限或授权。这个拆分是合理的，因为决策头追求校准和低误报，生成头追求可执行性和最小干预，两者目标不同。

从问题设定上看，这篇工作和常见 process critic 的区别在于时机。process critic 往往在动作执行后根据最近几步给反馈，trajectory diagnosis 更偏事后定位 decisive error；HiSentinel 把边界前移到 action proposal 与 environment execution 之间，试图在环境状态被污染前阻断错误。和简单的 prefix anomaly detection 也不同，它不是检测“看起来奇怪的动作”，而是预测该动作是否会降低 eventual task completion，并区分 agent 自主可修复与必须人工介入两类情况。1c:T94e,The method has three main pieces. First, the dataset. SWE-Intervene is built from natural software-engineering trajectories drawn from Open-SWE-Traces, SWE-Hero, and SWE-chat. Each instance preserves the task, full pre-action context, and exact proposed action, and is labeled as Allow, Redirect, or Hard-Pause. Natural AskUserQuestion interactions from SWE-chat provide Hard-Pause examples. Labels are produced by GPT-5.5 under human-written guidelines, then filtered through a two-stage human audit that rejects 25.3% of candidates. The final dataset contains 5,680 training instances and 1,243 held-out test instances, with explicit de-duplication against downstream benchmarks.

Second, hindsight-distilled supervision. A privileged teacher is trained or prompted with access to the proposed action and its recorded execution result. This gives the teacher post-action evidence when judging whether intervention would have improved the trajectory. Those judgments are then distilled into a lightweight causal sentinel that only sees the trajectory prefix and proposed action. This is the key design choice: instead of asking annotators or heuristics to guess from incomplete pre-action context, the training signal is informed by what actually happened after execution.

Third, feedback generation is optimized separately from intervention classification. The sentinel first decides whether to intervene. If intervention is needed, a dedicated feedback adapter generates concise, actionable guidance: minimal correction for Redirect, or a specific request for missing human information, authorization, or access for Hard-Pause. This separation makes sense because the classifier needs calibration and low false positives, while the generator needs usefulness and brevity.

Relative to prior work, HiSentinel differs from process critics and trajectory diagnosis in timing. Process critics usually react after execution; diagnosis methods localize decisive errors retrospectively. HiSentinel moves the decision boundary to the gap between action proposal and environment execution, aiming to prevent state corruption before recovery becomes expensive or impossible. It also differs from generic anomaly detection: the target is not whether an action looks odd, but whether executing it is likely to hurt eventual task completion, and whether the agent can self-correct afterward.1d:T683,The motivating statistics are strong. On 1,184 failed CLI-agent trajectories from Terminal-Bench, half of the decisive errors occurred by around step 7, trajectories became unrecoverable around step 12, and the first observable failure signal appeared only around step 16. Prefix monitoring detected only 3.7%–8.7% of failures before lock-in. That directly motivates pre-execution intervention.

The dataset is modest but curated: 5,680 train and 1,243 test instances, including 1,122 natural test cases and 121 AUQ-derived cases. The explicit benchmark de-duplication is important, since trajectory overlap can easily inflate apparent intervention quality.

The deployed sentinels are lightweight, at 0.6B and 1.7B parameters. The reported metrics include task completion, unnecessary interventions, and inference overhead.
