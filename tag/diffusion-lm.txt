18:Taa6,方法由三个关键部件组成。

第一，训练目标。作者采用 uniform token replacement 而不是 mask corruption。也就是每个位置以概率 1-α_t 被替换成词表中的均匀随机 token，而不是替换成特殊 [MASK]。这样得到的输入始终是一份“完整草稿”，错误 token 没有显式标记，模型必须同时学会两件事：当当前位置本来就对时要保留，当它错时要修复。训练时在所有位置上监督 clean-token posterior，等价于让 denoiser 在完整但带噪的草稿上做全位置重建。

第二，单次前向的上下文评估。直接拿 denoiser 对当前 token 的概率给草稿打分会有偏差，因为在 uniform corruption 信道下，观察到 token x_i 本身会显著提高 x_i 为真的后验概率，即便把该位置拿掉后，周围上下文其实更支持另一个 token。作者用已知的 corruption process 做 Bayes 校正，把“观察到自身 token 带来的证据”除掉，再重归一化，恢复出该位置的 cavity conditional，也就是 p(x_i | c, z_{-i}, t) 这一类“给定条件和其他 noisy token，但不看自己”的分布。然后把草稿每个位置真实 token 的负对数 cavity conditional 相加，得到 cavity energy。这个量不是精确联合似然，而是一个噪声平滑后的 pseudo-likelihood 型能量分数，但足够用于候选草稿之间的比较。

第三，推理算法 propose-read-retain。推理不是标准 diffusion ancestral sampling，也不是每轮完全重启。流程是：保留当前最优草稿；对其做部分 re-noise，避免陷入局部最优，同时保留部分结构；用同一个 denoiser 对所有位置并行预测 clean token，直接形成 candidate draft；再用一次新的前向、在固定 read noise level 下计算 candidate 的 cavity energy；若能量更低则接受，否则保留旧草稿。所有 proposal pass 和 scoring pass 都计入固定预算，最后返回最低能量的草稿。这里有两个设计很关键：一是“提案”和“评估”分开，避免用生成时的同一组 logits 给自己背书；二是 retain best draft，而不是每轮独立采样，这使得搜索更像局部修订而不是盲目重启。

和已有方法相比，差异主要在三点。相对 MDLM/UDLM 一类离散 diffusion，作者不依赖 reverse transition 逐步采样，而是把 denoiser 的 clean-token 预测直接当作修订操作。相对普通 non-autoregressive refinement，作者补上了一个有理论依据的整稿评分机制，而不是默认并行替换一定更好。相对 energy-based LM，这里的能量不是单独训练的打分器，而是从 denoiser 的后验结构中解析出来的。19:T477,For pretraining and alternative language-modeling paradigms, the contribution is meaningful in three ways. First, it moves diffusion-style language modeling away from schedule-driven ancestral denoising toward a draft-refinement loop where the denoiser acts as both editor and evaluator. Second, it introduces cavity energy, which turns a denoiser trained under uniform corruption into a contextual whole-draft scoring mechanism resembling noise-smoothed pseudo-likelihood. That is relevant beyond this paper: masked LM, any-order LM, energy-based LM, and draft-based reasoning all face the same issue of scoring partially self-supported token configurations. Third, it identifies and fixes a subtle but important failure mode: denoiser confidence on an observed token mixes contextual support with evidence from seeing that token itself. If that self-token evidence is not removed, the model can prefer internally stable but wrong drafts. This is not a drop-in replacement for mainstream large-scale AR pretraining, but it is a serious step in the line of work that tries to challenge next-token decoding with alternative generation dynamics.1a:T9f4,The method has three main components.

1) Training under uniform corruption. Instead of mask corruption, each token is independently replaced with a uniformly sampled vocabulary token with probability 1-α_t. The noisy input is therefore always a complete draft: every position contains an ordinary token, and wrong positions are unmarked. The denoiser is trained to reconstruct the clean sequence at every position. This forces it to learn both preservation and repair: keep a token when it is already supported, change it when the surrounding draft suggests it is wrong.

2) One-pass contextual evaluation via cavity correction. A naive score based on the denoiser probability of the current token is biased, because under the known corruption channel, observing token x_i itself is strong evidence in favor of x_i, even if the rest of the draft would support another token. The paper derives a correction that divides out this self-token likelihood and renormalizes, recovering the cavity conditional: the distribution of x_i given the condition and all other noisy draft tokens, but not the observed token at position i itself. Summing the negative log cavity probabilities assigned to the draft tokens yields cavity energy. This is not an exact joint likelihood; it is a learned, noise-smoothed pseudo-likelihood-style energy. The optimization analysis starts from the path-space ELBO for discrete diffusion. The objective can be decomposed into a transition-prediction term and a schedule-matching term. In standard MDMs, the forward process is an absorbing transition toward a mask token, and the schedule is independent of the denoiser, so the schedule-matching term vanishes. The model only needs to learn reverse prediction. In UDMs, transitions operate over the full vocabulary, and the schedule effectively depends on the denoiser, introducing an extra model-dependent schedule-matching loss. This creates additional excess loss and makes optimization harder. The paper therefore gives a principled reason, not just an empirical one, for why MDMs tend to train more easily.

The expressivity analysis uses circuit complexity. The key result is that standard MDMs remain in TC0, even with arbitrary-order prediction and bidirectional attention. In other words, their parallel computational depth stays constant because committed tokens cannot be rewritten. UDMs, by contrast, maintain a rewritable state and can repeatedly revise tokens, which enables richer hierarchical computation and supports NC1-style behavior. The exact complexity labels matter less than the underlying mechanism: rewritable intermediate states fundamentally change what the model can compute in parallel.

LED is built around this observation. It keeps the MDM-style commit process intact, but adds a proposal branch that is allowed to rewrite tokens. During training, a pretrained MDM first generates a proposal sequence. LED is then trained, with standard cross-entropy, to predict the target sequence conditioned on that proposal. At inference time, LED alternates between a proposal stage and a commit stage within each commit block. The proposal stage maintains a rewritable intermediate state, allowing tokens to be generated and revised over multiple lookahead steps. The commit stage then follows the standard masked-diffusion process: once a token is committed, it is fixed and cannot be changed later. Across stages, reliable proposal tokens are preserved, while erroneous ones are revised in future proposal iterations.

This is the central design trade-off. Why not train a UDM directly? Because rewritability inside the main generative process makes optimization harder. Why not stay with a plain MDM? Because commit-once decoding limits iterative correction. LED places rewritability in an auxiliary branch and keeps trainability in the main branch. It is better understood as a lookahead editor wrapped around an MDM than as a uniform diffusion model.
