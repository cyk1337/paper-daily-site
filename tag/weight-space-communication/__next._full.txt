18:T65d,The setup uses multiple senders and one receiver, all instantiated from the same frozen backbone but differentiated by role prompts. For a given query, each sender processes the input once and exposes hidden states. A learned parameter generator consumes these states and emits low-rank LoRA factors for selected linear layers in the receiver. Contributions from multiple senders are fused, and the resulting perturbations are transiently patched into the receiver during generation. After the response is produced, the perturbation is removed and the base weights remain unchanged.

Compared with text-based multi-agent systems, the key difference is not merely fewer tokens. The receiver never needs to read sender messages in-context, so the system avoids auxiliary decoding, prefill, and cache expansion. Compared with latent-state transfer, TFlow does not require the receiver to interpret the sender’s hidden geometry directly. Sender states only serve as conditioning signals for a generator that outputs tensors already aligned with the receiver’s parameter shapes.

Several design choices matter. The method assumes a fixed receiver architecture and known target modules, which improves practicality but limits generality. It uses LoRA-style low-rank updates rather than full dynamic weights, keeping the generator output manageable. The perturbation is query-specific and transient, so there is no persistent online update. Finally, multi-sender interaction happens through parameter fusion rather than token-level deliberation, making the system closer to parallel conditional adaptation than iterative discussion.19:T55c,The main setup is a three-agent system with a frozen Qwen3-4B backbone: two senders and one receiver. Evaluation spans five benchmarks covering reasoning, knowledge, and coding.

Against the standalone receiver, TFlow improves accuracy on all five benchmarks, with gains up to 8.5 points. This suggests that sender hidden states are being translated into useful computational bias rather than noise.

Against a text-based three-agent baseline, the efficiency gains are large: up to 83.27% fewer processed tokens and up to 4.6x lower wall-clock inference time. This is exactly where the method should win, since text communication pays both message generation and receiver-side reprocessing costs.

The paper also reports up to 32.69% fewer processed tokens relative to the standalone receiver. That is notable because it implies that some benefits of collaboration can be retained without paying for long explicit communication chains.

HumanEval+ is the main exception. TFlow is less competitive there, and the paper’s interpretation is sensible: code synthesis benefits more from extra generation budget and explicit externalized search than from compressed communication alone. This is an important boundary condition.
