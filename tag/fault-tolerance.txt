18:T45d,Agora is built around three constraints absent in centralized training: (1) the model is sharded primarily via pipeline parallelism, using subspace networks to compress cross-stage activations by roughly two orders of magnitude so that PP is viable over internet-grade links; (2) data-parallel replicas do not synchronize gradients with a per-step all-reduce; instead, sparse asynchronous parameter averaging exchanges only a small subset of slow-moving weights, infrequently and in the background, so weight synchronization overlaps with computation and never blocks the optimizer step; (3) fault tolerance is built into the training step rather than implemented as an external recovery mechanism, so joins, leaves, and heterogeneity are handled continuously, and newcomers catch up from stale weights without disrupting the run. On top of this, the system adopts ideas from Unextractable Protocol Models (UPM): because the model is model-parallel, no single participant ever holds the full weights, aiming to make weight extraction from individual nodes infeasible. The overall paradigm is termed Protocol Learning.19:T491,The design relies on two observations. First, in 3D parallel training, model shards and optimizer shards have different recoverability properties. Model parameters are often replicated across data-parallel peers and can be reconstructed from healthy ranks with the same logical partition. Sharded optimizer states, including first and second moments, are distributed within a data-parallel rank and may be lost when a node fails permanently. DeadPool therefore replicates optimizer-state shards to neighboring nodes in memory at every iteration, using asynchronous communication overlapped with compute to keep the backup off the critical path. Second, recovery is handled as a topology-repair problem. A spare node replaces the failed node, communication groups are reconstructed at runtime, and training resumes without terminating the whole job. The system also classifies failures so that topology-changing recovery is only used when node membership is truly invalidated. The implementation is built on PyTorch and Megatron-LM, but the required abstractions are generic: sharded states, spare-node management, recovery coordination, and communicator reconstruction.1a:T5e2,The framework partitions a global cluster into M independent learners. Each learner keeps its own model replica θ_m and runs an inner optimizer, such as AdamW, on its local data shard for H steps. Synchronization is expressed through the DiLoCo outer update: the difference between a learner’s current parameters and a reference parameter state is treated as an outer gradient, and an outer optimizer aggregates these updates. Earlier DiLoCo synchronized all learners every H steps. Streaming DiLoCo split parameters into P fragments, synchronized different fragments at different offsets, and allowed a small communication delay τ to reduce peak bandwidth. Decoupled DiLoCo removes the blocking barrier. Learners can continue training without waiting for all other learners to reach the same synchronization point. A central synchronizer asynchronously receives learner updates and sends reconciled parameter updates back. The design deliberately trades strict consistency for availability and partition tolerance. The main algorithmic question becomes how to control parameter drift through H, fragment size, delay, update scheduling, and the outer optimizer. Compared with elastic SPMD, it does not simply resize a still-synchronous job after a failure; it limits the failure blast radius to the affected learner. Compared with naive asynchronous SGD, it keeps the DiLoCo structure of multi-step local training and outer optimization, which is better aligned with bandwidth-constrained pre-training.1b:T4b2,The experiments are organized around three claims: asynchronous learners should not materially degrade pre-training quality; the method should work for both dense and MoE models; and it should improve goodput under realistic failures. The paper reports comparable downstream performance to standard data-parallel training across several model and compute scales, including dense and Mixture-of-Experts architectures, with both text and multimodal evaluations. It also checks whether post-training remains effective after asynchronous pre-training, and reports no clear degradation in later instruction or alignment-style stages. The robustness evaluation uses chaos-engineering style fault injection, with continuous hardware failures or learner disruptions. Under these conditions, Decoupled DiLoCo maintains high availability while synchronous SPMD suffers from global stalls, fault detection overhead, and cluster-wide reconfiguration. - The cluster is partitioned into M independent learners. Each learner runs an inner optimizer (e.g., AdamW) on its own data shard for multiple local steps.
- In DiLoCo, every H steps learners synchronize and an outer optimizer (often SGD with Nesterov momentum) treats inter-learner parameter differences as an “outer gradient” to update a global reference.
- Streaming DiLoCo shards parameters into P fragments to reduce peak bandwidth, but synchronization is still fundamentally blocking.
- Decoupled DiLoCo introduces a central synchronizer and an asynchronous reconciliation protocol: learners can continue local training while sending/receiving fragment-wise deltas with delay, tolerating stragglers, communication hiccups, and local failures without global stalls.
