18:Tac6,系统围绕 Listen–Think–Act–Speak 循环设计。推理时包含两条 Audio Encoder + LLM 路径：一条用于 full-duplex 决策，判断继续听、开始说、停止或恢复；另一条用于 speech-to-text 风格的响应内容生成。随后 context-aware voice renderer 根据文本内容、对话历史、声音线索和声学上下文生成流式语音。这个拆分的取舍是清楚的：内容生成、交互控制和语音渲染承担不同约束，避免把所有行为压到单一解码器里。

Think 层是 foundation post-training。流程包含四步：Core-Cocktail 冷启动、Multimodality OPD、domain GRPO specialists、Multi-Teacher OPD consolidation。Core-Cocktail 从 audio-pretrained AudioLM 出发，用 source Text LLM 作为语言参数锚点，先对齐共享语言参数，再用受控 SFT 建立可用的音频策略。训练数据约一百万小时 paired audio-text，覆盖通用音频理解、语音指令、多轮交互、工具请求、情绪与共情、语用意图、声学场景理解等。

M2-OPD 是关键。Audio Student 先在音频输入上采样自己的轨迹；Text Teacher 接收语义等价的文本提示和同一学生前缀，给出每个 token 位置的分布；Frozen Audio Reference 接收原始音频上下文和同一前缀，也给出分布。也就是说，教师不是提前生成答案让学生模仿，而是在学生的 on-policy 轨迹上逐步评分。这能减少离线蒸馏中的分布错位：学生在自己会访问的状态上学习，同时利用 Text LLM 的语言推理能力和 Audio Reference 的音频条件约束。

Act 层是方法中心。论文构造 executable environments，环境中包含工具、策略、数据库和任务。环境会经过验证，并通过 rollout 结果持续演化。训练不只看函数调用语法，而是看工具选择、状态校验、长期任务是否完成、是否该拒绝、进度沟通是否有根据。优化使用 GRPO，并把反馈分成 dialogue-level、milestone-level、turn-level。dialogue-level 约束整体任务完成，milestone-level 给长程过程提供中间信号，turn-level 处理局部响应和工具反馈解释。这种多粒度奖励比只给最终成功/失败更适合语音交互，因为用户中途改约束、打断、等待都会改变最优行为。

Speak and Coordinate 层把“说什么”之外的行为纳入策略：何时说、是否该说、何时行动、何时等待。它处理 full-duplex interaction 中常见的冲突，例如用户未说完时不应抢话，工具运行时不应给出超过证据的结论，用户修改目标时需要中止或更新执行计划。论文还提出单独的 Voice Harness，用显式任务边界和记忆边界约束评测与执行。19:Tb11,The system is organized around a Listen–Think–Act–Speak loop. At inference time, two Audio Encoder + LLM paths are used. One path makes full-duplex decisions such as keep listening, start speaking, stop, or resume. The other generates response content as text. A context-aware voice renderer then uses the content, dialogue history, voice cues, and acoustic context to produce streaming speech. This separation makes the control problem cleaner: response content, turn-taking policy, and voice rendering have different constraints.

The Think layer uses a four-stage foundation post-training pipeline: Core-Cocktail cold start, Multimodality OPD, domain GRPO specialists, and Multi-Teacher OPD consolidation. Core-Cocktail starts from an audio-pretrained AudioLM and uses the source Text LLM as an anchor for shared language parameters. It then applies controlled SFT over audio and text instruction data. The foundation data scale is about one million hours of paired audio-text data, covering general audio understanding, spoken instruction following, multi-turn interaction, tool-oriented requests, emotion, empathy, pragmatic intent, and acoustic-scene understanding.

M2-OPD is the core capability-transfer mechanism. The Audio Student samples a response trajectory conditioned on audio. At each token position, the Text Teacher receives a semantically equivalent text prompt plus the same student prefix, while the frozen Audio Reference receives the original audio context plus the same prefix. Both provide token-level distributions on the student’s on-policy trajectory. The teacher does not generate a separate answer for imitation; it scores the states actually visited by the student. This design combines text-grounded reasoning supervision with audio-conditioned constraints.

The Act layer builds executable environments that include tools, policies, databases, and tasks. These environments are validated and evolved using rollout feedback. Training uses GRPO with dialogue-level, milestone-level, and turn-level rollouts. Dialogue-level rewards capture final task success, milestone-level rewards provide intermediate signals for long-horizon execution, and turn-level rewards handle local behavior such as tool-feedback interpretation or progress communication. This is a stronger formulation than function-call SFT because the target behavior includes execution state, policy constraints, refusal, and evidence-bounded communication.

The Speak and Coordinate layer learns a conversational policy over how, when, and whether to speak or act. It handles cases such as user interruption, waiting until the user finishes, changing the target while a query is running, or withholding unsupported conclusions. The separate Voice Harness introduces explicit task and memory boundaries for evaluation and control.1a:T4f5,The concrete scale reported in the provided material is approximately one million hours of paired audio-text data for the foundation recipe. Parameter count, tokenizer details, total training tokens, and full benchmark tables are not included in the supplied content.

The evaluation is organized into intelligence, action, interaction, and real-time dimensions, comparing Qwen-Audio-3.0-Realtime with Qwen-Audio-3.1-Realtime. Intelligence covers audio reasoning, multilingual understanding, and multi-turn instruction following. Action covers tool use, feedback interpretation, task completion, refusal, and grounded progress reporting. Interaction covers conversational behavior and full-duplex decisions.
