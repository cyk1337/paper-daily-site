18:T5a8,Core represents a reasoning trajectory as a stack of decisions. Each decision has a stable identifier, dependencies, and a canonical key that preserves type, value, dependency context, and occurrence identity when needed. A proposer, which may be an LLM or a deterministic policy, returns a finite ordered list of candidates for the next decision. The verifier returns pass, fail(C), or unknown. A fail(C) output is only eligible for hard caching when C is a sound conflict core: no valid complete solution can contain all decision keys in C. The controller keeps a stack and a set of learned nogoods. Before verifying a candidate, it checks whether the resulting state contains a cached core; if so, the candidate is skipped without another verifier call. When a certified failure is found, Core optionally minimizes the core, inserts it into the cache, removes stored supersets, and backjumps to the latest decision contained in the core. Later decisions are discarded because they cannot repair a conflict that does not mention them. If all candidates at a level are exhausted, their explanations can be resolved into an exhaustion core. Unknown verifier outputs can extend the stack provisionally, but they cannot create hard constraints.
