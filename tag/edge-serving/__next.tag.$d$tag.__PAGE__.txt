a:T979,方法上，STEEL做了三件事。

第一件，是把 prefill attention 重写成适合 XDNA AIE 阵列的三阶段数据流流水线。论文沿用 FlashAttention 的在线 softmax 思路，不显式物化完整 attention matrix，而是按 tile 逐块计算 QK^T、维护每行的 running max 与归一化项，再与 V 累积得到输出。不同点在于，作者不是把它当作单 kernel，而是拆成可分布到多个 AIE tile 的 producer-consumer pipeline。按文中描述，这个 pipeline 将矩阵乘、归一化统计更新、以及后续与 V 的累积等步骤分散到不同阶段，并通过显式数据布局和片上缓冲传递中间量，尽量避免回写外存。

第二件，是数据布局与工作切分的联合设计。XDNA 这类 NPU 的关键不是线程块，而是 tile 上本地存储和 tile 间流式通信。作者针对 Q/K/V 的 tile 化、转置/重排、以及中间统计量的存放做了专门布局，使得每一级都能以较规则的块访问推进。这里的重点不是数学新意，而是把 FlashAttention 中“在线归一化必须跨 tile 保持数值正确”这件事，转成硬件上可流水执行的状态传递问题。论文还强调了与 layer-by-layer 实现的区别：后者把 attention 拆成多个独立算子，频繁落地中间结果；STEEL 则把这些步骤融合成一个持续流动的数据通路。

第三件，也是论文最有信息量的点，是 sparsity-aware pipeline placement。因果掩码使得不同 query block 对应的有效 key block 数量不同，靠近序列开头的块工作量小，靠近结尾的块工作量大。如果按均匀方式把 block 分给流水线阶段或 tile，会出现后段拥塞、前段空转和同步等待。作者利用这种由 causal mask 诱导出的三角形稀疏结构，重新安排 block 在 pipeline 中的位置和分配，使各阶段负载更接近均衡。文中给出的结果是，相比 uniform placement，这一策略单独带来 38% latency reduction。这个点值得注意，因为它不是传统意义上的 sparse attention，而是“对已知结构性空区的执行级利用”。

此外，论文还强调可移植性：同一套数据流 formulation 可以迁移到多代 XDNA-like 架构，并在 XDNA 1 上超过此前 DATO 的实现。这里的可移植不是源码无改动，而是算法分解与流水线组织方式具有架构族层面的复用性。b:T83f,STEEL has three main components.

First, it reformulates prefill attention as a three-stage dataflow pipeline over XDNA AI Engine tiles. The algorithm keeps the core FlashAttention idea: compute attention block by block, maintain online softmax statistics instead of materializing the full score matrix, and accumulate the output incrementally. The novelty is in how this is decomposed for a spatial NPU. Rather than treating attention as one monolithic kernel, the computation is split into pipeline stages that can run on different tiles with explicit producer-consumer communication through on-chip buffers.

Second, the implementation jointly designs tiling and data layout. On XDNA-like hardware, the critical resource is not just arithmetic throughput but how Q, K, V tiles and intermediate statistics move through local memories and streams. The paper restructures the computation so that the running max and normalization terms required by online softmax can be propagated correctly across tiles without repeatedly spilling large intermediates to external memory. This is the key difference from a layer-by-layer implementation, where attention is broken into separate operators and intermediate tensors are materialized between them.

Third, and most interestingly, STEEL introduces sparsity-aware pipeline placement. Because of causal masking, different query blocks interact with different numbers of key blocks. Early query blocks have less valid work; later ones have more. A uniform placement therefore creates severe load imbalance and synchronization stalls. STEEL explicitly accounts for this triangular workload pattern when assigning work to pipeline stages and tiles. The paper reports that this placement strategy alone reduces latency by 38% relative to uniform placement. This is an execution-level use of structured sparsity, not a modeling change.

The paper also argues for portability across multiple XDNA-like generations. The claim is not that the exact code is universally portable, but that the decomposition and pipeline organization are reusable across this architecture family.c:T512,The most useful results come from three comparisons.

First, on an AMD Ryzen AI 9 HX 370, STEEL on the XDNA 2 NPU is compared against FlashAttention on 12 Zen5 CPU cores and the RDNA 3.5 GPU. The reported average energy reduction is 9.17x versus CPU and 1.75x versus GPU. That is a meaningful system-level result for long-sequence prefill.

Second, against a layer-by-layer attention implementation on XDNA 2, STEEL achieves an average 22.8x speedup. This large gap indicates that fused dataflow execution matters much more than small kernel-level tuning on this class of hardware.

Third, on XDNA 1, STEEL reduces latency by 9.6x on average relative to the previous DATO FlashAttention implementation. That supports the portability claim and suggests the gain is not limited to one specific chip generation.

The key ablation is the sparsity-aware placement strategy, which gives a 38% latency reduction over uniform placement. This directly validates the paper’s main systems argument: causal-mask-induced imbalance and synchronization overhead are first-order bottlenecks on NPUs.

What is missing from a broader serving perspective is decode-time analysis, KV-cache-heavy workloads, and combinations with other long-context serving techniques such as paged attention or block-sparse variants.d:T42f,For a skim, start with the introduction and the contribution bullets to frame the paper correctly: it is about execution mapping, not a new attention objective. Then focus on the method section that explains the FlashAttention decomposition, the three-stage pipeline, and the source of load imbalance under causal masking. The most informative figures are likely the pipeline/dataflow diagram, any tile-utilization or timeline visualization, and the latency-energy comparison across NPU, CPU, and GPU. Expected reading time is about 20 to 30 minutes.

If you only keep one idea, keep the sparsity-aware pipeline placement. It explains why fused attention on NPUs is not just about operator fusion; it is about scheduling around the triangular work pattern created by the causal mask.
