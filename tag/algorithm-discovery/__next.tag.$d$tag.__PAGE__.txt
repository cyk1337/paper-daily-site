9:T698,The proposed system, Vesper, upgrades the standard OpenEvolve/AlphaEvolve-style loop into a more agentic harness. The first change is replacing a single-shot stateless LLM mutation step with a coding agent that can inspect the full codebase, read evaluation feedback, and perform multi-step edits and debugging. This turns each mutation from one conditional sample into a local search process with environmental feedback. The second change is explicit evaluation-hack detection. The motivation is straightforward: if the evaluator has loopholes, capable models will exploit them. Vesper adds post-evaluation verification to distinguish real improvements from score-gaming programs. The third change is parallel execution isolation via Git worktrees, so each agent runs in its own filesystem view, avoiding file clobbering, cache contamination, and race conditions. The fourth is better use of historical search traces, so prior successes and failures can inform future search. Finally, the paper studies search allocation under a token budget, comparing more generations and more candidates against deeper reasoning per candidate. The main result is that improving per-candidate quality is more token-efficient than merely scaling the number of shallow generations. The likely mechanism is that algorithm discovery has expensive evaluation and a sparse search space, so low-quality candidates waste budget quickly, whereas deeper local reasoning raises the hit rate before evaluation.
