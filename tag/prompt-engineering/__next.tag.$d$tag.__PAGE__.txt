a:T4ab,The setup is clean and controlled. The authors define a fixed Task Management API with seven components, explicit communication rules, data ownership constraints, six hard architectural rules, 25 HTTP routes, three ADRs, and a prescribed file layout. They then encode the exact same system in five formats: natural-language prose, Mermaid diagrams with constraints and ADRs, OpenAPI, C4/Structurizr DSL, and TypeScript interface contracts with ArchUnit-style rules. Six models from three vendor families are asked to implement the system in a multi-turn coding-agent setting. Evaluation combines three channels: automated static architecture checks, automated route-coverage analysis, and LLM-as-judge scoring for architectural adherence, constraint compliance, and completeness. The central result is not that one format universally wins, but that there is a strong format-by-model interaction. Frontier models can absorb almost any representation, whereas weaker models improve sharply when the specification is more structured and closer to executable code. The paper also identifies three recurring failure modes: compilation death spiral, premature termination, and perfectionist iteration.b:T46d,The study is modest in scale but well controlled: 90 main multi-turn trials are reported, and 93 full transcripts and codebases are released. Four results stand out. 1) Strong format-by-model interaction: on Sonnet 4.6 and GPT-5, the quality spread across formats is only 0.17 to 0.92 points, while on non-frontier models it reaches 0.83 to 2.42 points. 2) TypeScript contracts strongly help the weakest model: Gemini Flash implements only 33% of specified API routes under prose, but 100% under TypeScript interface contracts, a 3x improvement from representation alone. 3) Inverted cost efficiency: Haiku consumes about 735K tokens for a score of 6.50, while Sonnet uses about 640K tokens for 8.42, showing that smaller iterative agents are not necessarily cheaper in practice. 4) Self-validation collapses with weaker models: frontier models achieve 100% demo run rate, while the smallest model reaches 0%, meaning it never successfully tests its own system end to end. The primary variants preserve the objective, acceptance criteria, and test command while changing framing: precise baseline, deep thinking, exhaustive exploration, multiple approaches, maximum certainty, adjacent cleanup, no-questions autonomy, bounded efficiency, and related forms. Stress variants intentionally break semantic equivalence through ambiguity, conflicting constraints, irrelevant context, misleading hints, or multi-turn restatement. The main statistic is a paired reasoning ratio against the median baseline for the same model-harness-task block.
