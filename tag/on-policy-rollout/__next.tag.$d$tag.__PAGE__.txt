9:T900,方法核心是把每个问题的监督目标，从“固定 expert 轨迹”改成“由当前策略状态决定权重的候选轨迹池”。具体做法有三层。

第一层是构造 candidate pool。对每个问题，除了离线 expert trajectory 之外，作者还从当前模型按 on-policy rollout 采样多条解答，并通过可验证器筛出正确轨迹。这样每道题不再只有一条离线答案，而是有 expert + verified self-generated trajectories 的局部候选集合。

第二层是估计 problem-level solvability。作者用当前策略在该题上的 rollout 成功率，作为这道题对当前模型而言的“可解性”指标。这个量不是看 token 置信度，也不是看 expert 轨迹内部哪些 token 难学，而是直接问：模型自己能不能把题做出来。若成功率低，说明当前策略确实需要更强的 expert 纠偏；若成功率高，说明模型已经掌握了这类题的某些有效路径，此时继续强压单条 expert 轨迹，收益会下降，甚至会伤害已有分布。

第三层是基于 solvability 做 trajectory-level adaptive weighting，并加入 reference-constrained regularization。论文的表述里，RASFT 并不把问题显式写成 RL 的 reward/advantage 优化，而是把 expert 轨迹和模型自己生成的正确轨迹都视为“对齐候选”，然后根据 problem solvability 动态调整它们的训练权重：难题更偏向 expert，易题则放松对 expert 的刚性模仿，并允许正确的 self-rollouts 参与训练。与此同时，作者引入 frozen reference model 与当前 policy 的逆比率约束，用来抑制过度 policy drift。这个设计和 ASFT 一类 reference anchoring 有相似处，但这里的作用不是单纯稳定训练，而是更保守地“激活”模型已有推理能力，避免被新一轮 imitation 覆盖。

和已有方法相比，区别比较清楚。DFT、ASFT、ProFiT 都是在 expert trajectory 内部重加权，关注 token-level 或 objective-level 的拟合强弱；RASFT 则把适应性提升到 problem level，并显式利用 on-policy rollout 的可验证结果来决定 supervision strength。它不是简单把正确 self-generated data 混进来，而是先判断这道题当前是否还需要 expert 作为主导信号。a:T779,The method replaces the fixed expert-only target with a policy-conditioned candidate set and problem-level adaptive weighting.

First, for each problem, RASFT builds a local candidate pool containing the offline expert trajectory and verified correct trajectories sampled from the current policy. This is important: the model is not only trained on static demonstrations, but also on its own successful rollouts when they are available.

Second, it estimates a problem-level solvability score from the success rate of on-policy rollouts. This score is the central control signal. It does not ask which tokens in the expert trace are easy or hard. Instead, it asks whether the current model can already solve the problem. Low solvability means the model still needs strong expert correction; high solvability means strict imitation of one expert path is less necessary and may even be harmful.

Third, RASFT performs trajectory-level adaptive supervision. Expert trajectories receive higher influence on hard problems, while correct self-generated trajectories are allowed to contribute more on problems the model can already solve reliably. The paper frames this as policy-aware regularized SFT rather than explicit RL with rewards and advantages. In addition, it introduces an inverse-ratio constraint between a frozen reference model and the current policy to limit excessive policy drift. This reference anchoring is not only for optimization stability; it is meant to preserve the model’s existing reasoning distribution and avoid overwriting it through aggressive imitation.

Relative to prior SFT variants, the distinction is clear. DFT, ASFT, and ProFiT mainly adapt supervision within the demonstration, typically at token or objective level. RASFT moves adaptivity to the problem level and uses verified on-policy behavior to decide how much expert guidance is needed. That is the main conceptual step.b:T537,The experiments cover both math reasoning and code reasoning, comparing against standard SFT, several SFT-style variants, and GRPO.

On Qwen2.5-Math-1.5B, the reported math score improves from 25.00 to 27.72, a 10.9% relative gain. This is a meaningful result because it comes from changing the supervision scheme rather than scaling the base model or adding much more data.

On Llama-3.2-3B for code generation, performance improves from 24.93 to 31.63, a 26.9% relative gain. The larger gain on code is plausible: code tasks often have many valid solution paths and reliable verification, so over-imitation of a single reference can be especially restrictive.

Against GRPO, the paper reports an average math improvement from 20.25 to 23.47, or 15.9% relative. The right reading is not that RASFT dominates RL in general, but that when expert data and verifiers are available, a rollout-aware SFT objective can be more stable and less noisy than direct RL optimization.

The most important ablations are likely the following: removing self-generated correct trajectories, removing solvability-based weighting, removing the reference-ratio regularizer, and varying rollout count or verifier settings. Those ablations are what determine whether the gains come from genuine policy-aware supervision rather than simple data augmentation.c:T485,Start with the introduction and the method overview figure. The key distinction from DFT, ASFT, and ProFiT is that RASFT does not mainly modify token loss; it changes who the model should learn from, and by how much, on each problem.

Then read the method section carefully for four pieces: the local candidate pool, the solvability score, the trajectory-level weighting rule, and the inverse-ratio regularization with the frozen reference model. The exact training objective matters here, especially how expert and self-generated correct trajectories are mixed and normalized.

In the experiments, prioritize three things: the main comparison table against SFT-style baselines and GRPO, the ablations removing each component, and any analysis bucketed by problem difficulty or rollout success rate. If the paper includes such stratified analysis, it is the strongest evidence that the mechanism works as intended.
