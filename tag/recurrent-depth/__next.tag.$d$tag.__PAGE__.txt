9:T6f9,LoopVAE uses a scale- and loop-conditioned shared core. The encoder and decoder do not share parameters with each other, since analysis and synthesis are different transformations, but within each branch the same fixed-resolution operator is reused across all scales and loop steps. At scale s, a transition module first produces an initial feature h_{s,0}. The shared residual update is then conditioned on a learned scale embedding and a learned loop embedding, and applied L_s times.

A notable design choice is the gated input-injection path. Each scale has a scale-specific projection P_s(h), multiplied by a learnable scalar g_s initialized at zero. The first loop omits this injection; later loops add it once before the whole K-block core. This gives the recurrent process a shortcut back to the feature that entered the current scale, which likely helps prevent drift during repeated refinement. The authors explicitly note that the standalone effect of this path is not isolated experimentally.

The sharing boundary is deliberate. Downsampling, upsampling, and interface projections remain independent because they change tensor geometry and are inherently scale-dependent. Sharing is applied only to the expressive fixed-resolution computation. In the three-scale setup, the model stores K=4 core blocks and uses loop counts L=[1,2,4]. The encoder traverses scales from coarse to fine in one order, while the decoder uses the reverse order, so each branch stores only four blocks but executes 28 block applications. The paper also includes a non-adversarial Transformer ablation that keeps the execution graph fixed while varying the amount of sharing, which is important because it isolates the effect of sharing itself rather than conflating it with backbone differences.a:T63c,The experiments address three questions. First, how much sharing is acceptable? In a roughly 400k-step non-adversarial Transformer setup, the execution graph is held fixed while the number of stored core blocks varies from globally shared to partially shared to fully unshared. Global sharing gives the best PSNR and SSIM, while the fully unshared version gives the best LPIPS. That is a useful nuance: sharing favors pixel-level fidelity and structural consistency, but not necessarily perceptual quality.

Second, the main CNN result: on ImageNet-256, under an approximately 30-epoch two-stage training budget, the final 29M-parameter model reaches 0.28 rFID and 32.54 dB PSNR. The reference local Flux-style VAE uses about 84M parameters, so LoopVAE cuts parameter count by about 65.3% while remaining competitive in reconstruction quality.

Third, are the recurrent passes actually doing useful work, and what do they cost? The paper performs stage truncation and single-pass bypass interventions on trained models. Completing the trained loop schedule consistently improves reconstruction, and even relatively small intermediate feature changes can still produce meaningful output differences. So the repeated computation is not idle. At the same time, truncation results show that intermediate states are not automatically calibrated as an anytime decoder. On efficiency, the 8x-looped CNN stores 65.3% fewer parameters than the reference, but uses 1.57x estimated MACs and 2.85x batch latency. This is arguably the most important practical result: the method saves parameters, not runtime.b:T495,For a quick read, focus on three parts.
