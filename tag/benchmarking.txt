1. 通用 tracing。XPerf 支持对 LangChain、LangGraph 等常见 agent 框架做无侵入或低侵入埋点；对自建 agent 只需很少注释。它记录的不只是 LLM 请求本身，还包括工具调用及其时间信息。

2. 执行图重建。论文用基于 time-span tree 的分析方法，从 traces 中恢复 LLM call、tool call 及其依赖关系，得到 execution graph。这个设计比简单按时间顺序回放更合理，因为 agent 负载里存在并发、等待工具返回、条件分支等结构，只有显式依赖图才能保留真实调度约束。

3. 工作负载合成。作者没有把 benchmark 限定为“原样回放历史 trace”，而是允许在 execution graph 之上改变请求到达模式，构造 online serving、offline batch inference、fixed-concurrency 等不同场景。这一点很关键，因为系统研究需要控制 arrival process，才能比较调度器、batching、cache 策略在不同负载区间的行为。

4. 可复现回放。为保证 replay fidelity，XPerf 对每个 LLM call 提交记录下来的精确 input token IDs，而不是重新 tokenize 文本；这样可以保留 prefix cache 命中行为。必要时还可以强制 serving engine 解码记录过的 output tokens，避免因为模型输出偏移而改变后续控制流。回放时还遵守 execution graph 的依赖顺序，并把工具调用时长纳入时间轴，因此即便被测 serving engine 与 tracing 时不同，负载形态仍尽量贴近原始应用。

5. 细粒度 profiling。系统层面报告 KV cache usage、prefix cache hit rate、token throughput 等；硬件层面报告 GPU tensor core 利用率、memory bandwidth 利用率等。作者强调 profiler 开销很低，避免 benchmark 本身扭曲结果。

和已有工作相比，区别主要在两点：一是它不是只测独立请求，也不是只做 agent 任务完成率；二是它公开、可扩展，并且把“非确定性 agent 行为”通过 trace replay 固定下来，而不是接受 run-to-run variance 作为噪声。1c:T896,The method is a full pipeline: trace collection, execution-graph reconstruction, workload synthesis, deterministic replay, and low-overhead profiling.

1. Application-agnostic tracing. XPerf instruments popular agent frameworks such as LangChain and LangGraph with minimal friction, and supports lightweight annotations for custom agents. It records both LLM calls and tool calls, including timing information.

2. Execution-graph construction. Rather than replaying requests as a flat sequence, XPerf reconstructs dependencies among LLM calls and tool invocations using a time-span-tree-based analysis. This matters because agent workloads contain waiting, branching, and sometimes parallel structure. A dependency graph preserves the scheduling constraints that actually shape serving behavior.

3. Workload synthesis. XPerf does not stop at replaying historical traces. It can alter request arrival patterns over the reconstructed execution graphs to emulate online serving, offline batch inference, and fixed-concurrency settings. This makes the framework useful for controlled systems studies, where arrival processes must be varied independently of application logic.

4. Reproducible replay. For each LLM call, XPerf submits the exact recorded input token IDs, not just the raw text, so prefix-cache behavior is preserved. It can also force the serving engine to decode the recorded output tokens, preventing output drift from changing downstream control flow. Replay respects dependency order in the execution graph and accounts for tool-call durations, so the workload remains realistic even when the target serving engine differs from the one used during trace collection.

5. Fine-grained profiling. XPerf reports serving metrics such as KV-cache usage, prefix-cache hit rate, and token throughput, and hardware metrics such as tensor-core utilization and memory-bandwidth utilization. The profiler is designed to add negligible overhead.

Relative to prior work, the distinction is clear: it is neither an agent-quality benchmark nor a standard serving microbenchmark. Its central idea is to freeze the stochastic control flow of agent applications into a reproducible systems workload.1d:T5aa,The evaluation uses eight agentic applications spanning deep research, coding, Q&A, and general-purpose assistance. First, replay fidelity. XPerf achieves below 3% mean absolute percentage error in end-to-end request latency for both isolated and concurrent requests. That is the key validation result: if replay were not faithful, the rest of the benchmark would be hard to trust.

Second, workload variance in native agent runs. The paper quantifies how unstable agent execution can be without replay. Optimizations that look effective on standard chat-style benchmarks may behave differently once execution graphs become deeper and more irregular.1e:T581,BenchDrift constructs meaning-preserving benchmark variations and attributes every correctness flip to the specific transformation that caused it. The pipeline has four roles: a generator proposes rephrasings, a validator checks that the original ground-truth answer still holds, the target model answers the original and validated variants, and a judge scores the outputs. This separation is important because it isolates wording effects from genuine changes in problem semantics.

Variations are organized along four axes: linguistic, referential, pragmatic, and structural. The paper defines positive drift as a wrong-to-right flip and negative drift as a right-to-wrong flip. Both are measured over the same denominator, the original problem set size, which makes the two directions directly comparable and allows exact decomposition into reported accuracy, best-case accuracy, and worst-case accuracy. That is a stronger framing than standard robustness reporting because it captures both hidden capability and hidden brittleness.

Methodologically, the paper also includes two important controls: one to test whether rephrasings merely simplify the problems, and another to test whether drift only affects already uncertain examples. A single reported benchmark score is therefore only one point inside a wider interval defined by best-case and worst-case performance under meaning-preserving rephrasings.

This is a stronger design than prior work that only studies one ordering axis, because real multimodal systems inherit ordering from many sources: retrieval rank, chunk packing, image arrangement, and interleaving of text and visual evidence. The benchmark spans 12 datasets and four task families, aiming to cover both standard multiple-choice reasoning and multi-evidence aggregation settings.

ODI, or Ordering-Decomposed Item-Response Theory, is the statistical layer that separates different sources of answer flips. The authors argue that observed answer changes across permutations can come from true ordering bias, but also from decoder stochasticity or fragile decision boundaries. To disentangle these, they use a Bayesian 2PL IRT-style decomposition that estimates per-item ordering noise and per-facet systematic bias. A key design choice is the same-ordering control: the exact same input is decoded multiple times to estimate the stochastic floor, and only the excess flip rate under actual reordering is attributed to ordering effects. This control is essential; without it, raw flip rates are hard to interpret.
