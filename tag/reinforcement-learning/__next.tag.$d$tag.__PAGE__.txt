a:T476,Re$^3$Cap treats multimodal retrieval as a semantic constraint mechanism.
1) Image-to-dataset retrieval: given an image v, retrieve Top-K similar image-text pairs R_v from a paired corpus D using an image retrieval model.
2) CRS (Caption Refinement Suggester): extract semantic elements that consistently appear across the retrieved captions; these act as “must-preserve / should-include” anchors.
3) CQA (Caption Quality Assessor): use the generated caption as a query to retrieve another set R_c; discrepancies between R_v and R_c are interpreted as hallucinations (caption introduces content that shifts retrieval away from the image-based neighborhood) or omissions (missing details that prevent alignment).
4) RL training uses CRS+CQA outputs to guide caption refinement, encouraging generation of new candidates rather than merely scoring existing ones.
Key differences vs common RL captioning: it avoids relying on a single VLM/CLIP scalar judge, does not require extra keyword annotations, and aims to reduce reward hacking by grounding feedback in retrieval-set consistency—assuming the retrieval model and corpus are reliable.b:T451,DiDPO extends group-relative advantage from the trajectory level into the internal structure of a code diff.

Using a CodeAct-like interaction loop, each action yields an edit (add/del/none) and the environment provides an outcome reward (e.g., tests pass/fail). Instead of treating the whole response/diff as one credit carrier, DiDPO:
1) Aligns diffs across multiple rollouts for the same task by finding highly similar sub-diffs that recur across trajectories.
2) Uses these recurring sub-diffs as anchors to induce sub-diff boundaries within larger diffs, aiming to isolate functional regions.
3) Groups aligned sub-diffs and computes a local group-relative advantage (diff-level advantage), then combines it with the trajectory-level advantage and assigns it back to the tokens responsible for generating those sub-diffs.

To avoid anchors that are too broad (mixing functions) or too narrow (hard to aggregate), it introduces a groupability score to select anchors that balance semantic scope and group mass. The method remains critic-free and claims no additional rollouts beyond the sampled group.c:T41a,TRIAL keeps the GRPO rollout-level advantage and clipping rule unchanged, then adds a training-only hindsight objective. For each decision turn, it builds an outcome view that exposes the realized local consequence of that decision. The same generated response is scored under the ordinary interaction context and under the hindsight-conditioned context. The signed token-level log-probability gap determines update direction and local revision strength. TRIAL then aggregates absolute gaps within each turn and compares a turn’s share of total revision magnitude with its share of eligible tokens. This yields a trajectory-relative allocation multiplier. The multipliers are normalized so their eligible-token-weighted mean is one, which redistributes hindsight supervision while keeping the average allocation fixed. A scalar clamp bounds the dense loss contribution relative to the detached GRPO loss magnitude. It uses a generative reward model only for relative preference ranking, then derives scalar rewards from the resulting order. The first mechanism is self-competitive ranking: for a given prompt, multiple responses sampled from the current policy are compared against each other, and their relative order is mapped into rewards. This aligns naturally with group-relative policy optimization. The second mechanism is anchor-guided ranking: a small set of anchor responses serves as reference points, and candidate responses are compared against these anchors. This reduces the reward-model call pattern for larger candidate sets from a sorting-style O(m log m) regime to O(m n), where m is the number of sampled responses and n is the number of anchors. When n is small, this is more scalable. Unlike GenRM-style preference-token probabilities, RRC does not rely on a single token probability.
