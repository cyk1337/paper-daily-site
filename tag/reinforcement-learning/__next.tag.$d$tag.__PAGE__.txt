9:T412,TRACER uses a two-stage training recipe. First, supervised fine-tuning on real user dialogues teaches the model to generate user responses and to emit structured annotations: a rationale and an ordinal intent score. The intent score acts as an interpretable proxy for the user’s evolving commitment or engagement state. Second, the simulator is trained with multi-turn reinforcement learning while interacting with a fixed assistant. Rewards combine terminal outcome agreement and trajectory alignment against paired human logs. Dynamic time warping is used to align trajectories with different lengths and conversational pacing. A deviation-aware advantage modulation mechanism then uses local alignment errors, accumulated over discounted trajectory suffixes, to scale turn-level policy updates while preserving the direction of the session-level advantage. Compared with static persona prompting, the method optimizes state evolution; compared with standard turn-level optimization, it assigns credit using the whole dialogue trajectory.a:T4f9,The work has two parts. They keep the original iterative concept-generation procedure and prompts, but change the answer-generator sampling parameters. With temperature 1.0, top-p 0.95, and top-k disabled, concept guidance no longer improves over repeated sampling on MATH500.

The second part turns concept generation into a learned search policy. Instead of generating concepts one by one, the model emits many detailed, problem-specific concepts in a single autoregressive trajectory. These concepts are then used to condition the frozen answer generator, with the answer budget allocated across them. The concept generator is trained with reinforcement learning: the sampled concept trajectory is the action, and the reward is the downstream success of the answer generator. In the main setup, a Qwen2.5-7B concept generator is trained to steer a frozen Qwen2.5-32B answer generator. The goal is not just to make the model say less, but to make it reason in a different external format. DRT separates reasoning into two explicit channels: <visual> stores observed evidence from the image, while <think> stores compact logical derivations. Symbolic connectors and concise state transitions replace long natural-language sentences. This serves two purposes: reducing linguistic redundancy and disentangling observation from deduction so that assumptions are less likely to be written as if they were visual facts.

Training has two stages. The first is Dense Trace Initialization. High-quality multimodal instruction data are rewritten into the DRT format to create a DRT-SFT dataset, and supervised fine-tuning is used to internalize this reasoning mode. The key role of this stage is format adaptation rather than knowledge acquisition: the model learns to organize intermediate states in a compact structured space.

The second stage is Trace-Grounded Reinforcement Learning. The authors build a DRT-RL dataset using a tri-perspective verification pipeline, keeping only traces that satisfy three conditions simultaneously: correct final answer, logically consistent intermediate steps, and faithful visual grounding. They then optimize the model with a trace-grounded GRPO objective, augmented with process-based rewards and exploratory incentives. In effect, the policy is rewarded not only for being correct, but also for producing short, logically coherent, and visually grounded traces.

Compared with prior efficiency methods, this is not early stopping, token selection, or budget prediction within the same natural-language CoT space. It changes the reasoning expression space itself. Compared with standard CoT SFT/RL, it places much stronger emphasis on disentangling observation from deduction and on verifying grounding quality of intermediate traces.e:T6a4,The model is evaluated on five challenging multimodal reasoning benchmarks, including text tasks and out-of-distribution video tasks. That is the main empirical claim: shorter traces do not merely save tokens at the cost of quality; the structured format can improve the efficiency–accuracy tradeoff.

The paper also emphasizes component ablations rather than only final benchmark numbers. Dense Trace Initialization appears to be necessary for moving the model into the new reasoning format; without it, simply asking for concise reasoning would not reliably produce high-density traces. Trace-Grounded RL further improves faithfulness, especially under tight token budgets, where models otherwise tend to sacrifice logical completeness or grounding for brevity. The tri-perspective verification pipeline is important because it raises the quality of RL reference traces and filters out trajectories that are answer-correct but process-poor, or process-plausible but visually ungrounded.

The only task-specific input is a source repository. It does not consume issues, PRs, or human-written specs. First, the system identifies candidate functionality by inspecting repository structure, build metadata, and public entry points. It prioritizes functionality with observable behavior and nontrivial codebase context, including CLI tools, pure library functions, and stateful APIs. The selection criterion is important: the target should admit a behavioral specification while leaving implementation freedom open.

Second, the repository is adapted into a development starting point. The target implementation is removed or blanked out, while the rest of the project structure, dependencies, and surrounding context are preserved. This makes the task closer to real software work than isolated function completion.

Third, CodeMidas constructs tests grounded in execution of the original code. It runs the original implementation and uses observable outputs, return values, state transitions, file effects, and CLI behavior to infer expected behavior. The design goal is behavioral verification rather than implementation matching. The verifier should reject wrong solutions but still accept alternative correct implementations, so the pipeline tries to avoid overfitting tests to the original code path.

Fourth, the environment is checked for execution consistency. The original implementation must pass; the stripped starting point must not pass trivially; the containerized dependencies and grading flow must be stable. This is a data validity gate more than a modeling contribution, but it is essential for RL.

Fifth, and most interestingly, the paper adds rollout-based filtering. Candidate environments are probed with agent rollouts before RL training. The pipeline uses adversarial rollouts to detect leakage and exploitability, solution reviews to assess whether verifier outcomes align with the stated requirements, and rollout success rates to remove tasks that are too noisy, too easy, too hard, or reward-misaligned. This is a strong design choice: task quality is defined not only statically, but through interaction with actual agent behavior.

The final dataset contains 5,545 verifiable tasks from 3,185 open-source repositories, spanning 23 programming languages and 15 technical domains. RL is then run with GRPO on MiMo-V2.5.
