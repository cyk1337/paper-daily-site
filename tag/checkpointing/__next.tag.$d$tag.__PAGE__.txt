9:T491,The design relies on two observations. First, in 3D parallel training, model shards and optimizer shards have different recoverability properties. Model parameters are often replicated across data-parallel peers and can be reconstructed from healthy ranks with the same logical partition. Sharded optimizer states, including first and second moments, are distributed within a data-parallel rank and may be lost when a node fails permanently. DeadPool therefore replicates optimizer-state shards to neighboring nodes in memory at every iteration, using asynchronous communication overlapped with compute to keep the backup off the critical path. Second, recovery is handled as a topology-repair problem. A spare node replaces the failed node, communication groups are reconstructed at runtime, and training resumes without terminating the whole job. The system also classifies failures so that topology-changing recovery is only used when node membership is truly invalidated.
