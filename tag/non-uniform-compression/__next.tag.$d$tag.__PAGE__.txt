b:T8eb,Tangram 的技术路线围绕一个关键观察展开：不同 attention head 需要保留多少历史 token，这种 retention pattern 在同一模型内是相对稳定、可预先估计的，而不是每个请求都剧烈变化。基于这个观察，作者把原本需要在线决定的异构 KV 管理，改写成一个尽量静态、可预编排的问题。

第一部分是 Deterministic Budget Allocation。传统非均匀压缩如果按请求动态回收 KV，会产生大量控制面开销，因为系统要跟踪每个 head、每个 page 的占用与释放。Tangram 直接为各 head 预分配确定性的 retention budget，把动态 reclaim 变成静态 footprint 规划。这样做的好处是把复杂的在线内存管理前移，减少 runtime bookkeeping。代价是灵活性下降，但作者的前提是 head-wise pattern 足够稳定，因此这个取舍成立。

第二部分是 Head Group Page。现有 paged KV 设计通常以统一 page 结构管理所有 heads，适合均匀长度，不适合异构长度，因为某些 head 压缩后释放不出完整 page，形成严重内部碎片。Tangram 将具有相近 budget 的 heads 分组，给每组建立独立 page table。这样 page 的物理回收粒度更贴近真实保留长度，能显著减少 fragmentation。为了避免 page table 操作本身成为 CPU 瓶颈，作者还实现了 vectorized block table，用 CPU SIMD 并行处理映射与查表。

第三部分是 Ahead-of-Time Load Balancing。非均匀 KV 长度会让不同 head 或不同块的 attention 计算量差异很大，若仍按常规方式分配给 GPU SM，会出现 straggler，拖低 kernel 利用率。Tangram 利用预算分布是静态已知这一点，离线预计算 workload 切分方案，把负载均衡从 runtime planner 挪到 ahead-of-time 阶段。这样 kernel 执行时不需要再做复杂调度，能更稳定地维持 SM 利用率。

从方法性质看，这不是单点优化，而是一个围绕“静态化异构结构”的系统级重构：先把 head-wise retention 视为模型固有属性，再据此重写内存分配、页组织和 kernel 调度。它和单纯改 attention kernel 或单纯改压缩策略不同，重点在于把算法侧的异构性转成系统侧可利用的确定性结构。c:T8ca,The entire design is built on one observation: the retention budget needed by each attention head is relatively stable for a given model. Tangram uses that stability to turn an online heterogeneous-memory problem into a mostly static planning problem.

The first component is Deterministic Budget Allocation. A naive non-uniform KV system would reclaim memory dynamically as requests evolve, but that creates substantial control-plane overhead because the runtime must track and recover scattered pages for many heads. Tangram instead assigns deterministic per-head budgets ahead of time, converting dynamic reclamation into a preplanned memory footprint. The gain is lower runtime bookkeeping and simpler scheduling. The trade-off is reduced flexibility, but the paper argues that the head-wise pattern is stable enough that this is acceptable.

The second component is Head Group Page. Existing paged-KV designs use a monolithic page structure that works well when all heads have the same cache length. Under heterogeneous retention, that design causes severe internal fragmentation because compressed heads cannot reclaim memory cleanly at the right granularity. Tangram groups heads with similar budgets and gives each group its own page table. This makes physical memory reclamation better aligned with actual retention lengths. To keep page-table operations from becoming a CPU bottleneck, the system also introduces a vectorized block table implemented with CPU SIMD parallelism.

The third component is Ahead-of-Time Load Balancing. Non-uniform KV lengths create large differences in attention workload across heads and blocks. If the runtime uses standard scheduling, some GPU SMs become stragglers while others idle. Since the cache shape is known in advance from the deterministic budgets, Tangram moves load balancing offline and precomputes a workload distribution plan. This avoids runtime planning latency and improves kernel utilization under heterogeneous cache layouts.

What matters here is the overall design philosophy. Tangram does not optimize a single kernel in isolation. It treats head-wise heterogeneity as a predictable structural property and then co-designs memory management, paging, and execution around that property.d:T68f,The headline result is up to 2.6x end-to-end throughput improvement in multi-turn serving. That number matters because it is presented as a system-level outcome rather than a narrow kernel microbenchmark.

The evaluation is organized around the three bottlenecks identified earlier:
1. Memory efficiency: the paper compares how much GPU memory can actually be reclaimed under non-uniform compression, with a focus on the gap between theoretical compression and realized savings once fragmentation is accounted for.
2. Runtime overhead: it contrasts dynamic reclamation against deterministic budget allocation, showing that online management of scattered pages can become a major control-plane cost.
3. GPU utilization: it studies SM imbalance under heterogeneous KV lengths and measures how much Ahead-of-Time load balancing reduces stragglers and improves sustained throughput.

The experiments are centered on multi-turn dialogue serving, where KV cache growth is linear in the number of turns. The important question is not just whether compression reduces cache size on paper, but whether the system can maintain throughput as the conversation grows. Tangram is evaluated in the context of modern serving stacks rather than as a disconnected prototype, which makes the results more relevant.

From a research perspective, the most useful aspect of the experimental section is the separation between algorithmic savings and systems realization. The paper is effectively asking: once a compression method says it saved tokens, how much of that saving survives contact with memory layout, scheduling, and kernels?
