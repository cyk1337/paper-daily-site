9:T75e,The benchmark construction pipeline is graph-based and deliberately audit-friendly. The corpus is first partitioned by a quality classifier into D_high and D_low. Instead of mining the retained high-quality pool, the authors search D_low for low-exposure facts that are more likely to reveal parametric memory limits. Documents in D_low become nodes in a graph. Support edges connect documents about the same specific fact, while conflict edges connect documents that give incompatible accounts for the same subject-attribute pair.

A naive all-pairs comparison would be quadratic, so the paper uses a two-stage narrowing strategy. First, an LLM assigns each document a knowledge-point label, and candidate comparisons are restricted within those clusters. Second, entity-based retrieval further reduces the candidate set. Only then are LLM judgments used to verify support and conflict relations. This is an important design choice: the LLM is used offline to structure the corpus and identify disagreements, not to provide evidence at evaluation time.

Verified conflict edges seed subgraph sampling and QA synthesis. Each question is paired with an answer set containing at least two verified accounts, and every answer must remain traceable to source documents, externally checked against authoritative public sources, and reviewed by human annotators. The evaluation is closed-book: no retrieval, no source passages, no tools.

The metric design is also central. The paper separates fact recall from account completeness. A model may recover one account and therefore show some memory of the fact, yet still fail the completeness criterion by omitting the alternative verified account. The authors then use the number of supporting documents on each side of a disagreement as an exposure proxy, which allows them to analyze how corpus prevalence relates to these two failure modes.a:T58e,ElephantBench contains 1,094 closed-book questions mined from naturally occurring disagreements in a low-exposure web corpus. Each item is source-traceable, externally verified, and human-reviewed. The evaluation covers 32 models. The headline result is that even the strongest model recovers both accounts on only 52.4% of questions. On nearly all of the remaining cases, the model does not fail by total ignorance; instead, it recalls one verified account while omitting the other. That makes incompleteness, not pure forgetting, the dominant error mode.

The most informative analysis is the exposure asymmetry study. By counting how many documents support each side of a disagreement, the paper approximates relative corpus exposure. The more prevalent account is more predictive of whether the model recalls the fact at all. The less prevalent account is more predictive of whether the model recalls the full set of verified accounts. This is a clean empirical link between corpus imbalance and partial memory retention.

The paper also argues for construction efficiency. Knowledge-point clustering and entity-based retrieval reduce the need for exhaustive pairwise LLM judging. The excerpt provided here does not include the full cost table, but the design goal is clear: make the pipeline reusable for turning any low-exposure corpus into a memory probe rather than building a one-off benchmark by manual curation.b:T47b,Start with the introduction and benchmark positioning. After that, focus on the metric definitions and the exposure analysis.
