18:T6a1,The method has three stages.
First is autoformalization. Natural-language policy statements are translated into a symbolic representation, using first-order logic or Boolean constraints that are expressive enough to support formal reasoning over obligations, permissions, prohibitions, and eligibility conditions. The goal is not maximal logical sophistication, but a stable and checkable representation that can be enumerated.
Second, the formalized rules are converted into decision trees. Branches correspond to truth assignments over atomic facts, and each path incrementally specifies a scenario. If a path is sufficient to entail the target verdict, it becomes a determined-verdict benchmark item. If the path stops before the verdict is entailed, it becomes an abstention item. This is an important design choice: it separates false from underdetermined, rather than collapsing everything into a simple entailment-versus-non-entailment setup.
Third, benchmark generation is parameterized. The system can control path depth, diversity, and target verdict types, allowing a single policy document to produce combinatorially many benchmark instances. Labels come from symbolic deduction rather than manual annotation, which is the main reason the pipeline scales while preserving correctness.
The design choice is sensible. Why formalize first instead of asking an LLM to paraphrase policies and another LLM to write questions? Because free-form generation makes label reliability fragile, especially when policies contain exceptions, interacting clauses, or missing conditions. DeoGen trades some linguistic naturalness for a much stronger guarantee on logical consistency and label validity.19:T532,DeoGen is run on four policy sources: sections of the U.S. IRS tax code, an insurance cafeteria plan, a code of coverage, and a faculty hiring handbook. From these, the system generates 451,047 benchmark entries. For evaluation, the authors sample 1,639 items and test frontier models including Claude Sonnet 5 and GPT-5.5, along with open models such as Qwen3.6 and Gemma 4.
The main results split cleanly into two regimes. When the facts determine a verdict, model correctness ranges from 75.1% to 92.5%. That is decent but far from solved, especially for regulated workflows. When the facts are insufficient and the correct behavior is to abstain, performance drops sharply to 4.0%–40.0%. This gap is the central empirical result of the paper. It suggests the main weakness is not only rule application, but failure to withhold judgment under logical underdetermination.
A second important result is the generation scale itself: four policy documents yield more than 450k benchmark items, which supports the claim that formalize-then-enumerate is a practical route to scalable deontic evaluation. If the full paper includes breakdowns by policy type, path depth, or verdict class, those are the tables worth reading, because they can help separate failures due to long rule chains, exceptions, or generic non-abstention bias.1a:T5d3,TURTLE is a three-agent evolutionary pipeline:
- Task representation: tool-use tasks are encoded as Python programs (environment state, databases, tools, goals). This makes compositional mutation feasible and preserves compatibility with existing harnesses, but introduces risks of format/underspecification artifacts.
- Proposer: implemented via AlphaEvolve, a gradient-free evolutionary search operator. A practical point is that it can leverage strong closed-source LLMs as proposers via API calls, since no gradients/weights are needed.
- Solver: the target model under evaluation; each candidate mutated task is attempted N times to estimate an empirical completion rate.
- Fitness shaping: reward targets “hard but solvable” by pushing completion rates toward ~50%, motivated by maximal variance / maximal discriminative power near 0.5 (akin to learnability sampling).
- Feedback generator: summarizes failure reasons from execution traces plus the ground-truth solution, producing exploitable signals for the proposer’s next mutations.
- Post-filtering: an LLM judge (Gemini 3.6 Flash) removes trivial failures (format mismatches, ambiguous instructions, near-paraphrases), which is crucial to prevent evolution from exploiting loopholes.
