从当前给出的正文片段看，底座是 Qwen3-0.6B 几何配置。若全文有 perplexity 或 downstream LM 指标，阅读时要重点看 BF1 retrofit 后相对 dense-continued-training 的差距是否稳定很小，以及这种差距是否随上下文长度扩大。如果长上下文收益建立在明显牺牲短上下文 LM 质量之上，那方法的适用面会窄很多。a:T723,BF1 is a deterministic, block-aligned causal sparse-attention pattern. The sequence is partitioned into blocks of width b, with the reported public configuration using b = 64. For a query block j, the route includes four components: the causal self block, two exact local predecessor blocks, the first global block, and historical predecessor blocks at dyadic distances, i.e. j - 2^r starting from an offset of four blocks. In short, it is local + global-first + dyadic history.

The paper is explicit that this route is related to earlier log-sparse and dilated designs such as LogSparse Transformer and LongNet. The claimed novelty lies elsewhere: pretrained-model retrofit, matched topology-control experiments, and correctness-gated Blackwell measurements. The correctness-gated part is important. The authors do not only benchmark a fast path; they verify partial blocks, backward gradients, dense-path equivalence, future-token isolation, and opposite-order benchmarks up to 32K, which makes the systems claims more credible.

With fixed block width, each converted layer uses O(n log n) selected token interactions and has O(log n) graph communication depth. The communication-depth argument is the structural reason BF1 should beat pure local sliding windows: long-range information can propagate in logarithmically many sparse hops rather than linearly many local layers. Compared with static random nonlocal graphs, BF1 is deterministic and easier to optimize at the kernel level.

Another sensible design choice is that the paper does not replace all attention layers in the model and call it done. It reports an actual eight-layer retrofit separately from an all-layer timing-only ceiling. That makes the results more realistic for pretrained models, where replacing every layer with a sparse operator can be risky.b:T74e,The strongest evidence is on the systems side. On an NVIDIA RTX PRO 6000 Blackwell GPU, the optimized BF16 implementation reportedly crosses dense attention around 4K context length. At 32K, the per-layer attention operator reaches 10.91× speedup. More importantly, the actual eight-layer retrofit reduces warm whole-model TTFT by 15.3% at 32K. That number is much smaller than the per-layer speedup, but it is also much more informative because it includes the rest of the model and runtime overheads.

For language modeling, the paper runs three matched Stage A training comparisons: dense continued training, equal-pair-count local sliding, and equal-pair-count static-random nonlocal graphs. BF1 ranks first in all three matched runs. The key point is not the ranking alone. The controls are designed to keep the sparse budget comparable, so the advantage is more plausibly due to topology rather than simply attending to more pairs. In other words, the paper tries to answer whether a dyadic-plus-first-block graph is a better sparse inductive bias for next-token LM than local-only or random sparse graphs under similar budget.

The decode analysis is also useful. The paper reports selected-page decode semantics and argues that, at low batch, the dominant unresolved cost is planning lifecycle rather than selected-page attention arithmetic. That observation explains why sparse decode methods often look strong in operator benchmarks but deliver limited gains in real serving stacks.

That sampled trajectory is then scored token by token by the teacher, and the student is updated to reduce the discrepancy on the sampled tokens. Compared with sequence-level RL, this gives denser token-level supervision while preserving the on-policy nature. OPD2 changes the reward definition: instead of using log p_teacher minus log p_student, it uses log p_teacher minus log p_teacher_base. The motivation is to isolate capabilities acquired during post-training, especially reasoning, while suppressing generic language preferences and stylistic biases already present in the teacher’s base model. The technical center of the paper is not a new merge rule but a geometric diagnosis of why merge method barely matters here. Because all specialists adapt the same LoRA target modules, their task vectors have overlapping support by construction. This rules out the trivial explanation that they simply modify disjoint parameters. The authors therefore measure directional geometry, especially cosine similarity between task vectors, and calibrate the measurement with floor and ceiling references so that small cosine values cannot be dismissed as a low-rank LoRA artifact. The key finding is that the specialists’ task vectors are nearly orthogonal, with cosine around 0.06–0.10, despite large support overlap. If the conflicting shared component is already tiny, then support-aware or sign-aware merge rules have little left to disentangle.

A notable implementation detail is that, although the paper frames training in terms of LOOP, the actual compute-constrained regime is on-policy with one update per rollout batch and no rollout reuse. In effect, this reduces to RLOO / REINFORCE with a leave-one-out baseline rather than a stronger PPO-style off-policy variant. In other words, at 8B scale, with roughly 10 RL iterations and only a 1–2 difficulty margin between task groups, the merge-vs-joint differences sit below the noise floor.

The geometry analysis provides the explanation. The specialists’ task vectors have cosine similarity around 0.06–0.10, i.e. close to orthogonal, and the paper argues that this is not an artifact of low-rank LoRA. At the same time, support overlap is large because the same modules are adapted. So the vectors overlap in where they act, but not much in the directions they push.

1) General SFT to obtain a shared initialization.
2) Domain-specialized RL in parallel, producing a set of frozen domain teachers (math via verifiable RL, SWE via executable sandbox agent RL, etc.).
3) On-policy distillation fusion: initialize the student from the SFT checkpoint; for each batch of prompts, the student generates its own trajectories (on-policy rollouts). Each trajectory is routed to the corresponding domain teacher, which runs a prefill on that exact trajectory to produce per-token distributions. The student is updated by minimizing per-token reverse KL (student || teacher) along the trajectory.
Key properties:
- On-policy training eliminates exposure bias by matching train-time and inference-time state distributions.
- Token-level distribution matching provides a dense, low-variance learning signal compared to trajectory-level rewards.
- Integration happens in policy space via prompt-to-teacher routing, avoiding weight-space arithmetic/averaging instabilities.
