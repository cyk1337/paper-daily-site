During RL, every rollout gets a unique session ID, which enforces session-scoped state isolation. This is more important than the raw tool count: without per-rollout isolation, state contamination across episodes would corrupt both reward and learning. The environments cover domains such as finance, productivity, commerce, travel, IoT, developer tools, and knowledge management. Their defining property is statefulness: balances change, events persist, files accumulate edits, and so on. Compared with cached APIs, live execution exposes realistic failures such as insufficient balance, expired coupons, missing entities, or unmet prerequisites.

Second, grounded state-machine data synthesis. Instead of prompting an LLM to invent tasks from scratch, the pipeline first probes each live server to sample real entities and current state. Query generation is then grounded in those sampled entities, and a state-machine teacher generates multi-turn conversations following tool dependency graphs. Every generated trace is replayed and validated. This matters for two reasons: the queries refer to entities that actually exist in the environment, and the final trajectories are execution-valid rather than merely plausible in text form. The synthesized set includes not only standard multi-step tool-use traces, but also clarification turns for missing information and abstention cases where no tool should be used.

Third, a fully programmatic multi-component reward. The reward decomposes tool-use quality into five parts: tool-call validity, dependency-ordered coverage, an adaptive efficiency penalty with a complexity-scaled call budget, a tool-name signal, and an argument-value matching bonus. The design choice that matters most is that coverage is not enough; the model must cover the right calls in the right dependency order. The adaptive efficiency term is also important: instead of penalizing all extra calls equally, the budget scales with task complexity, which avoids over-penalizing genuinely complex tasks. The tool-name signal gives direct supervision on tool selection, while argument-value matching rewards correct parameter filling. The ablation identifies the adaptive budget and tool-name signal as the most critical components, suggesting that verbosity and wrong tool choice are the main distortions induced by naive RL rewards.

Training is implemented in VERL, with model-generated tool calls routed to the MCP servers and rewards computed from execution outcomes.
