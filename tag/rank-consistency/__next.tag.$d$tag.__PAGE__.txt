9:T4aa,The pipeline has three stages. First, ZipBench evaluates a small set of anchor LLMs on the full benchmark; the paper uses six anchors with separated accuracies. Per-item outcomes are represented as binary responses, with continuous metrics such as F1 discretized before compression. Second, it expands the anchor pool without running more models. It enumerates subsets of the real anchors, treats each subset as a virtual LLM, and defines the virtual response on each item by majority vote. These pseudo logs are accepted through an accuracy-bucket rejection scheme: if a virtual LLM falls into an empty accuracy bucket, it is kept. This makes the anchor pool more uniformly spread over the observed accuracy range, which reduces bias from having anchors only at a few capability levels. Third, ZipBench learns low-dimensional fingerprints for models and items from the augmented response matrix, then selects representative samples through clustering or representative-point selection.
