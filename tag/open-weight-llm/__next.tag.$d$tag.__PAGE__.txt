9:T679,The system is built as a five-stage adaptation pipeline. The base is Italia 10B, a from-scratch dense decoder-only Transformer trained on about 9T tokens across 50+ languages, with a native 16K context. Architecturally it is fairly standard for its size: 40 layers, hidden size 4096, GQA with 48 query heads and 8 KV heads, RoPE, squared ReLU MLPs, no dropout, and untied embeddings. Stage 1 is continued pretraining to extend the native context from 16,384 to 32,768 tokens, with the RoPE base reset to 500,000 at that boundary. This is not just positional extrapolation; it is meant to let the model adapt its attention behavior under a new length distribution. At inference time, YaRN is then used to stretch the context further to 131,072 tokens. Stage 2 is large-scale SFT on a 12.3B-token instruction mixture, followed by a short math-focused annealing run before RL. That annealing step is important: it narrows the policy toward verifiable reasoning before entering a higher-variance RL phase. Stage 3 applies GRPO with verifiable rewards, initially on math. Stage 4 inserts DPO under what the paper calls the Delta Learning Hypothesis, suggesting DPO is used as a preference-boundary correction step rather than as a replacement for RL. Stage 5 runs multi-environment GRPO over five domains: mathematics, code, multiple-choice QA, instruction following, and tool calling. The intent is to avoid over-specializing the policy to a single reward shape. The model is also exposed in dual inference modes, thinking on and thinking off, indicating that the chat template and decoding interface were designed with explicit reasoning-token control in mind.a:T4dd,The empirical section is relatively restrained, which makes it more useful. The headline result is not absolute accuracy leadership but an accuracy-efficiency balance: on reasoning benchmarks, Domyn-Small reportedly uses about one-third as many output tokens per problem as Qwen3.5-9B on average, which matters directly for serving cost. That explanation is plausible and also useful, because it prevents over-reading post-training gains as if they were unconstrained. On context length, the setup is also informative: 32K native context after CPT, then 128K-class inference via YaRN.
