Open-MOPD: Diagnosing and Fixing Capability Imbalance in Multi-Teacher On-Policy Distillation

这篇工作处理的不是“怎么把多个 teacher 接到一个 student 上”这么宽泛的问题，而是更具体的：在 multi-teacher on-policy distillation 里，即便路由完全正确，student 也常常学不会把多个 RL 专家的能力稳定整合起来。作者把这个现象定义为 capability integration gap，并用一个可控设定把它从路由误差里剥离出来：同一个 3B student，三类 domain teacher（math、code、instruction following），oracle routing，统一评测。全文最重要的发现是，瓶颈不主要来自常见直觉里的梯度冲突，而来自 token 级优化预算在不同 domain 之间被系统性扭曲。M-OPD 的损失按 token 聚合，真正决定谁被优化得更多的不是 prompt 数，而是 gradient token volume。短回答任务，尤其 instruction following，虽然 prompt 占比不低，但因为输出短、奖励衰减快、rollout reuse 带来 stale reward，最终几乎拿不到有效更新，导致能力整合明显失衡。

评应优先看诊断实验；“不是梯度冲突而是 token 预算错配”会改变多教师蒸馏的排查顺序。
Huan-ang Gao,Haohan Chi,Yong Yan,Shiyuan Feng,Hanlin Wu,Zheng Jiang,Bingxiang He,Wei-Ying Ma,Ya-Qin Zhang,Hao Zhou

The Effect of Training Task Diversity on In-Context Learning through the Lens of Low-Dimensional Subspaces

这篇工作研究的是：训练阶段的“任务多样性”为什么会改变 in-context learning 的学习速度和泛化边界，尤其是为什么多任务混合训练会缩短常见的 loss plateau，并在一定条件下带来更好的 OOD 泛化。它不是再做一个经验观察，而是试图给出一个可分析、可统一的数学定义。作者把训练任务分布建模成若干高斯成分的混合，每个成分对应一个低维子空间，不同成分之间共享一部分公共子空间。这样，“任务多样性”不再只是任务数变多，而是变成：模型在多个相关但不完全相同的低维结构上共同训练。核心问题因此被落到一个更具体的机制上：共享子空间提供可复用结构，私有子空间提供覆盖范围，二者如何共同决定训练动力学与泛化。

评不是直接改 recipe 的论文，但如果你在想 data mixture 为什么会改变 ICL emergence，这篇的子空间定义比“任务数越多越好”干净得多，重点看理论设定和对应实验。
Soo Min Kwon,Alec S. Xu,Can Yaras,Dogyoon Song,Laura Balzano,Qing Qu
