LiteTopK: Exploiting the Curse of Dimensionality for a Fused Indexer-TopK Kernel in Long-Context Sparse Attention

这篇工作处理的是长上下文稀疏注意力里的一个很具体但很卡脖子的内核问题：Indexer-TopK。它既要算 query 对大量候选 key 的相关性分数，又要做逐行 top-k 选择。现有 GPU 实现通常把“算分”和“选 top-k”拆成两步，先把完整 score matrix 写回 HBM，再做选择。这样做在 1M 级上下文下会同时带来三类代价：显存占用高、HBM 读写流量大、同步和选择开销重。论文指出，在 DeepSeek Sparse Attention 这类系统里，这个内核已经不是次要细节，而是 prefill 的主瓶颈；文中给出的例子是 GLM-5.2 在 1M context 下，DSA kernel 占到 prefill 总时长的 83.7%。
