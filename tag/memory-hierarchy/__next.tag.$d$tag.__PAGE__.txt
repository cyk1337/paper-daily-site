9:T54a,The system has four main components. 1) Architecture-aware KV sizing. The paper derives unified per-token, per-layer KV memory formulas for MHA, GQA, MQA, and MLA. The key point is MLA: its cache footprint is determined by latent-state dimensions plus a separately stored RoPE component, not by the standard KV-head-count times head-dimension formula. Using an MHA-equivalent budget for MLA can therefore massively overestimate memory. 2) A six-tier memory hierarchy. KV blocks can reside across GPU HBM, CPU DRAM, CXL-attached memory, NVMe with GPUDirect Storage, RDMA fabric, and parallel filesystems. This is not simple offloading; placement is tied to latency and bandwidth characteristics, with KV blocks treated as migratable objects. 3) Bayesian reuse prediction. Reuse is modeled with Beta-conjugate priors over 16 (block-type, transition-type) pairs. The motivation is that different block classes have different future-access probabilities, so eviction should depend on predicted reuse rather than recency alone. 4) Head-granular eviction and RoPE-aware prefetch. Instead of evicting whole blocks uniformly, the system tracks per-head importance with EMA-style scores and uses RoPE-induced sequential locality to prefetch likely-needed content. The broader idea is that cache value is heterogeneous even within the same token/block granularity.a:T67e,The method is Temporal-Tiered KV Cache, or TTKV. It has three components. First, Tier Layout: KV cache is split into a fast tier in HBM and a slow tier in DRAM, corresponding to short-term and long-term memory. The design assumption is that recent tokens are more latency-sensitive and should remain in high-bandwidth, high-precision storage. Second, Tier Content: different temporal regions of the cache are stored with different fidelity. Recent and frequently accessed tokens stay in full precision, while older tokens moved to the slow tier are further compressed using differential quantization and sparsification. The key point is that time is the organizing principle for both storage placement and compression budget. Third, Tier Interaction: to avoid decode-time stalls from DRAM access, the paper uses streaming attention so that transfer from the slow tier overlaps with computation. Instead of fetching all remote KV first and then computing attention, the system pipelines communication and computation to hide PCIe costs.

Relative to methods such as KIVI, KVQuant, and DiffKV, TTKV is not just a standalone quantization scheme. Relative to ShadowKV-style offloading, it is not only an access-pattern optimization. Its main distinction is that it jointly decides which tokens deserve low latency and which tokens deserve high precision. The underlying empirical claim is that recent tokens form the active working set, while only a small subset of distant tokens remains highly relevant. That assumption is often reasonable in long-context generation, though tasks requiring exact long-range copying or retrieval may stress the design more heavily.b:T4e3,The evaluation spans LLaMA-3.1-8B, Qwen2.5-32B, DeepSeek-R1-14B, and LLaMA-3.1-70B, which suggests the authors are aiming for model-family robustness rather than a single-model result. The main setting is long-context inference, especially 128K context. Against KIVI, KVQuant, DiffKV, and ShadowKV, TTKV reportedly reduces cross-tier traffic by up to 5.94x on 128K tasks, leading to as much as 76% lower latency and around 2x higher throughput while preserving accuracy.

The most important point is not the best single number, but the full causal chain: less slow-tier traffic, better overlap of the remaining traffic with compute, and then lower decode latency and higher throughput. The paper also emphasizes accuracy preservation, so this is not just a systems benchmark with quality ignored.
