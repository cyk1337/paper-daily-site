The authors decompose the path from native reasoning to full tool-augmented reasoning into measurable components.

The primary chain is NoTool-CoT -> NoTool-FCStyle -> Agent-NoopTool -> Agent-Full.

NoTool-CoT is the standard chain-of-thought baseline. NoTool-FCStyle changes only the prompt format into a function-calling style without granting tool access, isolating the style cost introduced by schema, role constraints, and output formatting. Agent-NoopTool then adds the full tool-calling protocol but replaces actual tool outputs with a no-op stub, estimating the protocol overhead before any useful external computation happens. Agent-Full restores real tool execution and measures the net gain from actual tool logic.

This yields three central quantities: Delta_sty for formatting cost, Delta_frc for function-calling protocol overhead, and Delta_cmp for the gain from real computation or tool execution. Instead of treating the CoT-versus-agent gap as a single black-box number, the framework asks how much performance is first lost and how much is later recovered.

The paper also introduces diagnostic conditions around Agent-Full. Agent-OracleCalc replaces tool outputs with gold answers to bound losses attributable to imperfect tool execution. Agent-OracleEvidence provides clean evidence to isolate distractor-sensitive evidence-selection failures. Agent-Max1Turn restricts the agent to a single function-calling turn to test whether extra turns help or mostly add overhead.

On the data side, the authors build semantic-distractor versions of GSM8K and HotPotQA rather than evaluating only on clean benchmarks.
