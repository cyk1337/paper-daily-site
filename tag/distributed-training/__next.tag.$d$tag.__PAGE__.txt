9:T57b,A BDLM splits a length-L sequence into B contiguous blocks of size M=L/B. Blocks are generated left to right, while tokens inside a block are denoised in parallel. During training, each target block b is corrupted at a sampled diffusion time and denoised conditioned on the clean prefix x(<b). The total objective is a sum over per-block losses. The paper exploits this structure. In conventional implementations, training builds a length-2L representation containing a clean copy and a corrupted copy, then applies a block-causal attention mask. Under context parallelism, both clean and corrupted K/V are sharded and communicated. The mismatch is that clean prefixes are shared by many later blocks, while corrupted K/V are local to one block. Block parallelism assigns each complete corrupted-block computation to a rank, keeping that block’s corrupted Q/K/V, activations, and gradients local. This removes block-specific cross-rank communication. The drawback is replication of long overlapping clean prefixes. Context-sharded block parallelism fixes this by sharding the clean sequence across the same ranks: each rank owns clean K/V shards that can serve all local block computations whose prefixes include those shards, and backward contributions are accumulated at the shard owner. The result preserves local corrupted-block computation while distributing clean-prefix storage and computation.a:T5d2,The method is Pipelined Gradient Coding (PGC). Standard gradient coding assigns each worker c=s+1 data partitions and asks it to compute all c gradients in the same step, then upload a coded linear combination. PGC spreads those c computations across multiple consecutive steps, so each worker computes only one partition gradient per step, matching the per-step compute cost of ordinary distributed gradient descent.

To preserve recoverability, the coded message at a given step is formed from gradients computed at the current and previous steps. This creates a temporal pipeline: redundancy is no longer concentrated within one step, but distributed over time.

The paper develops PGC for two classic placement schemes:
1. Fractional Repetition (FR): workers are grouped and share the same partition placement. PGC-FR is simpler to encode and decode.
2. Cyclic Repetition (CR): partitions are placed cyclically, which is more flexible and does not require c to divide n, but decoding is more involved and depends on the straggler pattern.

The main technical shift is from purely spatial redundancy to spatial-plus-temporal redundancy. This introduces delayed gradients, so the paper also provides convergence analysis under smooth and strongly convex settings. In other words, PGC trades extra same-step computation for analyzable gradient staleness. Compared with asynchronous SGD, the delay here is structured by coding rather than being an uncontrolled side effect of worker timing.b:T43c,The experiments first validate the motivation. On 12 Google Cloud VMs, training ResNet-18 on CIFAR-10 for one epoch, the authors compare vanilla distributed gradient descent with GC under FR and CR placement. All methods follow the same loss-per-step trajectory because they recover the same full gradient, but GC is consistently slower per step. The paper states that the slowdown relative to DGD exceeds 100%, and the gap widens as the tolerated straggler count s increases. GC-FR is faster than GC-CR due to lower coding complexity.

The second part evaluates PGC through simulations and real experiments. The main result is that PGC substantially reduces completion time relative to standard GC and improves convergence in wall-clock time, while keeping per-step compute close to DGD. The important nuance is that the gain is primarily in time-to-train, not necessarily in steps-to-convergence, since PGC uses delayed gradients. The method is most attractive when stragglers are present but not catastrophic, and when the compute amplification of standard GC is the dominant cost.c:T414,A skim read should take about 20–30 minutes.
