C_learning covers policy optimization, including an effective update-cost model for LoRA that accounts for trainable adapters as well as the frozen backbone forward and activation costs. C_reward covers reward or verifier inference, which is negligible for rule-based rewards but can be substantial for learned feedback such as process reward models. The main allocation variable is the update fraction ρ = C_learning / C_total. Low ρ corresponds to search- or feedback-heavy runs; high ρ corresponds to update-heavy runs. This differs from common reporting practice because reward-model inference is not treated as free. A PRM-based run and a rule-based run can have the same total FLOPs while buying different amounts of exploration and learning. The empirical setting uses LoRA-adapted Qwen2.5 policies trained with GRPO on mathematical reasoning tasks, and compares model sizes, allocation ratios, reward systems, and evaluation targets.
