18:T7b8,SCIT，Suffix Cache Interchange Test，本质上是一个 cache-level counterfactual intervention protocol。给定 recipient 问题 r 和 source 问题 s，先构造一个精确可验证的反事实：source 提供某个中间变量的替代值，把它与 recipient 其余变量组合后，得到已知正确的 counterfactual answer。然后让 latent-CoT 模型分别在 r 和 s 上 rollout 到某个 latent step t，在这个 patch 点把 source 的某个缓存切片插入 recipient，对比 recipient 的答案是否朝 source 定义的反事实移动。

方法不是只做一次 patch，而是做一整套 intervention grid。维度包括：patch 哪个 cache segment；只换 K、只换 V、还是 K/V 一起换；是否同时复制当前 hidden state；是否使用语义相近但答案相同的 source control；是否做 decoded validation，确认被 patch 的 latent 轨迹确实对应可读出的反事实行为；以及 matched corruption，用同一区域做破坏性干预来测试 necessity。作者据此定义三个状态：active carrier，指最小且 gated 的 cache segment，在 oracle interchange 下足够，并且主要竞争解释无法匹配；carrier shift，指存在可转移效应，但活跃片段与主结论模型不同；no-call，指由于能力、支持度、decoded 行为或控制检查不过关，不能下机制判断。

从全文看，论文最重要的技术细节有三点。第一，它强调 exact source-recipient counterfactual，而不是开放式 prompt patching，这样可以避免目标答案不明确。第二，它把 sufficiency 和 necessity 分开，且 necessity 通过 matched corruption 而不是随意噪声注入来做，减少“哪里都能破坏”的伪结论。第三，它把 hidden state 与 cache object 明确区分：h_t 不是 cache 的一部分，只有显式复制时才算干预对象。这让“是当前状态在算，还是历史 value 轨迹在承载”这个问题可以被单独检验。19:T74d,SCIT, the Suffix Cache Interchange Test, is a cache-level counterfactual intervention protocol. For a recipient problem r and a source problem s, the method first constructs an exact, verifiable counterfactual: the source supplies a changed intermediate quantity, which is then combined with the recipient’s remaining variables to define a known counterfactual answer. Both source and recipient are rolled out to a latent step t. At that patch point, a selected cache slice from the source is transplanted into the recipient, optionally together with the current hidden state, and the test checks whether the recipient moves toward the source-defined counterfactual answer.

The protocol is deliberately grid-like rather than a single patch experiment. It varies: which cache segment is patched; whether only K, only V, or both are copied; whether the hidden state is also copied; whether semantic source controls with the same answer are used; whether decoded validation confirms that the patched latent trajectory corresponds to the intended counterfactual behavior; and whether matched corruption on the same region supports necessity. Based on this battery, the paper defines three outcomes: active carrier, carrier shift, and no-call.

Three technical choices are especially important. First, the paper uses exact source-recipient counterfactuals rather than open-ended prompt patching, which keeps the target answer unambiguous. Second, it separates sufficiency from necessity, and tests necessity with matched corruption rather than arbitrary noise, reducing the risk of overcalling mechanisms. Third, it explicitly distinguishes the current hidden state from the cache object: h_t is not part of the cache unless copied by intervention. That makes it possible to ask whether the computation is carried by the present state or by a historical value trajectory.1a:T6f0,The experiments are centered on controlled arithmetic settings, chosen because they allow exact counterfactual labels and clean negative controls. The main result is checkpoint-specific but strong: on the CODI-GPT2 arithmetic checkpoint, counterfactual answer transfer occurs primarily through value-cache suffix trajectories, with the strongest restricted effect in middle-to-late value segments. This region is not only sufficient under oracle interchange, but also supported by matched-corruption necessity, which is why the authors make a full mechanism call for a late-value-suffix carrier. In contrast, hidden-only transfer, key-only transfer, single-token triggers, same-answer semantic source controls, and partial-variable controls are all much weaker and do not explain the same effect.

On a Sim-CoT-style GPT-2 reproduction, the pattern is directionally similar: value-suffix sufficiency and decoded transfer are present, but matched-corruption necessity is not strong enough for a full necessity claim. The paper is explicit about that limitation.

A broader checkpoint sweep shows that the mechanism is not uniform. Some arithmetic-like GPT-2/1B cells preserve latent-tail value/KV transfer, while several competent 8B or repaired non-arithmetic cells shift the carrier to prompt-prefix or full-cache K/V. The authors call this a carrier shift rather than a replication of the CODI-GPT2 mechanism. Some cells are labeled no-call because competence gating, decoded behavior, support, or source-control checks fail. This is one of the paper’s strengths: it does not argue that latent CoT universally lives in value-cache suffixes; it provides a framework that can separate local mechanism evidence, regime shifts, and cases where no mechanism claim is justified.1b:T4bf,For a skim, focus on the protocol before the results. The introduction already states the scope clearly: the goal is not to prove a universal latent-CoT mechanism, but to define a carrier-test contract. Start with Figure 1 and the method section to understand the four-step flow: define the patch object, specify the intervention grid, validate the readout, and apply the carrier decision rule.

Then read how the arithmetic counterfactuals are constructed. That part explains why the source-recipient pairing is exact and why the protocol is not yet directly portable to open-domain reasoning tasks.

In the experiments, prioritize the CODI-GPT2 main result, because that is the only place where the paper claims a full sufficiency-plus-necessity mechanism. Then read the Sim-CoT-style checkpoint to see why it is treated as partial corroboration rather than full replication. Finally, inspect the carrier-regime map and pay attention to the gating logic behind active carrier, carrier shift, and no-call.

A key design choice is how edges are ablated. Instead of zeroing an edge, the method uses paired clean/corrupted prompts and replaces the clean activation flowing through a closed edge with the corresponding activation from the corrupted prompt.
