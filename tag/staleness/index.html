KnitTrans: Coordinated Trajectory Transfer for Effective and Efficient LLM Reinforcement Learning

这篇工作处理的是大模型 RL 系统里一个常被低估、但会直接影响学习质量的问题：trajectory 从 rollout 侧进入 training 侧的这段路径，不只是系统搬运问题，而是会改变训练看到哪些样本、何时看到、以及参数反馈回 rollout 的延迟。全文把问题拆成两层。第一层是 admission barrier：训练常有 batch 级约束，比如多数据源配比、partial-rollout completion quota；如果必须等整个 train batch 都满足条件才能放行，已经完成的轨迹也要被迫等待，导致 disaggregated 架构下 rollout 使用更旧的参数，形成额外的 architectural staleness。第二层是 transfer inefficiency：长轨迹、per-token 辅助信息、多模态输入让 payload 很重，而现有 sample-level 存储与训练拓扑、micro-batch 消费顺序不对齐，带来冗余读取、无效传输和计算等待。论文的核心问题不是单点优化，而是如何在不破坏 RL 训练约束的前提下，把 rollout→training handoff 变成一个既保学习质量、又保吞吐的协调过程。

评做大规模 RL 管线的人该看，重点不是算法而是 rollout→learner 接口；先看 admission 设计和 staleness 定义，若实验只报吞吐不报 reward 质量，就当半个信号。
Bangjun Xiao,Chiheng Lou,Xiaodong Ji,Xiangwei Deng,Yikai Zhao,Gang Huang,Hailin Zhang

DORA: A Scalable Asynchronous Reinforcement Learning System for Language Model Training

这篇论文要解决的是 LLM 强化学习训练中的 rollout 吞吐瓶颈。同步训练会被最长生成样本卡住，而数学、代码和长 CoT 任务的生成长度分布很偏，99 分位长度可比中位数高一个数量级以上。直接异步化又会引入 stale trajectory，破坏 PPO/GRPO 等算法依赖的策略一致性。

评异步 RL 不是新点，但把“正确性约束”讲清并围绕长尾轨迹做编排是可落地的；只看三条约束定义+他们如何控 staleness。
