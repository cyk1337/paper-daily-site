The central metric is the observed-over-floor ratio, R_floor = t_obs / t_floor, where t_floor = (W + K) / B_peak. Here W is the weight traffic per decode step, K is the active KV-cache traffic, and B_peak is peak HBM bandwidth. If batch-1 decode were truly dominated by HBM bandwidth, this ratio should remain relatively stable and fast GPUs should approach the floor more closely. Instead, the ratio drops as peak bandwidth increases, which implies that the bottleneck shifts away from raw memory transfer and toward launch-side overhead.

The key methodological strength is that the paper does not stop at correlation. It runs a falsifiable A/B test with CUDA Graphs, chosen specifically because graph capture reduces launch overhead while leaving the underlying kernels largely unchanged. If H100 short-context decode is launch-bound, graphing should produce a clear speedup; if not, the gain should be small. The result supports the launch-tax interpretation on H100 and gives a near-null result on L4, which is exactly the contrast the mechanism predicts.
