Depth-adaptive Inference of Looped Language Models via Continuous Depth Batching

循环语言模型的深度自适应推理机制会为“简单”token分配更少的循环核迭代次数、为“困难”token分配更多迭代，从而实现更优的计算-精度权衡，但这种自适应特性会破坏标准batching流水线。vLLM等框架使用的token级调度器无法处理同一前向传播内不同token的循环次数差异，而模型中的非循环边界层（embedding、LM head、非共享层）又进一步增加了调度复杂度。此前的循环级调度方案缺少端到端实现，导致自适应循环LM的实际效率收益无法落地。

评只看调度抽象和边界层处理即可；若内部在试 looped/early-exit LM，这篇是 serving 侧必补的坑。
Kristian Schwethelm,Daniel Rueckert,Georgios Kaissis

Adaptive Depth in Looped Transformers: Diagnosing Learned Halting Gates and Trajectory Readouts

这项工作研究 looped Transformer 的自适应深度为什么经常表现不稳定。核心问题不是单纯“halting gate 学得好不好”，而是现有目标把两个角色绑在了一起：同一个 exit distribution 既用于推理时决定在哪一层停止，也用于训练时加权不同 recurrent depth 的 loss。这样 gate 会同时影响停止策略和隐藏状态轨迹的形成，导致性能问题很难归因。

评这篇会改你对 adaptive depth 失效原因的 prior：先别怪模型不会算，先查 gate 把监督和停机绑死了；读合成任务和 Ouro 分析就够。
Andrei Cristian Popescu,Haitz Sáez de Ocáriz Borde,Pietro Liò

Route, Communicate, and Reason: Gated Routing and Adaptive Depth for Efficient Multi-Agent Reasoning

这篇工作处理的是多智能体 LLM 系统里的一个老问题：如果用一组较小、异构、专长不同的模型协同推理，怎样才能让系统按题目难度自适应地决定‘找谁来做、做到多深、谁和谁需要通信’，而不是像固定 ensemble 那样每次都把所有 agent 全跑一遍。作者还额外处理了一个很实际的问题：当某个 expert 在部署时被替换后，原先学到的 gate 阈值会失效，系统需要一种低成本的重新校准机制。

评只看 gating ablation 和预算归一化；若 token/模型调用算清楚，它是多 Agent test-time compute 的好参照。
Sudipto Ghosh,Tanmoy Chakraborty
