What actually runs: a measurement study of language model placement and decode speed on the Apple Neural Engine

这篇工作解决的是一个很具体、但过去一直缺少可靠证据的问题：LLM 在 Apple Neural Engine 上到底什么会被放到 ANE 执行，什么决定了解码速度。作者强调，现有 CoreML 编译计划只能反映编译器“打算”怎么放置，不能证明运行时真的在 ANE 上执行；而常见功耗遥测还会因为芯片通道映射错误给出看似可信但完全错误的零读数。于是论文把问题拆成两个层面：一是 placement，哪些算子表达形式、模型结构、参数规模和权重量化方式会让模型真正驻留在 ANE；二是 decode speed，已经驻留后每 token 的延迟究竟由什么主导。核心结论不是“某个模型更快”，而是 ANE 上的可部署性和速度都强依赖表达形式与字节流量，不能用参数量、FLOPs 或编译器静态计划替代真实测量。

评揭示了苹果 ANE 上 LLM 部署的黑盒机制，发现算子融合方式决定硬件 placement，对端侧推理优化有启发，建议关注其测量方法和结论。

TileFuse: A Fused Mixed-Precision Kernel Library for Efficient Quantized LLM Inference on AMD NPUs

这篇工作解决的是一个很具体但长期被忽视的问题：边缘端 NPU 明明有不错的能效，却很难直接运行社区常用的量化 LLM，尤其是 AWQ 这类已经广泛分发的 W4A16 / W8A16 权重。问题不在于单纯算力不够，而在于现有 NPU 软件栈封闭、低层可编程性不足，以及量化格式、数据布局、DMA 流水和 tile 级执行方式之间不匹配。结果就是，用户往往得为了硬件去改模型或改量化方案，而不是把现成量化模型直接部署上去。TileFuse 试图把这个链条打通：让 AMD XDNA2 NPU 直接吃下 AWQ 风格权重，并把它真正接进端到端 LLM 推理流程。

评不是预训练论文，但很适合做小模型/端侧路线的人看：重点看它如何避免为硬件专有量化格式改模型，这个接口问题常被训练侧低估。
Wesley Pang,Gregory Hyegang Jun,Feiyang Liu,Deming Chen

SparKV: Overhead-Aware KV Cache Loading for Efficient On-Device LLM Inference

这篇工作解决的是端侧 LLM 推理里的 prefill 延迟问题，具体是“已有上下文可复用时，KV cache 到底该从云端传，还是在本地重新算”。现有方案通常只押注一边：要么做 KV 压缩后传输，要么优化本地 prefill 计算。但在真实边缘设备上，通信带宽、算力余量、内存带宽都在波动，而且不同 KV chunk 的传输成本和重算成本差异很大。论文要解决的核心问题，是在严格的 Transformer 依赖约束下，对每个 chunk 做 overhead-aware 的路径选择，并让云传输与本地计算尽可能重叠，从而降低 TTFT。

评不是 pretrain 论文，但边云协同 KV 的 cost model 很实在；只看调度建模和 runtime refinement，别在质量结论上过度外推。
Hongyao Liu,Liuqun Zhai,Junyi Wang,Zhengru Fang
