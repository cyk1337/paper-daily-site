18:T621,The paper introduces AgentPerturb, a two-dimensional perturbation framework. The first axis is perturbation target: user utterance (U), procedural specification (P), carried-over context (C), and tool contract (T). The second axis is perturbation type: Missing, Redundant, and Incorrect. This yields 12 perturbation families.

Two design choices are important. First, perturbations are single-target edits: only one channel is modified at a time while the others remain unchanged. This makes attribution cleaner and avoids confounding multiple failure sources. Second, perturbations are validated so that the original task goal is preserved, the environment remains executable, and a valid solution path still exists. So the benchmark is not broken; the agent is tested under controlled information corruption.

The framework is instantiated on APEX-Agents and Toolathlon, two long-horizon agent benchmarks with verifiable outcomes. The analysis is organized at three levels. Outcome-level analysis measures clean-to-perturbed performance drops. Factor-level analysis separates the effects of targets and types, and relates sensitivity to clean performance and task properties. Trajectory-level analysis audits reasoning traces, tool calls, observations, and state transitions to understand how perturbation-induced failures unfold. One of the most useful findings is that sensitivity clusters more strongly by perturbation target than by perturbation type. That suggests robustness interventions may need channel-specific treatment rather than generic noise injection.19:T46d,The evaluation covers 10 frontier models on APEX-Agents and Toolathlon. The headline result is consistent: all perturbations reduce performance, but the dominant vulnerability depends on the environment. In other words, the most damaging target is not universal across benchmarks. The paper also performs a focused analysis on Hunyuan-3-High and shows that task success alone can hide substantial losses in token efficiency. Some agents still solve the task, but only after much longer and less efficient trajectories.

For mechanism analysis, the authors manually audit 30 cases where DeepSeek-V4-Flash succeeds on the clean task but fails after perturbation. The recurring pattern is that agents rarely question altered inputs and often propagate corrupted information without verification. Once a bad assumption is accepted early, it contaminates later planning, tool use, and state updates.
