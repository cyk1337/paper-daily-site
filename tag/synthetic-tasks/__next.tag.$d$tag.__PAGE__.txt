9:T579,Two key components.
1) TaskPilot: an online, policy-adaptive task synthesis loop. Starting from real repository snapshots, it generates candidate tasks, runs rollouts with the current checkpoint to estimate learnability, keeps tasks within a target difficulty window (neither unsolved-always nor saturated), and uses policy feedback to adjust tasks toward that window. Training proceeds in iterations: when a checkpoint saturates on validation, it triggers a new synthesis/calibration round, so the task distribution co-evolves with the policy. This differs from offline difficulty filtering over a large static pool.
2) Leaf harness: a simplified Claude-Code-like tool interface designed for compact models. The authors found Qwen3.5-4B frequently fails to terminate under R2E-Gym/SWE-Agent (about 96% trajectories hit the turn limit). Leaf exposes five typed tools (read/write/edit/glob/bash) and uses a natural termination rule (no tool call => terminate), removing brittle “finish action” requirements. During RL, model-generated reasoning/text/tool calls are trained on; prompts and tool outputs stay in context but are masked from loss.
RL setup: DPPO with async rollouts plus a log-length penalty for concise generations; five rounds of (synthesize tasks -> RL). They also discuss a consolidation procedure to recover useful tool-use behaviors that may be forgotten across later iterations.a:T439,The authors use the synthetic function-regression setup popularized by Garg et al., where small transformers are trained on serialized (x, f(x)) pairs and evaluated for ICL behavior. The main intervention is to split the context into two phases: misleading linear examples first, then recovery quadratic examples. By sweeping over the number of examples in each phase, they quantify how much prior context biases predictions after a task switch and how many post-switch examples are needed for recovery.

They also compare different training curricula, including sequential, mixed, and random exposure to tasks, to test whether training distribution changes the reversibility of in-context adaptation. This is the most interesting design choice: it asks whether transformers can learn a more flexible update rule if task variation is present during training, instead of overcommitting to early evidence. The paper does not introduce a new architecture.
