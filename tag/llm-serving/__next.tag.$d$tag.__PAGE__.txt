The design has three main pieces: (1) a CUDA-graph-aware latency model, calibrated offline and refined online, that predicts at batch granularity how admitting fine-tuning will affect TTFT and TPOT; (2) an SLO-aware admission scheduler that admits, throttles, pauses, and resumes fine-tuning as inference load fluctuates; and (3) a decoupled backward executor that moves the long backward pass off the inference critical path to avoid blocking token-level latency. The system is integrated into vLLM, SGLang, and S-LoRA using the same host-agnostic core.6:T7b3,The main idea is a joint routing framework augmented with a lightweight latency estimator. For each incoming query, the router combines three signals: expected response quality, monetary cost, and predicted latency at a specific model instance. The difficult part is latency estimation. Unlike cost, latency depends on the current state of the serving system. The paper proposes a Serving Framework Simulation (SFS) estimator that simulates the evolution of autoregressive token batches at each instance. It tracks active requests, separates prefill and decode work, and incorporates the batching/admission/scheduling behavior of the underlying serving framework.

This is a more structured approach than using prompt length, expected output length, or queue length alone. In modern continuous batching systems, prefill is typically compute-bound while decode is more memory-bandwidth-bound, and the mix of the two phases strongly affects how much delay a new request will see. The estimator therefore models not just how long a query is, but what kind of workload is already occupying the instance.

The overall routing pipeline appears to have three components: (1) an accuracy/cost predictor from prior query-routing work, (2) the SFS latency predictor conditioned on per-instance workload state and serving policy, and (3) a routing objective that selects the model instance under a latency-aware utility or constraint. A notable design choice is that latency is not treated as a pure black-box regression target. Instead, the estimator uses serving mechanics explicitly, which should make it more robust across different batching policies and heterogeneous deployments.

Relative to prior latency-aware routing work based mainly on output-length heuristics, the key difference is the explicit modeling of prefill/decode composition and current instance workload.
