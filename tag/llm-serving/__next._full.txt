18:T857,The system, Galahad, has two separable components. Taliesin stores and restores the KV state produced by prefilling a block of text. Blaise stores the text itself in sectioned form and selects a relevant section on the CPU so the model reads only that section rather than the full corpus. Taliesin removes repeated computation; Blaise removes unnecessary reading.

Taliesin is built around byte-exact memory. After a runtime computes KV state for a prompt block, the system stores that state under a fingerprint defined by the exact input bytes, the model fingerprint, and the tenant identity. If a later request contains the same byte block, the runtime loads the saved KV state instead of recomputing it. The design goal is exactness: restored state must yield bit-identical logits to a fresh prefill. To enforce this, the system validates stored records on load and falls back to normal computation on any failure. The guiding rule is explicit: serve without memory rather than serve with wrong memory. This differs from approximate cache reuse or ordinary GPU prefix caching, where the emphasis is often hit rate rather than strict equivalence.

Blaise is retrieval-like, but the returned unit is byte-exact text rather than an approximate semantic chunk assembled from embeddings. The paper does not disclose the internal section-selection method. It reports only the first operating mode, where the CPU selects one section and passes its exact text to the model. A second mode is mentioned, where the model reads Blaise’s index and Taliesin amortizes that reading too, but that mode is not evaluated here.

Implementation-wise, Galahad is packaged as a shared library that plugs into vLLM, SGLang, and llama.cpp without modifying model weights or runtime source code. It requires tenant identity and model fingerprinting to prevent cross-model or cross-tenant misuse, supports integrity checks and encryption at rest, and explains why reuse must happen at block granularity with exact token-position alignment. That boundary follows from transformer positional structure and KV semantics: near matches are not safe substitutes.19:T662,The evaluation has two main parts: correctness and system behavior. The most important result is not a benchmark score but exact restoration. The authors report bit-identical logits after save-and-restore and byte-equal prefill across four model architectures. They also test four safety mechanisms—confirmation hash, licence signature, tenant separation, and byte comparison on load—using explicit attack toggles: attacks succeed when the defense is disabled and fail when it is enabled. This makes correctness a first-class requirement rather than a best-effort property.

On workload analysis, the paper reports that across seven real-world datasets, 98.7% of prompt tokens were text the model had already read before. That number is the main justification for persistent memory: if nearly all prompt tokens are repeated, prefill reuse can dominate latency and energy savings.

In a controlled recall test, Blaise reduces the text passed per question from roughly 97,000 tokens to about 668 tokens by selecting one relevant section instead of sending the full corpus. The introduction also states that the paper measures accuracy, latency, and GPU energy, includes an external retrieval baseline, and covers 30 out of 30 tested models, but the provided full-text excerpt does not include the complete result tables. The most concrete confirmed findings are therefore exact restoration, very high repeated-token rates, and large context reduction from section-level text selection.

From a research perspective, the two numbers to remember are 98.7% repeated prompt tokens and the 97k-to-668 token reduction in the recall setup.1a:T40c,For a skim, start with the problem reframing in the introduction: the point is not to make the model read better, but to stop paying repeatedly for reading the same bytes. Then read the system section to understand the division between Taliesin and Blaise. After that, go straight to the correctness section. The bit-identical logits, byte-equal prefill, and fail-closed fallback policy are what determine whether this is deployable infrastructure or just a systems idea.

If your interests are serving, long-context inference, agent memory, or KV-cache reuse, focus on Taliesin’s integration points, the exact-reuse boundary conditions, and the requirement that token positions match exactly. For Blaise, the main thing worth extracting is the empirical effect—reducing the model-visible context from about 97k to 668 tokens—since the internal selection method is intentionally not disclosed.

第二个组件是 buffered cache-aware scheduling。作者观察到，如果调度器只追求尽快塞满设备，很容易把 HBM 挤满，导致后续 decode 增长或跨轮复用 prefix 时不得不频繁驱逐和回载缓存。于是他们引入 admission buffer，也就是主动保留一部分 headroom，不把内存用到极限。这个策略看起来保守，但在多轮工作负载里反而能减少 cache churn、降低 HBF 写入、提高整体完成时间。这里的思路和很多训练系统里的“不要把某个资源打满”很像：局部利用率最大化不等于全局吞吐最优。

The first is an HBM–HBF–host hierarchical storage system. Newly generated KV state and reloaded prefixes enter HBM first; colder cache can be demoted to HBF or lower tiers when HBM becomes scarce. The point is not a simple cache policy but a placement strategy that accounts for each tier’s capacity and access cost. The second component is buffered cache-aware scheduling. The authors observe that aggressively filling device memory can be counterproductive in multi-turn workloads: it leaves no room for decode growth and forces frequent eviction of reusable prefixes, which then have to be reloaded or recomputed. Their solution is to reserve headroom through an admission buffer. This looks conservative locally, but improves global throughput by reducing cache churn, HBF writes, and repeated prefill. The idea is familiar from other large-scale systems: maximizing instantaneous utilization of one resource does not necessarily maximize end-to-end throughput.
