a:T8d2,方法核心是把 memory management 写成一个顺序决策问题。论文定义了一个 Memory MDP：状态同时编码任务进展和记忆状态，前者包括 goal type、当前 step phase、是否卡住、访问过的位置等，后者包括 memory size、是否已有可复用 plan、当前处于学习早期还是后期等。动作不是单一“retrieve”，而是一组带参数的 memory operation，包括 Retrieve、PlanInject、Re-Retrieve、Consolidate、Forget、NoOp，以及对应的 top_k、insight_k、graph hop 等参数选择。

控制策略没有用神经网络，也没有再训练一个小模型，而是用了 tabular contextual bandit + UCB exploration。这样做的原因很明确：一是在线部署时样本很少，二是状态特征是人工可解释的离散上下文，三是希望毫秒级决策而不是引入新的推理链路。策略从 human-readable priors warm start，而不是冷启动随机探索；任务结束后用 binary success 做反向折扣式 credit assignment，把一次任务成功或失败分摊给先前做过的 memory decisions。这个设计不追求严格的长期 credit 最优，而是追求在几十个任务内就能学到比固定启发式更稳的控制。

论文还强调它是 backend-agnostic wrapper。也就是说，MemCon 不定义新的存储格式，而是在 retrieve/store 抽象接口上做拦截和调度，因此可以套在 flat vector store、skill library、trajectory summary、graph memory、latent-token memory 等不同后端上。这个抽象是方法里最干净的部分，因为它把“存什么”和“怎么调用”分开了。

另外两个增强操作值得注意。PlanInject 面向重复 goal type，不再只做相似轨迹检索，而是优先注入抽象化、对象泛化后的成功计划模板；Re-Retrieve 面向 stuck 状态，当 agent 连续重复动作或无进展时，不是重复读同一批 top-k，而是换查询重检索。Consolidate 和 Forget 则处理长任务流中的记忆膨胀问题，避免 memory store 规模增长后把噪声一并带进 prompt。相比 MemGPT 这类让 LLM 自己当控制器的方案，MemCon 的区别不在记忆表达，而在把控制逻辑外置成一个廉价、可持续学习的策略层。b:T959,The method formulates memory management as a sequential decision problem. The paper defines a Memory MDP whose state combines task-progress signals and memory-status signals. Task-side features include goal type, step phase, whether the agent is stuck, and visited locations. Memory-side features include memory size, whether reusable plans already exist, and the current learning phase. Actions are not limited to a generic retrieve call. The action space includes Retrieve, PlanInject, Re-Retrieve, Consolidate, Forget, and NoOp, together with operation parameters such as top_k, insight_k, and graph-hop depth.

The policy is intentionally simple: a tabular contextual bandit with UCB exploration. The choice is pragmatic. Online deployment offers limited samples, the context variables are interpretable and mostly discrete, and the controller must run in milliseconds. The policy is warm-started with human-readable priors instead of random exploration. After each task, binary task success is propagated backward through a reverse-discounted credit assignment scheme so earlier memory decisions receive partial credit or blame. This is not trying to solve full long-horizon RL optimally; it is trying to learn a useful controller within tens of tasks.

A key design point is backend agnosticism. MemCon does not define a new storage format. It wraps the abstract retrieve/store interface and decides how the backend should be called. That means the same controller can sit on top of flat vector stores, skill libraries, trajectory summaries, graph memories, and latent-token memories. This separation between what is stored and how it is accessed is one of the cleanest aspects of the paper.

Two augmented operations are especially relevant. PlanInject is used for recurring goal types: instead of nearest-neighbor retrieval over raw trajectories, it injects a distilled and object-generalized plan template from prior successful episodes. Re-Retrieve is triggered when the agent appears stuck, so the system issues an alternative query rather than re-reading the same failed top-k results. Consolidate and Forget address memory growth over long task streams, aiming to prevent prompt dilution and retrieval noise. Compared with LLM-as-controller approaches, the novelty is not in memory representation but in externalizing control into a cheap, persistent, online-learned policy layer.c:T7ae,The evaluation is broad: 6 benchmarks, 3 agent frameworks, 3 LLM backbones, and 9 memory baselines. The environments named in the paper include ALFWorld, PDDL planning, ScienceWorld, TriviaQA, WebWalkerQA, and GAIA. The frameworks include Lobster, LangGraph, and Microsoft Agent Framework. The backbones include GPT-4.1-mini, Claude Sonnet-4, and DeepSeek-V3.2.

The main result is that MemCon achieves the best or near-best task success in most settings while also reducing average token usage by 5% to 20%. A representative number highlighted early in the paper is 67.9% success on ALFWorld with GPT-4.1-mini under the Lobster framework, the top score among the 10 memory systems compared in that cell. Relative to a no-memory baseline, the gains are often in the 5 to 30+ point range. That matters because the improvement appears across different backends, suggesting the controller itself contributes meaningful value.

The ablations are more important than the headline table. The paper isolates the contribution of the learned controller from the contribution of simply adding more memory operations. The reported pattern is that both matter, but the learned policy is a major source of gains, especially in three regimes: retrieving less in early tasks, preferring plan reuse for recurring goals, and triggering alternative retrieval when the agent is stuck. Another notable result is convergence speed: the controller learns useful behavior within tens of tasks, without any pretraining. That aligns with the choice of a contextual bandit rather than a heavier RL setup.

In terms of evidence quality, the strengths are breadth and backend diversity. The main limitation is the reward signal: task success is binary and coarse. For long-horizon tasks, the true value of individual memory actions may be obscured by final success or failure.
