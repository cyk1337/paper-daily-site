- Surprise key: compute mean token NLL sθ(c) on the claim target; learn only if sθ(c) exceeds a threshold (τ=1.0 nats/token), intended to capture novelty.

On the harness side, the system does not simply cache raw examples. Instead, it maintains two forms of external state. First, it refines textual skills that summarize reusable patterns from the current and past tasks. Second, it stores a bounded set of high-residual examples that those skills fail to explain well. This split is deliberate. Storing only examples wastes context budget and scales poorly with stream length; storing only abstract skills loses tail cases and exceptions. HERD treats the harness as a selective, fast-learning layer that keeps both abstraction and residual evidence.

On the parametric side, the model is updated by distillation rather than direct supervised finetuning on the raw task stream. The student starts from the previous checkpoint and is trained to match the behavior of the prior system when that system is equipped with the current harness. In effect, the harness organizes and filters experience first, and only then is that experience written into the weights. This is meant to reduce noise and lower drift compared with ordinary SFT.

The central technical idea is drift-constrained distillation with dual anchors. One anchor is the previous checkpoint, which limits per-stage movement and protects short-term retention. The other is the original base model, which limits cumulative drift across many stages and helps preserve broad general capabilities. The paper presents this as the key to recursive stability: the challenge is not merely learning stage t, but still behaving sensibly after stage 20 or 25.

Relative to standard continual finetuning methods such as replay, regularization, or LoRA-based sequential updates, HERD inserts an explicit external selection layer before weight updates. A task can look frontier-level or verifiable before training, yet the optimizer step induced by that task may fail to increase the likelihood of correct answers on fresh questions, or may even damage existing capabilities. The paper contributes at three levels. First, it sharpens the problem formulation: task-side signals and update value are different objects, and pre-update behavior alone cannot identify whether an optimizer step is beneficial. Second, it proposes a practical correction: HeirCommit accepts an update only after comparing the frozen successor against the current root on fresh probes, while EvoHeir further decouples parameter inheritance from experience inheritance. Third, it provides an empirical lesson with broader relevance: useful experience can outlive the model state that produced it. Even references from rejected rounds can help later learners. That is directly relevant to continual pretraining, self-training, RL-generated data reuse, and any setting where one currently binds data value and parameter value to the same acceptance decision.17:T96a,HeirCommit addresses the acceptance rule. In each round, the current root state St produces native branches through the host self-evolution loop. Standard systems typically inherit one branch endpoint. HeirCommit instead freezes a candidate successor and evaluates it against the current root on a fresh probe set that is disjoint from training and screening. The system commits the successor only if it beats the root on this new evidence; otherwise it retains the root. The key idea is that acceptance should be based on the realized transition, not on the task that motivated the update. The paper also gives a statistical argument: if one reuses screening evidence to accept among multiple branches, one pays a union-bound penalty over branches and can easily mistake selection noise for genuine improvement. Fresh confirmation removes that coupling.

EvoHeir tackles a deeper issue: whole-state acceptance bundles gains and losses together. A branch may acquire new skills while also degrading old ones, but standard inheritance forces an all-or-nothing choice. EvoHeir splits the round into screening, recovery, and confirmation. Screening chooses the recipient that will supply the next learner’s parameters, from either a branch endpoint or the current root. Recovery then repairs that recipient’s failures using reference solutions drawn from both the current round and an archive of past qualified experience, while trying to preserve existing successes. Confirmation finally applies a HeirCommit-style fresh comparison between the post-recovery proposal and the root. A notable design choice is that qualified experience enters the archive regardless of whether the donor model is inherited. Parameter inheritance can stop without discarding potentially useful experience.

The measurement choices are also important. The paper does not rely only on accuracy. Update audits use correct-target negative log-likelihood gain, which can detect whether the model actually shifts probability mass toward the correct answer even when accuracy stays unchanged. The key detail is that SST projects the applied parameter update, not the raw gradient. That distinction matters because stateful optimizers such as Adam transform gradients through momentum and coordinate-wise rescaling; a projected gradient does not guarantee a projected final step. By acting on the actual update written into the weights, SST becomes optimizer-agnostic.

The projection is bilateral: it removes components aligned with principal singular directions on both the output side and the input side. This is stronger than a one-sided constraint and is meant to preserve the dominant mapping structure of the pretrained matrix. Conceptually, SST freezes the high-energy spectral structure and pushes adaptation into the tail subspace.

The paper also addresses a practical limitation of a fixed protected basis. If the SVD basis is computed once and never updated, the allowed complement can become too restrictive as training progresses. SST therefore includes a refresh mechanism that periodically recomputes the SVD on the current weights. This trades off stricter preservation against continued adaptability: no refresh gives stronger protection, while refresh allows the protected subspace to track the evolving model and frees capacity for further learning.
