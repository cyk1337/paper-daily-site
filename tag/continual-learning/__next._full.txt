Execution trajectories are audited in the production harness, context configurations that shape behavior are searched, and high-quality trajectories are selected to update specialist LoRA adapters for the next revision. Deployment experience is thus converted into capability gains across successive revisions, with auditability and external contract constraints preserved. 2) Collaboration: a Mixture-of-LoRA (MoL) architecture that freezes the large base model and layers independent specialist LoRAs (for chat, agent, coding, GenUI, etc.) on top. A shared runtime selects exactly one LoRA per user turn, enabling modular composition of heterogeneous capabilities without modifying the base model and avoiding cross-task parameter interference.
