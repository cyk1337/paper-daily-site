1a:T628,The core idea is a trajectory-level evaluation protocol. Each run records the full session: user messages, agent responses, tool calls, file edits, command executions, verification attempts, final answer, and final repository state. Evaluation combines formal verification, when objective checks exist, with LLM-written trajectory reviews and metric-specific scoring. The dimensions include things like instruction following, tool discipline, validation behavior, recovery from errors, and user-facing communication. The important design choice is that the written review is treated as a first-class artifact, not just a hidden judge score. That makes the benchmark useful for diagnosis.

A second key component is side-by-side review. Instead of only scoring one trajectory in isolation, the benchmark also compares two agents or two versions on the same task. This is well suited for model comparison, feature evaluation, and regression analysis, because many product regressions show up as local behavior changes before they show up in final pass rate.

On the task side, AgentLens focuses on production-like interactive coding workflows and uses a simulated user driven by another LLM conditioned on a persona and task objective. This follows the hidden-goal interaction style seen in benchmarks like τ-bench. It allows the benchmark to cover tasks without a natural binary outcome, such as writing documentation or explaining a codebase. The paper also includes reliability and bias checks, which is important because LLM-as-judge setups are otherwise easy to overtrust.1b:T911,技术方案的核心是 Formal Disco 这个分布式 agenda 系统。它不是简单地并行调用多个 LLM，而是把数据生成拆成对象数据库和任务队列两层：系统维护程序对象、任务状态、agent 轨迹，不同类型的 worker 围绕共享 agenda 协作。具体有三类 agent。Initiator 负责从随机 GitHub README 和语言文档片段中抽取主题，先生成一个与主题相关的 verified program 草稿。这里用 README 作为外部熵源，是为了避免模型自举时反复回到少数熟悉题材。Fixer 负责处理编译失败或验证失败的程序，根据 verifier 返回的错误信号迭代修补。Extender 则在已有可工作的程序上继续打补丁，增加函数、规格、循环、lemma、proof 结构，让程序复杂度逐步增长。这个设计背后的取舍很清楚：如果一开始就要求 initiator 直接写复杂程序，成功率会很低；先写小而可修的程序，再通过 fixer 和 extender 逐步爬升，能兼顾通过率和复杂度。

另一个关键点是把 verifier 当成外部可执行判别器。系统不依赖人工逐条审核，而是用编译/验证结果作为强约束信号，既用于筛选样本，也用于后续 agent 自改进和蒸馏。作者还强调轨迹记录：agenda 中保留了从草稿到修复再到扩展的过程，这些 trace 可用于 distillation，让较强闭源模型的生成过程迁移到开源模型上，也可用于训练专门的 initiator/fixer/extender。相比只保留最终成功样本，轨迹数据更适合学会“如何修”和“如何扩”。

论文里另一个有意思的技术贡献是 entropy maximization 框架。作者不是只统计 token-level 多样性，而是定义程序层面的 feature entropy，例如规格形式、注释模式、循环结构、proof/lemma 形态等，用这些结构特征来比较不同数据集，并在生成时把“成功率”和“多样性”一起作为优化目标。这样做的原因是 verified code 的价值不在表面语法，而在逻辑结构；如果只看 token entropy，很容易被变量名和表面改写误导。这个思路和一般代码预训练里的去重、cluster balancing、mixture reweighting 是同一类问题，只是这里把质量信号换成了 verification-specific structure。1c:T8c7,The core system is Formal Disco, a distributed agenda-based framework. It is not merely parallel prompting. The system maintains an object database and a shared task agenda, and different worker types operate over that shared state while all traces are recorded. There are three main agent roles. Initiators read random GitHub READMEs and language documentation snippets, then draft an initial verified program aligned with that theme. The README sampling acts as an external entropy source, preventing the model from repeatedly falling back to a small set of familiar topics. Fixers take programs that fail compilation or verification and patch them using verifier feedback. Extenders operate on already working programs and grow them by adding functions, specifications, loops, lemmas, and proof structure.

This decomposition is a practical design choice. Asking a single model to directly produce large, complex, fully verified programs has low success rate. Starting from smaller drafts and then iteratively repairing and extending them gives a better trade-off between validity and complexity growth. Another important component is the verifier itself, which serves as an executable discriminator. Instead of relying on expensive human review, the system uses compile/verify outcomes as hard signals for filtering, improvement, and training. The recorded traces are also central: they preserve not just successful end states but the trajectory from draft to repair to extension, which is useful for distillation from stronger proprietary models and for training specialized open models to imitate the generation process.

A second technical contribution is the entropy-maximization framework. Rather than measuring diversity only at the token level, the paper defines feature entropy over program-level structures, including specification forms, annotation patterns, loop structures, and proof-related constructs. This is the right level of abstraction for verified code, where logical structure matters more than superficial lexical variation. The generation process is then pushed to optimize both success and structural diversity. That makes the dataset less prone to near-duplicate, conservative samples that merely satisfy the verifier.1d:T5ce,The experimental story has three main parts. First is dataset construction. The authors release three synthetic datasets—dafny-disco, framac-disco, and verus-disco—with more than 100k complete verified programs in total. For Dafny and Frama-C, this is orders of magnitude larger than prior public resources; the paper explicitly contrasts with DafnyBench, which has fewer than 800 deduplicated Dafny files. Second is dataset quality analysis. The paper does not stop at volume claims. It compares Formal Disco data against existing human-written datasets and against alternative generation strategies using feature entropy, showing that external theme sources plus the fixer/extender pipeline improve structural coverage rather than just sample count. Third is downstream training. The synthetic data is used to train open models on verification-relevant tasks such as adding assertions and loop invariants and proving lemmas. The headline result is that Qwen2.5-Coder-32B improves substantially, and in some settings becomes competitive with Claude 4.5 Opus.

The ablation logic is especially useful. Without external entropy from READMEs, topic diversity collapses. Without fixer/extender stages, the system struggles to move from easy drafts to more complex verified programs. And if optimization focuses only on verifier pass rate, the resulting dataset becomes too conservative and narrow.
