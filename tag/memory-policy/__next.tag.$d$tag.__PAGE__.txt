9:T79d,AdaMem centers on a structured Memory Policy. The policy is a JSON object that maps each character or role C_i to a natural-language extraction preference T_i, such as keeping only final business decisions and deadlines while ignoring casual chatter. The system then runs a weekly closed loop with four stages.

First is Daily Extraction. New conversations are processed by an extractor LLM, but the extraction prompt is conditioned on the current policy rather than using a generic save-everything rule. The paper also adds Time Anchoring: the prompt includes the absolute session date and instructs the model to resolve relative expressions like “tomorrow” into absolute dates before storing them. That is a small but important systems detail, because relative temporal references decay quickly in long-term memory.

Second is Weekly Evaluation. At the end of each week, the system is probed with QA examples targeting preference-aligned information.

Third is Policy Reflection. Errors are diagnosed into two categories. Recall Failure means the relevant information appeared in dialogue but was never written, so the policy is too restrictive. Precision Failure means irrelevant retrieved memories polluted the answer, so the policy is too permissive. Based on these failures, the model generates a policy patch rather than rewriting the full policy from scratch. This patch-style update is easier to inspect and easier to roll back.

Fourth is Failure Rollback and Policy Rendering. If the updated policy hurts validation performance on historical QA pairs, the change is rejected and the system reverts to the previous policy. The accepted policy is then rendered into extraction instructions for the next week. The interesting part here is not a new neural architecture but a control loop: write policy, evaluate, diagnose, patch, validate, and only then deploy. That makes the method easy to insert into existing RAG-style memory stacks.a:T6f7,The evaluation includes both a new benchmark and the method comparison itself. The benchmark, AdaMem-Bench, is designed specifically for preference-guided long-horizon memory. It uses multi-session dialogues over multiple weeks, multiple concurrent personas, and deliberately overlapping semantic content across characters so that the system must avoid confusing similar but irrelevant memories. Each session is annotated with golden memories: atomic facts that match the character’s preference profile are labeled as relevant, while the rest is treated as noise. That setup is better aligned with the paper’s goal than generic QA benchmarks.

Empirically, the paper reports up to +9.0% QA accuracy while reducing memory volume by 9%, across two extractor LLMs and two feedback modes. That combination matters more than the accuracy number alone, because it suggests the gains come from better selectivity rather than from simply storing more information. The analysis says improvements are concentrated in soft-preference categories such as emotions, promises, and schedules. That is plausible: these are exactly the categories where a uniform extraction rule tends to either miss subtle information or over-store irrelevant details. The main remaining bottleneck is policy inference from weak feedback, meaning the system can observe that an answer failed but cannot always infer the right policy adjustment.

When reading the experiments, the most useful questions are practical ones: what the baselines are, how memory volume is measured, how often rollback is triggered, and whether the gains hold across different extractor models.
