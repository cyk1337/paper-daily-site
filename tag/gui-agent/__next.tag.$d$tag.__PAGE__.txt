For a fixed agent and environment, evaluation, data collection, and RL training reuse the same observation processing, context construction, and action execution stack. This reduces harness drift. The platform covers mobile, computer, and web environments, manages provisioning, isolation, reset, and recovery, and reports scaling to 20,000 parallel environment instances. On the data side, MAI-Gym uses two synthesis layers. At the app level, coding agents build mocked apps with resettable backends, including safe clones of real services and novel interfaces. At the task level, cross-app world construction first creates a coherent world from a persona and scenario, populates multiple applications with consistent files and records, and then generates tasks that require retrieval and integration across apps. Step-balanced GSPO constructs importance ratios over action steps rather than raw assistant-token counts to balance learning across modalities.b:T540,MaP has two main components. The first is Masked Trajectory Prediction. A GUI interaction is represented as a multimodal trajectory consisting of the user instruction plus, at each step, a screenshot m_t, a reasoning trace r_t, and an action a_t. Instead of defining separate input-output mappings for different tasks, the method randomly masks a fixed proportion of components in the full trajectory and trains the model to autoregressively recover the missing parts. This turns step-wise decision, state-action alignment, and long-horizon planning into the same problem: predict missing pieces given a partially observed trajectory. The important point is not masking by itself, but the move from task-specific marginal dependencies to modeling a more unified trajectory structure. The second component is role-aware adapter learning. The authors argue that heterogeneity is not only dataset-level but also token-role-level: instruction tokens, action tokens, reasoning text, and visual-state-related tokens induce different optimization directions. They therefore add token-wise adapters routed by semantic role, so different token types can use specialized representation subspaces while still sharing the backbone. Compared with dataset-specific adapters, this is a finer-grained way to handle heterogeneous supervision inside each sample.c:T42d,The evaluation spans five GUI navigation benchmarks: AndroidWorld, AndroidControl, GUI-Odyssey, AITZ, and Mind2Web. The core design choice is to expose software through the deepest feasible access path available for each application. On the observation side, the agent receives a structured JSON object containing task metadata, application state, interactive elements, environment context, navigation structure, and a concise textual summary. On the action side, the agent emits a schema-constrained JSON action with explicit type, target, and parameters. The key shift is from “where to click” to “what to modify / invoke / export.”

The implementation is organized around three realization paths:
1. file-based access, where structured file formats are read and modified directly;
2. scripting-based access, where native scripting runtimes or automation APIs are used;
3. service-based access, where backend APIs or service endpoints expose semantic operations.

The paper emphasizes four design principles: completeness, semanticity, stability, and composability. Completeness addresses the partial observability of screenshots. Semanticity aligns actions with meaningful software operations. Stability avoids UI-dependent identifiers and layout drift. Composability allows complex tasks to be solved through a sequence of higher-level operations rather than long GUI event chains.

A notable systems contribution is the onboarding framework: reviewed interface profiles are compiled into validated adapter contracts. This makes ASIL more than a one-off wrapper. It resembles tool schemas or MCP-style interfaces, but with a stronger emphasis on state observability and action closure.

Importantly, ASIL is also treated as a trainable environment. The authors run small-scale SFT followed by resource- and time-limited on-policy RL. Because states and actions are structured and directly checkable, reward design and rollout efficiency become much cleaner than in screenshot-and-click settings. That is the part most relevant to agent training dynamics.f:T689,The evaluation has three layers. First, the environment and benchmark: ASIL is instantiated across 15 applications, with 300 single-application tasks and 80 multi-application tasks. The authors also render GUI snapshots from the underlying software state at every step, so ASIL and screenshot-driven agents can be compared under the same task definitions and validators. This is an important design choice because it controls for task specification while changing only the interaction interface.

Second, the interface comparison: the abstract reports that ASIL reaches above 80 with closed models on the benchmark. The paper also includes repaired GUI / 50max results, matched native-interface baselines such as LibreOffice UNO and draw.io MCP, and independent validity checks to bound the comparison. The main empirical message is not just higher end performance, but shorter and more stable trajectories. GUI agents pay a large step budget and are fragile to grounding, focus, timing, and layout errors. ASIL compresses many multi-step GUI procedures into one or a few semantic actions.
