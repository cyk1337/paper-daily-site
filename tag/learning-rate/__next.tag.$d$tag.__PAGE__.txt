a:Ta77,方法分两阶段。第一阶段是 empirical law discovery。作者先在小规模 proxy 模型上系统扫描不同 compute budget、学习率和 batch size，观察在 continued pre-training 过程中最优超参如何随训练推进而变化。全文给出的主要经验规律是：随着可用 compute 增加，最优 batch size 单调增大，而最优 learning rate 相应减小。这里的“相应”不是口头描述，而是通过标准 loss-compute scaling 关系推导出从 compute 到最优超参的函数映射。也就是说，作者不是直接拟合“步数→超参”，而是先把训练轨迹放到 compute/loss 坐标里，再建立超参最优点的函数形式。这个设计的好处是更容易跨模型规模和训练阶段迁移。

第二阶段是 quantifying the initial optimization state，也就是论文最关键的 equivalent pre-training compute。作者认为，一个任意 checkpoint 虽然来自别的预训练分布，但仍可以在目标域上通过 validation loss 定位到一条连续训练轨迹上的某个坐标。具体做法是：先在目标域上建立 loss 与 compute 的对应关系，再把 checkpoint 当前的 target-domain validation loss 映射成一个等效的已投入算力 C_pre。之后，把计划中的 continued pre-training 算力 C_cpt 加上去，得到总有效算力 C_total = C_pre + C_cpt。最后，把 C_total 代入第一阶段得到的超参标度律，直接预测该 run 的最优学习率和 batch size。

这个框架和传统做法的区别有三点。其一，传统 recipe 往往只看模型参数量、token 数或经验 warmup 规则，而这里显式把“checkpoint 当前状态”作为一等公民。其二，传统超参迁移通常依赖同架构、同数据、相近训练阶段的经验复用；这里试图用 loss-based coordinate 把不同生命周期的 checkpoint 放到统一坐标系。其三，很多 CPT 调参默认先固定 batch 再找 LR，或者反过来分步搜索；这篇工作把二者都写成 compute 的函数，目标是一次性 zero-shot 给出配置。

从全文表述看，这个方法隐含几个前提。一个前提是 target-domain loss 与有效 compute 之间存在足够平滑、可拟合的关系，否则 C_pre 的反演会不稳。另一个前提是 proxy 模型上发现的最优超参函数在更大模型和不同架构上保持形状稳定，只需做尺度迁移。论文声称 Dense 和 MoE 都验证了这一点，但阅读时需要特别留意：这种稳定性到底是“趋势一致”，还是参数化形式和系数都能可靠迁移。这里决定了方法是 recipe 级工具，还是只是一种较好的初始化器。b:T8e2,The method has two stages.

Stage 1 is empirical law discovery. The authors train small proxy models under continued pre-training across a range of compute budgets and hyperparameter settings, then identify how the optimal learning rate and batch size evolve as training proceeds. The main empirical pattern reported in the paper is that the optimal batch size increases monotonically with compute budget, while the optimal learning rate decreases accordingly. Rather than fitting hyperparameters directly against steps, the framework uses standard loss-compute scaling relationships to derive mappings from compute to optimal hyperparameters. This is an important design choice because compute is a more transferable coordinate than raw step count when model size and setup vary.

Stage 2 is quantifying the initial optimization state. This is the key conceptual move. A checkpoint inherited from prior pre-training is treated as a point on a continuous target-domain training trajectory. The paper maps the checkpoint’s validation loss on the target domain to an equivalent amount of pre-training compute, denoted C_pre. Planned continued pre-training compute is C_cpt, and the total effective compute becomes C_total = C_pre + C_cpt. The optimal learning rate and batch size are then predicted zero-shot by plugging C_total into the scaling laws discovered in Stage 1.

Compared with standard practice, the framework differs in three ways. First, it explicitly models checkpoint state instead of relying on model size, token count, or inherited recipes alone. Second, it uses a loss-based coordinate system to place checkpoints from different lifecycle stages onto a common axis. Third, it aims to predict both LR and batch size jointly, instead of doing sequential search or fixing one while tuning the other.

The proxy-discovered hyperparameter laws must also transfer in shape across larger scales and different architectures.
