9:T655,The design has three central pieces. First, the model uses a Causal Encoder-Decoder architecture. The encoder handles the causal prefill side, and decoder global KV is projected from the final encoder hidden states. This gives a cheaper prefill path and a stronger decode path, matching input-heavy agent workloads. Second, the paper introduces Compressed Sparse Attention 2, or CSA2. DeepSeek-V4 can be viewed as a sliding-window local-processing backbone plus compressed global context; V4.1-Flash keeps SWA in every layer but simplifies the global branch. CSA2 statically assigns layers to Full, Reindex, and Reuse modes. Full layers generate global KV and perform indexing. Reindex layers reuse global KV from a previous layer but use their own indexer Q to rescore shared indexer K and select fresh Top-K indices. Reuse layers reuse both global KV and Top-K indices. Each layer still keeps its own global Q and local SWA KV, so the method shares the expensive global cache components without collapsing all attention behavior into one shared layer. Third, the system combines FP4 global KV cache training with SWA Bounded Replay. FP4 global KV reduces runtime cache size with only small degradation. SWA Bounded Replay avoids persisting SWA KV to SSD by replaying only the most recent n_win tokens, rather than the L × n_win replay needed for exact reconstruction in the earlier design. Additional components include pure CSA2 instead of the previous CSA-HCA hybrid, Single-Pass mHC with a Mega-mHC kernel that halves activation memory traffic, the Engram conditional memory module, and DSpark speculative decoding.a:T40b,LSA has three complementary mechanisms. Streaming-Aware Indexing allocates part of the sparse-attention budget to predictable contiguous regions, namely attention sinks and a local sliding window, while using the remaining budget for dynamic token-level selection; this allows the core attention operator to use coalesced accesses over contiguous KV blocks. Cross-Layer Indexing exploits the observation that salient tokens are often consistent across adjacent layers: consecutive N layers are grouped, only the owner layer runs the indexer, and reuse layers share its selected tokens. A cross-layer distillation objective trains the owner indexer to capture tokens salient to the whole group, reducing indexing computation to roughly 1/N. Hierarchical Indexing is a training-free inference module that first retrieves top-M candidate pages from block-level representations and then performs fine-grained token scoring only within those pages, reducing per-query selection complexity from O(L) to O(L/P + MP), where P is the page size.b:T48e,PIVOT groups nearby queries and replaces multiple full-prefix scans with one shared scan. A group is aggregated into a single proxy query, which traverses the prefix once and selects a shared candidate set of size c. Then there are two variants. PIVOT-Refine rescoring: each query re-scores only the shared candidate set and picks its own top-k. This changes per-query work from O(L) to O(c), where k < c << L. PIVOT-Reuse is cheaper: it directly reuses the proxy top-k for all queries in the group, skipping per-query refinement. For a group of size g, indexing cost drops from O(gL) to O(L + gc) for Refine or O(L) for Reuse. The method relies on two empirical properties shown in the paper: high top-k overlap among nearby queries, and long-tailed indexer scores along the key axis, so a candidate budget only slightly above k is often enough. Importantly, PIVOT preserves the DSA interface and leaves the downstream Sparse MLA operator unchanged, making it a drop-in replacement. In prefill, groups are formed by contiguous query positions; in decode, the d+1 tokens from one multi-token prediction step form a natural group, so PIVOT composes with MTP speedups.c:T5e2,The central object is a blueprint: a dependency graph whose nodes are formal definitions and lemmas, and whose edges encode proof dependencies leading to the target theorem. The pipeline has three stages. First, blueprint generation: given the target theorem statement, optionally with a natural-language proof, the architect model emits a Lean file containing formally stated intermediate nodes and declared dependencies. Second, node proving: a tool-using Lean prover attempts to close open lemma nodes, using the declared dependencies and retrieval over Mathlib. These node-level proof attempts can run in parallel, which is important because the graph exposes independent subproblems. Third, global refinement: failed nodes are not handled only by deeper local decomposition. Instead, failure information is sent back to the architect, which can rewrite the blueprint globally by changing intermediate lemmas, adding or removing definitions, or restructuring dependencies.

This differs from recursive decomposition pipelines, where an early bad split can trap the system in an unproductive subtree. It also differs from Draft-Sketch-Prove style approaches. There, the informal proof becomes a flat sketch with placeholders. Here, the optional natural-language proof is converted into a graph of named sublemmas, which is easier to revise and recombine. Third, cost accounting: number of architect/prover calls, token usage, and retry overhead. For a systems paper like this, those details matter as much as pass rate.
