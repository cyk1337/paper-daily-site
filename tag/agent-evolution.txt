18:T7eb,方法分三阶段。Stage 1 先构造 evaluator。输入是任务指令、初始状态和只读观测接口。系统里有 Test-Suite Generator 和 Verifier Evolver 两个模型角色。前者从指令中抽取应满足的状态约束，生成正例、负例和 adversarial near-miss challenge states；这些 challenge 不是纯文本描述，而是通过 deterministic category adapters 物化成真实环境状态。后者基于这些 challenge states 合成 task-specific executable evaluator。这里的关键不是追求一次性完全复现专家 verifier，而是先得到一个能通过内部 gate、可用于搜索的 evaluator。Stage 2 用 frozen evaluator 做 workflow evolution。系统维护 persistent multi-alternative workflow nodes，也就是每个节点保留多个行为候选，而不是把一次 rollout 当成一次性轨迹；这样做更像在程序空间里做局部演化。Workflow Executor 执行候选 workflow，frozen evaluator 给出稳定 fitness signal，Workflow Evolver 再据此改写 workflow。作者刻意把 evaluator 冻结，避免搜索过程因为 reward function 漂移而失稳。Stage 3 做 evaluator revision。外部 benchmark verifier 不进入搜索环，只在环外做三件事：准入 evaluator、识别内部接受但外部失败的 false positives、以及最终测量结果。对于 false positive，系统比较 strong executor 与 weak executor 的最终状态差异，把这些 instruction-grounded differences 挖成 paired counterfactual test cases，再让 Verifier Evolver 生成修订版 evaluator。修订版只有在 cumulative regression 通过后才会被提升并再次冻结。这个设计里最有意思的点有两个：一是 evaluator-first，而不是 search-first；二是 revision 信号来自 state difference，而不是直接模仿外部 verifier。论文还讨论了 observability 和 state representation 的限制：如果观测接口看不到关键状态，或者状态难以规范化表示，自动 verifier 的上限会明显受限。19:T817,The framework has three stages. Stage 1 constructs the evaluator. Given a task instruction, initial state, and read-only observation interface, a Test-Suite Generator derives positive, negative, and adversarial near-miss challenge states implied by the instruction. These are not just textual descriptions: deterministic category adapters materialize them into actual environment states. A Verifier Evolver then synthesizes a task-specific executable evaluator over these states. The goal is not to perfectly reproduce an expert verifier in one shot, but to obtain an evaluator that passes internal gates and is good enough to support search. Stage 2 performs workflow evolution under a frozen evaluator. The system maintains persistent multi-alternative workflow nodes, so the search space is structured more like evolving a reusable workflow graph than sampling one-off trajectories. A Workflow Executor runs candidate workflows, the frozen evaluator provides a stable fitness signal, and a Workflow Evolver updates the workflow accordingly. Freezing the evaluator is a deliberate design choice to avoid reward drift during optimization. Stage 3 revises the evaluator. An external benchmark verifier is kept outside the search loop and is used only for admission, false-positive detection, and final measurement. When an internally accepted state fails external verification, the system compares strong-executor and weak-executor end states, mines instruction-grounded differences into paired counterfactual test cases, and asks the Verifier Evolver to produce a revised evaluator. The revision is promoted only after cumulative regression checks and is then frozen again. Two design choices stand out: evaluator-first rather than search-first, and revision driven by state differences rather than direct imitation of the external verifier. The paper also makes clear that observability and state representation are hard limits: if the observation interface misses critical state or the state cannot be normalized cleanly, automatic verifier synthesis degrades quickly.1a:T6a6,The main controlled study covers all 30 MCPMark Filesystem tasks. On these generated suites, agreement with the external verifier is 141/141. More importantly, on 122 held-out states later produced by executor agents, agreement is 113/122, showing some generalization beyond the construction set. With GLM-5.2 as the weaker executor, workflow evolution improves externally verified success from 6/30 at round 0 to 18/30. With Claude as the stronger executor, success rises from 27/30 to 30/30. This suggests the evaluator is especially useful as a workflow-organizing signal for weaker models. In all three cases, strong–weak state differences produce regression-validated evaluator revisions that remove the original errors; in structure_mirror, the weak executor reaches an externally valid state after a single revision.
