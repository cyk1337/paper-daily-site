18:T58f,REM (Reusable Experience Memory) introduces three explicit decisions, executed from within the agent’s loop:
1) What to store:
- Each completed run is a 55K–170K token trajectory with heavy exploration noise.
- REM consolidates it into a phase-structured document organized by four phases: localize, understand, fix, verify. This document is both the retrieval unit and the primary injected context, avoiding duplicated token spending.
- The design choice is deliberate: not raw trajectories (too noisy and context-hungry), not atomized factoids (lose solution structure).
2) When to recall:
- Two-tier read path: the phase document is injected at task start; a much costlier “implementation record” (fine-grained details closer to the original trace) is withheld.
- A struggle-gated in-loop node injects the implementation record only when the running agent appears stuck, leveraging the fact that the agent state is observable only inside the loop.
3) What to forget:
- The implementation record is evicted after a single exposure (one-shot eviction) to prevent persistent bias; the phase document remains for the whole run.
Additionally, the only domain-specific artifact is an extraction schema, which the paper claims can be automatically discovered from example trajectories. Ablations are framed to show gains come mainly from the stored form, while gating/eviction prevent the second tier from causing harm.19:T7a1,FedSkillGit is explicitly inspired by Git-style incremental collaboration. The server maintains a shared skill document d and a global experience document e. Each client has private train/validation splits and four LLM-based roles: an executor for task execution, a skill optimizer for local refinement, a sanitizer for privacy cleaning, and an auditor for private-value checking. Instead of uploading a rewritten full skill document, the client generates semantic commits: localized skill patches together with supporting experience summaries.

The pipeline has several stages. First, local skill evolution: the client executes tasks using the current global skill and global experience context, collects local successes and failures, and asks the optimizer to produce revisions. Second, two-stage privacy filtering: a sanitizer rewrites or removes sensitive content, and an auditor checks whether the commit still contains private values or environment-specific details. This is not formal differential privacy; it is semantic privacy filtering performed by LLM agents. Third, cross-round experience reuse: the server maintains a global experience document that accumulates reusable evidence over rounds and redistributes it to clients, reducing redundant rediscovery and making local optimization more informed. Fourth, experience-aware aggregation: the server uses a merge agent to combine commits with reference to the global experience document, rather than simply concatenating or voting over full documents. Fifth, version validation: a candidate updated skill is only published if it passes validation.

Relative to straightforward federated baselines, the key differences are the shift from document-level to commit-level updates, the inclusion of evidence alongside edits, and the explicit use of a shared experience memory. That makes the system closer to collaborative knowledge editing with validation than to standard federated averaging.1a:T63a,The paper reports experiments on three datasets and three LM families. The headline result is that FedSkillGit outperforms the strongest baseline by up to 22% and approaches centralized performance. From the provided full-text excerpt, the most reliable takeaways are as follows.

First, overall effectiveness: the gains appear across multiple datasets and backbones, suggesting that the improvement is not tied to a single model family or task distribution. The paper positions the method against federated baselines that evolve and aggregate full skill documents, and the reported gap indicates that the update representation itself matters.

Second, communication and privacy motivation: because the method transmits semantic commits rather than full documents, the communication cost should scale with newly acquired knowledge instead of accumulated skill length. When reading the full paper, the most important tables and plots to verify are communication curves, average commit size, and how document growth behaves over rounds.

Third, ablations: the architecture strongly suggests useful ablations around removing privacy filtering, removing the global experience document, disabling version validation, and replacing commit-level aggregation with full-document aggregation. Those ablations are likely where the paper justifies why each component exists.

The excerpt provided here does not include the full experimental tables, exact model sizes, or dataset sizes, so precise numbers beyond the reported “up to 22%” should be checked directly in the original paper before citation.1b:T842,方法核心是 FEB-30，一个面向 fact evolution 的 memory benchmark，以及与之配套的 intrinsic scoring 框架。

数据设计上，FEB-30 包含 30 条 fact-evolution trajectories，覆盖 6 个诊断类别和 3 个难度等级。6 个类别分别对应外在 QA 评测看不清的不同失败模式：
1. C1 LLM Compensation：memory 状态错了，但模型仍可能答对。
2. C2 Retrieval Bottleneck：memory 对了，但 retrieval 因词汇不匹配或抽象层级差异而失败。
3. C3 Classification Accuracy：系统是否正确判断新观察是 create、update、reinforce 还是 conflict。
4. C4 Synthesis Quality：多来源观察是否被正确合并成事实，哪些该合并，哪些应分开。
5. C5 Temporal Correctness：事实随时间演化、撤回、漂移时，memory state 是否保持正确时序。
6. C6 Multi-Author Attribution：不同作者来源对 corroboration、冲突处理、置信度整合的影响是否被正确建模。

这篇工作的关键创新不是类别枚举，而是数据生成范式。作者采用 paradigm inversion：不是先收集文档再人工标注事实，而是先定义每条 trajectory 在每个 state 应该有哪些 atomic claims、如何演化，再据此生成文档。这样 ground truth 从一开始就是确定的。文中还提到 multi-model rotation 和 3-judge verification，用来控制生成文档质量与事实一致性，减少单模型模板化偏差。

FEB-30 contains 30 fact-evolution trajectories spanning 6 diagnostic categories and 3 difficulty levels. The categories are designed to isolate failure modes that extrinsic QA-based evaluation cannot disentangle:
1. C1, LLM Compensation: the memory state is wrong, but the model may still answer correctly.
2. C2, Retrieval Bottleneck: the memory state is correct, but retrieval fails because of lexical mismatch or abstraction mismatch.
3. C3, Classification Accuracy: whether the system correctly classifies observations as create, update, reinforce, or conflict.
4. C4, Synthesis Quality: whether evidence from multiple artifacts is merged into the right fact structure.
5. C5, Temporal Correctness: whether the memory state tracks temporal evolution, retraction, and drift correctly.
6. C6, Multi-Author Attribution: whether source identity is handled correctly in corroboration, conflict handling, and confidence updates.

Difficulty is controlled in a structured way. L1 is close to surface matching, with target claims appearing almost verbatim. L2 embeds claims in more realistic document context. L3 requires inference from multiple statements and includes substantial distractor content.

The most important design choice is what the authors call paradigm inversion. Instead of starting from documents and then annotating facts, they first define the exact atomic claims that should hold at each state of a trajectory, then generate documents from those trajectories. This makes the ground truth deterministic from the start. The pipeline also uses multi-model rotation and three-judge verification to reduce generator-specific artifacts and improve factual consistency.

Evaluation is split into intrinsic and extrinsic metrics. Intrinsic evaluation directly compares the memory store against the state-specific ground truth, using metrics such as claim coverage, update detection, and false update rate. Extrinsic evaluation keeps the usual QA accuracy. The point is not to replace end-to-end evaluation, but to complement it with a unit-test-like view of the memory component itself.1d:T5bf,The central empirical result is straightforward: intrinsic and extrinsic evaluations diverge substantially. The paper reports an average gap of 16 percentage points, and 44% of trajectories show what the authors consider a meaningful divergence. This is the main evidence that QA accuracy alone is not a reliable measure of memory quality.

By construction, C1 and C2 are the clearest demonstrations of the problem. C1 produces cases where systems answer correctly despite broken memory. C2 produces cases where memory is correct but the final answer is wrong because retrieval fails. Categories C3 through C6 are more diagnostic of internal memory-pipeline behavior, including update classification, synthesis, temporal consistency, and source attribution. Two systems with similar QA scores can therefore have very different internal memory quality.
