18:T402,Repo2Skill-Evo is built as:
1) A fixed V1 skill set produced by Repo2Skill via staged distillation plus expert refinement. Each skill is packaged (e.g., SKILL.md, optional scripts/references) and augmented with provenance metadata (source paths/symbols) to enable traceability.
2) A maintenance task: given the official V1→V2 release patch, a maintenance agent must delete or revise patch-verified obsolete skill lines while preserving still-valid content. The design intentionally emphasizes minimal, selective edits rather than full regeneration.
3) Evaluation: a strict patch-grounded headline metric that rewards correct edits on verified obsolete lines and penalizes edits elsewhere, plus a rubric-based NL judge with five dimensions for overall quality.
The analysis frames two complementary bottlenecks: incomplete localization of affected skill files (coverage) and imperfect edit selection (precision/within-file evidence tracing). An oracle localization experiment tests how much of the gap is purely localization.19:T723,The central proposal is Knowledge Triage. The authors derive a five-type knowledge model from 396,934 agent artifacts and argue that this is the coarsest partition that still supports distinct safety guarantees. The exact labels are written as {C, P, B, F, E}; the important point is that each type tolerates a different kind of distortion. Constraints require wording-level fidelity, procedures allow behavior-preserving rewrites, and episodic logs can be aggressively summarized or dropped.

The knowledge base is formalized as K=(I, τ, T, π, σ), where I is the item set, τ is the type classifier, T is a topic tree, π maps items to topic leaves, and σ defines the scope of constraint items. This lets the paper unify three context-management operations under one typed budget-allocation view:
1. TypeCompact: in-place budget reduction with type-specific fidelity policies instead of uniform summarization.
2. TypeDecompose: splitting oversized topics before compression, so non-compressible constraints are not mixed with compressible background material.
3. TypeRetrieve: retrieval from external memory that is aware of item type, not just semantic relevance.

Two supporting components are added. A post-compaction guard verifier checks whether critical guards remain enforceable after rewriting. A SafetyMargin classifier scores items by counterfactual safety impact rather than surface form, which is more meaningful than keyword-based rule detection.

A strong point of the paper is that it does not stop at empirical anecdotes. It states per-operator safety requirements and argues that type-blind strategies cannot satisfy them across compaction, decomposition, and retrieval. The claim is therefore structural: one fidelity policy cannot serve heterogeneous knowledge objects with incompatible loss tolerances.1a:T5d4,The empirical section has two layers. First, it measures the failure mode directly. On 20 production agent configurations, Claude Code’s /compact prompt on Sonnet 4.6 preserves only 53% of safety rules after one compaction round and 10% after five rounds. The introduction also cites about 50% safety-constraint retention under hierarchical truncation on 50 real agent configurations. This rapid decay is the Compaction Cliff. The paper further reports that the same pattern appears across four LLM compactor families and the strongest non-LLM compressor they tested, which supports the claim that the issue is structural rather than model-specific.

Second, it validates the proposed framework. The authors build AgentArtifactCorpus with 396,934 artifacts from 54,628 public GitHub repositories and provide 2,000 type annotations. Their five-type taxonomy covers 97% of real configuration content, which is an important practical check. End-to-end validation on five public corpora shows that typed triage, together with the guard verifier and SafetyMargin classifier, preserves safety constraints better than uniform compaction without giving up too much budget efficiency. The excerpt provided here does not include the full result tables, so the exact gains beyond the headline recall numbers cannot be reproduced faithfully. Still, the main empirical signal is clear: the benefit is concentrated in constraint retention and multi-round robustness, not in generic summarization quality.1b:T47b,For a quick read, start with the introduction and the figure that plots the Compaction Cliff.
