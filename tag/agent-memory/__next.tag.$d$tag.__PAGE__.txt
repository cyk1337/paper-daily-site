a:T402,Repo2Skill-Evo is built as:
1) A fixed V1 skill set produced by Repo2Skill via staged distillation plus expert refinement. Each skill is packaged (e.g., SKILL.md, optional scripts/references) and augmented with provenance metadata (source paths/symbols) to enable traceability.
2) A maintenance task: given the official V1→V2 release patch, a maintenance agent must delete or revise patch-verified obsolete skill lines while preserving still-valid content. The design intentionally emphasizes minimal, selective edits rather than full regeneration.
3) Evaluation: a strict patch-grounded headline metric that rewards correct edits on verified obsolete lines and penalizes edits elsewhere, plus a rubric-based NL judge with five dimensions for overall quality.
The analysis frames two complementary bottlenecks: incomplete localization of affected skill files (coverage) and imperfect edit selection (precision/within-file evidence tracing). An oracle localization experiment tests how much of the gap is purely localization.b:T723,The central proposal is Knowledge Triage. The authors derive a five-type knowledge model from 396,934 agent artifacts and argue that this is the coarsest partition that still supports distinct safety guarantees. The exact labels are written as {C, P, B, F, E}; the important point is that each type tolerates a different kind of distortion. Constraints require wording-level fidelity, procedures allow behavior-preserving rewrites, and episodic logs can be aggressively summarized or dropped.

The knowledge base is formalized as K=(I, τ, T, π, σ), where I is the item set, τ is the type classifier, T is a topic tree, π maps items to topic leaves, and σ defines the scope of constraint items. This lets the paper unify three context-management operations under one typed budget-allocation view:
1. TypeCompact: in-place budget reduction with type-specific fidelity policies instead of uniform summarization.
2. TypeDecompose: splitting oversized topics before compression, so non-compressible constraints are not mixed with compressible background material.
3. TypeRetrieve: retrieval from external memory that is aware of item type, not just semantic relevance.

Two supporting components are added. A post-compaction guard verifier checks whether critical guards remain enforceable after rewriting. A SafetyMargin classifier scores items by counterfactual safety impact rather than surface form, which is more meaningful than keyword-based rule detection.

A strong point of the paper is that it does not stop at empirical anecdotes. It states per-operator safety requirements and argues that type-blind strategies cannot satisfy them across compaction, decomposition, and retrieval. The claim is therefore structural: one fidelity policy cannot serve heterogeneous knowledge objects with incompatible loss tolerances.c:T5d4,The empirical section has two layers. Reliable verification and broad retrieval coverage produce clear gains, while richer card formats, more elaborate retrievers, and repair-specific content do not show statistically supported advantages.10:T907,MemPrism explicitly separates persistent memory from decision-time working memory. The framework has five modules: Recorder, Router, Composer, Render, and Adapter. In inference, the first four form the main pipeline. Recorder stores real interactions as a unified event stream, keeping both raw events and structured fields such as pre-action observation, executed action, environment feedback, reward or step label, and task metadata. The point is to keep persistent memory neutral and reusable rather than collapsing it early into one fixed summary.

Router is the key learnable component. Instead of directly predicting the next environment action, it first decides how history should be viewed. A view action is defined over several axes: relation type, evidence range, outcome condition, and granularity. In other words, the policy chooses what relational structure to build, how much history to include, whether to filter by success/failure or other outcomes, and how coarse or fine the representation should be. This makes read-time memory representation an explicit decision variable.

Composer then selects events from the event stream and assembles a relational structure according to the chosen view action. Render converts that structure into an optical working-memory view. The optical format is not used only for token compression. The authors use two-dimensional layout to encode relations directly: spatial proximity groups related events, row/column alignment supports state comparison, arrows indicate change or dependency, and highlights emphasize failures or task-relevant evidence. A frozen task policy consumes the current input together with this temporary view and outputs the next environment action. The view is discarded after the step and is never written back into persistent memory, which avoids irreversible distortion from fixed summaries or repeated compression.

Training is also split cleanly. Router is first initialized with action-conditioned soft supervision, then optimized with trajectory-level grouped GRPO. The learning target is not the environment action itself, but the choice of memory view that best supports downstream action selection. This separation helps attribute gains to the memory representation interface rather than to a jointly entangled agent policy.11:T6a7,From the provided full-text excerpt, the experimental emphasis is on whether task-conditioned view selection improves long-horizon decision making, not on raw storage capacity. The paper appears to provide two kinds of evidence: end-task gains and attribution studies showing that the gains come from working-memory construction rather than unrelated components. The training setup for Router—soft supervision followed by grouped GRPO—is already designed to isolate the effect of view selection.

The excerpt does not include full tables or final numbers, so the exact quantitative gains cannot be stated reliably here. Still, the intended comparisons are clear: fixed representations such as timelines, summaries, or flat retrieved snippets are contrasted with dynamically constructed relational views defined by relation type, evidence range, outcome filter, and granularity. The expectation is that dynamic views are better matched to subtasks like loop detection, state tracking, failure analysis, and dependency reasoning.

Another likely experimental point is the decision not to write temporary views back into persistent memory. The authors argue that writing them back would bake task-local bias into long-term memory and reduce future reuse. A meaningful ablation should therefore compare persistent event streams plus on-demand views against fixed summary memories or recursively compressed memories.
