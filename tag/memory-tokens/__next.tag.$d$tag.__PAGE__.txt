9:T5e1,The method has two parts. First is Matryoshka-style training. Instead of training a compressor at one fixed K, the model samples K per training instance, so a single encoder learns to compress the same kind of context into different numbers of memory tokens. The underlying interface stays unchanged: an encoder LLM maps a context of length L into K continuous memory tokens, and a frozen decoder LLM consumes those soft tokens in place of the raw context. In practice, the encoder is usually a LoRA-adapted copy of the decoder. This makes the approach method-agnostic across ICAE, 500xCompressor, and SAC.

Second is inference-time budget selection. The paper proposes two strategies. Confidence-based cascade routing starts with the smallest, most aggressive budget and only retries with a larger K when the decoder is uncertain. This tends to preserve accuracy well, but may require multiple compression-decoding passes. The learned K predictor instead predicts the budget before compression, so inference runs in a single pass. That is more deployment-friendly because latency and throughput are easier to control.

An important empirical observation is that the accuracy-compression relation is not always monotonic at the instance level. Larger K can preserve distracting surface details and hurt the decoder, while K=1 can sometimes succeed where a larger budget fails. So adaptive budgeting is not just about saving tokens on easy cases; it also helps avoid over-preserving irrelevant information.a:T4c6,Experiments cover three compressor families—ICAE, 500xCompressor, and SAC—on in-domain and out-of-domain QA from MRQA. There are three main findings.

First, a single Matryoshka-trained model can largely replace a family of fixed-ratio specialists. At each native ratio, the gap to separately trained fixed-K models is at worst 1.3 F1, and the shared model is often better on OOD settings. That suggests multi-budget training does not significantly compromise specialization.

Second, adaptive budget selection improves the accuracy-compression trade-off. Cascade routing retains over 98% of the accuracy of the mildest compression setting while increasing average compression from 15x to as high as 266x. The learned K predictor reaches 158x–236x compression in a single compression-decoding pass, with at most 0.7 F1 loss.

Third, the gains translate into real serving metrics. At larger batch sizes, the K predictor reduces context KV cache by 50% and improves aggregate decoding throughput by 47% relative to always using the mildest budget. 真正的技术重点有三个。第一，memory tokens 被当作可学习寄存器，而不是普通前缀 token。作者系统扫了 token 数量，发现 81-cell Sudoku 上存在明显阈值：T=0 必败，T=4 处于临界区，T=8 开始稳定成功，T=8 到 32 基本进入平台区，再增大到 T=64 则因注意力稀释而退化。这说明 memory token 的作用不是“多一点上下文更好”，而是需要足够数量来承载中间状态，但过多又会稀释对问题 token 的注意力。

第二，作者把 ACT 失败归因到 router initialization trap。标准零偏置会让初始 halting probability 约为 0.5，Graves 的正偏置建议会更高到约 0.73，这两种都会让 token 在 1 到 2 步内过早停止。作者反过来采用 deep-start 初始化，把 halting bias 设为 -3，使初始 p 约为 0.05，等价于默认先跑满 K=18 步，再让模型学会在哪些位置提前停。这个设计背后的判断很清楚：对需要深计算的任务，先深后浅比先浅后深更容易优化，因为浅策略几乎不给“深度有用”这件事留下探索空间。

第三，作者做了较细的训练动态诊断。他们记录每步 router probability、step-weight 分布、router gradient norm 和注意力质量，发现能从 shallow-halt 中逃出的 run 往往伴随 router 梯度 10 到 45 倍的尖峰；而失败 run 的 router 梯度长期低于 0.04，说明 halting 子网络几乎被冻结。这个分析把“ACT 不稳定”从经验现象推进到更可操作的诊断框架。

At each step, the sequence is composed of learned memory tokens followed by the Sudoku tokens, and the whole sequence attends bidirectionally. The block uses attention plus SwiGLU, with per-step learned positional embeddings, RoPE, and QK normalization. The paper also uses a normalization-free variant called DerfNorm, but that is not the main source of the reported effect.

There are three technical points that matter. First, memory tokens are treated as persistent learned registers rather than generic prefix tokens. The authors sweep the number of memory tokens and find a sharp threshold: T=0 always fails, T=4 is borderline, T=8 reliably works, T=8 to 32 forms a broad plateau, and T=64 degrades because attention gets diluted. This is a stronger claim than “more tokens help.” It suggests a minimum state budget is needed for recursive computation, while too many state slots hurt token-to-problem interaction.

Second, the paper identifies an ACT router initialization trap. With zero bias, the initial halting probability is around 0.5; with the positive bias recommended in earlier ACT work, it is even higher, around 0.73. Both settings make tokens halt after roughly 1–2 steps. The proposed fix is a deep-start initialization with bias -3, giving p about 0.05. That means the model starts by using nearly the full depth budget and only later learns where to stop early. The rationale is simple and convincing: on tasks that truly need depth, starting shallow prevents the model from ever seeing evidence that deeper computation helps.

Third, the authors instrument the training dynamics in detail. They log per-step router probabilities, step-weight distributions, router gradient norms, and attention mass. Successful runs escaping the shallow-halting regime are associated with 10x to 45x spikes in router gradient norm, while failed runs keep router gradients near zero for the entire training trajectory. This turns ACT instability from a vague empirical complaint into a more diagnosable optimization phenomenon.

Relative to prior work, the paper does not introduce a new recursive architecture. Instead, it isolates two first-order factors inside the existing UT+ACT setup: explicit memory state and halting initialization.
