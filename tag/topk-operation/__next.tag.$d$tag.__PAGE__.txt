9:T763,The core idea is a sample-filter-select pipeline. Instead of maintaining exact scores for all candidates, the kernel first estimates where the eventual top-k region is likely to lie, then uses that threshold range to discard hopeless candidates during the main pass.

The method has three stages. First, sampling. The paper uses a locality assumption in sparse attention: adjacent token chunks often attend to similar historical tokens, so their score distributions are similar. LiteTopK therefore reuses the previous chunk’s top-k' scores as a lightweight sample; for DSA, the paper uses k' = 3k. Second, quantization and histogramming. The estimated score range is partitioned into equal-width bins, a histogram is initialized, and the bin containing the local top-k boundary is identified as the threshold bin. Third, fused filtering. During the full candidate scan, the kernel computes scores and dynamically maintains the threshold bin. The upper bound of that bin is used to filter out candidates that are unlikely to enter the final top-k, so only a small subset needs to be written back and processed further.

Several implementation choices are notable. The kernel replaces the original score computation path with direct bin-ID computation to avoid extra latency. Histogram updates are handled by idle warps using overwrite-style writes rather than lock-based synchronization; a slightly stale or loose threshold is acceptable because it does not break correctness, only filtering aggressiveness. The whole design relies on a high-dimensional concentration effect: most similarity scores lie in a narrow range, while truly large scores are rare long-tail events.
