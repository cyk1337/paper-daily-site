第二部分是 operator invocation policy。模型在每个解码步不再只在词表上做 next-token 预测，而是在“生成可见 token”与“调用某个 latent operator 并指定预算”之间做选择。也就是说，动作空间包含 visible decoding 和若干 latent actions，latent action 还带 budget 维度，决定插入多少 latent tokens。这样模型可以在简单位置直接输出文本，在困难位置先做内部计算，再回到显式生成。

训练分两阶段。Stage 1 先冻结主 LLM，只训练 latent operators 和 latent synthesis module，让每个 operator 对齐到预设的功能角色。这里作者引入 Latent Synthesis Model，把 operator identity 与当前状态映射成一段可被主模型消费的 latent token 序列。先冻结 backbone 的目的很明确：避免在早期把“operator 学什么”和“主模型如何适配 latent interface”纠缠在一起，降低训练不稳定性。Stage 2 再固定 Stage 1 学到的 latent interface，只训练调用策略，使用 GRPO 做策略优化。奖励来自最终任务表现，因此 policy 学的是何时调用、调用哪种 operator、预算给多少。由于 operator invocation 是稀疏事件，作者还加了 operator-anchored auxiliary objective 来稳定训练，避免 policy 在少量触发位置上梯度过弱或塌缩到单一动作。

First, it introduces typed latent operators. The model can invoke three operator types: Og for global orientation, Os for state update, and Op for procedural abstraction. Each operator takes the current decoding state and produces a sequence of operator-conditioned latent tokens, which are appended to the context and consumed by the same autoregressive backbone. The key idea is not latent-token insertion by itself, but functional specialization: latent computation is decomposed into reusable roles rather than collapsed into a single generic latent mode.

Second, Tyler learns an operator-invocation policy. At each decoding step, the model chooses between emitting a visible token and invoking one of the latent operators with a certain budget. The budget controls how much latent computation is inserted, typically via the number of latent tokens or latent steps. This turns decoding into a mixed action process: direct visible generation for easy steps, internal computation for harder ones.

Training is split into two stages. In Stage 1, the backbone LM is frozen while the latent operators and the latent synthesis module are trained. This isolates the problem of learning a usable latent interface from the problem of policy learning. The latent synthesis module maps the current state plus operator identity into latent-token sequences that the frozen LM can consume. In Stage 2, the learned latent interface is fixed and only the invocation policy is optimized with GRPO. The policy learns when to call an operator, which operator to call, and how much budget to allocate, using task-level reward. Because operator calls are sparse events, the paper adds an operator-anchored auxiliary objective to stabilize learning and prevent collapse or weak gradients at invocation positions.
