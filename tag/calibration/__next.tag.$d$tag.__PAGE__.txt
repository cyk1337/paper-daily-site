9:T80b,DecisionPivot 是一个诊断型 benchmark，而不是新模型。它的设计有几个关键点。

1. 两条评测轨。core track 是作者生成的受控任务，共 7,800 个样本，来自 13 个 task family，按 contrast group 组织。reference track 是 35 个公开测试集，共 32,233 个样本，保留原始评测协议和已知训练重叠信息。前者强调可控诊断，后者强调和既有工作可比。
2. typed decision interface。每个样本都写成 state、typed question、finite option set 的统一形式，模型输出对各选项的概率分布。这样 routing、guardrail、verification、goal checking 等不同角色可以放在同一接口下比较。
3. 七类 decision role。覆盖从 answerability / routing，到 policy guardrail、output verification、agent loop 中的 tool validation / goal checking，再到 reasoning-based classification、record reconciliation、constraint-based matching。作者想表达的是：LLM 系统里“决策”无处不在，而且这些决策共享一套概率输出与阈值控制问题。
4. contrast-group 设计。core track 的关键创新在这里。多数 task family 通过只改一个 pivotal detail 来改变正确答案，同时尽量保持上下文和表面形式不变。这样可以测模型是否真的抓住决定性变量，而不是靠模板、长度、词面线索做猜测。
5. 独立求解器验证。core 样本答案由独立实现的 solver 计算并验证，减少人工标注噪声，也降低 benchmark 本身出错的风险。
6. 评测指标不只看 accuracy。作者同时看 item accuracy、pair accuracy（更一般地说是 contrast-group 全对率）、probability ordering、calibration、selective coverage。这里 pair accuracy 很关键，因为它要求一个对比组里的所有变体都答对，能直接暴露“只会答一半”的脆弱性。

方法上的价值不在模型算法，而在评测协议：它把 decision quality 拆成 correctness、consistency、confidence reliability 三层，而不是混成一个总分。a:T7d1,DecisionPivot is a benchmark and evaluation protocol rather than a new model. Its design has several notable elements.

1. Two-track structure. The core track contains 7,800 generated items from 13 task families, organized into contrast groups for controlled diagnosis. The reference track contains 32,233 items from 35 public test sets, preserving original metrics and available overlap information. The first track gives control; the second gives comparability.
2. Typed decision interface. Every item is represented as a state, a typed question, and a finite option set. Models output a probability distribution over options. This allows routing, guardrails, output verification, and goal checking to be evaluated under a common interface.
3. Seven decision roles. The benchmark spans answerability and routing, policy guardrails, output verification, tool validation or goal checking in agent loops, reasoning-based classification, record reconciliation, and constraint-based search or matching.
4. Contrast-group construction. This is the core methodological contribution. In most generated families, a pivotal detail is changed while surrounding context remains largely fixed. The correct answer changes accordingly. This tests whether the model is sensitive to the actual decision variable rather than exploiting surface patterns.
5. Independent solver verification. Core answers are computed and checked by independently implemented solvers, reducing annotation noise and benchmark errors.
6. Multi-faceted metrics. The evaluation includes item accuracy, pair accuracy or full contrast-group correctness, probability ordering, calibration, and selective coverage. Pair accuracy is especially useful because it requires all members of a contrast group to be correct, exposing brittle behavior that average accuracy can hide.

The main contribution is therefore an evaluation decomposition of decision quality into correctness, consistency under controlled variation, and confidence reliability.b:T62c,The empirical study is fairly broad. The benchmark is used to evaluate 40 decision models and 14 general models, including 11 open general models and 3 API chat models on the core track. Several findings stand out.

1. Similar scores on public reference sets do not imply similar controlled decision behavior. The paper highlights cases such as Perplexity Decider and JEV-27B, which look similar on the reference track but differ substantially in core pair accuracy.
2. Similar item accuracy does not imply similar confidence quality. Kev 27B and JEV-27B reportedly have nearly identical item accuracy but differ in how often they make high-confidence predictions and how often those predictions are correct.
3. Correct probability ordering is not the same as correct decisions. The binary contrast analysis shows that a model may rank options in a roughly sensible way yet still fail to produce the correct argmax consistently.
4. Reasoning settings help on some cases but do not uniformly fix decision failures. This matters because it shows that the problem is not simply solved by adding more chain-of-thought.
5. Freshly sampled cases from the generators are used to test ranking stability, which is a good safeguard against benchmark-specific overfitting.

The selected blocks are physically bypassed, and no recovery training is applied, which isolates the effect of block selection.11:T4a0,The method defines a three-action controller over trust, fallback, and expand. Trust emits the current evaluator-preferred answer, fallback emits a conservative answer that avoids further continuation, and expand buys one more unit of inference before the controller acts again. The same framework covers both width expansion and revision expansion.
For terminal actions, the target value is success probability minus compute cost. For expand, the ideal target is the Bellman continuation value. In practice, the system learns one confidence head per action: trust and fallback estimate terminal answer success, while expand estimates a rollout-based continuation-success surrogate. These predictions are then post-hoc calibrated, and an optional uncertainty penalty is applied near brittle decision boundaries. The theory gives two main results: local action selection is stable when score error is smaller than the compute-adjusted action gap, and regret accumulates along the realized expansion path.
