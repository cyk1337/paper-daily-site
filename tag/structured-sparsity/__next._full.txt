19:T881,WIDE 的方法可以拆成‘路由学习’和‘执行实现’两部分。

先看路由学习。作者做的是 token-wise dynamic width pruning：每个 token 在每一层都可以独立选择保留哪些 attention head groups 和哪些 FFN channel groups，而不是像已有动态方法那样只决定“这一层算不算”或“这一整个子模块跳不跳”。为了让这种选择既细粒度又不至于完全失去结构性，attention 侧按 GQA 对齐的 head groups 做选择，FFN 侧按可配置 channel groups 做选择。group size 是一个显式超参，控制灵活性与 kernel 效率的折中：组越小，路由越细；组越大，执行越规整。路由器本身是轻量 bottleneck router，并采用 differentiable router-only calibration，也就是主要训练路由决策而不大改主干权重；必要时再加一个可选的 LoRA recovery 来补回精度。这个 recipe 的好处是部署改动小、校准成本低，也避免了全模型重训。

再看执行实现。论文认为细粒度动态稀疏落不了地，主要卡在两个点：一是同步的 mask-to-index 转换开销，二是 token-specific gather/scatter 导致的执行不规则。WIDE 的解法是先做 mask reordering，把任意 token-wise routing pattern 重排成更规则的执行布局：同一 routing group 的 active tokens 被 pack 到 tile-aligned prefix 中。这样原本稀疏且离散的 token 分布，被转成更适合 GPU block/CTA 处理的局部连续布局。在此基础上，作者设计了多级 predication kernel：先用 hardware-agnostic predicate 跳过完全 inactive 的 CTA，再用 architecture-aware predicate 进一步跳过 inactive 的 memory packet 和 tensor-core fragment。也就是说，它不是简单把稀疏张量喂给通用 kernel，而是围绕动态宽度掩码重新组织数据流和计算流。

与已有动态深度剪枝相比，WIDE 的区别不只是粒度更细，还在于它把‘粒度设计’和‘kernel 形状’绑在一起。很多动态方法在论文里默认稀疏就会带来加速，但 WIDE 明确承认不规则性会吞掉收益，因此把重排和 predication 作为一等公民。1a:T7a6,The method has two tightly coupled parts: routing and execution.

On the routing side, WIDE performs token-wise dynamic width pruning. For each token at each layer, lightweight bottleneck routers select which attention-head groups and which FFN-channel groups remain active. This is finer than prior dynamic pruning methods that decide whether to execute or skip an entire layer or submodule. To preserve structure, attention groups are aligned with GQA groups, and FFN channels are partitioned into configurable groups. Group size is a key control knob: smaller groups give more flexibility, larger groups improve kernel regularity. Training is done through differentiable router-only calibration, so the backbone is minimally modified; an optional LoRA recovery stage can restore quality if needed.

On the execution side, the paper identifies two main bottlenecks that prevent fine-grained dynamic sparsity from yielding real speedups: synchronized mask-to-index conversion and irregular gather/scatter patterns. WIDE introduces mask reordering to transform arbitrary token-wise routing masks into a more structured execution layout. Active tokens for each routing group are packed into tile-aligned prefixes, which converts irregular sparsity into CTA-friendly regularity. Based on that layout, the kernels apply multi-stage predication: hardware-agnostic predicates skip fully inactive CTAs, while architecture-aware predicates further avoid inactive memory-loading packets and tensor-core fragments. In other words, WIDE does not simply feed sparse tensors into generic kernels; it reorganizes both data layout and compute scheduling around dynamic width masks.

What differentiates WIDE from prior dynamic depth pruning is not only finer granularity, but the explicit co-design between pruning pattern and kernel structure. The paper directly addresses the usual failure mode of dynamic sparsity: theoretical savings being eaten by execution overhead.1b:T5e5,From the provided content, the experimental story is clear even if not all numbers are visible here. The paper evaluates both prefill and decoding, and reports end-to-end acceleration rather than only kernel-level microbenchmarks. It compares against static structured pruning and prior dynamic sparsity baselines. The claimed outcome is a better quality-efficiency Pareto frontier: token-wise width allocation retains more useful capacity than coarse layer skipping, while the custom kernels allow a larger fraction of theoretical compute savings to become actual runtime gains.

The most important quantitative details to extract from the full paper are likely: model sizes and backbones used for evaluation; quality drop versus throughput gain under different sparsity targets; whether prefill and decode benefit similarly; and how much optional LoRA recovery helps beyond router-only calibration. Those numbers determine whether the method is mainly a systems win, mainly an algorithmic win, or genuinely both.

For ablations, the most informative ones should be: dynamic width pruning without the specialized kernels; the isolated effect of mask reordering; separate contributions from attention-group pruning and FFN-group pruning; and the trade-off curve as group size varies. These analyses answer the central question of the paper: whether the gain comes mostly from better adaptive sparsity patterns or from better execution engineering. If both are necessary, that is exactly the point of the work.1c:T479,For a quick read, follow two threads. First, understand why existing dynamic pruning often fails to deliver practical speedups. Second, see how WIDE converts irregular token-wise sparsity into GPU-friendly structured execution. Start with the introduction and the method overview figure to distinguish token-level dynamic width pruning from layer skipping. Then read the router design, group definition, and router-only calibration sections to understand what is being pruned and what is being trained.

After that, spend most of the time on the kernel section. The key pieces are mask reordering, tile-aligned packing, and multi-stage predication. Those are the parts that determine whether the method is deployable rather than only conceptually appealing. In the experiments, prioritize Pareto curves and end-to-end latency or throughput tables over standalone accuracy metrics. A 40-minute skim should be enough for the main idea. A deeper read is needed if you want to judge portability to another serving stack, especially around GPU assumptions, GQA dependence, batching behavior, and decode-time interaction with KV-cache access patterns.1d:T6d1,The method starts from MoEfication. Intermediate FFN neurons are clustered with balanced k-means and permuted into E contiguous blocks, each treated as an expert. This preserves the original FFN computation while exposing a structured expert decomposition.

The main change is the routing mechanism. LTE uses sigmoid scores and activates every expert whose score exceeds a threshold, which is effectively a set of independent Bernoulli-style decisions. PrunePath instead computes a softmax-normalized distribution over experts, sorts experts by probability, and activates the smallest prefix whose cumulative mass reaches a threshold tau. This introduces three useful properties:
1. experts compete with each other under normalization;
2. sparsity becomes a token-level global probability budget rather than an indirect threshold effect;
3. the number of active experts can vary across tokens.

Mechanistically, this sits between fixed top-k and independent thresholding. Fixed top-k is too rigid because every token gets the same expert count. Independent thresholding lacks a global budget and can over-activate. Cumulative-mass routing keeps adaptivity while making the budget explicit.

A second contribution is single-checkpoint dynamic sparsity. The model is trained progressively so that one checkpoint supports a range of tau values at inference time, tracing a smooth efficiency-accuracy frontier without retraining separate sparse variants.

On the systems side, the authors implement Triton kernels for sparse FFN inference in autoregressive decoding.
