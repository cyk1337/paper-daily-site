Precise but Uncoupled: Reviewer Precision Does Not Guarantee Critique Uptake in Multi-Agent Math Reasoning

这篇论文研究的是一个推理系统设计问题：在多 agent 数学推理里，专门设置 reviewer 角色是否真的能把错误解修正为正确解。作者给出的答案是否定的，至少在他们测试的层级式 planner-executor-reviewer（PER）协议里，reviewer 即便能高精度指出问题，solver 也常常不采纳这些批评，导致“批评质量”和“修复效果”脱钩。论文把这个现象命名为 reviewer–solver decoupling，并进一步把问题拆成三步：reviewer 是否发现了有用错误、solver 是否据此改变下一版答案、这种改变是否真的完成修复。这个拆解比只看最终 pass rate 更细，也更能解释为什么一些多 agent 设计看起来结构复杂，但收益并不稳定。

评反常识的多Agent协作机制结论，做推理时Agent编排或RL reviewer设计的重点看摘要中的精度与采纳率对比数据。
Chih-Hsuan Yang,Jingyan Jiang,Vikram Vasudevan,Cheng-Hau Yang,Huihuo Zheng,Le Chen,Eliu A. Huerta,Venkatram Vishwanath,Ian T. Foster,Rajeev Thakur

Formal Disco: Scalable Open-Ended Generation of Formally Verified Programs

这篇工作解决的是“形式化验证代码数据极度稀缺，导致开源模型很难学会 verification-aware 编程”这个瓶颈。问题不只是样本少，而是少在三个层面：一是语言本身稀有，像 Dafny、Verus、Frama-C 这类语言公开仓库很少；二是高质量样本必须同时包含规格、实现和证明，生成难度远高于普通代码；三是如果只靠单轮 LLM 直接生成，往往会陷入主题坍缩、程序过短、验证不过、分布单一。作者要解决的不是单个 verified program 的生成，而是如何构造一个可扩展的、持续产出多样化 verified programs 的合成数据系统，并把这些数据真正转化为开源模型在验证相关任务上的能力提升。

评多Agent迭代+形式验证自动校验的代码数据合成方案，做预训练代码数据合成/清洗的研究员值得看系统设计部分。
Gabriel Poesia,Simon Henniger,Tzu-Han Hsu,Yilun Du,Nada Amin
