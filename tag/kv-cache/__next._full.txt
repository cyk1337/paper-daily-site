18:T703,The method starts by separating queries into two behavioral types. Local queries mostly attend to nearby tokens. Global queries, associated with TRTs, attend back to distant earlier context. The paper then shows that these global queries are not scattered arbitrarily in query-embedding space; they form a small number of similarity clusters. This motivates beacon queries: a compact set of representative queries intended to approximate future global revisiting patterns.

At eviction time, BeaconKV does not score historical KV entries using only recent queries. It also keeps a small set of beacon queries. A token is retained not only if it matters to the current local decoding state, but also if it is important to one of these representative global queries. This gives the system a way to protect tokens that may not look useful now, but are likely to be revisited later.

Because decoding is online, beacon queries cannot be obtained by offline clustering over the full query history. The paper therefore proposes Continual Farthest Point Sampling, an online procedure that incrementally selects geometrically diverse queries while keeping memory bounded. Intuitively, it maintains a compact cover of the query space seen so far. Compared with storing the full query history, this is memory efficient; compared with using only recent queries, it preserves information about potential future global attention patterns.

Methodologically, BeaconKV is training-free. It does not modify model weights and does not require distillation or calibration. Its main distinction from RPC and R-KV is not a better redundancy score, but an explicit treatment of future-query mismatch: future important queries may differ from recent ones, and a small representative set can partially bridge that gap.19:T537,The evaluation covers four open reasoning models: R1-Distill-Qwen-7B, R1-Distill-Llama-8B, Qwen3-4B, and Qwen3-14B. Benchmarks include AIME24, MATH-500, LiveCodeBench, and GPQA-Diamond, spanning math, coding, and science reasoning.

Several headline results matter. First, across a range of cache budgets, BeaconKV generally outperforms RPC and R-KV, with accuracy gains of up to 31.7 percentage points. That large gap suggests that under aggressive compression, the dominant issue is wrong eviction rather than raw capacity alone. Second, under strong compression, peak GPU memory can be reduced by up to 5.8x while keeping accuracy close to full-KV inference. Third, throughput improves by more than 4.3x over the uncompressed baseline, so the benefit is not only fitting longer traces but also improving practical serving efficiency.

The most informative ablations are the mechanism checks: TRTs indeed exhibit long-range attention; global queries show cluster structure in embedding space; recent-query-only scoring fails to cover these future revisiting needs; and adding beacon queries better preserves the tokens that full-KV inference would later rely on. An inference-side state machine reads these tags online and constructs the attention mask dynamically. DA defines three modes. <global> allows access to the full context and is used when the model needs to survey or search broadly. <focus> commits the model to a specific region of the context, restricting attention to that region. <local> limits attention to recent generated tokens, avoiding long-context reads altogether. 第一部分是 Head-Local。Full-Head Mapping 的做法是：对每个目标层、目标 KV 头，从选定源层的所有源 KV 头拼接后做回归。作者认为这隐含了一个过强假设，即不同模型之间头的对应关系是全局稠密的。CacheBridge 改成 architecture-indexed 的局部支持：每个目标头只从一个源头块接收输入，但仍允许跨层聚合。这样做的直接效果是把每个目标头的 fan-in 从“所有源头”缩到“一个局部块”，系数数量按源头数成倍下降，文中是 8× 缩减。更重要的是，这个约束把映射偏置到更符合架构对应关系的子空间，减少了在架构差异较大时的错误耦合。

第二部分是 Attn-Repair。作者指出，传统 held-out R² 只衡量 cache 坐标重建，而生成质量取决于这些误差经过目标模型 query 与 attention 组合后的放大或抵消。因此相同的 KV 拟合误差，可能对应完全不同的续写漂移。Attn-Repair 的做法是按残差对接收模型 attention 输出的一阶影响来重加权，相当于让拟合更关注那些会真正改变后续注意力计算的方向，而不是平均对待所有 cache 坐标。为了避免权重过度集中到极少数样本，作者加入 effective-sample-size floor 来限制退化，但不改变在线映射形式。

第三部分是 Fused-Fit。由于不同目标层会选择不同源层支持，top-k layer 选择会造成碎片化 gather，通用拟合器在构建加权充分统计量时会反复做 scattered materialization、centering 和 weighting，内存流量很大。Fused-Fit 用新的 fused GPU kernel 在有界 panel 内直接构建 head-batched 矩阵乘法所需统计量，保持同样的 ridge solver 和同样的最终 mapper artifact，只是把离线构建过程做成结构感知的高效实现。这个部分没有改变数学目标，但大幅改善了 mapper construction 的时间和内存行为。

整体上，CacheBridge 不是提出新的在线推理协议，而是在“离线拟合、在线仿射应用”这个框架内，把支持结构、目标函数和实现路径都改得更贴近真实 continuation quality。1f:T9b6,CacheBridge combines three components and keeps the online deployment interface unchanged: an offline-fitted affine mapper that can be applied directly at handoff time.

The first component is Head-Local. Full-Head Mapping regresses each target KV head on the concatenation of all source KV heads from selected source layers. CacheBridge argues that this assumes an overly dense correspondence between models. Instead, each target head is restricted to a single architecture-indexed source-head block, while still allowing cross-layer aggregation. This reduces fan-in dramatically and cuts the coefficient count by the number of source heads, 8× in the reported setup. More importantly, it biases the mapping toward a subspace that better matches architectural locality, reducing harmful cross-head coupling when the source and target architectures differ.

The second component is Attn-Repair. The paper points out that held-out R² only measures coordinate-wise cache reconstruction, while continuation quality depends on how those errors propagate through the target model’s queries and attention computation. Two mappings with similar cache fit can therefore produce very different continuation drift. Attn-Repair reweights residuals according to their first-order effect on the receiver’s attention output. In other words, it emphasizes errors that actually matter for downstream attention behavior rather than treating all cache coordinates equally. An effective-sample-size floor prevents the weighting from collapsing onto a tiny subset of examples, while preserving the same online affine form.

The third component is Fused-Fit. Because different target layers may choose different source-layer supports, top-k support selection creates fragmented gather patterns. A generic fitter repeatedly materializes scattered tensors, centers them, and applies weights, so memory traffic becomes a major cost. Fused-Fit introduces a fused GPU kernel that constructs the weighted sufficient statistics directly in bounded panels for head-batched matrix multiplication. It does not change the ridge objective, the solver, or the deployed mapper artifact; it simply makes offline construction structure-aware and much more efficient.

Taken together, CacheBridge does not propose a new online protocol. It refines the existing offline-fit / online-affine-transfer framework by redesigning support structure, fitting objective, and construction path around actual continuation quality.20:T70b,The evaluation covers three transfer directions, with two difficult Ministral 3 directions and one Qwen3 direction being the most informative. The paper first uses Full-Head Mapping to expose model sensitivity. Under the same 500-sequence calibration protocol and the same 8×128 KV interface, transfer to Qwen3 32B remains close to the target baseline, 79.2% versus 80.2%. But the two Ministral 3 directions targeting 14B drop sharply to 52.2% and 44.4%. This shows that the existence of a linear transfer path does not mean dense all-head mapping is the right inductive bias.

CacheBridge recovers 20.4 and 31.6 HellaSwag points on those two difficult directions, while preserving 99.83% mean target retention on Qwen3 14B→32B. So the gain is not coming from overfitting to one architecture family. On efficiency, mapper storage on Qwen3 drops from 4.296 GB to 0.538 GB, roughly an 8× reduction, and online application is up to 3.0× faster. For offline construction, the median time to build the 500-sequence Qwen3 mapper is 8.63 seconds in the reported setup.

The paper also analyzes three important phenomena. First, application latency grows almost linearly with the number of supported source layers k; on Ministral 3B→14B, transfer approaches target-side re-prefill by k=16 and exceeds it from k=20 onward. That means uncontrolled support growth can erase the systems benefit of cache transfer. Second, KV fit and continuation quality are misaligned: similar R² can correspond to very different attention drift. Third, top-k support causes fragmented construction, which is exactly the bottleneck Fused-Fit addresses. The most useful aspect of the experiments is that they optimize quality, online cost, and offline construction cost together rather than reporting only transfer accuracy.21:T76c,The main idea is affix-oriented cache reuse. Instead of restricting reuse to shared prefixes, the paper generalizes it to any shared contiguous span, or affix, which may appear at the beginning, middle, or end of the context. This is a natural systems opportunity created by bidirectional attention: unlike AR models, DLLMs are not inherently prefix-centric.

The key challenge is deciding which affix-token KV states become meaningfully stale as the masked generation tokens evolve. ACache introduces Anchor Tokens for this purpose. It measures the cross-attention importance from masked generation tokens to affix tokens, identifies a small request-specific subset of influential affix tokens, and recomputes KV states only for those anchors. The remaining affix-token cache is reused. In effect, the method turns a coarse full-span refresh decision into a sparse token-level refresh decision.

Implementation-wise, ACache is built on top of Fast-dLLM. It replaces periodic full-cache recomputation with selective anchor-token recomputation, so it is an incremental but targeted improvement over existing approximate caching frameworks rather than a completely new inference stack. The authors also implement a shared-prefix prototype in Nano-vLLM to test whether the gains survive under a more realistic serving environment with paged memory management and continuous batching.

Relative to prior work, the distinction is clear. dLLM-Cache uses asymmetric prompt/response refresh and feature-similarity-based partial recomputation for response tokens. dKV-Cache focuses more on decoded-token reuse with delayed block recomputation. Fast-dLLM improves the overall inference framework but still relies on periodic refresh. ACache is novel in treating shared context itself as the optimization target and shrinking the recomputation unit from an entire shared span to a request-specific token subset.22:T504,The main results operate at three levels. First, quality recovery: compared with direct affix-cache reuse, which causes noticeable degradation, ACache recovers most of the lost accuracy across multiple benchmarks while recomputing only around 20% of affix tokens. That number matters because it suggests the stale-cache problem is sparse enough to be exploitable. Second, system gains: in the Nano-vLLM shared-prefix prototype, ACache reduces recomputation latency by up to 55.7% and improves end-to-end throughput by up to 1.68x. For a researcher, the most informative part is likely the ablation structure rather than any single headline number: how stable the anchor-selection rule is, how quality changes as the recomputation ratio varies, whether affix position matters, and how stale-cache error accumulates across denoising steps. If the paper includes those plots, they are the ones worth studying closely.23:T598,TwinKV defines importance through pairwise redundancy in key space. For each token, it counts how many non-adjacent tokens have a key vector with cosine similarity above a fixed threshold. A high twin count means the token is redundant; a low count means it is likely unique and harder to recover if evicted. Two design choices matter. First, the method operates on keys rather than values or hidden states, because eviction affects what can later be retrieved through attention, and keys are the retrieval addresses. Second, it excludes adjacent tokens to avoid trivial local similarity from contiguous text.

The more interesting systems idea is to use TwinKV as a repair pass rather than a standalone eviction policy. Given any existing method’s retained and evicted sets under a fixed budget, TwinKV looks for two types of mismatch: an evicted token with no surviving near-duplicate, and a retained token whose information is already duplicated among retained tokens. It then swaps them while keeping the budget unchanged. This is a low-intrusion design: it does not need the wrapped method’s internal scores, only its final keep set. The paper also distinguishes this from anchor-based approaches that score keys by distance from a single global reference point. Those methods measure outlierness relative to a centroid; TwinKV measures substitutability through local pairwise relations. The correlation is effectively zero, which directly weakens the premise behind attention-based eviction.

Second, does TwinKV improve existing policies as a post-hoc repair? On Qwen3-4B, the method is composed with four recent eviction baselines: StreamingLLM, PyramidKV, SnapKV, and ExpectedAttention. 方法不是只做一次 patch，而是做一整套 intervention grid。维度包括：patch 哪个 cache segment；只换 K、只换 V、还是 K/V 一起换；是否同时复制当前 hidden state；是否使用语义相近但答案相同的 source control；是否做 decoded validation，确认被 patch 的 latent 轨迹确实对应可读出的反事实行为；以及 matched corruption，用同一区域做破坏性干预来测试 necessity。作者据此定义三个状态：active carrier，指最小且 gated 的 cache segment，在 oracle interchange 下足够，并且主要竞争解释无法匹配；carrier shift，指存在可转移效应，但活跃片段与主结论模型不同；no-call，指由于能力、支持度、decoded 行为或控制检查不过关，不能下机制判断。

从全文看，论文最重要的技术细节有三点。第一，它强调 exact source-recipient counterfactual，而不是开放式 prompt patching，这样可以避免目标答案不明确。第二，它把 sufficiency 和 necessity 分开，且 necessity 通过 matched corruption 而不是随意噪声注入来做，减少“哪里都能破坏”的伪结论。第三，它把 hidden state 与 cache object 明确区分：h_t 不是 cache 的一部分，只有显式复制时才算干预对象。这让“是当前状态在算，还是历史 value 轨迹在承载”这个问题可以被单独检验。27:T74d,SCIT, the Suffix Cache Interchange Test, is a cache-level counterfactual intervention protocol. For a recipient problem r and a source problem s, the method first constructs an exact, verifiable counterfactual: the source supplies a changed intermediate quantity, which is then combined with the recipient’s remaining variables to define a known counterfactual answer. Both source and recipient are rolled out to a latent step t. At that patch point, a selected cache slice from the source is transplanted into the recipient, optionally together with the current hidden state, and the test checks whether the recipient moves toward the source-defined counterfactual answer.

The protocol is deliberately grid-like rather than a single patch experiment. It varies: which cache segment is patched; whether only K, only V, or both are copied; whether the hidden state is also copied; whether semantic source controls with the same answer are used; whether decoded validation confirms that the patched latent trajectory corresponds to the intended counterfactual behavior; and whether matched corruption on the same region supports necessity. Based on this battery, the paper defines three outcomes: active carrier, carrier shift, and no-call.

Three technical choices are especially important. First, the paper uses exact source-recipient counterfactuals rather than open-ended prompt patching, which keeps the target answer unambiguous. Second, it separates sufficiency from necessity, and tests necessity with matched corruption rather than arbitrary noise, reducing the risk of overcalling mechanisms. Third, it explicitly distinguishes the current hidden state from the cache object: h_t is not part of the cache unless copied by intervention. On a Sim-CoT-style GPT-2 reproduction, the pattern is directionally similar: value-suffix sufficiency and decoded transfer are present, but matched-corruption necessity is not strong enough for a full necessity claim. The paper is explicit about that limitation.
