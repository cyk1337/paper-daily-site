18:T4dd,The paper uses a roofline-style analysis to separate weight traffic from KV-cache traffic during decode. For a model with P parameters and weight width wp, a batch-one decode step performs roughly 2P FLOPs and reads P·wp bytes, giving about 1 FLOP/B for BF16 weights. An H100 SXM has a BF16 dense ridge point around 295 FLOP/B, so this regime is bandwidth-bound by a large margin. KV attention has the same structure: one query attending over s cached tokens costs about 4sdh FLOPs per head and reads 2sdh·wkv bytes, again about 1 FLOP/B in BF16. GQA improves reuse by the query-to-KV head group factor g, but even g=8 gives only about 8 FLOP/B, still far below the ridge point. The paper then explains why batching helps weight reads but not KV reads. Weight bytes can be amortized across requests; KV bytes cannot, because each sequence owns its cache. The techniques are organized into five mechanism classes: quantization reduces element width, token eviction reduces retained tokens, paging manages KV blocks and fragmentation, prefix caching shares common prompt prefixes, and memory tiering moves KV state across HBM, host DRAM, and storage. The paper’s comparison discipline is to keep analytical claims and measured claims separate.19:T422,The most important quantitative examples are concrete. For Llama-3-70B in BF16, the weight footprint is about 140 GB, already larger than a single 80 GB HBM device. The KV cache size is Bkv = 2·L·nkv·dh·wkv·s. With L=80, nkv=8, dh=128, and BF16 storage, Llama-3-70B uses 327,680 KV bytes per token. A single 128k-token sequence therefore adds about 42 GB of KV state; a 1M-token sequence requires about 328 GB, more than the aggregate HBM of four 80 GB H100 devices. The arithmetic-intensity numbers are equally important: BF16 batch-one decode sits near 1 FLOP/B for weight traffic, while the H100 ridge point is about 295 FLOP/B. On the attention side, GQA with group factor 8 still reaches only about 8 FLOP/B. Weight-side batching approaches the ridge only at a batch size around 295 in this simplified model, while KV-side intensity is invariant to batch size. The paper’s measurement contribution is to make these comparisons explicit rather than mixing throughput, latency, memory footprint, and quality degradation under incompatible settings.1a:T91f,方法核心是 acoustic-to-text KV compression。基础模型是 MiniCPM-o 4.5，它按 1 秒为单位处理 duplex unit，每个 unit 内包含音频 token、一个 native 的 <|listen|> 或 <|speak|> 决策，以及后续可能的响应生成。作者在每个 unit 的第一个 native decision 之后，插入一个可选的 transcription segment，用新引入的 <|asr_start|> 和 <|asr_end|> 包围。这个 segment 只作为语言模型上下文中的文本记忆存在，不送入 speech decoder，也不会被说出来。

推理时，模型自己决定是否打开 side channel。如果预测出 <|asr_start|>，就贪心解码最多 64 个文本 token，直到 <|asr_end|>；若超长或遇到控制 token，则强制闭合。随后，当 resident KV cache 超过目标预算时，系统驱逐更早的 acoustic states，但保留这些 transcript token，并保留一个最近的 acoustic window 以覆盖转写延迟。于是，较老的语音内容以文本形式留在上下文里，最近一段仍保留原始声学细节，形成“远处文本化、近处声学化”的混合记忆。

训练上，作者没有单独接一个 ASR 模型，而是复用原有 LM backbone，只用 LoRA 适配 side channel。监督信号来自带词级强制对齐的转写数据：每个词根据其声学结束时间和额外延迟 δ 被分配到某个 1 秒 unit 中，每个词只出现在一个目标 transcription segment。仅用 transcription cross-entropy 会改变原模型的原生对话行为，所以作者再加入 token-level knowledge distillation。具体做法是：冻结原始 full-duplex 模型作为 teacher，让它在同一音频上、但不插入 transcription segment 地运行；收集 teacher 在所有 native prediction positions 的全词表分布；student 在插入 transcription segment 的序列上训练时，对这些 native 位置同时拟合 teacher 分布。这样 side channel 学会转写，同时尽量不扰动原有 listen/speak 决策、停顿处理、打断响应等行为。

这个设计和“单独训练一个流式 ASR，再把文本喂回模型”相比，有两个差异。其一，推理时不需要额外 ASR 模块，部署更简单；其二，蒸馏约束的是 full-duplex 原生行为，而不只是转写准确率，因此目标更贴近语音对话模型的系统需求。1b:T828,实验围绕三件事展开：KV 峰值控制、长时语音理解、实时性与交互行为保持。主模型是 MiniCPM-o 4.5。作者指出，转写后的文本记忆大约每秒只占 3 个序列位置，而原始 acoustic history 约占 17 个位置，这给压缩上限提供了直观背景。

The first is Token-Sparse Updates. The authors analyze hidden-state changes between adjacent loops and show that, as recurrence proceeds, only a small subset of tokens still changes substantially. Moreover, the active-token sets are approximately nested: tokens that remain active in a later loop are mostly a subset of those active in the previous one. FlashLoop therefore recomputes the Transformer block only for active tokens and reuses hidden states and KV states for tokens that have effectively converged. This reduces both compute and the need to maintain a full per-loop KV cache.

The second is Sparse Attention. The paper shows that cross-loop changes in attention outputs are dominated by a sparse subset of attention columns, meaning a small number of key/value positions account for most of the difference between adjacent loops. These important columns are relatively stable across loops, so FlashLoop predicts them using attention-contribution statistics from the previous loop. To avoid the scale mismatch that usually appears when softmax is computed on a subset, the method caches global probability mass to preserve the normalization scale of the full softmax. This is more careful than a generic top-k attention approximation; it is tailored to incremental cross-loop updates.

The third is KV-Residual Quantization. Instead of quantizing each loop’s full KV states independently, FlashLoop stores a quantized base state plus low-bit residuals between adjacent loops. The motivation is empirical: adjacent-loop KV residuals are easier to quantize than full KV tensors, yielding lower reconstruction error under the same bit budget. That matches the intuition that iterative refinement makes successive states highly correlated and low-entropy in difference space.

A key part of the paper is that these are not presented as isolated tricks. The system is implemented with GPU-aware pipelining and optimized kernels so that token sparsity, sparse attention, and residual quantization work together without losing the gains to irregular memory access or kernel overhead.
