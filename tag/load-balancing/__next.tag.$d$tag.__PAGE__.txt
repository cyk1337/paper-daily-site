a:T584,CacheRoute builds a periodically refreshed routing table that plans prefix affinity and expected load together, prioritizing cache stability over per-request reactive remapping.
- Inputs/abstraction: per-key arrival rates λ_b for business keys; R routable destinations (a destination is a model-server group; in the 70B setup, TP=2).
- Admission (warm set): admit the highest-rate keys into an affinity-managed warm set under a warm-prefix slot budget; non-admitted traffic falls back to cache-blind power-of-two choices.
- Load cap via replication: calibrate q_cap from a single destination’s latency/load knee. For each key, allocate enough destinations so the expected per-destination load contributed by that key is ≤ q_cap. Replication is primarily for load control (capping per-destination contribution), not for improving hit rate per se.
- Placement: assign admitted keys (and their replica counts) to destinations using LPT (longest-processing-time-first) list scheduling to reduce expected load imbalance.
- Control interval: keep the table fixed for a period to preserve cache warmth; avoid reactive spilling that would send the next request to a cold destination once a cap binds.

The key observation is that the input to an MoE router can be approximated well enough from the residual representation produced by the preceding layer. This prediction is used only for scheduling, not for model execution. Based on the predicted load, FreeBalance adjusts expert-device mapping and starts expert-weight migration immediately, overlapping migration with pre-routing computation stages, especially attention. To avoid over-migration, the method includes a cost model that limits how many experts can be moved given the available overlap window. In other words, it does constrained balancing rather than chasing the most even load at any cost. 1) TACG (Task-Aware Coactivation Grouping):
- Split calibration traffic into task families (K=4 in the setup) and collect per-family expert usage and co-activation statistics per layer.
- Compute soft expert-to-family preferences, then reweight the co-activation graph into a task-modulated graph so that within-family co-activated experts become closer.

- Identify cross-family “generic” experts that tend to become hotspots using co-activation centrality and cross-family consistency.
- Replicate only this small set onto a few secondary GPUs chosen to be structurally compatible with the primary placement.
- At serving time, select among replicas using a locality- and load-aware rule with exponentially decayed load signals to mitigate skew under workload shift.
The design trades optimality for operational simplicity: no router changes, no dynamic migration; it relies on task-family partitioning and calibration traces.10:T67a,MACS is a training-free inference framework with three components.

First, Entropy-Weighted Load replaces raw token counts with an information-aware load estimate. For each visual token, the method computes a Shannon entropy score from the token feature after a softmax transformation, normalizes entropy values within the current image or batch, and maps them to semantic weights through a sigmoid function. The intuition is simple: not all visual patches deserve equal capacity. Background or redundant patches should count less than semantically dense ones. Text tokens are assigned full weight because their semantic density is treated as relatively uniform and high.

Second, Dynamic Modality-Adaptive Capacity adjusts expert capacity according to the current batch-level modality composition. Standard methods use a fixed capacity factor gamma, which is brittle when some tasks are image-heavy and others are text-heavy. MACS makes capacity a function of the actual visual/text mix in the batch, so the budget tracks the current workload instead of a static approximation.

Third, Local Semantic Rerouting handles overflow. When an expert exceeds capacity, the framework first attempts to reroute overflow tokens to semantically nearby experts with spare room; only when rerouting fails does it fall back to a safe token drop. This is a practical design choice: it preserves more useful information than direct dropping, while avoiding the overhead of a more expensive global reassignment.

Relative to prior methods such as CAI-MoE, the key shift is not retraining the router but redefining load and capacity at inference time in a modality-aware way.11:T572,MoHGE combines architectural, routing, and systems ideas. First, experts are partitioned into groups; experts within the same group share the same size, while different groups have different hidden dimensions. This creates a tiered capacity structure, where smaller groups can handle easier patterns and larger groups can absorb harder contexts. Second, routing is hierarchical. A group-level gate first selects the top candidate groups, and an expert-level gate then chooses experts within those groups. This is better aligned with heterogeneous capacity than a single flat gate over all experts, because the model first decides how much capacity to use and only then which expert instance to activate. Third, the paper introduces two balancing losses. The Group-Wise Auxiliary Loss regulates how often different capacity groups are selected, aiming for a better match between token complexity and expert size while avoiding collapse to a single group. The Intra-Group Experts Auxiliary Loss balances usage among experts inside each group. On the systems side, the All-size Group-decoupling Allocation strategy spreads experts from every group across all GPUs, instead of concentrating large experts on a subset of devices.
