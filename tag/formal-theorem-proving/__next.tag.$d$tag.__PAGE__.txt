9:T470,The system maintains a shared proof state containing the theorem, current goal, hypotheses, tactic history, and four Lean-derived signals: syntax validity, type correctness, goal progress, and proof completion. Four agents operate over this state. A Strategist selects a high-level proof mode such as direct proof, induction, contradiction, cases, rewriting, or lemma application. A Tactician, implemented with Claude Sonnet 4.6, proposes tactics conditioned on the goal, retrieved Mathlib premises, critic guidance, and a list of previously failed tactics with their Lean error messages. A Critic, implemented with Claude Haiku 4.5, scores partial proof states and suggests pruning or next moves. A Retriever supplies the top-5 Mathlib premises. The search protocol is deliberately conservative: Phase 1 runs a Best-of-N sweep; Phase 2 runs critic-guided MCTS only on theorems that Phase 1 failed. This gives an internal monotonicity property within a VERITAS run, so new solves in Phase 2 can be attributed to feedback-guided search. 训练数据方面，作者从既有 theorem proving 数据中收集了 5.5M records，再清洗筛选出 300k SFT 数据用于 whole-proof fine-tuning。这里能看出作者没有直接把全部数据灌进去，而是做了质量筛选；对 formal domain 来说，这通常比盲目扩量更重要，因为错误证明、低质量中间轨迹和格式噪声会直接污染 verifier-sensitive 学习。

方法创新主要在 large block correction。作者不是做 token-level 或很小span的 infilling，而是训练 dLLM-Corrector 在较大 diffusion block 上进行局部修正。这样做的理由有两个。第一，形式化证明中的错误常常跨越多个 token，甚至一整段 tactic 组合，小span修补不够。第二，diffusion 模型天然能利用左右双向上下文，因此适合在“前后都已知，中间有错”的条件下重写局部片段。与 AR 模型相比，这种修补不需要从错误点之后整段续写，理论上更稳，也更符合 proof debugging 的工作流。

推理流程是：先由 dLLM-Prover-7B 根据 theorem statement 生成完整证明；如果 verifier 判错，但判断为 proof skeleton 大体正确，则调用 dLLM-Corrector 对局部块进行修复。这里的关键不是单次生成，而是“生成 + 验证 + 局部修补”的闭环。这个闭环和代码生成里的 generate-then-repair 很像，但在 formal proof 中更自然，因为 verifier 给出的成功/失败信号更干净。

从建模范式上看，这篇文章真正想说明的是：diffusion LM 的优势不只是并行生成，而是双向条件建模和 block-level rewriting。formal proving 只是一个高约束测试场景。b:T7b9,The framework, Diffusion-Proof, uses two 7B diffusion models built from Fast-dLLM-V2-7B: dLLM-Prover-7B for full-proof generation and dLLM-Corrector-7B for local proof repair. This split is sensible. In formal proving, many failures are not due to a completely wrong global plan; they often come from local inconsistencies, invalid tactics, typing issues, or broken intermediate steps. A dedicated correction model matches that error structure better than a single monolithic generator.

On the data side, the authors collect 5.5M theorem-proving records from prior work and clean/select 300k examples for SFT. That choice matters. In verifier-sensitive domains, low-quality trajectories and formatting noise can be more harmful than raw scale, so the paper implicitly treats data curation as part of the recipe.

The main technical idea is large-block correction. Instead of token-level or very small-span infilling, the correction model is trained to rewrite larger proof blocks using both left and right context. This is where diffusion modeling has a natural advantage over AR generation: it can condition bidirectionally and rewrite a local region without forcing a full left-to-right continuation from the first error onward. For formal proofs, where an error often spans a whole tactic chunk rather than a single token, large-block repair is a more realistic operation.

Inference follows a generate-then-verify-then-repair loop. The prover first generates a complete proof from the theorem statement. If the proof fails verification but appears structurally close, the corrector is invoked to repair local blocks. The important point is not just using diffusion for generation, but using it as a bidirectional rewriting engine under verifier feedback.

At the paradigm level, the paper is really arguing that the practical advantage of diffusion LMs is not merely parallel generation. It is block-level conditional rewriting with access to both past and future context.c:T4d0,The headline results are reported against AR baselines trained on the same data.
