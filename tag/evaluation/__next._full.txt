18:T588,The method is a staged verification pipeline. First, an LLM rewrites the original problem using strategies such as numerical reparameterization, logical restructuring, constraint modification, and contextual reconstruction. Importantly, the rewriter is instructed not to solve the rewritten problem, which helps separate problem generation from answer generation. Second, RePro performs conservative semantic screening. This stage filters out candidates that are ambiguous, under-specified, contradictory, unrealistic, or infeasible. The paper is careful about the notion of feasibility: it is not merely formal derivability, but semantic and constraint consistency of the rewritten problem. Third, the surviving candidates are translated into executable Lean specifications, and Lean-oriented neural ATPs such as Goedel-Prover and DeepSeek-Prover search for candidate proof scripts. A proof is accepted only if it passes Lean kernel-level verification.

This design differs from prior rewriting-based evaluation in three ways. It verifies answers through formal proof rather than heuristic checking. It evaluates reliability along three axes—well-definedness, feasibility, and answer correctness—rather than treating validity as a single vague notion. And it explicitly trades recall for precision by retaining only proof-verified instances. That trade-off is deliberate and sensible for benchmark construction.19:T4a3,The experiments are conducted on GSM8K and MATH. The headline result is straightforward: among the retained rewritten instances, RePro achieves 100% well-definedness, feasibility, and answer correctness, whereas prior rewriting methods still leave invalid questions or incorrect reference answers in the benchmark. This is the central empirical claim, and it supports the paper’s argument that formal verification changes the reliability ceiling of rewritten evaluation sets.

A second important result concerns reformulation sensitivity. Using proof-verified rewrites, the authors show that several models suffer noticeable accuracy drops when mathematically equivalent problems are restated in new forms. Because the rewritten items are verified, the drop is more plausibly attributed to sensitivity to formulation and possible memorization dependence, rather than to benchmark corruption. The paper also makes clear that not every rewrite survives the pipeline: the released benchmark is a retained subset of candidates that can be formalized and proved. That gives high precision, but limits coverage and may bias the benchmark toward problems that are easier to formalize in Lean.1a:T7cc,方法上，作者构造了一个四类动作空间：tool_call、ask、refuse、confirm，并把模型每一轮输出映射到其中一类；若输出没有明确决策信号，则落到 residual 的 other 类，但 GAR 不计入 other。分类规则采用固定优先级 tool_call > refuse > ask > confirm > other，tool_call 由语法判断，其余三类由文本 cue 识别。关键设计是 case-level、any-turn 的 Gold Action Recall（GAR）：对某个 benchmark category，若模型在任意一轮曾发出该场景所需的 gold action class，就算命中。它不关心轨迹最终是否通过，只问模型有没有在合适场景下做出过正确动作类型。然后把 GAR 与 benchmark 原有的 conversation accuracy（Acc）配对分析。若 grader 真正要求先做出 gold action 才能通过，则应有 Acc ≤ GAR；一旦出现 Acc > GAR，说明 grader 掩盖了动作类型错误，属于 bound violation。反过来，如果 GAR 远高于 Acc，则说明模型动作类型选对了，但后续执行、参数、状态推进出了问题。这个分解把“校准错”和“执行错”变成两个近似正交的失败模式。

作者还设计了两个推理时干预来验证机制。SRI（State-Reconciliation Intervention）针对漏掉 tool_call 的情况，通过上下文扰动去促使模型补做工具调用；CRI（Call-Reconciliation Intervention）针对不该调用却调用的情况，分成 retry 和 bypass 两种：retry 让模型重新选择动作，测试 emission 是否向 gold class 回归；bypass 则不改 emission，而是绕过不必要调用，观察轨迹分数是否恢复。这个设计的好处是，它不只是报告“模型错了”，而是在问：错误来自动作分布本身，还是来自执行链条；以及这种错误在 inference-time 是否具有可塑性。相比普通 benchmark slicing，这里更像是把 tool-use 评测从 end-to-end pass/fail 变成了 decision layer + execution layer 的分层诊断。1b:T77f,The method defines a four-way action space: tool_call, ask, refuse, and confirm. Each model emission is mapped into one class using a fixed priority order: tool_call > refuse > ask > confirm > other. Tool calls are identified syntactically, while the other classes are detected through textual cues. The key metric is Gold Action Recall (GAR), computed at the case level with any-turn aggregation: if the model emits the gold action class at any turn in the case, the case counts as recalled. GAR ignores whether the full trajectory eventually passes. It only asks whether the model ever made the contextually appropriate action decision.

GAR is then paired with the benchmark’s conversation accuracy (Acc). If passing the benchmark truly requires taking the gold action, one should have Acc <= GAR. A violation, Acc > GAR, indicates grader masking: the benchmark passes trajectories that never emitted the required action class. Conversely, large slack, GAR >> Acc, indicates that the model selected the right action class but failed later in tool choice, arguments, or state progression. This decomposition turns a single end-to-end score into two approximately orthogonal failure modes.

To probe causality, the paper introduces two inference-time interventions. State-Reconciliation Intervention (SRI) targets missed tool calls by perturbing context when the gold action is tool_call but the model emitted none. Call-Reconciliation Intervention (CRI) targets unwarranted tool calls when the gold action is non-call. CRI has two variants: retry, which asks the model to re-decide and tests whether emissions move toward the gold class, and bypass, which avoids the unnecessary call without changing the emission itself. This is a strong design choice because it tests not only whether calibration is poor, but also whether it is plastic and whether fixing the decision layer actually improves trajectory outcomes.1c:T5dd,The main evaluation is on BFCL v3 multi-turn, with replication on tau-squared-bench retail and airline settings. The headline result is that some models with high aggregate accuracy have very low GAR on categories that require asking or refusing. The clearest example in the paper is xLAM: 71.8% aggregate accuracy, but only 19.5% GAR on miss_param, with a 64.5-point gap relative to size-matched peers, while BFCL’s state grader still marks many such cases as PASS. That directly supports the claim that aggregate accuracy hides action miscalibration.

The authors also run a 200-case manual audit and report inter-annotator agreement of kappa = 0.92, which strengthens confidence that the diagnostic is not an artifact of noisy labeling. The same pattern appears on a second benchmark, suggesting the issue is not specific to one grader implementation.

The intervention results are especially informative. First, calibration is plastic, but heterogeneously so: the same SRI perturbation can improve Acc for one model family and hurt another. Second, CRI cleanly separates two mechanisms. Retry often shifts emissions toward the gold action class, but tends to reduce final trajectory accuracy across nearly all families. Bypass, in contrast, can preserve or improve trajectory accuracy without changing the emission. That implies that re-deciding the action is not always the right fix; in some systems, isolating or bypassing the bad call is more effective than forcing a second generation step.1d:T67a,The method is PTA-IRT, short for Privileged Trajectory-Aware Item Response Theory. It extends standard IRT in two ways: trajectory-aware item calibration and LUPI-based ability estimation.

First, the framework collects historical execution trajectories from prior agents on the benchmark. Instead of feeding raw logs directly, it converts them into structured semantic summaries that capture process-level signals such as context exploration, edit attempts, tool usage, and verification paths. These summaries are then used to learn trajectory-aware item characteristics under a four-parameter logistic (4PL) IRT model. Compared with simpler 2PL or 3PL variants, 4PL offers more flexibility for asymmetric success curves that are common in agent tasks.

Second, for subset selection, PTA-IRT uses trajectory-aware Fisher information to choose a difficulty-stratified calibration subset. The goal is not merely to pick tasks that separate agents by final outcome, but to pick tasks whose process patterns are informative for ability estimation.

Third, at test time, a new agent only needs to run on the selected calibration subset. The full historical trajectory information is not required online. Through Learning Using Privileged Information (LUPI), the system transfers trajectory-side knowledge learned offline into an estimator that can infer full-benchmark performance from limited calibration observations.

A practical strength of the setup is the protocol itself: trajectories are privileged only during offline training, while online evaluation remains cheap. That makes the method consistent with the original goal of reducing benchmarking cost.1e:T4e1,The experiments are conducted on four SWE benchmarks and compare PTA-IRT against prior IRT baselines. The main result is consistent across datasets: under low calibration budgets, PTA-IRT improves both score recovery and ranking recovery over outcome-only methods. In other words, the gains are strongest exactly where efficient evaluation matters most.

The ablations are important. Removing trajectory information and keeping only pass/fail outcomes or static task semantics weakens performance, which shows that the improvement comes from process signals rather than just a more complex estimator. Corrupting or degrading the trajectory summaries also hurts recovery, suggesting that the model is using meaningful solving-path information rather than simply benefiting from longer text inputs. The paper further compares issue text, submitted patches, and structured trajectory summaries, and finds that the structured summaries carry additional measurement value.

From a research perspective, the key takeaway is not a single absolute number but the regime where the method helps: low-budget evaluation. If one can afford full-benchmark runs, subset estimation is unnecessary. PTA-IRT is useful precisely when evaluation cost is the bottleneck.1f:T418,For a skim read, start with the task formulation and protocol figure to make sure the paper is about budgeted subset-to-full evaluation, not about improving the agent itself. Finally, inspect the low-budget result plots and the ablations to see whether the gains are robust.

If you only have 20 to 30 minutes, prioritize the method diagram, the main tables or plots showing score/rank recovery at different budgets, and the ablation that removes trajectory summaries. If you are not familiar with IRT, it is enough to understand how difficulty, discrimination, and latent ability are refined by trajectory information; the full derivation is not necessary for a first pass.

This paper is most relevant for people working on agent evaluation or benchmark design. For pretraining researchers, the useful lesson is methodological: process signals can be more informative than final labels.20:T618,The design is careful and controlled. The dataset consists of 237 step-numbered solutions to 79 Humanity’s Last Exam physics questions, generated by three frontier models, with no synthetic error insertion. Each trace is labeled for two targets: final-answer correctness and the location of the first false step. The reference standard combines physicist annotations, an independent LLM debate, and source-masked adjudication, which is a sensible way to reduce single-annotator bias on difficult technical derivations.

The key experimental device is an information ladder that varies only the epistemic status of the answer shown to the monitor: blind, unverified answer, certified answer, and answer revealed only after a blind commitment. There is also a reconsideration control and a stepwise online condition. This lets the authors separate error detection from first-error localization, and further split traces into wrong-answer cases versus correct-answer-but-flawed cases. That decomposition is the core contribution. It turns a vague question about “monitoring reasoning” into a cleaner measurement of whether the monitor is validating the argument or merely using the answer as a shortcut.

Another good choice is that the same trace is evaluated under different monitoring conditions. The paper avoids across-question correctness prediction, where models can exploit question difficulty or benchmark priors. Here the object being judged is fixed, so differences are much more plausibly due to answer access rather than prompt-level confounds.21:T64a,The dataset is modest in size but strong in curation. There are 237 traces from 79 HLE physics questions, and the generating models achieve about 65% final-answer correctness on this filtered subset, so the benchmark contains both positive and negative cases. The most important subset is the 24 critical traces where the final answer is correct but the reasoning contains a real error. Those are the cases that remove the easy shortcut of checking whether the conclusion is wrong.

Eight LLM monitors are evaluated. The headline result in the abstract is that certification of the answer raises mean detection performance, but the gain comes mainly from traces with incorrect final answers. On the critical traces, answer access provides little benefit, and first-error localization barely improves. That is the central empirical point: when the answer is wrong, monitors behave more like outcome checkers; when the answer is right but the process is flawed, their actual argument-verification ability is much weaker.

A useful background number from the paper is that 65% of traces end with the correct answer, yet some of those traces are still invalid. The authors explicitly connect this to the structure of reward hacking: acceptable output does not imply acceptable process. If monitoring relies on answer visibility, these cases will be systematically missed.

The most informative comparisons are not between monitor models, but between conditions: blind vs unverified vs certified vs commit-then-reveal. Those deltas support the paper’s main claim that answer access changes what is being measured.22:T8e8,方法上，这篇文章做得比较扎实，重点不在模型创新，而在协议设计和误差定位。

第一，作者在两个域上统一了评测协议。数学部分使用 MathNet-Retrieve：500 个 query，对 117,088 条完整语料全库排序，不做 shortlist。每个 query 都有唯一 gold source problem，同时 benchmark 还人为放入一个 lexical 相近但结构不同的 near-miss。作者同时报告 strict Hit@k（只认 gold）和 lenient Hit@k（gold 或 near-miss 都算），这个差值正好用来量化“模型是不是被表面相似项吸走了”。

第二，trajectory 部分没有沿用原 benchmark 的 pooled relevance，而是把 336 条 ALFWorld 轨迹全部按 task type 重新穷举标注，并进一步定义两层 disguise：定义(i)要求同 task type 但 target object 不同；定义(ii)再额外要求 receptacle 也不同，尽量去掉最容易驱动 lexical similarity 的 token。这里的设计很关键，因为它把“程序相同”与“对象词相同”拆开了。

第三，作者专门研究 lexical control 的符号翻转。他们引入一个便宜的 lexical reranker，观察它在两个域里的效果方向：在数学里它会伤害结构检索，因为它把 near-miss 顶上去；在轨迹里它反而能提升结果，因为 benchmark 构造仍保留了某些表面线索。随后又做 token-class ablation，去定位究竟是哪些 token 类别在驱动这个现象。

第四，作者分析了 LLM reranking 的 judge dependence。不是只看“加了 reranker 后有没有提升”，而是换三个独立训练的 judge，看恢复方向是否稳定、效应量是否可迁移。结论是方向大体一致，但幅度、tier profile、甚至哪个 judge 更强，都会随域和 query style 改变。这说明 reranker/judge 的结论可移植性很差。

第五，文章还做了 contamination probe 和 downstream null analysis。前者检查 reranking 增益是否集中在知名竞赛题上；后者在一个刻意构造的坏检索条件下比较 oracle retrieval 与 adversarial retrieval，发现下游几乎无差异，并进一步把原因定位到答案截断与评测解析问题，而不是 retrieval 真没作用。这个部分虽然偏评测卫生，但很有现实意义。23:T873,最关键的结果在数学检索。重 disguise 条件下，两个 production embedders 的 strict Hit@1 都是 0.0%，bootstrap 95% CI 也是 [0.0, 0.0]。但正确答案通常并没有消失，而是“在 top-10 里几乎总能找到”。这说明问题不是召回不到，而是排序头部被 lexical near-miss 占据。作者进一步统计 miss 的构成：在 95.2% 到 99.8% 的 miss 中，排在正确答案前面的候选在词面上比 gold 更接近 query。这基本把失败机制钉死在 surface-form bias 上。

轨迹检索的结果更微妙。只要 gold 定义排除了 query 中的 literal object 和 receptacle token，embedding retrieval 就会掉到 chance 以下。这个现象比“性能下降”更强，因为它说明模型不仅没抓住结构，反而系统性偏向错误的表面匹配项。

First, the authors enforce a shared evaluation protocol across two domains. In mathematics, they use 500 queries from MathNet-Retrieve against the full 117,088-item MathNet corpus, with no shortlist. Each query has exactly one gold source problem, plus a planted lexical near-miss that is structurally different. Second, for ALFWorld trajectories they do not rely on pooled relevance from the source benchmark.
