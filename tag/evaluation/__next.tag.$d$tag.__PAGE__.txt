A single-step repair is defined as replacing action a_t with a' at history h_t, after which an executor e completes the rest of the episode. The primary objective is net gain, p_e(h_t, a') - p_e(h_t, a_t), rather than post-repair success probability. This choice matters: the original action may still succeed on rerun, so a repair should only get credit for the extra success it adds; also, different positions have different baselines, so post-repair success can change the ranking across repair locations.

The protocol fixes three objects: the failed trajectory, the candidate repair set, and the deployed executor e0. For every candidate repair, the authors estimate its true value under e0 using independent rollouts that are never used for selection. Each evaluator then scores candidates using its own mechanism, and the selected repair is compared against matched selection, which uses the deployed executor’s own rollouts. The gap in deployed value is the decision regret.

The evaluator set is broad: greedy replay of the deployed model, rollout-based scoring with a substitute executor such as Qwen2.5-14B, cross-model evaluation between Qwen2.5-7B and Llama-3.1-8B, environment oracles, published verification rules, and LLM judges that only read the failed log. A quick read takes about 25–35 minutes; a deeper read should include the appendix on alternative objectives and the statistical protocol.11:T6a1,The method has three stages.
First is autoformalization. Natural-language policy statements are translated into a symbolic representation, using first-order logic or Boolean constraints that are expressive enough to support formal reasoning over obligations, permissions, prohibitions, and eligibility conditions. The goal is not maximal logical sophistication, but a stable and checkable representation that can be enumerated.
Second, the formalized rules are converted into decision trees. Branches correspond to truth assignments over atomic facts, and each path incrementally specifies a scenario. If a path is sufficient to entail the target verdict, it becomes a determined-verdict benchmark item. If the path stops before the verdict is entailed, it becomes an abstention item. This is an important design choice: it separates false from underdetermined, rather than collapsing everything into a simple entailment-versus-non-entailment setup.
Third, benchmark generation is parameterized. The system can control path depth, diversity, and target verdict types, allowing a single policy document to produce combinatorially many benchmark instances. Labels come from symbolic deduction rather than manual annotation, which is the main reason the pipeline scales while preserving correctness.
The design choice is sensible. Why formalize first instead of asking an LLM to paraphrase policies and another LLM to write questions? Because free-form generation makes label reliability fragile, especially when policies contain exceptions, interacting clauses, or missing conditions. DeoGen trades some linguistic naturalness for a much stronger guarantee on logical consistency and label validity.12:T532,DeoGen is run on four policy sources: sections of the U.S. IRS tax code, an insurance cafeteria plan, a code of coverage, and a faculty hiring handbook.
