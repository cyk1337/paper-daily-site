a:T5a3,The method is an agentic LLM-as-judge setup. The data consists of pairs of revisions for the same declaration from Mathlib PRs: an earlier version that was sent back for revision, and the later version that was accepted. Importantly, each version is scored independently. The judge does not know the score of the other revision and is not explicitly told it is doing pairwise comparison, which reduces comparison leakage. The rubric decomposes proof quality into five dimensions: library leverage, automation fit, structural clarity, statement quality, and Mathlib conventions. Each dimension is scored from 1 to 10, then combined by a harness into a final score. The key design choice is tool grounding. The judge can query the exact Mathlib state at the relevant commit through bash, search for existing lemmas, inspect signatures, and check available APIs. That lets it reason like a human reviewer: is this proof reinventing something already in the library, should the statement be more general, is there a cleaner one-line invocation already available. This is materially different from a text-only judge because proof quality often depends on library context, not just the local proof text. For dataset construction, the authors used Claude Sonnet 5 to inspect historical PRs and identify cases with substantial revision differences that were not just linting or newly added declarations, then split them into development and test sets.b:T5dc,The benchmark contains 218 declaration pairs in the test split and 123 pairs in the dev split used for rubric tuning. Six judges were evaluated, including three open-weight and three closed models, with three replicates per judge. Each evaluation allows up to 20 tool calls per sample to cap inference cost. The main metric is preference alignment: whether the judge assigns a higher score to the revision that Mathlib ultimately accepted. All models perform well above the 50% random baseline. Claude Sonnet 5 is best at 80.8%, while even DeepSeek-V4-Flash reaches 63.5%, with all sign tests reported at p < 1e-5. Among open models, muse-glimmer-30b gets 70.2% and inkling-small 69.3%, showing that the task is not exclusive to frontier closed models. The most useful experimental finding is the variance analysis. Re-running the same judge on the same declarations flips roughly one-fifth to nearly half of the verdicts. Some ablations look non-significant in one replicate, p = 0.34, and significant in another, p = 0.006. That means single-run judge benchmarks can easily overstate differences. The PR 11640 case study is also informative: the initial proof reconstructed a result already present in Mathlib, while the merged revision replaced it with a one-line call to H.restrictPreimage s. The judge found the existing declaration via tool use and consistently penalized the initial version on library leverage. This kind of semantic review cannot be replicated by linting or regex heuristics.c:T4ab,The experiments use code-generation tasks because hidden unit tests provide an exact oracle while remaining unavailable to the operators. The data comes from MBPP+ and HumanEval+. The loop runs on 75 MBPP+ training tasks. Evaluation uses 428 unseen tasks: 75 held-out MBPP+ tasks, 228 additional MBPP+ tasks, and 125 HumanEval+ tasks. A naive operator-generation loop is highly redundant: five runs produce 183 flagging operators but only 96 distinct flag sets. Scoring all 295 authored operators at the narrow interface yields no discovery. EvalCEGAR admits an operator in six of eight runs, and all six admitted operators help on the 428 unseen tasks. The best generated operator is 55 lines of Python and matches the best hand-written operator on a second benchmark while using about one third as many flags. Ablations show that changing the admission question alone moves admissions from zero to one, while the narrow interface admits nothing in 336 attempts. For composition, the authors enumerate about 2.3M subsets and show that the loop’s original composition objective can rank near the 5th percentile, whereas an untuned class-weighted objective reaches the 91st percentile or above.d:T413,The main tool is a judge-as-latent-solver model. For a single-answer task with answer-space size k, a reference-free judge implicitly solves the problem with grading-context competence c. If it is wrong, its internal answer is assumed to be uniformly distributed over the other k-1 answers. The judge score is then whether the candidate answer matches the judge’s internal answer. Under this model, TPR is c and FPR is (1-c)/(k-1), giving AUC = 0.5 * (1 + c - (1-c)/(k-1)). This yields a necessary condition: c must exceed 1/k for the judge to discriminate above chance. The paper also shows that marginal AUC can be confounded by item difficulty; a scorer that only reads difficulty can appear useful. The proposed measurement therefore uses a within-question estimator, comparing correct and incorrect candidates for the same question, with question-clustered bootstrap uncertainty. The judge is run as a non-intervening probe: the real optimizer still accepts or rejects candidates using the verifier, while the judge only records scores.e:T5cf,They propose a two-stage selective evaluation policy with joint threshold calibration.
- Setup: an examinee model produces an answer; a judge outputs a binary verdict. A held-out calibration set provides ground-truth evaluation labels (human or reference-based matching). Define a Bernoulli failure indicator for whether the judge verdict matches ground truth.
- Mode 1 (parametric judging): the judge decides using only its internal knowledge and emits an uncertainty/confidence score. If uncertainty is below threshold τ1, accept the verdict.
- Mode 2 (retrieval-augmented judging): otherwise, trigger web search, re-judge with retrieved evidence, and accept if uncertainty is below τ2; else abstain.
- Risk control: thresholds (τ1, τ2) are calibrated on the labeled calibration set using Clopper–Pearson upper confidence bounds to ensure the error rate (framed as FDR / false discovery among accepted verdicts) is bounded by a user-specified α with high probability.
- Key technical point: they argue the Bernoulli structure required for the CP bound still holds under the two-threshold routing scheme, so the finite-sample guarantee extends without extra distributional assumptions.
- Compared to prior selective prediction: prior work is typically single-threshold accept/abstain; here retrieval is an intermediate action, and the two thresholds are jointly calibrated to increase coverage under the same risk constraint while concentrating retrieval cost on uncertain cases.f:T5ae,The benchmark construction pipeline is the main technical contribution. Instead of directly scraping product demos or manually inventing tasks, the authors use a multi-stage process. They first identify AI-native startups with evidence of funding and real adoption, using that as a proxy that users genuinely delegate these workflows to AI. They then interview deep users to recover actual usage contexts, task goals, inputs, constraints, expected deliverables, and acceptance criteria. Domain experts convert those validated scenarios into benchmark instances that are reproducible, answerable, and evaluable. A final quality-control stage checks realism, answerability, evaluability, and discriminative difficulty. The result is a 97-task benchmark spanning six major domains.

The evaluation protocol is equally important. Each task is scored with multiple independent rubrics covering functionality, structure, formatting, and domain-specific quality, rather than a single holistic score. The reason is straightforward: real work products must satisfy several coupled requirements at once, and a single score can hide severe failure on one dimension. The authors also evaluate representative models under a unified agentic harness to reduce confounding from system-specific tooling. The novelty here is not an algorithmic method but the coupling of task sourcing, task abstraction, and deliverable-level evaluation into one coherent benchmark design.10:T4c7,The headline result is that even the strongest model completes only about 30% of tasks under the unified harness. That is a strong signal that current general-purpose agents are still far from reliably producing professionally usable deliverables. Performance varies substantially by domain, with Finance, STEM & Computer Science, and Education & Humanities emerging as especially difficult. This suggests that high-constraint, expertise-heavy, and strongly structured tasks remain major weaknesses.

The paper’s analysis points to a few recurring failure modes. One is complex instruction following: models often capture the broad objective but fail to satisfy many detailed constraints simultaneously. Another is domain-specific expertise: the issue is not generic fluency, but instability in professional content, terminology, conventions, and reasoning. A third is deliverable completion: systems can often produce something plausible-looking, yet still fall short of a directly usable final product. The emphasis is less on leaderboard separation and more on showing that once task sourcing becomes more realistic and scoring becomes more faithful, the apparent capability ceiling of current agents drops materially.11:T4cd,VideoGAIA is an agentic video understanding benchmark for general AI assistants. The benchmark is built via a multi-stage human-model co-design pipeline: starting from 100K public videos, frontier models (Gemini-3.1-Pro, GPT-5.5) handle frame-level captioning, evidence-grounded task generation, rubric-based quality control, cross-modal filtering, and tool-necessity assessment. Metrics include rubric-level agreement, Cohen’s kappa, and sample-level exact match. The mitigation method, SARA, uses on-policy self-distillation. A student generates a joint multi-rubric report, which is parsed into per-rubric segments. A slowly updated teacher evaluates these segments under isolation context.
