18:T74a,The core contribution is a benchmark and a probing protocol, not a new model. MotionBlind uses a contrastive minimal-pair design. Each instance contains two near-identical clips recorded in the same scene with the same objects and background, differing only in one motion property such as left vs right movement, faster vs slower motion, or larger vs smaller displacement. Each clip is paired with two complementary yes/no questions, yielding four binary decisions per instance. An instance counts as correct only if all four are correct. This strict instance-level metric is intended to suppress inflated scores from partial guessing.

The dataset is self-recorded rather than scraped from the internet. That choice matters because internet videos are hard to control for static confounds and hard to label precisely for physical motion variables. The paper also prefers relative-motion questions over absolute notions like “fast” or “slow,” since absolute labels depend heavily on context. Comparing two moving references within the same scene reduces semantic ambiguity and makes the benchmark a cleaner test of motion perception.

The probing setup is well designed. First, a no-video text-only probe tests whether questions can be answered from language priors alone. Second, shuffled-frame and reversed-frame probes test temporal-order sensitivity: if performance barely changes when order is destroyed, the model is likely not using motion information. Third, the paper studies frame selection under budgets from 1 to 24 frames, comparing uniform sampling, random sampling, a GRPO-trained learned selector (HORNet), and a training-free key-clip selector (Frame2Clip). Non-contrastive benchmarks such as Video-MME can make models look broadly capable, but performance drops sharply when static content is controlled and only motion differs. The introduction cites TimeBlind as a reference point, where even strong frontier models reach only 48.2% instance accuracy while humans achieve 98.2%. MotionBlind narrows the focus further to speed, direction, and magnitude.

The frame-budget and frame-selection experiments then ask whether the issue is simply missing key frames. The central hypothesis is that correct final answers are usually reached through a small set of stable intermediate outcomes, such as solved subproblems, validated constraints, case splits, or applied lemmas. Different correct trajectories may vary in wording, but they often converge on these checkpoints. The paper calls them consensus nodes. Construction proceeds by sampling N rollouts per prompt, keeping the correct ones, extracting intermediate conclusions from those trajectories, and clustering semantically equivalent conclusions into shared nodes. This is an important design choice: the target is not to imitate one canonical solution path, but to recover objective checkpoints that multiple successful paths pass through. Based on these nodes, the authors define ConsensusPR, a rule-based process reward that densifies the original terminal reward along the reasoning path. They also introduce three evaluation metrics: Final Answer Accuracy for endpoint correctness, Node Coverage Rate for how many consensus nodes a trajectory reaches, and Tokens per Node for reasoning efficiency. The metric design is tightly aligned with the failure modes they identify: NCR captures partial progress, while TPN distinguishes concise reasoning from verbose but uninformative chains. A practical advantage is that ConsensusPR plugs into existing GRPO and DAPO/RLVR pipelines without training a separate process reward model. Unlike PRMs, which try to score the quality of each step, ConsensusPR only checks whether the trajectory reaches verifiable intermediate states. Second, capabilities are released from common core capabilities toward the long tail, which is meant to mimic real harness growth in deployed systems.

The benchmark supports two evaluation modes. In deployment evaluation, no experience is carried across stages; each harness version is evaluated independently. In self-evolving adaptation evaluation, persistent artifacts such as memory, prompts, or learned skills can be updated within each stage and then carried forward, while the underlying model weights remain fixed. This tests whether accumulated experience helps or hinders adaptation under a growing harness.

The benchmark is reasonably large: 17 controlled harness streams, each with 3 to 6 cumulative stages, 802 unique tasks, 1,510 axis-specific evaluation examples, 520 executable tools, 42 latent reference skills, and 62 specialist agents.
