9:T9a6,方法设计很克制，核心是把“能力存在”与“组合后退化”严格分开。作者先从同一数据集抽取独立任务，要求模型在单题条件下已经答对，再把这些任务按固定模板直接串接成一个 prompt，形成大小为 k 的 composition。这样做避免了任务改写、提示变化、跨任务依赖等混杂因素，确保唯一变化是同一响应里要同时处理的任务数。随后按 task 级别计算 accuracy drop：比较某题在 k-way composition 中的正确率与 isolation 中的正确率差值，并用多次采样估计。

机制分析分两步。第一步是排除独立错误累积。若每题在 isolation 中失败概率为 p_i，那么组合后的退化若只是累积效应，per-task 正确率不应显著低于其单题水平；但作者观察到的 drop 明显更大，说明组合改变了每个子任务本身的求解过程。第二步是定位预算机制。作者统计模型在不同 composition size 下为每个任务实际生成的 reasoning token，发现随着 k 增大，平均每题 token 数系统性下降，并且近似 obey power-law scaling。这里的关键不是总输出长度触顶，而是在远未达到 context/output 上限时，模型仍然主动把每题“想”的篇幅压短。

在 fragile task 的定义上，作者不是凭任务类型先验划分，而是用经验退化模式来识别：某些题在不同随机采样、不同 composition size 下反复表现出更大 drop，这些题构成模型特定的 fragile 子集。全文进一步表明，这些 fragile 题在 isolation 中往往就有更长的 reasoning trace，说明它们更依赖充足的 test-time compute。值得注意的是，fragility 在同一模型内部相对稳定，但跨模型不完全一致，意味着这不是数据集固有难度，而是模型内部表征与推理策略共同决定的属性。

基于这个发现，作者提出 fragility-aware batching。它不改模型、不需要 logits 或内部状态，是纯黑盒策略：先通过经验测量估计任务 fragility，再按 fragility 把题分到不同 batch size。非 fragile 题放大 batch，让隐式预算自动压缩每题 token；fragile 题放小 batch，保留足够思考空间。它和常规“全都单独做”相比更省 token，和“全都大 batch”相比更稳。这个方法的意义不在算法复杂度，而在于它把一个认知层面的缺陷转成了可操作的 inference policy。a:T977,The experimental design is the main strength. The authors separate capability existence from composition-induced degradation. They first select tasks that the model already solves correctly in isolation. They then leave those tasks unchanged and simply concatenate them into a single prompt using a fixed dataset-specific template. This removes confounds such as paraphrasing, task reformulation, or inter-task dependencies. The only manipulated variable is how many tasks share one response.

They measure task-level accuracy drop by comparing each task’s accuracy at composition size k against its isolated accuracy, using multiple trials for estimation. This lets them ask whether composition changes the model’s ability on the constituent task itself, not just the aggregate prompt success rate.

The mechanism analysis proceeds in two stages. First, they rule out independent error accumulation as a sufficient explanation. If each task merely retained its isolated failure probability, the observed per-task degradation should be much smaller than what they actually measure. Second, they analyze reasoning-token allocation. As k increases, the model systematically emits fewer reasoning tokens per task, and this reduction follows an approximate power law. The important point is that this happens even when the total response remains comfortably below the model’s explicit output limit, so the effect is not simple truncation.

They then define fragile tasks empirically rather than by task category. Some tasks repeatedly suffer larger drops across sampling noise and across composition sizes. These tasks also tend to have longer reasoning traces in isolation, which supports the interpretation that they are more sensitive to reduced test-time compute. Fragility is relatively stable within a model but differs across models, suggesting that it is not just dataset difficulty; it depends on the model’s internal representations and reasoning policy.

Based on this, the paper proposes fragility-aware batching. It is a black-box inference strategy: estimate task fragility empirically, batch non-fragile tasks more aggressively to exploit the model’s tendency to shorten reasoning, and keep fragile tasks in smaller batches so they retain enough budget. The contribution is modest algorithmically but strong conceptually: a weakness in budget allocation is converted into a practical scheduling policy.b:T72f,The study spans eight datasets across mathematical and linguistic settings. Two are constructed by the authors: 1,000 indefinite integrals with symbolic verification, and OneWordQA, a factual QA set with single-word or numeric answers and minimal reasoning demand. The rest include established benchmarks such as GPQA-Diamond, GSM8K, and MATH-500. The model suite includes strong open-weight models as well as Claude Opus 5.

The first main result is that composition-induced degradation is robust. Even when only tasks solved correctly in isolation are used, per-task accuracy drops substantially as more tasks are concatenated, and the drop is much larger than what independent error accumulation would predict. This holds across both math-heavy and language-heavy datasets.

The second result is the token-allocation pattern. Reasoning tokens per task decrease systematically with composition size and approximately follow a power-law trend. Since the full response is still far from the model’s hard sequence limit, this is evidence for an internal budget-allocation behavior rather than explicit truncation.

The third result is the characterization of fragility. Tasks with longer isolated reasoning traces are more likely to be fragile under composition. Fragility is stable within a model across random trials and composition sizes, but the fragile subset is not the same across models.

The most actionable result is fragility-aware batching. Relative to solving every task separately, it reduces generated tokens by about 43% on average across datasets with no accuracy loss. The same idea transfers to a proprietary frontier model: on GPQA-Diamond with Claude Opus 5, generated tokens drop by 24% without degrading performance. That makes the paper relevant not only for evaluation but also for practical inference scheduling.c:T574,Start with the problem setup in the introduction and the early part of Section 3.
