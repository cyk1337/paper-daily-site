18:T4ad,The methodology is straightforward but well controlled. The authors use OpenCode as a fixed agent scaffold and implement five compaction strategies as drop-in replacements for the default compaction logic. They then evaluate four frontier models on three realistic long-horizon benchmarks. The study is organized around four questions. First, threshold sensitivity: they sweep the token threshold that triggers compaction, from 160K to 380K, and measure downstream task performance. Second, strategy sensitivity: they compare default self-summarization against alternatives such as using a smaller model to summarize, removing reasoning blocks, and writing the pre-compaction context to disk as a near-lossless external memory. Third, constraint retention: on tasks with explicit anti-cheating rules, they inspect how many constraints survive the first and subsequent compactions. Fourth, benchmark bias: they compare benchmark trajectories with real user-agent sessions from SWE-chat to see which kinds of information are disproportionately lost. The contribution is less about a new algorithm and more about turning compaction from an implementation detail into a measurable experimental factor.19:T64d,The evaluation covers PaperBench, ProgramBench, and PostTrainBench, using Claude Opus 4.6, GPT-5.3-Codex, GPT-5.4, and Gemini 3.1 Pro Preview, with two runs per task/configuration. Several results stand out. First, for the 1M-context models, changing the compaction threshold from 160K to 380K does not materially affect task performance. GPT-5.3-Codex, with a smaller 400K context window, degrades more clearly at lower thresholds on PaperBench and shows a weaker similar trend on PostTrainBench. Second, no compaction strategy consistently beats default self-summarization, including the near-lossless strategy that writes the full pre-compaction context to disk. This suggests that preserving information externally is not enough; the model must also know when and how to retrieve and reconstruct state from it. Third, more aggressive strategies can hurt some models substantially: removing reasoning blocks or summarizing with a smaller model can cost up to about 20 points on PaperBench for certain models, while leaving others nearly unchanged. That model-specific interaction is one of the most useful findings. Fourth, on ProgramBench, the first compaction summary already drops roughly one of the task’s three anti-cheating rules on average, and the loss compounds with repeated compactions. Fifth, in real SWE-chat sessions, compaction drops instructions about how the agent should work, and what it should avoid doing, about six times more often than it drops specifications of what to build.
