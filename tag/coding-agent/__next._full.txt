1a:T40b,This is useful for both coding-agent evaluation and training. First, it reframes repository-level failure from vague claims about insufficient context or weak retrieval into a more causal object: edit-time fact availability. That is a sharper target for diagnosis. Second, it shows strong substitution between parametric memory and explicit context, which means many apparently successful agent strategies on familiar repositories or APIs may simply be benefiting from memorized knowledge rather than sound workflow design. Third, it exposes a systematic blind spot in read-derived instrumentation: when facts are missing, agents usually do not stop; they guess, fabricate, and continue. As a result, measuring what the agent read can underestimate the shortfall and mislead harness design. For pretraining researchers, the paper matters because it touches the interface between what is stored in parameters, what must be supplied externally, and how benchmarks can accidentally conflate memorized priors with genuine agent competence.1b:T847,The core framework is a two-channel, edit-time working-set model for repository coherence. Each edit depends on a set of coupled facts, such as imports, tests, configuration rules, migration constraints, or naming conventions. Those facts can come either from recent context or from parametric memory. If neither channel covers a required fact, the edit carries coherence debt. This turns repository coherence from a loose intuition into something that can be manipulated experimentally.

The experimental design is unusually controlled. The first setup uses four fictional API migration tasks, each with 12 mechanically checkable requirements. In the closed-book condition, the model gets the task description but no workspace and no tools, effectively emptying both channels. In the matched front-loaded condition, the exact rules and source files are placed in the prompt while keeping the model and tool surface fixed, isolating whether explicit context can substitute for missing memory. The second setup uses a real Pydantic migration with 79 tests, plus a renamed twin where all API names are changed so that memorized library knowledge becomes useless. This isolates the role of parametric memory. The third setup instruments tool-using trajectories by checking whether the agent read the dependencies of an edited file shortly before editing. The fourth uses synthetic tasks authored by the researchers, where the required facts are fully known, enabling precise fault injection and attribution.

Two boundary findings are especially important. Availability is not sufficient on its own: when written standards conflict with working code, agents systematically follow the written standard even when the code is the better guide. So seeing a fact is not the same as weighting it correctly. Also, decomposition is not automatically helpful: if the task is tightly coupled, splitting it across subagents can sever dependencies and create additional coherence debt. The paper also compares harnesses and finds that some configurations spend far more tokens for the same end result, without improving fact coverage.1c:T6c0,There are five main empirical results. First, on the four fictional migrations, none of the 154 closed-book trials succeeds, while front-loading the exact facts into the prompt lifts 299 of 300 matched trials to at least 9 out of 12 requirements. This is strong evidence that explicit context can substitute for missing parametric knowledge. Second, on the renamed version of the real Pydantic migration, 66 of 70 trials across seven models end at the same score and pass the exact same 24 of 79 tests. Once memorized knowledge is neutralized, failures become highly aligned, suggesting that availability rather than model style determines the outcome. Third, the damage from withholding facts is reported to be linear in the work those facts support: removing a fact costs exactly the edits it enables and no more. Fourth, distance itself is not the issue: when a fact is supplied, models use it about as reliably at the far end of a 128,000-character context as when it is placed near the edit. Fifth, harnesses can differ by 12.8x in total token consumption while holding only 1.8x different amounts of context in front of the model at any moment, and the more expensive setups recover no extra capability when facts are withheld.

Two negative results matter as much. In 39 conflict trials, agents consistently follow written standards over contradictory but working code, showing that coverage does not guarantee correct arbitration. And the framework does not transfer cleanly to SWE-bench, where models likely already know the repositories and the task structure is observed only coarsely, so reading behavior no longer predicts success. The paper is careful not to overclaim universality beyond its controlled workloads.1d:T435,For a quick read, focus on three parts. First, read the introduction and experimental design carefully to internalize the three key concepts: coupled-fact graph, two-channel availability, and coherence debt. Without them, the results can look like a collection of coding-agent anecdotes. Second, prioritize the closed-book, front-loaded, and renamed-migration interventions. These are the strongest causal pieces of evidence in the paper. Third, read the sections on harness cost, subagent decomposition, and conflicting facts, because they show that the paper is really about the design limits of coding-agent systems, not just benchmark behavior.

If time is limited, the main figures and the five headline claims are enough to capture the argument in about 35 minutes. For a deeper read, spend time on the synthetic-task construction and the fault-injection analysis, especially the argument that read-derived instruments cannot measure the shortfall they are intended to detect. Using a CodeAct-like interaction loop, each action yields an edit (add/del/none) and the environment provides an outcome reward (e.g., tests pass/fail). Instead of treating the whole response/diff as one credit carrier, DiDPO:
1) Aligns diffs across multiple rollouts for the same task by finding highly similar sub-diffs that recur across trajectories.
2) Uses these recurring sub-diffs as anchors to induce sub-diff boundaries within larger diffs, aiming to isolate functional regions.
3) Groups aligned sub-diffs and computes a local group-relative advantage (diff-level advantage), then combines it with the trajectory-level advantage and assigns it back to the tokens responsible for generating those sub-diffs.

To avoid anchors that are too broad (mixing functions) or too narrow (hard to aggregate), it introduces a groupability score to select anchors that balance semantic scope and group mass.
