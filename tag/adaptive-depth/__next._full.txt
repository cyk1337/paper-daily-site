19:T424,Continuous Depth Batching (CDB) schedules computation at the granularity of individual loop iterations, routing tokens between model stages within a forward pass. Two execution modes are provided: (1) No-refill mode shrinks the recurrent batch as tokens exit the loop, and runs the coda stage for all exited tokens only after the full batch completes looping, for minimal implementation complexity; (2) Refill mode uses a priority queue to schedule prelude, recurrent core, and coda stages independently, interleaving boundary stage computation with loop steps and filling freed recurrent batch slots with new tokens to maximize throughput. A modified KV cache layout handles gaps left by tokens exiting at different depths, and a lookahead gate makes exit decisions one loop step in advance to overlap batch preparation with GPU execution and hide scheduling overhead. A FLOPs-based upper bound on adaptive depth speedup is derived, and a hardware-aware roofline model is used to identify batch size regimes where refill mode provides net performance benefit.1a:T74e,The proposed system, GRADE, is a hierarchical multi-agent architecture with three levels. At the top is a lightweight orchestrator M0 that consumes a shared query representation from an encoder and makes initial routing decisions. The middle layer contains two manager modules, implemented as small MLPs, which provide grouping signals over subsets of specialists. The bottom layer consists of sub-agents, each backed by a frozen expert LLM plus lightweight trainable components: an adapter into a shared latent space, an answer head, and a calibration map used after expert substitution.

The main design is a set of four learned gates. The Assignment Gate selects which sub-agents are activated. The Depth Gate decides whether the system should continue deeper into the hierarchy or stop early. The Communication Gate learns pairwise message passing masks so that agents do not always broadcast to one another. The Pruning Gate removes low-value branches during execution. Together, these gates turn a fixed multi-agent pipeline into a query-adaptive conditional-compute system.

For training, the paper introduces CoGRPO, a multi-agent variant of group-relative policy optimization. It avoids a critic and instead assigns relative advantage to all gates and agents that contributed to a rollout under a final correctness reward. The important point is credit assignment: the system must propagate a sparse end reward back to routing, communication, and answering decisions jointly.

A practical addition is the Expert Registry with lightweight recalibration. Agents are associated with swappable experts through registry descriptors, and when an expert is replaced at inference time, only a small calibration step on 64 anchor queries is needed. The gates themselves are left untouched. This is meant to handle distribution shift in expert outputs after substitution.1b:T483,The experiments are organized around five questions: whether GRADE beats monolithic and flat-ensemble baselines at lower active-parameter cost, how much each gate contributes, whether CoGRPO improves credit assignment, whether calibration is necessary after expert hot-swap, and whether harder tasks trigger deeper and broader agent usage.

On AIME-2025, however, Puppeteer’s brute-force four-model ensemble remains ahead by 1.9 points, suggesting that for very hard mathematical reasoning, simply allocating more large-model compute still helps.

The ablations indicate that hierarchical routing, selective communication, and adaptive depth each matter; they are not interchangeable extras.
