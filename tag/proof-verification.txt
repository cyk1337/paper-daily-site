18:T61f,The framework has two stages. In stage one, the system starts from roughly 17.8K theorem statements collected from public formal corpora, mainly NuminaMath-LEAN and Lean-Workbook. For each theorem, a model is prompted to produce a proof attempt in a single pass, as numbered natural-language steps paired with corresponding Lean tactics. A key design choice is that the model never receives Lean execution feedback during generation. This preserves genuine model errors instead of repaired trajectories, which is exactly what a verifier needs to learn from.

In stage two, the formal proof is compiled in Lean. All steps before the first failing tactic are labeled correct; the first failing step and all subsequent steps are labeled incorrect. The authors recognize that Lean failure is not always a mathematical failure: some failures are purely syntactic or due to formalization mismatch. To reduce such false negatives, they add a second model call that reads the Lean error message, attempts one syntax repair, and classifies the failure as mathematical versus merely formal. Only proofs whose first failure is judged to be mathematical are kept. For fully compiling proofs, there is an additional consistency check to ensure the natural-language steps actually express the same mathematics as the formal proof.

This yields 10,634 labeled proofs and 152,005 step labels, plus a held-out 200-proof benchmark called LeanPRM-Bench. Verifiers are then trained purely on natural-language inputs, so Lean is only used once during data creation, not at inference time.19:T535,The main empirical result is a controlled comparison against PRM800K-style human supervision. With the same model, the same training recipe, and the same number of updates, LeanPRM-Verifier-4B outperforms the PRM800K-trained verifier on four out of five benchmarks. The gains are large: +14.4 exact step-label accuracy on LeanPRM-Bench, +9.7 on Hard2Verify, and +9.4 on IMO-GradingBench.

The paper also evaluates proof selection in a best-of-N setting on IMO-level problems. The LeanPRM-trained verifier selects correct proofs noticeably more often than random, while the PRM800K verifier stays close to chance. This is an important sanity check: the model is not merely learning stylistic preferences, but something closer to proof validity.

Another useful result is scale consistency. The improvement from LeanPRM supervision appears across all tested model sizes, from 0.6B to 8B, on LeanPRM-Bench, Hard2Verify, and IMO-GradingBench. Given that the dataset is only 10.6K proofs, this suggests that supervision quality and domain alignment matter more than raw label count in this setting.
