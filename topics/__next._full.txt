真正要分清的是 compute-optimal batch 和 token-optimal batch。Kaplan 与 Chinchilla 约束的是模型规模 N、训练 token D 和 compute 的配比,没有直接给 optimizer step 数;batch 决定同样 D 个 token 被多少次参数更新消化,所以它是 scaling law 到 optimizer trajectory 的桥 [Kaplan2020ScalingLaws][Hoffmann2022Chinchilla]。如果目标是固定 FLOPs 或固定 token budget 到最低 loss,过大 batch 会减少更新次数并浪费 token signal;如果目标是固定日历时间或集群吞吐,更大 batch 仍可能合理,但必须用 warmup、LR scaling、gradient accumulation、packing/length 控制和 data order 把早期低 CBS 阶段兜住 [Goyal2017AccurateLargeMinibatch][You2019LargeBatchBERT][Merrill2025CriticalBatchRevisited]。

LR scaling 也不是 linear scaling rule 的永久许可证。Goyal 的 ResNet 和 LARS/LAMB 的 BERT 经验说明 warmup + linear/sqrt scaling 能把一部分大 batch 推进临界区,Smith & Le 则把“降 LR”换成“增 batch”,本质是在调 SGD noise 而不是免费扩大 batch [Goyal2017AccurateLargeMinibatch][Smith2017DontDecayLR][Smith2018BayesianPerspective][You2017LargeBatchLARS][You2019LargeBatchBERT]。LLM 预训练里 AdamW、token batch、sequence packing、梯度裁剪和 cooldown 共同定标;超过临界区后,正确动作常常不是继续乘 batch,而是重配 LR schedule 或把并行资源转向 model/data parallelism [Loshchilov2019AdamW][Shoeybi2019MegatronLM][Brown2020LanguageModels]。

2024/2025 的新证据把老理论拉回 LLM 训练现实。Zhang et al. 在 C4 上训练 85M 到 1.2B autoregressive LM,发现 Chinchilla 联合放大时 CBS 会升,但控制 token 数后它主要随数据量/训练时长而不是模型大小增长 [Zhang2024CriticalBatchPretraining]。Merrill et al. 在 OLMo 1B/7B 上直接测 CBS,报告 CBS 初始接近 0、早期快速上升后平台化,并用 batch-size warmup 在 OLMo 1B 上以 43% 更少 gradient steps 达到略好 loss;这支持“动态 batch schedule”,但仍应按 source-reported 证据处理 [Merrill2025CriticalBatchRevisited][Groeneveld2024OLMo]。16:Tb93,Critical batch size is not a fixed threshold; it is a local answer to whether a larger token batch is still worth using at the current training state. McCandlish links it to gradient noise scale: when batch is far below the noise scale, more samples mostly reduce gradient variance and steps fall nearly inversely with batch; when batch is far above it, extra tokens add little statistical signal and wall-clock parallelism starts buying speed with token inefficiency [McCandlish2018EmpiricalLargeBatch][Shallue2018MeasuringBatchSize]. The scale moves with loss, training duration, data mixture, optimizer, LR schedule, and parameterization, so one proxy run cannot define a constant batch for the whole pretraining job [Zhang2024CriticalBatchPretraining][Merrill2025CriticalBatchRevisited].

The practical split is compute-optimal batch versus token-optimal batch. Kaplan and Chinchilla constrain model size N, training tokens D, and compute, but they do not directly specify optimizer steps; batch is the bridge from token budget to trajectory length [Kaplan2020ScalingLaws][Hoffmann2022Chinchilla]. For fixed FLOPs or fixed tokens to minimum loss, an oversized batch reduces updates and wastes token signal; for fixed calendar time or cluster throughput, a larger batch can still be rational, but only if warmup, LR scaling, gradient accumulation, packing/length control, and data order protect the low-CBS early phase [Goyal2017AccurateLargeMinibatch][You2019LargeBatchBERT][Merrill2025CriticalBatchRevisited].

Learning-rate scaling is not a permanent linear-scaling license. Goyal's ResNet recipe and LARS/LAMB BERT experience show that warmup plus linear/sqrt scaling can push part of large-batch training into the useful regime, while Smith & Le's “increase batch instead of decaying LR” treats batch as a noise-annealing knob, not as free batch growth [Goyal2017AccurateLargeMinibatch][Smith2017DontDecayLR][Smith2018BayesianPerspective][You2017LargeBatchLARS][You2019LargeBatchBERT]. In LLM pretraining, AdamW, token batch, sequence packing, gradient clipping, and cooldown are co-scaled; past the critical region the right move is often to retune the LR schedule or shift parallelism into model/data parallelism rather than multiplying batch again [Loshchilov2019AdamW][Shoeybi2019MegatronLM][Brown2020LanguageModels].

Recent evidence brings the older theory back to LLM pretraining. Zhang et al. train 85M to 1.2B autoregressive LMs on C4 and find CBS rises under Chinchilla-style joint scaling, but after controlling tokens it depends more on data/training duration than on model size [Zhang2024CriticalBatchPretraining]. Post-training 的 model merging 是另一类问题。Wortsman 2022 Model Soups、Ilharco 2023 Task Arithmetic、Yadav 2023 TIES、Yu 2024 DARE 处理的是跨独立 fine-tuning 路径的参数组合,不是 trajectory 内的加权平均 [Wortsman2022ModelSoups][Ilharco2023TaskArith][Yadav2023TIES][Yu2024DARE]。两类方法在 loss landscape 上作用不同: pretrain merging 沿同一 basin 的 SGD 轨迹做 EMA,post-train merging 跨 basin 做 task vector 加减;DARE / TIES 的稀疏化,就是为缓解跨 basin 时 sign 冲突带来的相互抵消。需要保留的 caveat 是,把两类方法混在一起,很容易得出「merging 总能涨点」或「merging 必然丧失多样性」这类过度泛化结论。

对 pretraining 团队,可执行口径是把 merging 当成两条独立信号源来用: (a) constant-LR 阶段的 PMA / EMA 既是 cooldown 之后 loss 的 proxy,也可直接用于 ablation,每改一次配方都不必重跑 cooldown [Li2025PMAPretrain][Sanyal2023EarlyAvg];(b) cooldown 末的 EMA 与 last-iterate 应同时上报,两者差距就是 averaging gain,通常在 0.02-0.08 validation NLL; (c) eval-loss 与下游 few-shot 不应假设同步,Hu 2024 MiniCPM 的「cooldown 解锁下游能力」与 Li 2025 PMA 的「constant 阶段 average 已经能预测 cooldown loss」对应的是不同机制,前者落在下游能力解锁,后者落在 loss 预测,因此实验上应把 LR cooldown 与 trajectory average 分别消融 [Hu2024MiniCPMWSD][Li2025PMAPretrain]; (d) Boyd 的 EWMM 与 Press 的 NumRec 条目给了 weighted average 的统计解释,窗口 / 衰减率就是 bias-variance trade-off 的调参项,不要把 SWA / EMA / LAWA 当成「玄学加成」 [Boyd2013EWMM][Press1992NumRec][Hansen2015NonParametrics]。1b:Tbbb,Start from the structural claim: cosine / WSD cooldown and PMA / SWA / EMA-style trajectory averaging implement the same weighted-average geometry — pretrain-time "merging" is not an isolated hack but Polyak-Juditsky averaging under different wrappers (Izmailov 2018 SWA, Tarvainen 2017 Mean Teacher EMA, Kaddour 2022 LAWA, ByteDance Seed 2025 PMA, Meterez 2026 Anytime Pretraining all average trajectory iterates before evaluation or continued training) [Izmailov2018SWA][Tarvainen2017MeanTeacher][Kaddour2022LAWA][Li2025PMAPretrain][Meterez2026Anytime]. Post-training model merging is a different object. Wortsman 2022 Model Soups, Ilharco 2023 Task Arithmetic, Yadav 2023 TIES, and Yu 2024 DARE combine parameters across independent fine-tuning paths, not iterates within one trajectory [Wortsman2022ModelSoups][Ilharco2023TaskArith][Yadav2023TIES][Yu2024DARE]. The two operate on different objects in loss landscape: pretrain merging walks along one SGD basin doing an EMA; post-train merging crosses basins via task-vector arithmetic. The sparsification in DARE / TIES exists specifically to mitigate the sign interference that emerges when crossing basins. Conflating the two leads to over-generalisations like "merging always wins" or "merging must destroy diversity."

For a pretraining team the actionable framing is to treat merging as two independent signal channels: (a) constant-LR PMA / EMA is both a proxy for post-cooldown loss and an ablation lever (no need to re-run cooldown for every recipe change) [Li2025PMAPretrain][Sanyal2023EarlyAvg]; (b) at the end of cooldown, report EMA and last-iterate together — the gap is the averaging gain, typically 0.02–0.08 validation NLL; (c) do not assume eval-loss and downstream few-shot move together — Hu 2024 MiniCPM's "cooldown unlocks downstream capability" and Li 2025 PMA's "averaging during constant LR predicts cooldown loss" jointly imply that loss improvement and downstream unlock are separable mechanisms; the experimental design that decouples them is to ablate LR cooldown and trajectory averaging independently [Hu2024MiniCPMWSD][Li2025PMAPretrain]; (d) Boyd's EWMM and Press's Numerical Recipes give the statistical name to weighted averaging — tune the window / decay rate as a bias-variance trade-off, do not treat SWA / EMA / LAWA as folk magic [Boyd2013EWMM][Press1992NumRec][Hansen2015NonParametrics].1c:T992,首要判断:≥32K 时代单一 headline 长上下文分数已经基本失去分辨力;剩下的是 evergreen 测量工程设计,换一张静态榜单收不了场。Kamradt 2023 把 NIAH 推成事实标准后,2024 起几乎所有 ≥32K 模型在 NIAH 上接近满分,继续把它当主指标等于在一堆满分样本上做排序 [Kamradt2023NIAH]。RULER 按 retrieval / tracking / aggregation 三族受控负载拆任务,能暴露「nominal 128K 在组合任务上有效长度更接近 32K」这类失效模式;但同样的 13 类模板已反复进入公开 SFT 与 distillation 数据,2025 年底在头部模型上已出现 RULER 自身饱和迹象 [Hsieh2024RULER]。Liu 2023 的 lost-in-the-middle 比「均值 recall」更稳,因为它要求按位置分桶报告;当前主流榜单仍把不同位置的 needle recall 平均成一个数字,会丢掉 20-40 pp 诊断信号 [Liu2023LostInMiddle][Wu2024RetrievalHeads]。caveat 是,每一代新评测都会以可预期速度饱和。

The cleaner boundary is three curves. Curve 0 is the Kaplan/Chinchilla compute-bound regime: when D is plentiful, one pass over fresh tokens is the baseline and repetition is usually waste [Kaplan2020][Hoffmann2022Chinchilla]. Curve 1 is uniform repeat over a fixed mixture: the first few passes over a clean pool still help, but the return quickly shifts from fresh-equivalent tokens to memorization and capacity crowding [Hernandez2022RepeatedData][Xue2023TokenCrisis]. Curve 2 is targeted repeat: for math/code/reasoning/long-tail facts, 8–32 exposures can still beat more fresh examples at the same token budget [Charton2024Emergent][Zuo2025MemoGuided]. Cabannes 2024's associative-memory account links the curves: repetition does not create new keys; it writes existing keys deeper. If the key is under-written, this is generalization; if it is already saturated, it becomes memorization crowding [Cabannes2024AssocMem].

The cheapest validation is therefore not "pick the epoch with the lowest loss", but a small scaling ladder: 3 model sizes × 3 multiplicities × 3 subset classes at matched token budget. Loss/bpb only says whether average language modelling got easier; it does not say whether the target capability appeared, whether the run has entered a memorization phase, or whether the eval was contaminated. Hong 2024 shows representation-side memorization appears before val-loss rebound [Hong2024ROME]; Charton 2024 shows capability can emerge with almost no loss movement [Charton2024Emergent].
