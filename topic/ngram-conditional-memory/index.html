n-gram 提示、Over-Encoding 与 Engram 的机制及成本

摘要

外部检索增加可访问文本，可学习记忆通过稀疏读取扩展表示容量，两者对应不同的计算替代路径。Brunborg 的短时训练结果依赖提示库与评测条件；OE 支持独立扩大输入容量；Engram 显示受控预算下记忆与条件计算的分配收益。现有证据尚未建立通用替代率。预训练预算的调整，应依据匹配数据访问、训练时长与系统成本后的收益，以及它们在留出的大模型、后训练和实际服务中的保持程度。

记忆改变什么

外部检索、可学习记忆与稀疏专家改变了模型的不同部分。比较计算收益时，需要分别说明存储内容、寻址方式和预测接口。

路线地址与内容接口及阶段
n-gram 提示语料前缀查后续 token 与统计训练学习信任，推理注入残差流 [2]
OE输入 n-gram 取模查可学习向量预训练输入层扩容 [22]
Engram规范化 token、多头哈希查向量预训练指定层门控融合 [6]
N-Grammer离散潜表示构造潜在 n-gram架构增强，摘要未明确训练阶段 [20]
Infini-gram后缀数组查语料计数与概率统计语言模型及神经模型增强 [13]
kNN-LM表示空间近邻查后续分布已预训练模型的推理概率插值 [14]

无需额外训练不等于无需建库和搜索。Infini-gram 摘要报告 5T token 与毫秒级查询；这些是规模和查询指标，不是预训练节省。[13]

PKM 用乘积键检索可训练记忆，为稀疏容量扩展提供了早期实现。[24] 可学习记忆还须区别于专家计算：Memory Layers 报告最多 128B 记忆参数、1T 预训练 token、最多 8B base，并优于计算超过两倍的稠密模型及计算／参数匹配的 MoE，初始化未明确；PEER 检索超过百万个微型专家，摘要缺完整规模与硬件协议。[19][23]

BLT 按下一字节熵形成动态 patch，改变计算粒度而非查表；摘要报告最多 8B 参数、4T 训练字节的 FLOP 受控研究。字节、词与 token 不能直接换算。[1]

外部提示与评测条件

Brunborg 报告在 8×H100 的 NanoGPT Speedrun 中，达到目标损失的时间由 39.9 秒降至 6.7 秒。CPU 建立 37B-token 提示库与 GPU 训练并行；6、10、20-gram 的后续 token embedding 结合长度、计数和纯度相关的可学习信任信息，注入三处残差流。39.9 秒基线已有大型哈希 n-gram 表，因此这是两种含记忆系统的比较，而非给无记忆模型添加记忆的净收益。[2]

固定实际训练 token 数为 70.8M 的同一模型，将评测提示库从 75M 扩至 37B token，损失由 3.7219 降至 3.2739，无提示时为 3.7454。这是外部数据访问曲线，不是模型尺度曲线；骨干与索引可访问的独立语料未匹配，实际训练 token 数也不等于独立语料量。[2]

3.1 秒方案采用不同建库条件：先读取验证前缀，再定向统计训练文本续接。提示内容仍来自训练集，但建库依赖评测输入，规则适用性也保留条件。作者给出的复杂度为 O(NtrainNval)O(N_{\mathrm{train}}N_{\mathrm{val}})O(Ntrain​Nval​)，主方案为 O(Ntrain+Nval)O(N_{\mathrm{train}}+N_{\mathrm{val}})O(Ntrain​+Nval​)，其中两项分别表示训练与验证规模；它不能替代 6.7 秒主结果。[2]

20-gram 匹配覆盖 10.7% 的验证 token，续接正确率 97.7% 是匹配条件下的准确率。模糊文档去重后仍约 10 秒达标、覆盖率为 6.6%，说明整篇复制不足以解释全部收益，也未排除长片段重叠。大提示库还会形成依赖：同步数训练后撤除提示，骨干略差。计算替代因此需要同时考察有匹配、无匹配及撤除后的表现。[2]

输入容量与训练时长

OE 保留基础 tokenizer 与输出词表，将层次化输入 n-gram 映射至可学习表，经低维切片与投影后叠加。OD 扩大输出监督，OT 结合二者；论文将 MTP 视为 OD 的近似，而不是 OE。CFG 实验中扩大编码与解码词表在小模型上表现不同，支持将输入容量和输出监督分开研究。[22]

自然语言实验从头训练 151M、400M、1B 稠密骨干：前两者实际训练 token 数为 400B，1B 最多为 1T。在共同的 400B 截面，400M OE-12.8M 损失接近 1B 基线；400M 不含新增 embedding 参数。500B-token MoE 实验中的 OE embedding 分别有 13.1B、26.3B 参数。报告的 5.7 倍对应损失收敛对齐，并非端到端墙钟加速保证。[22]

输入容量的 log-linear 趋势限于已测范围。行切分与稀疏通信使特定实现的吞吐下降低于 5%，未优化 FSDP 则下降 25% 且受显存限制。机制优势在于用较少新增算术工作扩大输入表示，实际收益仍取决于访存与实现。罕见表行是否训练充分、碰撞的影响，以及更长训练后相对基线的排序，是进一步扩容需要检验的条件。[22]

条件记忆与容量分配

Engram 以规范化 token、多头哈希读取可学习向量，由隐藏状态门控，经轻量卷积在指定层融合，保留标准输入／输出 embedding。“静态”不是未经训练；确定性地址便于预取，但门控、投影与传输仍有成本。[6]

在 2×10202\times10^{20}2×1020／6×10206\times10^{20}6×1020 FLOPs 下，总／活跃参数固定为约 5.7B／568M、9.9B／993M，稀疏比约 10；总参数不含词表 embedding 与 LM head。约 20%—25% 非活跃预算分给记忆最优，再增加会挤占条件计算。这只是两个预算内的 U 形关系，不是通用比例。[6]

较大预训练对照共享 262B token 及顺序、3.8B 活跃参数。Engram／MoE-27B 均为 26.7B 总参数，前者含 5.7B 记忆；BBH 50.9→55.9（3-shot），HumanEval 37.8→40.8（0-shot Pass@1），40B 模型后者回落至 38.4。摘要 MMLU +3.4 与 v2 表 57.4→60.4 不一致，尚未解决。非单调收益不证明跨尺度排序反转，早层重构减负也只是作者解释。[6]

Tokenizer-Agnostic Engram 改用多项式哈希、跨 n 共享嵌入；摘要报告相当性能与字节等价序列的哈希等价，但不保证无碰撞或跨骨干无损迁移，规模、阶段和预算未明。[30]

TF-Engram 是外部短语记忆的免训练后置推理系统。Qwen3-0.6B 平均分 57.6→59.4，优于冻结骨干和参数匹配 LoRA；摘要缺评测集合、方差、语料量及完整预算。GPU—DRAM—SSD 分层与预取改善访存，但参数匹配不等于总成本匹配，新增内容也妨碍将收益全归于存储设计。[29]

研究机制与产品披露

OE 与 Engram 研究模型明确实现各自机制；产品则须区分明确采用、相关机制与未知。判断不在于报告是否出现“记忆”或 n-gram，而在于是否披露目标模块的内容、接口和训练阶段。三个对照限定了可作出的结论。[22][6]

第一，DeepSeek V4 披露 MoE、MTP 与压缩注意力，不等于披露 OE 或 Engram 部署。ProphetNet／Engram 引文及未来工作讨论也不是采用证据，不能以研究关联替代实现说明。[5]

第二，数据处理的 n-gram 与模型查表记忆不同。Llama 3 将其用于重复过滤、重采样和评测；Nemotron 3.5 的 8／13-gram 用于 SFT／RL 去污染。这些用途说明处理或评估流程，不能定位预训练记忆模块；Nemotron 的 Mamba-Transformer／MoE 与 MTP 也不能补足这一缺口。[17][21]

第三，Qwen3.8 Max 披露 Qwen3.5 架构基础及 2.4T 总参数／95B 活跃参数，但 27B 卡的 Gated DeltaNet 与 Gated Attention 组合不能移作 Max 的完整层配置，两者均未确认 OE 或 Engram。TF-Engram 在 Qwen3-0.6B 上的后置推理实验同样不证明 Qwen3.8 原生采用。[25][26][27][29]

其余模型见独立清单：新发布、同实验室关系、一般数据披露及后训练改进均不足以确认目标记忆模块，未知不等于未采用。

成本与尺度检验

计算替代须以达到目标质量的总成本判断，不只看 FLOPs。训练算术、GPU／CPU 时、建库更新、存储、通信、能耗与服务延迟分别计量；并行缩短关键路径，不消除消耗。Brunborg 的 352 GiB 索引与 377 GiB 构建 arena 未经生命周期测量不能相加为峰值。[2] OE／Engram 还需计表权重、优化器状态、梯度通信和主机传输；100B 参数表卸载开销低于 3% 的报告不能推广到任意冷缓存或并发。[22][6]

最清晰的拟议主对照，是让基线与训练型记忆共享骨干已处理的文本，以去重留出损失及达到目标损失的总成本衡量复用收益，同时分列实际训练 token、独立语料、重复次数和总／活跃参数。后置推理系统另设固定骨干与内容的对照，计入表示抽取、建库及服务，避免混同额外信息与架构收益。

拟以约 150M、400M、1B 活跃骨干开发，留出约 3B，资源允许再检验另一家族；每尺度三个训练时长。固定分词器、上下文和数据顺序，统一调参额度，报告固定超参数与公平调优结果；冻结配置和预测后检验留出排序。这是待执行设计，同一运行或家族检查点不作独立重复。

骨干、索引与测试按文档、域名和时间隔离；精确去污染仍可能漏掉释义泄漏。[4] 分测匹配／未匹配损失、长尾及新组合，以错误提示、陈旧库和读取失败检验依赖。服务另列冷／热缓存、预填充／解码、并发、尾延迟及摊销量；SFT／RL 统一数据、更新和生成／验证预算，agent 固定框架并计工具成本。成本优势消失、域外表现恶化或服务约束不满足，均应预先列为失败条件。

结论与开放问题

可扩展记忆提供了调整预训练资源配置的具体路径：OE 扩大输入容量，Engram 分配记忆与条件计算预算，外部提示利用可复用语料改善预测。[22][6][2] 相应的研究优先级是，有重复语料时测试提示，需要局部表示扩容时测试 OE，具备分片传输条件的 MoE 测试 Engram 分配。这是候选实验顺序，而非通用部署建议。

核心判断是：在明确的数据访问与服务约束下，读取是否比被替代的计算更经济。损失、下游能力与总成本的排序需要分别验证，当前尚无统一替代率，也未建立跨家族和后训练保持收益的保证。四个开放问题最直接影响预算决策：

  • 匹配独立语料访问、隔离长片段重叠后，外部提示还能节省多少目标损失成本？
  • 表容量、训练时长、重复率与稀疏比如何共同改变 OE／Engram 的跨尺度排序？
  • 冷缓存、低批量与高并发下，预取还能隐藏多少传输，多少服务量足以摊销建库？
  • 统一 SFT／RL 与 agent 预算后，收益是否保留，撤除提示或更新记忆是否需要重新训练？
