Aux-loss-free [DeepSeekAI2024V3]（图 6）的表面叙事是：把 router 平衡损失从 LM loss 中拿走，模型不再被两个目标拉扯。实际机制是给每个专家配一个可学习偏置 b_i，并按 batch 内负载偏离量直接更新——均衡压力从“可微目标”变成“一阶 SGD 控制器”。代价是训练动力学更依赖学习率、γ 控制系数、batch 配置；好处是 LM loss 更干净，专家分布更稳定。一条轻量 sequence-level balance loss 仍保留作兜底，说明 DeepSeek 自己也不把 bias-only 视为无条件充分。

DualPipe [DeepSeekAI2024V3] 是 pipeline 调度上的工程改进：在常规 1F1B 之外，交替排布 micro-batch 的前向 / 反向阶段，让通信（all-to-all、reduce-scatter）尽量与计算（GEMM、激活）重叠。论文没有完整给出边界条件；公开提示是，当 expert-parallel 通信占 step time 比例变高时收益最明显。在通信不是瓶颈的更小规模或纯 dense 训练里，DualPipe 额外引入的实现成本（micro-batch 配对、bubble 计费、debug 流程）很可能不值。

Multi-Token Prediction [DeepSeekAI2024V3] 把 next-token 预测扩展到 next-1..N-token：在每个位置加一个轻量 MTP head，用相同的 hidden state 预测之后第 i 个 token。训练时，它把 token 级监督信号提高到 N 倍；推理时，可以关掉 MTP 头退化为标准自回归，也可以把它送入 speculative decoding，由主 head 负责验证。这是少见的“pretrain 数据效率 + 推理 speculative decoding”同时受益的设计，但它假设服务端能正确处理 MTP-augmented KV cache，而这条 serving 协议在公开文档里仍偏薄。

Read together, they show one pattern: complexity does not vanish; it moves between the loss, numerical precision, pipeline schedule, and decoding stack.

Aux-loss-free [DeepSeekAI2024V3] (Figure 6) reads on the surface as removing router-balance pressure from the LM loss so the model is no longer pulled between two objectives. The actual mechanism gives each expert a learnable bias b_i and updates it directly from per-batch load deviation — turning the balance signal from a differentiable term into a first-order SGD controller. The cost is training dynamics that depend more on learning rate, the γ controller, and batch configuration; the benefit is a cleaner LM loss and more stable expert allocation. A small sequence-level balance loss still remains as a backstop, which shows that DeepSeek itself does not treat bias-only as unconditionally sufficient.

FP8 per-block [DeepSeekAI2024V3][FP8LM2023] (Figure 7): the key is not ‘switch to FP8’ but which ops are allowed to switch. V3’s published allowlist is approximately: high-throughput GEMMs (attention QKVO, FFN, MoE expert FFN, all-to-all dispatch / combine) run in FP8 — E4M3 forward, E5M2 backward — with (1×128) per-token tiles on activations and (128×128) per-block on weights; accumulation starts in FP32 inside tensor-core registers and is promoted to FP32 every Nc=4 ticks to mitigate E4M3 underflow; embedding / output head / RMSNorm / softmax / RoPE / router gate / MTP head / loss reduction all stay in BF16; master weights and Adam first / second moments stay in FP32. In short, FP8 is not a ‘global switch’ but ‘per-op toggles plus an allowlist.’ The same FP8-LM [FP8LM2023] path is not always worth it at smaller scale, where complexity and stability costs can exceed GEMM throughput savings.

DualPipe [DeepSeekAI2024V3] is a pipeline-scheduling engineering improvement: beyond plain 1F1B, it interleaves micro-batch forward and backward stages so communication (all-to-all, reduce-scatter) overlaps as much as possible with compute (GEMM, activations). The paper does not fully specify the boundary conditions; the public hint is that the gain is most visible when expert-parallel communication occupies a large share of step time. At smaller scale, or in pure dense training where communication is not the bottleneck, DualPipe’s added implementation cost (micro-batch pairing, bubble accounting, debugging) likely outweighs the savings.

Multi-Token Prediction [DeepSeekAI2024V3] extends next-token prediction to next-1..N-token: a lightweight MTP head sits at each position and predicts the i-th future token from the same hidden state. During training, this raises token-level supervision to N times the signal; during inference, the MTP heads can be disabled to fall back to standard autoregression, or fed into speculative decoding with the main head doing verification. This is a rare design where pretrain data efficiency and inference-time speculative decoding both benefit, but it assumes the serving stack can correctly handle an MTP-augmented KV cache — a serving protocol still underspecified in public documents.

The larger message of V3 is not to copy all four ideas, but to grade them first. V4 的训练与后训练同样不是孤立模块。mHC 替代传统 residual connection 的一部分角色，用 manifold-constrained hyper-connections 试图提高深层信号传播稳定性；Muon 负责大多数模块，embedding、prediction head、mHC bias/gating 与 RMSNorm 仍保留 AdamW，说明优化器切换也是算子/模块级白名单，而不是全局替换。预训练 token 增至 32T+。后训练先训练多个 domain specialist，再用 multi-teacher on-policy distillation 合入统一模型；OPD 使用学生自身轨迹上的 reverse KL，并在工程上做 full-vocabulary logit distillation。Quick Instruction 则把 search/action/title/query 等辅助任务改成特殊 token，复用已有 KV cache，避免再跑一个小模型做重复 prefill。V4 因此把 DeepSeek 谱系从“训练一个强 base + reasoning fork”推进到“base、长上下文 serving、specialist 合并、产品辅助任务共用一套 KV 账本”。17:Tb82,The main conclusion from V4 [DeepSeekV42026] is not “another larger MoE,” but that the long-context bottleneck has become a joint problem across attention, KV cache, serving kernels, and post-training rollout. V4-Pro has 1.6T total parameters with 49B active; V4-Flash has 284B total with 13B active; both support one-million-token context and retain DeepSeekMoE plus MTP. The structural change is attention. CSA first compresses every m tokens of KV into one compressed entry, then uses a lightning indexer to select top-k compressed blocks for sparse attention. HCA uses a much larger compression ratio m′ for heavier compression, without sparse selection. Both add a sliding-window branch to restore local fine-grained dependencies. The design acknowledges a hard limit: at one million tokens, latent KV compression alone is insufficient; the model needs local windows, compressed global memory, and indexable sparse remote evidence at the same time.

The cost is equally important. CSA/HCA make KV shape heterogeneous across layers, breaking the fixed-block assumptions behind PagedAttention. V4 therefore introduces a heterogeneous KV cache: SWA and not-yet-compressed tail states live in a state cache, while CSA/HCA compressed entries live in a classical KV cache, with blocks aligned by lcm(m, m′). The report also puts on-disk KV cache into the serving path: when shared prefixes hit, compressed KV can be reused directly; SWA KV is roughly 8× larger than the compressed cache and therefore needs separate handling. The scientific reading is that the reported 27% single-token FLOPs and 10% KV cache relative to V3.2 at one-million-token context are not the gain of one attention trick; they come from closing the loop across attention structure, cache layout, kernel alignment, and low-precision storage.

The training and post-training changes are not isolated either. mHC replaces part of the role of conventional residual connections with manifold-constrained hyper-connections for more stable deep signal propagation. Muon updates most modules, while embeddings, prediction heads, mHC bias/gating factors, and RMSNorm stay on AdamW, so the optimizer switch is also a module-level allowlist rather than a global replacement. Pretraining grows to 32T+ tokens. Post-training first trains multiple domain specialists, then merges them into one model through multi-teacher on-policy distillation; OPD uses reverse KL on the student’s own trajectories and implements full-vocabulary logit distillation. Quick Instruction turns auxiliary tasks such as action/search/title/query classification into special tokens that reuse the existing KV cache rather than invoking a separate small model for redundant prefill. The surface claim of aux-loss-free balancing is simple: move router-balance pressure out of the main loss to reduce interference with language modeling. In practice, that pressure moves into a sliding per-expert bias update, with a lightweight sequence-level term as a backstop; the loss is cleaner, but the training dynamics are harder to reproduce [DeepSeekAI2024V3]. FP8 follows the same pattern. FP8-LM [FP8LM2023] already showed that FP8 training is feasible, but V3 [DeepSeekAI2024V3] pushes it into a 671B MoE regime and relies on finer per-block scaling, BF16 accumulation, and BF16 fallback for selected GEMMs. In other words, low precision is not a global switch; it is an operator-level allowlist. def grpo_step(policy, ref_policy, batch, G=64, eps=0.2, beta=0.04):
    """One GRPO update. No critic network — group itself is the baseline."""
    loss = 0.0
    for q in batch:                                  # per prompt
        outs = [policy.sample(q) for _ in range(G)]  # G rollouts
        rew  = [reward_fn(q, o) for o in outs]       # scalar reward, e.g. {0,1}
        # ── group baseline: no critic, no GAE ─────────────────────────────
        mu, sd = mean(rew), std(rew) + 1e-8
        adv = [(r - mu) / sd for r in rew]           # A_i

        for o_i, A_i in zip(outs, adv):
            # token-mean importance ratio against the SAMPLING policy
            log_ratio = policy.log_p(o_i, q) - o_i.log_p_old
            ratio     = exp(log_ratio)
            unclipped = ratio * A_i
            clipped   = clip(ratio, 1 - eps, 1 + eps) * A_i
            pg = -mean(min(unclipped, clipped))      # PPO-style surrogate
            kl = beta * KL(policy(·|q) || ref_policy(·|q))
            loss += pg + kl

    return loss / (len(batch) * G)

# Why this works for reasoning:
#  · Reward is sparse but verifiable (math: exact-match; code: pass@1).
#  · G ≥ 32 makes the per-group baseline stable enough to skip a value net.
#  · KL to π_ref keeps the policy close to the SFT base — without this the
#    model degrades into reward-hacking gibberish (R1-Zero failure mode).
