从 GRPO 到 DAPO、GSPO、CISPO:开放推理模型的 critic-free 策略优化谱系

Critic-free 组基线在开放推理 post-train 里变成默认,但方差、clip 几何与序列 credit 设计把难题前移到目标函数本身

16 篇论文·2026年5月11日

领域综述

判断放在最前:从工业界可复现路线看,GRPO 把 PPO/RLHF 里最让人头疼的 critic 开销拿掉,用组内相对排序 / 归一化标量回报做优势信号 — DeepSeekMath 把这条写进开放权重推理链路的先例里,核心机制是「同一提示下多次 rollout 的组统计量替代 value baseline」而不是新的回报模型 [1][2]。代价也很直接:没有 critic 之后,方差与长度偏置、退化组(no 全对/全错)、熵塌缩、以及长链思考下的 token-level credit 设计,全都回到损失函数与采样策略上被重新放大。DAPO 在公开系统快照里把这条线的工程瓶颈拆成四块 — 非对称 clip、动态过滤采样、按 token 聚合的归一化损失、超长输出的 reward shaping — 并明确是建立在 GRPO 组 采样范式之上的可复现迭代 [6]。GSPO 的论点更偏理论语法:把重要性权重从逐 token 比率的乘积噪声迁到序 列似然层面的剪裁/优化,用来对齐「稀疏末置奖励 + 序列决策」下 importance sampling 该遵从的对象,并报告在 MoE RL 上的稳定性收益 [7]。CISPO 在 MiniMax-M1 技术稿里被定义为放弃传统 trust-region 叙事、转而剪裁 importance-sampling 权重且始终对所有 token 送梯度的一种工程算法 [8];Qi 等的 DPPO 工作则从 相反角度论证 token 级 PPO ratio 在长尾词表上是坏的散度代理,并把 PG-TIS(CISPO) 当作无约束 importance-sampling 基线对照 — 这两篇应分开读:前者是产品模型的训练 Recipe 自述,后者给出「为何ratio clip会失配」的论证框架 [9]。

HF 的合成博文把 GRPO→DAPO→GSPO 的 narrative 串成一条易读时间线,对学习曲线友好[11];但它不是独立实验证据,引用时应压权到「路线图 / 术语对齐」,不能与主文里的数值结论同级。后续引用图(2025–2026)里,真正重复出现的是三条轴:(i) trust region 究竟约束 ratio、序列似然、还是近似的 TV/KL[9][7];(ii) 组内采样与优势归一化怎么做才不制造长度偏置/退化组 [6][10][12];(iii) 探索性低概率 token 的梯度是否在 clip 机制下被系统性掐掉 [13][9]。R1 类长思考 post-train 把这些问题从小规模数学抬到通用推理预算层,报告量与工程约束都跟 InstructGPT 时代的 PPO+RM 不在同一量级 [5][3]。

可执行判断是:先固定「outcome-only / verifier-hookup」设定,再选目标 —— GRPO-family 适合作为默认组基线;若在长输出上 entropy 崩溃或低概率转折词升不上去,优先审查 clip 几何与采样过滤而不是盲目加 critic;若在 MoE 上出现不稳定或训练-推理数值分叉,序列级 ratio 重参数与散度约束类方法应在同一评测协议下做对照 [7][9]。Open question 方面,过程监督与末置奖励的混排、验证器分布外推、以及 replay 造成的 off-policy 纠偏,仍然可以把名义上「同类」的 GRPO 变体训练成不同的归纳偏置 [14][16]。

TL;DR

GRPO 用组内相对回报替代 critic baseline,是 DeepSeekMath 对 PPO/RLHF 栈最直接的「减模型数」改法 [1][2]。DAPO 在同一条组采样骨架上堆了四件工程补丁来对抗朴素 GRPO 在长链推理里的熵塌、退化采样与 token 归一化问题 [6]。GSPO 论证 token 乘积重要性比在长回答里与 clip 相互作用会爆方差,把比率和剪裁移到序列似然层是机制核心而非口号 [7]。CISPO 在 MiniMax-M1 报告里被定义为剪裁 IS 权重且始终对所有 token 反传;Qi 等的 DPPO 把它放进 PG-TIS 名号下做无 trust-region 对照,同时主张 token 级 PPO ratio 不是好的散度代理 —— 两条叙事相关但不应合并成一句话 [8][9]。HF 路线图文章适合对齐术语与时间线,不能当独立实验证据 [11]。

核心断言

#1GRPO 相对 PPO/RLHF 的第一性节省是 critic:组内多答案的标量/排序基线替代 value net,DeepSeekMath 把这条写进「PPO 变体」而不是全新优化器门类 [1][2]。
#2DAPO 针对的是公开可复现语境里「朴素 GRPO 长链推理」的多点失效 — 熵塌、奖励噪声、训练不稳 — 用 Clip-Higher、动态采样、token-聚合损失与超长 shaping 四点打包回应,不是换一套完全不同的采样定理 [6]。
#3GSPO 的核心改动在对象层:importance ratio 绑定序列似然、序列级 clip / 组优势与序列奖励对齐;论文把它归因于 GRPO-family 中 token 级 IS 权重误用带来的高方差与长度放大 [7]。
#4CISPO 在 MiniMax-M1 自控叙事里=剪裁 importance-sampling 权重 + 全 token 梯度;Qi 等复述 PG-TIS 为 CISPO 并指出这类路线弱化 trust region,与其 DPPO(TV/KL)诉求相对照 — 读的时候别混成同一「置信区间」故事 [8][9]。
#5U-统计量视角说明「去掉 critic」不是去掉方差机构,只是换成组对比估计量的方差剖分 — 这对调 group size 与温度比盲目加正则更有指导 [10]。
#6RLOO / CE-GPPO / DPPO 形成侧向分支:分别强调留一估计量、clip 失配的熵动态、以及散度约束 — 它们共享低概率 token 梯度议题,但解法落在不同算法层 [12][13][9]。
#7HF 合成文把 GRPO→DAPO→GSPO 串成教学轴 [11]; 采纳行业叙事时要用 arXiv 主文核对机制声称,并对 2025 后半急速迭代的引用图延迟有预期 — Semantic Scholar 统计需要冷却期。

§1 GRPO 相对 PPO/RLHF:省下的 critic 与回来的方差

结论先行:DeepSeekMath 里的 GRPO 先把 actor-critic PPO 中最贵的 value network 从训练图里拿掉,改成「同一数学题提示下重复 rollout,用组内归一化 reward 构造优势」——这在内存与实现复杂度上对中小团队通常是净赢,但把 baseline 噪声与采样偏差完全推回到「每组能得多少正负例」这个结构上 [1][2]。相对 InstructGPT 式 PPO+RM,KL 约束仍然可以保留,但优势来源从 A=R−Vϕ​ 退化成 A=R−groupstat(R) ,critic 拟合误差消失了,取而代之的是组规模、奖励标度、以及长短答案混在一起时的长度耦合 [3]。Zhong 等的 U-统计量分析把这点说得更干净:GRPO 的梯度是组对比结构,方差随 group size 与奖励分布形态走,不是在论文里「写无 critic」就自动比 PPO 稳 [10]。并行线上,RLOO 用 REINFORCE 形状写组内留一法,是「critic-free」的另一个实现分支 —— 哲学相近,估计量不相等,换实现时别假设指标可互换 [12]。DPO 代表偏好参数上的平行支路,与 verifier 钩住的 RLVR 不在同一采样命题之下,但常在同一 post-train 流水线里并排出现 [4]。

caveat:任何声称「GRPO 总比你手上的 PPO 稳」要看任务是否真的是稀疏末置奖励 + 可 cheap 验证;一旦 verifier 噪声大或组内全同号,优势估计直接退化,表现会接近纯 REINFORCE 噪声下限。

§2 DAPO:针对 GRPO 基线的四点工程反制

结论先行:DAPO 文自查的对象是「朴素 GRPO 长思考场景」:作者报告 Qwen2.5-32B 上朴素 GRPO AIME 分数显著低于其对标管线,并把问题拆成熵塌、奖励噪声、不稳与样本效率 [6]。对应手段在文内逐项命名:Clip-Higher(非对称 clip,让低概率动作更容易放大)、Dynamic Sampling(过滤极端通过率提示,缓解梯度死区)、token 级 policy gradient 但在 loss 里用 token 数目归一(长链场景下关键)、以及 Overlong Reward Shaping(对超长/截断输出做软惩罚降低长度投机噪声)。四点合在一起是「保持 GRPO 的多采样 comparing-G 结构,但改 clip 形状、改数据管线、改归一化与长度先验」。与 GSPO 差别在:GSPO 重写 IS 比率的概率对象,DAPO 仍停留在「公开实现细节如何 stabilise 现有 token-ratio GRPO 栈」这一侧 [6][7]。

判断:若复现路径完全照抄开源 verl 默认而忽略动态采样,最先爆的通常是 batch 级 degenerate groups;若忽略 Clip-Higher,常见表观现象是 explore 温度看起来正常但熵曲线迅速躺平。

§3 GSPO:序列似然比与序列级 trust-region 语法

结论先行:GSPO 的论文主张不是「再把 normalize 写法改一改」而是指出 GRPO-family 里 token 级 importance ratio 与 clip 的耦合在长回答上是错误对象:方差随长度积累,且与序列级稀疏奖励的 credit 结构不对齐 [7]。据此,算法把比率建立在整段响应 y 的似然比 s(θ)=πθ​(y∣x)/πθold​​(y∣x) 上并做序列级 clipping/优化,组内归一化优势仍在多条响应之间计算,以便「优势定义尺度」和「奖励只在句末给出」一致。作者进一步报告 MoE RL 里 GRPO 的不稳定与工程牵扯可以用这条重写缓解 —— 这条是经验声称,读者应把它放回自家 MoE数值与路由噪声设定里重做 [7]。

与 DAPO 的边界:两者可能在实现里约略共享「token 梯度要怎么按长度归一」的细节,但 GSPO 的理论文本把修复对象钉在 IS 概率空间;不要用 DAPO ablation 去直接证伪 GSPO 的措辞,反之亦然。

§4 CISPO 与 DPPO:同名症状,两条 trust-region 立场

结论先行:先拆「名字」再拆「机制」。MiniMax-M1 把 CISPO 描述成「放弃传统 trust region、剪裁 importance sampling 权重、始终让所有 token 参与梯度」以稳定大规模 RL 并缩短达到同 AIME 阈值所需步数相对于 GRPO/DAPO 的自述 [8]。Qi 等在 DPPO 里把 PG-TIS 称为 CISPO(Chen et al. in their bibliography)并把它与 PPO式 ratio clip、GRPO-Clip-Higher 并列;他们批评的焦点是 token-level ratio 作为散度代理在长尾词表上失真 —— 低概率 token 上 ratio 可能极大但真实分布位移很小,导致 clip 机制过度惩罚探索性 token,而高概率 token 上大质量移动却可能逃脱约束 [9]。DPPO 的回应是用 TV/KL 及其 Binary / Top-K 近似直接在策略空间控制信任域,而不是继续在单点 sampled ratio 上打补丁;这条思路把 Schulman–Kakade–Langford 以来的 trust-region 下界语言接回有限视界无折扣 LLM generate 设定 [19][9]。换言之,CISPO/IS-heavy 路线与 DPPO 在同一张失败症状图上,但一个放松 trust region 以保梯度,一个把 trust region 改写成散度估计 [9][8]。

判断:把 CISPO 自动等同于「置信区间代理」会认错问题;它在本技术报告语境里主要是 clipped IS + 全 token 反传。阅读工业推文时需要回链到 MiniMax-M1 原文句子。

§5 引用图之后还留下什么:采纳 vs 话语热度

结论先行:2025–2026 可见的真正「硬扩展」在系统层 — DeepSeek-R1 把手机构推理预算拉到默认,Qwen3 与 MiniMax-M1 把 MoE 大模型丢进同一类 RLVR 管道 [5][7][8]。算法论文层面,重复出现的是三条可检验轴:token vs sequence ratio 对象 [7][9]、组采样与动态过滤 [6][10]、clip 与熵耦合 [13][6]。Uhr 的 HF 文章把这些点串成易读叙事,对入门极其高效,但引用计数不应替代主文实验 harness [11]。更冷静的 limitation 是:Semantic Scholar / OpenReview 对 2025Q3 之后的互引边仍有滞后;很多「某某模型用某某损失」只出现在厂商发布或开源 commit message,应标注为间接证据。把过程奖励线路接回末置 RLVR 时,Lightman 式逐步验证仍是 credit 设计的前后参照 [14]。

§6 失效模式与评估:hack、长度、pass@k、算力与 KL

结论先行:verifier-only reward 把模型推到三个可预测张力区:(i) 对公开单测过拟合与高 pass-rate 投机,这在代码 RL 的负结果里已经被点名「稠密 surrogate 不一定单调指向 full pass」;(ii) 长链推理下长度分布右移,单样本 mean@1 与 pass@k 解耦 —— 提升后者有时靠放宽采样而非单序列质量;(iii) KL-to-reference 不是装饰项,温度、clip 与 entropy bonus 任一侧失真都会表现成「奖励涨、可读性崩」而不是平滑 Pareto。DAPO 的动态采样与 Clip-Higher 直接打 (i)(iii) 的交集,GSPO 打 (ii) 方差轴,Zheng2025GSPO MiniMax2025M1 等 MoE 报告把 train-inference 数值 mismatch 重新变成 ratio 危机 [6][7][8][9]。评测侧,tulu 系综述提醒开放 post-train 永远是 SFT + 偏好 + 可验证 RL 的混成堆栈,单列一项 GRPO 变体指标无法推出整体安全或能力 [16]。MATH/GSM8K 作为 cheap scalar hook 解释 benchmark 选择史,也解释 hack 表面 [17][18]。CoT 作为可测随机变量是把长度与 clip 议题推成硬约束的历史前情 [15]。

实操清单:同时报 mean@1、pass@k、长度分位数、entropy、KL、以及「 verifier 版本/Prompt 模板哈希」;否则论文之间的 AIME 差值不可比。

研究立场对比

Token 级 PPO ratio 是否「足够好」?

立场 — 认为多数工业 GRPO 仍在 token-ratio 语法上补丁即可,不需要动 IS 对象。

证据：[6][13]

反方 — Zheng2025GSPO Qi2026DPPO 给出相反机制故事:长回答与长尾词表下对象层面可能错。

判词 — 在未固定长度分布与词表尾部分布前,这条争议只能用同一 harness 的 A/B 判,而不是口号。

CISPO 是否必然是「无 trust region」?

立场 — MiniMax-M1 文本强调放弃经典 trust region 叙事以换取全 token 梯度。

证据：[8]

反方 — Qi2026DPPO 把 PG-TIS/CISPO 当作弱化 trust region 的 IS 基线并与 DPPO 对照,不等价于「永远应该无约束」。

判词 — 是否存在「轻量 trust region + CISPO 权重剪裁」的交集实现,要看开源复现而不是名称推断。

博客叙事 vs 论文采纳

立场 — HF 路线图降低认知成本,等价于「行业事实」。

证据：[11]

反方 — _blog_没有独立测评 harness;与 Yu2025DAPO Zheng2025GSPO 机制段落冲突时必须以主文为准。

判词 — 把博客当术语表,不当实验数据库。

实践要点

GRPO 的价值是把 LLM RL 从「必须再养一张 critic」缩成「同一提示多答案对比»,这对算力受限团队是结构性利好;代价是方差、长度与采样偏置全部搬进损失与数据管线 —— Zhong2026GRPOUStat 只是把这条讲成可计算的 U-统计量语言 [1][10]。在这个前提下,DAPO 像一份可 fork 的急诊手册:针对公开复现里朴素 GRPO 的熵与退化 batch 现象给四联药;GSPO 像一次对象级修正:如果相信 token 乘积 IS 在长输出上失配,就应当用序列似然书写 clip;CISPO 与 DPPO 共享「低概率 token 梯度被错误 clip」的症状素描,但一个通过 IS 权重剪裁+全 token 反传换稳定性,一个通过 TV/KL 信任域把问题拉回散度 —— 不要在脚注里把它们揉成同一个 acronym story [6][7][8][9]。HF 帖 [11] 只适合当对齐地图。落地选法时,用固定预算跑:mean@1 + pass@k + 长度 CDF + KL + verifier 哈希,否则所有 AIME 涨跌都可能是采样方差而不是目标改进 [16][17]。

悬而未决的问题

  • Q1.token broadcast 的末置优势与序列似然 ratio 是否在极限下可写成同一优化问题,还是只在特定充分统计量假设下对齐?
  • Q2.公开数学/代码验证器升级时,旧 checkpoint 的收益曲线在何种意义下可迁移 —— 是否存在可检验的 verifier 分布漂移界?
  • Q3.大规模异步 replay / 离线包混合时,GRPO-family 需要哪种级别的 IS 矫正才能守住宣称的 on-policy 改进不等式?
  • Q4.在仅有 outcome reward 时,如何把过程监督 weak signal 注入而不把 credit 误配放大 —— 与 Lightman 式 PRM 的接口应放在哪一层 advantage [14]?
  • Q5.RL 计算预算与「可验证任务覆盖」之间的实证 scaling law 是否已经出现,还是仍被 product 周期掩盖在私有日志里?
  • Q6.MoE 路由噪声、低精度核与 train-inference 数值差异三者耦合成 ratio 失配时,应先把预算投进数值对齐还是投进目标重写 (GSPO/DPPO)?
