19:T75d,Construction methods for Hyper-Doc pretraining can be uniformly grouped into ERS (Evidence Restitching) and IVI (Intent Inversion), then crossed with 3 entity dimensions to form a 2×3 recipe matrix; each cell maps to published work. ERS×Space injects cross-file/cross-document dependencies, with RepoCoder [2303.12570], Stack v2 [2402.19173], and Galactica [2211.09085] as representative works; ERS×Time stitches version-evolution trajectories, with FIM [2207.14255] and diff packing [2308.07124] as representative works; ERS×Semantics injects similar-content retrieval results, represented by ReACC [2203.07722]. IVI×Space infers missing dependencies/citations from existing content, represented by the citation prediction task in Galactica [2211.09085]; IVI×Time infers evolution history/modification intent from the current version, represented by the commit message generation task in OctoPack [2308.07124] and the bug inference task in DeepDebug [2105.09352]; IVI×Semantics infers prior intent/instructions from final products, with ProX [2409.17115], Rephrase-the-Web [2401.16380], Self-Alignment [2308.06259], and Magicoder [2312.02120] as representative works. This matrix covers most published Hyper-Doc pretraining methods and provides a reference frame for method innovation, reducing redundant design.

1b:T432,Domains differ substantially in the amount of structured information they expose along the three entity dimensions. Marking strength as ● (strong), ◐ (partial), and ○ (weak) yields a dimension-strength spectrum that directly sets ERS / IVI deployment priority: use ERS first on strong dimensions (stitch existing structured information, low cost and high yield); use IVI first on weak dimensions (invert missing structure to close coverage gaps). §5 presents the full 16-domain spectrum with recommended methods. Three representative examples: code is strong across all three dimensions, so it uses ERS full-dimension augmentation; medical is weak in Space but strong in Time, so it uses an ERS × Time + IVI × Space hybrid (EMRs are timestamp-rich, while clinical guideline citations are usually implicit); legal is strong in Space but partial in Time, so it uses an ERS × Space + IVI × Time hybrid. Stack v2 [2402.19173] for code and Galactica [2211.09085] for scientific literature are both consistent with the spectrum’s predictions under post-hoc alignment.1c:T4a6,The orchestration layer assembles content from the 3 entity dimensions along an intent→plan→action→obs→correction cognitive trajectory and applies a differentiated loss mask: augmented context C is excluded from loss, action tokens are excluded from loss, and plan and final artifacts are included in loss. ReAct [2210.03629] and STaR [2203.14465] verify the effectiveness of this loss mask rule. Training filtering must use SemDeDup [2303.09540] for document-level semantic deduplication and Rho-1 [2404.07965] for token-level learnability gating, retaining only high-learning-value tokens for loss calculation; using either alone significantly reduces the quality gain. The orchestration layer must be completely decoupled from entity dimensions, so the same orchestration rule can adapt to entity dimension content from different domains; UL2 [2205.05131] verifies the generality of separating objectives and data sources. Methods that only distill successful trajectories (such as SWE-Gym replay, RL successful trajectories) are therefore only a subset of the orchestration layer: they lose the cognitive gap signal of error correction and incur measurable generalization drops.1d:T756,Hyper-Doc pretraining does not replace adjacent paradigms; it moves the cross-document / cross-version / cross-intent layer from inference-time or post-training into the pretraining data. The six contrasts below define its boundary against neighbouring paradigms:

· vs. pure RAG (retrieval at inference time) — RAG leaves cross-doc association to inference, bounded by retriever recall and the context window; Hyper-Doc anchors the same signals into the pretraining distribution itself [2303.12570, 2203.07722].

· vs. IDP + packing — pure window extension and token-level packing only change 'how much is in view'; Hyper-Doc additionally models 'inter-document dependency', so tokens in a long window carry learnable structure rather than opaque sequence concatenation [2207.14255, 2308.07124].

· vs. trajectory distillation — trajectory distillation relies on teacher rollouts replayed as tokens, with quality upper-bounded by the teacher; Hyper-Doc anchors 'state → next step' directly on source data (code diffs, citation chains, review rounds), teacher-free [2210.03629, 2203.14465].

· vs. ProX / WRAP (pure semantic slice) — ProX [2409.17115] and Rephrase-the-Web [2401.16380] rewrite only within a doc; Hyper-Doc generalises the rewrite mechanism across space (cross-file) and time (cross-version), with the semantic slice being one of six cells.

· vs. FIM / code concat (pure space/time slice) — FIM [2207.14255] deletions remain token-level; Hyper-Doc lifts the deletion unit to 'file / version / author intent', so ERS and IVI appear as dual pairs rather than one-way fills.

· vs. r1-style long CoT — r1 rollouts are task-driven post-training trial chains; Hyper-Doc is pretrain-time data-driven structure stitching. The two are orthogonal and composable: wire the structure into weights during pretraining, then let CoT exploit it downstream.1e:T641,An actionable checklist:

1. For Hyper-Doc pretraining, first map each task into its corresponding 2×3 matrix cell — do not redesign the pipeline from scratch. ProX [2409.17115] and RepoCoder [2303.12570] have already verified that the matrix covers the bulk of published methods.

2. Preserve the 3+1 asymmetric structure — do not flatten orchestration into the entity dimensions. UL2 [2205.05131] shows that decoupling objectives from data sources yields measurable training-efficiency gains.

3. For cross-domain deployment, consult the 16-domain strength spectrum first: apply ERS to strong dimensions and IVI to weak ones — this is the reliable path to improved data efficiency.

4. Enforce the loss mask discipline: augmented context C is excluded from loss, action tokens are excluded from loss, plan and final artifacts are included in loss. ReAct [2210.03629] and Rho-1 [2404.07965] supply battle-tested recipes.

5. Do not substitute inference-time RAG for training-time 4D augmentation — they are complementary. Stack v2 [2402.19173] shows that training-time augmentation yields more stable long-context performance with no inference overhead.

6. FIM [2207.14255] is a general gap-filling primitive whose neighbor relation can be temporal or spatial — do not restrict it to the Time dimension. FIM is verified effective in the Space dimension (sibling function completion) as well.
