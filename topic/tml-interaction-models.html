Thinking Machines Interaction Models:200ms micro-turn 如何改写 agent harness

TM 把互动从 harness 外围推进模型时钟,真正的工程启发是连续时间里的工具、上下文与安全治理。

20 篇论文·2026年5月13日

领域综述

Interaction Models 的核心论点是:实时协作不该继续由 VAD、UI state machine 和工具调度器在模型外模拟,而应该把 feedback timing、前台共同在场和后台推理分工纳入可训练系统 [1]。200ms time-aligned micro-turn 牺牲了传统 harness 的可插拔灵活性,换来 proactive interjection、同传、live commentary 和视觉纠错这类难以 emulate 的能力;encoder-free early fusion 则把音频、视频和语音输出的时钟交给主模型,而不是先由 Whisper-like encoder、视觉 encoder 或 TTS decoder 固化语义 [5][6][7]。对 agent/harness 设计更重要的是 foreground interaction model × async background model:它是 coding-agent sub-agent dispatch 的实时版本,前台持续承接用户反馈,后台执行工具、搜索和长推理,两者共享上下文而不是在 thinking/instant 模式间切换 [12][13]。这条路线会把 tool scheduling、context accounting、safety refusal 从离散 turn 推向连续时间;TM 的 batch-invariant kernels 和 SGLang streaming sessions 因此不是系统附录,而是让 200ms 互动行为可复现、可归因、可回归测试的前置条件 [2][22]。

TL;DR

Interaction Models 的核心价值不是多模态产品形态,而是把 agent harness 里的 turn detector、前台状态机和后台 worker 调度重新切分。200ms micro-turn 让反馈时机进入模型 forward,encoder-free early fusion 减少前端语义瓶颈,foreground interaction model × async background model 则像 coding-agent sub-agent dispatch 的实时版 [1][12][13]。TM blog reported 的 FD-bench、TimeSpeak、CueSpeak 等数字应被当作工程一手证据,它们显示现有 VAD-harness 强模型在 proactive interjection、同传、视觉计数和 live commentary 上缺坐标 [19][20][21]。更深的判断是:当共同在场成为默认,tool scheduling、context accounting 和 safety refusal 都要从离散 turn 迁移到连续时间;TM 的 Defeating Nondeterminism 也因此从系统细节变成交互研究的可复现前置条件 [2][22]。

核心断言

#1200ms micro-turn 的结构意义是把反馈控制从 VAD harness 推进模型 forward。机制是输入和输出在同一时间对齐序列里交错,因此沉默、打断、视觉线索和同传都能成为可学习行为 [1][8]。
#2encoder-free early fusion 的押注是让主模型直接学习多模态时钟,不是让大前端先做语义裁剪。dMel、40×40 patch hMLP 与 flow head 降低前后端边界,代价是训练归因更难 [5][6][7]。
#3foreground interaction × async background 是 coding-agent sub-agent dispatch 的实时形态。前台模型保留用户共同在场,后台模型承接工具与长推理,结果以增量证据回流而不是 turn 级完整答案 [1][12][13]。
#4连续共同在场会重写 tool scheduling、context accounting 和 safety refusal。机制是工具、视觉事件、语音重叠和后台结果同时进入决策窗口,所以 harness 必须支持暂停、预算、增量合并与可审计拒绝 [1][3]。
#5trainer-sampler bitwise alignment 在实时互动里是行为归因工具,不是洁癖。连续 200ms serving 会把数值分叉表现成不同打断时机或拒绝边界,所以 batch-invariant kernels 与 streaming sessions 成为评测基础 [2][22]。
#6TM blog reported 的 TimeSpeak 64.7 与 CueSpeak 81.7 是 frontier 信号,因为对手在这些任务上接近无法形成有效行为。机制不是分数更高,而是 benchmark 开始测何时说、是否说、说多久这类旧 harness 很难 emulate 的维度 [1][20]。

§1 200ms micro-turn 改写 harness 边界

关键变化不是语音助手更快,而是 interactive feedback 从 VAD/state-machine harness 进入模型 forward。TM blog 把输入 200ms 与输出 200ms 交错成同一时间对齐序列,因此沉默、打断、backchannel 和视觉线索都成为上下文的一部分 [1]。Moshi 也取消了显式 turn 边界,但主要把用户语音和模型语音做成并行流,目标是低延迟 spoken dialogue [8];PersonaPlex 在这条线上加入 voice/role 控制,但控制变量仍偏会话属性 [9]。TM 的架构含义更接近 agent harness:原来由 VAD、UI event loop 和 state machine 维护的 feedback timing,被压进可训练序列。代价也清楚:VAD harness 的可插拔性下降,调试对象从可读规则变成模型行为;收益是 proactive interjection、同传、live commentary 与视觉纠错不再需要每个能力单独写 harness。Clark and Brennan 的 copresence/contemporality/simultaneity 提供了交互理论坐标,但 TM 的工程动作是把这些坐标放进 tokenization 与 serving 时钟 [3]。

§2 early fusion 的押注是少前端,多共同训练

TM 的 encoder-free early fusion 不是省一个 encoder 的小优化,而是拒绝把多模态语义先交给独立大前端定型。音频用 dMel 进入轻量 embedding [5],视频切成 40×40 patch 后用 hMLP 投影 [6],音频输出用 flow head 生成 [7],这些组件和 Transformer 从头共同训练 [1]。这和 Whisper-like encoder + frozen LM + TTS decoder 路线的差异在责任分配:级联系统让前端先决定什么信息值得传给 LM,TM 让主模型在 200ms 时钟里直接学习哪些音频/视频细节会改变互动动作。Qwen3-Omni 是最强的公开对照之一,它用 Thinker/Talker 等模块化分工取得低首包延迟和广模态覆盖 [11];TM 的选择更激进,因为它把实时互动的时钟也纳入主模型训练。这个路线的风险是训练成本和归因难度都上升,但它更符合 Sutton 对可扩展学习系统的判断:手写接口会先赢可控性,可学习接口会在规模上吃掉更多例外 [4]。

§3 foreground × background 是子代理调度的连续时间版本

TM 最重要的 agent 启发不是多模态,而是把 foreground interaction model 和 async background model 同时保持在场。coding-agent harness 里的 Task/sub-agent dispatch 通常是离散的:主代理卡住,派子任务,等待回传,再合并上下文。TM 把同一结构改成实时版本:前台模型继续听、看、答、拒绝和接住用户修正,后台模型做工具、搜索和长推理,结果到达后由前台按当前互动时机编织回对话 [1]。KAME 已经展示 speak-while-thinking 的 tandem 架构 [12],MoshiRAG 也利用 full-duplex 响应中的时间缝隙做检索 [13],但两者的后台更像知识辅助层。TM 的关键差异是共享上下文与持续前台:后台不是另一个 response mode,而是一个与用户共同在场的 worker。由此 tool scheduling、context accounting 和 safety refusal 都不能只在 turn 结束时决策;它们要在连续时间里被预算、抢占和回滚。

§4 可复现 serving 变成交互研究的前置条件

连续互动把 nondeterminism 从评测噪声放大成产品行为差异,所以 TM 的 batch-invariant kernels 和 trainer-sampler bitwise alignment 是 Interaction Models 的基础设施。TM blog reported TML-Interaction-Small uses deterministic kernels with less than 5% end-to-end overhead, including NVLS all-reduce/reduce-scatter on Blackwell and Split-KV consistent accumulation between prefill and decode [1][2]。这条线和普通 LLM serving 的差别是归因压力:如果 200ms prefill、streaming session、tool dispatch 和 speech overlap 同时存在,一次不同的 accumulation order 可能表现成不同打断时机、不同拒绝边界或不同工具调用。SGLang streaming sessions 对应推理栈的另一半:把每个 200ms chunk 作为请求发来,但在 GPU 内维持 persistent sequence,减少重复 metadata 与内存分配 [22]。MoE 上选择 gather+gemv 而不是 grouped gemm 也不是微优化,而是低 batch、小 prefill、双向 serving shape 下的 latency 选择 [1]。

§5 新 benchmark 把互动能力从延迟分数改成行为坐标系

TM 的内部 benchmark 价值不在分数本身,而在把实时协作拆成传统模型几乎无法 emulate 的行为轴。TM blog reported FD-bench v1.5 average 77.8 for TML-Interaction-Small, versus GPT-realtime-2 minimal 46.8 and Gemini-flash-live high 45.5;reported turn-taking latency is 0.40s,Audio MultiChallenge APR is 43.4,TimeSpeak is 64.7,and CueSpeak is 81.7 [1]。这些数字要按 blog 一手证据处理,不能当独立 peer-reviewed 结论,但它们指出了评测坐标变化:TimeSpeak/CueSpeak 测语音时机,RepCount-A online 改造测视觉计数开口,ProactiveVideoQA 测答案出现时刻,Charades streaming 测 start/stop temporal grounding [19][20][21]。StreamBridge、Streamo、StreamingVLM、MMDuet2 与 AURA 都在逼近 streaming video 交互,但多数仍是 text-out 或 ASR/TTS 包装 [14][15][16][17][18]。TM 的强信号是把 speech-output 的持续时间、可重叠性和安全拒绝纳入同一评测面。

§6 对 agent/harness 的启发是连续时间治理

Interaction Models 对 agent/harness 设计的结论是:一旦共同在场变成默认,工具调度、上下文预算和安全拒绝都要从离散 turn 迁移到连续时间。传统 coding agent 可以在一次 tool call 前做许可、在一次编辑后跑测试、在 compaction 前计算摘要;实时互动模型需要在用户半句话、视觉事件和后台结果同时到来时做相同治理 [1]。这会改变 harness API:tool calls 需要可暂停和可撤销,context manager 需要按时间衰减而不只是按 token 截断,safety policy 需要处理 spoken refusal 的时机和语气,后台 agent 的结果也需要以增量证据而不是完整答案回流。与其把 TM blog 看成产品发布,更准确的读法是 agent runtime 的未来压力测试:当 forward pass 本身吃进互动时钟,harness 剩下的工作会从补交互能力转成约束、审计和资源仲裁。

研究立场对比

阵营 A: VAD-harness + 强 LM 仍是更稳路线

立场 — 这一路线认为 turn detection、ASR/TTS、工具和安全都外置更可控,强 LM 只需在清洁 turn 上推理;Qwen3-Omni 是最强公开对照之一 [11]。

证据：[11]

反方 — TM 的反驳是 proactive interjection、live translation、视觉纠错和实时工具回流都不是清洁 turn 问题;200ms micro-turn 把这些能力压进模型时钟 [1]。

判词 — 若目标是客服式稳定对话,VAD-harness 仍可能赢;若目标是 hands-on-keyboard 共创,TM 路线更像长期结构。

阵营 B: full-duplex speech 已经足够,无需 omni interaction model

立场 — Moshi、PersonaPlex 和 Nemotron VoiceChat 说明低延迟全双工语音可以不用完整 omni 主干 [8][9][10]。

证据：[8][9][10]

反方 — TM 的不同目标是 speech + vision + tools + background reasoning 的共同在场;仅语音 full-duplex 不解决视觉 cue 和工具调度 [1][14]。

判词 — full-duplex speech 是必要下界,不是完整 agent runtime。

阵营 C: 后台推理应该是模式切换,不是双在场

立场 — Anthropic/OpenAI 式 thinking-vs-instant 产品通常把深推理当模式选择:要么快答,要么等想完。KAME 和 MoshiRAG 已经显示可以异步注入,但范围较窄 [12][13]。

证据：[12][13]

反方 — TM 的双在场把等待期间的用户修正、视觉事件和工具状态都保留给前台模型,更接近 coding-agent 子代理调度的实时版本 [1]。

判词 — 模式切换适合明确任务;双在场适合需求持续变化的协作。

阵营 D: streaming-video 原型已经覆盖视觉主动性

立场 — StreamBridge、StreamingVLM、MMDuet2 和 AURA 已经把视觉流、何时回答和 proactive response 做成研究任务 [14][16][17][18]。

证据：[14][16][17][18]

反方 — TM 的差异在 speech-output 约束:说话有持续时间,能和用户重叠,还要和拒绝、工具和后台结果协调 [1]。

判词 — 视觉 proactive 是必要维度,但 speech-native full-duplex 才把互动约束合在一起。

悬而未决的问题

  • Q1.200ms 是否是最优时钟还没有公开消融。更短会提高 overhead,更长会损失打断与同传;需要按任务、语言和网络延迟分层评估 [1][22]。
  • Q2.连续时间 tool scheduling 需要新的安全与审计接口。工具调用可能在用户还没说完时启动,所以 pause、cancel、budget 和 partial-result merge 应成为 harness 原语 [1]。
  • Q3.context accounting 不能只按 token window 管理。实时音视频、后台推理和用户纠错需要按时间、证据新鲜度和可撤销性共同计账 [3][1]。
  • Q4.spoken refusal 的评价仍缺 benchmark。实时拒绝不仅要判定内容边界,还要判定插话时机、语气、持续时间和是否阻断安全工具 [1]。
  • Q5.deterministic serving 对互动质量的真实贡献需要公开 ablation。TM blog reported overhead 很低,但还需要量化 bitwise alignment 对 debug、eval variance 和 safety regression 的收益 [2]。
