16:Tb23,Critical batch size 的工程含义不是一个固定阈值,而是某个训练状态下“再扩大 token batch 还值不值”的局部判据。McCandlish 把它接到 gradient noise scale:当 batch 远小于噪声尺度时,更多样本主要降低梯度方差,step 数近似按 batch 反比下降;当 batch 远大于它时,新增 token 的边际信号迅速变低,wall-clock 并行收益开始以 token efficiency 为代价 [McCandlish2018EmpiricalLargeBatch][Shallue2018MeasuringBatchSize]。这个尺度随 loss、训练时长、数据混合、optimizer、LR schedule 和参数化变化,不能拿一次小实验的绝对 batch 当全程常数 [Zhang2024CriticalBatchPretraining][Merrill2025CriticalBatchRevisited]。

真正要分清的是 compute-optimal batch 和 token-optimal batch。Kaplan 与 Chinchilla 约束的是模型规模 N、训练 token D 和 compute 的配比,没有直接给 optimizer step 数;batch 决定同样 D 个 token 被多少次参数更新消化,所以它是 scaling law 到 optimizer trajectory 的桥 [Kaplan2020ScalingLaws][Hoffmann2022Chinchilla]。如果目标是固定 FLOPs 或固定 token budget 到最低 loss,过大 batch 会减少更新次数并浪费 token signal;如果目标是固定日历时间或集群吞吐,更大 batch 仍可能合理,但必须用 warmup、LR scaling、gradient accumulation、packing/length 控制和 data order 把早期低 CBS 阶段兜住 [Goyal2017AccurateLargeMinibatch][You2019LargeBatchBERT][Merrill2025CriticalBatchRevisited]。

LR scaling 也不是 linear scaling rule 的永久许可证。Goyal 的 ResNet 和 LARS/LAMB 的 BERT 经验说明 warmup + linear/sqrt scaling 能把一部分大 batch 推进临界区,Smith & Le 则把“降 LR”换成“增 batch”,本质是在调 SGD noise 而不是免费扩大 batch [Goyal2017AccurateLargeMinibatch][Smith2017DontDecayLR][Smith2018BayesianPerspective][You2017LargeBatchLARS][You2019LargeBatchBERT]。LLM 预训练里 AdamW、token batch、sequence packing、梯度裁剪和 cooldown 共同定标;超过临界区后,正确动作常常不是继续乘 batch,而是重配 LR schedule 或把并行资源转向 model/data parallelism [Loshchilov2019AdamW][Shoeybi2019MegatronLM][Brown2020LanguageModels]。

2024/2025 的新证据把老理论拉回 LLM 训练现实。Zhang et al. 在 C4 上训练 85M 到 1.2B autoregressive LM,发现 Chinchilla 联合放大时 CBS 会升,但控制 token 数后它主要随数据量/训练时长而不是模型大小增长 [Zhang2024CriticalBatchPretraining]。Merrill et al. 在 OLMo 1B/7B 上直接测 CBS,报告 CBS 初始接近 0、早期快速上升后平台化,并用 batch-size warmup 在 OLMo 1B 上以 43% 更少 gradient steps 达到略好 loss;这支持“动态 batch schedule”,但仍应按 source-reported 证据处理 [Merrill2025CriticalBatchRevisited][Groeneveld2024OLMo]。17:Tb93,Critical batch size is not a fixed threshold; it is a local answer to whether a larger token batch is still worth using at the current training state. McCandlish links it to gradient noise scale: when batch is far below the noise scale, more samples mostly reduce gradient variance and steps fall nearly inversely with batch; when batch is far above it, extra tokens add little statistical signal and wall-clock parallelism starts buying speed with token inefficiency [McCandlish2018EmpiricalLargeBatch][Shallue2018MeasuringBatchSize]. The scale moves with loss, training duration, data mixture, optimizer, LR schedule, and parameterization, so one proxy run cannot define a constant batch for the whole pretraining job [Zhang2024CriticalBatchPretraining][Merrill2025CriticalBatchRevisited].

The practical split is compute-optimal batch versus token-optimal batch. Kaplan and Chinchilla constrain model size N, training tokens D, and compute, but they do not directly specify optimizer steps; batch is the bridge from token budget to trajectory length [Kaplan2020ScalingLaws][Hoffmann2022Chinchilla]. For fixed FLOPs or fixed tokens to minimum loss, an oversized batch reduces updates and wastes token signal; for fixed calendar time or cluster throughput, a larger batch can still be rational, but only if warmup, LR scaling, gradient accumulation, packing/length control, and data order protect the low-CBS early phase [Goyal2017AccurateLargeMinibatch][You2019LargeBatchBERT][Merrill2025CriticalBatchRevisited].

Learning-rate scaling is not a permanent linear-scaling license. Goyal's ResNet recipe and LARS/LAMB BERT experience show that warmup plus linear/sqrt scaling can push part of large-batch training into the useful regime, while Smith & Le's “increase batch instead of decaying LR” treats batch as a noise-annealing knob, not as free batch growth [Goyal2017AccurateLargeMinibatch][Smith2017DontDecayLR][Smith2018BayesianPerspective][You2017LargeBatchLARS][You2019LargeBatchBERT]. In LLM pretraining, AdamW, token batch, sequence packing, gradient clipping, and cooldown are co-scaled; past the critical region the right move is often to retune the LR schedule or shift parallelism into model/data parallelism rather than multiplying batch again [Loshchilov2019AdamW][Shoeybi2019MegatronLM][Brown2020LanguageModels].

Recent evidence brings the older theory back to LLM pretraining. Zhang et al. train 85M to 1.2B autoregressive LMs on C4 and find CBS rises under Chinchilla-style joint scaling, but after controlling tokens it depends more on data/training duration than on model size [Zhang2024CriticalBatchPretraining]. Merrill et al. directly measure CBS on OLMo 1B/7B, report that CBS starts near zero, rises early, then plateaus, and use batch-size warmup to train OLMo 1B to slightly better loss with 43% fewer gradient steps; treat those numbers as source-reported current evidence [Merrill2025CriticalBatchRevisited][Groeneveld2024OLMo].18:T490,Critical batch size should be read as a local efficiency boundary: the same model and data mixture can have different critical points at different losses and LR schedules. McCandlish's empirical model writes GNS as gradient variance divided by squared mean gradient, explaining the bend in step efficiency as batch grows; Shallue's measurement study shows the bend depends on target loss, optimizer, and tuning budget [McCandlish2018EmpiricalLargeBatch][Shallue2018MeasuringBatchSize]. CBS is therefore best expressed as token batch, not sample count; sequence packing, length distribution, and gradient accumulation all alter the effective statistic.

The early generalization debate is easy to overread. Keskar ties large batch to sharp minima, Hoffer shows much of the gap can come from fewer updates/training time, and Smith's Bayesian/noise-scale view links generalization to SGD noise [Keskar2016LargeBatchSharpMinima][Hoffer2017TrainLonger][Smith2018BayesianPerspective]. For LLM teams, the safer decision order is first ask whether the batch still reduces steps in the current loss range, then ask whether the resulting noise level serves final generalization.19:T46e,Kaplan and Chinchilla answer how many parameters and tokens a compute budget should buy, not how many optimizer updates those tokens should be split into [Kaplan2020ScalingLaws][Hoffmann2022Chinchilla]. Batch enters at a precise point: for the same D tokens, a larger global batch means fewer optimizer steps; inside the linear regime this is parallelization, past CBS it changes the trajectory and loses token efficiency. Besiroglu and Porian's discussions of Chinchilla replication and discrepancies also show that token budget and optimization adequacy details can change scaling-law readings [Besiroglu2024ChinchillaOptimal][Porian2024BatchSizeScaling].

Compute-optimal batch therefore often leans toward throughput and cluster utilization, while token-optimal batch leans toward more effective updates. GPT-3's use of GNS for batch choice shows this bridge was already needed in large LM training; Megatron-LM reminds us that after the statistical boundary for data-parallel batch, better wall-clock can come from tensor/model/pipeline parallelism rather than larger token batch [Brown2020LanguageModels][Shoeybi2019MegatronLM].1a:T40c,Goyal's linear scaling plus warmup works because LR is adjusted to keep the per-token update trajectory comparable after batch grows; this is clean in ResNet/ImageNet, but must be re-estimated for AdamW pretraining [Goyal2017AccurateLargeMinibatch][Loshchilov2019AdamW]. You's LARS/LAMB line shows layer-wise trust ratios can stabilize extremely large BERT batches, but this solves layer-scale imbalance and optimizer stability, not the best loss for a fixed token budget [You2017LargeBatchLARS][You2019LargeBatchBERT].

Smith & Le are often misread as saying batch replaces LR decay. The better reading is that LR and batch jointly control SGD noise, and late-stage noise reduction can be achieved by lowering LR or increasing batch; once batch exceeds local CBS, more batch also sacrifices token efficiency [Smith2017DontDecayLR][Smith2018BayesianPerspective]. LLM recipes should sweep warmup, cosine/cooldown, gradient clipping, weight decay, and accumulation together; sweeping batch alone mistakes schedule failure for a batch law.1b:T4ae,The actionable policy is to treat batch schedule as part of the optimizer schedule. Early in training, high loss and low CBS favor small token batch or batch warmup to preserve update density; mid-training CBS growth makes data-parallel batch valuable for wall-clock; late training may benefit more from cooldown, data mixture, or parallelism changes than from another batch multiplier [Merrill2025CriticalBatchRevisited][Zhang2024CriticalBatchPretraining]. Adaptive batch schedule work extends the same judgment to data/model parallel constraints: batch is a scheduling variable, not a one-time launch parameter [Zhang2024AdaptiveBatchSchedules].

Task differences must stay in the decision. CLIP-style contrastive objectives gain in-batch negatives from larger batch, which is not the same mechanism as LM next-token loss; LAMB large-batch BERT is an optimizer engineering result, not proof of causal-LM token-optimal batch [Radford2021CLIP][You2019LargeBatchBERT]. For GPT-era and Chinchilla-era training, the minimum rule is to express global batch as token batch, record effective sequence length/packing/accumulation at each phase, and report both token-to-loss
