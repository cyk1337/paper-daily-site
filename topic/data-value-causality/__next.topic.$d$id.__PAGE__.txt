4:T539,The executable ordering is: use an ablation ladder as the merge gate, bulk filtering to compress candidates, influence/attribution for diagnosis, and causal inference for confounding and evaluator-bias checks. This ordering is not because ladders are more elegant; it is because they match the actual merge decision: fixed budget, fixed evaluation, regression-testable. After DCLM turned data recipes into controlled experiments, one clear signal is that transfer across scale depends on capability: MMLU is more stable, while HumanEval flips more easily. Anthropic’s influence work gives a second boundary: top-influence examples drift with model scale, so they should not be treated as durable assets. FineWeb-Edu, DSIR, and RegMix show that proxies and classifiers are useful for throughput, but every proxy needs a declared domain of validity. Causal methods should not be the daily main gate; they are better used to ask whether a correlation is polluted by length, duplication, or domain confounding, and whether an evaluator mistakes length bias for capability gain. The 2026 floor is an internal toolchain: reserve 1–5% of frontier compute for ladders, replace single loss with a per-capability matrix such as MMLU/HumanEval/MATH, and encode each proxy’s language, code, length, and time-domain validity into release gates.5:T4d6,Data-value assessment first needs to answer a merge question: under the same tokenizer, training recipe, token budget, and evaluation matrix, should a data change enter the mainline? This question is narrower than assigning a value to every example, and it is closer to the engineering loop. [DCLM2024] is useful because it turns filtering, deduplication, mixing, and thresholds into fixed-budget comparisons; it shows that scale transfer is more stable for knowledge/understanding, with about 0.78 Spearman for MMLU across 412M↔7B, but about 0.41 for HumanEval. [RegMix2024] fits mixture regression from small runs and reduces blind mixture sweeps, but the regression is reliable only when data families and recipes remain close. [OLMo2024] shows that logs and artifacts determine whether ladders are auditable: data versions, filter commits, packing, and checkpoint evaluations need to be retained. [DataOrganization2026] adds that in one-epoch or few-epoch training, ordering and packing change effective exposure; logging only which documents were selected is insufficient. A safer engineering order is to use proxies to narrow candidates, then use ladders to decide merges, with capability-dependent transfer written into the gate.6:T493,Classifiers, ladders, influence, and causal graphs are often placed on the same “data value” list, but they answer different questions. Bulk filters handle throughput: remove junk, duplication, template contamination, and visibly weak domains before expensive training. [FineWeb2024] distills large-model educational-quality ratings into a classifier, showing that this path can change token distributions at low cost. [PerplexedByPerplexity2024] pushes back on “perplexity pruning is enough” because a small reference model can remove long-tail structure useful to a larger model. [WhenLessIsMore2023] and [DataPruningScalingLimits2023] give the high-compression boundary: score ranking is not the same as an optimal subset. Influence handles diagnosis; the below-10% cross-scale overlap in [AnthropicInfluence2023] makes it weak as a durable gate. [LESS2024], [TRAK2023], and [Simfluence2023] support attribution when the target task and data pool are local. Causal methods handle confounding and evaluation bias; [CausalLL2024] and [SkillIt2023] are better suited to robustness checks, while [LengthControlledAlpacaEval2024] controls length bias in the metric.7:T471,A single validation loss is useful for training health, but it should not be the only acceptance metric for data changes. The reason is that capabilities respond differently to data selection. [MMLU2020] is closer to knowledge and reading comprehension, [HumanEval2021] represents code synthesis, and [Llemma2023] shows that math lines are sensitive to specialized corpora and code mixture. The MMLU≈0.78 versus HumanEval≈0.41 rank correlations in [DCLM2024] quantify the issue: the same small-model proxy can help knowledge filtering while being weak for code decisions. [Textbooks2023] gives another example of concentrated gains: synthetic textbooks and verifiers can drive HumanEval high, but the gain concentrates on code distributions covered by the verifier and should not be read as universal data value. [PhysicsLMs2024] shows that duplication and memorization curves can be nonlinear; one exposure can be close to ineffective, while 4–8 exposures produce measurable gains. A per-capability matrix should include at least MMLU, HumanEval, and MATH lines, and report repeats, confidence intervals, and negative regressions.8:T4dd,Framing data selection as a causal problem is useful, but it should not replace ladders. In real web data, the treatment is rarely a single variable: educational quality, domain, length, duplication, language, time period, and template format are entangled. IV-style methods such as [CausalLL2024] are useful for risk questions, such as whether length is merely a domain proxy or whether deduplication also removes rare facts. The hard part is that the exclusion restriction for an instrument is difficult to prove; if the instrument directly affects downstream capability, the estimate is biased. The mediator route in [SkillIt2023] is more usable when skills are enumerable, but emergent capability can break the skill list. Evaluation also has causal bias: [LengthControlledAlpacaEval2024] shows that length control changes preference-evaluation readings, so instruction-data selection that optimizes ordinary win rate can mistake longer answers for better answers. [Dedup2021] also warns that leakage and duplication can contaminate evaluation itself.
