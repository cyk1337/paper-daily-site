Programming Every Example：把预训练数据质量控制从全局规则推进到逐样本程序

逐样本 program 不是替代所有过滤器；它应当成为高价值、低覆盖缺陷上的第二层执行系统。

15 篇论文·2026年5月19日

作者@Thor·gpt-5.5

0 篇扩展证据

领域综述

预训练数据治理正在从“写一组全局规则”转向“为每个样本决定该执行什么操作”。全局 heuristics、去重、语言识别和困惑度过滤仍然是第一层防线；它们便宜、可复现、易审计，但只能处理长度、重复、编码错误、模板噪声这类稳定模式。模型打分和数据混合方法把规则升级为连续权重，能更好地选择领域和难度，但通常只输出一个 scalar score，难以说明样本应该被删除、截断、改写还是保留。Programming Every Example 的核心变化是把判断变成可执行程序：对每条样本生成或选择局部操作，再用 sandbox 和验证器约束副作用。这个方向的成败不取决于“LLM 会不会判断质量”这一句，而取决于三个工程边界：程序生成成本能否摊到预训练预算内，程序执行是否可复现且可审计，局部改写是否会破坏长程分布和事实密度。

TL;DR

Programming Every Example [1] 的价值不在于把清洗规则写得更花，而在于把数据治理的动作空间从“保留/丢弃/重采样”扩展到“对这条样本执行哪段可验证程序”。更稳的用法是两层架构：第一层继续用 C4、RefinedWeb、Dolma 这类全局 pipeline 做语言识别、dedup、模板噪声和安全过滤；第二层只把 5–20% 的边界样本送入 program 生成、sandbox 执行和验证。这样能保留规则系统的吞吐与审计性，又给 semantic defect、结构残缺、局部 boilerplate、代码块提取这类细粒度问题留下操作空间。若 program 日志、失败率、token 保留率和训练 FLOPs 没有公开，逐样本方法很容易退化成昂贵的黑盒 scorer。

核心断言

#1在 10^11–10^12 token 级别语料中，抽检 0.1% 也对应 10^8–10^9 token；逐样本 program 若没有自动验证和失败回退，人工审计无法覆盖主要风险。
#210–50 条全局规则足以覆盖语言、长度、重复、乱码和模板噪声，但对“同一模式在不同上下文中应删或应留”的错误，precision/recall 会被规则粒度卡住。
#3只输出一个质量分数的 scorer 至少丢失 4 类动作信息：删除、截断、抽取、改写；Programming Every Example [1] 的可证伪优势应体现在这些动作的受控执行率，而不只是平均分更高。
#4逐样本 program 只有在生成与执行开销低于保留样本预训练 FLOPs 的 1–5% 时才适合作为常规 pipeline；超过 10% 时，更像离线构造高价值子集的工具。

§1 质量控制的分歧不在“要不要过滤”，而在动作空间有多大

结论先行：Programming Every Example [1] 反驳的不是 C4 式规则本身，而是“全局规则足以表达专家判断”这一隐含假设。Raffel et al. [2] 用语言识别、坏词、短行和去重做出 C4；Penedo et al. [7] 把网页清洗推进到高吞吐工程；Lee et al. [4] 证明重复会放大记忆与评测污染。这些方法适合稳定、可枚举、可批处理的缺陷。问题出在长尾：同样的导航栏在论坛页应删，在代码教程里可能是上下文；同样的表格残片在商品页是噪声，在科学文档里可能保留信息。Scalar scorer 把这种差别压成一个分数，通常只能决定保留或丢弃。Programming Every Example [1] 把动作改为 program：抽取正文、删除局部 boilerplate、修复格式、验证代码块或拒绝执行。这个选择更贵，但表达力不同；它不是更强过滤器，而是更细动作层。

逐样本 program 的卖点不是更严格，而是能表达“对这条样本该做什么”。

§2 Scorer 和 mixture 方法解决“选哪些数据”，但通常不解决“如何修这条数据”

一个务实区分：scorer 优化排序，program 优化操作。Marion et al. [11] 研究 pruning，说明同样 token 预算下数据子集会改变预训练效率；FineWeb-Edu [15] 用教育性 classifier 从 FineWeb 中选子集，给网页质量打分提供了便宜基线；Li et al. [14] 把过滤方法放到固定 compute 评测中，迫使方法报告同 token、同 FLOPs 下的收益。另一条线是 mixture：Xie et al. [8] 用 importance resampling 贴近目标分布，Xie et al. [9] 用 proxy 模型学习 domain weights。它们和 Programming Every Example [1] 的差别不是谁更“智能”，而是输出类型不同：weight 和 score 改变采样概率，program 改变样本内容或结构。若任务只是提高数学、代码或百科比例，mixture 更便宜；若缺陷位于单条样本内部，比如正文被菜单包围、代码块缺少依赖、问答结构混乱，program 才有动作优势。

§3 程序化清洗的核心约束是可审计，而不是生成能力

逐样本 program 最容易被高估的地方是“能生成操作”，最容易被低估的地方是“能复查操作”。Soldaini et al. [13] 的价值在于公开来源、过滤器和处理轨迹，使数据实验可以被别人复跑；Chen et al. [10] 的 operator 体系也把清洗动作拆成可组合模块。Programming Every Example [1] 若要进入预训练主链路，需要继承这两个约束：每条样本至少保存 input hash、program hash、执行环境、输出 hash、validator 结果、失败原因和回退路径。否则 program 生成器一旦更新，同一批原始数据可能得到不同语料，训练差异无法归因。另一个边界是副作用。文件系统、网络访问、随机数、外部包版本都应默认关闭或固定；代码样本验证可用 sandbox，但网页文本改写也需要 schema validator、长度变化阈值和事实保留抽检。没有这些约束，逐样本 program 只是把不可解释规则换成不可解释模型。

能生成 program 只是入口；能解释每次执行为什么改变了语料，才是预训练 pipeline 能接受的条件。

§4 合成数据经验支持“生成能提升质量”，但不等于支持任意改写原始语料

合成数据给逐样本 program 提供了正例，也给出边界。Gunasekar et al. [12] 用 textbook 风格代码数据训练小模型，说明高密度生成数据能改变 code 任务上的样本效率；Ben Allal et al. [16] 用主题覆盖和 prompt 控制生成大规模教材式语料，说明质量可以通过 recipe 工程化获得。Programming Every Example [1] 与它们共享一个假设：生成模型可以把松散、噪声高的数据变成更适合学习的序列。但二者风险不同。合成教材从零生成，主要风险是覆盖偏差、模板化和幻觉；逐样本改写保留原始来源，风险是局部操作破坏事实、删除少数语言信号、把网页分布压成统一风格。Hoffmann et al. [6] 提醒 token 预算和模型参数存在配比约束；如果改写让 token 更少但信息密度更高，需要在固定 compute 下验证 loss、下游任务和 contamination，而不是只看清洗后语料更“像教材”。

§5 评价应从“数据看起来更好”改成“同预算训练曲线更好归因”

逐样本 program 的评测最低要求是四组对照。第一，同 raw corpus、同 tokenizer、同 packing、同训练 FLOPs，对比全局规则、scorer、mixture 和 program；Li et al. [14] 的固定预算设定可以直接借用。第二，报告 token 保留率、样本保留率、程序失败率、validator 拒绝率和人工抽检错误率；没有这些数，无法判断收益来自更好清洗还是更少训练噪声。第三，按缺陷类型分桶：boilerplate、格式残缺、低信息密度、代码不可运行、多语言混杂分别算收益，因为不同 program 的错误模式不同。第四，做回退实验：program 输出被拒绝时保留原样、丢弃、或用 scorer 决策，三者训练结果应分开。Rae et al. [5] 把数据 pipeline 放进大模型 recipe 讨论，说明质量实验不能脱离模型规模。结论层面的建议是：先在 1B–7B 模型、50B–300B token 区间证明稳定收益，再谈 10^13 token 级主训练链路。

研究立场对比

阵营 A：全局规则和 dedup 仍是主链路

立场 — Raffel et al. [2]、Penedo et al. [7]、Lee et al. [4] 支持先用固定规则处理高频缺陷。这个阵营的核心选择是简单动作、全量覆盖、强复现。

证据：[2][7][4]

反方 — Programming Every Example [1] 反驳的是规则的表达粒度：同一规则在不同上下文中会出现相反决策，规则数量继续增加会降低可维护性。

判词 — 一条更稳的读法：全局规则应保留为第一层，覆盖 80–95% 的便宜缺陷；不要让逐样本 program 处理语言识别、exact dedup、长度截断这类低熵任务。

阵营 B：质量 scorer 足够，排序比改写更稳

立场 — FineWeb-Edu [15]、Marion et al. [11] 和 Li et al. [14] 支持用 learned scorer 做过滤和数据剪枝。这个阵营偏向少改动原文，降低事实破坏风险。

证据：[15][11][14]

反方 — Programming Every Example [1] 的反驳点是 scorer 的动作空间太窄。一个 0.72 分的网页可能该抽取正文，不该整页丢弃；一个 0.91 分的代码样本可能仍需执行验证。

判词 — 结论层面的建议：scorer 适合作为 router，把 5–20% 的边界样本送到 program 层；不宜把 scorer 当最终执行器，除非目标动作只有保留和丢弃。

阵营 C：数据混合比逐样本修复更影响训练

立场 — Xie et al. [8] 和 Xie et al. [9] 支持先调 domain weights；Gao et al. [3] 也把来源组合当作质量变量。这个阵营认为来源比例常比局部清洗更划算。

证据：[8][9][3]

反方 — Programming Every Example [1] 处理的是 mixture 无法表达的内部缺陷。把网页域权重调低不会告诉 pipeline 哪个 DOM 片段该删，也不会验证代码块是否可运行。

判词 — 一个更务实的定位：mixture 决定桶级预算，program 决定桶内动作。先用 mixture 控制数学、代码、多语言比例，再在高损耗桶内启用逐样本 program。

阵营 D：直接生成高质量合成数据，少修网页噪声

立场 — Gunasekar et al. [12] 和 Ben Allal et al. [16] 支持用 recipe 生成高密度教材式语料。这个阵营认为从零生成比修复低质网页更可控。

证据：[12][16]

反方 — Programming Every Example [1] 的不同点是保留真实分布和来源痕迹。全合成容易带来 topic coverage 偏差、模板化和模型自蒸馏闭环。

判词 — 结论层面的建议：合成数据适合填补稀缺技能或构造教材子集；逐样本 program 适合从真实网页中回收可学习片段。二者不应互相替代。

实践要点

实操要点：1) 先做便宜层：language ID、exact/near dedup、MIME 检查、长度边界、乱码检测必须在 program 前完成，[2]+[4]+[7] 已给出足够强的工程基线。2) 不要全量调用 program generator；先用 scorer 或规则路由，只处理 5–20% 的边界样本，[15]+[11] 适合作为 router 参考。3) 每条 program 必须保存 input hash、program hash、output hash、validator 状态、失败原因和 fallback；否则无法达到 [13] 要求的可追溯性。4) program 动作先限制在 4 类：抽取、局部删除、格式修复、可执行验证；不要一开始允许开放式改写，因为事实保留难测，[1]+[10] 更适合作为 operator 组合而非自由生成。5) 评测固定 raw corpus、tokenizer、packing、模型架构、训练 FLOPs；采用 [14] 式预算控制，不接受只报告“清洗后语料更好看”。6) mixture 仍要单独调；先用 [8]+[9] 控制 domain weight，再在高噪声域内启用 program。7) 如果 program 生成和执行成本超过保留样本预训练 FLOPs 的 10%，不要放进常规主链路；改为离线构造高价值子集。8) 合成数据和逐样本修复分开归因；[12]+[16] 的收益不能直接外推到任意网页改写。

悬而未决的问题

  • Q1.逐样本 program 在 1B–7B 模型、50B–300B token 固定预算下，相比 scorer-only 是否能稳定带来至少 0.02–0.05 nats validation loss 降低？需要 controlled experiment 和公开训练曲线。
  • Q2.program 生成器更新后，同一 raw corpus 的输出漂移有多大？需要报告 output hash 变化率、token 保留率变化和下游任务方差。
  • Q3.局部改写会不会系统性删除少数语言、低资源领域或非标准写作风格？需要按语言、来源、长度、主题分桶的保留率和误删率。
  • Q4.代码验证类 program 的收益能否迁移到普通网页文本？代码有编译器和测试，网页事实保留缺少同等强度 oracle，这是当前证据最薄的部分。
  • Q5.program 层应处理多少比例样本才划算？5%、10%、20%、50% 四档的成本、失败率和训练收益需要在同一 raw corpus 上比较。
