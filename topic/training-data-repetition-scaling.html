训练数据重复的 scaling law：从 4-epoch 神话到 per-subset 决策

三条 scaling-law、不是一个 4-epoch 阈值——把 epochs 拆成 per-subset 决策

16 篇论文·2026年5月8日

领域综述

有限数据能不能被重复用，答案不是“能”或“不能”，而是要先判断重复发生在哪类子集上。在 web-bulk 上，重复主要是在同一信息上继续写权重；Hernandez 2022 与 Muennighoff 2023 看到的 2–4 epoch 后 effective token 折算率下降，仍是最可靠的默认线 [3][5]。在 reasoning、算术和长尾事实上，相同结论不成立：Charton 2024 的算术实验、Allen-Zhu 2024 的事实写入曲线、Wang 2025 的 implicit-reasoning scaling law 都指向同一件事——有些能力不是靠更多不同样例出现，而是靠同一pattern 被看够次数后才 lock in [11][10][14]。所以“扩 unique data”和“重复有限高质量数据”不是替代关系；前者解决覆盖面，后者解决某些 key 没有写深的问题。把二者混成一个 global epoch 超参，才是 4-epoch 神话真正的问题。

更精确的边界是三条曲线。曲线 0 是 Chinchilla/Kaplan 的 compute-bound 区间：D 充裕时，1 epoch 的 fresh token 是基准，重复通常浪费 [1][2]。曲线 1 是固定 mixture 的 uniform repeat：干净池前几轮仍有收益，但收益很快从“等效新鲜 token”变成 memorization 与 capacity crowding [3][6]。曲线 2 是 targeted repeat：对 math/code/reasoning/长尾事实这类子集，8–32 次曝光仍可能比同 token budget 的更多 fresh examples 更有效 [11][16]。Cabannes 2024 的 associative-memory 解释把这三条线接起来：重复不是凭空创造新 key，而是把已有 key 写深；该 key 未写够时是泛化收益，已饱和时就是记忆化挤占 [9]。

因此，最低成本的验证不应是“看哪个 epoch loss 最低”，而应是一个小型 scaling ladder：3 个模型规模 × 3 个 multiplicity × 3 类 subset，在同 token budget 下比较。loss/bpb 只回答语言模型平均拟合得更好没有，不能回答是否学到目标能力、是否进入记忆化相位、是否污染评测。Hong 2024 证明 representation-side memorization 早于 val loss 反弹出现 [7]；Charton 2024 证明能力浮现时 loss 可以几乎不动 [11]。所以 ladder 的验收指标至少要包括 val loss、memorization window、per-skill learning curve、独立 contamination probe 和 capability eval。这样得到的不是一个“4 epoch 上限”，而是每类子集自己的 repeat envelope。

TL;DR

训练数据重复的正确问题不是“4 epoch 行不行”，而是某个子集的 key 是否还没写够。web-bulk 的价值主要是覆盖面，1–4 epoch 后继续重复通常不如扩 unique data [3][5]；reasoning、算术和长尾事实的价值常在 pattern 被多次看见后才释放，少样例 × 高 multiplicity 可以胜过更多 fresh examples [11][10][14]。所以 unique data 和 repetition 是互补约束：前者买覆盖，后者买 key depth。验证上不要只看 loss；最小可执行方案是 3N × 3 multiplicity × 3 subset 的 ladder，同时报 loss、memorization window、per-skill curve、representation fingerprint、contamination probe 与 capability eval [7][16][15]。

核心断言

#1web-bulk 需要扩 unique data；reasoning / 长尾事实需要高 multiplicity。把两者做成二选一，是 data-bound pre-training 的错误抽象 [5][11]。
#2loss 是训练健康指标，不是 repetition 配方指标；memorization fingerprint 与 capability eval 必须一起看 [7][11]。
#33N × 3 multiplicity × 3 subset 的 ladder 是最小 falsification test；不带 K-epoch 轴的proxy 不能预测 frontier reasoning 曲线 [15]。
#4“4-epoch 普世上限”是 mixture-conditional 的口语版——Galactica 的 4-ep 与 Muennighoff 的 4-ep 不在同一条曲线 [Taylor2022Galactica · Muennighoff2023DataConstrained]。
#5associative-memory 模型把曲线 1 退化与曲线 2 获益统一在“写已有 key 深”的尺度上——“epoch 全局旋钮”概念上就是错的 [9]。
#6scaling-law 拟合必须把 multiplicity 当独立 nuisance；proxy 不带 K-epoch 维就不能预测frontier reasoning 曲线 [Pearce2024Hitchhiker · Su2024Unraveling · Lin2025ProxyReasoning]。

§1 数据墙的两个真问题：unique data 必须扩吗？loss 还能当唯一指标吗？

答案不是“多找数据”或“多训几轮”，而是先给每类子集定 repeat envelope。 同一训练 run 里至少有三种不同数据对象：web-bulk、curated high-quality、reasoning/long-tail。它们共享一个 optimizer，却不共享同一条 repetition law。

Q1：是否真的必须 scaling up unique data？ 在 web-bulk 上，是。Hernandez 与 Muennighoff 的 uniform-repeat 实验仍是最可靠的默认线：前几轮能近似兑换 fresh token，随后折算率快速下降 [3][5]；Xue 2023 在 1B–13B 多尺度复现了这个方向 [6]。这类文本的主要价值是覆盖面，重复一遍不能替代新页面、新主题、新格式。

在 reasoning、算术和长尾事实上，答案相反。Charton 2024 在受控算术上给出最干净的反例：同 token 预算下，少样例 × 高 multiplicity 出现能力，多样例 × 单次曝光不出现 [11]。Allen-Zhu 2024 的 per-fact 曲线也指向同一个机制：很多事实不是一次曝光就进入参数，而是在第 K 次曝光附近突然 lock in [10]。Wang 2025 把这个现象写进 implicit-reasoning scaling law：pattern multiplicity 是独立变量，不是 D 的别名 [14]。

Galactica 处在中间：100%-curated 科学池 4+ epoch 仍能降 loss [4]，说明高质量有限池可以被重复使用；但它不证明 web-bulk 也能无脑重复，也不证明不需要扩新数据。更稳的结论是：扩 unique data 买覆盖，targeted repetition 买 key depth。两者是互补约束，不是二选一。

Q2：简单 scaling ladder 怎么做，loss 能不能作唯一指标？ 最小 ladder 不需要大：3 个模型规模 × 3 个 multiplicity × 3 类 subset，同 token 预算即可。这个设计不是为了找“最低 loss 的 cell”，而是为了 falsify 两个假设：web-bulk 是否真的在 m=4/16 之后进入折算率下降，reasoning-targeted 是否在 m=16 才出现能力。Lin 2025 的结论很直接：proxy 不带 K-epoch 维，就无法预测 frontier reasoning 曲线 [15]。

loss 只能当守门指标，不能当结论指标。Hong 2024 显示 representation/logit 侧的 memorization 早于 val loss 反弹 [7]；Charton 2024 显示能力浮现时 loss 可以几乎不动 [11]。因此 ladder 每个 cell 至少要同时报：val loss/bpb、memorization window、per-skill learning curve、0-exposure contamination probe、capability eval。只看 loss，等于看不见 curve 1 的越线，也看不见 curve 2 的收益。

§2 三条曲线：把 epochs 当全局旋钮的根本错误

曲线 0（compute-bound）: D ≥ 20·N，1 epoch 最优 [1][2]。对今天的 frontier 几乎不再适用，但仍是衡量 efficiency 的零点——任何 multi-epoch 配方都该和“同 compute 下用更多 fresh token 1 epoch”做对照。

曲线 1（uniform repeat）: 在固定 mixture 上均匀多 epoch。三篇互相印证的工作：
- Hernandez 2022 [3] 在 small/mid scale 上观察到：把一个干净池子里塞入 0.1%–10% 的“被重复 K 次”子集，整体 loss 与 K 不是单调下降——超过约束阈值后开始反吞，并在 induction-head 上留下机制指纹；
- Muennighoff 2023 [5] 把它写成可拟合的“effective fresh-token equivalent”函数：前 ~2–4 epochs 接近 1（每多一遍 ≈ 等量新鲜），后续以 e−α⋅(E−4) 形式衰减；
- Xue 2023 [6] 在 1B–13B 多个尺度独立复现，并观察到 quality不一致时曲线斜率剧变——高 quality 子集多 1–2 epoch 仍然涨，低 quality 子集 1 ep 后立掉。
判别：阵营“4 ep 作普世上限”的同学读这三篇时常常忽略两件事：(a) 实验都是uniform passes over fixed mixture，不能直接外推到 per-subset 决策；(b) Galactica [4] 的 4-epoch 是在已经 100% 人工筛过的科学语料上，和 web-scale 的 4 epoch不是同一条曲线——把这两个 number 混着说，是“4 epoch 神话”的关键源头。

曲线 2（targeted repeat）: 同一子集重复 8–32 次仍涨。三篇组合：
- Charton & Kempe 2024 [11] 在受控算术任务上，同 token 预算下少样例 × 高 multiplicity 触发 emergent capability，多样例 × 1 ep 不触发；
- Allen-Zhu 2024 [10] 在受控合成事实上做 per-fact 跟踪，证明事实写入参数所需 exposure 远多于 1，且很多事实在第 K 次曝光才突然 lock-in；
- Zuo 2025 [16] 用 memorization window 信号在 LLM 上把uniform 4-epoch 上限往后推；同样 budget 下 quality-test set 仍持续涨。

为什么三条曲线不能合一：曲线 1 的退化机制（key 容量已饱和→ memorization挤占 generalization）和曲线 2 的获益机制（emergent capability 必须经历多次曝光才浮现）发生在同一个模型里——但作用在不同子集上。Cabannes 2024 的associative-memory 模型 [9] 给出最简的统一解释：repeat = 把已有 key 写得更深；这件事在 key 已经存在但没写够时是收益（曲线 2），在 key 早已饱和但模型还在花容量去复读时是损耗（曲线 1）。全局 epoch 旋钮把两者混成一条平均曲线，自然得到一个 4-epoch 假上限。

§3 机制：repeat 何时是“写深”，何时是“占座”

两个机制账放在一起读：
- Cabannes 2024 [9] 把 transformer 当 Hopfield-style associative memory，推得 repeat 在固定容量下是 (a) 已有 key 深化、(b) 已有 key 与新输入的interference 增加、(c) 没有创建新 key。曲线 2 的获益对应 (a) 主导，曲线 1 的损耗对应(b) 主导。两条曲线哪个主导取决于：subset 在该模型规模下的 key 是否已经写够。
- Hong 2024 [7] 在 logits 与表征层观察到 repeat 引发的相位转变：在表征上可以先于输出文本看到 memorization 迹象。这意味着只 watch validation loss 已经太晚——等到 loss 反弹时大量 capacity 已经被划给 memorization。
- Chang 2024 [13] 给出工程上可用的 estimator：per-example loss轨迹的早期 signature 即可预测“多重复对该 skill 是泛化还是过拟合”。这把 Cabannes / Hong 的机制结论翻译成了一个早期信号——不必等 frontier run 跑完。

与曲线 0/1/2 的对应：
- 曲线 0：key 还未被写满，1 epoch 已经把 D 用尽；不重就好。
- 曲线 1：mixture 内大部分 key 已经被写深、少量 key 已经饱和；继续 uniform 重复等于按平均比例继续给所有 key 加“写入”，饱和的那一批进入 memorization 挤占——这就是为什么曲线 1 是先涨后掉。
- 曲线 2：目标子集（math / code / 长尾事实）对应的 key 远未写满；即使全模型已经接近饱和，这些 key 的写入仍然产生 generalization 收益。Allen-Zhu 2024 的 per-fact曲线就是这件事的微观显微镜。

判别：把 4-epoch 神话归因到“模型容量”是错的——容量是 per-key 的，不是 per-token 的。正确的诊断是“按 subset 看 key 写够没有”，而 Chang 2024 给的 per-example signature是目前最便宜的探针。

§4 方法学：在重复语料上估 scaling-law 的常见错法

核心错法：把 multiplicity 强塞进 D，再用 Chinchilla 形式拟合 L = E + A·N−α+B·D−β。Pearce 2024 [12] 在 1000+ 个 fit 上系统给出这种做法的 bias 模式：估出的 β 会变小、E（不可约项）会变大——表面上像“数据见底”，其实是 estimator artifact。

两条修正线：
1. Functional form：Su 2024 [8] 把 multiplicity 拎成独立 nuisance：L = E + A·N−α+B·De​ff(D_unique, multiplicity)^{-β}，其中 De​ff(·) 在 (D_unique, m=1) 处回归 D_unique，在 m≫1 时按 Muennighoff 的指数衰减形式。这种解耦后，曲线 1 和曲线 2 可以共存于同一拟合。
2. Reasoning 轴：Wang 2025 [14] 进一步把 implicit-reasoning 的generalization gap 写成 (N, D, pattern multiplicity) 的三元函数——pattern multiplicity 不是D 的别名，而是独立轴。这把 Charton 2024 的算术结论从“个别任务现象”推到 reasoning 通用层。

proxy 的最大坑：Lin 2025 [15] 给出最实用的一条结论：要让 small proxy预测大模型在 reasoning 上的真实曲线，proxy 必须显式带 multi-epoch 维度。仅用 1-epoch proxy做 ablation ladder（DCLM 风格）会在 D-bound 区间得出错误的“repeat 4 ep 最优”；用 K-epoch proxy 拟合，则可在 frontier 验证 K=4–32 都成立。

对工程的直接含义：scaling-law 团队应同时报告 (D_unique, multiplicity 分布)，而不是单点 D。任何 epoch ablation 都应在 proxy 上显式扫 multi-epoch 维，否则会把“proxy 没看到的曲线 2 收益”全部归零。

§5 简单可执行：27-run ladder + 多指标，把曲线 0/1/2 直接读出来

这个 ladder 不是为了拟合一条漂亮曲线，而是为了让两个决策可证伪。 第一，web-bulk 在多大 multiplicity 后不再值得重复；第二，reasoning-targeted 子集是否真的需要高 multiplicity 才出现能力。只要设计能回答这两个问题，ladder 可以很小。

最小设计：3 个 N（例如 100M / 400M / 1B）× 3 个 multiplicity（1 / 4 / 16）× 3 类 subset（web-bulk / curated-quality / reasoning-targeted），每个 cell 同 token budget。N 轴负责排除“只是模型太小”的解释；multiplicity 轴负责验证 repeat 是否本身有效；subset 轴负责防止 web-bulk 的退化曲线把 reasoning 的收益平均掉。Lin 2025 的提醒很关键：proxy 如果没有 K-epoch 轴，就不能预测 frontier reasoning 曲线 [15]。

读数方式：web-bulk 的 m=1 → m=4/16 应该表现为 Curve 1：loss 可能先降，但 capability 收益变弱，memorization signal 上升。reasoning-targeted 的 m=1 → m=16 应该表现为 Curve 2：loss 不一定明显变化，但 math/code/fact 受控评测应出现非线性跃迁。curated-quality 是边界条件：它测试 Galactica 式高质量池到底能把 Curve 1 的拐点推后多少 [4]。如果这三类cell 被混在一起，平均数会再次伪装成“4 epoch 上限”。

指标必须比 loss 多。 loss/bpb 仍然要报，因为它是训练是否失控的第一道门槛；但它不能决定“重复是否有用”。需要同时报四类附加信号：(1) memorization window，用 loss-retention 与downstream growth 的比例看是否已经从写深 key 变成复读 [16]；(2) per-skill learning curve，用受控 math/code/fact 子集判断高 multiplicity 是泛化还是过拟合 [13]；(3) representation/logit fingerprint，因为 Hong 2024 显示记忆化相位会早于 val-loss 反弹出现 [7]；(4) 0-exposure contamination probe，防止 targeted repeat 把 benchmark 也一起写进参数。

验收口径：不要选择最低 loss 的 cell；选择满足约束的 envelope。web-bulk 的 envelope 是“m 增加后 capability 不涨且 memorization 上升则停”；reasoning-targeted 的 envelope 是“capability 仍涨、contamination 不涨、memorization window 未过线则继续”；curated-quality 的envelope 是“loss 下降必须被 capability 或 retention 信号确认”。这样 ladder 输出的是生产配方，不是一条事后解释的 scaling plot。

研究立场对比

阵营 A：4-epoch 是 universal ceiling（Muennighoff orthodox 的口语版）

立场 — 把 Muennighoff 2023 的 effective fresh-token 曲线视为通用上限：D 见底就重 ≤ 4 ep，再多就是浪费。

证据：[5][3][6]

反方 — 反例 1：Charton2024Emergent 在算术任务上证明少样例 × 高 multiplicity 是 emergentcapability 的必要条件——同 budget 下 ≤ 4 ep 拿不出来。反例 2：Galactica 的 4+ epoch 在 100%-curated 科学语料上仍然涨 [4]——“4 ep”这个数字本身是 mixture-conditional。反例 3：Lin2025ProxyReasoning 显示1-epoch proxy 估出的“4 ep 最优”是 estimator artifact，不是真实现象。

判词 — 在 web-bulk uniform 重复这一条窄轨上，Camp A 是对的；但作为 frontier 通用上限，证据不足且与 2024–2025 的反例相冲突。把它当配方 default 没事，当上限就错。

阵营 B：定向高 multiplicity（reasoning / 长尾事实子集，8–32 ep）

立场 — 在 emergent capability、math、code、长尾事实子集上，重复 8–32 次仍涨；按 subset设独立 multiplicity 才是 D-bound 区间的正确配方。

证据：[11][16][10][14]

反方 — Counter（来自 Camp A）：在 web-bulk 上同样 8–32 ep 会触发曲线 1 的 memorization-crowd效应——mixture-wide 不能照搬。Camp B 的正确读法是把它绑定在“关键子集 + 监控信号”上，而不是“全 mixture 8–32 ep”。Hong2024ROME 给的相位证据是必要监控；只盯 val loss 会在曲线进入相位 2 后才被发现。

判词 — Camp B 在 reasoning / 长尾事实上是对的，证据已经叠到“多个独立机制账”级别[Charton2024Emergent · AllenZhu2024Knowledge · Yang2025ImplicitReasoning]；但落地必须配 per-skill monitor（Chang2024LearningDynamics）和 memorization window（Zuo2025MemoGuided），否则会把 Camp B 的赢面在 web-bulk 上还回去。

阵营 C：repeat 是 anti-pattern——优先扩 fresh data / 高质量合成

立场 — 重复出多少 effective token 都不如同 budget 多搞 fresh tokens；frontier 的正确投资是 data acquisition + 合成数据，而非 per-subset multiplicity 调度。

证据：[2][3]

反方 — Counter：Camp C 在 D 充裕时是对的（曲线 0），但 2024 起 frontier 已经离开Chinchilla-optimal 区间。Hoffmann 自己的 D ≈ 20·N 在 N ≈ 70B 时要求 D ≈ 1.4T，但frontier 已经在 14.8T、15T 量级运行——unique high-quality 池估计在 10–20T，再扩 fresh 的边际成本（合成 + 高质量）已经接近曲线 1/2 的边际收益。Charton2024Emergent 还给出更尖锐的反例：在算术上，多 fresh 反而不如多 repeat。

判词 — 正确读法：扩 fresh 与 per-subset multiplicity 不是替代关系，而是同时进行——high-quality 合成喂 reasoning 子集，per-subset multiplicity 调度决定怎么用它。把 Camp C 当 default investment direction 还是对的，但把它当反对 multiplicity 的理由就错了。

阵营 D：repetition × quality × diversity 是 trilemma，不要单轴最优化

立场 — 把 repetition 当配方时同时记 quality 与 diversity 两条账：高 quality 子集买更多 epoch，diversity 见顶时 multiplicity 收益反而上升；任何只调 epoch 的实验都会被另两个轴 confound。

证据：[6][12][8]

反方 — Counter：trilemma 框架在概念上正确，但工程上需要可操作的 estimator——否则就退化为“都重要”的口号。Chang2024LearningDynamics + Zuo2025MemoGuided + Lin2025ProxyReasoning 三个 estimator 一起，恰好填上 quality（per-skill curve）× repetition（memo window）× diversity（pattern multiplicity）三轴各一把可观测信号。Camp D 应当具体引用这三件工具，而不是停在“是 trilemma”。

判词 — Camp D 在分析层面正确，落地层面不完整。补完三轴 estimator 后是和 Camp B 兼容的——二者拼起来才是 2026 的可执行配方。

实践要点

可执行清单（2026 frontier 视角，带边界）：

1. Do：把 repetition 拆成 per-subset 决策，按曲线 0/1/2 分配。最低限度：web-bulk ≤ 2 ep + high-quality curated ≤ 4–6 ep + reasoning/math/长尾事实 8–32 ep。Don't：留单一 epochs全局超参 [Muennighoff2023DataConstrained · Charton2024Emergent · Xue2023TokenCrisis]。
2. Do：scaling-law 拟合显式拆 (D_unique, multiplicity 分布)，proxy 必须显式带 K-epoch 维。Don't：把 multiplicity 折进 scalar D 后再 fit Chinchilla 形式 [Pearce2024Hitchhiker · Su2024Unraveling · Lin2025ProxyReasoning]。
3. Do：reasoning / 长尾事实子集做 multiplicity sweep（8/16/32），与 fresh-data 投资做同 budget A/B 对照，否则 Camp B vs Camp C 的辩论无证据。Don't：只在 web-bulk 做 ablation 就外推到全 mixture [Charton2024Emergent · Yang2025ImplicitReasoning]。
4. Do：监控信号至少三件——val loss + memorization window（Zuo2025）+ per-skill 学习曲线 （Chang2024）。Don't：只看 validation loss——曲线 1 反吞拐点上看到 loss 反弹时已经迟了 [Hong2024ROME · Chang2024LearningDynamics · Zuo2025MemoGuided]。
5. Do：benchmark / PII / 版权 子集硬绑 0–1 次曝光，与 multiplicity 优化完全隔离——这条逻辑由姊妹报告 [pretrain-data-repetition] 完整给出。Don't：把它和曲线 1/2 混在一起讨论——guardrail 与 efficiency 是两件事。
6. Do：把 De​ff 当 nuisance 参数看；任何 “4 ep 是上限” 的论断必须附 mixture / subset 限定。Don't：把 Galactica 4 ep 与 Muennighoff 4 ep 当同一 number 引用 [Taylor2022Galactica · Muennighoff2023DataConstrained]。
7. Do：在 frontier scale 上做 small-proxy + multi-epoch ablation 时，proxy 配方（mixture / multiplicity）必须 mirror 目标 run。Don't：用 1-epoch DCLM-style ablation ladder 决定 frontier 的 epoch [15]。
8. Open：mechanism 解释（Cabannes / ROME）尚未给出工程上可直接读的 capacity-vs-multiplicity 公式，目前都是 per-skill estimator + 经验校准 [Cabannes2024AssocMem · Hong2024ROME]。证据不足时优先采集监控信号，不要把机制论文当 recipe 直接抄。

悬而未决的问题

  • Q1.曲线 2 的“targeted 8–32 ep”上限本身是 emergent-capability 出现就停，还是会在某个 multiplicity 之后也进入 memorization-crowd 阶段？目前 Charton2024 / Zuo2025 都没扫到上限。
  • Q2.Cabannes 2024 的 associative-memory 模型给出的 key 容量与模型 N 的具体函数 f(N)缺少跨架构 / 跨 tokenizer 的实证；曲线 1/2 切换点能否仅用 N、subset 大小、tokenizer 估出？
  • Q3.Allen-Zhu 2024 的 per-fact lock-in 现象（K-th exposure 突然写入）是否对应 ROME 的相位转变？若是，K 与 representation-side fingerprint 的对应函数应当是工程上的核心 estimator。
  • Q4.Lin 2025 提示 small-proxy 必须带 multi-epoch 维才能预测 frontier；具体到生产上，K-epoch proxy 的最小 K 是多少？4 够吗？8？还是要全照 frontier 的 multiplicity schedule？
  • Q5.implicit-reasoning scaling law（Wang 2025）把 pattern multiplicity 当独立轴；它和 De​ff 的关系仍开放——是同一指数下的一个 multiplicative factor，还是独立的对数项？
  • Q6.Galactica 4 ep 在 100%-curated 科学语料上 loss 仍降；这条记录在公开领域没有被严肃复现——其他 frontier 团队是否在同等 curation 下能反复观测到？这关系到“curated × 4 ep”这条default 的可信度。

曲线 0：compute-optimal 基线(2)

Kaplan 2020 / Chinchilla 2022 给出的 D 充裕场景：D ≈ 20·N 时 1 epoch 最优。讨论 repetition 之前必须先承认这条曲线已经不适用于 frontier 的 D-bound 区间。

Scaling Laws for Neural Language Models

Jared Kaplan,Sam McCandlish,Tom Henighan,Tom B. Brown,Benjamin Chess,Rewon Child,Scott Gray,Alec Radford,Jeffrey Wu,Dario Amodei2020年1月23日
把 compute–data–model 三个轴的 power law 写成同一组方程；为后续 repetition 讨论提供必要的“一 epoch 时多少 token 是 optimal”坐标——但本身假设 D 是不重复的 fresh token。

Training Compute-Optimal Large Language Models

Jordan Hoffmann,Sebastian Borgeaud,Arthur Mensch,Elena Buchatskaya,et al.2022年3月29日
把 Kaplan 的曲线斜率重新校准——D 应当与 N 同步线性增长。这条结论使 2022–2024全行业急速去抓更多 unique token；当 unique token 见底时，repetition 才被迫成为“代偿轴”，把后续三条曲线推上了风口。

曲线 1：均匀多 epoch 的 scaling law(4)

Hernandez / Muennighoff / Xue 三篇把“同一池子均匀多看几遍”量化成可操作的曲线。也包含 Galactica——这套 4-epoch 工程口语的来源之一。

Scaling Laws and Interpretability of Learning from Repeated Data

Danny Hernandez,Tom Brown,Tom Conerly,Nova DasSarma,et al.2022年5月21日
把“在干净池子里塞入一段被重复 N 次的子集”当受控变量，给出 D_eff 的分段函数；并第一次把退化对应到 induction-head 的可解释指纹。这是后续讨论“repeat 在多大比例 / 多大 multiplicity 起负作用”的几何起点。

Scaling Data-Constrained Language Models

Niklas Muennighoff,Alexander M. Rush,Boaz Barak,Teven Le Scao,et al.2023年5月25日
把“数据不够”写成可解的 epoch–loss 函数：定义“effective fresh-token equivalent”并测得在 ~2–4 epoch 内接近线性、之后指数衰减。这是“4 epoch”这个 number 在 LLM工程界出现的最直接来源；但作者本人在论文里就警告了它对 mixture / quality 不变的依赖。

To Repeat or Not To Repeat: Insights from Scaling LLM under Token-Crisis

Fuzhao Xue,Yao Fu,Wangchunshu Zhou,Zangwei Zheng,Yang You2023年5月22日
在 1B–13B 多个尺度上独立复现 Hernandez/Muennighoff 的 epoch–loss 关系，并强调一个常被忽略的方向：高 quality 子集承受更多 epoch，低 quality 子集 1 epoch就开始反吞收益——这说明 4-epoch 是 mixture-conditional 而非常数。

Galactica: A Large Language Model for Science

工程现实里“4 epoch” numerical 的来源之一：在严格筛过的 ~106B token 科学语料上跑 4+ epoch 时，validation loss 仍在下降——给“小而精的池子可以多扫几遍”提供了首个 frontier-scale 实证。但读这个数字时要记得：池子是被 100% 人工/规则筛过的，和 web-scale 的 4 epoch 不在一条曲线上。

曲线 1↔3 的机制：associative memory 与 memorization phase(3)

为什么 uniform repeat 在 ~4 epoch 后开始亏，而 targeted repeat 仍能涨？Cabannes 2024 给出 associative-memory 模型，ROME / factual-knowledge 工作给出logits / 表征侧的相位证据。

把 repeat 的“一开始涨、后来掉”给出一个数学解释：repeat 在固定 key 容量内把已有 key 写得更深（深化记忆），而不是新建 key（新增能力）；当 key 容量和数据 multiplicity 失衡时，generalization 通道被 memorization 抢占。这是连接 Hernandez 退化曲线与 Charton 定向 repeat 收益的最简模型。

曲线 2：定向重复 —— 4-epoch 上限失效的地方(4)

在算术、推理、长尾事实等子集上，重复 10–100 次仍在涨。这部分给出反例与可执行的调度信号（memorization window、learning dynamics）。
