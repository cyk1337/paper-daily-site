数据价值评估 × 因果：influence、ablation 与 causal inference 的工程地图

把数据合并决策放回可回归实验：ladder 管合并，filter 管吞吐，influence 管诊断，causal 管偏差

16 篇论文·2026年6月13日

作者@Thor·gpt-5.5

0 篇扩展证据

领域综述

可执行的排序是：ablation ladder 做合并门禁，bulk filtering 做候选压缩，influence/attribution 做诊断，causal inference 做混杂与评估偏差检查。这个排序不是因为 ladder 更精致，而是因为它最接近实际合并决策：固定预算、固定评测、可回归。DCLM 把数据配方变成受控实验后，一个清晰信号是跨规模迁移依赖能力类型：MMLU 更稳，HumanEval 更容易反转。Anthropic 的 influence 结果给出另一条边界：高 influence 样本集合随模型规模漂移，不能当作长期资产。FineWeb-Edu、DSIR、RegMix 说明 proxy 和 classifier 能用较低成本处理吞吐，但 proxy 必须绑定适用域。因果方法不应被放成日常主门禁；它更适合回答“这个相关性是否被长度、重复度、域混杂污染”以及“evaluator 是否把长度偏置当成能力收益”。2026 年的底线是内部工具链：1–5% frontier compute 预留给 ladder，指标从单一 loss 改成 MMLU/HumanEval/MATH 这样的 per-capability matrix，并把每个 proxy 的语言、代码、长度和时间适用域写入发布门禁。

TL;DR

数据价值评估的默认主干应是 ablation ladder，而不是样本级 influence 排名或完整因果识别。原因很直接：生产里的问题是“这次数据改动是否合并”，需要固定预算、固定评测、可回归的答案。[1] 给出关键边界：MMLU 在 412M↔7B 的 rank correlation 约 0.78，HumanEval 约 0.41，code/math 决策不能只靠小 proxy。[2] 显示同一 completion 的 top-influence 跨 810M↔52B 重叠低于 10%，influence 更适合 debug。bulk filtering 仍然必要，用来压缩候选空间；causal 工具用于检查 domain、长度、重复度和 evaluator bias 的混杂。2026 的底线是 1–5% frontier compute 给 ladder，指标改成 MMLU/HumanEval/MATH 矩阵，并为每个 proxy 写清适用域。

核心断言

#1在 DCLM 设置中，proxy-to-7B rank correlation 对 MMLU 约为 0.78、对 HumanEval 约为 0.41；因此 code 数据改动只在 ≤1B 验收会产生系统性误判。[1]
#2同一 completion 的 top-influence 样本在 810M↔52B 间重叠低于 10%；旧模型 influence 结果不能长期支配新模型数据入口。[2]
#3bulk filtering 的第一阶选择是 classifier family，而不是同一 classifier 的阈值微调；DCLM 中 fastText、DSIR、perplexity 家族差距可达数个 MMLU pp，单阈值扫描通常小于 1 pp。[1][21]
#4高压缩 pruning 存在成本悬崖：当单样本分数和泛化收益相关性不足时，单调排序会输给更宽覆盖或 repetition。[5][6]
#5自动偏好评估若不控制长度，会把 verbosity 误记为数据收益；length-controlled win rate 应进入 instruction-data ladder 的默认指标。[14]

§1 合并门禁应是 ablation ladder，而不是单个 proxy 分数

数据价值评估先要回答合并问题：给定同一 tokenizer、训练 recipe、token budget 和评测矩阵，新数据改动是否进入主线。这个问题比“每个样本值多少钱”更窄，也更接近工程闭环。[1] 的价值在于把过滤、去重、混合和阈值变成固定预算比较；它显示知识/理解类指标的跨规模排序较稳，MMLU 在 412M↔7B 约 0.78，而 HumanEval 约 0.41。[15] 用小规模 run 拟合 mixture 回归，减少组合盲扫，但回归只在数据族和 recipe 接近时可靠。[7] 则说明日志和 artifact 决定 ladder 能否复核：数据版本、filter commit、packing、checkpoint 评测都要留痕。[9] 进一步提醒，少 epoch 训练里 ordering 和 packing 会改变有效曝光；只记录“选了哪些文档”不够。更稳的工程排序是：先用 proxy 缩小候选，再用 ladder 决定合并，并把 capability-dependent transfer 写进门禁。

ladder 的任务不是解释每个样本，而是在固定预算下阻止错误数据改动进入主线。

§2 四类方法不是替代关系：它们对应不同失败模式

classifier、ladder、influence、causal graph 经常被放在同一张“数据价值”清单里，但它们回答的问题不同。bulk filter 处理吞吐：先去掉垃圾、重复、模板污染和明显低质域；[3] 用大模型打分蒸馏教育质量 classifier，说明这条路能以较低成本改变 token 分布。[4] 反驳“perplexity pruning 足够”是因为小 reference model 会错删大模型可用的长尾结构。[5] 和 [6] 进一步给出高压缩边界：分数排序不等于最优子集。influence 处理诊断；[2] 的 <10% 跨规模重叠说明它不适合作为长期门禁。[8]、[16]、[17] 支持 attribution 在目标任务和局部数据池中的价值。causal 方法处理混杂和评估偏差；[19]、[18] 更适合做稳健性检查，[14] 则把长度偏置纳入指标控制。

§3 数据价值不是单一标量：按能力线报告比单 loss 更稳

单一 validation loss 适合监控训练健康，但不适合单独验收数据改动。原因是不同能力对数据选择的响应不同。[11] 更接近知识和阅读理解线，[12] 代表 code synthesis，[13] 说明数学线对专门语料和 code 混合敏感。[1] 的 MMLU≈0.78 与 HumanEval≈0.41 rank correlation，把这个问题量化出来：同一个小模型 proxy 对知识类筛选有用，对 code 决策就不够。[22] 也给出集中收益的例子：合成教材和 verifier 能把 HumanEval 做高，但收益集中在 verifier 覆盖的代码分布，不能推成通用数据价值。[20] 的 synthetic biographies 结果说明重复次数和记忆曲线可能是非线性的；1 次曝光几乎无效，4–8 次曝光才出现可测收益。per-capability matrix 至少要有 MMLU、HumanEval、MATH 三条线，并报告重复次数、置信区间和负向回归。

把数据价值压成一个 loss 数字，会把 code、math、事实记忆和知识理解的反转全部平均掉。

§4 因果工具的务实位置：识别风险，而不是替代训练实验

把 data selection 写成因果问题是有价值的，但它不应替代 ladder。真实 web 数据里的 treatment 往往不是单一变量：教育质量、域、长度、重复度、语言、时间段和模板格式互相缠绕。[19] 的 IV 风格方法适合提出风险问题，例如“长度是否只是 domain 的代理”“去重是否同时删掉稀有事实”。难点是 instrument 的 exclusion restriction 很难证明；如果 instrument 也直接影响下游能力，估计量会偏。[18] 的 mediator 路线在 skill 可枚举时更可用，但 emergent capability 会打穿 skill 列表。评估侧也有因果偏差：[14] 显示长度控制会改变偏好评估读数，instruction 数据选择如果只优化普通 win rate，可能把更长回答当成更好回答。[23] 还提醒泄漏和重复会污染评测本身。结论层面的建议是：因果图写进设计评审，IV/mediator/length-control 做 robustness check，最终合并仍由固定预算 ladder 决定。

研究立场对比

阵营 A：classifier + ablation ladder 已覆盖多数生产决策

立场 — 这一路线对应 c-c5b285848d、c-b6f26e7c87 和 c-2a5bd5b489：用 classifier/perplexity/dedup 做 bulk filtering，再把候选改动送进固定预算 ladder。它不追求解释每个样本，只要求每次合并有可复现的净收益。

证据：[1][3][15][7]

反方 — 反驳 c-9f0043b113：这条路线在知识和阅读线上更稳，在 code、math、事实记忆上边界较窄。[1] 的 HumanEval≈0.41 和 [20] 的重复非线性说明，小 ladder 与单 proxy 不够覆盖所有能力。

判词 — 一条更稳的读法：把 A 作为默认主干，但强制 per-capability ladder；不要把“95% 决策够用”外推到 code/math 和高价值稀有事实。

阵营 B：example-level influence 才能回答 data value

立场 — 这一路线对应 c-cb40136041、c-230595d964 和 c-bb37143a19：先用 influence/attribution 找关键样本和关键簇，再做 targeted curation、reweighting 或补数。它比 domain mixture 更细，也更接近失败样例解释。

证据：[2][8][16][17]

反方 — 修正 c-0f6b7dadb2：问题不在于 influence 没用，而在于它不是模型无关资产。[2] 的 top-influence 跨 810M↔52B 重叠 <10%，说明旧 proxy 结果不能长期支配新模型入口。

判词 — 一个更务实的定位：influence 放在 debug 和 targeted instruction tuning；预训练主线只允许它提出候选改动，不允许它绕过 ladder 合并。

阵营 C：完整因果识别才是数据选择的正确形式

立场 — 这一路线对应 c-00e3812909、c-cdd0499162 和 c-e385bd2b45：domain、长度、重复度、质量分数和下游能力之间混杂太强，相关性筛选会选到共同原因；应使用 IV、mediator 或 robustness graph 估计干预效应。

证据：[19][18][14][23]

反方 — 反驳 c-6cb1d91960：真实 web 数据里 instrument 的 exclusion restriction 难验证，skill mediator 也要求技能可枚举。因果图能揭示风险，但不能替代训练实验给出合并答案。

判词 — 结论层面的建议：因果方法进入设计评审和发布前 robustness check；日常门禁仍以 ladder 为准，尤其在 instrument 或 mediator 假设无法审计时。

阵营 D：少测量，多覆盖，依赖 scale 与 researcher 直觉

立场 — 这一路线对应 c-9a9047abb8、c-0cc7a00d89 和 c-7a3940a933：数据工具链成本高、跨规模不稳，不如扩大 token、保持覆盖，在 data scarcity 下允许 repetition，用规模对冲过滤偏置。

证据：[10][5][6]

反方 — 修正 c-d7cc4e91f7：scale 和 coverage 不能替代回归测试。[1] 的大量受控 ablation 说明 mixture 和 filter family 会造成多个 pp 的下游差异；[3] 也显示 classifier recipe 能改变同等 token 下的结果。

判词 — 一条更稳的读法：保留 coverage-first 的警惕，反对过度 pruning；但 frontier 团队不建 internal ladder 的成本会转移到整次大训练。

实践要点

可操作清单：
1) Do：把 ablation ladder 作为数据改动合并门禁，预算按 frontier compute 的 1–5% 预留；低于约 1% 时通常只看早期 checkpoint，容易漏掉过度过滤进入 data-limited 后的反转。[1][10]
2) Do：每次数据改动报告 MMLU、HumanEval、MATH 三条线的 Δ、重复次数和置信区间；单一 loss 只能做训练健康监控，不能单独做合并依据。[11][12][13]
3) Do：bulk filtering 先选 classifier family，再调阈值；fastText/DSIR/perplexity/教育质量 classifier 的家族差异通常大于单阈值微调。[1][21][3]
4) Don’t：让 2–3 年前训练的 quality classifier 长期支配新一代模型入口；每代模型至少重训或重标一次 proxy，并写清语言、code、多语、长度和时间分布适用域。[3][4]
5) Don’t：把 influence 排名当作可跨规模复用的数据资产；top-influence 跨 810M↔52B 重叠 <10%，它更适合解释失败样例、定位缺口簇和做 targeted补数。[2][8]
6) Do：高压缩 pruning 必须和随机采样、宽覆盖、repetition baseline 对比；当压缩率超过 70–90% 时，分数法要默认进入风险审查。[5][6]
7) Do：instruction-data ladder 默认加入 length-controlled win rate；普通 win rate 只要受长度影响，就可能把 verbosity 当成数据收益。[14]
8) Open：ordering、packing、FIM、重复曝光和少 epoch 组织还没有足够公开 controlled experiment；先把这些变量写进日志和小 ladder，不要把它们当作固定背景。[9][20]

悬而未决的问题

  • Q1.code/math ladder 的最小可靠规模是多少？[1] 给出 HumanEval≈0.41 的跨规模排序，但还缺少 7B↔30B↔100B 级别的公开 controlled experiment。
  • Q2.influence 能否通过 stage-conditioned 或 checkpoint-conditioned 归因提高跨规模稳定性？[2] 给出的 <10% 重叠是强警告，但还不能排除更好的 conditioning 方案。
  • Q3.IV 风格 causal data selection 在真实 web 数据中能否找到可审计 instrument？[19] 的方向合理，难点仍是 exclusion restriction 和 backdoor path 的可验证性。
  • Q4.repetition、dedup 和事实记忆之间是否存在可迁移曲线？[20] 的 synthetic biographies 说明曲线非线性，[23] 说明重复会带来泄漏和过拟合风险，真实混合语料上还缺公开 ladder。
  • Q5.ordering、packing、FIM 和 few-epoch data organization 是否会改变已有 filtering 结论？[9] 把问题提出来了，但还需要与 DCLM 风格固定预算评测对齐。
