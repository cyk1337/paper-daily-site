It changes (i) the reachable string distribution implied by the training objective, (ii) how learning signal is allocated across units, and (iii) systems cost via sequence length and KV-cache footprint. 9:T522,A tokenizer change modifies at least three coupled chains. (1) The training objective: a tokenized LM learns a distribution over token strings, while applications care about character strings; changing the tokenizer changes both the reachable token-string set and the decomposition of the same surface string, so per-token PPL is no longer denominator-comparable [Vieira2024Characters][Gastaldi2024FoundationsTokenization]. (2) Learning-signal allocation: segmenting the same character sequence into fewer/more tokens changes which local patterns are easier to fit in early training, thereby shifting inductive bias; controlled experiments show this can reach 0.6–5.1 pp downstream differences [Ali2024TokenizerChoice], and compression/mean token length does not fully explain it [Goldman2024UnpackingTokenization][Schmidt2024MoreThanCompression]. (3) Systems cost: sequence length linearly drives KV-cache footprint and batchability, which serving systems optimize as a primary constraint [PagedAttention2023]; therefore bytes-per-token/fertility improvements can translate directly into throughput gains [Dubey2024Llama3]. b:T80a,把 vocab 从 32K 扩到 128K 的可交付收益主要来自序列缩短，而不是神秘的语义跃迁。Llama 3 报告给出的收益是 0.02–0.04 nats 更低训练 loss，并用 bytes-per-token/fertility 将其归因于 non-English 与 code 的 token 数下降 [Dubey2024Llama3]。在 serving 侧，序列缩短会线性降低 KV cache 占用，从而提高并发与吞吐；PagedAttention 将 KV cache 作为核心内存瓶颈处理，使这种线性关系直接体现在 batchability 上 [PagedAttention2023]。

这条经验过去缺的是“最优词表到底应该多大”的量化预算。Tao et al. [Tao2024VocabScalingLaw] 在 33M–3B / ≤500B characters 上把 vocab size 升格为独立 scaling 轴，并用三条互证路径（IsoFLOPs sweep、导数估计、参数化损失拟合）一致拟合出：compute-optimal 词表随非词表参数 N_nv 成幂律 V★ ∝ N_nv^γ，但 γ < 1（约 0.27）。因此模型变大时词表也应变大，但增速远慢于参数；按该公式外推，Llama2-70B 应至少 ~216K 而非 32K，许多现行 LLM 系统性偏小。同一论文的可执行实验也可作 sanity check：在 2.3e21 FLOPs 同算力下，把 33M 模型的词表从 32K 提到 43K，ARC-Challenge 从 29.1 升到 32.0，相当于不加参数也不加 tokens 获得 ~3 pp 下游收益 [Tao2024VocabScalingLaw]。

但仍不应把 256K+ 设为默认，因为 vocab 公式给出的是最优区间，而不是越大越好。Tao 2024 的结论同样意味着，小模型继续放大词表会过冲到欠训练区；同时，词表变大也会提高 embedding/softmax 成本、tokenize latency，以及 tail token 欠训练风险 [FastWordPiece2020][LandBartolo2024Magikarp]。可操作做法是：把 V 与 N、D 一起放进 IsoFLOP 小 grid（含 32K/64K/128K/256K 至少四点），用 BPB 而不是 per-token loss 做对齐回归，并把 systems ledger（吞吐、tokenize latency、KV cache）和 tail under-training 扫描作为同一份报告交付 [Ali2024TokenizerChoice][Vieira2024Characters][PagedAttention2023]。c:T876,The deliverable gain from scaling vocab from 32K to 128K comes mostly from sequence shortening, not a mysterious semantic jump. The Llama 3 report states 0.02–0.04 nats lower training loss and attributes it via bytes-per-token/fertility to fewer tokens for non-English and code [Dubey2024Llama3]. On the serving side, shorter sequences linearly reduce KV-cache footprint, improving concurrency and throughput; PagedAttention treats KV cache as the core memory bottleneck, so this linearity appears directly in batchability [PagedAttention2023].

What this empirical picture lacked was a quantitative budget for how large the vocabulary should be in the first place. Tao et al. [Tao2024VocabScalingLaw] promote vocab size to an independent scaling axis and, on 33M–3B models trained on up to 500B characters, fit three mutually corroborating routes (IsoFLOPs sweep, derivative estimation, parametric loss fit) to one law: compute-optimal vocab grows as V★ ∝ N_nv^γ with γ < 1 (~0.27). Larger models therefore deserve larger vocabularies, but vocab grows much slower than non-vocab parameters; extrapolating, Llama2-70B should use ≥216K rather than 32K, and many current LLMs are systematically under-sized. The same paper gives an executable sanity check: at fixed 2.3e21 FLOPs, raising a 33M model’s vocabulary from 32K to 43K lifts ARC-Challenge from 29.1 to 32.0—an ~3 pp downstream gain without adding parameters or tokens [Tao2024VocabScalingLaw].

Defaulting to 256K+ still needs caution: the law identifies an optimum, not bigger is always better. Tao 2024 also implies that, for smaller models, oversizing vocab pushes tokens into the under-trained tail; at the same time, embedding/softmax cost, tokenization latency, and tail-token under-training risk all rise [FastWordPiece2020][LandBartolo2024Magikarp]. The operational rule is to add V to the same IsoFLOP grid as N and D (at least 32K/64K/128K/256K), regress on BPB rather than per-token loss, and ship a systems ledger (throughput, tokenize latency, KV-cache footprint) and tail-under-training scan in the same report [Ali2024TokenizerChoice][Vieira2024Characters][PagedAttention2023].d:T45e,The main failure mode of “bigger vocab” is not compute; it is local structural choices that distort the inductive bias of reasoning tasks. 11:T583,The practical constraint in tokenizer versioning is that models, tooling, and data assets are coupled to token-ID semantics. Two lines of work provide implementable buffers. First, probability alignment across tokenizers: exact byte-level probabilities align tokenized LM outputs at the byte level, preventing tokenizer changes from making FIM/ensemble probabilities incomparable [Phan2024ExactByteProbabilities]; linguistics-oriented work also shows how to compute word probabilities from subword LMs, emphasizing that the alignment target should be strings/words, not tokens [Pimentel2024WordProbability]. Second, knowledge transfer across tokenizers: WECHSEL reduces cold-start cost via subword embedding initialization [Minixhofer2021WECHSEL], while universal cross-tokenizer distillation relaxes the “teacher/student tokenizer must match” constraint into approximate likelihood matching [Minixhofer2025CrossTokenizerDistillation].
