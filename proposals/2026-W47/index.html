#1H · 硬待研判2026-11-19adaptive-compute-counterfactuals

自适应推理的正确估计量：会错、能改、该停是三件事

The Right Estimand for Adaptive Reasoning: Error, Recoverability, and Stopping Are Separate

» 高置信度检测错误不等于多花计算能修正错误；自测通过后继续工作也不一定增益为正。test-time scaling 需要估计“下一单位计算的反事实价值”，而不是把错误率、AUROC 或总分当作同一个目标。

触发：`2611.22778` 明确把“当前会错”和“多想会变好”拆开；`2611.21651` 指出 consistency/confidence 支持 abstention 不等于支持 correction；`2611.22901` 在 coding agent 中测到停止规则的成本—质量曲线。再加上 `2611.06372`、`2611.23154`、`2611.22301` 对预算分配、策略分层和 MCTS count 的修正，近期证据已经足够支撑一个方法论命题。

锚点论文

  • 2611.22778A Full-Ledger Counterfactual Audit of Adaptive Reasoning— 把继续推理的真实反事实收益作为审计对象，而不是只看当前答案对错。
  • 2611.21651Consistency Is Not Correction: Separating Confidence, Abstention, and Recovery in LLM Agents— 给出 error detection、abstention、recovery 三者不能互相替代的直接证据。
  • 2611.22901Done, But Still Working: Anytime Evaluation of When Coding Agents Should Stop— 把 agent 继续工作后的边际收益和边际成本放在同一张曲线上。
  • 2611.06372Give Up to Get More: Priors, Not Policies, Govern Test-Time Compute Allocation— 挑战“越难越该给更多采样预算”的单调分配直觉。
  • 2611.23154Learning Stratified Policies for Inference-Time Objectives— 把 best-of-k 的多样性从温度采样推进到策略族预算分配。

对立阵营

  • · 阵营 A：把 confidence、consistency 或 verifier 分数当作是否继续推理的代理信号。
  • · 阵营 B：直接估计继续计算的反事实增益，承认“会错”和“能改”不是同一变量。
  • · 阵营 C：把预算分配给互补策略、停止规则或搜索统计，而不是给同一策略重复采样。

品味：关键是估计量，不是又一个推理框架。

#2H · 硬待研判2026-11-19sampler-as-model-abi

采样器是模型接口：长生成、量化和并行解码不能把 sampler 当实现细节

The Sampler Is a Model ABI: Long Generation, Quantization, and Parallel Decoding Cannot Treat Sampling as Plumbing

» 同一组权重在不同 sampler、temperature、logits processor 或量化后解码参数下，可能表现为不同模型。把 sampler 当作部署细节，会把训练不足、架构缺陷和解码错误混在一起。

触发：`2611.22148` 把高温长生成崩坏定位到 sampling；`2611.22128` 显示量化后沿用全精度 temperature/top-p 会扭曲行为；`2611.04042` 说明 speculative decoding 的无偏保证会被 processor contract 破坏。DLM 侧的 `2611.04152`、`2611.20693`、`2611.21852` 又显示 parallel commit、threshold fallback 和 sampler kernel 都会改变质量—成本曲线。

锚点论文

  • 2611.22148Long-Context Generation Is a Sampling Problem (When You Turn Up the Heat)— 直接挑战“长轨迹退化主要来自预训练不足”的解释。
  • 2611.22128TempQuant: Learning Adaptive Temperatures for Quantized Language Models— 说明量化会改变 next-token 分布，需要重设解码控制面。
  • 2611.04042Testing Processor Contracts in Speculative Decoding Engines— 把 speculative decoding 的分布保持条件落到工程 contract 上。
  • 2611.04152PACT: Certifying What Is Written in Parallel Decoding of Diffusion Language Models— 指出 commit rule 认证分布而非实际采样 token 会在高温下失效。
  • 2611.20693Fast at the Frontier, Wrong at the Fallback: A Commit-Level Analysis of Threshold Decoding in Diffusion Language Models— 把 DLM threshold decoding 的质量损失定位到 fallback 与 EOS 提前提交。

对立阵营

  • · 阵营 A：把 decoding 参数、processor 和 sampler kernel 视为部署实现，训练报告只披露模型权重和少量默认参数。
  • · 阵营 B：把 sampler 视为模型 ABI；任何 benchmark、量化和推理优化都必须固定并测试其分布合约。
  • · 阵营 C：针对不同模型状态学习或搜索 sampler 策略，但需要承认这已经改变了被评估系统。

品味：很多“模型退化”先是采样合约坏了。

#3H · 硬待研判2026-11-19controlled-proxies-for-pretrain-scaling

小模型外推不能只缩参数：需要同时控制上下文 horizon、容量和状态通道

Small-Scale Extrapolation Needs More Than Fewer Parameters: Control Horizon, Capacity, and State Channels Separately

» 很多预训练架构消融把“看多远”“存多少状态”“每层算多少”混成一个模型尺寸变量。这样的小尺度胜出很容易在大尺度反转；更可用的 proxy 应该显式拆开 horizon、rank/capacity、residual/state width 和 compute width。

触发：`2611.23093` 用 Tree-gram 显式拆开 n-gram horizon 与 capacity；`2611.17332` 关注架构实验证据如何记录和复核；`2611.23197`、`2610.41711`、`2611.19800`、`2611.21608` 都在挑战 Transformer 默认的结构、残差、分支和状态通道绑定。近期信号共同指向一个问题：架构研究缺的不是更多小实验，而是更干净的外推坐标。

锚点论文

  • 2611.23093What's in a Tree ? Hierarchical n-gram models as controlled approximators of language— 提供可独立控制 horizon n 与 capacity d 的中间模型族。
  • 2611.17332ArchSpace: Recording, Reviewing, and Referencing LLM Architecture Research— 把架构实验从单表格结果推进到可复核证据账本。
  • 2611.23197Structure--Residual Inductive Biases for Language Model Pretraining— 把可复用结构和序列残差信息的分工显式放进预训练架构。
  • 2610.41711Hierarchical Residuals: A Minimalist Decoupling of Residual Width from Compute Width— 直接拆开 residual state capacity 与层内 compute width。
  • 2611.19800Multi-Branch Transformer— 把宽、深之外的并行分支作为新的架构缩放轴。

对立阵营

  • · 阵营 A：用参数量、训练 token 和最终 loss 作为小模型外推的主要坐标。
  • · 阵营 B：构造可控 proxy，单独旋转 horizon、capacity、state width 和 compute width。
  • · 阵营 C：用证据账本记录失败、等 FLOPs 对照和外推误差，而不是只保留胜出的配置。

品味：小实验要能解释反转，才配外推。

#4M · 中待研判2026-11-19visual-evidence-transport-in-vlm-evals

VLM 评测先验要改：很多视觉推理失败先是证据没有到达模型

VLM Evaluation Needs Evidence Transport: Many Reasoning Failures Start Before the Model Sees the Evidence

» 把 VLM 小目标、长视频和安全场景错误直接归因于视觉推理不足，经常会错。服务端缩放、tiling、证据稀疏、共现先验和最终答案判分会共同遮蔽真实失败位置；评测应先证明关键视觉证据进入了模型并被使用。

触发：`2611.22709` 显示在线 VLM 的小细节失败常由缩放和 token 预算触发；`2611.22790` 在长视频中给出最终答案与 evidence verifier 之间的 54→79 差距；`2611.22360` 显示图文共现先验会伪装成视觉理解；`2611.23206` 则把场景状态安全漏洞放到视觉证据链上。`2611.17334` 和 `2611.22351` 进一步说明视觉编码和融合位置不能在评测里混作一个黑盒。

锚点论文

  • 2611.22360Can Vision-Language Models Truly Understand Images? A Benchmark Beyond Commonsense Bias— 构造违背常识共现的图文样本，分离视觉 grounding 与语言先验。

  • 2611.17334Unbundling Multimodal Vision Encoding— 拆开视觉先验、专用视觉容量和融合位置，避免把编码瓶颈误归因给推理。

对立阵营

  • · 阵营 A：用最终答案正确率评估视觉推理，把图像预处理和证据可达性当作实现细节。
  • · 阵营 B：先审计 visual evidence transport，包括缩放、tiling、frame selection、token budget 和证据 verifier。
  • · 阵营 C：把 VLM 预训练与评测同时拆成视觉编码、融合损失、语言先验和场景状态安全四个账本。

品味：先确认看见证据，再讨论推理能力。

#5H · 硬待研判2026-11-18curvature-as-pretrain-control

曲率不是优化器注脚：预训练应按模块 sharpness 分配学习率、状态和探针预算

Curvature Is Not an Optimizer Footnote: Allocate Learning Rates, States, and Probes by Module Sharpness

» 统一学习率把 Transformer 当成同质堆叠，但近期结果反复指向相反结论：attention、MLP、embedding、router 的曲率和可塑性不同。更可检验的立场是先量 block-level sharpness，再决定 blockwise LR、二阶状态或零阶曲率探针，而不是先押某个优化器名字。

触发：`2502.19002` 明确把 block-level sharpness disparity 做成预训练加速变量；`2611.16905` 用 FOAM 重新打开可扩展二阶优化器路线；`2611.02688` 把闲置推理算力用于 zeroth-order curvature；`2611.17876` 和 `2611.00593` 又说明 Muon/约束类收益不能只看即时 loss。

锚点论文

  • 2502.19002The Sharpness Disparity Principle in Transformers for Accelerating Language Model Pre-Training— 近期最直接的触发点：把不同模块曲率差异转成 blockwise LR 预训练方法。
  • 2611.16905Factored One-sided Adam-Moment for Practical and Scalable SOAP— 给二阶路线一个更实际的状态和分解成本账本。
  • 2611.02688Accelerating LLM Pretraining with Zeroth-Order Curvature on Idle Serving Compute— 把曲率测量从主训练 step 中拆出来，变成可外包的诊断信号。
  • 2611.17876Delayed Effects of Temporary Weight Decay in Muon Pretraining— 说明优化器 schedule 的收益可能滞后，不能用切换点 loss 做选择。
  • 2611.00593Do Orthogonality Constraints Help Language-Model Training Beyond Sphere Optimization?— 给约束类优化收益提供了强 baseline，避免把几何约束误读成普适收益。

对立阵营

  • · 阵营 A：统一 AdamW/Muon recipe，靠全局 LR、WD、batch schedule 调参。
  • · 阵营 B：blockwise LR 或 blockwise optimizer，把模块 sharpness 当成训练控制变量。
  • · 阵营 C：二阶/零阶曲率探针先做诊断，再决定哪些模块值得付状态、通信或额外前向成本。

品味：好题。难点是等 FLOPs 和等调参预算。

#6H · 硬待研判2026-11-18latent-state-compute-accounting

宽度和深度之外：把每 token 状态容量、分支计算和 KV 成本放进同一张架构账本

Beyond Width and Depth: Put Per-Token State Capacity, Branch Compute, and KV Cost in One Architecture Ledger

» 近期架构工作共同挑战一个默认搜索空间：提升 LM 质量不一定要加深、加宽或拉长 CoT。真正的分歧是把额外 FLOPs 花在残差状态、并行分支、latent lattice、looped compute 还是 feedback path；这些路径的训练收益和推理 KV 成本不同，不能只报 perplexity。

触发：`2611.19800` 把 Multi-Branch block 放到质量和 KV 成本的共同坐标里；`2611.21608` 用 latent lattice 增加每 token 可用计算容量；`2610.41711` 解耦 residual width 和 compute width；`2611.20404` 用 latent feedback 对比重复数据；`2611.19446` 则提醒 depth-recurrent 的省参收益会被 KV cache 吃回去。

锚点论文

  • 2611.19800Multi-Branch Transformer— 直接把并行分支、质量收益和推理 KV 成本放在同一设计空间。
  • 2611.21608Latent Lattice Language Models— 把 token 内部状态数作为独立旋钮，而不是简单加深网络。
  • 2610.41711Hierarchical Residuals: A Minimalist Decoupling of Residual Width from Compute Width— 将跨层状态容量与层内计算宽度拆开，是该话题的关键历史近端锚点。
  • 2611.20404Latent Feedback Is a Compute and Data Amplifier— 给出数据受限下重复 token 与改变计算路径的直接对照。
  • 2611.19446Architectures and KV Replay for Depth-Recurrent Language Models— 把 depth recurrence 的参数账和 KV cache 账对齐。

对立阵营

  • · 阵营 A：加深/加宽标准 Transformer，用参数和层数买质量。
  • · 阵营 B：增加 residual/state capacity，让每层携带更多跨层信息但不等比例增加矩阵计算。
  • · 阵营 C：looped、lattice、feedback 或 multi-branch，把额外 FLOPs 放在 token 内部路径，并接受不同的 KV 与延迟账。

品味：别只看小模型 PPL，KV 账会翻案。

  • 2611.01125What Does a Safety Label Measure? Auditing Situational-Safety Benchmarks for Multimodal LLMs— 证明安全标签可能测到非语义捷径，而不是目标风险。
  • 2611.12225A Cost That Practice Accuracy Hides: Worked Solutions in Self-Generated Training Data and the Compositional Use of New Rules— 说明训练样本中的解释格式会改变模型学到的规则使用方式。

对立阵营

  • · 阵营 A：把偏好、风险、数据价值压成单个 score，再用 DPO/RL/过滤器优化。
  • · 阵营 B：显式列出质量标准，只合成或选择单一标准发生变化的样本。
  • · 阵营 C：把 attribution 当成发现属性和设计干预的工具，而不是训练集的一次性排序器。

品味：标量标签最省事，也最容易学偏。

Agent Training Data Should Not Stop at Traces: Executable Environments Are the Reusable Unit for Long-Horizon Learning
