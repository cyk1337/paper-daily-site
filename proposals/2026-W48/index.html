#1H · 硬待研判2026-11-23judge-scale-topology-reward-bias

LLM Judge 的数字量表不是中性仪器：评测漂移会变成后训练偏差

LLM Judge Scales Are Not Neutral: Evaluation Drift Becomes Post-Training Bias

» 同一 rubric 只要改变数字方向或分数空间，归一化后的判断也会系统漂移。更麻烦的是，用这种 judge 做 RL 时，学生继承的往往不是 judge 的知识，而是类别级盲区和量表偏好。

触发：`2611.25588` 和 `2611.26077` 同时把 LLM judge 的数字轴拆成实验变量；`2611.25191` 进一步显示 judge 的盲区会被 RL 学生放大；`2611.25135` 则把 reward 质量收窄到校准概率，而不是裸分数。

锚点论文

  • 2611.25588Rubric Semantics or Numerical Priors? Auditing Scale-Direction Bias in LLM Judges— 直接证明分数方向会覆盖 rubric 语义，适合作为量表非中性的主锚点。
  • 2611.26077Same Judgement, Different Scores: Numerical Scoring Topology in LLM-as-a-Judge Evaluation— 把分数区间形状作为变量，显示归一化不能消除系统漂移。
  • 2611.25191Blind Spots Travel, Knowledge Stays Home: What RL Inherits from an LLM Judge— 把 judge 偏差从评测问题推进到 RL 训练信号问题。
  • 2611.25135Calibrated Decision Rewards: Training Language Models with a Judge That Knows How Sure It Is— 给出用校准概率替代 reference-free 裸分的后训练路径。
  • 2611.20608Same Papers, Different Verdicts: Tracing Version Drift in LLM Peer Review— 说明 judge model 版本漂移会让阈值和分数口径失去可复现性。

对立阵营

  • · 阵营 A：把 LLM judge 当便宜、可替代人工的打分器，重点优化相关性和平均一致率。
  • · 阵营 B：把 judge 当带有数字先验和版本漂移的测量仪器，必须固定量表、方向、版本和归一化协议。
  • · 阵营 C：把 judge 当后训练 reward source，核心验收从评分相关性转向校准、分布外检测和偏差迁移。

品味：好 topic：评测误差会进入训练梯度。

#2H · 硬待研判2026-11-23rl-rollout-caps-shape-reasoning

固定 Rollout 预算不是训练成本参数：它会塑造模型的推理长度偏好

Rollout Caps Are Not Just Training Cost: They Shape the Model’s Reasoning Policy

» RLVR 里的 rollout token cap 看似只控制 GPU 成本，实际会让模型把“预算内解题”内化成行为偏好。测试时再给更多 token，不一定能恢复长思考收益。

触发：`2611.26172` 直接提出 fixed-budget RLVR 会用预算内准确率交换测试时扩展；`2611.26084` 说明 RL 只能强化已经看到成功的轨迹；`2611.18627`、`2611.13560` 和 `2611.07639` 则分别从单 rollout、dense reward 和 SFT 边际贡献角度重写 RLVR 的成本账。

锚点论文

  • 2611.26172Budget Internalization: Fixed-Budget RLVR Trades Test-Time Scaling for In-Budget Accuracy— 把 rollout cap 从成本约束改写成行为约束，是主触发点。
  • 2611.26084RL Can Only Reinforce What It Sees Succeed— 给出轨迹覆盖不足时 RL 无法创造新成功模式的干净机制。
  • 2611.18627FlashREINFORCE: Critic-Free Single-Rollout Asynchronous RL for Agentic Language Models— 挑战同 prompt 多 sibling rollout 的默认做法，适合讨论覆盖率与吞吐的交换。
  • 2611.13560Are Dense Rewards Worth Their Tokens in GRPO?— 要求在相同 token 和 GPU 小时下评估 process reward，避免 per-update 假增益。
  • 2611.07639Measuring the Marginal Value of Verifier-Based RL Beyond Supervised Fine-Tuning— 把 RLVR 增益拆成 SFT 覆盖、verifier 形状和策略优化三部分。

对立阵营

  • · 阵营 A：把 rollout cap 当训练预算，只要测试时放开长度就能买回推理收益。
  • · 阵营 B：把 rollout cap 当行为先验，训练时成功轨迹的长度分布会限制测试时扩展。
  • · 阵营 C：把核心变量放在轨迹覆盖率，优先扩大 prompt/解法覆盖，而不是增加同题 sibling 数或 dense reward token。

品味：关键是测同题多想是否仍有边际值。

#3H · 硬待研判2026-11-23author-level-exposure-governance

数据泄露不止是成员推断：作者级可识别性应进入预训练治理

Data Exposure Is Not Just Membership Inference: Author-Level Identifiability Belongs in Pretraining Governance

» 只问“这条样本是否在训练集里”太窄。若 frontier model 能用单段文本识别人、实验室或线上账号，预训练治理就要从文档级去重推进到作者级暴露、风格指纹和群体隐私。

触发：`2611.26216` 把单样本文风识别推到 frontier 模型；`2611.21315` 显示 benchmark 泄漏已经下沉到 base model；`2611.24844` 又说明删除特定训练信号不等于删除能力，因为通用进展可能替代专门数据。三者合在一起，说明暴露风险不能只靠成员检测。

锚点论文

  • 2611.26216Frontier models need only one text to unmask its human or AI author— 直接提出单文本作者识别能力，扩展了训练数据暴露的风险定义。
  • 2611.21315Benchleaking Is Accelerating: Benchmark contamination has worsened sharply in the past month -- from post-training down to pre-training base models— 提供 base model 层面的污染风险背景，说明泄漏不是 post-training 专属问题。
  • 2611.24844General progress substitutes for specific training data in language models— 说明删除数据与删除能力之间没有简单一一对应关系。
  • 2611.15479DETER: Suppression During Pretraining for Tamper Resistance— 把安全约束前移到预训练动态，可作为作者级风险治理的对照路线。
  • 2611.19698Data Attribution Should Steer Pretraining— 把 attribution 从一次性样本打分改成可复用属性发现，适合承接作者级属性。

对立阵营

  • · 阵营 A：以样本成员推断、benchmark continuation 和 exact/near-exact dedup 作为主要审计对象。
  • · 阵营 B：以作者、账号、实验室和风格簇为暴露单位，测单样本文风识别与群体可链接性。
  • · 阵营 C：以能力替代为中心，承认删数据不一定删能力，治理目标改成降低可识别性和可滥用性。

品味：风险单位从文档变成作者，结论会变。

#4H · 硬待研判2026-11-23dlm-denoising-self-shortcuts

Diffusion LM 的训练信号可能走捷径：看见自身噪声不等于学会跨 Token 依赖

Diffusion LM Training Can Take Shortcuts: Seeing Self-Noise Is Not Learning Cross-Token Dependence

» 离散 diffusion 训练常允许模型看到目标位置自身的腐蚀状态，这可能让模型学到局部去噪捷径，而不是真正利用上下文。解码阶段再修 commit policy，未必能补上训练目标里的条件化错误。

触发：`2611.26359` 明确提出 jump diffusion 的 leave-one-out 条件；`2611.19127` 用 leave-one-out Transformer 同时处理稀疏监督和自纠错；`2611.07721` 指出 continuous LM 的 embedding MSE 会丢失 token identity；再加上 `2611.07845`、`2611.11551`、`2611.20693`、`2611.22576` 对并行解码和承诺策略的连续压力，DLM 的问题已从采样器扩展到训练信号。

锚点论文

  • 2611.26359Learning from Context: Leave-One-Out Prediction in Jump Diffusions— 主锚点；直接挑战“目标坐标自身噪声可见也没事”的默认假设。
  • 2611.19127Empowering Masked Diffusion Models to Self-Correct with Leave-One-Out Transformers— 把 leave-one-out 机制落实到 MDM 架构和监督密度。
  • 2611.07721Continued Training of Continuous Language Flows with Token Identity Squared Supervision— 说明非 AR 语言模型的连续监督可能不可辨识，需要 token identity 约束。
  • 2611.07845Masked diffusion as random sequential adsorption: an exactly solvable model for parallel decoding— 提供并行解码错误积累的可解析模型。
  • 2611.11551When Should Diffusion Language Models Reconsider Their Commitments?— 从可撤回承诺角度揭示 DLM 的局部一致性问题。

对立阵营

  • · 阵营 A：主要修 sampler、commit threshold、KV cache 和 schedule，认为训练目标基本可用。
  • · 阵营 B：认为训练目标本身可能泄露目标坐标信息，必须用 leave-one-out 或 token identity 约束切断捷径。
  • · 阵营 C：折中路线，用 recurrent refinement、remask policy 或 edit operations 在冻结模型上补救，但需要承认这是后验修补。

品味：别只调解码器，先查 loss 学了什么。

#5M · 中待研判2026-11-23proxy-validity-for-architecture-search

小规模架构实验不是玩具，但必须证明排序能迁移到真实预训练

Small Architecture Proxies Are Useful Only If Their Rankings Survive Real Pretraining

» 合成 playground 和小模型 ablation 不是天然不可信；问题是它们常只报告局部涨点，不报告排序在 1T token、B 级参数和真实 kernel 下是否保留。position 的核心应是 proxy validity，而不是再列一个架构榜。

触发：`2611.24963` 用 64 次从零预训练检验 synthetic pretraining 结论是否在 1.3B–8B、1T–2T token 下成立；`2611.17332` 提出 ArchSpace 记录架构证据链；`2611.23093` 用 Tree-gram 提供可控中间模型；`2611.22947` 则提醒 kernel 现实会改写高效 attention 的收益。

锚点论文

  • 2611.24963Physics of Language Models: Part 4.2, Canon Layers at Scale where Synthetic Pretraining Resonates in Reality— 直接检验 synthetic playground 到真实预训练的排序迁移，是主锚点。
  • 2611.17332ArchSpace: Recording, Reviewing, and Referencing LLM Architecture Research— 提供架构实验证据链和失败案例记录的基础设施视角。
  • 2611.23093What's in a Tree ? Hierarchical n-gram models as controlled approximators of language— 用可控 horizon 和 capacity 作为 proxy，适合讨论中间模型的外推边界。
  • 2611.22947The Kernel Reality Check: Benchmarking and Distilling Efficient Attention at Scale— 说明理论高效结构在现代 kernel 和真实训练下可能失去优势。
  • 2611.07103A Night at the LLM Zoo: Data Conditioned Flow Matching for Generating Pretrained LLM Weights— 通过受控模型 zoo 分解数据配比对权重空间的影响，是 proxy 设计的另类证据。

对立阵营

  • · 阵营 A：用小模型或合成任务快速筛结构，只要求同设置下相对涨点。
  • · 阵营 B：要求 proxy 排序在更大模型、更多 token、真实语料和真实 kernel 下保留，否则不进入主线 recipe。
  • · 阵营 C：建立证据账本，记录失败、反转、系统成本和超参敏感性，把架构研究从单篇结果改成可累积资产。

品味：重点不是小实验，而是排序是否保真。
