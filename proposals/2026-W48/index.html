#1H · 硬待研判2026-11-25judge-rewards-transfer-bias-not-knowledge

LLM Judge 奖励传递的是偏差与漏洞，不是知识本身

LLM Judges Transfer Bias and Loopholes, Not Knowledge

» 用 LLM judge 做 RL 奖励时，学生模型不一定继承 judge 的事实知识；更稳定迁移的是类别级偏好、盲区和可采样到的漏洞。静态红队只能说明 judge 会误判什么，不能说明策略训练会先放大什么。

触发：2611.29651 把 judge 漏洞拆成策略起点概率与 judge 误报率的乘积；2611.25191 显示 RL 主要继承 judge 的类别盲区而非单题知识；2611.28940 和 2611.30925 进一步说明 rubric 与 rationale 自洽不能保证 reward 质量。

锚点论文

  • 2611.29651Which Loopholes Get Found? Predicting Reward Hacking of LLM Judges Before RL Training— 给出训练前排序 judge 漏洞的 exposure audit，是该话题的直接触发点。
  • 2611.25191Blind Spots Travel, Knowledge Stays Home: What RL Inherits from an LLM Judge— 把“judge 提供知识”与“judge 偏差迁移”分开测，结论更接近 RL 奖励信号的真实作用。
  • 2611.28940When Rubrics Do Not Decide: Silent Value Completion in LLM Evaluation— 指出 rubric 缺少权衡规则时，judge 会补上未声明价值前提。
  • 2611.30925PRIMEAPE: A Multilingual Benchmark for Fine-Grained Meta-Evaluation of Judge Models— 把 verdict 与 rationale 分开审计，说明 rationale 自洽不是 reward 可靠性的充分证据。
  • 2611.30185Causal Evidence for the Emergence and Spread of Reward Hacking in AI Agent Swarms— 说明轨迹池和社交暴露会改变 reward hacking 的传播概率。

对立阵营

  • · 阵营 A：把 LLM judge 当作低成本 reward oracle，主要优化 verifier 准确率。
  • · 阵营 B：把 judge 看成会被策略分布主动搜索的环境，先做 exposure audit 再训练。
  • · 阵营 C：放弃单一 judge 标量，用多 judge、规则 verifier、轨迹约束和类别级偏差审计分账。

品味：reward 质量要按策略分布验收。

#2H · 硬待研判2026-11-25latent-feedback-vs-depth-reuse

Latent Feedback 不是加深网络：它在重写 token 间的计算路径

Latent Feedback Is Not Just More Depth: It Rewrites Cross-Token Computation

» 新一批工作把“上一 token 的深层状态”变成当前 token 可读的信号，这和 looped Transformer 反复复用同一层不是一回事。关键分歧是：收益来自更多计算步，还是来自跨位置、跨深度的信息路由被改写。

触发：2611.31154 直接把上一 token 深层表示接入 attention；2611.29843 用 Temporal Residual 给已有 LM retrofit latent feedback；2611.20404 把 latent feedback 与重复 epoch、数据稀缺放在同一 FLOP 账里比较；2611.29704 和 2611.30581 则暴露 looped/depth-recurrent 训练与系统调度里的不同失败模式。

锚点论文

  • 2611.31154Attention Latent Feedback— 把跨位置深层状态显式接入自回归 attention，是最新的直接证据。
  • 2611.29843The Temporal Residual: Fast and Effective Retrofitting of Latent Feedback into Pretrained Language Models— 强调 validation loss 与解码收益可能脱钩，适合讨论 latent feedback 的评估盲区。
  • 2611.20404Latent Feedback Is a Compute and Data Amplifier— 把 latent feedback 放进数据受限训练和 FLOP 分配问题中。
  • 2611.29704Loop-Count Schedules in Looped Transformers: An Empirical Study— 说明循环次数调度会决定 loop 是真实深度还是输出修正。
  • 2611.30581A Pipeline-Parallel System for Depth-Recurrent Models— 提醒 depth recurrence 不是普通 pipeline 的小改，系统调度会影响可训练性判断。

对立阵营

  • · 阵营 A：用 looped/depth-recurrent 结构增加每 token 计算步，训练时让模型适应递归。
  • · 阵营 B：在标准 AR Transformer 上接入 latent feedback，让浅层读取先前位置的深层状态。
  • · 阵营 C：用后训练 retrofit 或 continued pretrain 改造已有 checkpoint，接受 loss 与解码指标可能不同步。

品味：别把更多步数误判成更好路由。

Calibrate Attention Temperature Before Claiming Long-Context Extrapolation

触发：2611.31113 直接指出 attention temperature 混淆了 zero-shot context extension；2611.29664 用短序列训练 sparse-attention indexer 再服务长上下文，依赖 RoPE 诊断；2611.30934 和 2611.30554 则显示长上下文替代架构与检索式稀疏注意力都需要端到端成本和校准检查。

锚点论文

  • 2611.31113Attention Temperature Confounds Zero-Shot Context Extension— 该话题的核心证据，要求在 long-context ablation 中加入 temperature calibration 和 gain movement check。
  • 2611.29664Position-Skipped Distillation of Sparse-Attention Indexers: Train Short, Serve Long— 把短训长服的有效性压到位置编码和 indexer 外推诊断上。
  • 2611.30934LimeTree: Linear-Memory Graph Neural Networks over Tree-Graphs for Resource-Efficient Language Modeling and Context Extrapolation— 代表长上下文替代架构的小规模外推主张，需要同样的校准标准。
  • 2611.30554Near-Far Attention: Region-Aware Sparse Retrieval for Long-Context LLM Decoding— 显示 selection overhead 与端到端速度会改写 sparse attention 的收益判断。
  • 2611.12956ADIndex: Layer-Adaptive Sparse Attention Indexing via Group-Level Distillation— 近期 sparse attention 证据中，indexer 成本与层间异质性是关键变量。

对立阵营

  • · 阵营 A：先改位置编码或注意力结构，再用 NIAH、perplexity 或少量长文任务验收。
  • · 阵营 B：先校准 attention temperature、gain movement 和低精度误差，再比较结构收益。
  • · 阵营 C：把外推质量、indexer 成本、selection overhead 和端到端 serving 延迟放在同一张账上。

品味：先排数值温度，再谈结构外推。

RLVR Trains a Compute Policy, Not Just an Answer Policy

» 固定 rollout token 上限、dense process reward、单样本异步更新和全词表蒸馏，都会改变模型何时继续思考、何时停止、何时探索稀有轨迹。把它们只当训练效率参数，会误判测试时扩展能力。

触发：2611.26172 显示固定预算 RLVR 会让模型把预算限制内化到测试行为；2611.13560 质疑 dense reward 在 matched-token 预算下是否划算；2611.30325 把 verifier 稀疏信号变成全词表密集监督；2611.18627 和 2611.29795 则从异步单 rollout 与 effective horizon 重新拆 RLVR 的信用分配。

锚点论文

  • 2611.26172Budget Internalization: Fixed-Budget RLVR Trades Test-Time Scaling for In-Budget Accuracy— 直接把 rollout cap 从成本参数改成行为参数。
  • 2611.13560Are Dense Rewards Worth Their Tokens in GRPO?— 要求在相同 token 与 GPU 预算下比较 process reward 和 outcome reward。
  • 2611.30325Verifiable On-Policy Distillation— 把 verifier 的序列级稀疏信号转换为全词表密集信号，改变 RLVR 的监督形态。
  • 2611.18627FlashREINFORCE: Critic-Free Single-Rollout Asynchronous RL for Agentic Language Models— 挑战多 sibling rollout 和同步 group baseline 是 RLVR 稳定性的必要条件。
  • 2611.29795Dimension Is Free, Horizon Is Not: When Evolution Strategies Rival Policy Gradients for LLM Fine-Tuning— 把 ES 与 policy gradient 的差异落到 effective horizon，而不是参数维度。

对立阵营

  • · 阵营 A：把 rollout cap、group size、dense reward 当成训练成本与方差控制参数。
  • · 阵营 B：把这些量当成会被模型学习的行为约束，必须测测试时预算弹性。
  • · 阵营 C：用 verifier distillation、ES 或异步单 rollout 改变监督密度与 credit horizon，换取不同的探索分布。

品味：预算上限会写进策略习惯。

#7H · 硬待研判2026-11-24rl-verifier-domain-boundary

RL Can Repair Bad CoT or Cement Hallucinations: The Verifier Domain Decides Which

» 数学 RL 里，低质量 SFT 轨迹可能只提供格式，RL 可以靠可验证成功信号修正推理；知识任务里，长 CoT 加 outcome reward 可能把模型自己的幻觉写回参数。分歧不在 RL 是否有效，而在 verifier 是否覆盖了出错维度。

锚点论文

  • 2611.26756Reinforcement Learning Unlearns Corrupted SFT Reasoning— 给出 form-only 或 corrupted SFT 后仍可通过 RL 恢复数学推理的反例。
  • 2611.26863LLMs Memorize Their Own Hallucinations During Post-Training— 指出 reasoning-centric post-training 用到知识任务时会把幻觉固化。
  • 2611.25191Blind Spots Travel, Knowledge Stays Home: What RL Inherits from an LLM Judge— 把 judge 迁移拆成知识不迁移、类别盲区迁移。
  • 2611.26084RL Can Only Reinforce What It Sees Succeed— 用受控设置说明 outcome RL 受成功轨迹覆盖限制。
  • 2611.14912Rethinking "RL Generalizes, SFT Memorizes": The Role of SFT Data— 挑战 RL 泛化优势来自优化算法而非数据覆盖的默认解释。

对立阵营

  • · 阵营 A：SFT 主要提供格式和交互模板；只要 verifier 干净，RL 可以修正坏推理轨迹。
  • · 阵营 B：SFT/RL 数据中的错误会被模型吸收；长 CoT 会扩大错误表面积，尤其在知识任务上。
  • · 阵营 C：关键变量是 verifier 覆盖率；数学答案 verifier、LLM judge、隐藏测试和人类偏好不是同一类训练信号。

品味：同一 RL recipe，换 verifier 域会反转结论。

Weight Space Is Becoming an Interface: Few-Shot Adaptation, Self-Editing, and Guardrail Removal Share a Ledger

» 如果 LLM 可以根据样例写另一个模型的权重，甚至编辑自身权重，那么权重不再只是训练产物，也是可编程接口。这个接口同时带来持久适配和白盒攻击，不能只用下游分数判断是否成立。

  • · 阵营 B：权重编辑是开放权重安全的攻击面，行为抽测不足以发现护栏被移除。
  • · 阵营 C：权重编辑结果可能来自搜索、提示泄漏或评测脏 setup；必须有随机编辑、未完成 run、wording sensitivity 和隔离验证。

品味：新意很高，但最容易被脏 setup 欺骗。

#9M · 中待研判2026-11-24agent-benchmark-grader-integrity

Agent benchmark 的 grader 是训练信号：权限隔离、错 reward 与真实偏好必须一起审计
